3 惯性导航原理：IMU核心器件与解算方法

惯性导航，说白了就是「自己算自己在哪里」。

它不依赖任何外部信号，全靠内部的传感器推算位置。我刚开始接触这个技术时，觉得挺神奇的——一个黑盒子，扔到地下，它就能知道自己在哪。后来拆开一看，核心就是加速度计和陀螺仪。

3.1 IMU核心器件：加速度计与陀螺仪

IMU（惯性测量单元）是惯导系统的「眼睛」和「耳朵」。它主要由两类传感器组成：

  • 加速度计：测量物体在三个轴上的加速度（包括重力加速度）
  • 陀螺仪：测量物体绕三个轴的角速度（旋转快慢）

嗯，这里要注意：加速度计测的是「比力」，不是纯运动加速度。什么意思呢？就是它测的是「物体受到的合力减去重力」之后的结果。我在项目里调试时，经常看到静止状态下加速度计输出不是0，而是9.8 m/s²——那就是重力分量。

关键点：加速度计不能区分重力加速度和运动加速度。这是惯导系统的一个先天缺陷，后面会讲到怎么处理。

陀螺仪呢，它测的是角速度。比如你让AGV原地转个90度，陀螺仪就会输出一个角速度脉冲。我习惯用陀螺仪来做航向保持——AGV走直线时，如果陀螺仪检测到有偏转，就立刻修正。

传感器 测量物理量 单位 典型精度（工业级）
加速度计 比力（加速度） m/s² 或 g 0.01 ~ 0.1 m/s²
陀螺仪 角速度 °/s 或 rad/s 0.01 ~ 0.1 °/s

3.2 惯性导航解算原理

有了加速度和角速度，怎么算出位置和姿态？

说白了就是「积分」。加速度对时间积分得到速度，速度再对时间积分得到位移。角速度对时间积分得到角度。

举个例子：

// 一维情况下的惯导解算伪代码
float velocity = 0;
float position = 0;
float dt = 0.01; // 采样周期 10ms

while (running) {
    float acc = readAccelerometer(); // 读取加速度
    velocity += acc * dt;            // 速度积分
    position += velocity * dt;       // 位置积分
    delay(dt * 1000);
}

看着简单吧？但实际项目里，这个积分过程坑特别多。我曾经在一个AGV项目里，只用加速度计积分算位移，结果跑了10米，算出来位置偏差了2米多。为什么会这样？因为加速度计有零偏误差，积分一次变成速度误差，再积分一次变成位置误差——误差是二次方增长的。

避坑指南：我曾经在调试时发现，加速度计静止时输出不是0，而是0.02 m/s²。这个误差看起来很小，但积分10秒后，速度误差就变成了0.2 m/s，位置误差变成了1米。所以，惯导系统必须配合其他传感器做修正，不能单独用。

3.3 捷联惯导系统

捷联惯导，英文叫Strapdown Inertial Navigation System。说白了就是「把IMU直接绑在车体上」的惯导系统。

早期的惯导系统是平台式的——IMU放在一个稳定平台上，平台始终保持水平。但捷联惯导不一样，IMU直接固定在车体上，跟着车一起转。好处是结构简单、成本低、体积小。坏处是——你得用软件把「车体坐标系」转换到「导航坐标系」。

这个转换过程，核心就是姿态解算。我常用的方法是四元数法，比欧拉角更稳定，没有万向锁问题。

// 四元数姿态更新（简化版）
void updateAttitude(float gx, float gy, float gz, float dt) {
    // gx, gy, gz 是陀螺仪角速度（rad/s）
    float q0, q1, q2, q3; // 四元数
    
    // 四元数微分方程
    q0 += 0.5 * (-q1*gx - q2*gy - q3*gz) * dt;
    q1 += 0.5 * ( q0*gx + q2*gz - q3*gy) * dt;
    q2 += 0.5 * ( q0*gy - q1*gz + q3*gx) * dt;
    q3 += 0.5 * ( q0*gz + q1*gy - q2*gx) * dt;
    
    // 归一化
    float norm = sqrt(q0*q0 + q1*q1 + q2*q2 + q3*q3);
    q0 /= norm; q1 /= norm; q2 /= norm; q3 /= norm;
}

有了姿态，就能把加速度从「车体坐标系」转换到「导航坐标系」，然后做积分算位置。

3.4 误差累积特性

这是惯导系统最让人头疼的问题。我直接说结论：惯导的误差是随时间累积的，而且是指数级增长。

为什么会这样？

  • 加速度计零偏：静止时输出不为0，积分后产生速度误差，再积分产生位置误差
  • 陀螺仪漂移：角速度有偏置，积分后姿态误差越来越大
  • 姿态误差导致加速度分解错误：姿态偏了，重力加速度被错误分解到水平方向，产生虚假的水平加速度

我举个例子你就明白了：

假设陀螺仪有0.1°/s的零偏。10秒后，姿态误差就是1°。这1°的误差，会把重力加速度的1.7%分解到水平方向——也就是0.17 m/s²的虚假加速度。再积分10秒，位置误差就接近1米了。你想想看，这才20秒。

我的经验：在AGV项目里，纯惯导的定位误差大约每10秒增长1~3米。所以，惯导只能作为短时辅助，或者配合磁条、二维码、激光雷达等做修正。我习惯的做法是：用惯导做高频姿态更新（100Hz），用磁条或二维码做低频位置修正（1Hz）。

嗯，总结一下：

  • 加速度计和陀螺仪是IMU的核心，一个测加速度，一个测角速度
  • 惯导解算就是积分——加速度积分得速度，速度积分得位置，角速度积分得姿态
  • 捷联惯导把IMU直接绑在车体上，靠软件做坐标系转换
  • 误差累积是惯导的致命弱点，必须配合其他传感器做修正

下一章，我会讲磁条导航的原理和实现。磁条导航和惯导正好互补——一个稳定但不够灵活，一个灵活但会漂移。结合起来用，效果最好。
