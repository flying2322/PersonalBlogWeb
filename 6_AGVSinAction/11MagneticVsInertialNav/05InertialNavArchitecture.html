5 惯性导航系统架构：IMU选型指标、里程计融合方案、卡尔曼滤波框架、嵌入式实现要点

各位同学，今天我们来聊聊惯性导航系统架构。说实话，这部分内容在AGV领域里，属于那种「看着不难，做起来全是坑」的模块。我自己刚入行那会儿，觉得IMU不就是个加速度计加陀螺仪嘛，能有多复杂？结果第一个项目就被现实狠狠教育了一顿。

嗯，咱们今天就把这块掰开揉碎了讲。我会从IMU选型开始，一路讲到里程计融合、卡尔曼滤波，最后落到嵌入式实现上。你跟着我的思路走，保证能少走弯路。

5.1 IMU选型指标：别被参数表骗了

选IMU这事儿，我个人的习惯是：先看应用场景，再看数据手册。为什么？因为很多芯片的参数都是在实验室理想环境下测出来的，你放到AGV上，震动、温度变化、电磁干扰一上来，性能直接打对折。

我重点关注的几个指标：

  • 零偏稳定性：这个指标决定了你的航向角能飘多快。消费级IMU一般在10°/h以上，工业级能做到1°/h以内。做AGV的话，我建议至少选工业级。
  • 角度随机游走：说白了就是噪声水平。这个值越小越好，否则卡尔曼滤波里协方差矩阵调起来会非常痛苦。
  • 加速度计量程：AGV一般选±2g到±4g就够了。别选太大，量程越大分辨率越低。
  • 陀螺仪量程：±250°/s到±500°/s足够。除非你做全向移动AGV，转弯特别猛。
  • 输出频率：至少100Hz以上。低于这个数，你没法做有效的姿态解算。

我踩过的坑：曾经选了一款号称「工业级」的IMU，零偏稳定性标称1°/h。结果装到AGV上，电机一启动，数据直接炸了。后来发现是振动抑制没做好。所以选型时一定要看芯片的「振动环境下性能」这一栏，很多厂商根本不写。

给大家一个参考表格，是我自己项目里常用的几款芯片对比：

型号 零偏稳定性 量程 输出频率 适用场景
BMI088 0.5°/h ±2000°/s 200Hz 中速AGV
ADIS16470 0.1°/h ±2000°/s 400Hz 高精度AGV
MPU9250 5°/h ±2000°/s 100Hz 低成本方案

5.2 里程计融合方案：轮子+IMU才是王道

纯IMU做定位？别想了，几分钟就飘到天上去。纯轮式里程计？打滑一次你就哭。所以必须融合。

我常用的融合方案有两种：

  • 松耦合：轮式里程计做主定位，IMU做短时插值和姿态修正。实现简单，但精度提升有限。
  • 紧耦合：把轮速脉冲和IMU原始数据一起扔进滤波器。精度高，但计算量大，调试也麻烦。

我个人更推荐紧耦合。为什么？因为AGV在工厂里跑，地面情况太复杂了。油污、水渍、小石子，轮子随时可能打滑。紧耦合能利用IMU的短时精度，在打滑瞬间把位置「撑住」，等轮子恢复抓地力再慢慢修正回来。

一个小技巧：做融合时，别忘了给轮式里程计加一个「置信度」参数。比如当前加速度变化剧烈时，降低轮式里程计的权重。这个逻辑我是在一次AGV过减速带时悟出来的——轮子腾空的那一瞬间，里程计数据全是错的。

5.3 卡尔曼滤波框架：别怕，就那几步

很多同学一听到卡尔曼滤波就头大。其实你把它拆开看，就五个公式：预测两步，更新三步。

我习惯用扩展卡尔曼滤波（EKF），因为AGV的运动模型是非线性的。这里给出一个简化的框架：

// 状态向量： [x, y, theta, v, w]
// 输入：     轮速脉冲 + IMU角速度

// 预测步骤
x_pred = f(x_prev, u)  // 运动模型
P_pred = F * P_prev * F^T + Q  // 协方差预测

// 更新步骤
K = P_pred * H^T * (H * P_pred * H^T + R)^-1  // 卡尔曼增益
x_upd = x_pred + K * (z - H * x_pred)  // 状态更新
P_upd = (I - K * H) * P_pred  // 协方差更新

你看，核心就这五步。但实际工程里，调参才是大头。Q矩阵和R矩阵怎么设？我个人的经验是：先让系统跑起来，然后看残差序列。如果残差均值不为零，说明模型有偏；如果方差太大，说明噪声参数设小了。

注意：千万别一上来就用自适应卡尔曼滤波。我见过太多人想一步到位，结果系统直接发散。老老实实先手动调参，跑通了再考虑自适应。

5.4 嵌入式实现要点：代码里全是细节

这部分我多说几句。因为理论再漂亮，落不了地都是白搭。

嵌入式实现时，我重点关注这几个点：

  • 时间同步：IMU数据和轮速数据必须打同一个时间戳。我遇到过最坑的情况是，IMU用SPI读取，轮速用外部中断计数，两个时间基准不一样，融合出来的轨迹直接扭曲。
  • 中断优先级：轮速脉冲中断优先级要高于IMU数据读取中断。为什么？因为丢一个脉冲，位置误差就累积了。IMU数据丢一帧，大不了插值补上。
  • 浮点运算优化：卡尔曼滤波里全是矩阵运算。如果MCU没有FPU，建议用定点数或者查表法。我曾经在STM32F103上跑EKF，优化前一次迭代要2ms，优化后降到0.3ms。
  • 内存管理：别动态分配内存。所有矩阵预分配好，用指针传递。嵌入式系统里，malloc是万恶之源。

一个血泪教训：有一次我在现场调试，AGV跑着跑着突然「抽风」，位置跳变了好几米。查了两天才发现，是IMU的SPI时钟线被电机线干扰了，偶尔读出来全是0xFF。后来加了硬件滤波和软件校验才解决。所以，嵌入式实现不只是写代码，还得懂点硬件抗干扰。
