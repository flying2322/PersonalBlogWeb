12 软件滤波与数据处理：滑动平均滤波、中值滤波、低通滤波在传感器数据中的应用，异常值检测与插值修复，数据平滑与降噪

各位工程师朋友，大家好。今天我们来聊聊AGV导航中一个特别“接地气”的话题——软件滤波与数据处理。

说实话，做AGV导航这些年，我最大的感触就是：传感器数据从来不会“干干净净”地送到你面前。激光雷达偶尔跳个点，IMU时不时飘一下，编码器在颠簸路面更是“放飞自我”。如果你直接拿这些原始数据去算定位、做控制，那AGV大概率会像个醉汉一样在路上晃悠。

所以，软件滤波不是“锦上添花”，而是“雪中送炭”。我个人习惯把滤波分为三类：平滑类、去突跳类、降噪类。下面我们一个一个聊。

核心观点：滤波的本质不是“消除真实信息”，而是“剔除虚假干扰”。选对滤波器，比堆算力更重要。

12.1 滑动平均滤波：最简单的平滑利器

滑动平均滤波，说白了就是取最近N个数据的平均值。你想想看，如果传感器每10ms输出一个距离值，但每次都有±2cm的随机噪声，那取最近5个点的平均值，噪声立马被压到±1cm以内。

我在项目中遇到过这样一个场景：AGV在粗糙水泥地上行驶，超声波传感器测距值跳得厉害。用了滑动平均滤波后，数据曲线瞬间“温柔”了很多。

// 滑动平均滤波示例（C语言风格）
#define WINDOW_SIZE 5
float buffer[WINDOW_SIZE] = {0};
int index = 0;
float sum = 0;

float sliding_average(float new_value) {
    sum -= buffer[index];
    buffer[index] = new_value;
    sum += new_value;
    index = (index + 1) % WINDOW_SIZE;
    return sum / WINDOW_SIZE;
}

这里有个坑：窗口大小怎么选？我建议你先观察一下噪声的频率。如果噪声周期是100ms，那窗口至少覆盖2~3个周期，也就是200~300ms的数据量。窗口太小，滤波效果差；窗口太大，信号延迟严重，AGV转弯时反应会慢半拍。

我的经验：对于AGV常用的10Hz~50Hz传感器，窗口大小取3~10比较合适。编码器数据可以小一点（3~5），激光雷达数据可以大一点（5~10）。

12.2 中值滤波：专治“野点”突跳

滑动平均滤波怕什么？怕“野点”。如果某个时刻传感器突然跳出一个离谱的值（比如激光打到镜面反射物上），滑动平均会把整个窗口都“带偏”。这时候，中值滤波就派上用场了。

中值滤波的原理很简单：把窗口内的数据排序，取中间那个值。这样一来，哪怕有一个数据是1000，其他都是10左右，中值还是10，完全不受影响。

// 中值滤波示例
#define MEDIAN_WINDOW 5
float median_filter(float new_value) {
    static float window[MEDIAN_WINDOW];
    static int idx = 0;
    float temp[MEDIAN_WINDOW];
    
    window[idx] = new_value;
    idx = (idx + 1) % MEDIAN_WINDOW;
    
    // 拷贝并排序
    memcpy(temp, window, sizeof(temp));
    // 冒泡排序（实际项目中建议用更高效的排序）
    for (int i = 0; i < MEDIAN_WINDOW - 1; i++) {
        for (int j = 0; j < MEDIAN_WINDOW - 1 - i; j++) {
            if (temp[j] > temp[j+1]) {
                float t = temp[j];
                temp[j] = temp[j+1];
                temp[j+1] = t;
            }
        }
    }
    return temp[MEDIAN_WINDOW / 2];
}

我曾经在一个立体仓库项目中，AGV的激光雷达经常被货架立柱反射出“幽灵点”。用了中值滤波后，这些突跳点被完美过滤，定位再也没有飘过。

注意：中值滤波不适合处理快速变化的信号。比如AGV急停时的速度数据，中值滤波会“削平”真实的突变，导致控制响应变慢。这种情况我建议用滑动平均或者低通滤波。

12.3 低通滤波：模拟世界的“惯性”

低通滤波，说白了就是让信号“慢下来”。它模拟了物理系统的惯性——你推一个重物，它不会瞬间加速，也不会瞬间停止。

在AGV导航中，我最常用的是一阶RC低通滤波，公式简单，计算量小，非常适合嵌入式实时系统。

// 一阶低通滤波
float lowpass_filter(float input, float prev_output, float alpha) {
    // alpha = dt / (RC + dt)，通常取0.1~0.5
    return alpha * input + (1 - alpha) * prev_output;
}

alpha值怎么调？我个人的习惯是：先看信号的噪声频率，再决定截止频率。比如IMU的角速度数据，噪声在50Hz以上，那我设截止频率为10Hz，alpha大约0.2。这样既能滤掉高频抖动，又不会让AGV的转向响应太迟钝。

应用场景 推荐alpha值 说明
IMU角速度 0.1~0.3 噪声较高，需要强滤波
编码器速度 0.3~0.5 信号相对干净，弱滤波即可
激光雷达距离 0.2~0.4 视环境噪声程度调整

12.4 异常值检测与插值修复

滤波只能“压制”噪声，但有些数据坏得太离谱，比如传感器断线、通信丢包，这时候滤波也救不了。我们需要先做异常值检测，再做插值修复。

我常用的异常检测方法有两种：

  • 阈值法：设定物理极限，比如激光雷达测距不可能超过30米，超过就直接标记为无效。
  • 变化率法：相邻两个数据的变化率超过某个阈值（比如50%），就认为是异常。AGV不可能在10ms内移动1米。

检测到异常后，怎么修复？我个人偏爱线性插值，简单且有效。

// 线性插值修复
float linear_interpolate(float prev_valid, float next_valid, int gap_count, int current_gap) {
    float step = (next_valid - prev_valid) / (gap_count + 1);
    return prev_valid + step * current_gap;
}

举个例子：假设第5帧数据丢了，第4帧是10.0，第6帧是12.0，中间缺了1帧。那插值结果就是11.0。如果连续丢了3帧，那就依次插出10.5、11.0、11.5。

避坑指南：我曾经在AGV经过金属门框时，激光雷达连续丢了5帧数据。如果还用线性插值，插出来的轨迹会“穿墙”。后来我加了限制：连续丢帧超过3个，直接丢弃这段数据，用里程计推算代替。嗯，这个经验让我少调了好几个晚上的bug。

12.5 数据平滑与降噪：组合拳才是王道

实际项目中，我很少只用一种滤波方法。通常的做法是：

  1. 先做异常检测，剔除野点，用插值补上。
  2. 再做中值滤波，干掉残留的突跳。
  3. 最后用滑动平均或低通滤波，把曲线磨平。

这套组合拳，我在多个AGV项目里验证过，效果非常稳定。你想想看，如果只做滑动平均，野点会污染整个窗口；如果只做中值滤波，高频噪声又滤不干净。只有组合使用，才能做到“既干净又真实”。

最后说一句：滤波参数不是调一次就完事的。环境变了、传感器换了、AGV速度改了，参数都得跟着调。我建议你在代码里留一个“滤波参数调试接口”，方便现场快速调整。嗯，这个习惯让我少跑了很多趟现场。

总结一下：

  • 滑动平均滤波：平滑噪声，但怕野点。
  • 中值滤波：干掉野点，但会削平快速变化。
  • 低通滤波：模拟惯性，适合高频噪声。
  • 异常检测+插值：先修再滤，效果翻倍。

组合使用，才是AGV导航数据处理的正确姿势。
