20 抗干扰设计规范：AGV导航系统抗干扰设计检查清单

做AGV导航系统这么多年，我最大的体会就是——抗干扰不是靠后期打补丁，而是从选型那天就得想清楚的事。很多项目前期图省事，硬件随便搭、软件随便写，等到现场跑起来才发现，一个电机启停就能让定位跳几厘米。嗯，那时候再回头改，成本可就大了去了。

这一章，我把这些年踩过的坑、总结的经验，整理成一份抗干扰设计检查清单。你照着这个清单过一遍，至少能避开80%的常见干扰问题。

20.1 硬件选型与布局规范

硬件是抗干扰的第一道防线。我见过太多人把精力全放在算法上，结果一个劣质电源就把所有努力全毁了。说白了，硬件底子不行，软件再牛也救不回来。

20.1.1 核心器件选型要点

器件类别 选型要求 我踩过的坑
主控芯片 工业级温度范围（-40℃~85℃），ESD防护≥8kV 曾经用了一款商业级芯片，夏天车间温度一高，系统直接死机
传感器 抗环境光干扰能力≥100k Lux，支持多路径抑制 激光雷达在强光下丢数据，后来换了带滤光片的型号才解决
电机驱动 内置过流、过压、过温保护，PWM频率≥20kHz 低频PWM产生的谐波会串到IMU信号线上，定位数据直接飘了
电源模块 隔离型DC-DC，纹波噪声≤50mVpp，输入反接保护 非隔离电源导致地环路，导航精度从±1cm掉到±5cm
通信模块 屏蔽双绞线，共模扼流圈，差分信号传输 RS485没加终端电阻，长距离通信误码率高达5%

核心原则： 选型时留出至少20%的余量。比如你需要1A的电流，就选1.2A以上的器件。别问我为什么，现场环境永远比你实验室里恶劣得多。

20.1.2 布局与布线规范

布局这件事，我个人的习惯是：先分区，再布线，最后检查回路。你想想看，如果强电和弱电走在一起，那干扰就是必然的。

  1. 分区布局：将强电区（电机驱动、电源）、弱电区（主控、传感器）、通信区（无线模块、CAN总线）物理隔离，间距≥10mm
  2. 地线设计：采用星型接地或大面积接地，避免形成地环路。我在项目中遇到过，地环路导致IMU数据周期性跳变，排查了整整两天
  3. 信号隔离：所有长距离信号（>30cm）必须使用屏蔽线，屏蔽层单端接地
  4. 电源滤波：每个模块入口加磁珠+电容滤波，高频噪声能衰减40dB以上
  5. 散热考虑：大功率器件远离传感器，热辐射会引起传感器温漂

警告： 千万不要把电机线和传感器线绑在一起走线。我曾经见过一个项目，工程师为了走线美观，把所有线扎成一束，结果导航系统根本没法用。分开走线，间距至少5cm，这是底线。

20.2 软件架构与容错设计规范

硬件做好了，软件也不能拖后腿。我常说一句话：好的软件架构，能让硬件在恶劣环境下多撑30%的性能。这不是夸张，是实测数据。

20.2.1 软件抗干扰架构

我个人习惯把软件抗干扰分成三层：数据层、算法层、决策层。每一层都要有自己的容错机制。

// 数据层：传感器数据预处理
// 我习惯用滑动窗口+中值滤波，效果比均值滤波好很多
#define WINDOW_SIZE 5
float median_filter(float new_sample) {
    static float buffer[WINDOW_SIZE] = {0};
    static int index = 0;
    float temp[WINDOW_SIZE];
    
    // 更新环形缓冲区
    buffer[index] = new_sample;
    index = (index + 1) % WINDOW_SIZE;
    
    // 复制并排序
    memcpy(temp, buffer, sizeof(temp));
    // 这里用冒泡排序，简单可靠
    for (int i = 0; i < WINDOW_SIZE - 1; i++) {
        for (int j = 0; j < WINDOW_SIZE - i - 1; j++) {
            if (temp[j] > temp[j + 1]) {
                float t = temp[j];
                temp[j] = temp[j + 1];
                temp[j + 1] = t;
            }
        }
    }
    // 返回中值
    return temp[WINDOW_SIZE / 2];
}

小技巧： 滤波窗口大小不是越大越好。窗口太大，信号延迟就大，AGV急停时反应不过来。我一般设5~7个点，既能滤掉毛刺，又不影响实时性。

20.2.2 容错设计规范

容错设计，说白了就是假设所有数据都可能是错的。你想想看，传感器会丢包、通信会中断、电机启动会产生强电磁干扰——这些不是「如果」的问题，而是「什么时候」的问题。

  1. 数据有效性校验：每个传感器数据必须经过范围检查、变化率检查、时间戳检查
  2. 多传感器融合：至少使用3种不同原理的传感器（如激光+IMU+编码器），互相校验
  3. 看门狗机制：独立硬件看门狗，超时时间设为正常周期的3倍
  4. 状态机保护：定义非法状态转换，一旦检测到异常，立即进入安全模式
  5. 数据冗余：关键数据（如位置、速度）在内存中保存3份，通过投票机制决定最终值

避坑指南： 我曾经在一个项目中，只用了激光雷达做定位。结果有一次车间里突然多了很多反光物体，激光数据大面积异常，AGV直接撞墙了。从那以后，我坚持至少用两种不同原理的传感器做定位融合。记住：单一传感器永远不可靠。

20.3 抗干扰设计检查清单

下面这份清单，是我每次做项目评审时必过的。你照着检查一遍，基本不会出大问题。

检查项 检查内容 通过标准
电源完整性 纹波噪声、瞬态响应、隔离方式 纹波≤50mVpp，瞬态恢复时间≤100μs
信号完整性 上升时间、过冲、振铃 过冲≤10%，振铃幅度≤5%
EMC防护 屏蔽、滤波、接地 通过IEC 61000-4-2/4/6标准
软件滤波 中值滤波、卡尔曼滤波、限幅滤波 噪声衰减≥60%
容错机制 看门狗、数据校验、状态机保护 单点故障不影响系统安全
热管理 温升、散热、热漂移补偿 温升≤30℃，定位漂移≤1mm/℃

20.4 抗干扰设计知识体系

为了让你更直观地理解抗干扰设计的整体架构，我画了一张图。这张图是我多年经验的总结，你照着这个框架去设计，基本不会漏掉关键环节。

这张图的核心思想就是：硬件和软件要协同设计，不能偏废任何一方。我见过太多团队，硬件工程师只管硬件，软件工程师只管软件，结果两边都不管接口处的抗干扰问题。最后出了问题，互相推诿，项目延期。
