14 环境建模与地图优化：栅格地图与特征地图的抗干扰更新策略，动态障碍物地图剔除，多时相地图融合与更新

做AGV导航这么多年，我越来越觉得——地图不是建完就完事的。它得“活着”。

什么叫活着？就是能抗干扰、能剔除动态障碍物、能融合多时相的数据。说白了，地图得自己会进化。今天咱们就聊聊这个。

14.1 栅格地图的抗干扰更新策略

栅格地图，大家都不陌生。每个格子存一个概率值，表示“这里有没有障碍物”。但问题来了——传感器总有噪声，激光偶尔打偏，超声波可能被干扰。怎么更新才靠谱？

我个人习惯用贝叶斯更新。不是简单地把新观测值覆盖旧值，而是把新旧信息做概率融合。

// 贝叶斯栅格更新伪代码
float updateCell(float prior, float measurement, float p_hit, float p_miss) {
    // prior: 先验概率
    // measurement: 当前观测 (0=空闲, 1=占用)
    // p_hit: 传感器检测到障碍物的准确率
    // p_miss: 传感器漏检的概率
    
    float likelihood = (measurement == 1) ? p_hit : p_miss;
    float posterior = (likelihood * prior) / 
                      (likelihood * prior + (1 - likelihood) * (1 - prior));
    return posterior;
}

嗯，这里要注意——不要直接用0和1。我见过不少项目，直接把栅格值设成0或1，结果一帧噪声数据就把地图毁了。用概率值，慢慢收敛，才是正道。

核心原则：栅格更新要“慢进快出”。障碍物出现要多次确认，障碍物消失要快速响应。

14.2 特征地图的抗干扰更新

特征地图，比如点云特征、角点、线段，比栅格地图更“娇气”。为什么？因为特征一旦匹配错，整个位姿估计就偏了。

我在项目中遇到过一个问题：仓库里有一排货架，激光扫描到的角点特征，跟另一排货架的角点几乎一模一样。结果地图更新时，特征匹配错了，AGV直接“迷路”。

怎么解决？我建议用RANSAC + 局部一致性检查。

// 特征匹配抗干扰策略
bool matchFeature(Feature observed, Feature map_feature, float threshold) {
    // 1. 几何距离检查
    float dist = euclideanDistance(observed.position, map_feature.position);
    if (dist > threshold) return false;
    
    // 2. 描述子相似度检查
    float sim = descriptorSimilarity(observed.descriptor, map_feature.descriptor);
    if (sim < 0.7) return false;  // 相似度阈值
    
    // 3. 局部拓扑一致性检查
    // 检查该特征周围的其他特征是否也匹配
    int consistent_neighbors = checkNeighborConsistency(observed, map_feature);
    if (consistent_neighbors < 3) return false;  // 至少3个邻居一致
    
    return true;
}

我的小技巧：特征地图更新时，给每个特征加一个“置信度计数器”。连续匹配成功就加1，匹配失败就减1。低于阈值就剔除。这样能有效过滤掉临时出现的干扰特征。

14.3 动态障碍物地图剔除

动态障碍物——行人、叉车、托盘——是AGV导航的“头号公敌”。

你想想看，如果地图里永远保留着刚才那个行人站的位置，AGV下次路过时就会绕一个大弯。多傻啊。

我常用的策略是时间戳差分法：

  1. 每个栅格或特征都记录最后一次更新时间
  2. 如果某个区域在短时间内“出现又消失”，标记为动态
  3. 动态区域不参与全局路径规划，只做局部避障
// 动态障碍物剔除逻辑
void updateDynamicMap(GridMap& map, ScanData& scan, float time_now) {
    for (auto& cell : map.cells) {
        // 检查该栅格是否被当前扫描覆盖
        if (scan.isCovered(cell.position)) {
            bool occupied = scan.isOccupied(cell.position);
            
            if (occupied) {
                cell.last_observed_occupied = time_now;
                cell.occupancy = min(1.0f, cell.occupancy + 0.3f);
            } else {
                // 如果之前是占用，但现在是空闲
                if (cell.occupancy > 0.5f) {
                    float duration = time_now - cell.last_observed_occupied;
                    if (duration < 2.0f) {
                        // 短时间内变化，可能是动态障碍物
                        cell.is_dynamic = true;
                        cell.occupancy = 0.0f;  // 立即清除
                    } else {
                        cell.occupancy = max(0.0f, cell.occupancy - 0.1f);
                    }
                }
            }
        }
    }
}

警告：千万别把动态障碍物直接删掉就完事了。我曾经吃过这个亏——动态障碍物虽然要剔除，但它的位置信息要保留到局部代价地图里，用于实时避障。否则AGV会直接撞上去。

14.4 多时相地图融合与更新

什么叫多时相？就是不同时间采集的地图数据。早上、中午、晚上，仓库的布局可能不一样——货架被移动了，通道被堵了。

我建议用加权滑动窗口来做融合：

时间窗口 权重 说明
最近1小时 0.6 最新数据，权重最高
1~24小时 0.3 短期历史，辅助判断
24小时以上 0.1 长期背景，防止误删 
// 多时相地图融合
void fuseMultiTemporalMap(GridMap& fused_map, 
                          vector<GridMap>& temporal_maps) {
    // temporal_maps[0] = 最新, temporal_maps[1] = 1小时前, ...
    vector<float> weights = {0.6, 0.3, 0.1};
    
    for (int i = 0; i < fused_map.cells.size(); i++) {
        float fused_value = 0.0f;
        float weight_sum = 0.0f;
        
        for (int t = 0; t < temporal_maps.size() && t < weights.size(); t++) {
            if (temporal_maps[t].cells[i].is_valid) {
                fused_value += temporal_maps[t].cells[i].occupancy * weights[t];
                weight_sum += weights[t];
            }
        }
        
        if (weight_sum > 0) {
            fused_map.cells[i].occupancy = fused_value / weight_sum;
        }
    }
}

这里有个坑——时间窗口不能太短。我记得有一次，客户说“地图更新太慢了”，我把窗口改成15分钟。结果呢？AGV在货架通道里来回晃，因为地图一直在变。后来改成2小时窗口，稳了。
