13 标定与校准：激光雷达与IMU外参标定方法，编码器刻度系数校准，视觉相机内参标定与畸变校正

各位同行，今天咱们聊聊标定与校准。说实话，这活儿看着不起眼，但绝对是AGV导航系统的“地基”。地基没打好，后面算法调得再好也是白搭。我见过太多项目，明明传感器选型没问题，控制算法也够先进，结果跑起来就是各种飘——十有八九是标定没做到位。

标定这事儿，说白了就是给传感器“对表”。让它们知道彼此之间的相对位置、姿态，以及自身的内部参数。今天我把三个核心模块拆开讲：激光雷达与IMU的外参标定、编码器刻度系数校准、视觉相机的内参标定与畸变校正。

核心观点：标定不是一次性工作。温度变化、机械振动、长期磨损都会导致参数漂移。我建议每3-6个月做一次复检，关键项目甚至要上在线标定。

13.1 激光雷达与IMU外参标定

激光雷达和IMU是AGV导航的“黄金搭档”。激光雷达给精确的距离信息，IMU提供高频的姿态变化。但问题是——它们俩装在车上的位置和角度不一样。你得知道它们之间的旋转矩阵和平移向量，这就是外参。

我个人习惯用三种方法，按场景选：

  1. 旋转法标定：把AGV放在转台上，让车体做纯旋转运动。激光雷达观测到的静止点云会形成圆弧，IMU记录角速度。通过拟合圆弧中心和IMU的角速度积分，就能解出外参。这个方法精度高，但需要转台设备。
  2. 手眼标定法：借鉴机器人手眼标定的思路。让AGV走一段已知轨迹，同时记录激光雷达的SLAM结果和IMU的积分结果。构建AX=XB方程，用最小二乘法求解。我在项目里常用这个方法，因为不需要额外设备。
  3. 自然场景法：在环境里放几个特征明显的标定物（比如反光柱），让AGV从不同角度观测。利用激光雷达和IMU对同一特征点的观测差异来解算外参。这个方法适合现场快速标定。

我的经验：旋转法标定出来的外参最准，但操作麻烦。手眼标定法最实用，但要注意轨迹设计——别走直线，要有充分的旋转运动，否则IMU的偏置误差会吃掉外参信息。

这里给一段手眼标定的核心代码片段，用的是Eigen库：

// 手眼标定：求解 AX = XB
// A: 激光雷达的位姿变换 (4x4)
// B: IMU的位姿变换 (4x4)
// X: 待求的外参 (4x4)

Eigen::Matrix4d solveHandEye(
    const std::vector<Eigen::Matrix4d>& A_list,
    const std::vector<Eigen::Matrix4d>& B_list) {
    
    // 构建旋转部分方程
    std::vector<Eigen::Matrix3d> R_A, R_B;
    for (size_t i = 0; i < A_list.size(); ++i) {
        R_A.push_back(A_list[i].block<3,3>(0,0));
        R_B.push_back(B_list[i].block<3,3>(0,0));
    }
    
    // 使用Tsai方法求解旋转矩阵
    Eigen::Matrix3d R_X = tsaiRotation(R_A, R_B);
    
    // 求解平移部分
    Eigen::Vector3d t_X = solveTranslation(A_list, B_list, R_X);
    
    // 组装外参矩阵
    Eigen::Matrix4d X = Eigen::Matrix4d::Identity();
    X.block<3,3>(0,0) = R_X;
    X.block<3,1>(0,3) = t_X;
    
    return X;
}

注意：IMU数据一定要做零偏补偿。我曾经在一个项目里忽略了IMU的零偏，结果标定出来的外参误差达到5度，导致融合定位直接发散。后来加了静止段数据做零偏估计，才把问题解决。

13.2 编码器刻度系数校准

编码器是AGV的“腿”，它告诉你轮子转了多少圈。但问题是——轮子有磨损、有打滑、有安装误差。编码器输出的脉冲数，和实际走过的距离之间，存在一个刻度系数。这个系数不准，里程计就会漂。

校准方法我常用这三种：

方法 原理 精度 适用场景
直线校准法 让AGV走一段已知直线距离，对比编码器脉冲数 ±0.5% 日常维护、快速校准
圆形轨迹法 让AGV绕固定半径转圈，利用几何约束解算 ±0.2% 高精度场景、差速底盘
双编码器互校 左右轮编码器互相约束，解算各自的刻度系数 ±0.1% 双轮差速、需要在线校准

直线校准法最简单。你在地上贴一条5米长的胶带，让AGV从起点走到终点。记录编码器脉冲数N，那么刻度系数就是：

// 刻度系数 = 实际距离 / 编码器脉冲数
// 单位：米/脉冲
double scale = 5.0 / N;  // 5米距离

// 如果是差速底盘，左右轮要分别校准
double scale_left = 5.0 / N_left;
double scale_right = 5.0 / N_right;

嗯，这里要注意——直线校准法看似简单，但有个坑：AGV必须走直线，不能有偏航。我见过有人用手推着AGV走，结果走歪了，校准出来的系数左右轮不一致，反而引入了新的误差。我建议用AGV自己的导航系统控制它走直线，或者用导轨辅助。

避坑指南：编码器刻度系数会随温度变化。我曾经在冬天校准好的AGV，夏天跑起来里程计误差大了3%。后来发现是轮胎气压随温度变化，导致滚动半径变了。解决方案：在温度变化超过15°C时重新校准，或者加装胎压监测做补偿。

13.3 视觉相机内参标定与畸变校正

视觉相机是AGV的“眼睛”。但镜头不是完美的——有径向畸变、切向畸变。内参标定就是搞清楚相机的焦距、主点位置和畸变参数。说白了，就是让相机知道“我看到的东西，实际在什么位置”。

我用的标定方法是经典的棋盘格法，流程如下：

  1. 采集图像：打印一张棋盘格标定板，从不同角度拍20-30张照片。注意：棋盘格要占画面1/3以上，角度要覆盖俯仰、偏航、滚转三个方向。
  2. 角点检测：用OpenCV的findChessboardCorners提取棋盘格角点。亚像素精度是关键，用cornerSubPix做细化。
  3. 求解内参：用calibrateCamera函数求解内参矩阵和畸变系数。
  4. 畸变校正：用undistort或initUndistortRectifyMap生成校正映射表。

代码示例：

// OpenCV 相机标定核心代码
cv::Mat cameraMatrix, distCoeffs;
std::vector<cv::Mat> rvecs, tvecs;

// 棋盘格尺寸：内角点数量 (9,6)，方格边长 30mm
cv::Size patternSize(9, 6);
float squareSize = 30.0f;  // mm

// 准备世界坐标系中的棋盘格角点
std::vector<cv::Point3f> objectPoints;
for (int i = 0; i < patternSize.height; ++i) {
    for (int j = 0; j < patternSize.width; ++j) {
        objectPoints.push_back(cv::Point3f(j * squareSize, i * squareSize, 0));
    }
}

// 执行标定
double rms = cv::calibrateCamera(
    objectPointsList,   // 世界坐标点集
    imagePointsList,    // 图像坐标点集
    imageSize,          // 图像尺寸
    cameraMatrix,       // 输出：内参矩阵
    distCoeffs,         // 输出：畸变系数
    rvecs, tvecs,       // 输出：外参
    cv::CALIB_FIX_ASPECT_RATIO | cv::CALIB_ZERO_TANGENT_DIST
);

// 检查重投影误差
std::cout << "重投影误差: " << rms << " 像素" << std::endl;
// 一般要求 rms < 0.5 像素才算合格

我的习惯：标定完成后，我会用undistort校正一张图像，然后手动检查棋盘格的直线是否变直了。如果边缘还有弯曲，说明畸变校正不彻底，需要重新标定。另外，我建议把校正映射表存成文件，运行时直接查表，省去每次校正的计算开销。

畸变模型分两种：径向畸变和切向畸变。径向畸变是镜头形状导致的，表现为“桶形”或“枕形”失真。切向畸变是镜头和成像平面不平行导致的。OpenCV默认用5个畸变系数（k1, k2, p1, p2, k3），其中k1、k2、k3是径向系数，p1、p2是切向系数。

注意：标定板一定要平整！我曾经用一张有点褶皱的打印纸做标定板，结果标定出来的内参误差很大，导致视觉定位偏差超过10厘米。后来换了亚克力板做的标定板，问题才解决。另外，标定板的方格尺寸要精确测量，误差不要超过0.1mm。

最后说一句——标定不是终点，是起点。参数标定好了，还要在实际运行中验证。我一般会在AGV跑完一圈后，对比激光雷达、IMU、视觉三个传感器的定位结果，看看偏差是否在容忍范围内。如果偏差持续增大，说明某个传感器的标定参数可能已经漂了，需要重新标定。

好了，这一章的内容就到这里。标定是个细致活，急不得。你想想看，如果连传感器之间的“默契”都没培养好，AGV怎么可能跑得稳？
