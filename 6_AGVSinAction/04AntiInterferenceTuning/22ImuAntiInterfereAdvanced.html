22 IMU抗干扰进阶：温度补偿、振动补偿与融合抗干扰

做AGV导航这么多年，IMU（惯性测量单元）一直是个让人又爱又恨的传感器。爱它是因为它不依赖外部信号，能提供高频的姿态和加速度信息；恨它是因为——它太容易受干扰了。温度一变，零偏就飘；振动一来，噪声就炸。今天我就把这几年的实战经验掰开揉碎，跟你聊聊IMU抗干扰的那些进阶技巧。

核心观点：IMU的干扰主要来自三个方面——温度漂移、机械振动、以及随机噪声。这三者如果不处理，IMU数据基本没法直接用。但处理好了，它就能成为导航系统里最可靠的“定海神针”。

22.1 温度补偿：别让IMU“发烧”

IMU里的MEMS传感器对温度极其敏感。我遇到过一台AGV，夏天在车间跑得好好的，一到冬天冷启动，航向角直接偏了5度。查了半天，就是温度补偿没做好。

温度补偿的核心思路其实很简单：建立温度与零偏的映射关系，然后在运行时实时修正。具体做法分三步：

  1. 标定阶段：把IMU放进温箱，从-20°C到60°C，每5°C记录一次零偏数据。
  2. 建模阶段：用多项式拟合温度-零偏曲线。我个人习惯用三阶多项式，精度够用，计算量也不大。
  3. 运行阶段：根据当前温度查表或计算补偿值，实时修正IMU输出。

下面是我常用的温度补偿代码框架：

// 温度补偿函数
void imu_temp_compensate(float temp, float *gyro_bias, float *accel_bias) {
    // 三阶多项式系数（标定得到）
    float coeff_gx[4] = {0.0012, -0.0034, 0.0089, -0.0156};
    float coeff_ax[4] = {0.0008, -0.0021, 0.0056, -0.0098};
    
    // 计算补偿值
    float comp_gx = coeff_gx[0] + coeff_gx[1]*temp + 
                    coeff_gx[2]*temp*temp + coeff_gx[3]*temp*temp*temp;
    float comp_ax = coeff_ax[0] + coeff_ax[1]*temp + 
                    coeff_ax[2]*temp*temp + coeff_ax[3]*temp*temp*temp;
    
    // 修正零偏
    gyro_bias[0] -= comp_gx;
    accel_bias[0] -= comp_ax;
}

实战技巧：标定时别忘了让IMU充分预热。我一般会先通电30分钟，等内部温度稳定了再开始采集数据。否则你标定出来的曲线，实际用起来还是会有偏差。

22.2 振动补偿：把“抖”出来的噪声滤掉

AGV在粗糙地面跑的时候，IMU输出的加速度数据简直没法看。高频振动会混入真实运动信号里，导致姿态解算出错。你想想看，本来车子在直行，结果IMU告诉你它在上下颠簸，这导航还能准吗？

振动补偿我常用的方法有两种：

方法 原理 适用场景 我踩过的坑
低通滤波 截止频率设为5-10Hz，滤除高频振动 地面较平整，振动频率稳定 截止频率设太低，真实转弯信号也被滤掉了
自适应陷波滤波 实时检测振动主频，动态抑制 振动频率变化大的场景 参数调不好容易产生震荡
小波去噪 多尺度分解，分离信号与噪声 振动复杂，需要高精度姿态 计算量大，嵌入式上跑不动

我个人最常用的是自适应陷波滤波。为什么呢？因为AGV在不同路面上的振动频率不一样——水泥地是20-30Hz，钢板地是40-50Hz。固定参数的滤波器根本搞不定。

// 自适应陷波滤波器示例
typedef struct {
    float freq;      // 当前陷波频率
    float Q;         // 品质因数
    float b0, b1, b2;
    float a0, a1, a2;
    float x1, x2, y1, y2;
} NotchFilter;

void notch_filter_update(NotchFilter *f, float sample_rate, float input) {
    // 实时检测主频（通过FFT或锁相环）
    f->freq = detect_dominant_freq(input, sample_rate);
    
    // 更新滤波器系数
    float w0 = 2 * PI * f->freq / sample_rate;
    float alpha = sin(w0) / (2 * f->Q);
    
    f->b0 = 1;
    f->b1 = -2 * cos(w0);
    f->b2 = 1;
    f->a0 = 1 + alpha;
    f->a1 = -2 * cos(w0);
    f->a2 = 1 - alpha;
    
    // 滤波计算
    float output = (f->b0 * input + f->b1 * f->x1 + f->b2 * f->x2
                   - f->a1 * f->y1 - f->a2 * f->y2) / f->a0;
    
    // 更新状态
    f->x2 = f->x1;
    f->x1 = input;
    f->y2 = f->y1;
    f->y1 = output;
}

注意：振动补偿不是越强越好。滤波太狠，真实运动信号也会被衰减。我见过有人把截止频率设到2Hz，结果AGV转弯时IMU完全没反应，导航直接崩了。记住一个原则：在保证不丢失真实信号的前提下，尽量滤除噪声。

22.3 零偏稳定性与随机游走抑制

零偏稳定性（Bias Stability）和角度随机游走（Angle Random Walk, ARW）是IMU的两个核心指标。说白了，前者衡量的是零偏随时间漂移的程度，后者衡量的是噪声积分后产生的角度误差。

为什么会这样？因为IMU的噪声是随机的，积分之后会累积成随机游走误差。时间越长，误差越大。这就是为什么纯IMU导航几分钟就飘得没边了。

抑制随机游走，我常用的方法有：

  • Allan方差分析：先分析IMU的噪声特性，确定最优的平滑窗口大小。
  • 滑动平均滤波：对陀螺仪输出做滑动平均，降低高频噪声。
  • 零速检测+零偏修正：当AGV静止时，实时更新零偏估计值。

这里重点说说零速检测。我曾经在一个项目里发现，AGV停着的时候IMU的角速度输出居然有0.5°/s的漂移。如果不做零速修正，10秒就能偏5度，导航根本没法用。

// 零速检测与零偏修正
void zero_velocity_update(float gyro[3], float accel[3], float *bias) {
    // 检测条件：角速度小 + 加速度接近重力
    float gyro_norm = sqrt(gyro[0]*gyro[0] + gyro[1]*gyro[1] + gyro[2]*gyro[2]);
    float accel_norm = sqrt(accel[0]*accel[0] + accel[1]*accel[1] + accel[2]*accel[2]);
    
    if (gyro_norm < 0.1 && fabs(accel_norm - 9.81) < 0.2) {
        // 静止状态，更新零偏
        for (int i = 0; i < 3; i++) {
            bias[i] = 0.99 * bias[i] + 0.01 * gyro[i];  // 一阶低通
        }
    }
}

避坑指南：零速检测的阈值不能设得太死。我曾经设了0.05°/s的角速度阈值，结果AGV在斜坡上静止时，因为重力分量导致加速度判断不通过，零偏一直没更新。后来我把加速度阈值放宽到0.3m/s²，问题就解决了。

22.4 IMU与轮式里程计融合抗干扰

IMU有高频姿态但会漂移，轮式里程计有低频位置但会打滑。两者融合，正好互补。但融合不是简单加权平均，得讲究策略。

我常用的融合框架是扩展卡尔曼滤波（EKF），状态量包括位置、速度、姿态、以及IMU零偏。观测值来自轮式里程计的位移和速度。

这里的关键在于：当轮式里程计打滑时，要降低它的置信度。怎么判断打滑？看IMU加速度和轮速的一致性。

// 打滑检测与融合权重调整
float detect_slip(float imu_accel, float wheel_accel) {
    float diff = fabs(imu_accel - wheel_accel);
    if (diff < 0.5) {
        return 1.0;   // 正常，完全信任里程计
    } else if (diff < 2.0) {
        return 0.5;   // 轻微打滑，半信半疑
    } else {
        return 0.1;   // 严重打滑，几乎不信
    }
}

// EKF观测更新时，根据打滑程度调整观测噪声协方差
void ekf_update_with_slip(float slip_factor) {
    float R_base = 0.1;  // 基础观测噪声
    float R_adjusted = R_base / (slip_factor + 0.01);  // 打滑越严重，噪声越大
    // ... 执行EKF更新
}

说白了，融合的核心就是一句话：谁可靠就信谁多一点。IMU在短时间内的姿态很准，那就用它来修正航向；轮式里程计在平整地面上的位移很准，那就用它来修正位置。一旦检测到打滑或振动异常，立刻切换信任权重。

我的经验总结：IMU抗干扰不是靠单一技巧就能搞定的。温度补偿解决的是环境变化问题，振动补偿解决的是机械干扰问题，零偏修正解决的是器件自身缺陷问题，融合算法解决的是多传感器协同问题。这四个层面缺一不可。

嗯，今天就聊到这儿。IMU这东西，你越了解它的脾气，就越能驾驭它。下次遇到IMU数据异常，别急着换硬件，先看看是不是温度补偿没做好，或者振动滤波参数没调对。很多时候，软件层面的优化比换一个更贵的IMU管用得多。
