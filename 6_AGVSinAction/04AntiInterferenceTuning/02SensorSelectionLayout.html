2 传感器选型与布局：激光雷达、IMU、编码器、视觉相机的抗干扰调优

各位做AGV的同行，大家好。这一章咱们聊聊传感器的选型和布局。说实话，我见过太多项目，算法写得漂漂亮亮，结果一上路就翻车。为什么？传感器没选对，或者装的位置不对。这就像人戴了副度数不对的眼镜，看啥都是花的。

我个人习惯，做AGV导航系统第一步不是写代码，而是先画一张传感器布局图。你想想看，传感器就是AGV的眼睛和耳朵，它们要是被干扰了，整个系统就瞎了。今天我就把这些年踩过的坑、总结的经验，一次性倒给你们。

2.1 激光雷达：抗干扰的硬骨头

激光雷达这东西，精度高、测距远，但抗干扰能力其实挺脆弱的。我在一个仓储项目里遇到过，两台AGV在巷道里交汇，激光雷达互相扫到对方，结果定位直接飘了半米。嗯，这里要注意——多机场景下，激光雷达的串扰是个大问题。

干扰类型 影响程度 我的调优建议
环境光干扰（阳光/强光） 高 加装遮光罩，或选用905nm/1550nm波段雷达
多机串扰 中高 错开扫描频率（如A机15Hz，B机17Hz）
镜面/高反物体 中 安装角度倾斜5-10°，避免垂直入射
灰尘/水雾 低中 加装气吹装置，定期清洁窗口
我的经验：激光雷达安装高度建议在30-50cm。太低容易被地面杂物遮挡，太高又容易扫到货架横梁。我一般先做一次现场激光点云采集，看看哪些位置反射率异常，再定安装点。

2.2 IMU：别小看这个"小不点"

IMU这东西，体积小、成本低，但用好了是神器，用不好就是坑。说白了，IMU最怕两件事：振动和温度漂移。

我记得有个项目，AGV在粗糙地面跑，IMU数据抖得像筛子。后来我加了层硅胶减震垫，效果立竿见影。你想想看，IMU里的MEMS传感器对加速度变化极其敏感，车轮碾过一颗小石子，它都能给你记下来。

  • 安装位置：尽量靠近AGV的几何中心，远离电机和驱动轮
  • 减震方案：用3mm硅胶垫+铝合金支架，共振频率控制在50Hz以上
  • 温漂补偿：上电后静置30秒做零偏校准，我习惯每10分钟做一次在线补偿
避坑指南：我曾经把IMU直接贴在电机驱动器外壳上，结果温漂大到离谱，航向角每分钟偏3°。后来拆下来才发现，驱动器表面温度都到65°C了。IMU一定要远离热源，至少保持5cm间距。

2.3 编码器：精度高但怕打滑

编码器是AGV的"里程计"，精度很高，但有个致命弱点——打滑。AGV急加速、急刹车，或者地面有水渍油污，编码器数据就开始"说谎"了。

我一般会在AGV左右驱动轮各装一个编码器，再在从动轮上装一个辅助编码器。三个数据互相校验，哪个轮子打滑了，一算就知道。

// 编码器打滑检测伪代码
if (abs(left_encoder - right_encoder) > THRESHOLD) {
    // 左右轮差速异常，可能单侧打滑
    if (abs(aux_encoder - left_encoder) < abs(aux_encoder - right_encoder)) {
        right_wheel_slip = true;  // 右轮打滑
    } else {
        left_wheel_slip = true;   // 左轮打滑
    }
    // 切换到IMU辅助定位
    use_imu_heading = true;
}
关键参数：编码器分辨率建议不低于1000线/转，配合4倍频可到4000脉冲/转。对于直径200mm的驱动轮，每个脉冲对应约0.157mm位移，够用了。

2.4 视觉相机：光线的艺术

视觉相机在AGV上用得越来越多，但也是最"娇气"的传感器。光线一变，特征点就找不到了。我在一个物流仓库里调试时，白天和晚上的定位精度能差5cm，就是因为自然光变化导致图像过曝或欠曝。

我的解决方案是：

  • 自动曝光+补光灯：相机开启AE自动曝光，同时加装环形LED补光灯，亮度可调
  • 安装角度：相机光轴与地面呈45-60°夹角，既能看清地面纹理，又不容易被顶光直射
  • 帧率控制：室内场景15fps足够，室外高速场景建议30fps以上
小技巧：如果AGV在货架间穿行，光线忽明忽暗，可以给相机加一个ND滤镜，减少进光量波动。我试过ND8滤镜，效果不错。

2.5 冗余传感器融合策略

单一传感器总有短板，所以必须搞融合。我常用的策略是"主从+投票"模式：

  1. 主传感器：激光雷达（提供全局定位）
  2. 辅助传感器：IMU+编码器（提供短时高精度位姿）
  3. 校验传感器：视觉相机（定期修正累积误差）

说白了，就是让激光雷达当"老大"，IMU和编码器当"小弟"做高频更新，视觉相机每隔几秒检查一下大家有没有跑偏。我习惯用扩展卡尔曼滤波（EKF）做融合，状态向量包括x、y、θ、v、ω五个量。

// EKF融合核心步骤（简化版）
// 1. 预测（IMU+编码器）
x_pred = x_prev + v * cos(theta) * dt;
y_pred = y_prev + v * sin(theta) * dt;
theta_pred = theta_prev + omega * dt;

// 2. 更新（激光雷达/视觉观测）
K = P_pred * H^T * (H * P_pred * H^T + R)^(-1);
x_est = x_pred + K * (z_obs - H * x_pred);
P_est = (I - K * H) * P_pred;
注意：融合时一定要做传感器的时间戳同步。我见过一个项目，激光雷达是20Hz，IMU是100Hz，没做时间对齐，融合出来的轨迹像锯齿一样。解决办法是用硬件触发同步，或者软件插值对齐。

最后说一句，传感器布局没有标准答案，每个项目都要根据现场环境微调。但记住一个原则：冗余不是浪费，是保命。多一个传感器，就多一份容错能力。
