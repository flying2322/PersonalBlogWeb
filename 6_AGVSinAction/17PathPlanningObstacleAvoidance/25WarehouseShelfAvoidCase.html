25 工业AGV案例实战（一）——仓储AGV的货架搬运路径规划与避障

各位同学，今天咱们来聊点真家伙。

前面讲了那么多理论，什么A*、DWA、TEB，说实话，很多同学可能心里犯嘀咕：这些算法在真正的工厂里到底能不能打？

这一章，我就带大家走一遍完整的工业AGV案例。咱们选一个最常见的场景——仓储环境下的货架搬运。我当年刚入行时，第一个跟的项目就是给某电商仓库做AGV调度，那会儿踩过的坑，今天全给你们抖出来。

1. 场景定义与需求分析

先搞清楚我们要解决什么问题。

一个典型的仓储AGV搬运任务是这样的：AGV从A点（比如充电站或待命区）出发，行驶到指定货架下方，顶升起货架，然后搬运到拣选站台，最后再把货架送回原位或指定存储区。

这里面有几个关键约束：

  • 货架不可旋转：AGV顶升货架后，整体尺寸变大，转弯半径受限
  • 通道狭窄：仓储通道通常只有1.2-1.5米宽，AGV宽度约0.8米，两侧余量很小
  • 动态障碍物：可能有其他AGV、人工叉车、临时堆放的货物
  • 效率要求：单次搬运任务通常要求在30-60秒内完成路径规划

核心指标：路径规划成功率 > 99.5%，平均规划耗时 < 200ms，避障响应延迟 < 100ms。

我个人习惯，拿到需求后第一件事不是写代码，而是画一张场景拓扑图。把货架位置、通道宽度、充电站、拣选站全部标出来。你想想看，如果连地图都没吃透，规划出来的路径能靠谱吗？

2. 地图构建与分层设计

仓储AGV的地图，我建议采用三层结构：

  1. 几何层：用激光SLAM构建的2D栅格地图，分辨率5cm/pixel，用于碰撞检测
  2. 拓扑层：人工标注的节点-边网络，节点包括货架位、路口、充电站，边代表可行通道
  3. 语义层：标注货架ID、区域属性（如禁行区、低速区）、动态障碍物信息

为什么要分层？

我在项目中遇到过一个问题：直接用栅格地图做全局规划，地图一大（比如100m×100m），A*算法跑起来要好几秒，根本没法用。后来改成拓扑层做全局规划，几何层做局部优化，速度直接提升了20倍。

3. 货架搬运的路径规划策略

好，地图有了，接下来就是规划路径。仓储AGV的路径规划和普通移动机器人最大的区别在于——货架尺寸约束。

AGV顶升货架后，整体长度可能从1.2米变成2.5米。这意味着原来能通过的通道，现在可能过不去了。我见过不少新手工程师，直接在空载地图上规划路径，结果AGV顶起货架后卡在通道里，进退两难。

注意：货架搬运路径规划必须使用带载状态下的碰撞模型。AGV的轮廓要从矩形扩展为「矩形+货架」的组合多边形。

具体做法分三步：

  1. 预计算货架位姿：在拓扑地图中，对每个货架位预计算AGV顶升后的可行朝向和停靠点
  2. 分段规划：空载段用普通A*，带载段用约束A*（考虑货架外轮廓）
  3. 路径后处理：对带载路径做B样条平滑，确保曲率连续

这里我贴一段核心代码，是带载状态下的碰撞检测函数：

// 带载状态碰撞检测
bool checkCollisionWithLoad(const Pose2D& agv_pose, 
                            const std::vector<Point2D>& load_contour,
                            const GridMap& map) {
    // 1. 计算AGV本体占据的栅格
    std::vector<Point2D> agv_corners = getAgvCorners(agv_pose);
    std::vector<GridIndex> agv_cells = rasterizePolygon(agv_corners, map);
    
    // 2. 计算货架占据的栅格（相对AGV坐标偏移）
    std::vector<Point2D> load_world;
    for (const auto& pt : load_contour) {
        Point2D world_pt = transformToWorld(pt, agv_pose);
        load_world.push_back(world_pt);
    }
    std::vector<GridIndex> load_cells = rasterizePolygon(load_world, map);
    
    // 3. 合并所有占据栅格
    std::set<GridIndex> all_cells;
    all_cells.insert(agv_cells.begin(), agv_cells.end());
    all_cells.insert(load_cells.begin(), load_cells.end());
    
    // 4. 检查是否有任何栅格被占用
    for (const auto& cell : all_cells) {
        if (map.isOccupied(cell)) {
            return true;  // 发生碰撞
        }
    }
    return false;
}

这段代码看起来简单，但实际调试时坑很多。我曾经因为货架轮廓的坐标系偏移算错了5厘米，导致AGV在仓库里连续三次撞到货架腿。后来我加了一个可视化调试工具，把碰撞检测结果实时显示在Rviz上，问题才暴露出来。

4. 动态避障实战技巧

仓储环境里，动态障碍物是家常便饭。最常见的是两辆AGV在通道里迎面相遇，或者有人工叉车临时占道。

我的避障策略是分层决策：

优先级 障碍物类型 避障策略 响应时间
1（最高） 行人/突然出现的障碍物 紧急制动 + 重新规划 < 50ms
2 同向慢速AGV 减速跟随，等待超车时机 < 200ms
3 对向AGV 协商避让（靠右原则） < 500ms
4 静态障碍物（临时堆货） 局部路径绕行 < 1s

这里有个关键点：不要一遇到障碍物就重新全局规划。全局规划耗时高，而且频繁切换路径会导致AGV行驶不连贯。我的做法是：先尝试局部绕行，如果绕行失败（比如通道太窄），再触发全局重规划。

小技巧：在DWA算法中，可以给「保持当前路径方向」的轨迹增加一个偏置权重。这样AGV在避障时会更倾向于回到原路径，而不是到处乱窜。我在某项目里把这个权重从0.3调到0.7，AGV的行驶效率提升了15%。

5. 实战中的避坑指南

最后，我把自己这些年踩过的坑整理一下，你们遇到了可以直接拿来用：

  • 货架定位偏差：AGV顶升货架时，货架的实际位置和理论位置可能有2-3cm偏差。我建议在顶升后做一次局部激光定位修正，否则后续路径规划会累积误差。
  • 通道死锁：两辆AGV在狭窄通道里面对面相遇，谁也过不去。解决方案是引入「交通管制」机制——在通道入口处设置虚拟信号灯，同一时间只允许一个方向的AGV进入。
  • 路径抖动：局部规划器在避障后，路径可能会剧烈抖动。我一般会在速度指令上加一个低通滤波器，截止频率设在2-3Hz，效果立竿见影。
  • 地图更新滞后：仓储环境变化快，货架可能被移动，通道可能被临时占用。建议每5分钟做一次局部地图更新，或者用语义层标记「可疑区域」，触发重扫描。

嗯，说到地图更新，我记得有一次在客户现场，仓库主管临时挪了三个货架的位置，没通知我们。结果AGV按照旧地图规划路径，直接撞上了货架腿。从那以后，我强制要求所有AGV在启动任务前，必须做一次局部地图一致性校验。

6. 小结

这一章我们完整走了一遍仓储AGV货架搬运的实战流程。从场景分析、地图分层、带载路径规划，到动态避障策略，再到实战中的各种坑。说白了，工业AGV的核心就两件事：知道自己在哪，知道怎么安全地到想去的地方。
