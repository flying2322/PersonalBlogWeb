7 全局路径规划算法（一）：Dijkstra算法原理、伪代码、优缺点分析

各位做AGV的朋友，今天我们来聊聊路径规划里最经典的一个算法——Dijkstra。说实话，我入行那会儿，第一个认真啃下来的算法就是它。那时候还在做仓储机器人，导航地图就几十个节点，用Dijkstra跑起来绰绰有余。现在回想起来，这个算法虽然简单，但它的思想贯穿了整个路径规划领域。

你想想看，一个算法能活六十多年，至今还在各种导航系统里被广泛使用，肯定有它的独到之处。今天我就带大家把Dijkstra的底裤扒干净，从原理到实现，再到实际项目中的坑，一次性说透。

7.1 算法核心思想

Dijkstra算法要解决什么问题？说白了就是：在带权图中，找到从起点到所有其他节点的最短路径。

它的核心逻辑其实特别朴素——像水波一样，从起点一圈一圈往外扩散，每次只走当前已知最短的路径。嗯，这里要注意，它要求图中所有边的权重不能为负数。为什么？我后面会讲。

我个人习惯把Dijkstra理解成「贪心+动态规划」的混合体。贪心体现在每次选当前最优的节点，动态规划体现在用子问题的最优解来构造全局最优解。

核心思想一句话：每次从未访问的节点中，选择距离起点最近的节点，然后通过它去更新邻居节点的距离。

7.2 算法详细步骤

咱们一步步拆解，我尽量用大白话讲清楚：

  1. 初始化：把起点到自己的距离设为0，到其他所有节点的距离设为无穷大。所有节点标记为「未访问」。
  2. 选当前节点：从所有未访问的节点中，挑出距离起点最近的那个。第一次选到的肯定是起点本身。
  3. 更新邻居：遍历当前节点的所有邻居，计算「起点到当前节点的距离 + 当前节点到邻居的边的权重」。如果这个值比之前记录的邻居距离小，就更新它。
  4. 标记已访问：当前节点标记为「已访问」，以后不再考虑它。
  5. 重复：重复步骤2-4，直到所有节点都被访问过，或者目标节点被访问到（可以提前终止）。

我在项目中遇到过一个问题：当图特别大时，每次都从所有未访问节点里找最小值，效率会非常低。所以实际工程中，我们一般用优先队列（最小堆）来优化这一步。

7.3 伪代码实现

下面是我手写的伪代码风格，跟实际C++/Python实现很接近。你可以直接照着这个思路去写代码：

function Dijkstra(Graph, source):
    // 初始化
    dist[source] = 0
    for each vertex v in Graph:
        if v != source:
            dist[v] = INFINITY
        visited[v] = false
        prev[v] = null  // 记录前驱节点，用于回溯路径
    
    // 创建优先队列，按距离排序
    pq = new MinHeap()
    pq.push((0, source))
    
    while pq is not empty:
        // 取出距离最小的节点
        (d, u) = pq.pop()
        
        // 如果节点已访问，跳过（防止重复处理）
        if visited[u] == true:
            continue
        visited[u] = true
        
        // 遍历邻居
        for each neighbor v of u:
            if visited[v] == false:
                newDist = dist[u] + weight(u, v)
                if newDist < dist[v]:
                    dist[v] = newDist
                    prev[v] = u
                    pq.push((newDist, v))
    
    return dist, prev

小技巧：实际编码时，我建议用 std::priority_queue（C++）或 heapq（Python）来实现优先队列。但要注意，这些库默认是大顶堆，需要自定义比较器或者存负值来模拟小顶堆。

7.5 时间复杂度分析

这个必须搞清楚，不然你选型的时候会吃亏。我整理了一张表，方便你对比不同实现方式：

实现方式 时间复杂度 适用场景
朴素实现（数组遍历找最小） O(V²) 节点数少（V < 1000）
二叉堆优化（优先队列） O((V+E)logV) 稀疏图（E ≈ V）
斐波那契堆优化 O(VlogV + E) 稠密图（E ≈ V²）

实际项目中，我99%的情况都用二叉堆实现。斐波那契堆虽然理论更快，但常数大、实现复杂，性价比不高。你想想看，谁会为了省那点时间，去维护一个容易出bug的数据结构？

7.6 优缺点分析

做了这么多年AGV，我对Dijkstra的感情很复杂。它可靠，但有时候又让人又爱又恨。

优点

  • 保证最优解：只要图里没有负权边，它一定能找到最短路径。这一点在工业场景里非常重要——我们做AGV导航，安全性和可靠性是第一位的。
  • 实现简单：代码量少，逻辑清晰，团队里的新人也能快速上手维护。
  • 稳定性好：不会出现震荡或者不收敛的情况。我曾经在一个项目里用A*算法，启发式函数没调好，路径老是跳变，最后换回Dijkstra才稳定下来。

缺点

  • 效率偏低：没有目标导向，会向所有方向扩散。在大型地图上，它可能会探索很多无关区域。
  • 不支持负权边：这是硬伤。如果图里有负权边，Dijkstra会给出错误结果。这时候得用Bellman-Ford算法。
  • 内存占用：需要维护dist数组和visited数组，对于超大规模图（比如上百万节点），内存压力不小。

避坑指南：我曾经在一个项目中，地图里有一条「下坡路」被建模成了负权边。结果Dijkstra跑出来的路径完全不对，排查了半天才发现问题。所以，建图的时候一定要确保所有边的权重非负。如果业务上确实需要负权，那就换算法吧。

7.7 在AGV中的应用场景

Dijkstra在AGV领域最常见的用法，就是静态环境下的全局路径规划。比如：

  • 仓储地图预计算：仓库的布局相对固定，我们可以提前用Dijkstra算出所有节点对之间的最短路径，存成查找表。AGV运行时直接查表，速度飞快。
  • 多AGV协同：在调度系统中，用Dijkstra为每台AGV规划初始路径，然后再做冲突解决。
  • 拓扑地图导航：当AGV的工作区域被抽象成拓扑图（节点代表关键位置，边代表可行路径）时，Dijkstra是首选算法。

不过要注意，如果环境是动态变化的（比如有临时障碍物），Dijkstra就不太合适了。这时候需要结合局部规划器，或者用D* Lite这类增量式算法。

7.8 个人经验总结

讲了这么多，最后分享几点我的实战心得：

  • 优先队列的重复节点问题：用二叉堆实现时，同一个节点可能会被多次加入队列。一定要在弹出时检查visited标记，否则会多出很多无效计算。
  • 路径回溯：Dijkstra只给出距离值，要得到具体路径，需要维护prev数组。回溯时从目标节点反向走到起点，然后反转一下。
  • 提前终止：如果只需要起点到某个目标点的路径，可以在目标节点被访问到时立即停止。这样能节省大量计算。
  • 地图预处理：对于超大图，建议先用连通分量分析，把不可达的区域排除掉。不然Dijkstra会在死胡同里浪费很多时间。
