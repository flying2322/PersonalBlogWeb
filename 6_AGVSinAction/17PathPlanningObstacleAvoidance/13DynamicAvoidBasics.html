13 动态避障基础：障碍物检测、速度障碍法（VO）、互惠速度障碍法（RVO）

各位同学，欢迎来到动态避障这一章。

说实话，做AGV导航这么多年，我觉得最刺激的就是动态避障。静态地图规划，说白了就是解一道几何题。但动态环境不一样——行人突然横穿、其他机器人迎面而来、叉车从侧面窜出来……这些才是真正考验算法功底的地方。

今天咱们就聊聊动态避障的三个核心概念：障碍物检测、速度障碍法（VO）和互惠速度障碍法（RVO）。

13.1 障碍物检测：你得先知道“谁”在动

动态避障的第一步，不是怎么躲，而是怎么知道有东西在动。

我个人习惯把障碍物检测分成两个层面：

  • 感知层面：用传感器获取环境数据
  • 跟踪层面：判断哪些是静态的，哪些是动态的

我在项目中遇到过最头疼的问题，就是激光雷达把墙上的反光条当成了移动物体。嗯，这里要注意——传感器数据一定要做滤波和聚类。

核心思路：动态障碍物检测 = 传感器数据 + 运动状态估计

常用的传感器组合：

传感器 优点 缺点
2D激光雷达 精度高、速度快 只能检测同一平面
3D激光雷达 三维信息完整 成本高、数据量大
深度相机 成本低、信息丰富 受光照影响大
超声波 近距离可靠 分辨率低

你想想看，如果传感器数据都不靠谱，后面再牛的避障算法也是白搭。所以我的建议是：先花70%的精力搞定感知，再花30%的精力做规划。

13.2 速度障碍法（VO）：一个很直观的想法

速度障碍法，英文叫Velocity Obstacle，简称VO。这玩意儿是1998年由Fiorini和Shiller提出的，到现在快30年了，依然是动态避障的基石。

VO的核心思想是什么？说白了就是一句话：找出那些会让你撞车的速度，然后避开它们。

怎么找？咱们一步步来：

  1. 计算相对速度：把机器人和障碍物的速度放到同一个坐标系里
  2. 构建碰撞锥：如果相对速度指向障碍物，就会撞上
  3. 映射到速度空间：把所有会导致碰撞的速度标出来，这就是VO区域
  4. 选择安全速度：在VO区域之外选一个速度

小技巧：实际工程中，我们通常会把机器人膨胀成一个圆，障碍物也膨胀成一个圆。这样碰撞检测就变成了圆与圆之间的相交判断，计算量小很多。

我曾经在一个仓储项目里直接用VO，结果发现机器人经常“犹豫不决”——因为VO只考虑当前时刻，没有考虑未来。后来我加了一个预测窗口，效果就好多了。

下面是一个简化的VO实现思路：

// 伪代码：速度障碍法核心逻辑
function computeVO(robot, obstacle):
    // 1. 计算相对位置和速度
    relPos = obstacle.pos - robot.pos
    relVel = obstacle.vel - robot.vel
    
    // 2. 构建碰撞锥
    collisionCone = buildCone(relPos, robot.radius + obstacle.radius)
    
    // 3. 判断当前相对速度是否在碰撞锥内
    if isInside(relVel, collisionCone):
        // 4. 如果会撞，找安全速度
        safeVel = findSafeVelocity(robot.vel, collisionCone)
        return safeVel
    else:
        return robot.vel  // 安全，保持原速

13.3 互惠速度障碍法（RVO）：让双方都动起来

VO有个大问题——它假设障碍物不会主动避让。这在多机器人场景下就尴尬了：两个机器人都用VO，结果互相让来让去，最后卡在原地不动。

这就是所谓的“振荡”现象。你想想看，两个人在走廊里迎面走来，都往左边让，结果又撞上了，再同时往右边让……是不是很熟悉？

互惠速度障碍法（Reciprocal Velocity Obstacle，RVO）就是来解决这个问题的。它的核心思想是：每个机器人承担一半的避让责任。

RVO vs VO 的关键区别：

  • VO：我躲你，你不动
  • RVO：我躲一半，你躲一半

具体怎么做？RVO把VO区域平移了一半。也就是说，每个机器人只需要避开一半的碰撞速度，剩下的另一半由对方负责。

我曾经在一个多AGV协同的项目里测试过：

  • 用VO：4台机器人就开始振荡，8台直接死锁
  • 用RVO：8台机器人流畅运行，16台才出现轻微拥堵

嗯，这就是互惠的魅力。

RVO的伪代码：

// 伪代码：互惠速度障碍法核心逻辑
function computeRVO(robot, obstacle):
    // 1. 计算VO（和之前一样）
    vo = computeVO(robot, obstacle)
    
    // 2. 关键步骤：将VO平移一半
    // 每个机器人只承担一半的避让责任
    rvo = translate(vo, (robot.vel + obstacle.vel) / 2)
    
    // 3. 在RVO区域外选择速度
    safeVel = findSafeVelocity(robot.vel, rvo)
    
    return safeVel

注意：RVO虽然解决了振荡问题，但它假设所有机器人都在使用相同的避让策略。如果遇到不按套路出牌的行人，RVO的效果会打折扣。这时候需要结合预测模型或者学习算法。

13.5 实战中的几个坑

最后，分享几个我在实际项目中踩过的坑：

  • 传感器延迟：激光雷达扫描一圈要50ms，这50ms里障碍物可能已经移动了。一定要做运动补偿。
  • 速度突变：VO/RVO算出来的速度可能变化很大，直接发给电机的话，机器人会“抽搐”。加个速度平滑滤波器会好很多。
  • 局部最优：VO/RVO都是局部方法，可能会陷入死胡同。需要和全局规划器配合使用。

我的经验：在实际部署时，我会把VO/RVO的输出作为“建议速度”，然后加一个安全校验层。如果建议速度会导致碰撞，就降速或者停车。安全第一，效率第二。

好了，动态避障的基础就讲到这里。记住一句话：避障不是目的，安全高效地到达目的地才是。
