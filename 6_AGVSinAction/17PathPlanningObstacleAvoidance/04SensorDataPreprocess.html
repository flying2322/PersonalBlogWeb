4 传感器基础与数据预处理

各位同学好，我是你们的老朋友。今天我们来聊聊AGV的「感官系统」——传感器。

做AGV这么多年，我最大的体会就是：算法再牛，传感器数据不行，一切都是白搭。就像一个人眼神不好，跑得再快也容易撞墙。所以这一节，我们好好掰扯掰扯激光雷达、IMU、编码器、深度相机这些家伙到底怎么工作，数据长什么样，又该怎么「洗」干净。

4.1 激光雷达：AGV的「眼睛」

激光雷达，说白了就是靠发射激光束，测量反射回来的时间，算出距离。我最早接触的是单线雷达，只能扫一个平面，但做AGV导航已经够用了。

核心原理：TOF（飞行时间法）或三角测距法。TOF精度高，抗干扰强，现在主流都用它。

数据格式：通常是一组极坐标点 (角度, 距离)，或者直接是 (x, y) 坐标。比如一个16线雷达，每秒能出30万个点。

// 典型的激光雷达数据帧结构
struct LaserScan {
    float angle_min;      // 起始角度 (rad)
    float angle_max;      // 终止角度
    float angle_increment; // 角度分辨率
    float[] ranges;       // 距离数组 (m)
    float[] intensities;  // 反射强度 (可选)
};

我的经验：我在项目里遇到过玻璃墙和黑色物体反射率低的问题。玻璃会透光，黑色吸光，导致数据丢失。后来我加了多回波检测，才勉强搞定。

4.2 IMU：AGV的「内耳」

IMU（惯性测量单元）包含加速度计和陀螺仪。加速度计测线加速度，陀螺仪测角速度。两者融合，就能得到姿态和位移。

但IMU有个致命缺点——漂移。你想想看，加速度积分一次得速度，再积分得位移，误差会像滚雪球一样越来越大。所以IMU只能做短时辅助，不能单独用。

避坑指南：我曾经在一个项目里只用IMU做定位，结果跑了10米就偏了半米。后来老老实实加了激光雷达做修正。记住：IMU是「短跑冠军」，不是「马拉松选手」。

数据格式：通常包含时间戳、三轴加速度、三轴角速度，有时还有磁力计数据。

// IMU数据帧
struct ImuData {
    double timestamp;
    float accel_x, accel_y, accel_z;  // m/s²
    float gyro_x, gyro_y, gyro_z;     // rad/s
    float mag_x, mag_y, mag_z;        // μT (可选)
};

4.3 编码器：AGV的「脚步计数器」

编码器装在电机上，每转一圈输出固定数量的脉冲。通过脉冲数，我们能算出轮子转了多少圈，进而推算位移。

这东西看着简单，但坑不少。比如轮子打滑、地面不平、轮胎磨损，都会导致里程计误差。我见过一个项目，编码器算出来走了100米，实际只走了95米——因为地面有水，轮子一直在空转。

传感器 优点 缺点
激光雷达 精度高，范围广 受反射率影响，成本高
IMU 不受外界干扰 漂移严重
编码器 简单可靠，成本低 打滑误差，累积误差
深度相机 信息丰富，可识别物体 受光照影响大，视野有限

4.4 深度相机：AGV的「立体视觉」

深度相机能直接输出每个像素的深度值，相当于给普通相机加了个「测距」功能。常见的有结构光（如Kinect v1）和TOF（如Kinect v2）两种。

深度相机的好处是能识别障碍物的形状，比如桌子腿、箱子。但坏处也很明显——在强光下基本废掉。我试过在室外大太阳底下用深度相机，结果全是噪点，根本没法用。

数据格式：深度图是一张灰度图，每个像素值代表该点的深度（毫米）。通常配合RGB图一起使用，形成RGB-D数据。

// 深度相机数据
struct DepthFrame {
    int width, height;           // 图像尺寸
    uint16_t* depth_data;        // 深度数组 (mm)
    uint8_t* rgb_data;           // RGB图像 (可选)
    float fx, fy, cx, cy;       // 相机内参
};

4.5 数据预处理：把「脏数据」洗干净

传感器数据天生就有噪声。激光雷达有飞点，IMU有高频振动，编码器有量化误差，深度相机有空洞。所以预处理是必须的。

4.5.1 滤波与去噪

我常用的滤波方法有几种：

  • 中值滤波：对付激光雷达的飞点特别有效。取周围几个点的中值，能干掉孤立的噪声点。
  • 高斯滤波：适合平滑连续数据，比如IMU的加速度信号。但注意别把真实突变也平滑掉了。
  • 卡尔曼滤波：这是重头戏。它能把多个传感器的数据融合起来，得到最优估计。我后面会专门讲。

我的习惯：做滤波前，先画个数据分布图看看。如果噪声是高斯分布，用卡尔曼；如果是脉冲噪声，用中值。别一上来就套算法，先观察数据特征。

4.5.2 时间同步

不同传感器的采样频率不一样。激光雷达10Hz，IMU 100Hz，编码器可能1000Hz。如果不做时间同步，融合出来的数据就是「鸡同鸭讲」。

我一般用两种方法：

  1. 硬同步：用硬件触发信号，让所有传感器同时采集。精度高，但需要硬件支持。
  2. 软同步：在软件里用时间戳插值。比如激光雷达来了，找最近的两个IMU数据做线性插值。

4.5.3 坐标变换

每个传感器都有自己的坐标系。激光雷达在车头，IMU在车中心，编码器在轮子上。要统一到一个坐标系下，才能正确融合。

这步看似简单，但最容易出错。我见过一个团队，因为激光雷达的安装角度标定错了，导致建图全是歪的。后来花了三天才找到原因。

避坑指南：坐标变换的参数一定要用标定工具算，别用手量。我推荐用ROS的tf工具包，或者自己写个最小二乘标定程序。千万别偷懒。

4.7 小结

这一节我们聊了四种核心传感器的工作原理和数据格式，也讲了滤波、同步、坐标变换这些预处理手段。说实话，传感器这块没有太多捷径，就是多动手、多踩坑。

我个人建议，刚开始做AGV的同学，先拿一个激光雷达和编码器练手，把数据读出来、画出来、滤波看看效果。等熟悉了，再加IMU和深度相机。一步一步来，别贪多。

好了，今天就到这里。记住：数据是算法的基石，把传感器数据搞干净了，后面的路径规划才能跑得稳。
