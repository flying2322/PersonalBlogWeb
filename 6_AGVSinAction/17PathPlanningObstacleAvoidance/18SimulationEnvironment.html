18 仿真环境搭建——Gazebo仿真世界构建、TurtleBot3/自定义AGV模型导入、传感器仿真

说实话，做AGV导航这么多年，我踩过最大的坑就是——真机调试太贵了。

有一次在客户现场，AGV直接怼上了货架腿，修车花了三天，还被甲方爸爸骂了一顿。从那以后，我养成了一个习惯：所有导航算法，先在Gazebo里跑三天，再上真车。

这一章，我就带你搭一套完整的仿真环境。说白了，就是让你在电脑里先造一个虚拟工厂，把AGV放进去跑。你想想看，撞坏了也不用赔钱，多好。

本章核心目标：掌握Gazebo仿真世界的构建方法，学会导入TurtleBot3及自定义AGV模型，并配置激光雷达、IMU、里程计等传感器仿真。

18.1 为什么非要用Gazebo？

我个人习惯用Gazebo，原因有三：

  • 物理引擎真实：摩擦力、碰撞、重力都模拟得不错。我在项目中遇到过，真机上AGV打滑，Gazebo里也能复现出来。
  • 传感器仿真成熟：激光雷达、深度相机、IMU都有现成的插件，不用自己造轮子。
  • 和ROS无缝集成：你写的路径规划代码，在Gazebo里直接跑，不需要改一行。

嗯，这里要注意：Gazebo不是游戏引擎，它是个严肃的机器人仿真器。别指望画面多好看，但数据绝对靠谱。

18.2 搭建你的第一个仿真世界

我们先从零开始，搭一个简单的测试环境。我一般叫它test_world.world。

<?xml version="1.0" ?>
<sdf version="1.6">
  <world name="agv_test_world">
    <include>
      <uri>model://sun</uri>
    </include>
    <include>
      <uri>model://ground_plane</uri>
    </include>

    <!-- 添加几个障碍物 -->
    <model name="obstacle_1">
      <pose>2.0 1.0 0.5 0 0 0</pose>
      <link name="body">
        <collision name="collision">
          <geometry>
            <box>
              <size>0.5 0.5 1.0</size>
            </box>
          </geometry>
        </collision>
        <visual name="visual">
          <geometry>
            <box>
              <size>0.5 0.5 1.0</size>
            </box>
          </geometry>
        </visual>
      </link>
    </model>

    <!-- 添加墙壁 -->
    <model name="wall">
      <pose>0.0 3.0 0.5 0 0 0</pose>
      <link name="body">
        <collision name="collision">
          <geometry>
            <box>
              <size>6.0 0.2 1.0</size>
            </box>
          </geometry>
        </collision>
        <visual name="visual">
          <geometry>
            <box>
              <size>6.0 0.2 1.0</size>
            </box>
          </geometry>
        </visual>
      </link>
    </model>
  </world>
</sdf>

这段代码干了三件事：加了个太阳（照明）、加了个地面、加了几个障碍物。你把它保存成.world文件，然后用gazebo test_world.world启动，就能看到一个简陋但可用的仿真环境了。

我的小技巧：刚开始别搞太复杂。先放两个箱子，让AGV能绕过去就行。等算法调通了，再慢慢加货架、人模、叉车什么的。

18.3 导入TurtleBot3——最省心的入门方案

TurtleBot3是ROS生态里最经典的移动机器人平台。我建议新手先用它，因为所有传感器配置都是现成的。

安装步骤很简单：

sudo apt install ros-noetic-turtlebot3-gazebo
export TURTLEBOT3_MODEL=burger
roslaunch turtlebot3_gazebo turtlebot3_world.launch

启动后，你会看到一个小圆机器人，带着激光雷达，在迷宫里转悠。这时候你打开rviz，就能看到激光点云数据了。

我曾经用这个环境测试A*算法，跑了整整两天，发现了一个bug——机器人在窄通道里会卡住。后来在真车上也验证了这个问题。你看，仿真环境的价值就在这里。

18.4 自定义AGV模型——从零到一

但实际项目中，你不可能用TurtleBot3去搬货。你得有自己的AGV模型。

我一般用URDF（Unified Robot Description Format）来描述机器人。说白了，就是告诉Gazebo：你的机器人长什么样、轮子多大、传感器装在哪。

下面是一个简化版的自定义AGV模型：

<robot name="my_agv">
  <link name="base_link">
    <visual>
      <geometry>
        <box size="0.8 0.6 0.3"/>
      </geometry>
      <origin rpy="0 0 0" xyz="0 0 0.15"/>
    </visual>
    <collision>
      <geometry>
        <box size="0.8 0.6 0.3"/>
      </geometry>
    </collision>
  </link>

  <!-- 左轮 -->
  <link name="left_wheel">
    <visual>
      <geometry>
        <cylinder radius="0.1" length="0.05"/>
      </geometry>
    </visual>
  </link>

  <joint name="left_wheel_joint" type="continuous">
    <parent link="base_link"/>
    <child link="left_wheel"/>
    <origin rpy="0 0 0" xyz="-0.3 0.35 -0.1"/>
    <axis xyz="0 1 0"/>
  </joint>

  <!-- 右轮类似，省略 -->

  <!-- 激光雷达 -->
  <link name="laser_link">
    <visual>
      <geometry>
        <cylinder radius="0.03" length="0.05"/>
      </geometry>
    </visual>
  </link>

  <joint name="laser_joint" type="fixed">
    <parent link="base_link"/>
    <child link="laser_link"/>
    <origin rpy="0 0 0" xyz="0.3 0 0.2"/>
  </joint>
</robot>

这个模型很简单：一个长方形的底盘，两个轮子，头顶一个激光雷达。你把它保存成.urdf文件，然后在Gazebo里加载：

rosrun gazebo_ros spawn_model -file my_agv.urdf -urdf -model my_agv

注意：URDF里一定要定义<collision>标签，否则Gazebo不会检测碰撞。我曾经忘了加，结果AGV直接穿墙而过，找了半天bug才发现。

18.5 传感器仿真配置

AGV导航最常用的传感器就三种：激光雷达、IMU、里程计。Gazebo里都有现成的插件。

18.5.1 激光雷达（Lidar）

我一般用gazebo_ros_ray_sensor插件。配置如下：

<gazebo reference="laser_link">
  <sensor type="ray" name="head_laser">
    <pose>0 0 0 0 0 0</pose>
    <visualize>true</visualize>
    <update_rate>10</update_rate>
    <ray>
      <scan>
        <horizontal>
          <samples>360</samples>
          <resolution>1</resolution>
          <min_angle>-3.14159</min_angle>
          <max_angle>3.14159</max_angle>
        </horizontal>
      </scan>
      <range>
        <min>0.1</min>
        <max>10.0</max>
        <resolution>0.01</resolution>
      </range>
    </ray>
    <plugin name="laser_controller" filename="libgazebo_ros_laser.so">
      <topicName>/scan</topicName>
      <frameName>laser_link</frameName>
    </plugin>
  </sensor>
</gazebo>

这里的关键参数：samples=360表示360度扫描，max=10.0表示最远测距10米。你想想看，这跟真实激光雷达的参数已经很接近了。

18.5.2 IMU仿真

IMU插件更简单：

<gazebo>
  <plugin name="imu_plugin" filename="libgazebo_ros_imu.so">
    <topicName>/imu</topicName>
    <frameName>base_link</frameName>
    <updateRate>100.0</updateRate>
  </plugin>
</gazebo>

IMU数据在AGV导航里主要用来做航迹推算。但说实话，Gazebo仿真的IMU太理想了，没有噪声。我一般会在代码里手动加一点高斯噪声，模拟真实传感器。

18.5.3 里程计（Odometry）

里程计通常由轮式编码器推算。Gazebo里可以通过libgazebo_ros_p3d.so插件发布地面真值位置，然后我们自己加噪声模拟编码器数据。

<gazebo>
  <plugin name="p3d_plugin" filename="libgazebo_ros_p3d.so">
    <frameName>odom</frameName>
    <topicName>/ground_truth</topicName>
    <updateRate>50.0</updateRate>
  </plugin>
</gazebo>

我的经验：在仿真里，我习惯同时订阅/ground_truth和/odom两个话题。前者用来评估算法精度，后者用来做实际控制。这样能清楚看到里程计漂移对导航的影响。

18.7 避坑指南

最后，分享几个我踩过的坑：

  • 模型加载失败：检查URDF里的路径是不是绝对路径。Gazebo有时候不认相对路径。
  • 传感器没数据：看看update_rate是不是设得太低了。我曾经设成0.1Hz，等了一分钟才看到数据。
  • 机器人原地打转：检查轮子的<joint>类型。如果是revolute，轮子转不动。要用continuous。
  • 碰撞检测失效：确认<collision>标签的几何体大小和<visual>一致。有时候视觉看着撞上了，但碰撞体太小，就穿模了。

嗯，这一章的内容就到这里。仿真环境搭好了，下一章我们就能真正开始写路径规划算法了。记住：仿真跑不出来的算法，真机上一定跑不出来。别偷懒，好好搭环境。
