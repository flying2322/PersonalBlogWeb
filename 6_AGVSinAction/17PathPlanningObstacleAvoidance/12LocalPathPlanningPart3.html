12 局部路径规划算法（三）——模型预测控制（MPC）在路径跟踪中的应用

各位好，欢迎来到局部路径规划的第三讲。前两讲我们聊了DWA和TEB，今天要聊的MPC，可以说是局部规划里的「重武器」了。

说实话，我第一次接触MPC是在做AGV高速跟踪的项目时。当时用纯跟踪算法，低速还行，速度一上来，车就开始「画龙」。后来换成MPC，效果立竿见影。嗯，今天我就把这块的经验掰开揉碎了讲给你听。

12.1 为什么需要MPC？

先问个问题：DWA和TEB不好吗？

好，但不够「前瞻」。DWA只看未来几秒内的速度窗口，TEB虽然考虑了时间，但本质上还是基于当前状态做优化。说白了，它们都是「近视眼」。

MPC不一样。它像下棋一样，会往前看很多步。每走一步，都重新算一遍未来N步的最优轨迹。这种「滚动优化」的机制，让它在高速、大曲率路径下表现特别稳。

我在项目中遇到过最典型的场景：AGV在仓库里以2m/s的速度过直角弯。用DWA时，每次到弯道前都要急刹车，效率很低。换成MPC后，它能提前预判弯道曲率，平滑减速过弯，效率提升了30%以上。

12.2 MPC的核心思想

MPC说白了就三步：

  1. 预测模型：用数学模型预测未来N步的状态
  2. 滚动优化：在每个控制周期，求解一个有限时域的最优控制问题
  3. 反馈校正：只执行第一步的控制量，然后重新预测、优化

你想想看，这像不像我们开车时的操作？眼睛看着前方100米的路况，心里盘算着接下来几秒怎么打方向盘，然后只执行当前这一秒的动作。到了下一秒，再重新评估。

MPC vs 其他算法的核心区别：

  • DWA/TEB：开环控制，一次规划到底
  • MPC：闭环控制，每步都在重新规划

12.3 预测模型怎么建？

这里我以差速AGV为例，讲最常用的运动学模型。

差速AGV的状态量通常取：[x, y, θ, v, ω]，其中x、y是位置，θ是朝向，v是线速度，ω是角速度。

离散化的运动学方程长这样：

x(k+1) = x(k) + v(k)*cos(θ(k))*dt
y(k+1) = y(k) + v(k)*sin(θ(k))*dt
θ(k+1) = θ(k) + ω(k)*dt
v(k+1) = v(k) + a(k)*dt
ω(k+1) = ω(k) + α(k)*dt

其中a是线加速度，α是角加速度，这两个是控制量。

我个人习惯把控制量设为加速度，而不是直接设速度。为什么？因为加速度更接近真实的电机控制接口，而且能自然地限制加加速度，让轨迹更平滑。

12.4 优化问题的构建

MPC的核心是一个优化问题。目标函数通常包含三部分：

  1. 路径跟踪误差：让AGV尽量贴近参考路径
  2. 控制量惩罚：避免猛打方向盘或急加速
  3. 终端代价：保证最终状态收敛

我常用的目标函数形式：

min J = Σ (w1 * e_pos² + w2 * e_heading²) 
       + Σ (w3 * a² + w4 * α²) 
       + w5 * e_terminal²

其中e_pos是位置误差，e_heading是朝向误差。

约束条件也很关键：

  • 速度限制：v_min ≤ v ≤ v_max
  • 加速度限制：a_min ≤ a ≤ a_max
  • 角速度限制：ω_min ≤ ω ≤ ω_max
  • 避障约束：距离障碍物≥安全距离

避坑指南：我曾经在调MPC时，只加了速度约束没加加速度约束。结果AGV在急转弯时，虽然速度没超限，但加速度突变导致电机过载。后来加上加速度约束，问题就解决了。

12.5 求解器怎么选？

MPC的优化问题通常是非线性、带约束的。求解器的选择直接影响实时性。

求解器类型优点缺点适用场景
OSQP速度快，适合二次规划只能处理线性约束线性MPC
ACADO支持非线性，代码生成配置复杂非线性MPC
CasADi灵活，支持多种求解器后端学习曲线陡研究原型
自定义SQP完全可控，轻量开发工作量大嵌入式平台

我个人在工业项目中最常用的是OSQP。因为大部分场景下，把运动学模型线性化后，用二次规划就能得到不错的效果。而且OSQP的C语言接口，在STM32这类MCU上也能跑。

12.6 实战中的调参经验

调MPC参数，说白了就是调权重矩阵。我总结了一个「三步调参法」：

  1. 先调跟踪权重：把w1、w2调大，让AGV能跟上路径。这时候车可能会抖，没关系。
  2. 再调平滑权重：逐步增加w3、w4，直到轨迹变得平滑。注意不要加太多，否则跟踪误差会变大。
  3. 最后调预测时域：预测步数N太小，前瞻性不够；N太大，计算量爆炸。我一般从10步开始试，根据CPU负载往上加。

注意：预测时域N和采样时间dt是联动的。N*dt就是总的预测时间。比如dt=0.1s，N=20，那么预测未来2秒。这个时间要覆盖AGV从当前速度到完全刹停的距离。

12.7 避障怎么融入MPC？

MPC做避障，最直接的方法是把障碍物距离作为约束加进去。

对于圆形障碍物，约束可以写成：

(x(k) - x_obs)² + (y(k) - y_obs)² ≥ r_safe²

但这个约束是非线性的，求解起来比较慢。我常用的技巧是把它线性化：

n_x * (x(k) - x_obs) + n_y * (y(k) - y_obs) ≥ r_safe

其中n_x、n_y是障碍物指向AGV的单位方向向量。这样就把非线性约束变成了线性约束，求解速度快很多。

嗯，这里要注意：线性化后的约束只在当前时刻附近有效。如果障碍物突然出现，可能需要重新线性化。我在项目中遇到过这种情况，后来加了一个「约束更新」的机制，每步都重新计算线性化点。

12.9 一个简单的代码框架

下面是一个MPC路径跟踪的伪代码框架，我用的是类似C++的语法：

// MPC主循环
while (running) {
    // 1. 获取当前状态
    State current = getRobotState();
    
    // 2. 获取参考轨迹（未来N步）
    vector<State> ref = getReferenceTrajectory(current, N);
    
    // 3. 构建优化问题
    MPCProblem problem;
    problem.setModel(motionModel);
    problem.setCost(weights);
    problem.setConstraints(velocityLimits, accelerationLimits);
    
    // 4. 添加避障约束
    for (auto& obs : obstacles) {
        problem.addObstacleConstraint(obs, current);
    }
    
    // 5. 求解
    MPCSolution sol = solver.solve(problem);
    
    // 6. 只执行第一步
    Control cmd = sol.controls[0];
    sendControl(cmd);
    
    // 7. 等待下一个控制周期
    sleep(dt);
}

这个框架看起来简单，但实际工程中坑不少。比如求解失败时的fallback策略、约束冲突时的松弛处理，这些都需要仔细设计。

我的经验：刚开始做MPC时，别追求一步到位。先跑通线性MPC，再慢慢加非线性项。我见过太多人一上来就搞非线性MPC，结果调了两个月还没跑起来。

12.10 总结

MPC在路径跟踪中的优势很明显：前瞻性强、能处理约束、闭环稳定。但代价是计算量大、调参复杂。

如果你现在做的项目对实时性要求极高（比如1ms控制周期），那MPC可能不太合适。但如果你的控制周期在10ms以上，而且路径曲率变化大，MPC绝对值得一试。
