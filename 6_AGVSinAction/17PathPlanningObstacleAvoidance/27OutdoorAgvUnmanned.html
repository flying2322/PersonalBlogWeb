27 室外AGV与无人车：GPS融合、高精地图、复杂交通场景下的路径规划

说实话，做室内AGV做了五六年，第一次接到室外项目时，我心里是有点发怵的。室内环境再复杂，好歹有墙有柱子，激光雷达一打，地图结构清晰。室外呢？GPS信号飘忽不定，路面起伏不平，还有行人、自行车、汽车跟你抢道。嗯，这完全是另一个维度的挑战。

今天我们就聊聊室外AGV和无人车的导航问题。核心就三件事：GPS怎么跟其他传感器融合、高精地图怎么做、复杂交通场景下怎么规划路径。这三件事搞定了，室外导航的基本盘就稳了。

27.1 GPS融合定位：别只信GPS

先说说GPS。很多人觉得GPS就是定位神器，其实不然。我在一个港口AGV项目里吃过亏——当时车辆在集装箱堆场里跑，GPS信号被集装箱遮挡，定位误差直接飙到十几米。AGV差点撞上货架，吓得我赶紧加了IMU和轮式里程计做融合。

室外定位，我个人的习惯是：GPS + IMU + 轮式里程计 + 视觉/激光，四者融合。为什么？因为每个传感器都有短板：

传感器 优势 短板
GPS 全局无漂移，长期稳定 信号遮挡、多路径效应、更新频率低（10Hz）
IMU 高频（100Hz+），短时精度高 积分漂移，长期不可靠
轮式里程计 地面速度准确，无累积漂移 打滑时失效
激光/视觉 相对定位精度高，可做地图匹配 计算量大，特征稀疏时失效

融合的核心思想很简单：用GPS校正长期漂移，用IMU和里程计填充短期高频。最常用的方法是扩展卡尔曼滤波（EKF）或因子图优化。

给你看一段我常用的EKF融合伪代码：

// 预测步骤（IMU + 里程计）
void predict(State &x, Covariance &P, double dt) {
    // 状态预测：x = f(x, u)
    x.position += x.velocity * dt;
    x.velocity += imu.acceleration * dt;
    x.orientation = integrateGyro(imu.gyro, dt);
    
    // 协方差预测：P = F * P * F^T + Q
    Matrix F = computeJacobian(x, dt);
    P = F * P * F.transpose() + processNoise;
}

// 更新步骤（GPS观测）
void update(State &x, Covariance &P, GPSObservation z) {
    // 观测残差
    Vector y = z.position - x.position;
    
    // 卡尔曼增益
    Matrix H = I;  // 观测矩阵
    Matrix S = H * P * H.transpose() + R_gps;
    Matrix K = P * H.transpose() * S.inverse();
    
    // 状态更新
    x += K * y;
    P = (I - K * H) * P;
}
我的经验：GPS的协方差矩阵R不要设成固定值。我一般根据GPS的HDOP（水平精度因子）动态调整——信号好时R设小，信号差时R设大。这样融合出来的轨迹更平滑，不会出现GPS跳变导致的急转弯。

27.2 高精地图：不只是画几条线

室内AGV用的地图，通常是二维栅格地图或者特征地图。但室外不行。你想想看，室外道路有车道线、有红绿灯、有路沿、有坡度，光靠一个二维栅格根本不够用。

高精地图（HD Map）说白了就是给无人车看的“超详细导航图”。它包含三层信息：

  1. 道路层：车道中心线、车道边界、交叉口拓扑
  2. 语义层：红绿灯位置、停止线、限速标志、人行横道
  3. 定位层：路标、杆状物、地面纹理等可匹配特征

我在一个园区物流项目里，自己搭了一套高精地图制作流程。核心步骤是这样的：

// 高精地图制作流程（简化版）
1. 数据采集：用装有RTK-GPS + 激光雷达 + 相机的采集车跑一遍
2. 点云建图：用LOAM或LIO-SAM生成高精度点云地图
3. 语义标注：人工或自动标注车道线、路沿、标志牌
4. 拓扑生成：提取车道中心线，构建路网拓扑
5. 定位特征提取：提取杆状物、地面纹理等用于定位匹配
6. 地图发布：以OpenDRIVE或Lanelet2格式存储
注意：高精地图的更新是个大坑。道路施工、临时封路、季节变化（比如落叶遮挡地面纹理）都会导致地图失效。我曾经因为没及时更新地图，AGV在一条新画了车道线的路上跑偏了。后来我加了一个在线地图更新模块——车辆运行时实时检测地图变化，自动标记可疑区域，回传后台人工确认。

27.3 复杂交通场景下的路径规划

好了，定位有了，地图有了，接下来就是怎么走了。室外交通场景比室内复杂得多——有交叉口、有环岛、有行人横穿、有对向车辆。路径规划不能只考虑最短路径，还得考虑交通规则和交互博弈。

我一般把室外路径规划分成三层：

  • 全局规划：基于路网拓扑，用A*或Dijkstra找一条符合交通规则的最优路径
  • 行为规划：决定当前该跟车、变道、还是停车让行
  • 局部规划：生成平滑、无碰撞的轨迹，考虑动力学约束

这里重点说说行为规划。室内AGV基本不需要“决策”——跟着路径走就行。但室外不行。举个例子：

你的AGV要左转，对面有直行车辆。按交规，你得让行。但让多久？对方减速了，你是继续等还是加速通过？这就是博弈问题。

我常用的方法是有限状态机 + 速度障碍法：

// 行为规划状态机
enum BehaviorState {
    FOLLOW_LANE,    // 车道保持
    STOP_AND_WAIT,  // 停车等待
    YIELD,          // 让行
    CROSS_INTERSECTION, // 通过交叉口
    EMERGENCY_STOP  // 紧急停车
};

// 速度障碍法判断是否碰撞
bool willCollide(VehicleState ego, VehicleState other, double dt) {
    // 计算相对速度
    Vector relVel = ego.velocity - other.velocity;
    // 计算相对位置
    Vector relPos = other.position - ego.position;
    // 判断相对速度方向是否指向碰撞区域
    double angle = angleBetween(relVel, relPos);
    double collisionCone = atan2(ego.radius + other.radius, 
                                  norm(relPos));
    return abs(angle) < collisionCone;
}

核心思路：状态机负责“该做什么”，速度障碍法负责“能不能做”。两者结合，就能在复杂交通场景下做出合理的决策。

27.5 避坑指南与实战建议

最后，分享几个我在室外AGV项目里踩过的坑：

  • GPS信号丢失怎么办？ 我曾经在隧道里测试，GPS一丢，定位直接崩了。后来我加了视觉里程计作为备份——GPS信号好时用GPS，信号差时自动切换到视觉里程计，等GPS恢复后再融合回来。
  • 高精地图更新不及时 前面提过，道路施工是常态。我的做法是：车辆运行时，用激光雷达实时检测地图变化。如果发现新障碍物或道路边界变化，自动标记并上传，后台人工审核后更新地图。
  • 行人横穿怎么处理？ 别指望行人会按规则走。我见过行人突然从盲区冲出来的情况。我的策略是：预测 + 保守。用卡尔曼滤波预测行人轨迹，如果预测轨迹与AGV路径有交集，提前减速到安全速度，而不是等到跟前才急刹。
  • 交叉口博弈 这个最头疼。我的经验是：让行规则写死，但执行时加一点“侵略性”。比如左转时，如果对向车辆距离还远，就正常通过；如果距离近，就停车让行。但不要让行太久——超过3秒还没通过，就缓慢前移，逼对方减速。

一个小技巧：室外AGV的路径规划，我建议把安全距离设得比室内大一些。室内我一般设0.5米，室外我设1.0米以上。为什么？室外路面不平，刹车距离变长，而且行人、自行车的行为不可预测。多留点余量，总比撞上强。

好了，关于室外AGV和无人车的导航，今天就聊到这儿。核心就三句话：定位要融合，地图要精细，规划要懂规则。把这三点吃透了，室外导航就不再是难题。
