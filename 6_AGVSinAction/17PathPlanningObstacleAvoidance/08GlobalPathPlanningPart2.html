8 全局路径规划算法（二）——A*算法原理、启发函数设计、优化技巧

各位同学，欢迎来到第八讲。上一讲我们聊了Dijkstra，那个老老实实、地毯式搜索的算法。今天要讲的A*，可以说是Dijkstra的“升级版”——它多了个“脑子”，知道往哪个方向找更划算。

我个人做AGV项目这么多年，用得最多的全局规划算法就是A*。不是说它完美，而是它在效率和最优性之间找到了一个很好的平衡点。你想想看，工厂里几百台AGV同时跑，每台都要实时规划路径，计算量稍微大一点，调度系统就卡死了。A*在这种场景下，表现相当靠谱。

8.1 A*算法的核心思想

A*本质上是一种启发式搜索算法。它跟Dijkstra最大的区别在于：Dijkstra只考虑“从起点走到当前点花了多少代价”，而A*还考虑了“从当前点到终点大概还要花多少代价”。

这个“大概还要花多少代价”，就是我们说的启发函数（Heuristic Function）。

A*的代价评估公式很简单：

f(n) = g(n) + h(n)
  • f(n)：节点n的总评估代价
  • g(n)：从起点到节点n的实际代价
  • h(n)：从节点n到终点的估计代价（启发函数）

算法每次从open list中取出f(n)最小的节点进行扩展。说白了，就是“既要看走过的路，也要看没走的路”。

核心理解：如果h(n)=0，A*就退化成Dijkstra。如果h(n)比实际代价大很多，A*就变成贪心算法，速度快但不保证最优。所以，启发函数的设计是A*的灵魂。

8.2 启发函数的设计

启发函数怎么选？这取决于你的地图类型和运动模型。我给大家总结三种最常用的：

启发函数 公式 适用场景 特点
曼哈顿距离 |dx| + |dy| 四方向移动（上下左右） 计算快，但低估实际代价
欧几里得距离 √(dx² + dy²) 八方向或自由移动 最直观，但开方运算稍慢
切比雪夫距离 max(|dx|, |dy|) 八方向移动（对角代价相同） 适合网格地图，效率高

我在项目中遇到过一个问题：用曼哈顿距离做启发函数，结果AGV在仓库里走出来的路径全是“直角拐弯”，看着特别别扭。后来换成切比雪夫距离，路径就平滑多了。嗯，这里要注意：启发函数的选择会影响路径的“风格”。

避坑指南：我曾经在AGV项目里直接用欧几里得距离，结果发现算法跑得特别慢。为什么？因为欧几里得距离往往低估实际代价（尤其在有障碍物时），导致A*扩展了太多不必要的节点。后来我改用“对角距离”（D* Lite里常用的一种），效果好了很多。

8.3 A*的优化技巧

基础A*在简单地图上够用，但到了复杂场景，比如几千个节点的工厂地图，性能就不太行了。下面分享几个我常用的优化技巧。

8.3.1 JPS（Jump Point Search）

JPS是A*的一种加速变体。它的核心思想是：在网格地图中，很多节点是“对称”的，不需要一个个去扩展。

举个例子：你在一条笔直的走廊里往前走，中间没有障碍物。A*会逐个检查走廊上的每个格子，而JPS会直接“跳”到走廊的尽头或者拐弯处。这一跳，省掉了大量无效计算。

JPS的规则其实不复杂：

  • 如果当前节点在一个直线方向上，且前方没有障碍物，就一直往前跳，直到遇到障碍物或拐点
  • 拐点就是“强迫邻居”——即某个方向上有障碍物，导致必须改变方向的位置

我做过对比测试：在1000x1000的网格地图上，普通A*需要扩展约15万个节点，而JPS只扩展了不到2万个。速度提升了7-8倍。不过JPS只适用于均匀网格地图，非网格场景用不了。

8.3.2 双向A*

双向A*的思路更直接：从起点和终点同时开始搜索，让它们在中间相遇。

你想想看，如果地图很大，从起点单向搜索，搜索区域会像一个不断扩大的圆。而双向搜索，相当于两个圆同时扩大，它们相遇时，总面积比单个圆小得多。

具体实现时要注意：

  • 两个方向的搜索交替进行，每次选f(n)较小的那个方向扩展一步
  • 当两个方向的搜索区域有交集时，算法终止
  • 需要维护两个open list和两个close list

注意：双向A*的终止条件要小心处理。我曾经踩过一个坑：两个方向各自找到了路径，但拼接起来不是最优的。原因是它们“相遇”的点不是最优连接点。正确的做法是：当两个方向的搜索区域有重叠时，检查所有重叠节点，取g值之和最小的那个作为连接点。

8.3.3 其他实用优化

  • 二叉堆优化open list：这是最基础的优化。用二叉堆代替普通列表，取最小f(n)的操作从O(n)降到O(log n)。
  • 权重A*：给启发函数加一个权重w（w>1），让算法更“贪心”。比如f(n)=g(n)+w*h(n)。w=1.5时，速度提升明显，路径质量下降不多。
  • 分层规划：先在高分辨率地图上做粗略规划，再在局部细化。适合超大场景。

8.5 代码示例：基础A*实现

最后，给大家一个基础A*的Python实现。这个版本我加了详细的注释，方便你理解每一步在干什么。

import heapq

def astar(grid, start, goal):
    """
    grid: 二维网格，0表示可通行，1表示障碍物
    start: 起点坐标 (x, y)
    goal: 终点坐标 (x, y)
    """
    rows, cols = len(grid), len(grid[0])
    
    # 启发函数：曼哈顿距离
    def heuristic(a, b):
        return abs(a[0] - b[0]) + abs(a[1] - b[1])
    
    # open list：用二叉堆存储 (f, g, x, y, path)
    open_list = []
    heapq.heappush(open_list, (0, 0, start[0], start[1], [start]))
    
    # close list：记录已访问节点
    visited = set()
    visited.add(start)
    
    # 四个方向：上、下、左、右
    directions = [(-1,0), (1,0), (0,-1), (0,1)]
    
    while open_list:
        f, g, x, y, path = heapq.heappop(open_list)
        
        # 到达终点
        if (x, y) == goal:
            return path
        
        for dx, dy in directions:
            nx, ny = x + dx, y + dy
            
            # 边界检查
            if nx < 0 or nx >= rows or ny < 0 or ny >= cols:
                continue
            # 障碍物检查
            if grid[nx][ny] == 1:
                continue
            # 已访问检查
            if (nx, ny) in visited:
                continue
            
            visited.add((nx, ny))
            new_g = g + 1
            new_f = new_g + heuristic((nx, ny), goal)
            new_path = path + [(nx, ny)]
            heapq.heappush(open_list, (new_f, new_g, nx, ny, new_path))
    
    return None  # 无路径

小提示：这段代码是教学用的简化版。实际项目中，我一般会用面向对象的方式封装，把节点状态、路径回溯逻辑都拆开。另外，open list的更新操作（当发现更优路径时更新已有节点的f值）在这个版本里没有体现，但实际应用中很重要。

好了，这一讲的内容就到这里。A*算法说难不难，说简单也不简单——关键是你得理解它的“启发”思想，以及在不同场景下怎么调参、怎么优化。我建议你先把基础A*跑通，然后试着加上JPS或者双向搜索，感受一下性能的提升。
