11 局部路径规划算法（二）：时间弹性带（TEB）算法原理、轨迹优化与约束处理

大家好，欢迎来到局部路径规划的第二讲。

上一讲我们聊了DWA，那个算法说白了就是“速度空间采样+评价”。今天要讲的TEB，思路完全不一样。它把路径规划问题，转化成了一个带约束的轨迹优化问题。

我第一次接触TEB时，觉得这名字挺玄乎——“时间弹性带”。后来做项目用上了，才发现它真的很巧妙。尤其适合那种需要精确控制到达时间的场景，比如AGV在工位前精准停靠。

11.1 TEB的核心思想：从“路径”到“轨迹”

先问大家一个问题：DWA规划出来的是什么？是一段速度指令，对吧？它没有显式地规划“未来几秒我在哪”。

TEB不一样。它直接优化一条带时间戳的路径，也就是轨迹。

什么叫“弹性带”？你想象一根橡皮筋，两端固定（起点和终点）。中间有一些点（机器人位姿），橡皮筋可以伸缩变形。TEB就是通过“拉”这根橡皮筋，让它既满足运动学约束，又能快速到达目标。

核心公式（简化版）：

TEB将轨迹表示为一系列离散的机器人位姿 Q = [x0, y0, theta0, x1, y1, theta1, ...]，以及对应的时间间隔 dt = [dt0, dt1, ...]。

优化目标：min f(Q, dt) = 路径平滑性 + 时间最优性 + 约束惩罚

说白了，TEB就是在求解一个非线性优化问题。我习惯用g2o或者Ceres来解它。嗯，这里要注意，优化变量里包含了时间间隔dt，所以它能直接控制机器人“什么时候到哪”。

11.2 轨迹优化的三大要素

TEB的优化问题，通常包含三个部分。我一个个说。

11.2.1 目标函数：追求“快”与“稳”

  • 时间最优性：我们希望总时间 sum(dt) 尽量小。说白了就是“快点到”。
  • 路径平滑性：相邻位姿的转角变化要小。避免急转弯，否则AGV容易甩货。
  • 轨迹连续性：速度和加速度不能突变。这个在代码里通常用二阶差分约束来实现。

我记得有一次调试，发现AGV在拐弯时总是抖一下。查了半天，原来是平滑性权重设得太低。调高之后，轨迹就顺滑多了。

11.2.2 约束处理：把“不能做”的事写进优化

TEB最强大的地方，就是能处理各种约束。我把它分为三类：

约束类型 具体内容 我的处理经验
运动学约束 最大速度、最大加速度、最小转弯半径 用不等式约束，超出就惩罚
避障约束 与障碍物的最小距离 用符号距离场，计算梯度很快
任务约束 终点位姿、到达时间、朝向要求 用硬约束，或者加高权重

避坑指南：我曾经在约束权重上吃过亏。避障权重设得太高，导致机器人为了绕一个小障碍，走了个大弯路。后来我改用“软约束+自适应权重”，效果好很多。

11.4 代码实战：TEB的核心片段

下面这段代码，是我从实际项目中摘出来的。它展示了如何构建TEB的优化问题。

// 伪代码：TEB优化问题构建
// 使用Ceres Solver

// 1. 定义优化变量
std::vector<double> x, y, theta;  // 位姿
std::vector<double> dt;           // 时间间隔

// 2. 构建问题
ceres::Problem problem;

// 2.1 添加时间最优目标
for (int i = 0; i < dt.size(); ++i) {
    problem.AddResidualBlock(
        new ceres::AutoDiffCostFunction<TimeCost, 1, 1>(new TimeCost()),
        nullptr, &dt[i]
    );
}

// 2.2 添加平滑性约束
for (int i = 1; i < x.size() - 1; ++i) {
    problem.AddResidualBlock(
        new ceres::AutoDiffCostFunction<SmoothCost, 2, 1, 1, 1>(new SmoothCost()),
        nullptr, &x[i-1], &x[i], &x[i+1]
    );
}

// 2.3 添加避障约束（使用符号距离场）
for (int i = 0; i < x.size(); ++i) {
    problem.AddResidualBlock(
        new ceres::AutoDiffCostFunction<ObstacleCost, 1, 1, 1>(new ObstacleCost(sdf)),
        nullptr, &x[i], &y[i]
    );
}

// 3. 求解
ceres::Solver::Options options;
options.max_num_iterations = 20;
ceres::Solver::Summary summary;
ceres::Solve(options, &problem, &summary);

我的小技巧：实际部署时，不要把整个轨迹都优化完再走。我习惯只优化前10-15个位姿，然后取前2-3个位姿计算速度。这样实时性更好。

11.5 TEB vs DWA：什么时候用哪个？

很多同学问我，TEB和DWA到底选哪个？我个人的经验是这样的：

  • DWA：适合反应式避障，计算快，但轨迹质量一般。适合在开阔环境、速度要求不高的场景。
  • TEB：适合精确轨迹跟踪，能处理复杂约束。适合在狭窄通道、需要精准停靠的场景。

我做过一个项目，AGV要在仓库里走“S”形弯道，还要在货架前精确停靠。用DWA总是撞到货架腿，换成TEB之后，一次就过了。为什么？因为TEB显式地优化了与障碍物的距离，而DWA只是采样时检查一下。

注意：TEB的优化问题是非凸的。如果初始轨迹给得不好，容易陷入局部最优。我建议用全局路径作为初始值，或者用A*先粗规划一条路径。

11.6 总结与思考

好了，今天的内容就到这里。我们来捋一捋：

  • TEB把路径规划变成了轨迹优化问题
  • 它同时优化位姿和时间间隔
  • 可以处理运动学、避障、任务三类约束
  • 求解器用g2o或Ceres，迭代10-20次即可

说实话，TEB是我个人最喜欢的局部规划算法。它优雅、灵活，而且效果真的好。但代价就是计算量比DWA大一些。不过现在嵌入式平台性能越来越强，这个已经不是问题了。

你想想看，如果你的AGV需要在复杂环境中精确导航，TEB绝对值得一试。下次遇到避障难题，不妨试试把问题“优化”一下。
