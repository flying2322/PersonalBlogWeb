22 AGV定位技术：AMCL自适应蒙特卡洛定位、EKF融合定位、基于图优化的定位

定位，说白了就是让AGV回答三个问题：“我在哪？我要去哪？我怎么去？” 第一个问题如果答错了，后面全是白搭。

我刚开始做AGV那会儿，最头疼的就是定位。明明地图画得清清楚楚，车就是不知道自己站在哪。后来踩的坑多了，才慢慢摸清楚门道。今天咱们就把AGV定位的三种主流方案掰开揉碎讲清楚。

一、AMCL自适应蒙特卡洛定位

AMCL，全称是Adaptive Monte Carlo Localization。名字挺唬人，其实核心思想很简单：用一堆随机粒子来猜位置。

想象一下，你蒙上眼睛走进一个房间，手里拿着一张地图。你一开始完全不知道自己在哪，那就先在地图上随机撒1000个点——每个点就是一个“粒子”，代表一个可能的位置。

然后你往前走两步，摸到一面墙。这时候，那些落在墙里的粒子就“死掉”了，只有落在合理位置的粒子活下来。再走几步，摸到一个门，继续筛选。几轮下来，粒子就会聚集到真正的位置附近。

AMCL的核心流程：

  1. 初始化：在地图范围内随机撒粒子
  2. 预测：根据里程计数据移动所有粒子
  3. 更新：用激光雷达等传感器数据计算每个粒子的权重
  4. 重采样：淘汰权重低的粒子，复制权重高的粒子
  5. 自适应：根据收敛情况动态调整粒子数量

这里有个关键点——自适应。为什么叫自适应？因为粒子数量不是固定的。我见过很多新手把粒子数设成固定值，比如5000个。结果在空旷走廊里，5000个粒子全散开了，定位精度反而差。

AMCL的做法是：定位越不确定，粒子越多；定位越确定，粒子越少。收敛好了可能只用200个粒子，跑起来飞快。

我的经验： 在实际项目中，AMCL最怕两件事：一是 kidnapped robot problem（机器人被突然抱起放到别处），二是对称环境。我曾经在一个长走廊里调试，左右两边一模一样，粒子死活分不清方向。后来我加了个磁条辅助，才把这个问题解决。

二、EKF融合定位

AMCL虽然好用，但它有个硬伤——只依赖激光雷达。如果激光雷达被遮挡，或者环境特征太少，AMCL就抓瞎了。

这时候就需要EKF（扩展卡尔曼滤波）出场了。EKF的本质是多传感器数据融合，把里程计、IMU、激光、甚至视觉的数据揉在一起，取长补短。

我打个比方：AMCL像是一个靠眼睛认路的人，EKF则是一个既看路又数步子还感受加速度的人。眼睛被挡住了，还能靠脚步推算大概位置。

EKF的工作流程分两步：

  • 预测步：根据里程计和IMU，推算下一时刻的位置和姿态
  • 更新步：用激光或视觉观测数据，修正预测的误差

这里有个数学细节——协方差矩阵。它代表了每个状态量的不确定度。比如里程计漂移严重，那协方差就设大一点；激光数据很准，协方差就设小一点。EKF会自动根据这些权重做最优融合。

注意： EKF有个前提假设——系统是高斯分布的。但实际中，AGV的噪声往往不是严格的高斯分布。我遇到过IMU的零偏突然跳变，EKF直接发散的情况。后来加了异常检测逻辑，才稳住。

EKF的代码实现其实不复杂，核心就几个矩阵运算。我贴一段伪代码，大家感受一下：

// EKF预测步
x_pred = A * x + B * u;          // 状态预测
P_pred = A * P * A^T + Q;        // 协方差预测

// EKF更新步
K = P_pred * H^T * (H * P_pred * H^T + R)^-1;  // 卡尔曼增益
x = x_pred + K * (z - H * x_pred);              // 状态更新
P = (I - K * H) * P_pred;                       // 协方差更新

说白了，EKF就是在“相信预测”和“相信观测”之间找一个平衡点。卡尔曼增益K就是那个平衡系数。

三、基于图优化的定位

如果说AMCL是“实时猜位置”，EKF是“实时融合”，那图优化就是“事后算总账”。

图优化的思路很优雅：把AGV的每个时刻的位姿看作一个节点，把节点之间的约束（比如里程计、激光匹配、闭环检测）看作边，然后构建一个图。最后通过最小化所有边的误差，得到最优的位姿序列。

我举个例子：你让AGV在车间里跑一圈，回到起点。AMCL可能告诉你终点和起点差了20厘米。但图优化会说：“等等，你明明回到了原点，这个闭环约束应该让起点和终点重合。”然后它会调整整条路径上的所有位姿，让误差均匀分布。

图优化的核心优势：

  • 全局一致性：能利用闭环检测消除累积误差
  • 稀疏性：实际中图是稀疏的，计算效率高
  • 可回滚：可以离线优化，不要求实时性

不过图优化也有缺点——计算量大。如果图里有几万个节点，求解一次可能要几秒钟。所以它通常用于建图阶段，或者作为定位的后端优化。实时定位还是靠AMCL或EKF。

我记得有一次做仓储AGV项目，客户要求定位精度±2厘米。AMCL死活达不到，后来我改成AMCL+图优化的方案：AMCL做实时定位，每10秒触发一次图优化修正漂移。最终精度做到了±1.5厘米。

三种方案怎么选？

我整理了一个对比表，方便大家选型：

方案 适用场景 优点 缺点
AMCL 环境特征丰富、激光雷达稳定 实现简单、鲁棒性好 依赖激光、对称环境易失效
EKF 多传感器融合、实时性要求高 计算量小、融合灵活 高斯假设、无法消除累积误差
图优化 建图、高精度定位、闭环场景 全局一致性、精度高 计算量大、不适合纯实时

我个人习惯是：能用AMCL就用AMCL，因为它最简单、最稳定。如果环境太差或者精度要求高，就上EKF融合。如果还要更高精度，那就图优化兜底。

避坑指南： 我曾经在一个项目里只用EKF，结果跑了半小时后漂移了半米。后来发现是IMU的零偏没有在线校准。加了个零偏估计器后，问题就解决了。所以做EKF时，一定要关注传感器的误差模型，别想当然地认为数据是准的。

好了，关于AGV定位的三种主流方案就聊到这儿。AMCL、EKF、图优化，各有各的脾气。选型时别贪多，也别图省事，根据实际场景和传感器配置来定。记住一句话：没有最好的定位方案，只有最合适的。
