10 局部路径规划算法（一）：动态窗口法（DWA）原理、速度空间搜索、评价函数设计

各位同学，今天我们来聊聊局部路径规划里一个非常经典的算法——动态窗口法（DWA）。

说实话，全局路径规划给你画了一条大路，但车怎么走、遇到障碍怎么躲，这得靠局部规划。DWA 就是干这个的。我最早接触 DWA 是在一个仓储 AGV 项目上，当时车跑着跑着突然被一个临时堆放的纸箱挡住了，全局路径还没来得及重算，DWA 直接带着车绕过去了。嗯，那一刻我就觉得这算法真香。

10.1 动态窗口法的核心思想

DWA 说白了就一句话：在速度空间里采样，找一条最安全、最快、最朝向目标的路。

它不关心全局地图长什么样，只盯着当前时刻机器人能跑的速度范围。这个范围就是「动态窗口」。为什么叫动态？因为窗口的大小取决于机器人的加减速能力——你想想看，一个急转弯的车，下一秒能跑的速度肯定不是无限大的。

核心流程三步走：

  1. 在速度空间 (v, ω) 中采样，生成一组候选速度对。
  2. 对每个速度对模拟一段轨迹，看看会撞到啥、跑多远。
  3. 用评价函数打分，选最高分的速度对执行。

我习惯把 DWA 比作「有限视野内的最优决策」。它不贪心，只看未来几秒钟，但足够应付大多数动态场景。

10.2 速度空间搜索——动态窗口到底怎么算？

速度空间搜索，就是找出所有「下一秒可能达到的速度」。这个空间受三个因素约束：

约束类型 含义 数学表达
自身速度极限 电机能跑的最大/最小速度 v ∈ [v_min, v_max], ω ∈ [ω_min, ω_max]
电机加减速能力 当前速度下，Δt 内能加速/减速到的范围 v ∈ [v_cur - a_max·Δt, v_cur + a_max·Δt]
安全制动约束 遇到障碍能刹住车的速度上限 v ≤ √(2·dist(obs)·a_brake)

这三个约束取交集，就是动态窗口。我当年第一次实现时，忘了加制动约束，结果车直接怼墙上了……嗯，从那以后我再也不敢漏掉这个条件。

实战小技巧：采样密度别太高。我一般把线速度 v 分成 10~20 份，角速度 ω 分成 8~12 份。太密了计算量大，太疏了容易漏掉最优解。

10.3 轨迹模拟——怎么知道这条路能不能走？

对每个采样到的 (v, ω)，我们要模拟未来一小段时间的轨迹。通常用运动学模型：

// 差速轮模型轨迹模拟
x_new = x + v * cos(θ) * Δt
y_new = y + v * sin(θ) * Δt
θ_new = θ + ω * Δt

模拟步长 Δt 我习惯取 0.1~0.2 秒，总时长 2~3 秒。为什么？太短了看不到障碍，太长了计算量爆炸。你想想看，如果模拟 5 秒，采样 200 个速度对，每个模拟 50 步，那就是 10000 次碰撞检测——这还没算评价函数呢。

注意：轨迹模拟时一定要考虑机器人轮廓。别把机器人当质点！我见过有人用圆形近似，结果车角刮到货架。建议用多个圆或矩形包络做碰撞检测。

10.4 评价函数设计——三个维度的博弈

评价函数是 DWA 的灵魂。它通常包含三个子项：

  • 方位角评价 (heading)：轨迹终点朝向与目标方向的夹角。夹角越小，分数越高。
  • 障碍物距离评价 (dist)：轨迹上离最近障碍物的距离。距离越远，分数越高。如果撞上，直接给 0 分。
  • 速度评价 (velocity)：线速度大小。速度越快，分数越高，鼓励快速通过。

最终得分 = α·heading + β·dist + γ·velocity。这三个权重怎么调？我个人的经验是：

场景 α (朝向) β (避障) γ (速度)
狭窄通道 0.3 0.6 0.1
开阔直道 0.4 0.2 0.4
密集动态障碍 0.2 0.7 0.1

我曾经在一个仓库项目里，β 设得太小，车总想贴着障碍物高速通过，结果被叉车逼停了。后来我把 β 提到 0.6，车就老实多了。

归一化很重要！三个子项的量纲不同——heading 是角度（0~π），dist 是距离（0~10m），velocity 是速度（0~1m/s）。不归一化的话，大数值项会主导结果。我习惯用当前窗口内的最大值做归一化：

heading_norm = heading / max_heading_in_window
dist_norm = dist / max_dist_in_window
vel_norm = vel / max_vel_in_window

10.5 完整算法流程（伪代码）

把上面这些串起来，就是 DWA 的完整流程：

function DWA_control(robot_pose, goal, obstacles):
    best_score = -inf
    best_vel = (0, 0)
    
    // 1. 计算动态窗口
    dw_v = intersect(v_limits, v_accel_range, v_brake_range)
    dw_w = intersect(w_limits, w_accel_range, w_brake_range)
    
    // 2. 在窗口内采样
    for v in sample(dw_v, N_v):
        for w in sample(dw_w, N_w):
            // 3. 模拟轨迹
            traj = simulate_trajectory(robot_pose, v, w, dt, horizon)
            
            // 4. 计算评价函数
            heading = calc_heading(traj[-1], goal)
            dist = calc_obstacle_dist(traj, obstacles)
            if dist < robot_radius:
                continue  // 撞上了，跳过
            
            vel = abs(v)
            score = alpha * heading + beta * dist + gamma * vel
            
            // 5. 选最优
            if score > best_score:
                best_score = score
                best_vel = (v, w)
    
    return best_vel

这段代码看着简单，但实际调参能调到你怀疑人生。我建议你先用仿真环境调好权重，再上真车。

10.6 DWA 的优缺点与适用场景

没有银弹，DWA 也有自己的脾气：

  • 优点：计算快（毫秒级）、实现简单、对动态障碍反应灵敏。
  • 缺点：容易陷入局部最优（比如 U 形障碍出不来）、不保证全局可达性、对参数敏感。

我一般在什么场景用 DWA？室内平坦地面、障碍物不太密集、机器人速度不太快（< 1.5m/s）的情况。高速 AGV 或者越野场景，我建议用 TEB 或者 MPC。

避坑指南：我曾经在一个项目里，DWA 在走廊尽头总是左右摇摆，后来发现是 heading 项权重太大，车在目标点附近反复横跳。解决办法是：当距离目标点小于 0.5m 时，降低 heading 权重，增加速度权重，让车果断停过去。

好了，DWA 的核心内容就这些。下一节我们会聊另一个局部规划算法——TEB（时间弹性带），它和 DWA 的思路完全不同，但同样精彩。各位先把 DWA 吃透，动手写个仿真跑一跑，比看十遍文章都管用。
