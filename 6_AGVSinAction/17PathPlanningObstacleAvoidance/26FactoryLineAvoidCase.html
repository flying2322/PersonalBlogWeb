26 工厂产线AGV的物料配送与动态绕障

各位同学，欢迎来到实战案例的第二讲。上一讲我们聊了仓储场景，今天我们把目光转向工厂产线。说实话，产线场景比仓储要「闹腾」得多——人车混流、叉车穿梭、临时堆料，这些都是家常便饭。我当年第一次调试产线AGV时，差点被一个突然伸出来的托盘逼停，那叫一个狼狈。

今天我们就来拆解一下，产线物料配送中的路径规划与动态绕障到底该怎么搞。

产线场景的特殊性

工厂产线和仓库最大的区别在哪？我总结了三句话：

  • 动态障碍物多：工人、叉车、临时物料，随时可能出现在路径上
  • 任务节奏快：产线不能停，AGV必须准时送达，否则整条线都得等
  • 空间狭窄：产线通道通常只有2-3米宽，会车、绕行都很受限

你想想看，如果AGV在产线中间突然停下来「思考人生」，后面的工人可能直接上手推车了。所以，产线AGV的路径规划，核心就两个字——鲁棒。

核心原则：产线AGV的路径规划，不是找最短路径，而是找「最不容易被堵死」的路径。

物料配送的路径规划策略

产线物料配送，说白了就是「从A点取料，送到B点，然后空车返回或接下一个任务」。但这里有个坑——产线工位是动态变化的。比如某个工位正在加工，AGV就不能直接停到工位前，得等它加工完。

我建议的做法是：

  1. 全局路径预规划：用拓扑地图 + Dijkstra算出一条基础路径。产线环境相对固定，拓扑地图比栅格地图更高效。
  2. 局部路径实时调整：遇到动态障碍物时，用TEB（Timed Elastic Band）算法做局部绕行。TEB的好处是能同时考虑路径长度、平滑度和时间约束。
  3. 工位对接的精细控制：最后1米用视觉或激光引导，做厘米级对接。

我的经验：全局路径不要只算一条。我习惯算3条备选路径——主路径、备用路径、应急路径。主路径被堵时，直接切备用，不用重新规划，省时间。

动态绕障实战：TEB算法

说到动态绕障，TEB是我用得最多的算法。为什么？因为它天然支持「时间最优」。产线AGV最怕什么？怕迟到。TEB把时间维度直接塞进优化目标里，说白了就是「既要绕开障碍物，又要尽量准时到」。

核心思路是这样的：

  • 把路径离散成一系列位姿点（x, y, theta）
  • 每个位姿点关联一个时间戳
  • 构建一个多目标优化问题：最小化路径长度 + 最小化时间 + 最大化障碍物距离
  • 用g2o或ceres求解

代码实现的核心片段我贴一下：

// TEB优化核心参数配置
TebConfig config;
config.robot.max_vel_x = 1.0;        // 最大线速度 m/s
config.robot.max_vel_theta = 0.5;    // 最大角速度 rad/s
config.robot.acc_lim_x = 0.5;        // 最大加速度 m/s²
config.robot.min_turning_radius = 0.4; // 最小转弯半径 m

// 障碍物代价权重
config.obstacles.min_obstacle_dist = 0.3;  // 最小安全距离
config.obstacles.inflation_dist = 0.5;     // 膨胀距离
config.obstacles.weight_obstacle = 100.0;  // 障碍物代价权重

// 时间最优权重
config.trajectory.weight_time = 10.0;      // 时间代价权重
config.trajectory.weight_velocity = 5.0;   // 速度代价权重

// 初始化TEB规划器
TebOptimalPlanner planner(config);
planner.setVisualization(visualization);

// 每次规划时调用
bool success = planner.plan(global_plan, start_pose, goal_pose, &teb_plan);
if (success) {
    // 提取控制指令
    geometry_msgs::Twist cmd = planner.getVelocityCommand();
    robot_control.publish(cmd);
}

这段代码看着简单，但实际调参是个体力活。我记得有一次在客户现场，AGV总是贴着障碍物走，差一点就蹭上了。后来发现是min_obstacle_dist设得太小，调到0.4米就好了。

注意：TEB的权重参数非常敏感。weight_obstacle设太大，AGV会绕很远的路；设太小，又可能撞上。我一般先用仿真跑一遍，再拿到产线微调。

多车协同与交通管制

产线通常不止一辆AGV。多车运行时，最怕的就是「死锁」——两辆车面对面堵着，谁也别想走。

我常用的策略是路段锁机制：

  • 把地图划分成若干路段（segment）
  • 每辆车进入路段前，先申请锁
  • 锁被占用时，车辆在路段入口等待
  • 离开路段后释放锁

这个机制实现起来不复杂，但要注意死锁检测。我曾经遇到过一个情况：A车占了路段1，要去路段2；B车占了路段2，要去路段1。两辆车互相等，死锁了。后来加了一个超时机制——如果某辆车在路口等超过5秒，调度器强制重新规划路径。

实战中的避坑指南

最后分享几个我踩过的坑，希望对你有帮助：

  • 地面反光问题：工厂地面经常打蜡，激光雷达会打滑。我后来加了反光柱辅助定位。
  • 叉车干扰：叉车的金属货叉会反射激光，造成假障碍物。解决方案是在感知层做动态滤波，把快速移动的物体标记为「动态障碍物」，不纳入静态地图。
  • 急停后的恢复：AGV急停后，TEB的优化会发散。我习惯在急停后先做一段直线后退，再重新规划。
  • 产线节拍匹配：AGV的速度不是越快越好。要跟产线节拍匹配，快了反而会造成拥堵。我一般会跟MES对接，获取产线实时节拍，动态调整AGV速度。

好了，这一讲的内容就到这里。产线AGV的物料配送，核心就是「全局规划 + 局部绕障 + 多车协同」这三个环节。每个环节都有不少细节，但掌握了这些，你基本就能应对大部分产线场景了。

一句话总结：产线AGV的路径规划，不是算法竞赛，而是工程实践。稳定、可靠、可预测，比花哨的算法更重要。
