3 坐标变换与空间描述

各位同学，大家好。这一章我们聊聊坐标变换。说实话，这是AGV导航里最基础也最容易出错的地方。我见过不少新手，代码写得飞起，结果车跑偏了，最后发现是坐标系搞反了。嗯，咱们今天就把这块彻底理清楚。

核心观点：坐标变换的本质，就是用数学语言描述“我在哪，我看哪，我怎么动”。

3.1 二维与三维坐标：从平面到立体

先说说二维坐标。AGV在工厂里跑，很多时候就是二维平面运动。一个点(x, y)就能定位。但注意，AGV是有朝向的，所以除了位置，还得有个角度θ。这就是我们常说的位姿(x, y, θ)。

到了三维空间，就复杂了。除了x、y、z，还有三个旋转自由度：俯仰、偏航、横滚。我个人习惯把三维坐标想象成“你站在AGV上，看前方、看左右、看上下”。

举个例子。我在项目里调试一台叉车AGV，它要举升货架。二维坐标只能管地面跑，但举升高度、货叉倾斜，这些都得用三维坐标。当时有个坑——传感器装在车顶，但控制点在货叉上，坐标不统一，车差点把货架怼翻。后来怎么解决的？就是老老实实做坐标变换。

小技巧：做AGV项目，先画一张坐标系关系图。把车体、传感器、执行器、地图原点都标出来。这一步省不了。

3.2 齐次坐标：为什么需要多一个维度？

你可能会问：明明三维坐标就够了，为什么搞个四维的齐次坐标？

说白了，就是为了把旋转和平移统一成一个矩阵运算。你想，一个点先旋转再平移，如果用普通坐标，你得先乘旋转矩阵，再加平移向量。两步操作，麻烦。齐次坐标下，一个4x4矩阵搞定一切。

齐次坐标的形式是(x, y, z, w)，其中w通常为1。当w=0时，表示方向向量（无穷远点），这个在表示光线或无穷远方向时很有用。

// 齐次坐标示例：二维点(2,3)的齐次表示为(2,3,1)
// 变换矩阵 T = [R t; 0 1]
// 变换后点 = T * 齐次坐标

// 实际代码中，我常用Eigen库：
Eigen::Vector3d p_homogeneous(2, 3, 1);
Eigen::Matrix3d T;
T << cos(theta), -sin(theta), tx,
      sin(theta),  cos(theta), ty,
      0,           0,           1;
Eigen::Vector3d p_transformed = T * p_homogeneous;

注意：齐次坐标的w分量，千万别搞错。w=0和w=1意义完全不同。我曾经在代码里把方向向量当位置向量用，结果AGV定位直接飞了。

3.3 旋转矩阵：最直观的旋转表达

旋转矩阵，说白了就是一个3x3的正交矩阵，行列式为+1。它描述了一个坐标系相对于另一个坐标系的旋转关系。

二维旋转矩阵很简单：

R(θ) = [cosθ  -sinθ]
       [sinθ   cosθ]

三维就复杂了。绕x轴、y轴、z轴的旋转矩阵，分别对应roll、pitch、yaw。我建议你记住一个规律：绕哪个轴转，哪个轴对应的行和列不变，其他四个元素是三角函数。

我记得有一次，团队里新来的同事把绕x轴和绕y轴的矩阵搞混了，结果机械臂抓取时角度全错。排查了一下午，最后发现就是矩阵写反了。从那以后，我要求所有代码里必须注释清楚“绕哪个轴旋转”。

3.4 欧拉角与四元数：两种旋转的优缺点

欧拉角直观，但有个致命问题——万向锁。当俯仰角达到±90°时，偏航和横滚会耦合，丢失一个自由度。我在做AGV爬坡时遇到过这个问题，车在陡坡上姿态突然乱跳，就是因为欧拉角在奇异点附近不稳定。

四元数就没有这个问题。它用四个数(q0, q1, q2, q3)表示旋转，没有奇异点，插值也平滑。缺点是直观性差，你没法一眼看出它代表什么角度。

表达方式 优点 缺点 适用场景
旋转矩阵 计算稳定，可组合 9个参数，冗余 底层运算
欧拉角 直观，易理解 万向锁，插值不平滑 人机交互、显示
四元数 无奇异点，插值平滑 不直观 姿态控制、SLAM

我的建议：内部计算用四元数，显示和调试用欧拉角。ROS里tf默认用四元数，但你可以用tf::getYaw()转成偏航角来看。

3.5 TF树基础：坐标变换的骨架

TF树，说白了就是一张坐标系关系网。每个坐标系是一个节点，变换关系是边。AGV上可能有十几个坐标系：车体、激光雷达、IMU、轮子、地图原点……它们之间的关系，就是TF树。

TF树有两个核心概念：

  • 广播（Broadcaster）：发布坐标系之间的变换关系
  • 监听（Listener）：查询任意两个坐标系之间的变换

我在项目里遇到过最典型的坑：TF树断链。比如激光雷达的坐标系没连到车体上，那激光数据就没法和地图对齐。排查方法很简单——用tf2_tools里的view_frames命令，生成TF树图，一眼就能看出哪里断了。

# 查看TF树的命令
rosrun tf2_tools view_frames.py
# 会生成frames.pdf，显示所有坐标系和变换关系

# 代码中监听变换
tf2_ros::Buffer tf_buffer;
tf2_ros::TransformListener listener(tf_buffer);
geometry_msgs::TransformStamped transform;
try {
  transform = tf_buffer.lookupTransform("map", "base_link", ros::Time(0));
} catch (tf2::TransformException &ex) {
  ROS_WARN("TF lookup failed: %s", ex.what());
}

避坑指南：我曾经在调试时，发现TF树一直在报“Lookup would require extrapolation into the past”。原因是时间戳没对齐。记住：ros::Time(0)表示取最新数据，但如果你用具体时间戳，一定要确保数据已经到达。

这张图把本章内容串起来了。左边是坐标系统，中间是旋转表达，右边是TF树。三者缺一不可。你想想看，如果坐标系统没搞对，旋转表达再漂亮也没用；如果TF树断了，所有变换都白搭。

本章小结：坐标变换不是纯数学，它是AGV导航的骨架。我建议你每做一个项目，先把TF树画出来，再写代码。这样能避免80%的定位问题。
