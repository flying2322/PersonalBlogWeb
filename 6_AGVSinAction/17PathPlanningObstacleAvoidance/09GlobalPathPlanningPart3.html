9 全局路径规划算法（三）：RRT与RRT*算法原理、在AGV中的应用场景

聊完了A*和Dijkstra，咱们今天来点不一样的。说实话，前两种算法在结构化环境里表现确实不错，但一旦遇到复杂、高维、或者非结构化空间，它们就有点力不从心了。这时候，RRT和RRT*就派上了用场。

我个人习惯把RRT叫做“随机撒点”算法。你想想看，在未知环境里，与其费劲去建模整个地图，不如直接随机采样，快速构建一条可行路径。这思路，是不是很直接？

9.1 RRT算法：快速探索随机树

RRT的全称是Rapidly-exploring Random Tree，翻译过来就是“快速探索随机树”。它的核心思想很简单：从起点开始，像树根一样，随机向四周生长，直到触及终点区域。

9.1.1 算法核心流程

我直接给你拆解一下步骤，你跟着走一遍就明白了：

  1. 初始化：以起点作为树的根节点。
  2. 随机采样：在地图空间里随机选一个点，叫它q_rand。
  3. 找最近邻：在已有的树上，找到离q_rand最近的节点q_near。
  4. 扩展生长：从q_near向q_rand方向，走一个固定步长delta，得到新节点q_new。
  5. 碰撞检测：检查q_near到q_new的路径上有没有障碍物。有的话，就放弃这次扩展。
  6. 加入树中：如果没有障碍，就把q_new加入树中，并记录它的父节点是q_near。
  7. 终止判断：如果q_new离终点足够近（比如小于步长），或者已经到达终点区域，就停止搜索。
  8. 回溯路径：从终点节点一路回溯到起点，就得到了一条完整路径。

核心要点：RRT不保证找到最优路径，但它能保证快速找到一条可行路径。这在实时性要求高的场景下，非常实用。

9.1.2 我在项目中的实际应用

我记得有一次做仓储AGV的项目，仓库里堆满了货架，通道非常狭窄。用A*规划出来的路径，经常因为货架位置微调而失效。后来我换成了RRT，效果立竿见影。

为什么？因为RRT不需要精确的环境模型。它只需要知道“这里能不能走”，而不是“这里是什么”。说白了，它更适合动态变化的环境。

避坑指南：我曾经遇到过RRT在狭窄通道里“钻牛角尖”的情况。因为随机采样点很难落到狭窄通道里，导致树一直长不过去。后来我加了一个“目标偏置”策略——以一定概率直接采样终点方向，才解决了这个问题。

9.2 RRT*算法：渐进最优的改进版

RRT虽然快，但它找到的路径往往很“丑”——弯弯绕绕，不是最短的。RRT*就是在RRT基础上，加入了渐进最优的机制。

说白了，RRT*不满足于“找到一条路”，它还要“找到一条好路”。

9.2.1 RRT*的两个关键改进

RRT*在RRT的基础上，多了两个步骤：

  1. 重新选择父节点：当生成新节点q_new后，不是直接把它挂在最近的节点上。而是在q_new附近的一个邻域内，寻找一个“代价更小”的节点作为父节点。
  2. 重新布线：检查邻域内的其他节点，如果通过q_new到达它们的代价更小，就把它们的父节点改为q_new。

这两个操作，让RRT*的树结构会随着采样点的增多，不断自我优化。你想想看，这就像一棵树在生长过程中，不断调整自己的枝干，让养分输送的路径更短。

关键区别：RRT找到一条路径就停了。RRT*会继续采样，不断优化路径，直到达到迭代次数上限或时间上限。所以RRT*找到的路径，随着时间推移，会越来越接近最优解。

9.2.2 代价函数与收敛性

RRT*的代价函数通常就是路径长度。但实际项目中，我会把“转弯次数”、“靠近障碍物的距离”也加进去。比如在AGV场景里，频繁转弯会降低效率，增加能耗。

关于收敛性，数学上已经证明RRT*是几乎必然收敛到最优解的。但“几乎必然”不等于“一定”，而且收敛速度取决于采样策略和步长参数。我个人的经验是，迭代次数达到几千次后，路径质量就基本稳定了。

注意：RRT*的计算量比RRT大得多。如果你对实时性要求极高（比如AGV需要每秒重新规划），RRT可能更合适。如果对路径质量要求高（比如AGV执行精密对接任务），那就选RRT*。

9.3 在AGV中的应用场景对比

我把这两个算法在AGV场景里的适用性，整理成了一个表格，方便你对比：

场景 推荐算法 原因
仓储AGV（货架密集、通道窄） RRT（带目标偏置） 快速找到可行路径，适应动态货架位置
工厂AGV（长距离运输） RRT* 路径质量高，减少转弯和能耗
巡检AGV（室外、非结构化） RRT 环境复杂，需要快速探索未知区域
AGV对接工位（高精度） RRT* + 局部优化 需要平滑、精确的末端路径

9.5 代码示例：RRT核心逻辑（伪代码）

下面这个伪代码，是我在实际项目中提炼出来的RRT核心逻辑。你拿过去，稍微改改就能用：

function RRT_plan(start, goal, map, max_iter):
    // 初始化树
    tree = [start]
    
    for i = 1 to max_iter:
        // 随机采样（带目标偏置）
        if random() < 0.1:
            q_rand = goal
        else:
            q_rand = random_sample(map)
        
        // 找最近邻
        q_near = find_nearest(tree, q_rand)
        
        // 扩展
        q_new = steer(q_near, q_rand, step_size)
        
        // 碰撞检测
        if not collision(q_near, q_new, map):
            // 加入树
            tree.add(q_new)
            q_new.parent = q_near
            
            // 检查是否到达终点
            if distance(q_new, goal) < goal_threshold:
                return reconstruct_path(q_new)
    
    // 迭代结束，未找到路径
    return None

个人经验：代码里的goal_threshold不要设得太小。我刚开始设了0.1米，结果AGV经常因为采样点落不到那么精确而规划失败。后来改成0.5米，配合终点附近的局部规划，效果就好多了。

9.6 避坑指南与实战建议

最后，我把自己这些年踩过的坑，总结成几条建议：

  • 步长选择：步长太大，路径粗糙；步长太小，树生长慢。我一般取地图对角线长度的1%~5%。
  • 采样策略：纯随机采样效率低。加一个“目标偏置”或“边界偏置”，能显著提升搜索速度。
  • 路径平滑：RRT/RRT*生成的路径都是折线。实际AGV运动需要平滑曲线，所以后面一定要接一个路径平滑模块（比如B样条曲线）。
  • 动态环境：如果环境变化快，RRT*的重新布线可能跟不上。这时候我倾向于用RRT + 局部重规划的组合。

嗯，关于RRT和RRT*，今天就聊这么多。这两个算法，一个求快，一个求优，各有各的用武之地。你在实际项目中，根据需求选一个就行。
