19 路径规划综合实战（一）：在仿真环境中实现A* + DWA的完整导航

终于到了综合实战环节。

说实话，前面我们讲了A*全局规划，也讲了DWA局部避障。但很多同学学完之后，还是不知道怎么把这两块拼起来。我当年刚入行时也踩过这个坑——A*算出来的路径很漂亮，但机器人一走就撞墙；DWA避障能力很强，但经常绕远路。

这章我们就来解决这个问题。把A*和DWA串成一个完整的导航系统，在仿真环境里跑起来。

19.1 整体架构：全局+局部，各司其职

先看一张整体流程图，理清思路。

整个流程其实不复杂。A*负责看全局，DWA负责管眼前。关键是怎么让它们配合好。

19.2 第一步：搭建仿真环境

我个人习惯用Python + matplotlib做快速仿真。不用ROS，因为调试起来太慢。等算法验证好了，再移植到ROS上。

先建一个简单的栅格地图：

import numpy as np
import matplotlib.pyplot as plt

# 创建地图：0=空闲，1=障碍物
grid_map = np.zeros((20, 20))
# 添加一些障碍物
grid_map[5:8, 5:8] = 1
grid_map[12:15, 3:6] = 1
grid_map[2:5, 12:15] = 1
grid_map[15:18, 10:13] = 1

# 起点和终点
start = (1, 1)
goal = (18, 18)

plt.imshow(grid_map, cmap='gray_r', origin='lower')
plt.plot(start[1], start[0], 'go', markersize=10)
plt.plot(goal[1], goal[0], 'ro', markersize=10)
plt.grid(True)
plt.show()
小技巧： 仿真时地图尺寸别太大。20x20就够用，跑得快，看得清。我一开始用100x100的地图，A*跑一次要好几秒，调试起来急死人。

19.3 第二步：实现A*全局规划

A*的代码前面章节已经讲得很细了。这里直接复用，只强调一个关键点——路径点要稀疏化。

为什么？因为DWA的局部目标点是从全局路径上取的。如果路径点太密，DWA刚走到一个点，下一个点就在眼前，根本来不及做避障。

def astar_path(grid_map, start, goal):
    # ... 标准A*实现，返回路径点列表 ...
    # 假设返回的路径是密集的
    path = [(1,1), (1,2), (1,3), ..., (18,18)]
    
    # 关键步骤：路径稀疏化
    sparse_path = []
    step = 3  # 每隔3个点取一个
    for i in range(0, len(path), step):
        sparse_path.append(path[i])
    if path[-1] not in sparse_path:
        sparse_path.append(path[-1])
    
    return sparse_path
注意： 稀疏化步长不能太大。步长=3意味着每隔3个格子取一个点。如果地图格子是0.5米一个，那局部目标点就在1.5米外。这个距离对DWA来说刚刚好。步长太大，DWA可能看不到目标点；步长太小，DWA没有避障空间。

19.4 第三步：实现DWA局部规划

DWA的核心是速度采样+轨迹评价。这里我直接给出简化版代码，重点看评价函数怎么设计。

class DWA:
    def __init__(self):
        self.max_speed = 1.0      # m/s
        self.max_yaw_rate = 0.5   # rad/s
        self.predict_time = 2.0   # 预测轨迹长度（秒）
        self.dt = 0.1             # 时间步长
        
    def evaluate_trajectory(self, trajectory, local_goal, obstacles):
        # 三个评价指标
        heading_cost = self.calc_heading_cost(trajectory, local_goal)
        obstacle_cost = self.calc_obstacle_cost(trajectory, obstacles)
        speed_cost = self.calc_speed_cost(trajectory)
        
        # 加权求和
        total_cost = (0.5 * heading_cost + 
                      0.3 * obstacle_cost + 
                      0.2 * speed_cost)
        return total_cost

这里有个坑。我刚开始做的时候，heading_cost算的是轨迹终点朝向局部目标点的角度。结果机器人经常在目标点附近来回摆动，就是停不下来。

后来我改成：heading_cost = 轨迹终点到局部目标点的距离。距离越近，cost越小。这样机器人会主动靠近目标点，而不是只对着目标点方向走。

19.5 第四步：A* + DWA 主循环

这是整个系统的核心。说白了就是一个while循环：

def run_navigation(grid_map, start, goal):
    # 1. 全局规划
    global_path = astar_path(grid_map, start, goal)
    path_index = 0
    
    # 2. 初始化机器人状态
    robot_x, robot_y, robot_yaw = start[0], start[1], 0.0
    
    # 3. 主循环
    while True:
        # 检查是否到达终点
        if distance(robot_x, robot_y, goal[0], goal[1]) < 0.3:
            print("到达终点！")
            break
        
        # 4. 获取局部目标点
        local_goal = global_path[path_index]
        
        # 5. 如果到达局部目标点，切换到下一个
        if distance(robot_x, robot_y, local_goal[0], local_goal[1]) < 0.3:
            path_index += 1
            if path_index >= len(global_path):
                path_index = len(global_path) - 1
            local_goal = global_path[path_index]
        
        # 6. DWA计算速度指令
        v, omega = dwa.compute_velocity(
            robot_x, robot_y, robot_yaw,
            local_goal, obstacles
        )
        
        # 7. 更新机器人位置
        robot_x += v * np.cos(robot_yaw) * dt
        robot_y += v * np.sin(robot_yaw) * dt
        robot_yaw += omega * dt
        
        # 8. 可视化（可选）
        plot_frame(grid_map, robot_x, robot_y, robot_yaw, 
                   global_path, path_index)
关键逻辑： 局部目标点不是终点，而是全局路径上的一个中间点。DWA只负责把机器人带到这个中间点。到了之后，再取下一点。这样A*负责大方向，DWA负责小细节，各司其职。

19.6 避坑指南：我踩过的三个坑

坑一：局部目标点切换太频繁

我曾经把局部目标点的到达阈值设成0.1米。结果机器人刚靠近，还没稳定，就切换到下一个点。机器人路径变得很抖，像喝醉了酒。

解决办法：阈值设成0.3-0.5米。让机器人有一个缓冲区间。

坑二：DWA评价函数权重不对

有一次我把obstacle_cost的权重设成0.8，heading_cost只有0.1。结果机器人为了避障，在空旷的地方也绕大圈，路径效率极低。

解决办法：权重要根据场景调。狭窄通道里obstacle_cost权重高一些，开阔区域里heading_cost权重高一些。

坑三：全局路径穿过障碍物

A*算出来的路径理论上不会穿过障碍物。但如果地图更新了（比如新增了临时障碍物），全局路径可能就失效了。

解决办法：每次DWA计算前，检查局部目标点是否被障碍物挡住。如果挡住了，就回退到上一个有效的路径点，或者重新规划全局路径。

19.7 仿真结果怎么看

跑完仿真后，我一般看三个指标：

指标 正常值 异常表现 可能原因
路径长度 接近A*规划长度 明显比A*路径长 DWA权重不合理，绕路太多
运行时间 几秒到几十秒 卡在某处不动 局部目标点被障碍物挡住
轨迹平滑度 无明显抖动 来回摆动 局部目标点切换阈值太小

嗯，这三个指标基本能帮你定位90%的问题。

19.8 完整代码结构

最后给一个代码文件组织建议。我习惯这样分：

navigation_sim/
├── main.py          # 主循环
├── astar.py         # A*算法
├── dwa.py           # DWA算法
├── map.py           # 地图生成与可视化
├── robot.py         # 机器人运动模型
└── config.py        # 参数配置

这样分的好处是，每个文件只做一件事。调试的时候，改参数去config.py，改算法去对应的文件。不会乱。

我的习惯： 先把所有参数写在config.py里，包括地图尺寸、机器人速度、A*步长、DWA权重等。调试时只改config.py，不动算法代码。这样能保证算法逻辑的稳定性。
