23 动态环境中的重规划策略

各位做AGV的朋友，大家好。今天我们来聊一个很实际的问题——动态环境中的重规划。

说实话，静态地图下的路径规划，现在开源方案一大堆，跑个A*谁都会。但真正让AGV“翻车”的，往往是环境变了，机器人还在按老路走。我见过太多项目，仿真跑得飞起，一上产线就撞人——说白了，就是重规划没做好。

这一讲，我们就聚焦两个核心问题：局部代价地图怎么更新？全局路径什么时候该重新搜？

一、局部代价地图：动态环境的“实时感知”

先说说局部代价地图。我个人习惯把它比作AGV的“近程雷达”——它只管机器人周围几米到十几米的范围，但更新频率很高，通常10Hz甚至更高。

1.1 传感器数据怎么“喂”进地图？

激光雷达、深度相机、超声波……这些传感器每帧都会吐出一堆点云或障碍物信息。关键是怎么把这些数据高效地融合到代价地图里。

我常用的做法是分层更新：

  • 障碍物层（Obstacle Layer）：直接写入传感器检测到的障碍物，标记为不可通行（cost=254）。
  • 膨胀层（Inflation Layer）：根据机器人尺寸，对障碍物进行膨胀，生成梯度代价。
  • 静态层（Static Layer）：加载事先建好的地图，作为背景。

核心原则：局部地图的更新要“快进快出”。传感器数据进来后，只更新机器人当前位置周围的一个滑动窗口，不要全图刷新。

嗯，这里有个坑。我曾经在一个项目里，直接用全局地图的更新方式去处理局部地图，结果每帧都要遍历整个200x200的栅格图，CPU直接飙到80%。后来改成滑动窗口，只更新机器人周围5米半径的区域，CPU占用降到了15%。

1.2 膨胀层的动态调整

膨胀半径不是一成不变的。你想想看，AGV空载和满载时，转弯半径能一样吗？

我建议的做法是：

  • 根据当前车速动态调整膨胀半径。车速越快，膨胀半径越大——给刹车留出余量。
  • 根据负载重量调整。重载时，机器人惯性大，膨胀层要更“厚”一些。
// 伪代码：动态膨胀半径计算
float compute_inflation_radius(float speed, float load_ratio) {
    float base_radius = 0.3;  // 基础半径 0.3m
    float speed_factor = speed * 0.1;  // 速度每增加1m/s，半径增加0.1m
    float load_factor = load_ratio * 0.15;  // 满载时额外增加0.15m
    return base_radius + speed_factor + load_factor;
}

1.3 代价衰减与遗忘机制

动态环境里，障碍物会移动，也会消失。比如一个人从AGV前面走过去了，如果代价地图还记着他，机器人就会傻傻地停在那里等。

我常用的策略是时间衰减：

  • 每个栅格记录最后一次被观测到的时间戳。
  • 如果超过一定时间（比如5秒）没有被观测到，代价开始衰减。
  • 衰减到0后，恢复为自由空间。

小技巧：衰减速度不要线性，用指数衰减更符合直觉。我一般用 cost = cost * exp(-Δt / τ)，τ取3秒左右。

二、全局路径重新搜索：什么时候该“推倒重来”？

局部代价地图更新得再快，如果全局路径本身已经不可行了，那也是白搭。所以我们需要一套触发条件，来决定什么时候重新搜索全局路径。

2.1 路径阻塞检测

这是最直接的触发条件。当机器人沿着全局路径走，发现前方一段路径被障碍物完全堵死，而且局部规划器尝试绕行失败时，就该触发全局重规划了。

怎么判断“堵死”？我个人的经验是：

  • 检查全局路径上，距离机器人前方2-5米范围内的所有路径点。
  • 如果连续N个点（比如5个）在局部代价地图中的代价都超过阈值（比如200），就认为路径被阻塞。
  • 同时，局部规划器尝试绕行超过一定时间（比如3秒）仍未成功，触发重规划。

注意：不要一检测到障碍物就重规划。有时候只是临时遮挡，比如有人从机器人面前经过。我建议加一个“确认延迟”——障碍持续存在超过1秒再触发。

2.2 代价阈值触发

有时候路径没有被完全堵死，但代价变得很高。比如原本规划的路线经过一个狭窄通道，现在通道两边都堆了货物，虽然还能过，但风险很大。

这种情况下，我建议设置一个累计代价阈值：

  • 计算全局路径上所有路径点的平均代价。
  • 如果平均代价超过某个阈值（比如100），触发重规划。
  • 或者，如果路径上任意一个点的代价超过254（不可通行），立即触发。
触发条件 阈值建议 适用场景
连续阻塞点数 ≥5个点（分辨率0.05m时） 静态障碍物突然出现
路径平均代价 ≥100（0-255范围） 环境逐渐变拥挤
单点最大代价 ≥254 路径被完全阻断
局部绕行超时 ≥3秒 局部规划器陷入死胡同

2.3 定时重规划策略

还有一种情况——环境变化很缓慢，但一直在变。比如仓库里货物被慢慢搬走，通道逐渐变宽。这种情况下，代价阈值可能永远不会触发，但路径其实已经不是最优的了。

我的做法是加一个定时器：

  • 每隔一定时间（比如30秒），强制触发一次全局重规划。
  • 但如果当前路径代价很低（比如平均代价<30），可以跳过这次重规划，节省算力。
  • 重规划后，如果新路径比旧路径代价降低超过10%，就切换过去。

核心思想：重规划不是越频繁越好。每次重规划都要消耗算力，而且可能导致机器人走走停停。我见过有人把重规划频率设成1Hz，结果机器人像抽风一样来回变道——这就是过度重规划。

三、实战中的“避坑指南”

最后，分享几个我踩过的坑：

  • 坑1：重规划时忘记清空局部代价地图。 我曾经有一次，全局路径重规划后，局部代价地图里还残留着旧障碍物信息，导致新路径刚生成就被局部规划器否决了。解决方案：重规划时，把局部代价地图中动态障碍物层清空，重新从传感器获取数据。
  • 坑2：重规划频率过高导致路径抖动。 后来我加了一个“冷却时间”——每次重规划后，至少等2秒才能再次触发。这样既保证了响应速度，又避免了频繁切换。
  • 坑3：代价地图更新和路径规划用同一个线程。 这会导致地图更新时路径规划被阻塞，反之亦然。我建议把代价地图更新放在一个独立线程，优先级设高一些。

好了，关于动态环境中的重规划策略，今天就聊到这里。核心就两句话：局部地图要快，全局重规划要稳。把握好这个平衡，你的AGV才能在复杂环境中跑得又稳又安全。
