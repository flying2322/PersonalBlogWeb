20 多传感器融合定位：EKF融合GPS+IMU+编码器、因子图优化

各位同学，今天我们来聊聊多传感器融合定位。说实话，这是AGV导航里最核心、也最让人头疼的一块。你想想看，单靠GPS，进了仓库就抓瞎；单靠IMU，漂移漂到你怀疑人生；单靠编码器，打滑一次就全完蛋。所以，必须把它们揉在一起，取长补短。

我个人习惯把融合方案分成两类：一类是经典的滤波方法，另一类是近年火起来的图优化方法。今天我们就重点讲EKF和因子图优化这两种典型代表。

20.1 为什么需要融合？—— 传感器的“性格”差异

先聊聊每个传感器的脾气。我在项目中遇到过不少新手，上来就写融合代码，结果定位精度还不如单传感器。为什么？因为没摸透每个传感器的“性格”。

传感器 优点 缺点 典型误差模型
GPS 无累积误差，绝对位置 更新频率低（10Hz），易受遮挡 高斯白噪声 + 多径效应
IMU 高频（100Hz+），短时精度高 漂移严重，低频误差大 零偏 + 随机游走
编码器 低成本，速度测量准 打滑、轮胎磨损导致误差累积 比例误差 + 打滑噪声

说白了，GPS是“老实人”，但反应慢；IMU是“急性子”，但记性差；编码器是“苦力”，但容易偷懒。融合的目的，就是让它们互相监督、互相纠正。

20.2 EKF融合：经典但够用

扩展卡尔曼滤波，简称EKF。很多教材把它讲得很玄乎，其实核心就两步：预测和更新。

预测阶段：用IMU和编码器的数据，推算下一时刻的位置。这里要注意，IMU的角速度和加速度，编码器的轮速，都要统一到车体坐标系下。我曾经见过一个项目，IMU坐标系和车体坐标系差了90度没校准，结果定位轨迹直接画了个圈。

更新阶段：当GPS数据到来时，用它来修正预测的误差。EKF的厉害之处在于，它知道每个传感器“可信度”是多少——这个可信度就是协方差矩阵。

核心公式（简化版）：

// 预测
x_pred = f(x_prev, u_imu, u_encoder)  // 运动模型
P_pred = F * P_prev * F^T + Q          // 协方差预测

// 更新
K = P_pred * H^T * (H * P_pred * H^T + R)^(-1)  // 卡尔曼增益
x_est = x_pred + K * (z_gps - H * x_pred)       // 状态更新
P_est = (I - K * H) * P_pred                    // 协方差更新

嗯，这里要注意，Q和R矩阵的调参是个体力活。我刚开始做的时候，Q设得太小，IMU的漂移根本压不住；R设得太小，GPS一抖动整个系统就跟着跳。后来我总结了一个经验：先让AGV静止，调IMU的零偏；再让AGV直线跑，调编码器的比例因子；最后才调GPS的R值。

避坑指南：我曾经在室外AGV上遇到一个问题——GPS信号被高架桥遮挡，定位突然跳变。EKF虽然能平滑，但如果跳变幅度太大，协方差会膨胀，导致后续几分钟定位都不可用。解决方案是：在更新前加一个马氏距离检验，如果GPS观测值和预测值偏差超过3倍标准差，就暂时不用这个观测。

20.3 因子图优化：更现代的选择

EKF虽然经典，但它有个硬伤：只维护当前状态，过去的信息用一次就丢了。因子图优化不一样，它把所有的历史状态和观测都当作“节点”和“因子”，构建成一个图，然后用非线性最小二乘法一次性优化。

为什么因子图在AGV上越来越流行？我举个例子：你的AGV在仓库里转了一圈，回到原点附近。EKF会告诉你“大概在这里”，但因子图优化会利用“闭环检测”这个因子，把整个轨迹拉回正确的位置。说白了，EKF是“走一步看一步”，因子图是“回头看全局”。

因子图的核心思想：

// 因子图优化目标函数
min Σ ||z_ij - h(x_i, x_j)||^2_Σ_ij

// 其中：
// z_ij: 传感器观测（GPS位置、IMU预积分、编码器里程计）
// h(x_i, x_j): 预测模型
// Σ_ij: 观测的协方差矩阵（信息矩阵）

因子图里常见的因子包括：

  • 先验因子：初始位置，通常来自GPS或人工标定
  • IMU预积分因子：两个时刻之间的相对位姿变化
  • 编码器里程计因子：轮速计推算的相对运动
  • GPS因子：绝对位置观测
  • 闭环因子：检测到重复经过同一位置时的约束

你想想看，这么多因子加在一起，优化出来的轨迹自然比EKF平滑得多。不过代价是计算量大——每加入一个新节点，就要重新优化整个图。好在现在有iSAM2这样的增量式求解器，可以只更新受影响的部分。

20.4 两种方案的对比与选型

很多同学问我：“到底用EKF还是因子图？”我的回答是：看场景。

对比维度 EKF 因子图优化
计算资源 低，适合嵌入式MCU 高，需要ARM Cortex-A级别
实时性 好，固定延迟 依赖求解器，可能有波动
闭环能力 弱，无法修正历史轨迹 强，全局优化
实现复杂度 中等，调参麻烦 较高，需要图构建和求解器
适用场景 室外开阔、短距离、低算力 室内外混合、长距离、高精度

我个人建议：如果你的AGV只在室外跑，而且路径简单，EKF完全够用。但如果你要做室内外无缝切换，或者AGV需要在仓库里来回穿梭，那就上因子图优化。我在一个物流项目中，AGV每天跑几十公里，用EKF累积误差越来越大，换成因子图后，闭环检测一触发，定位误差直接降到10厘米以内。

20.5 实战中的融合策略

最后分享一个我常用的融合策略，算是多年踩坑总结出来的：

  1. 初始化阶段：用GPS获取初始位置，IMU静止初始化零偏，编码器标定轮距和脉冲系数。
  2. 正常行驶阶段：以IMU+编码器做高频预测（100Hz），GPS做低频修正（10Hz）。如果GPS信号丢失，切换到纯里程计模式，同时增大协方差。
  3. 重定位阶段：如果GPS恢复后偏差过大，不要直接融合，先做一次“对齐”——用最近几秒的轨迹匹配，确认GPS没有跳变。
  4. 闭环检测：对于因子图方案，定期检测是否回到已知区域。检测方法可以用欧氏距离+时间窗口，也可以用更高级的视觉词袋。

重要提醒：无论用EKF还是因子图，传感器的时间同步都是前提。我见过太多案例，IMU和GPS的时间戳差了50毫秒，融合出来的轨迹就歪了。建议所有传感器都用PTP或NTP同步到同一个时钟源，或者在代码里做插值对齐。

好了，关于多传感器融合定位，今天就聊到这里。EKF和因子图优化各有千秋，关键是根据你的AGV硬件平台和应用场景做选择。记住，没有最好的算法，只有最合适的方案。
