7 编码器：增量式与绝对式编码器、脉冲计数、速度与位置计算

编码器这东西，说白了就是AGV的「眼睛」和「腿」之间的传感器。没有它，电机转了多少圈、轮子走了多远，你完全不知道。我在做第一个AGV项目时，就吃过编码器的亏——选型没选对，结果定位精度差得一塌糊涂。

今天咱们就把编码器彻底聊透。从原理到实战，从选型到避坑，一步到位。

7.1 增量式编码器 vs 绝对式编码器

先搞清楚这两个最基础的概念。我习惯这么理解：

  • 增量式：只告诉你「动了多少」，不告诉你「在哪儿」
  • 绝对式：直接告诉你「当前位置是哪儿」

你想想看，这区别有多大？

增量式编码器

原理很简单：码盘上刻了一圈黑白相间的条纹，光耦透过条纹产生脉冲信号。每转一圈，输出固定数量的脉冲。

它的核心输出是两路信号：A相和B相，相位差90°。通过判断A相和B相的先后顺序，就能知道电机是正转还是反转。

关键点：增量式编码器断电后位置信息丢失。重新上电必须回零。

我在项目中遇到过一个问题：AGV在充电站断电后，重新启动时不知道自己在哪里。后来加了磁条回零方案才解决。嗯，这个坑踩得值。

绝对式编码器

绝对式编码器就高级多了。它每个位置都有唯一的编码值，断电后位置信息不丢失。上电就知道自己在哪儿。

常见的有两种：

  • 单圈绝对式：一圈内有唯一编码，超过一圈就重复
  • 多圈绝对式：不仅记录圈内位置，还记录圈数，理论上可以记录几十甚至上百圈

AGV导航中，我建议优先考虑多圈绝对式。为什么？因为AGV经常需要长距离移动，单圈绝对式根本不够用。

特性 增量式 绝对式
断电记忆 无 有
成本 低 高
精度 取决于线数 取决于位数
接线 简单（A/B/Z） 复杂（并行/SSI/BiSS）
适用场景 低成本AGV 高精度、高可靠性AGV

7.2 脉冲计数——从硬件到软件

脉冲计数听起来简单，但做起来有不少门道。

硬件层面

编码器输出的脉冲信号，需要接入MCU的定时器或专用的编码器接口。我常用的方案：

  • STM32定时器编码器模式：直接硬件解码，自动计数，CPU零负担
  • 外部中断+GPIO：低成本方案，但CPU负担重，容易丢脉冲
  • 专用编码器芯片：如LS7366，适合高精度场景

我个人习惯用STM32的定时器编码器模式。它内部有硬件滤波器，能有效抑制毛刺信号。我曾经用外部中断方案，结果电机一震动，脉冲数就乱跳。换成定时器模式后，问题直接解决。

软件层面

脉冲计数的核心代码其实不长：

// 定时器编码器模式初始化
void encoder_init(void) {
    TIM->SMCR = TIM_SMCR_SMS_3;  // 编码器模式3（A/B双边沿触发）
    TIM->CCMR1 = TIM_CCMR1_CC1S_0 | TIM_CCMR1_CC2S_0;  // 输入捕获
    TIM->CCER = 0x0011;  // 使能捕获，不反相
    TIM->ARR = 0xFFFF;   // 自动重装载值
    TIM->CR1 |= TIM_CR1_CEN;  // 启动定时器
}

// 读取脉冲数
int32_t encoder_get_pulse(void) {
    return (int32_t)TIM->CNT;
}

// 清零
void encoder_clear(void) {
    TIM->CNT = 0;
}

小技巧：读取脉冲数时，建议连续读两次，如果两次值相同再使用。这样可以避免在读取过程中定时器溢出导致的错误值。

7.3 速度计算——三种常用方法

有了脉冲数，怎么算速度？我常用的方法有三种：

方法一：M法（测频法）

固定时间窗口，统计这个窗口内的脉冲数。

速度 = 脉冲数 / (时间窗口 × 编码器线数 × 减速比) × 轮周长

优点：高速时精度高
缺点：低速时脉冲少，误差大

方法二：T法（测周法）

测量两个脉冲之间的时间间隔。

速度 = 1 / (脉冲间隔时间 × 编码器线数 × 减速比) × 轮周长

优点：低速时精度高
缺点：高速时时间间隔太短，误差大

方法三：M/T法（综合法）

结合M法和T法的优点。高速用M法，低速用T法，中间区域平滑切换。

我在实际项目中，强烈推荐M/T法。它覆盖了全速范围，精度最稳定。我曾经在AGV上只用M法，结果低速时速度波动特别大，导致定位抖动。换成M/T法后，问题迎刃而解。

注意：速度计算一定要做低通滤波。原始速度数据噪声很大，直接用于控制会导致电机抖动。我习惯用一阶低通滤波，截止频率设在5-10Hz。

7.4 位置计算——从脉冲到坐标

位置计算是编码器数据融合的核心。说白了，就是把脉冲数转换成AGV在空间中的位置。

单轮位置计算

位置 = 脉冲数 / (编码器线数 × 减速比) × 轮周长

举个例子：编码器线数1000，减速比10:1，轮周长0.5m，脉冲数5000。

位置 = 5000 / (1000 × 10) × 0.5 = 0.25m

双轮差速模型

AGV常用双轮差速驱动。左右轮各有一个编码器，通过它们的差值可以计算出AGV的航向角。

左轮位移 = 左轮脉冲数 × 脉冲当量
右轮位移 = 右轮脉冲数 × 脉冲当量

AGV位移 = (左轮位移 + 右轮位移) / 2
航向变化 = (右轮位移 - 左轮位移) / 轮距

这个模型在直道上很准，但转弯时会有误差。为什么？因为轮胎会打滑。我做过测试，急转弯时航向误差能达到5°以上。

航位推算法（Dead Reckoning）

有了位移和航向，就可以做航位推算了：

x += 位移 × cos(航向)
y += 位移 × sin(航向)

但注意，航位推算的误差会累积。走10米可能误差只有1cm，走100米误差可能就到10cm了。所以编码器必须配合其他传感器（IMU、激光雷达）做融合。

核心结论：编码器在短距离内精度很高，但长距离必须融合其他传感器。单独用编码器做导航，AGV跑不了多远就会偏。

7.5 避坑指南——我踩过的那些坑

做编码器相关项目，有几个坑我印象特别深：

  • 脉冲丢失：电机高速运行时，如果MCU中断响应不及时，会丢脉冲。解决方案是使用硬件计数器。
  • 信号毛刺：电机启停时，编码器信号会有毛刺。硬件上要加RC滤波，软件上要做去抖。
  • 零位漂移：增量式编码器长时间运行后，零位会漂移。定期回零是必须的。
  • 温度影响：编码器内部的光电器件受温度影响，脉冲宽度会变化。高精度场景要考虑温度补偿。

我曾经在一个项目中，AGV运行半小时后定位误差越来越大。排查了两天才发现，是编码器线缆屏蔽层没接地，电机产生的电磁干扰导致脉冲计数错误。接地后问题立刻解决。嗯，这个教训让我养成了「先查接地」的习惯。
