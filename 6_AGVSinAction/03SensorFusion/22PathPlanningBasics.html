22 路径规划基础：Dijkstra算法、A*算法、DWA算法

各位做AGV的朋友，今天我们来聊聊路径规划。说实话，这是AGV导航系统里最核心的模块之一。没有好的路径规划，传感器融合得再好，车子也跑不起来。

我个人习惯把路径规划分成两层：全局路径规划和局部路径规划。全局规划负责找一条从起点到终点的宏观路径，局部规划则负责处理实时避障和运动控制。今天要讲的Dijkstra和A*属于全局规划，DWA属于局部规划。

一、Dijkstra算法：最朴素的路径搜索

Dijkstra算法是路径规划里的"老前辈"了。它的思路很简单：从起点开始，一层一层往外扩展，直到找到终点。每次扩展都选当前代价最小的节点。

说白了，这就是一个广度优先搜索的加权版本。每个节点都记录从起点到它的最短距离，然后不断更新。

核心思想：贪心策略 + 动态规划。每次选当前最优的节点，保证一旦节点被访问，它的最短路径就已经确定了。

我在项目中遇到过一个问题：地图稍微大一点，Dijkstra就跑得很慢。为什么？因为它要遍历所有节点，没有方向性。你想想看，从北京到上海，它可能先往西藏方向搜一圈，再折回来。

// Dijkstra算法伪代码
function Dijkstra(graph, start, goal):
    dist[start] = 0
    priority_queue.push((0, start))
    
    while priority_queue is not empty:
        cost, current = priority_queue.pop()
        
        if current == goal:
            return reconstruct_path()
        
        for neighbor in graph.neighbors(current):
            new_cost = cost + graph.cost(current, neighbor)
            if new_cost < dist[neighbor]:
                dist[neighbor] = new_cost
                priority_queue.push((new_cost, neighbor))
    
    return None  // 无路径

实用建议：如果地图节点数超过1万，Dijkstra就不太合适了。我一般用它做小范围路径规划，或者作为其他算法的基准对比。

二、A*算法：带方向感的路径搜索

A*算法是Dijkstra的升级版。它加了一个启发式函数，让搜索有了方向感。估价函数 f(n) = g(n) + h(n)，其中g(n)是实际代价，h(n)是估计代价。

我曾经踩过一个坑：h(n)选错了，导致A*退化成Dijkstra。当时排查了半天，才发现是启发函数设计不合理。

重要提醒：h(n)必须满足可采纳性（admissible），即h(n) ≤ 实际代价。否则A*可能找不到最优路径。

常用的启发函数有几种：

启发函数 适用场景 计算公式
曼哈顿距离 四方向移动（上下左右） |x1-x2| + |y1-y2|
欧几里得距离 八方向或自由移动 √[(x1-x2)² + (y1-y2)²]
对角线距离 八方向移动（带对角线） max(|dx|, |dy|) + (√2-1)*min(|dx|, |dy|) 
// A*算法伪代码
function AStar(graph, start, goal):
    open_set = priority_queue()
    open_set.push(start, f(start))
    came_from = empty_map
    g_score[start] = 0
    f_score[start] = h(start, goal)
    
    while open_set is not empty:
        current = open_set.pop()
        
        if current == goal:
            return reconstruct_path(came_from, current)
        
        for neighbor in graph.neighbors(current):
            tentative_g = g_score[current] + graph.cost(current, neighbor)
            if tentative_g < g_score[neighbor]:
                came_from[neighbor] = current
                g_score[neighbor] = tentative_g
                f_score[neighbor] = g_score[neighbor] + h(neighbor, goal)
                open_set.push(neighbor, f_score[neighbor])
    
    return None

我的经验：在AGV项目中，我通常用A*做全局路径规划。地图用栅格表示，每个格子0.5米。A*能在几十毫秒内找到路径，完全满足实时性要求。

三、DWA算法：动态窗口法

DWA（Dynamic Window Approach）是局部路径规划的经典算法。它不找全局路径，而是考虑当前时刻的速度和角速度，在速度空间里采样，然后选最优的一组。

说白了，DWA就是在问：我接下来该以多快的速度、多大的转弯角度走？

DWA有三个核心步骤：

  1. 速度采样：在允许的速度范围内采样(v, ω)组合
  2. 轨迹预测：对每个(v, ω)模拟一段时间的运动轨迹
  3. 轨迹评价：用评价函数选最优轨迹

评价函数通常包含三个项：

  • 方位角代价：轨迹终点朝向目标点的角度偏差
  • 障碍物代价：轨迹与最近障碍物的距离
  • 速度代价：鼓励高速行驶，提高效率
// DWA算法伪代码
function DWA(robot_state, goal, obstacles):
    // 1. 计算动态窗口
    v_min = max(0, robot.v - max_accel * dt)
    v_max = min(v_max_abs, robot.v + max_accel * dt)
    w_min = max(-w_max_abs, robot.w - max_angular_accel * dt)
    w_max = min(w_max_abs, robot.w + max_angular_accel * dt)
    
    best_trajectory = None
    best_cost = INF
    
    // 2. 采样并评价
    for v in [v_min : v_resolution : v_max]:
        for w in [w_min : w_resolution : w_max]:
            trajectory = simulate_trajectory(robot_state, v, w, predict_time)
            
            // 3. 评价
            heading_cost = calc_heading_cost(trajectory, goal)
            obstacle_cost = calc_obstacle_cost(trajectory, obstacles)
            velocity_cost = calc_velocity_cost(v)
            
            total_cost = alpha * heading_cost + beta * obstacle_cost + gamma * velocity_cost
            
            if total_cost < best_cost:
                best_cost = total_cost
                best_trajectory = (v, w)
    
    return best_trajectory

避坑指南：我曾经把障碍物代价的权重设得太高，结果AGV在空旷区域也龟速前进。后来调整了权重，让车子在安全前提下尽量快跑。权重调参是个细致活，建议先仿真再实车。

四、三种算法的对比与选择

特性 Dijkstra A* DWA
规划类型 全局 全局 局部
最优性 保证最优 保证最优（h可采纳） 次优（实时性优先）
计算速度 慢 快 很快
适用场景 小地图、教学演示 静态环境全局规划 动态避障、实时控制

在实际AGV系统中，我通常这样搭配：A*做全局规划，生成一条参考路径。DWA做局部规划，沿着参考路径走，同时避开动态障碍物。Dijkstra嘛，我一般只在调试时用，或者作为A*的对比基准。

总结一下：路径规划没有银弹。全局规划选A*，局部规划选DWA，这是AGV领域最经典的组合拳。但具体参数怎么调，还得看你的车、你的场地、你的任务。

嗯，今天就聊到这儿。这三种算法够你应付大部分AGV路径规划场景了。记住，算法是死的，场景是活的。多动手调参，多跑仿真，慢慢就有感觉了。
