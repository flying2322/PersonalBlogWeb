24 ROS系统集成：ROS节点通信、Bag包录制与回放、Rviz可视化

说到ROS集成，这其实是AGV传感器融合里最“接地气”的一环。你算法写得再好，跑不起来、看不到效果，那都是白搭。我个人习惯把ROS比作AGV的“神经系统”——节点就是神经元，话题就是神经信号，而Bag包就是你的记忆存档。

今天咱们就聊聊这三板斧：节点怎么通信、数据怎么录下来回放、以及怎么用Rviz把看不见的传感器数据“画”出来。

24.1 ROS节点通信：AGV的“神经元”怎么对话

ROS里每个传感器驱动、每个算法模块，都是一个独立的节点。节点之间通过话题（Topic）或服务（Service）通信。我建议你优先用话题，因为AGV传感器数据是流式的，话题的发布/订阅模型天然适合。

举个例子，激光雷达节点发布/scan话题，里程计节点发布/odom话题。你的融合节点订阅这两个话题，然后发布融合后的位姿。代码结构大概是这样：

// 伪代码：传感器融合节点
ros::Subscriber sub_scan = nh.subscribe("/scan", 10, scanCallback);
ros::Subscriber sub_odom = nh.subscribe("/odom", 10, odomCallback);
ros::Publisher pub_pose = nh.advertise<geometry_msgs::PoseStamped>("/fused_pose", 10);

void scanCallback(const sensor_msgs::LaserScan::ConstPtr& msg) {
    // 处理激光数据
}

void odomCallback(const nav_msgs::Odometry::ConstPtr& msg) {
    // 处理里程计数据
    // 融合后发布
    pub_pose.publish(fused_pose_msg);
}

这里有个坑——时间同步。我在项目中遇到过激光和里程计时间戳对不上的情况，融合出来的位姿直接飘了。解决办法是用message_filters做时间同步：

message_filters::Subscriber<sensor_msgs::LaserScan> scan_sub(nh, "/scan", 10);
message_filters::Subscriber<nav_msgs::Odometry> odom_sub(nh, "/odom", 10);
TimeSynchronizer<sensor_msgs::LaserScan, nav_msgs::Odometry> sync(scan_sub, odom_sub, 10);
sync.registerCallback(boost::bind(&callback, _1, _2));

嗯，这里要注意：时间同步的容忍窗口别设太大，我一般设0.05秒，超过这个时间差的数据直接丢掉。

我的小技巧： 调试节点通信时，用 rqt_graph 看一眼节点和话题的拓扑图。如果发现某个节点没连上，八成是话题名拼错了。

24.2 Bag包录制与回放：把现场“搬”回实验室

Bag包是ROS的“黑匣子”。你在现场跑AGV，录一个bag包，回到办公室就能复现现场的所有传感器数据。这功能太实用了——你想想看，调试算法时不用每次都推着AGV跑一圈。

录制bag包的命令很简单：

rosbag record -o agv_data /scan /odom /imu /cmd_vel

这条命令会录制激光、里程计、IMU和速度指令四个话题。我个人习惯加-o参数，这样文件名会自动带上时间戳，方便管理。

回放时要注意：

rosbag play agv_data_2024-01-15-14-30-00.bag

默认是1倍速回放。如果你想慢速分析，可以加-r 0.5参数。我曾经调试一个融合算法，发现某个时刻位姿跳变，用0.2倍速回放才看清是激光数据丢了一帧。

避坑指南： 我曾经录了一个小时的bag包，结果回放时发现里程计话题没录进去——因为启动录制时里程计节点还没起来。所以我的习惯是：先启动所有传感器节点，等个几秒钟，确认话题都在了，再开始录制。

还有一个实用技巧：bag包压缩。激光雷达数据量很大，一小时能录几十GB。用--lz4参数可以压缩存储：

rosbag record --lz4 -o agv_data /scan /odom /imu

压缩比大概3:1，解压速度也很快，不影响回放。

24.3 Rviz可视化：让传感器数据“看得见”

Rviz是ROS的“眼睛”。你写融合算法，光看数字是看不出问题的。把激光点云、路径、位姿估计都显示在Rviz里，一眼就能看出哪里不对劲。

我常用的Rviz配置包括：

  • LaserScan：显示激光雷达的点云，颜色按距离渐变
  • Odometry：显示里程计的路径轨迹
  • PoseWithCovariance：显示融合后的位姿和协方差椭圆
  • Path：显示规划路径
  • TF：显示坐标系变换关系

启动Rviz的命令：

rosrun rviz rviz

然后手动添加显示项。不过我更推荐用配置文件：

rosrun rviz rviz -d my_agv_config.rviz

这样每次启动都是同样的布局，省得重复配置。

说到TF，这是Rviz里最容易出问题的地方。你想想看，激光雷达在车头，里程计在车中心，IMU在车尾——如果TF树没配好，Rviz里显示的数据全是对不上的。我建议用tf_echo工具检查：

rosrun tf tf_echo /base_link /laser_frame

这条命令会实时显示两个坐标系之间的变换关系。如果发现数值不对，赶紧检查你的URDF文件。

核心要点： Rviz不是“锦上添花”的工具，而是调试传感器融合的“刚需”。我每次跑新算法，第一件事就是打开Rviz看数据流。如果激光点云和里程计轨迹对不上，那融合结果肯定有问题。

24.4 知识体系总览

下面这张图总结了ROS集成的核心逻辑。说白了就是：节点负责干活，话题负责传数据，Bag包负责记录，Rviz负责展示。四者缺一不可。

最后说一句：ROS这套工具链，用熟了就是你的“第二双手”。我见过太多人花大量时间写算法，却忽略了调试工具。结果算法跑起来出了问题，两眼一抹黑。记住——先让数据流起来，再谈算法精度。

我的习惯： 每次跑新场景前，先录一段bag包，然后在Rviz里回放一遍。确认所有传感器数据都正常、TF树正确，再开始调融合参数。这步能省掉80%的调试时间。
