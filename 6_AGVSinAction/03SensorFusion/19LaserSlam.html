19 激光SLAM：Cartographer框架、子图构建、闭环约束、栅格地图

聊到激光SLAM，Cartographer绝对是个绕不开的名字。我个人习惯把它称为“Google家的扫地僧”——看着低调，但真用起来就知道有多扎实。当年我在做AGV项目时，试过好几个开源方案，最后稳定跑起来的，就是Cartographer。今天咱们就把它拆开，看看里面到底是怎么玩的。

19.1 Cartographer整体框架

Cartographer的核心思想，说白了就是“局部先建图，全局再优化”。它不像某些方案一上来就搞全局优化，那样计算量太大，实时性扛不住。Cartographer的做法是：

  • 前端（Local SLAM）：实时处理激光数据，构建局部子图
  • 后端（Global SLAM）：定期做闭环检测和全局优化

我画了一张框架图，帮你理清这个流程：

你看，整个流程其实很清晰。传感器数据进来，前端先快速构建子图，后端再慢慢做全局优化。这种“前后端分离”的设计，让Cartographer既能跑在嵌入式设备上，又能保证大场景下的精度。

19.2 子图构建（Submap）

子图是Cartographer里最核心的概念之一。我刚开始接触时，总觉得“子图”这词有点玄乎。其实说白了，子图就是一小块局部地图，由连续几帧激光数据拼接而成。

具体怎么构建的呢？

  • 扫描匹配（Scan Matching）：新来一帧激光数据，先跟当前子图做匹配，找到最优位姿
  • 插入子图：匹配成功后，把这一帧数据“插入”到子图中，更新栅格概率
  • 子图完成：当子图里插入了足够多的帧（比如几十帧），就把它“冻结”，开始构建下一个子图

关键点：子图之间是有重叠的。每个新子图都会跟之前的子图有部分区域重合，这为后面的闭环检测埋下了伏笔。

我记得有一次调试AGV，发现地图总是出现“重影”。查了半天，原来是子图构建时，扫描匹配的参数没调好。匹配太松，帧与帧之间对不齐；匹配太紧，又容易陷入局部最优。嗯，这里要注意，ceres_scan_matcher 的权重参数，我建议从 1.0 开始调，别一上来就搞太大。

19.3 闭环约束（Loop Closure）

闭环检测，是SLAM里最性感的部分。没有闭环，地图就会像喝醉了一样越飘越远。Cartographer的闭环检测，核心思路是：

  1. 检测候选闭环：当一个新的子图完成时，把它跟之前所有子图做匹配
  2. 计算约束：如果匹配得分足够高，就认为找到了一个闭环，计算相对位姿
  3. 加入优化：把这个闭环约束加入后端图优化中，调整所有子图的位姿

这里有个细节：Cartographer用的是分支定界（Branch and Bound）加速匹配。为什么？因为暴力匹配太慢了。你想想看，一个子图可能有几万个栅格，跟所有历史子图匹配一遍，计算量爆炸。

我的经验：分支定界的搜索窗口大小很关键。设太大，匹配慢；设太小，容易漏掉闭环。我一般设 7m × 7m，角度范围 30°，效果比较均衡。

我曾经在一个仓库项目里，AGV跑了半小时后突然“跳变”——地图位置瞬间偏移了半米。排查后发现，是闭环检测的得分阈值设得太低，把假闭环当成真闭环了。后来我把 min_score 从 0.3 提到 0.6，问题就解决了。

19.4 栅格地图（Occupancy Grid Map）

最后说说栅格地图。Cartographer用的是概率栅格地图，每个格子存的是“被占据的概率”，而不是简单的0或1。

更新规则很简单：

  • 激光打到的地方，格子概率增加（被占据）
  • 激光穿过的区域，格子概率减少（空闲）
  • 没被观测到的区域，概率保持0.5（未知）

代码里是这样实现的：

// 栅格概率更新（Cartographer源码简化版）
void UpdateGrid(Cell* cell, bool is_hit) {
  float odds = cell->probability / (1.0f - cell->probability);
  if (is_hit) {
    odds *= kHitOdds;  // 击中更新
  } else {
    odds *= kMissOdds; // 穿过更新
  }
  cell->probability = odds / (1.0f + odds);
}

这里 kHitOdds 和 kMissOdds 是两个超参数。我习惯设 kHitOdds = 2.0，kMissOdds = 0.5。这样更新几次后，地图就能快速收敛。

避坑指南：我曾经把 kHitOdds 设得太大（比如 10.0），结果地图上全是“噪点”——激光稍微有点噪声，格子概率就飙到0.9以上。调参数时，记得先在小场景里验证。

栅格地图的分辨率也是个关键。分辨率太高，内存爆炸；分辨率太低，细节丢失。我一般用 0.05m（5厘米），室内AGV够用了。如果是室外大场景，可以降到 0.1m。

19.5 小结

Cartographer这套框架，说白了就是“先局部后全局”的思路。子图构建保证了实时性，闭环约束保证了全局一致性，栅格地图提供了可导航的环境表示。三个环节环环相扣，缺一不可。

如果你正在做AGV导航，我建议先从Cartographer的官方demo跑起，把参数调一遍，感受一下每个参数对地图质量的影响。别急着上真车，先在数据集上跑通，再移植到嵌入式平台。嗯，这样能省不少调试时间。
