16 特征提取：点云特征(FPFH、SHOT)、图像特征(SIFT、ORB)、特征匹配

各位同学，今天我们来聊聊传感器融合里最核心的一环——特征提取与匹配。

说实话，做AGV导航这么多年，我踩过最大的坑就是特征选错了。你想想看，如果特征本身就不靠谱，后面什么卡尔曼滤波、图优化，全都是白搭。所以这一章，咱们把点云和图像两边的特征都捋一遍。

16.1 点云特征：FPFH 与 SHOT

点云特征，说白了就是给三维点找个“身份证”。我最早做激光SLAM时，用的是最朴素的点特征，后来发现场景一复杂就崩。直到用上FPFH和SHOT，才算真正稳下来。

16.1.1 FPFH（快速点特征直方图）

FPFH是Rusu那帮人搞出来的，本质是对每个点邻域内的几何关系做统计。它不直接描述点本身，而是描述点周围的“地形”。

核心思想： 对每个查询点，计算它与邻域内所有点的法线夹角、距离等关系，然后统计成33维的直方图。

我个人习惯用PCL里的实现，代码长这样：

// C++ 示例：FPFH 特征提取
pcl::PointCloud<pcl::PointXYZ>::Ptr cloud(new pcl::PointCloud<pcl::PointXYZ>);
pcl::PointCloud<pcl::Normal>::Ptr normals(new pcl::PointCloud<pcl::Normal>);
pcl::FPFHEstimation<pcl::PointXYZ, pcl::Normal, pcl::FPFHSignature33> fpfh;
fpfh.setInputCloud(cloud);
fpfh.setInputNormals(normals);
pcl::search::KdTree<pcl::PointXYZ>::Ptr tree(new pcl::search::KdTree<pcl::PointXYZ>);
fpfh.setSearchMethod(tree);
pcl::PointCloud<pcl::FPFHSignature33>::Ptr fpfh_features(new pcl::PointCloud<pcl::FPFHSignature33>);
fpfh.setRadiusSearch(0.05); // 5cm 邻域
fpfh.compute(*fpfh_features);
我的经验： 邻域半径别设太大。我在仓库AGV上试过，半径设到10cm以上，特征就开始模糊，匹配时一堆误匹配。一般5cm左右比较稳。

16.1.2 SHOT（方向直方图签名）

SHOT比FPFH更“精细”一点。它不光统计几何关系，还引入了局部参考系（LRF），让特征具有旋转不变性。

SHOT的特点：

  • 维度更高：默认352维（32个方位角 × 11个径向分区）
  • 对噪声更鲁棒：因为用了局部参考系做归一化
  • 计算量更大：比FPFH慢2-3倍

我曾经在室外AGV上对比过两者。FPFH在草地场景下误匹配率约15%，SHOT能降到5%以下。但代价是每帧处理时间多了30ms。嗯，这里要注意：如果你用的是嵌入式平台，FPFH可能更现实。

避坑指南： 我曾经在点云密度不均匀的场景里直接用SHOT，结果局部参考系算出来全是歪的。后来加了体素滤波下采样，才把特征质量提上来。所以，特征提取前一定要做预处理。

16.2 图像特征：SIFT 与 ORB

图像特征这块，我最早学的是SIFT，后来项目里为了实时性换成了ORB。两者各有千秋，咱们一个一个说。

16.2.1 SIFT（尺度不变特征变换）

SIFT是Lowe在1999年提出的，到现在二十多年了，依然是图像特征里的“天花板”。它的核心是构建高斯差分金字塔，在尺度空间里找极值点。

SIFT的优势：

  • 尺度不变性：图像放大缩小都不怕
  • 旋转不变性：图像转个角度照样匹配
  • 光照鲁棒：对亮度变化不敏感

但缺点也很明显——慢。一张640×480的图，SIFT提取特征要100-200ms。我在AGV上试过，跑SIFT的话帧率直接掉到5fps以下，根本没法用。

# Python 示例：OpenCV SIFT
import cv2
img = cv2.imread('scene.jpg', 0)
sift = cv2.SIFT_create()
keypoints, descriptors = sift.detectAndCompute(img, None)
print(f"检测到 {len(keypoints)} 个特征点")

16.2.2 ORB（定向FAST和旋转BRIEF）

ORB是2011年Ethan Rublee搞出来的，说白了就是FAST角点检测 + BRIEF描述子的升级版。它加了方向信息，让特征有了旋转不变性。

ORB的特点：

  • 极快：比SIFT快两个数量级
  • 二进制描述子：用汉明距离匹配，比欧氏距离快
  • 尺度不变性弱：没有金字塔的话，尺度变化大了就崩

我现在的AGV项目，90%的情况都用ORB。为什么？因为实时性要求摆在那里。你想想看，AGV跑起来每秒要处理10帧以上图像，SIFT根本扛不住。

关键对比： SIFT适合离线建图、高精度场景；ORB适合在线定位、实时导航。选哪个，取决于你的帧率要求和计算资源。

16.3 特征匹配：从粗配到精配

特征提取完了，下一步就是匹配。匹配的质量直接决定后续的位姿估计准不准。

16.3.1 匹配策略

我常用的匹配方法有三种：

方法 原理 适用场景 我的评价
暴力匹配 穷举所有特征对 特征点少（<500） 简单但慢，小场景凑合用
FLANN匹配 用KD树或LSH加速 特征点多（>1000） 我项目里最常用，又快又稳
比率测试匹配 取最近邻与次近邻距离比 所有场景 Lowe提出的，能过滤掉大部分误匹配

我个人习惯用FLANN + 比率测试的组合。比率阈值一般设0.7-0.8，太严了匹配太少，太松了误匹配多。

# Python 示例：FLANN 匹配 + 比率测试
import cv2
# 假设 des1, des2 是两幅图的描述子
FLANN_INDEX_KDTREE = 1
index_params = dict(algorithm=FLANN_INDEX_KDTREE, trees=5)
search_params = dict(checks=50)
flann = cv2.FlannBasedMatcher(index_params, search_params)
matches = flann.knnMatch(des1, des2, k=2)

# 比率测试
good_matches = []
for m, n in matches:
    if m.distance < 0.75 * n.distance:
        good_matches.append(m)
print(f"保留 {len(good_matches)} 个匹配对")

16.3.2 点云与图像的跨模态匹配

这里有个难点：点云和图像的特征维度不同，怎么匹配？

我常用的做法是投影法。把3D点云投影到图像平面上，然后在2D图像里找对应的特征点。这样就把3D-2D匹配问题，转化成了2D-2D匹配问题。

具体步骤：

  1. 用相机内参把3D点投影到图像坐标
  2. 在投影位置附近搜索图像特征点
  3. 用RANSAC剔除误匹配
注意： 投影法依赖标定精度。我曾经因为相机和激光雷达的外参标定差了2度，导致投影偏差了10个像素，匹配全乱了。所以，标定一定要做扎实。
