15 数据预处理：点云滤波与图像去畸变

各位同学，大家好。今天我们来聊聊传感器融合里一个特别“脏活累活”的环节——数据预处理。

说实话，很多刚入行的工程师，拿到激光雷达和相机数据就往算法里灌。结果呢？定位飘得妈都不认。我当年也犯过这个错。后来才明白，数据预处理做不好，后面的一切都是空中楼阁。

这一章，我带你手把手过一遍：点云怎么滤波、图像怎么去畸变、异常值怎么剔除。全是实战经验，没有废话。

一、点云滤波：别让噪声毁了你的地图

激光雷达点云，说白了就是一堆三维坐标点。但原始数据里什么妖魔鬼怪都有：飘在空中的灰尘、玻璃上的反射噪点、甚至飞过的蚊子。你想想看，要是把这些都当成障碍物，AGV 还怎么走？

1. 体素滤波（Voxel Filter）——降采样利器

体素滤波的核心思想很简单：把空间切成小立方体（体素），每个立方体里只保留一个点。这样既能大幅降低点云数量，又能保留几何结构。

为什么需要它？ 一个 16 线激光雷达，每秒产生 30 万个点。直接处理？算力扛不住。体素滤波可以把点云压缩到原来的 1/10，而形状基本不变。

关键参数：体素大小

  • 室内场景：0.05m - 0.1m（5cm 到 10cm）
  • 室外场景：0.1m - 0.2m
  • 我个人的习惯：先设 0.1m，看效果再微调
// C++ 示例：PCL 体素滤波
pcl::VoxelGrid<pcl::PointXYZ> voxel_filter;
voxel_filter.setInputCloud(cloud_in);
voxel_filter.setLeafSize(0.1f, 0.1f, 0.1f);  // 体素边长 10cm
voxel_filter.filter(*cloud_out);

我的经验：体素大小别设太小。设 0.02m 的话，点云还是太密，滤波效果不明显。设 0.5m 的话，墙角细节就没了。0.1m 是个不错的起点。

2. 统计滤波（Statistical Outlier Removal）——揪出离群点

体素滤波只管降采样，不管噪声。统计滤波就是干这个的。

原理其实很直观：对每个点，计算它到 k 个最近邻的平均距离。如果这个距离明显大于全局平均值，那它大概率是个离群点。

我在项目中遇到过：有一次在仓库里测试，AGV 老是莫名其妙地急停。排查了半天，发现是屋顶通风口吹下来的灰尘，在点云里形成了几个“幽灵点”。统计滤波一上，问题立刻解决。

// PCL 统计滤波
pcl::StatisticalOutlierRemoval<pcl::PointXYZ> sor;
sor.setInputCloud(cloud_in);
sor.setMeanK(50);          // 近邻点数
sor.setStddevMulThresh(1.0); // 标准差倍数阈值
sor.filter(*cloud_out);

注意：标准差倍数设得越小，剔除得越狠。设 0.5 的话，连正常点都可能被干掉。我一般从 1.0 开始调，效果不满意再改。

二、图像去畸变：让相机看到真实的世界

相机镜头不是完美的。尤其是广角镜头，画面边缘的直线会变成曲线。这就是畸变。

畸变主要分两种：

  • 径向畸变：画面像鱼眼一样向外凸（桶形）或向内凹（枕形）
  • 切向畸变：镜头和成像平面不平行导致的倾斜

去畸变的本质，就是用一个数学模型把变形的像素“拉”回正确位置。

畸变模型公式

// 径向畸变
x_corrected = x * (1 + k1*r^2 + k2*r^4 + k3*r^6)
y_corrected = y * (1 + k1*r^2 + k2*r^4 + k3*r^6)

// 切向畸变
x_corrected = x + [2*p1*x*y + p2*(r^2 + 2*x^2)]
y_corrected = y + [p1*(r^2 + 2*y^2) + 2*p2*x*y]

其中 k1、k2、k3 是径向畸变系数，p1、p2 是切向畸变系数。这些参数来自相机标定。

实操建议：

  • 用 OpenCV 的 cv::undistort() 一步到位
  • 或者用 cv::initUndistortRectifyMap() + cv::remap()，效率更高
  • 我建议用 remap 方式，因为可以提前算好映射表，实时处理时只查表，速度飞快
// OpenCV 去畸变示例
cv::Mat camera_matrix, dist_coeffs;
// ... 从标定文件读取参数

cv::Mat map1, map2;
cv::initUndistortRectifyMap(camera_matrix, dist_coeffs, 
    cv::Mat(), camera_matrix, image.size(), CV_32FC1, map1, map2);

cv::Mat undistorted_img;
cv::remap(distorted_img, undistorted_img, map1, map2, cv::INTER_LINEAR);

避坑指南：我曾经在标定时用了错误的棋盘格尺寸，结果去畸变后图像边缘扭曲得更厉害了。标定板尺寸一定要量准，差 1mm 都不行。

三、异常值剔除：别让一个坏点毁了全局

异常值不光是点云里的噪声，还包括：

  • 激光雷达的“飞点”（比如打到玻璃边缘，距离突变）
  • 相机图像中的坏像素
  • 时间戳错乱的数据包

1. 基于距离的异常值剔除

激光雷达有最大/最小测量范围。超出范围的直接扔掉。这个最简单，也最有效。

// 距离范围滤波
if (point.x < 0.3f || point.x > 50.0f) continue;  // 0.3m 到 50m

2. 基于邻域密度的剔除

如果一个点周围 10cm 内没有其他点，那它很可能是孤立的噪声点。这个逻辑和统计滤波类似，但更轻量。

3. 时间戳一致性检查

多传感器融合时，时间戳必须对齐。如果某个数据包的时间戳比上一帧还早，或者偏差超过 100ms，直接丢弃。

重要提醒：异常值剔除要放在预处理的第一步。先去掉明显错误的数据，再做滤波和去畸变。顺序搞反了，计算资源就白费了。

四、预处理流程总结

步骤 输入 操作 输出
1 原始点云 距离范围滤波 + 时间戳检查 干净点云（粗）
2 干净点云（粗） 体素滤波（降采样） 稀疏点云
3 稀疏点云 统计滤波（去离群点） 最终点云
4 原始图像 去畸变（remap） 矫正图像
5 矫正图像 坏像素检测 + 插值 最终图像

嗯，到这里，数据预处理的核心内容就讲完了。你可能会问：这些操作看起来都不难，为什么还要单独讲一章？

因为在实际项目中，预处理往往是整个系统里最耗时的环节。参数调不好，后面定位精度直接掉一个数量级。我见过太多人花几周调 SLAM 算法，结果发现是预处理参数没设对。

所以，我的建议是：花 30% 的时间在预处理上，一点都不亏。

一句话总结：体素滤波降采样，统计滤波去噪声，图像去畸变保精度，异常值剔除防翻车。四步走完，数据才算“能用”。
