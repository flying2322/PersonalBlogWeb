23 运动控制——PID控制器、纯追踪模型、Stanley控制器

各位，欢迎来到运动控制这一讲。

说实话，在AGV导航系统里，传感器融合负责“感知”，路径规划负责“决策”，而运动控制，就是那个最终“执行”的环节。你前面算得再准，规划得再好，如果控制跟不上，车就会像喝醉了一样，左右摇摆，甚至冲出路径。我见过太多项目，传感器精度很高，但最后死在控制参数没调好上。

今天我们就来聊聊三种最经典的运动控制方法：PID控制器、纯追踪模型和Stanley控制器。它们各有各的脾气，也各有各的适用场景。

一、PID控制器：最朴素的“纠偏”大师

PID，比例-积分-微分。说白了，就是看你现在偏了多少（P），过去累计偏了多少（I），以及未来可能偏多少（D），然后综合起来给一个控制量。

我刚开始做AGV时，第一个接触的就是PID。当时觉得这东西太简单了，不就是三个系数嘛。结果调了一周，车还是在原地画圈。后来才明白，PID虽然简单，但调参是一门玄学。

1.1 位置式PID vs 增量式PID

在AGV运动控制中，我们通常用增量式PID。为什么？因为位置式PID输出的是绝对控制量，一旦积分项饱和，车就会失控。增量式只输出变化量，相对安全。

// 增量式PID实现
float pid_incremental(float target, float current, PID_t *pid) {
    float error = target - current;
    float output = pid->Kp * (error - pid->last_error) 
                 + pid->Ki * error 
                 + pid->Kd * (error - 2*pid->last_error + pid->last_last_error);
    
    pid->last_last_error = pid->last_error;
    pid->last_error = error;
    
    return output;
}
我的经验：调PID时，先把I和D设为0，只调P。让车能走直线但有点震荡时，加一点D来抑制超调。最后再加I消除静差。千万别一上来三个参数一起调，你会疯的。

1.2 PID在AGV中的局限性

PID适合直线跟踪和定点停车。但如果你让AGV走一个弯道，PID就有点力不从心了。为什么？因为PID本质上是在“纠偏”，它不知道前方有弯道，只能等偏了再拉回来。这就导致了弯道处的“切弯”现象。

注意：PID的积分项在AGV启动和停止时容易引起超调。我曾经遇到过AGV在目标点前反复震荡，就是因为积分项累计了太多误差。解决方案是加积分限幅，或者在误差小于某个阈值时冻结积分。

二、纯追踪模型：让AGV学会“看前方”

纯追踪模型，英文叫Pure Pursuit。这个名字很形象——就是让AGV像猎豹一样，始终盯着前方一个“目标点”去追。

它的核心思想很简单：在路径上选一个前视距离处的点，然后计算一个圆弧，让AGV沿着这个圆弧运动到目标点。说白了，就是“看多远，走多弯”。

2.1 前视距离的选取

这是纯追踪模型最关键的地方。前视距离太短，车会左右震荡；前视距离太长，车会“切弯”，走大半径弧线。

前视距离 效果 适用场景
太短（<0.5m） 震荡剧烈，路径跟踪不稳定 低速、高精度纠偏
适中（1-2m） 跟踪平滑，弯道不切弯 一般AGV导航
太长（>3m） 弯道严重切弯，路径偏移大 高速、大曲率路径

我个人习惯的做法是：让前视距离与车速成正比。车速快时看远一点，车速慢时看近一点。这样能兼顾稳定性和跟踪精度。

// 纯追踪模型计算转向角
float pure_pursuit(float lookahead_distance, float lateral_error) {
    float alpha = atan2(lateral_error, lookahead_distance);
    float curvature = 2.0 * sin(alpha) / lookahead_distance;
    float steering_angle = atan(curvature * wheelbase);
    return steering_angle;
}
核心要点：纯追踪模型不直接控制速度，它只输出转向角。速度控制通常由另一个PID或速度规划器负责。两者解耦，调试起来更清晰。

三、Stanley控制器：基于横向误差的“精准打击”

Stanley控制器是斯坦福大学在DARPA挑战赛中提出的方法。它比纯追踪模型更“激进”，因为它同时考虑了横向误差和航向误差。

说白了，纯追踪模型只看“点”，而Stanley控制器既看“点”也看“方向”。

3.1 控制律公式

Stanley控制器的核心公式很简洁：

steering_angle = heading_error + atan2(k * lateral_error, velocity)

其中：

  • heading_error：当前航向与路径切线方向的夹角
  • lateral_error：车辆中心到路径的垂直距离
  • k：增益系数，控制横向误差的收敛速度
  • velocity：当前车速

你想想看，这个公式妙在哪里？当车速很低时，atan2项会很大，横向误差被快速纠正。当车速很高时，atan2项变小，避免过度转向导致侧滑。这就是所谓的“速度自适应”。

3.2 与纯追踪模型的对比

特性 纯追踪模型 Stanley控制器
输入 前视距离、横向误差 横向误差、航向误差、车速
弯道表现 平滑，但会切弯 精准，但可能震荡
速度适应性 需手动调整前视距离 自动适应车速
调试难度 低（一个参数） 中（两个参数）
避坑指南：我曾经在一个项目中用Stanley控制器，发现AGV在直线路径上左右摆动。排查了半天，发现是航向误差的计算方式有问题——我用了全局航向角，但路径切线方向计算有延迟。后来改用局部坐标系下的相对航向角，问题就解决了。记住，误差一定要在车辆坐标系下计算。

四、三种控制器的选择策略

说了这么多，到底该用哪个？我的建议是：

  • 直线路径为主 + 定点停车：用PID就够了，简单可靠。
  • 有弯道 + 速度不高：用纯追踪模型，调试方便，效果稳定。
  • 高速 + 弯道多 + 精度要求高：用Stanley控制器，但要做好参数整定。

当然，实际项目中我经常把它们组合使用。比如直线段用PID，弯道切换到纯追踪模型。切换时要注意平滑过渡，否则车会“抖”一下。

好了，运动控制这一章就讲到这里。三种方法各有千秋，没有绝对的好坏。关键是你得理解它们的原理，然后根据实际场景去选、去调、去优化。我在项目里踩过的坑，上面都提到了，希望能帮你少走弯路。

记住，控制算法是“死”的，但AGV是“活”的。多观察车的实际表现，多思考背后的物理意义，你也能成为运动控制的高手。
