3 里程计模型：两轮差速模型、阿克曼模型、航迹推演算法

各位同学，今天我们来聊聊里程计。这玩意儿在AGV里有多重要呢？我打个比方——它就像是AGV的「内耳前庭系统」。没有它，你的车就是个瞎子，只能靠外部传感器（比如激光雷达）来感知世界。

但里程计有个致命弱点：它会漂。你想想看，轮子打滑、地面不平、轮胎磨损，这些都会让里程计慢慢偏离真实位置。所以，理解里程计模型，是做好传感器融合的第一步。

3.1 两轮差速模型

两轮差速，说白了就是靠两个独立驱动的轮子来转弯。左边轮子转得快，右边转得慢，车就往右拐。这是最基础的AGV底盘结构，也是我入行时第一个接触的模型。

它的核心公式其实很简单：

// 两轮差速模型的核心计算
// 输入：左右轮编码器读数 (encoder_left, encoder_right)
// 输出：机器人位姿 (x, y, theta)

// 1. 计算左右轮移动距离
double d_left = (encoder_left - last_encoder_left) * wheel_circumference / encoder_resolution;
double d_right = (encoder_right - last_encoder_right) * wheel_circumference / encoder_resolution;

// 2. 计算中心点移动距离和转角
double d_center = (d_left + d_right) / 2.0;
double d_theta = (d_right - d_left) / wheel_base;  // wheel_base: 轮距

// 3. 更新位姿（航迹推演）
x += d_center * cos(theta + d_theta / 2.0);
y += d_center * sin(theta + d_theta / 2.0);
theta += d_theta;

嗯，这里要注意一个细节：为什么更新位姿时要用 theta + d_theta / 2.0？而不是直接用 theta？

我个人习惯用中点法。因为机器人在移动过程中，角度是连续变化的。如果你直接用起始角度，误差会累积。我在项目中遇到过，用起始角度算出来的轨迹是锯齿状的，而用中点法就平滑多了。

关键参数：

  • 轮距（wheel_base）：左右轮中心之间的距离。这个值必须精确测量，差1毫米都不行。
  • 车轮周长（wheel_circumference）：受胎压影响，实际值会变化。我建议每次换轮胎后重新标定。
  • 编码器分辨率（encoder_resolution）：每转一圈的脉冲数。越高越好，但要注意脉冲丢失。

避坑指南：

我曾经在项目里犯过一个低级错误——把轮距写成了轮子直径。结果AGV转圈时，角度计算完全不对，定位误差直接爆炸。后来花了整整两天排查，才发现是参数搞混了。所以，参数命名一定要规范，最好加注释。

3.2 阿克曼模型

阿克曼模型，就是汽车转向模型。前轮转向，后轮驱动。这种结构在工业AGV里也很常见，尤其是那些需要高速行驶的场景。

阿克曼模型的核心思想是：所有车轮的转向中心必须交于一点。这样才能保证车轮在转弯时不会侧滑。

它的计算公式稍微复杂一点：

// 阿克曼模型的核心计算
// 输入：前轮转向角 (steering_angle), 后轮速度 (v_rear)
// 输出：机器人位姿 (x, y, theta)

// 1. 计算转弯半径
double turning_radius = wheel_base / tan(steering_angle);  // wheel_base: 轴距

// 2. 计算角速度
double omega = v_rear / turning_radius;

// 3. 更新位姿（航迹推演）
double dt = time_step;
x += v_rear * cos(theta) * dt;
y += v_rear * sin(theta) * dt;
theta += omega * dt;

你可能会问：为什么阿克曼模型比差速模型复杂？

其实，阿克曼模型在低速时反而更简单。因为它的运动学约束更强——车只能沿着圆弧运动。而差速模型可以原地旋转，自由度更高，但控制起来也更灵活。

个人经验：

我在做仓储AGV时，发现阿克曼模型有个好处：它的航迹推演误差比差速模型小。为什么呢？因为阿克曼模型的车轮转向角是直接测量的，而差速模型的角度是靠左右轮差积分出来的。积分嘛，误差会累积。所以，如果你对角度精度要求高，阿克曼模型是更好的选择。

3.3 航迹推演算法

航迹推演（Dead Reckoning），说白了就是「猜」你现在在哪。根据上一时刻的位置，加上这一时刻的运动量，推算出当前位置。

这个算法看起来简单，但坑很多。我总结一下常见的几种实现方式：

方法 精度 计算量 适用场景
欧拉法 低 低 低速、短距离
中点法 中 中 一般AGV场景
龙格-库塔法 高 高 高速、高精度需求

我个人最常用的是中点法。为什么？因为它在精度和计算量之间取得了很好的平衡。欧拉法虽然快，但误差大；龙格-库塔法精度高，但计算量大，在嵌入式平台上跑起来有点吃力。

来看看中点法的完整实现：

// 航迹推演 - 中点法
void dead_reckoning(double v, double omega, double dt) {
    // 预测中点处的位姿
    double mid_theta = theta + omega * dt / 2.0;
    
    // 用中点处的角度更新位置
    x += v * cos(mid_theta) * dt;
    y += v * sin(mid_theta) * dt;
    
    // 更新角度
    theta += omega * dt;
    
    // 归一化角度到 [-PI, PI]
    theta = normalize_angle(theta);
}

重要提醒：

航迹推演有个致命问题——误差会随时间累积。你想想看，每次推演都有微小误差，这些误差会像滚雪球一样越滚越大。所以，航迹推演只能用于短时间内的定位，必须配合其他传感器（比如激光雷达、IMU）进行修正。

我记得有一次，客户要求AGV在100米长的走廊里自主导航。我们只用里程计做定位，结果走到50米时，位置误差已经超过1米了。后来加了激光雷达的修正，才把误差控制在10厘米以内。

避坑指南：

我曾经在项目里遇到过一个诡异的问题——AGV在光滑地面上行驶时，里程计显示走了10米，实际只走了8米。排查了半天，发现是轮子打滑导致的。从那以后，我每次做航迹推演都会加一个「打滑检测」逻辑：如果左右轮速度差突然变大，或者加速度异常，就降低里程计的置信度。

好了，关于里程计模型，我就讲这么多。记住一句话：里程计是基础，但别太依赖它。它就像你的直觉，有时候准，有时候不准。真正可靠的定位，还是要靠多传感器融合。
