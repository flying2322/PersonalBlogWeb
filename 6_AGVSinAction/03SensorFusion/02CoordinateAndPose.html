2 坐标系与位姿表示：世界坐标系、机器人坐标系、欧拉角与四元数

各位同学，咱们今天聊点硬核的。坐标系和位姿表示，说白了就是回答三个问题：我在哪？我往哪看？我怎么描述这个状态？

我刚开始做AGV那会儿，觉得坐标系不就是个原点加三个轴嘛，有啥好讲的？结果第一次联调，车在车间里乱窜，定位数据跳得跟心电图似的。查了一整天，最后发现是坐标系定义搞反了。嗯，从那以后，我再也不敢小看这个基础环节了。

2.1 世界坐标系与机器人坐标系

先说说两个最常用的坐标系。

世界坐标系，也叫全局坐标系。你可以把它想象成一张大地图，原点固定，方向固定。比如工厂车间里，我们通常把原点设在某个墙角，X轴指向东，Y轴指向北。这个坐标系是绝对参考，所有地图、路径、目标点都基于它定义。

机器人坐标系，也叫本体坐标系。原点在机器人中心，X轴朝前，Y轴朝左（或者朝右，看你的习惯）。这个坐标系是相对参考，跟着机器人一起动。传感器数据、控制指令通常都在这个坐标系下表达。

为什么要区分这两个？你想想看，激光雷达扫到的障碍物，距离是相对于机器人自身的。但你要规划路径，得知道障碍物在世界地图上的位置。这就涉及到坐标变换。

核心公式：

世界坐标 = 旋转矩阵 × 机器人坐标 + 平移向量

反过来，机器人坐标 = 旋转矩阵的逆 × (世界坐标 - 平移向量)

我个人习惯把变换矩阵写成齐次形式，4×4矩阵，一次搞定旋转和平移。代码里用Eigen库的Isometry3d，或者ROS里的tf2，都很方便。

2.2 欧拉角：直观但危险

欧拉角，就是用三个角度来描述姿态：绕X轴转的叫横滚角（Roll），绕Y轴转的叫俯仰角（Pitch），绕Z轴转的叫偏航角（Yaw）。

为什么说它直观？因为三个数字，一看就懂。比如偏航角30度，就是车头朝东北方向。做上位机界面显示姿态时，我一般用欧拉角，操作员看着舒服。

但欧拉角有个大坑——万向锁。当俯仰角接近±90度时，横滚和偏航会耦合，丢失一个自由度。我在项目里遇到过，AGV爬坡时俯仰角到了85度，姿态解算突然炸了，车直接原地打转。

避坑指南：

我曾经在融合IMU和里程计时，直接用欧拉角做插值。结果姿态跳变，定位全乱。后来才明白，欧拉角不适合做插值和滤波。如果你要做姿态估计，老老实实用四元数或者旋转矩阵。

欧拉角的另一个问题是表示不唯一。同样的姿态，可以有多种欧拉角组合。比如偏航角360度和0度，其实一样。做差值和滤波时，这个问题很头疼。

2.3 四元数：优雅但抽象

四元数，说白了就是四个数：一个实部加三个虚部。写成 q = w + xi + yj + zk，其中 w² + x² + y² + z² = 1。

我第一次接触四元数时，觉得这东西太抽象了。四个数，怎么就能表示三维旋转？后来做多了才理解，四元数其实是在四维空间里描述旋转，投影到三维空间就是我们要的姿态。

四元数的好处很明显：

  • 无万向锁，随便转，不会丢自由度
  • 插值平滑，用球面线性插值（SLERP），姿态过渡很自然
  • 计算高效，比旋转矩阵少几个乘法

我建议你在做传感器融合时，内部运算全部用四元数。只在最后输出给显示界面时，才转成欧拉角。这样既保证了精度，又方便人看。

实用技巧：

四元数乘法不满足交换律，顺序很重要。我习惯用 q_result = q2 * q1 表示先做q1旋转，再做q2旋转。ROS里的tf2也是这个约定。

2.4 坐标系变换与位姿链

实际AGV系统里，坐标系远不止两个。我列一下常见的：

坐标系 原点位置 用途
世界坐标系 固定点 地图、路径、目标点
机器人坐标系 机器人中心 控制指令、局部规划
激光雷达坐标系 雷达安装位置 激光点云数据
IMU坐标系 IMU芯片位置 加速度、角速度
相机坐标系 相机光心 视觉图像

这些坐标系之间通过变换矩阵连接，形成一条位姿链。比如激光点云要转到世界坐标系，需要经过：激光→机器人→世界，两步变换。

我见过不少新手，直接硬编码变换参数。结果换了个传感器，或者重新标定后，代码改得一团糟。我的建议是：用树状结构管理坐标系，每个坐标系只存父节点和变换关系。ROS的tf树就是这种思路。

2.5 实战：位姿表示的选择策略

讲了这么多，到底什么时候用啥？我总结一下个人经验：

  • 存储和传输：用四元数+平移向量。比如保存路径点、发送定位结果。四个数加三个数，紧凑无歧义。
  • 显示和调试：用欧拉角。Rviz里显示姿态，或者打印日志，三个角度一目了然。
  • 滤波和融合：用四元数。卡尔曼滤波、粒子滤波，内部状态都用四元数。注意归一化，防止数值漂移。
  • 控制指令：用旋转矩阵。计算速度、加速度时，矩阵形式方便做微分和积分。

代码示例：四元数转欧拉角（C++）

#include <Eigen/Dense>
#include <cmath>

Eigen::Vector3d quatToEuler(const Eigen::Quaterniond& q) {
    // 四元数转欧拉角（ZYX顺序）
    double roll = atan2(2.0*(q.w()*q.x() + q.y()*q.z()),
                        1.0 - 2.0*(q.x()*q.x() + q.y()*q.y()));
    double pitch = asin(2.0*(q.w()*q.y() - q.z()*q.x()));
    double yaw = atan2(2.0*(q.w()*q.z() + q.x()*q.y()),
                       1.0 - 2.0*(q.y()*q.y() + q.z()*q.z()));
    return {roll, pitch, yaw};
}

注意，这个转换在pitch接近±90度时会有数值问题。实际项目中，我会加个阈值判断，如果pitch绝对值大于85度，就用其他方法处理。

最后说一句，坐标系和位姿表示是传感器融合的地基。地基没打好，上层算法再牛也白搭。我见过太多项目，定位精度上不去，最后查出来是坐标系标定有偏差。所以，这块内容值得你花时间吃透。

我的建议：

动手写个小程序，实现四元数、欧拉角、旋转矩阵之间的互相转换。然后拿真实数据跑一遍，看看转换前后是否一致。这个练习做完，你对位姿表示的理解会上一个台阶。
