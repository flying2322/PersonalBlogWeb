25 仿真环境搭建：Gazebo仿真、传感器模型配置、场景设计

做AGV导航系统，最怕什么？

怕真车撞了。怕传感器标定没做好。怕算法在实车上跑起来才发现逻辑漏洞。

所以我个人的习惯是——先在仿真里把坑踩一遍。今天我们就聊聊Gazebo仿真环境的搭建，包括传感器怎么配、场景怎么设计。这些东西看着基础，但我在项目里见过太多人因为仿真没做好，后面调试花了三倍时间。

25.1 为什么选Gazebo？

市面上仿真工具有不少，比如Webots、CoppeliaSim、CARLA。但做AGV导航，我首选Gazebo。原因很简单：

  • ROS集成度高——几乎所有的ROS导航栈都能直接对接Gazebo
  • 传感器模型丰富——激光雷达、IMU、里程计、摄像头，开箱即用
  • 物理引擎成熟——支持碰撞检测、摩擦力、惯性参数
  • 社区活跃——遇到问题基本都能搜到答案

嗯，这里要注意一点：Gazebo和ROS的版本要匹配。我见过有人用ROS Noetic配Gazebo 11，结果死活打不开，最后发现是版本不兼容。建议直接用官方推荐的组合。

推荐版本组合：

  • ROS Noetic + Gazebo 11（稳定）
  • ROS2 Humble + Gazebo Fortress（新项目推荐）

25.2 传感器模型配置

AGV导航最核心的传感器就三个：激光雷达、IMU、里程计。我们一个一个说。

25.2.1 激光雷达配置

激光雷达是AGV的「眼睛」。我建议用2D激光雷达做室内导航，比如Sick TIM系列或者Hokuyo URG系列。Gazebo里配置起来很简单：

<!-- 激光雷达模型配置示例 -->
<sensor name="laser" type="ray">
  <pose>0 0 0.3 0 0 0</pose>
  <ray>
    <scan>
      <horizontal>
        <samples>360</samples>
        <resolution>1</resolution>
        <min_angle>-3.14159</min_angle>
        <max_angle>3.14159</max_angle>
      </horizontal>
    </scan>
    <range>
      <min>0.1</min>
      <max>30.0</max>
      <resolution>0.01</resolution>
    </range>
  </ray>
  <plugin name="gazebo_ros_laser" filename="libgazebo_ros_laser.so">
    <topicName>/scan</topicName>
    <frameName>laser_frame</frameName>
  </plugin>
</sensor>

这里有几个参数我特别想提醒你：

  • samples——360线就是每圈360个点，够用了。我曾经试过720线，结果CPU负载直接飙到80%
  • min_angle/max_angle——全向扫描就是-π到π。如果AGV只需要前方探测，可以缩小范围
  • max——30米对于室内AGV足够了。室外的话建议设到50米

小技巧：激光雷达的安装高度很关键。我一般装在0.3米左右，太低容易被地面杂物遮挡，太高又扫不到低矮障碍物。你可以根据AGV的实际尺寸调整。

25.2.2 IMU配置

IMU提供角速度和加速度数据。AGV导航里，IMU主要用于航位推算和姿态估计。Gazebo里配置IMU也很直接：

<sensor name="imu" type="imu">
  <pose>0 0 0 0 0 0</pose>
  <imu>
    <noise>
      <type>gaussian</type>
      <mean>0.0</mean>
      <stddev>0.001</stddev>
    </noise>
  </imu>
  <plugin name="gazebo_ros_imu" filename="libgazebo_ros_imu.so">
    <topicName>/imu/data</topicName>
    <frameName>imu_frame</frameName>
  </plugin>
</sensor>

为什么要在IMU上加噪声？因为真实的IMU数据就是有噪声的。如果你在仿真里用完美数据，到了实车上你会发现算法完全失灵。我刚开始做项目时就吃过这个亏——仿真里定位精度5厘米，实车上直接漂到半米。

注意：IMU的噪声参数要根据实际传感器来设。比如MPU6050的噪声水平就和ADIS16470差很多。建议先查一下你用的IMU的datasheet，再设置stddev。

25.2.3 里程计配置

里程计通常来自轮式编码器。Gazebo里可以通过差速驱动插件来模拟：

<plugin name="diff_drive" filename="libgazebo_ros_diff_drive.so">
  <leftJoint>left_wheel_joint</leftJoint>
  <rightJoint>right_wheel_joint</rightJoint>
  <wheelSeparation>0.4</wheelSeparation>
  <wheelDiameter>0.2</wheelDiameter>
  <topicName>/odom</topicName>
  <frameName>odom_frame</frameName>
</plugin>

这里wheelSeparation和wheelDiameter必须和你的AGV模型一致。我见过有人随便填了个值，结果里程计算出来的位移和实际差了30%。

25.3 场景设计

场景设计决定了你的算法在什么环境下测试。我个人建议分三个阶段来设计场景：

  1. 基础场景——空旷的仓库，只有几个柱子
  2. 中等场景——有货架、通道、障碍物
  3. 复杂场景——动态障碍物、狭窄通道、多楼层

下面是一个简单的仓库场景示例：

<!-- 仓库场景模型 -->
<model name="warehouse">
  <static>true</static>
  <link name="wall">
    <collision name="collision">
      <geometry>
        <box>
          <size>20 0.2 3</size>
        </box>
      </geometry>
    </collision>
    <visual name="visual">
      <geometry>
        <box>
          <size>20 0.2 3</size>
        </box>
      </geometry>
    </visual>
  </link>
</model>

你想想看，如果只在空旷场景里测试，你的避障算法根本不会触发。等到实车上遇到一个纸箱，直接就撞上去了。所以我建议在场景里多放一些不同形状的障碍物——箱子、圆柱、斜坡，甚至模拟一些动态行人。

25.5 避坑指南

最后分享几个我在项目中踩过的坑：

  • 坐标系混乱——Gazebo里默认是ENU（东-北-天），但ROS里常用FLU（前-左-上）。不统一的话，传感器数据全是错的。我建议在URDF里明确指定每个传感器的frame_id。
  • 时间戳问题——仿真时间戳和真实时间戳不一样。如果你用ros::Time::now()，在仿真里会出问题。要用ros::Time(0)来获取仿真时间。
  • 模型碰撞边界——有时候AGV模型明明看着没撞到东西，但Gazebo报碰撞。检查一下碰撞模型的边界框，可能比视觉模型大了一圈。

我的经验：仿真环境搭建好了之后，先跑一个简单的开环控制——让AGV直走1米，看里程计反馈是不是1米。这一步能发现80%的配置问题。
