18 视觉SLAM：ORB-SLAM3框架、关键帧、回环检测、图优化

说到视觉SLAM，ORB-SLAM3绝对是个绕不开的名字。我个人习惯把它称为「视觉SLAM界的瑞士军刀」——功能全、性能稳、代码质量高。今天咱们就把它拆开揉碎了聊一聊。

ORB-SLAM3的整体框架

ORB-SLAM3是第一个能够同时支持单目、双目、RGB-D以及IMU融合的视觉SLAM系统。说白了，它把视觉和惯性传感器揉在了一起，让定位更鲁棒。

它的核心架构分三块：

  • 跟踪线程（Tracking）：实时处理每一帧图像，估计当前位姿
  • 局部建图线程（Local Mapping）：管理局部地图点，优化局部位姿
  • 回环检测线程（Loop Closing）：检测是否回到之前去过的地方，做全局修正

嗯，这里要注意——ORB-SLAM3相比前代最大的变化是加入了Atlas（地图集）的概念。它允许系统同时维护多个子地图，当跟踪丢失时可以自动切换到另一个地图。我在项目中遇到过AGV在仓库里被货架遮挡导致视觉跟踪丢失的情况，Atlas机制帮了大忙，系统能快速重定位到之前建好的地图上。

核心知识点：ORB-SLAM3的三大线程是并行运行的，但关键帧的插入和回环检测之间有严格的互斥锁保护。这一点在工程实现上非常讲究，搞不好就会死锁。

关键帧：SLAM系统的骨架

关键帧是什么？说白了就是「挑出那些信息量大的帧，扔掉冗余的帧」。你想想看，如果每一帧都参与优化，计算量会爆炸。ORB-SLAM3有一套很聪明的筛选策略。

我个人习惯把关键帧的插入条件总结为「三看」：

  1. 看时间：距离上一个关键帧超过一定帧数（默认20帧）
  2. 看视差：当前帧与最近关键帧的视差足够大（超过12度）
  3. 看质量：跟踪到的地图点数量在合理范围内（既不能太少也不能太多）

避坑指南：我曾经在AGV项目中把关键帧插入阈值设得太低，结果建图时关键帧堆积如山，局部BA每次都要优化几百帧，实时性直接崩了。后来我加了一个「关键帧冗余剔除」机制——如果新关键帧与旧关键帧的共视点超过90%，就直接丢弃。效果立竿见影。

关键帧之间通过共视图（Covisibility Graph）连接。这个图记录了哪些关键帧能看到相同的地图点。共视图是后续局部BA和回环检测的基础数据结构。

回环检测：让地图不再漂移

回环检测是视觉SLAM的「后悔药」。当AGV绕了一圈回到原点，系统需要识别出「哦，这个地方我来过」，然后把累积的漂移修正掉。

ORB-SLAM3用的是词袋模型（DBoW2）。具体做法是：

  • 每一帧提取ORB特征，量化成视觉词汇
  • 构建一个词汇树，把相似的描述子聚类到一起
  • 当前帧与历史关键帧做词袋匹配，找到候选回环

嗯，这里有个细节——ORB-SLAM3做了几何验证。光靠词袋匹配是不够的，因为不同场景可能共享相似的词汇。它会在候选帧和当前帧之间做特征匹配，然后用RANSAC求解单应矩阵或基础矩阵，只有几何一致性通过才算真正的回环。

注意：回环检测最怕「感知歧义」——比如仓库里两排货架长得一模一样。我曾经在自动化立体仓库里遇到过这个问题，AGV在A巷道和B巷道之间误检测了回环，导致地图被错误地「拉变形」。解决方案是加入IMU约束，只有视觉+IMU都一致时才接受回环。

图优化：把一切拧在一起

图优化是SLAM后端最核心的数学工具。你想想看，我们有那么多关键帧、那么多地图点、还有IMU预积分约束，怎么把它们统一优化？

ORB-SLAM3使用g2o（General Graph Optimization）库来做图优化。图优化的本质是：

  • 节点：关键帧的位姿（SE3）、地图点的3D坐标
  • 边：观测约束（重投影误差）、IMU预积分约束
  • 目标：最小化所有边的误差之和

我给大家看一个简化的图优化代码结构：

// 创建优化器
g2o::SparseOptimizer optimizer;

// 添加顶点（关键帧位姿）
g2o::VertexSE3Expmap* vSE3 = new g2o::VertexSE3Expmap();
vSE3->setEstimate( Sophus::SE3d() );
optimizer.addVertex( vSE3 );

// 添加边（重投影误差）
g2o::EdgeSE3ProjectXYZ* e = new g2o::EdgeSE3ProjectXYZ();
e->setVertex(0, dynamic_cast<g2o::OptimizableGraph::Vertex*>( optimizer.vertex(id) ));
e->setMeasurement( Eigen::Vector2d(obs.u, obs.v) );
e->setInformation( Eigen::Matrix2d::Identity() );
optimizer.addEdge( e );

// 执行优化
optimizer.initializeOptimization();
optimizer.optimize(10);  // 迭代10次

ORB-SLAM3的图优化分三个层次：

优化层次 优化范围 频率 实时性要求
局部BA 当前关键帧+共视关键帧+局部地图点 每插入一个关键帧 高（毫秒级）
回环BA 回环两侧的关键帧和地图点 检测到回环时 中（秒级）
全局BA 所有关键帧和地图点 回环修正后 低（分钟级，后台运行）

我个人建议在AGV项目中，局部BA一定要保证实时性。如果优化时间超过50ms，跟踪线程就会卡顿。我曾经把局部BA的迭代次数从20次降到10次，优化精度只下降了2%，但实时性提升了40%。

工程经验：ORB-SLAM3的图优化中，IMU预积分约束的协方差矩阵设置非常关键。如果设得太小，优化会过度信任IMU，导致视觉约束被忽略；如果设得太大，IMU又起不到作用。我一般会在标定IMU噪声参数后，先跑一段数据做「协方差调参」，找到视觉和IMU的平衡点。

最后说一句——ORB-SLAM3的代码质量很高，但学习曲线也比较陡。我建议你从单目版本开始读，先理解关键帧管理和回环检测的逻辑，再去看IMU融合的部分。别一上来就啃全部代码，容易劝退。
