23 磁导航与二维码导航传感器接口：I2C/SPI/UART的典型应用

做AGV控制器选型这么多年，我经常被问到：“磁导航和二维码导航，到底用哪种接口好？”

说实话，这个问题没有标准答案。但有一点我可以肯定——接口选错了，后面调试能让你怀疑人生。

今天我就把I2C、SPI、UART这三种接口在磁导航和二维码传感器上的应用，掰开了讲清楚。都是实战中踩过的坑和总结的经验。

23.1 三种接口的“性格”差异

先说说我对这三种接口的理解。你想想看，它们就像三种不同性格的人：

接口 性格特点 典型速率 线数 适合场景
UART 老实人，一根线发一根线收 115200bps ~ 1Mbps 2线（TX/RX） 低速、远距离、简单传感器
I2C 管家型，一根时钟一根数据 100kHz ~ 400kHz 2线（SCL/SDA） 多设备、短距离、板级通信
SPI 急性子，四根线全双工 10MHz ~ 50MHz 4线（SCK/MOSI/MISO/CS） 高速、大数据量、实时性要求高

嗯，这里要注意：速率不是唯一指标。我见过有人用SPI接磁导航传感器，结果发现传感器根本不需要那么快，反而把简单问题搞复杂了。

23.2 磁导航传感器的接口选择

磁导航传感器，说白了就是检测地面磁条的磁场强度。数据量很小，一般就几个字节——磁条偏移量、磁场强度、ID号。

23.2.1 为什么UART是主流？

我个人习惯，磁导航传感器首选UART。原因很简单：

  • 数据量小：一次通信就几个字节，UART完全够用
  • 距离远：磁导航传感器经常装在车底，离控制器好几米，UART用RS485电平可以轻松搞定
  • 调试方便：串口助手一接，数据一目了然

我在项目中遇到过一个问题：某款磁导航传感器用I2C接口，结果线长了1.5米就开始丢数据。后来换成UART+RS485，稳如老狗。

典型接线方式（UART）：

磁导航传感器          AGV控制器
    TXD  ————————→  RXD
    RXD  ←————————  TXD
    GND  ————————  GND
    VCC  ————————  5V/3.3V

23.2.2 什么时候用I2C？

如果磁导航传感器和控制器在同一块PCB上，或者距离很短（<30cm），I2C也是个好选择。好处是：

  • 只用两根线，可以挂多个传感器
  • 每个传感器有独立地址，方便区分

但要注意：I2C的驱动能力有限。我曾经试过挂4个磁导航传感器在一条I2C总线上，结果总线电容太大，波形都变形了。后来加了I2C总线缓冲器才解决。

避坑指南：我曾经因为I2C上拉电阻选错，导致传感器数据偶尔出错。查了两天才发现——上拉电阻太小，信号反射严重。记住：100kHz用4.7kΩ，400kHz用2.2kΩ，这是经验值。

23.3 二维码导航传感器的接口选择

二维码导航就不一样了。它要处理图像数据，信息量大得多。一个二维码里可能包含位置坐标、角度、甚至路径信息。

23.3.1 SPI是王道

我个人强烈建议：二维码导航传感器优先用SPI。为什么？

  • 速度快：二维码解码后可能有几十到几百字节数据，UART的115200bps要传好久
  • 全双工：可以一边发指令一边收数据，不浪费时间
  • 实时性好：AGV高速运行时，每毫秒都很关键

你想想看，AGV以1m/s的速度跑，每10ms就要读一次二维码数据。如果用UART传256字节，115200bps下要传22ms——黄花菜都凉了。

典型SPI时序（二维码传感器）：

// 主机发送读指令
CS拉低
SPI_Send(0xAA)      // 读命令
SPI_Send(0x00)      // 寄存器地址
SPI_Send(0x00)      // 填充字节（等待传感器准备）
SPI_Receive(&data)  // 读取数据
CS拉高

// 实际项目中，我一般用DMA+中断方式
// 避免CPU被SPI通信阻塞

23.3.2 UART也能用，但有条件

如果控制器没有多余的SPI接口，或者二维码传感器本身只支持UART，那也不是不能用。但要注意：

  • 波特率要够高：至少921600bps，最好1Mbps以上
  • 数据包要精简：只传必要信息，别把原始图像数据也传了
  • 流控要加上：硬件流控（RTS/CTS）能避免数据溢出

我记得有个项目，客户非要省成本用UART接二维码传感器。结果AGV一加速，数据就丢包。后来加了硬件流控，又优化了数据包格式，才算勉强能用。但说实话，还是SPI省心。

23.5 实战中的“潜规则”

最后分享几个我踩过的坑，希望能帮你少走弯路：

技巧1：电平匹配

很多磁导航传感器是5V供电，但现在的MCU很多是3.3V。直接连会烧IO口。我习惯用电平转换芯片（比如TXS0108E），或者用MOS管搭个简单电平转换电路。

技巧2：隔离很重要

AGV的电机驱动会产生很大的电磁干扰。传感器接口最好加隔离——磁耦隔离（比如ISO7240）或者光耦隔离。我曾经因为没加隔离，SPI通信在电机启动时直接乱码。

避坑指南：我曾经在二维码传感器上用过软件模拟SPI，结果发现CPU被占用了30%的时间在“打转”发时钟。后来换成硬件SPI+DMA，CPU占用率直接降到2%。记住：能用硬件就别用软件。

嗯，关于接口选型就说这么多。每种接口都有自己的脾气，关键是要根据实际场景来选。磁导航用UART省心，二维码用SPI高效，I2C适合板级多设备——这个思路基本不会错。
