11 人机交互接口：触摸屏选型、按键矩阵、状态指示灯与蜂鸣器驱动

人机交互接口，说白了就是AGV跟人“说话”和“听话”的通道。操作员要告诉AGV去哪、干什么，AGV得告诉操作员“我准备好了”、“我出故障了”。这一章，我重点聊聊触摸屏、按键、指示灯和蜂鸣器这几个最常用的交互手段。

11.1 触摸屏选型：别只看尺寸

触摸屏是AGV最直观的交互窗口。我个人习惯，选型时先看三个硬指标：分辨率、亮度、触摸方式。

  • 分辨率：7寸屏至少1024×600，10寸以上建议1920×1080。分辨率太低，图标和文字会糊成一团，操作员看着难受。
  • 亮度：AGV经常在仓库、车间跑，环境光变化大。我建议亮度不低于500cd/m²，最好能自动调节。我在项目中遇到过，一台AGV在阳光直射的装卸区，屏幕亮度不够，操作员得用手遮着看，体验极差。
  • 触摸方式：电容屏是主流，支持多点触控。但如果你在粉尘大、戴手套的环境，电阻屏反而更靠谱。嗯，这个要结合实际工况来定。

我的经验：选触摸屏时，别忘了看接口。LVDS、RGB、MIPI是常见的屏接口，主控芯片得能直接驱动。我建议优先选带RGB接口的屏，兼容性好，调试也方便。

11.2 按键矩阵：低成本、高可靠

触摸屏虽好，但有些场景下，物理按键更可靠。比如紧急停止、模式切换，这些操作不能依赖屏幕。按键矩阵，就是用较少的IO口检测多个按键。

典型的4×4矩阵，16个按键只需要8个IO口。原理很简单：行线输出扫描信号，列线检测输入。我常用的驱动方式是这样的：

// 按键矩阵扫描示例
#define ROW_PINS  {GPIO_PIN_0, GPIO_PIN_1, GPIO_PIN_2, GPIO_PIN_3}
#define COL_PINS  {GPIO_PIN_4, GPIO_PIN_5, GPIO_PIN_6, GPIO_PIN_7}

uint8_t key_scan(void) {
    uint8_t key_value = 0xFF;  // 无按键按下
    for (uint8_t row = 0; row < 4; row++) {
        // 拉低当前行
        HAL_GPIO_WritePin(ROW_PORT, ROW_PINS[row], GPIO_PIN_RESET);
        delay_us(10);  // 等待电平稳定
        
        // 读取列状态
        for (uint8_t col = 0; col < 4; col++) {
            if (HAL_GPIO_ReadPin(COL_PORT, COL_PINS[col]) == GPIO_PIN_RESET) {
                key_value = row * 4 + col;  // 计算按键编号
                break;
            }
        }
        
        // 恢复行电平
        HAL_GPIO_WritePin(ROW_PORT, ROW_PINS[row], GPIO_PIN_SET);
        
        if (key_value != 0xFF) break;
    }
    return key_value;
}

避坑指南：我曾经在按键矩阵上吃过亏——没做消抖处理。AGV振动大，按键会误触发。后来我加了20ms的软件消抖，问题才解决。另外，矩阵扫描时，行线切换后要加一点延时，等电平稳定再读列线，不然会读到错误值。

11.3 状态指示灯：颜色、闪烁、亮度

指示灯是AGV的“表情”。操作员远远看一眼，就知道AGV在干嘛。我一般用三色LED（红、绿、蓝），通过PWM调出多种颜色。

状态颜色闪烁模式说明
待机绿色常亮AGV空闲，等待指令
运行蓝色慢闪（1Hz）正在执行任务
故障红色快闪（5Hz）需要人工干预
充电黄色呼吸灯正在充电

驱动方式很简单，用定时器产生PWM波，控制RGB三路的占空比。比如红色常亮：R=100%，G=0%，B=0%。呼吸灯效果，就是让PWM占空比按正弦波变化。

关键点：指示灯亮度要适中。太亮刺眼，太暗看不清。我一般把最大亮度控制在200cd/m²左右，夜间模式自动降低到50cd/m²。这个可以通过光敏电阻检测环境光，自动调节PWM占空比实现。

11.4 蜂鸣器驱动：频率、时长、音量

蜂鸣器是AGV的“嗓子”。它用来提示操作员，比如“任务完成”、“故障报警”。蜂鸣器分有源和无源两种。有源蜂鸣器通电就响，频率固定；无源蜂鸣器需要外部提供方波信号，频率可调。

我建议用无源蜂鸣器，因为可以控制音调。比如故障报警用2kHz的尖锐声，任务完成用1kHz的柔和声。驱动代码很简单：

// 蜂鸣器驱动示例
void buzzer_on(uint16_t freq, uint16_t duration_ms) {
    // 设置定时器输出PWM，频率为freq
    TIM->ARR = SystemCoreClock / freq - 1;
    TIM->CCR1 = TIM->ARR / 2;  // 50%占空比
    
    // 开启PWM输出
    HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1);
    
    // 延时duration_ms
    HAL_Delay(duration_ms);
    
    // 关闭PWM输出
    HAL_TIM_PWM_Stop(&htim1, TIM_CHANNEL_1);
}

我的习惯：蜂鸣器不要一直响，会让人烦躁。我一般设计成“短促提示音”，比如故障时响3声，每声200ms，间隔100ms。这样既引起注意，又不至于太吵。另外，音量也要可调，通过改变PWM占空比就能控制。

11.5 知识体系总览

下面这张图，把本章的核心逻辑串起来了。从输入（触摸屏、按键）到输出（指示灯、蜂鸣器），再到主控芯片的驱动逻辑，一目了然。

你看，整个交互系统其实就三个环节：输入、处理、输出。输入设备把操作员的意图传给主控，主控根据逻辑驱动输出设备，反馈给操作员。说白了，就是“你按一下，它亮一下”这么简单。但要做好，细节就多了去了。

总结一下：触摸屏选型看分辨率、亮度、接口；按键矩阵注意消抖和扫描时序；指示灯用PWM调色，亮度要自适应；蜂鸣器用无源型，频率和时长可控。这些细节，都是我在项目里一点点踩坑踩出来的。你照着做，至少能少走一半弯路。
