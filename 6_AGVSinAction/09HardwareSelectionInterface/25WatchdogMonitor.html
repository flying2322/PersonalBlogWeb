25 硬件看门狗与系统监控：独立看门狗芯片、电压监控与复位电路

AGV 在工厂里跑着跑着突然死机了，你想想看，那是什么场景？

轻则堵住通道，重则撞坏货架。我见过太多因为系统“假死”导致的现场事故了。所以这一章，咱们聊聊怎么用硬件手段，把系统的“命”给看住。

25.1 为什么需要硬件看门狗？

软件看门狗，说白了就是定时器中断里喂狗。但有个致命问题：如果 CPU 跑飞了，中断都进不去，软件看门狗也就废了。

硬件看门狗不一样。它是一颗独立的芯片，不依赖 CPU 内核。你必须在规定时间内给它一个“心跳”信号，否则它就强制拉低复位引脚。

核心原则：硬件看门狗是最后一道防线。软件看门狗防逻辑错误，硬件看门狗防 CPU 彻底死机。

我在项目中遇到过一台 AGV，软件看门狗设了 3 秒超时，但 CPU 在某个极端工况下进入了死循环，中断被屏蔽了。结果呢？车直接撞上了货架腿。从那以后，我所有项目都强制加上独立看门狗芯片。

25.2 独立看门狗芯片选型

市面上常见的看门狗芯片，我列几个常用的：

型号 超时时间 特点 典型应用
MAX706 1.6s 带手动复位、低电平有效 STM32、i.MX 系列
TPS3823 1.6s / 可调 带电压监控、推挽输出 电池供电设备
ADM706 1.6s 与 MAX706 兼容，更便宜 成本敏感项目
SP706 1.6s 低功耗、宽电压范围 便携式 AGV 控制器

我个人习惯用 MAX706 系列。为什么？因为它的 WDI 引脚对脉冲宽度要求不苛刻，只要在 1.6 秒内给一个高低电平跳变就行。有些芯片要求严格的 50% 占空比，反而容易误触发。

选型小技巧：看门狗超时时间建议设为系统最大任务周期的 2~3 倍。比如你的控制循环是 100ms，那看门狗设 300ms 左右比较合理。太短容易误复位，太长又起不到保护作用。

25.3 电压监控与复位电路

AGV 用的是电池供电，电压波动是家常便饭。电机启动瞬间，电池电压可能从 48V 跌到 42V。如果 3.3V 或 5V 电源也跟着掉，CPU 就会进入“亚稳态”——逻辑混乱，程序跑飞。

电压监控芯片就是干这个的。它实时监测电源电压，一旦低于阈值，立刻拉低复位引脚，让 CPU 安全停机。

常用的电压监控芯片：

  • MAX809/MAX810：最简单的电压监控，只有复位输出，没有看门狗功能。适合对成本敏感的项目。
  • TPS3808：可编程阈值，精度高，适合对电压要求严格的场合。
  • ADM809：与 MAX809 兼容，但价格更低。

我曾经在一个项目中，只用了软件检测电压，结果电池电压掉到 3.0V 时，CPU 还在“正常”运行，但 Flash 写入已经出错了。等发现时，参数已经全乱了。从那以后，我所有板子都加上了硬件电压监控。

25.4 复位电路设计要点

复位电路看着简单，但坑不少。我总结几个关键点：

  1. 复位时间要够长：一般要求复位脉冲宽度至少 200ms，确保所有外设都能完成复位。有些芯片要求更长的复位时间，比如某些 CAN 收发器需要 500ms。
  2. 手动复位按钮：调试阶段一定要留一个手动复位按钮。我习惯用带复位功能的按键，按下时直接拉低 MR 引脚。
  3. 上电复位时序：CPU 内核供电先于 I/O 供电，否则 I/O 引脚可能输出不确定状态，导致电机误动作。
  4. 去耦电容：复位引脚旁边放一个 0.1μF 的电容，防止噪声干扰导致误复位。

警告：千万不要把复位引脚直接连到 CPU 的复位脚就完事了。一定要加一个上拉电阻（通常 10kΩ），否则复位信号可能被外部噪声拉低，导致系统频繁复位。

25.5 喂狗策略与代码实现

喂狗不是随便在循环里加个脉冲就行的。我见过有人把喂狗放在中断里，结果主循环卡死了，中断还在跑，看门狗永远不超时——这等于没装看门狗。

正确的喂狗策略：

  • 喂狗放在主循环的最后，确保所有关键任务都执行完毕。
  • 不要在中断里喂狗，除非你明确知道自己在做什么。
  • 喂狗前检查关键状态，比如电机是否正常、通信是否超时。

下面是一个典型的喂狗代码示例：

// 主循环
while(1)
{
    // 1. 读取传感器数据
    read_sensors();
    
    // 2. 执行控制算法
    control_algorithm();
    
    // 3. 发送电机指令
    send_motor_command();
    
    // 4. 检查系统状态
    if(system_ok())
    {
        // 喂狗：给 WDI 引脚一个脉冲
        HAL_GPIO_WritePin(WDI_GPIO_Port, WDI_Pin, GPIO_PIN_SET);
        delay_us(10);
        HAL_GPIO_WritePin(WDI_GPIO_Port, WDI_Pin, GPIO_PIN_RESET);
    }
    else
    {
        // 系统异常，不喂狗，让看门狗复位
        // 或者主动触发复位
        NVIC_SystemReset();
    }
}

经验之谈：喂狗脉冲的宽度不要太宽，一般 10~50μs 就够了。太宽的脉冲可能被误判为持续高电平，导致看门狗不工作。

25.7 避坑指南

最后，我把自己踩过的坑分享给你：

  • 不要共用复位电路：多个芯片共用一个复位信号时，要确保驱动能力足够。我曾经用一颗芯片的复位输出直接驱动三个外设，结果复位信号被拉低到 1.5V，所有芯片都处于半复位状态。
  • 注意上电顺序：有些 CPU 要求内核电压先于 I/O 电压建立。如果顺序反了，I/O 引脚可能输出不确定电平，导致电机误动作。
  • 看门狗超时时间不要设得太短：我见过有人设 100ms，结果系统启动时初始化时间太长，还没开始喂狗就复位了。建议至少 500ms 起步。
  • 调试时关闭看门狗：调试阶段建议用跳线或软件开关关闭看门狗，否则单步调试时频繁复位，根本没法调。

总结一句话：硬件看门狗和电压监控是 AGV 控制器的“生命线”。别省这几块钱的芯片，现场出一次事故，够你买一万颗看门狗芯片了。
