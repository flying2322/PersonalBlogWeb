12 存储与日志设计：eMMC、SD卡、NAND Flash的选型与文件系统选择（FAT32/EXT4）

做AGV控制器这么多年，存储这块我踩过的坑真不少。你想想看，一台AGV在仓库里跑一天，要记录多少数据？路径规划日志、传感器原始数据、异常事件、地图文件……要是存储选型没搞好，轻则丢数据，重则系统崩溃。

今天咱们就聊聊存储介质和文件系统的选型。说白了，就是三件事：用什么存、怎么存、存了怎么读。

12.2 eMMC：AGV系统盘的首选

我个人习惯，AGV主控板上的系统盘首选eMMC。为什么？因为它把主控和NAND封装在一起，内部自带FTL（Flash Translation Layer）。你想想看，这相当于买了个“即插即用”的存储方案，不用操心坏块管理、磨损均衡这些底层破事。

我在项目中遇到过一件事：某次用了一款便宜的eMMC，结果AGV在高温环境下连续运行8小时后，系统突然卡死。查了半天，发现是eMMC内部温度保护触发了降频。从那以后，我选eMMC必看两个参数：

  • 工作温度范围：工业级必须-40℃~85℃
  • TBW（Total Bytes Written）：至少满足3年寿命
我的经验：AGV控制器建议选eMMC 5.1及以上版本，容量16GB起步。太小了，系统+日志+地图数据很快就撑爆了。

12.3 SD卡：日志导出的好帮手

SD卡嘛，说白了就是方便。AGV跑了一天，把SD卡拔下来插电脑上，日志直接拷走分析。但要注意——SD卡在AGV上不能当系统盘用！

为什么？我踩过这个坑。曾经有个项目，为了省成本，直接把系统装在SD卡上。结果AGV在仓库里颠簸了几下，SD卡接触不良，系统直接挂了。从那以后，我定了个规矩：SD卡只做数据导出和日志备份，系统盘必须用eMMC。

选SD卡时，我建议注意这几点：

  • 速度等级：至少Class10，最好U3（写速度30MB/s以上）
  • 接口：用SPI模式还是SDIO模式？SDIO速度快，但占用引脚多
  • 热插拔：一定要加检测引脚，防止带电插拔损坏

12.4 NAND Flash：高可靠性场景的硬核选择

如果你对数据可靠性要求极高，比如AGV的“黑匣子”数据，那NAND Flash裸片是更好的选择。但代价是——你得自己写驱动、管理坏块、做ECC校验。

我记得有个军工项目，要求存储芯片必须能承受10000次擦写。eMMC和SD卡都达不到，最后选了SLC NAND Flash。SLC的寿命是MLC的10倍，TLC的100倍。当然，容量也小，价格也贵。

警告：NAND Flash的坏块管理不是闹着玩的。我曾经有个同事，没做坏块跳过，结果写到坏块上，整条产线的AGV都读不到校准数据。嗯，那周他加了三天班。

12.5 文件系统选择：FAT32 vs EXT4

文件系统的选择，其实取决于你的使用场景。我直接给结论：

对比项 FAT32 EXT4
最大文件大小 4GB 16TB
日志功能 无 有（journal）
掉电保护 弱 强
Windows兼容 原生支持 需第三方工具
Linux兼容 支持 原生支持
适用场景 SD卡数据导出 系统盘、核心数据

你可能会问：为什么FAT32还有市场？很简单，Windows直接认啊。AGV的日志导出到电脑上，运维人员插上SD卡就能看，不用装任何软件。但FAT32有个致命伤——单文件不能超过4GB。AGV跑一天的日志，加上高清地图数据，很容易就超了。

EXT4就好多了。它有日志功能，掉电不会丢数据。我习惯在eMMC上挂EXT4，配合wear leveling，寿命能延长不少。

12.7 日志设计的几个关键点

日志设计看着简单，其实坑不少。我总结了几条经验：

  1. 日志分级：DEBUG、INFO、WARN、ERROR。别什么都往日志里写，不然一天能写几个GB。
  2. 循环覆盖：SD卡空间有限，我习惯保留最近7天的日志，旧的自动删除。
  3. 掉电保护：日志写到一半掉电怎么办？用EXT4的journal功能，或者自己加校验。
  4. 压缩存储：日志文件用gzip压缩，能省70%空间。读取时再解压。
小技巧：我习惯在日志文件名里加时间戳，比如"log_20250115_143000.txt"。这样查找特定时间的日志，直接按文件名排序就行，不用打开文件看内容。

12.8 代码示例：日志写入与文件系统挂载

最后给个实际代码片段，Linux环境下挂载SD卡并写日志：

// 挂载SD卡（FAT32）
mount -t vfat /dev/mmcblk0p1 /mnt/sd卡

// 挂载eMMC（EXT4）
mount -t ext4 /dev/mmcblk1p2 /mnt/系统

// C代码：日志写入示例
FILE *fp = fopen("/mnt/sd卡/log_20250115.txt", "a");
if (fp == NULL) {
    // 写入失败，尝试写入eMMC备份
    fp = fopen("/mnt/系统/backup_log.txt", "a");
}
fprintf(fp, "[INFO] AGV位置: x=12.5, y=34.2, 速度=1.2m/s\n");
fclose(fp);

嗯，这里要注意：fopen之后一定要检查返回值。我曾经见过一个案例，SD卡没插好，fopen返回NULL，程序没检查就直接fprintf，结果段错误，AGV直接死机。

好了，存储和日志设计这块就聊到这儿。记住一句话：存储选型没有银弹，eMMC、SD卡、NAND Flash各有各的用武之地。关键是根据你的AGV应用场景，找到最合适的组合。
