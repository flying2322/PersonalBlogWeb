19 AGV任务管理与状态机：任务生命周期与调度核心

各位同学，今天我们来聊聊AGV系统里最“灵魂”的部分——任务管理与状态机。说白了，就是AGV怎么知道自己该干什么，以及怎么干。

我刚开始做AGV那会儿，觉得这玩意儿不就是“接到指令，跑过去，放下”嘛。结果第一次联调，三台车在仓库里“打架”，任务乱抢，充电桩排队排到死机。嗯，从那以后，我再也不敢小看任务管理了。

任务生命周期：从生到死的完整旅程

一个AGV任务，就像一个人从出生到死亡。我习惯把它拆成五个阶段：创建、分配、执行、完成、取消。每个阶段都有明确的职责。

核心观点：任务生命周期管理，本质上是“谁负责、何时做、怎么做”的闭环控制。

1. 创建（Created）

任务被系统生成，但还没指派给任何AGV。比如WMS下发了一个“从A点取货送到B点”的指令。这时候任务处于“待分配”状态。

  • 触发方式：手动下发、定时任务、事件触发（如传感器检测到缺料）
  • 关键字段：任务ID、起点、终点、优先级、创建时间、超时时间

2. 分配（Assigned）

系统根据某种策略，把任务绑定到一台具体的AGV上。我见过最蠢的做法是“随机分配”，结果车跑一半没电了。

  • 分配策略：最近距离优先、空闲优先、电量优先、负载均衡
  • 避坑：我曾经遇到过分配后AGV突然离线，任务卡死。后来加了“分配确认超时”机制，10秒内没确认就重新分配。

3. 执行（Executing）

AGV开始导航、取货、放货。这个阶段状态机最复杂，后面细讲。

4. 完成（Completed）

任务成功结束。系统记录日志、释放AGV资源、通知上游系统。

5. 取消（Cancelled）

人为取消或系统异常导致任务终止。注意：取消不等于删除，要保留日志用于复盘。

// 任务状态枚举示例（C#风格）
public enum TaskState
{
    Created,    // 已创建
    Assigned,   // 已分配
    Executing,  // 执行中
    Completed,  // 已完成
    Cancelled   // 已取消
}

AGV状态机设计：车在干什么？

AGV本身也有自己的状态。我把它归纳为四个核心状态：空闲、导航、充电、异常。你想想看，一台车不可能同时“在跑”和“在充电”，对吧？

状态 含义 触发条件 典型动作
空闲（Idle） 无任务，等待指令 任务完成、系统启动 待机、低功耗
导航（Navigating） 正在执行移动任务 任务分配、路径规划完成 循线、避障、定位
充电（Charging） 正在充电桩充电 电量低于阈值、任务空闲 对接充电、电量监控
异常（Error） 发生故障或异常 传感器故障、碰撞、离线 急停、报警、等待人工

个人经验：我建议把“充电”状态单独拎出来，不要和“空闲”混在一起。因为充电时AGV不能接任务，但空闲时可以。很多新手把充电当空闲，结果任务分配过去，车还在充电桩上发呆。

任务优先级调度：谁先谁后？

仓库里任务有轻重缓急。比如“紧急补料”肯定比“常规巡检”优先级高。我常用的优先级分三级：

  • 高优先级：紧急任务、故障恢复任务
  • 中优先级：常规运输任务
  • 低优先级：巡检、数据采集、空闲充电

调度算法上，我推荐优先级队列 + 时间戳排序。同优先级下，先来的先执行。别搞什么“动态优先级”，容易死锁。

注意：优先级不能滥用。我曾经见过一个项目，所有任务都标“高优先级”，结果调度器直接瘫痪。优先级是稀缺资源，要严格控制。

任务队列管理：排队也是一门艺术

任务队列，说白了就是“待办事项列表”。但AGV的队列比人的复杂，因为要考虑多车协同、路径冲突、充电需求。

我常用的队列结构是全局队列 + 局部队列：

  • 全局队列：所有未分配的任务，按优先级和时间排序
  • 局部队列：每台AGV自己的待执行任务列表（最多3-5个）

为什么要分两层？因为全局队列要统一调度，局部队列让AGV有“预知能力”——提前知道下一个任务，减少空闲等待。

// 任务队列管理伪代码
class TaskQueueManager
{
    Queue<Task> globalQueue;      // 全局队列
    Dictionary<string, Queue<Task>> localQueues; // 每台AGV的局部队列

    void AssignTask()
    {
        var task = globalQueue.Dequeue(); // 取最高优先级任务
        var agv = SelectBestAgv(task);    // 选择最优AGV
        localQueues[agv.Id].Enqueue(task); // 加入局部队列
        agv.ExecuteNext();                // 通知AGV执行
    }
}

避坑指南与个人经验

最后，分享几个我踩过的坑：

  • 任务超时处理：我曾经没加超时，结果一个任务卡了三天。现在每个任务都有“最大执行时间”，超时自动取消并报警。
  • 状态机死锁：两台AGV互相等待对方让路，状态卡在“导航”不动。解决方案是加一个“死锁检测”定时器，5秒没变化就触发重新规划。
  • 充电调度：别让所有车同时去充电。我习惯用“电量阈值 + 任务空闲窗口”来判断。电量低于20%强制充电，低于50%且无任务时主动充电。

小技巧：任务队列里加一个“预估完成时间”字段。调度时不仅看优先级，还看“谁最快能完成”。这样能显著提升整体效率。

好了，任务管理和状态机这块，核心就是“任务怎么流转，车怎么响应”。你把这个逻辑理清了，AGV调度系统就稳了一半。剩下的，就是细节和调优了。
