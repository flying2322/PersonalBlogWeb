23 AGV系统集成与联调

系统集成，说白了就是把一堆零件拼成一台能跑的车。

但这里头门道很深。我见过太多团队，硬件选型都挺好，软件框架也漂亮，结果一联调就崩。为什么？因为集成不是简单的「插上线、烧个固件」就完事。

这一章，我把硬件集成、软件集成、联调流程、常见问题排查，一条线给你捋清楚。

23.1 硬件集成：底盘、主控、传感器

硬件集成是地基。地基不稳，上层软件再牛也白搭。

23.1.1 底盘集成

底盘是AGV的腿。常见的底盘类型有：

  • 差速底盘：两个驱动轮+两个万向轮。结构简单，转向灵活。我早期做的小型AGV基本都是这种。
  • 舵轮底盘：一个或两个舵轮+从动轮。负载能力强，适合重载场景。
  • 麦克纳姆轮底盘：四个全向轮。可以横向移动，但地面要求高，效率也低一些。

集成时要注意什么？

  • 电机驱动器通信：我习惯用CAN总线。抗干扰强，实时性好。RS485也行，但注意总线终端电阻要匹配。
  • 编码器信号：差分信号比单端信号靠谱。我踩过坑——单端编码器线长了，信号衰减导致里程计漂移。
  • 急停回路：硬件急停必须独立于主控。主控死机了，急停还能用。这是安全底线。

核心原则：底盘集成时，先确认电机驱动器的控制模式（速度模式/位置模式/力矩模式）。AGV导航一般用速度模式。

23.1.2 主控集成

主控是AGV的大脑。选型上，我推荐：

  • 工业级ARM主板：比如RK3588、树莓派CM4。性价比高，生态好。
  • x86工控机：算力强，适合跑SLAM和路径规划。但功耗和体积大一些。
  • MCU+MPU组合：MCU负责底层实时控制，MPU负责上层算法。这种架构最稳。

集成要点：

  • 电源管理：主控、电机驱动器、传感器要分开供电。我见过一次，电机启动瞬间电压跌落，主控直接重启。
  • 接口预留：至少留2个USB、1个以太网、1个CAN口。别问我为什么——后期调试时你就知道了。
  • 散热：主控装在底盘上，别忘了散热。我有一台AGV，夏天跑半小时就过热降频，导航直接卡顿。

23.1.3 传感器集成

传感器是AGV的眼睛和耳朵。常见的传感器有：

传感器类型 用途 集成注意事项
激光雷达（2D/3D） 建图、定位、避障 安装高度要避开底盘遮挡。2D雷达注意扫描平面水平。
IMU（惯性测量单元） 姿态估计、辅助定位 安装位置靠近底盘中心。远离电机磁场干扰。
编码器 里程计 差分信号传输。线缆用屏蔽双绞线。
超声波/红外 近距离避障 注意探测角度和盲区。多个传感器要避免串扰。

我的经验：传感器集成时，先做「裸数据验证」。比如激光雷达，先单独接电脑看点云是否正常。别等全部装好了再查问题，那会非常痛苦。

23.2 软件集成：底层驱动、ROS2、调度

软件集成是灵魂。硬件装好了，软件跑不起来，那就是一堆废铁。

23.2.1 底层驱动集成

底层驱动负责和硬件打交道。我一般分三层：

  • MCU固件层：跑在STM32或类似芯片上。负责电机控制、编码器读取、IO控制。用FreeRTOS做实时调度。
  • 通信协议层：MCU和主控之间用自定义协议。我习惯用「帧头+长度+命令+数据+校验」的结构。简单可靠。
  • ROS2驱动层：在主控上写一个ROS2节点，解析MCU发来的数据，发布成/cmd_vel、/odom等话题。
// 底层通信协议示例（简化版）
typedef struct {
    uint8_t  header;      // 0xAA
    uint8_t  length;      // 数据长度
    uint8_t  cmd;         // 命令类型
    int16_t  data[4];     // 数据内容
    uint8_t  checksum;    // 校验和
} AGV_Frame_t;

注意：底层驱动和ROS2之间的通信延迟要控制在10ms以内。否则导航控制会感觉「肉肉的」，反应迟钝。

23.2.2 ROS2集成

ROS2是AGV软件的核心框架。集成步骤：

  1. 搭建ROS2工作空间：创建src目录，放你的功能包。
  2. 编写节点：至少要有底盘驱动节点、传感器驱动节点、导航节点。
  3. 配置TF树：base_link -> odom -> map。TF树错了，定位全乱。
  4. 集成导航栈：Nav2或者自己写的路径规划器。我建议先用Nav2，稳定后再定制。

集成时容易踩的坑：

  • 话题命名冲突：多个传感器都用/cmd_vel？那不乱套了。命名空间要规划好。
  • QoS设置不匹配：发布者和订阅者的QoS要一致。我遇到过，激光雷达数据收不到，查了半天发现是QoS不匹配。
  • 时间同步：多个传感器的时间戳要对齐。用ROS2的time_synchronizer或者message_filters。

23.2.3 调度系统集成

调度系统是AGV的大脑。它负责：

  • 任务分配：哪台AGV去执行哪个任务。
  • 路径规划：全局路径规划，避免AGV之间打架。
  • 交通管理：交叉路口、狭窄通道的通行控制。

集成方式：

  • 调度系统和AGV之间用MQTT或HTTP通信。我推荐MQTT，轻量级，支持QoS，适合工业场景。
  • AGV上报状态：位置、电量、任务状态、故障信息。
  • 调度系统下发指令：去A点、去B点、充电、暂停、恢复。

关键点：调度系统和AGV之间的通信要设计心跳机制。AGV每隔1秒发一次心跳，调度系统3秒没收到就判定AGV离线，自动重新分配任务。

23.3 系统联调流程

联调不是一蹴而就的。我一般分四步走：

23.3.1 单机调试

先调一台AGV。确认底盘能动、传感器能采数据、ROS2节点能跑通。这一步别急，稳扎稳打。

23.3.2 导航调试

建图、定位、路径规划、避障。让AGV在已知地图里跑一圈，看轨迹是否平滑，定位是否漂移。

23.3.3 多机联调

两台AGV同时跑。看调度系统能不能正确分配任务，交通管理能不能避免碰撞。我遇到过，两台AGV在路口互让，结果死锁了。

23.3.4 压力测试

满负荷运行。连续跑8小时、24小时。看系统稳定性、电池续航、通信可靠性。

我的习惯：联调时一定要有日志系统。每个关键节点都打日志，出问题才能快速定位。别靠肉眼观察，那太原始了。

23.4 常见问题排查

联调过程中，问题层出不穷。我列几个高频问题：

问题现象 可能原因 排查方法
AGV不走直线 左右轮编码器不一致、电机PID参数不对 先校准编码器，再调PID
定位漂移 IMU未校准、激光雷达安装倾斜、里程计误差累积 重新校准IMU，检查雷达安装水平度，加入回环检测
通信断连 WiFi信号弱、MQTT心跳超时、CAN总线终端电阻缺失 检查网络信号强度，调整心跳间隔，确认CAN总线匹配电阻
避障失效 传感器盲区、探测角度不对、避障算法参数不合理 调整传感器安装位置，增大探测范围，优化避障参数

我曾经踩过的坑：有一次AGV在某个区域总是定位失败。查了三天，最后发现是那个区域的地面反光太强，激光雷达点云全是噪点。后来换了吸光材料的地面贴纸，问题解决。

嗯，系统集成与联调，说白了就是「把对的零件，用对的方式，组合在一起」。每一步都有坑，但每一步也都有解法。多调试、多总结，慢慢就有感觉了。
