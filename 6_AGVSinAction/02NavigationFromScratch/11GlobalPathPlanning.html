11 全局路径规划算法

全局路径规划，说白了就是给AGV找一条从A到B的可行路径。很多新手觉得这事简单——不就是找条路吗？但实际做起来，坑多得很。我最早做AGV时，用的就是Dijkstra，后来发现效率不行，才换的A*。再后来遇到阿克曼底盘的车，A*又不好使了，这才上了Hybrid-A*。

这一章，我把这三种算法掰开揉碎了讲。你跟着走一遍，基本就能应付大部分场景了。

核心要点：全局规划 ≠ 最短路径。要考虑车辆运动约束、地图更新频率、计算资源限制。选对算法，比调参更重要。

11.1 Dijkstra算法原理

Dijkstra是全局路径规划的「老祖宗」。它的思路很简单：从起点开始，一层层往外扩散，直到碰到终点。每次只选当前代价最小的节点扩展。

我当年在学校学这个算法时，觉得它挺完美的。直到第一次在AGV上跑——地图稍微大一点，计算时间就飙上去了。为什么呢？因为它不知道终点在哪，只能盲目地往所有方向扩散。

我的经验：Dijkstra适合静态地图、小规模场景（比如50x50网格以内）。如果地图超过200x200，建议直接上A*。

伪代码其实很简单：

function Dijkstra(start, goal, grid):
    open_set = {start}          // 待扩展节点
    closed_set = {}             // 已扩展节点
    g[start] = 0                // 起点代价为0
    
    while open_set is not empty:
        current = min_cost_node(open_set)  // 取代价最小的
        if current == goal:
            return reconstruct_path(current)
        
        open_set.remove(current)
        closed_set.add(current)
        
        for neighbor in get_neighbors(current):
            if neighbor in closed_set:
                continue
            tentative_g = g[current] + cost(current, neighbor)
            if tentative_g < g[neighbor]:
                g[neighbor] = tentative_g
                parent[neighbor] = current
                if neighbor not in open_set:
                    open_set.add(neighbor)
    
    return None  // 无路径

注意看，它没有用到任何终点信息。这就是它慢的根本原因。

11.2 A*算法原理与实现

A*算法在Dijkstra基础上加了一个启发式函数。说白了，就是告诉搜索器：「嘿，终点在那边，别往反方向瞎跑。」

代价函数变成了：f(n) = g(n) + h(n)

  • g(n)：从起点到当前节点的实际代价
  • h(n)：从当前节点到终点的估计代价（启发式）

启发式函数怎么选？我一般用欧几里得距离或曼哈顿距离。对于网格地图，曼哈顿距离更常用，因为它考虑了只能上下左右走的情况。

避坑指南：我曾经在一个项目中用了欧几里得距离做启发式，结果路径经常穿墙。后来才发现，对于有障碍物的地图，欧几里得距离会低估实际代价，导致搜索方向偏了。换成曼哈顿距离后，问题就解决了。

A*的代码实现：

function AStar(start, goal, grid):
    open_set = PriorityQueue()
    open_set.put(start, 0)
    g[start] = 0
    f[start] = heuristic(start, goal)
    
    while not open_set.empty():
        current = open_set.get()
        if current == goal:
            return reconstruct_path(current)
        
        for neighbor in get_neighbors(current):
            if not is_walkable(neighbor):
                continue
            tentative_g = g[current] + cost(current, neighbor)
            if tentative_g < g.get(neighbor, float('inf')):
                g[neighbor] = tentative_g
                f[neighbor] = g[neighbor] + heuristic(neighbor, goal)
                parent[neighbor] = current
                open_set.put(neighbor, f[neighbor])
    
    return None

你想想看，A*比Dijkstra快在哪？它用启发式函数引导搜索方向，减少了大量无效扩展。在1000x1000的地图上，A*可能只需要扩展几百个节点，而Dijkstra要扩展几万个。

11.3 Hybrid-A*算法（适用于阿克曼底盘）

这里我要重点说一下Hybrid-A*。为什么需要它？因为A*规划出来的路径，阿克曼底盘根本走不了。

阿克曼底盘有最小转弯半径，不能原地掉头。A*规划出的路径全是直角转弯、锐角转弯，实际车辆根本执行不了。Hybrid-A*就是在A*的基础上，加入了车辆的运动学约束。

它的核心思想：

  • 状态空间是连续的（x, y, theta），而不是离散的网格
  • 扩展节点时，用Reeds-Shepp曲线或Dubins曲线生成可行路径段
  • 启发式函数考虑非完整约束

关键区别：A*在网格上跳来跳去，Hybrid-A*在连续空间里「开车」。它生成的路径，车辆可以直接跟着走，不需要后处理平滑。

伪代码大致如下：

function HybridAStar(start, goal, grid):
    open_set = {start}
    g[start] = 0
    f[start] = heuristic(start, goal)
    
    while open_set is not empty:
        current = min_f(open_set)
        if distance(current, goal) < threshold:
            // 尝试用Reeds-Shepp曲线连接
            path = reeds_shepp(current, goal)
            if path is valid:
                return path
        
        // 扩展：生成运动学可行的子节点
        for control in [steer_left, steer_straight, steer_right]:
            next_state = simulate_motion(current, control)
            if not is_collision(next_state):
                tentative_g = g[current] + motion_cost
                if tentative_g < g.get(next_state, inf):
                    g[next_state] = tentative_g
                    f[next_state] = g[next_state] + heuristic(next_state, goal)
                    open_set.add(next_state)
    
    return None

我在做仓储AGV时，一开始用A*规划路径，结果车辆在转弯处频繁卡住。后来换成Hybrid-A*，路径平滑多了，执行成功率从70%提升到了95%以上。

我的建议：如果你的AGV是差速底盘（可以原地旋转），用A*就够了。如果是阿克曼底盘（汽车式转向），一定要上Hybrid-A*。别想着用A*规划完再平滑——那只是治标不治本。

11.4 Nav2中全局规划器配置与调优

Nav2是ROS2的导航框架，它内置了多种全局规划器。常用的有：

规划器名称 适用场景 特点
NavFn规划器 差速底盘、静态地图 基于Dijkstra/A*，稳定可靠
Smac Planner 阿克曼底盘、动态地图 支持Hybrid-A*，支持2D/3D
Theta*规划器 任意角度路径 路径更平滑，计算量大

配置Smac Planner的YAML文件示例：

planner_server:
  ros__parameters:
    planner_plugins: ["GridBased"]
    GridBased:
      plugin: "nav2_smac_planner/SmacPlanner2D"
      tolerance: 0.5
      downsample_costmap: false
      allow_unknown: false
      max_iterations: 1000000
      max_on_approach_iterations: 1000
      cost_travel_multiplier: 2.0
      analytic_expansion_ratio: 3.5
      analytic_expansion_max_length: 3.0
      motion_model_for_search: "DUBIN"  # 或 REEDS_SHEPP

调优的几个关键参数：

  • tolerance：终点容差。设太大路径可能不准，设太小可能找不到路径。我一般设0.3-0.5米。
  • analytic_expansion_ratio：启发式扩展比例。值越大，搜索越快，但可能错过最优解。我习惯设3.0-4.0。
  • motion_model_for_search：运动模型。阿克曼底盘用DUBIN，差速底盘用REEDS_SHEPP。

避坑指南：我曾经把max_iterations设得太小（10万），结果在复杂环境中经常规划失败。后来改成100万，问题就解决了。但注意，迭代次数越大，计算时间越长。要根据你的CPU性能来权衡。

启动Nav2时，记得在launch文件中指定规划器：

# 在nav2_bringup的launch文件中
planner_server:
  ros__parameters:
    planner_plugins: ["GridBased"]
    GridBased:
      plugin: "nav2_smac_planner/SmacPlannerHybrid"

嗯，这里要注意：如果你用的是阿克曼底盘，一定要选SmacPlannerHybrid，而不是SmacPlanner2D。后者不支持运动学约束，规划出的路径车辆走不了。

最后说一句：全局规划只是导航的一部分。路径规划得再好，局部规划跟不上也是白搭。下一章我们会讲局部规划，到时候你就知道全局和局部怎么配合了。

本章总结：

  • Dijkstra：保证最优解，但效率低，适合小地图
  • A*：启发式加速，效率高，适合差速底盘
  • Hybrid-A*：考虑运动学约束，适合阿克曼底盘
  • Nav2配置：选对规划器，调好参数，比什么都重要
