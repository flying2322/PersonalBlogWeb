20 AGV充电对接与自动充电：充电桩识别与精准对接实战

各位同学，今天我们来聊聊AGV自动充电这个环节。说实话，充电对接这个功能，看着简单，做起来坑不少。我最早做AGV的时候，觉得不就是让车去找个插座嘛，结果被现实狠狠教育了一顿。嗯，今天我把这些年踩过的坑和积累的经验，一次性讲清楚。

20.1 充电桩识别：三种主流方案怎么选？

充电桩识别，说白了就是让AGV知道「充电桩在哪」。目前主流方案有三种：二维码、激光反射板、视觉模板匹配。我分别说说它们的优缺点。

20.1.1 二维码识别方案

这个方案最简单，成本也最低。在充电桩上贴一个二维码，AGV用摄像头扫一下，就能得到相对位置。

核心思路：二维码不仅提供ID，还提供精确的6D位姿（x, y, z, roll, pitch, yaw）。

我在项目中遇到过一个问题：二维码被灰尘遮挡或者反光，识别率直线下降。后来我们加了个补光灯，并且定期清洁，才稳定下来。

// 二维码识别伪代码
bool detectChargingDockQR(Mat& frame, Pose2D& dockPose) {
    // 1. 图像预处理
    Mat gray;
    cvtColor(frame, gray, COLOR_BGR2GRAY);
    
    // 2. 检测二维码
    vector<Point2f> corners;
    string qrData;
    bool found = detectQR(gray, corners, qrData);
    
    if (!found) return false;
    
    // 3. 解析位姿（假设二维码尺寸已知）
    dockPose = estimatePoseFromQR(corners, QR_SIZE_MM);
    
    // 4. 验证ID是否匹配
    return (qrData == "CHARGING_DOCK_01");
}

我的建议：二维码方案适合近距离（1米以内）识别。如果AGV需要从远处就开始导航，建议配合其他传感器。

20.1.2 激光反射板方案

这个方案在工业AGV上很常见。在充电桩上安装高反射率的反光板，激光雷达扫描到反射强度异常高的点，就能定位。

为什么会用这个？因为激光雷达不受光照影响，稳定可靠。我曾经在一个阳光直射的仓库里调试，二维码方案直接废了，但激光方案纹丝不动。

// 激光反射板检测
struct ReflectivePoint {
    float angle;
    float distance;
    float intensity;
};

vector<ReflectivePoint> findReflectors(LaserScan& scan) {
    vector<ReflectivePoint> reflectors;
    
    for (int i = 0; i < scan.ranges.size(); i++) {
        // 反射强度阈值判断
        if (scan.intensities[i] > REFLECTOR_THRESHOLD) {
            ReflectivePoint pt;
            pt.angle = scan.angle_min + i * scan.angle_increment;
            pt.distance = scan.ranges[i];
            pt.intensity = scan.intensities[i];
            reflectors.push_back(pt);
        }
    }
    
    return reflectors;
}

注意：反射板不能贴歪，否则角度偏差会导致对接失败。我见过一个案例，反射板贴歪了2度，结果AGV每次对接都偏了5厘米。

20.1.3 视觉模板匹配方案

这个方案最灵活，不需要额外贴标记。直接用摄像头拍摄充电桩的外观，通过特征匹配来识别。

说白了，就是让AGV「认识」充电桩长什么样。我用过ORB特征和深度学习两种方式。深度学习准确率高，但算力要求也高。

方案 精度 距离 成本 稳定性
二维码 ±2cm 0.5-1m 低 受光照影响
激光反射板 ±1cm 0-10m 中 高
视觉模板 ±3cm 0.5-3m 高 受环境纹理影响

20.2 充电对接导航策略：末端精准对接

识别到充电桩之后，下一步就是精准对接。这里有两个阶段：粗导航和精对接。

20.2.1 粗导航阶段

AGV从当前位置导航到充电桩附近（比如1米范围内）。这个阶段用常规的路径规划就行，A*或者DWA都可以。

我个人习惯在靠近充电桩时，切换成「对接模式」。对接模式下，速度要降下来，控制周期要加快。

// 对接模式控制参数
struct DockingConfig {
    double max_linear_speed = 0.2;   // m/s，低速
    double max_angular_speed = 0.3;  // rad/s
    double control_frequency = 50;   // Hz，高频控制
    double approach_distance = 0.8;  // m，开始精对接的距离
};

20.2.2 精对接阶段

精对接是难点。AGV需要把充电插头准确插入充电桩的插座里。我见过很多AGV在这个环节「撞墙」或者「插歪」。

核心思路是：使用视觉或激光的实时反馈，做闭环控制。

// 精对接PID控制
void dockingControl(Pose2D currentPose, Pose2D targetPose) {
    // 计算偏差
    double dx = targetPose.x - currentPose.x;
    double dy = targetPose.y - currentPose.y;
    double dtheta = normalizeAngle(targetPose.theta - currentPose.theta);
    
    // PID控制器
    double vx = Kp_x * dx + Ki_x * integral_x + Kd_x * derivative_x;
    double vy = Kp_y * dy + Ki_y * integral_y + Kd_y * derivative_y;
    double vtheta = Kp_theta * dtheta + Ki_theta * integral_theta + Kd_theta * derivative_theta;
    
    // 限幅
    vx = clamp(vx, -MAX_VX, MAX_VX);
    vy = clamp(vy, -MAX_VY, MAX_VY);
    vtheta = clamp(vtheta, -MAX_VTHETA, MAX_VTHETA);
    
    // 发送速度指令
    sendVelocity(vx, vy, vtheta);
}

避坑指南：我曾经遇到过AGV在最后5厘米时，因为地面不平导致插头对不准。后来我加了一个「柔性对接」机制——在最后阶段使用弹簧缓冲，允许±1cm的偏差。

20.3 充电状态检测

对接上了，不代表充电开始了。我们需要实时检测充电状态。

我一般检测三个信号：

  • 物理接触信号：充电插头是否完全插入（微动开关或霍尔传感器）
  • 电气信号：电压、电流是否正常（充电机反馈）
  • 通信信号：电池BMS是否握手成功（CAN或RS485通信）
// 充电状态机
enum ChargingState {
    IDLE,           // 空闲
    DOCKING,        // 对接中
    CONTACT_CHECK,  // 接触检测
    CHARGING,       // 充电中
    CHARGED,        // 充电完成
    ERROR           // 异常
};

ChargingState checkChargingStatus() {
    // 1. 检测物理接触
    bool contactOK = digitalRead(CONTACT_PIN);
    if (!contactOK) return DOCKING;
    
    // 2. 检测电气参数
    float voltage = readChargerVoltage();
    float current = readChargerCurrent();
    
    if (voltage > CHARGING_VOLTAGE_MIN && current > CHARGING_CURRENT_MIN) {
        return CHARGING;
    }
    
    // 3. 检测BMS通信
    if (checkBMSHandshake()) {
        return CHARGING;
    }
    
    return ERROR;
}

注意：充电过程中要持续监控温度。我见过一个案例，充电插头接触不良导致发热，差点烧了。后来我们强制要求每100ms检测一次温度，超过60度立即停止充电。

20.4 充电任务调度

多台AGV同时需要充电怎么办？这就涉及到任务调度了。

我常用的策略是：

  1. 优先级调度：电量最低的AGV优先充电
  2. 排队机制：每个充电桩维护一个等待队列
  3. 动态分配：如果某个充电桩故障，自动分配到其他桩
// 充电任务调度器
class ChargingScheduler {
private:
    struct ChargingTask {
        int robotID;
        float batteryLevel;
        int dockID;
        int priority;
    };
    
    vector<ChargingTask> taskQueue;
    
public:
    void addTask(int robotID, float batteryLevel) {
        ChargingTask task;
        task.robotID = robotID;
        task.batteryLevel = batteryLevel;
        task.priority = calculatePriority(batteryLevel);
        
        // 按优先级插入
        auto it = taskQueue.begin();
        while (it != taskQueue.end() && it->priority > task.priority) {
            it++;
        }
        taskQueue.insert(it, task);
    }
    
    int assignDock() {
        // 找到空闲的充电桩
        for (int dockID = 0; dockID < NUM_DOCKS; dockID++) {
            if (isDockAvailable(dockID)) {
                return dockID;
            }
        }
        return -1; // 无可用充电桩
    }
};

你想想看，如果10台AGV同时回到充电区，没有调度策略会怎样？那就是一锅粥。我见过最夸张的情况，三台AGV抢一个充电桩，结果互相堵死，整个仓库都瘫痪了。

核心总结：

  • 识别方案选型要看现场环境，没有万能方案
  • 精对接必须用闭环控制，开环必歪
  • 充电状态检测要冗余，三个信号互相验证
  • 调度策略要提前设计，否则多车场景会乱套
