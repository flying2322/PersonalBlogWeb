5 AGV底层驱动开发（STM32）：从CubeMX配置到PID闭环

各位同学，欢迎来到第五章。这一章我们真正开始「动手」了。

AGV的底层驱动，说白了就是让电机听话地转起来，并且转得准、转得稳。我见过不少项目，上层规划算法写得天花乱坠，结果底层电机抖得像筛糠，车都走不直。所以，这一章的内容，是整台AGV的「地基」。

5.1 STM32CubeMX配置：别小看这一步

我个人习惯，拿到一个新项目，第一件事就是打开CubeMX。不是因为它多智能，而是它能帮你把时钟树、引脚冲突这些烦心事提前暴露出来。

对于AGV驱动，我们至少需要配置以下几块：

  • 定时器（TIM）：至少两个。一个用于输出PWM（驱动电机），一个用于编码器模式（读取电机转速）。
  • USART：与上位机（比如树莓派或工控机）通信，收发指令和状态。
  • I2C或SPI：驱动OLED显示屏，调试时看数据用。
  • GPIO：控制电机方向、使能，以及一些限位开关。
我的小技巧： 在CubeMX里，先把所有用到的外设都勾上，然后统一分配引脚。别一个一个配，容易漏。我遇到过有人配了PWM忘了配编码器通道，结果调了一下午。

时钟配置上，我建议把主频拉到最高（比如STM32F103用72MHz）。AGV的实时性要求高，尤其是后面做PID运算时，时钟越快，控制周期越短，效果越好。

5.2 电机驱动：PWM + 编码器

电机驱动分两部分：让电机转（PWM），和知道电机转了多少（编码器）。

5.2.1 PWM输出

PWM的频率我一般设10kHz到20kHz。太低电机会啸叫，太高MOS管开关损耗大。占空比就是电机的「油门」。

// 以TIM2的CH1为例，输出PWM
HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_1);
// 设置占空比，假设ARR=999，那么CCR=500就是50%占空比
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, 500);

嗯，这里要注意：别忘了配置GPIO为复用推挽输出。我刚开始学的时候，忘了这步，PWM死活出不来，查了半天。

5.2.2 编码器读取

编码器我用的是AB相增量式。STM32的定时器有编码器模式，硬件直接帮你解码，省了中断开销。

// 配置TIM3为编码器模式
TIM_Encoder_InitTypeDef sEncoder;
sEncoder.EncoderMode = TIM_ENCODERMODE_TI12; // 同时检测AB相
sEncoder.IC1Polarity = TIM_ICPOLARITY_RISING;
sEncoder.IC2Polarity = TIM_ICPOLARITY_RISING;
HAL_TIM_Encoder_Init(&htim3, &sEncoder);
HAL_TIM_Encoder_Start(&htim3, TIM_CHANNEL_ALL);

读取当前计数值直接用 __HAL_TIM_GET_COUNTER(&htim3)。这个值会随着电机正反转增减。我一般每10ms读一次，然后换算成实际速度（rpm或m/s）。

避坑指南： 我曾经在编码器线没接好的情况下调试，发现计数值乱跳。后来用示波器一看，A相波形全是毛刺。所以，编码器线一定要用屏蔽双绞线，且远离电机动力线。

5.3 PID速度闭环控制：让电机稳如老狗

开环控制下，电机转速会随着负载变化而波动。AGV爬坡时速度掉下来，下坡时速度飙上去，这显然不行。所以我们要用PID闭环。

PID公式我就不抄书了，直接上代码。我习惯用位置式PID，简单直观。

typedef struct {
    float target;    // 目标值
    float actual;    // 实际值
    float err;       // 当前误差
    float err_last;  // 上一次误差
    float Kp, Ki, Kd;
    float integral;  // 积分项
    float output;    // 输出（PWM占空比）
} PID_TypeDef;

float PID_Calc(PID_TypeDef *pid, float target, float actual) {
    pid->target = target;
    pid->actual = actual;
    pid->err = pid->target - pid->actual;

    // 积分限幅，防止积分饱和
    pid->integral += pid->err;
    if(pid->integral > 1000) pid->integral = 1000;
    if(pid->integral < -1000) pid->integral = -1000;

    pid->output = pid->Kp * pid->err
                + pid->Ki * pid->integral
                + pid->Kd * (pid->err - pid->err_last);

    pid->err_last = pid->err;
    return pid->output;
}

调用时，每10ms执行一次：

float pwm_out = PID_Calc(&motor_pid, target_speed, current_speed);
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, (uint16_t)pwm_out);
调参心得： 我一般先调Kp，让系统不振荡；再加一点Ki消除静差；最后加Kd抑制超调。记住，Ki不要太大，否则积分饱和会让你反应迟钝。我曾经在一个AGV项目上，Ki设大了，结果车启动时「思考人生」好几秒才动。

5.4 串口通信协议设计：和上位机「对话」

AGV的底层驱动板（STM32）和上位机（比如ROS主控）之间，需要一套清晰的通信协议。我见过有人直接用printf发字符串，解析起来一团糟。我的建议是：用结构体 + 帧头帧尾 + 校验。

这里给一个我常用的协议格式：

字节 内容 说明
0 0xAA 帧头
1 0x55 帧头2
2 数据长度 从本字节后到校验前的字节数
3 命令字 0x01: 设置速度, 0x02: 查询状态...
4 ~ N 数据区 比如目标速度值（float转4字节）
N+1 校验和 前面所有字节累加取低8位
N+2 0x0D 0x0A 帧尾

接收时，我一般用状态机解析。收到0xAA进入状态1，再收到0x55进入状态2，然后收长度、收数据、校验。这样即使中间有干扰，也能自动恢复。

一个小建议： 上位机下发的目标速度，最好用mm/s为单位，整型传输。浮点数在串口里传输容易出精度问题，而且解析麻烦。我习惯把速度乘以1000转成int32，到STM32端再除以1000恢复。

5.5 OLED显示调试信息：看得见的调试

调试AGV时，总不能每次都接串口线看日志吧？OLED屏就派上用场了。我一般显示以下几项：

  • 当前目标速度 vs 实际速度
  • PID输出值（PWM占空比）
  • 编码器计数值
  • 系统运行状态（正常/异常）

驱动OLED我用I2C接口，库用u8g2或者自己写个简单的。刷新率不用太高，5Hz就够了，人眼看起来流畅，又不占用CPU。

// 伪代码示例
void OLED_Display_Debug(PID_TypeDef *pid) {
    char buf[32];
    OLED_Clear();
    sprintf(buf, "Target: %.1f", pid->target);
    OLED_ShowString(0, 0, buf);
    sprintf(buf, "Actual: %.1f", pid->actual);
    OLED_ShowString(0, 16, buf);
    sprintf(buf, "Output: %.0f", pid->output);
    OLED_ShowString(0, 32, buf);
    OLED_Refresh();
}
注意： OLED的I2C地址一般是0x3C或0x3D，买模块时问清楚。我上次买了一批，结果地址不一样，焊上去才发现，又得改代码。
