13 代价地图（Costmap）深入解析

代价地图这东西，说白了就是机器人的“安全距离感知图”。我刚开始做AGV那会儿，总觉得它就是个简单的黑白栅格图——能走的地方是0，不能走的是255。后来踩了无数坑才明白，代价地图是整个导航系统的“交通规则”，它决定了机器人敢不敢走、怎么走、走多快。

这一章，我带你彻底搞懂代价地图的每一层。

13.1 代价地图的“四层结构”

ROS Navigation Stack里的代价地图，默认是四层叠加的。我个人习惯把它们比作“四层滤镜”：

  • 静态层（Static Layer）：地图本身的障碍物，比如墙、柱子
  • 障碍物层（Obstacle Layer）：传感器实时检测到的动态障碍
  • 膨胀层（Inflation Layer）：给障碍物“加一圈安全距离”
  • 传感器层（Sensor Layer）：其实它是障碍物层的变种，专门处理特定传感器数据

嗯，这里要注意：ROS里默认的costmap_common_params.yaml里，通常只配了static_layer、obstacle_layer、inflation_layer这三层。传感器层其实可以合并到障碍物层里，但如果你有多个不同特性的传感器（比如激光雷达+深度相机），分开配会更灵活。

13.2 静态层：地图的“底图”

静态层是最简单的一层。它读取预先建好的地图（通常是PGM或YAML文件），把地图中的障碍物像素映射成代价地图的栅格值。

我曾经犯过一个低级错误：地图分辨率是0.05米，但代价地图分辨率设成了0.1米。结果机器人贴着墙走，因为地图里的障碍物被“稀释”了。后来我养成了一个习惯——代价地图分辨率必须和建图分辨率一致，或者更精细。

关键参数：

  • map_topic：地图话题名，默认是"/map"
  • subscribe_to_updates：是否订阅地图更新。如果设为true，地图更新时会自动刷新静态层
  • track_unknown_space：是否保留未知区域。我建议设为true，这样机器人不会贸然冲进没探索过的地方

13.3 障碍物层：实时感知的“眼睛”

障碍物层负责把激光雷达、深度相机等传感器的数据实时注入代价地图。它的工作流程是这样的：

  1. 接收传感器数据（LaserScan或PointCloud）
  2. 把传感器数据投影到代价地图坐标系
  3. 标记障碍物栅格（通常设为254，表示致命障碍）
  4. 根据传感器观测角度，标记“自由空间”（传感器射线穿过的栅格设为0）

这里有个坑：如果你用的是深度相机，点云数据量很大。我见过有人直接把原始点云塞进障碍物层，结果CPU飙到100%，机器人直接卡死。我的建议是——先对点云做体素滤波（Voxel Filter），把点云密度降到每平方米几百个点就够了。

避坑指南：

我曾经在仓库项目里，把障碍物层的observation_keep_time设成了10秒。结果机器人转弯时，障碍物层里还残留着3秒前的障碍物信息，导致路径规划认为前方有墙，直接原地打转。后来我把这个值改成了0.5秒，问题解决。

13.4 膨胀层：安全距离的“护城河”

膨胀层是代价地图里最“玄学”的一层。它给每个障碍物栅格周围加一圈“代价梯度”，让路径规划器知道——离障碍物越近，代价越高。

膨胀层的核心参数就两个：

参数名 作用 我的经验值
inflation_radius 膨胀半径，即障碍物影响范围 0.3~0.5米（室内）
cost_scaling_factor 代价衰减系数，值越大衰减越快 10.0（默认）

你想想看，如果inflation_radius设得太大，机器人会“不敢”走窄通道；设得太小，机器人又容易擦墙。我一般这样调：先设0.3米，如果机器人过窄门时犹豫，就降到0.2米；如果机器人总撞墙，就升到0.4米。

13.5 代价地图更新机制

代价地图不是一次性生成的，它是“滚动更新”的。每次更新时，四层地图会按顺序叠加：

  1. 先加载静态层（地图底图）
  2. 再叠加障碍物层（实时传感器数据）
  3. 最后应用膨胀层（给所有障碍物加安全距离）

更新频率取决于传感器数据频率。激光雷达一般是10Hz，所以代价地图也是10Hz更新。但如果你用的是深度相机（30Hz），建议在障碍物层里设置update_frequency为5Hz，别让CPU累死。

小技巧：

我习惯在调试时把publish_frequency设成1Hz，这样在RViz里能看到代价地图的实时变化，又不至于刷屏。等调好了再改回10Hz。

13.6 多层代价地图叠加原理

四层地图叠加时，遵循“取最大值”原则。也就是说，如果某个栅格在静态层里是0（自由），但在障碍物层里是254（致命障碍），那最终代价就是254。

但膨胀层比较特殊——它是在所有障碍物层叠加完之后，再对整个地图做一次膨胀处理。所以膨胀层的代价是“后处理”的结果，不参与其他层的叠加。

13.7 Inflation参数对路径的影响

膨胀参数直接影响路径规划的质量。我拿实际项目举例：

  • inflation_radius = 0.1米：机器人贴着墙走，路径最短，但容易刮蹭
  • inflation_radius = 0.5米：机器人离墙很远，路径绕大圈，但安全
  • cost_scaling_factor = 5.0：代价衰减慢，机器人会“害怕”靠近障碍物
  • cost_scaling_factor = 20.0：代价衰减快，机器人敢走窄通道

我记得在某个医院项目里，走廊只有1.2米宽，机器人宽0.8米。如果inflation_radius设0.3米，机器人就过不去（因为0.8+0.3*2=1.4米>1.2米）。后来我把inflation_radius降到0.15米，机器人才能顺利通过。嗯，这就是参数调优的“艺术”。

13.8 动态障碍物处理

动态障碍物是AGV导航里最头疼的问题。比如行人、叉车、其他机器人。代价地图处理动态障碍物的逻辑是：

  1. 传感器检测到动态障碍物，标记为致命障碍（254）
  2. 膨胀层给这个障碍物加安全距离
  3. 路径规划器重新规划路径，绕开这个区域
  4. 障碍物移走后，障碍物层自动清除（根据observation_keep_time）

但这里有个问题：如果动态障碍物移动速度很快（比如叉车），代价地图的更新频率跟不上，机器人可能来不及避让。我的解决方案是：

  • 提高传感器频率（激光雷达用20Hz）
  • 减小observation_keep_time（0.3秒）
  • 在全局路径规划里加入“动态障碍物预测”模块（这个后面章节会讲）

避坑指南：

我曾经在工厂项目里，机器人旁边有AGV叉车来回穿梭。代价地图里障碍物层频繁刷新，导致路径规划器一直在“重新规划”，机器人走走停停，效率极低。后来我加了static_map参数，把叉车经常走的区域标记为“高代价区域”，让机器人尽量避开，问题才解决。

13.9 实战配置示例

最后，给你一份我常用的代价地图配置，可以直接拿去用：

# costmap_common_params.yaml
global_frame: map
robot_base_frame: base_footprint
update_frequency: 5.0
publish_frequency: 2.0
transform_tolerance: 0.5
resolution: 0.05

plugins:
  - {name: static_layer, type: "costmap_2d::StaticLayer"}
  - {name: obstacle_layer, type: "costmap_2d::ObstacleLayer"}
  - {name: inflation_layer, type: "costmap_2d::InflationLayer"}

static_layer:
  map_topic: /map
  subscribe_to_updates: true
  track_unknown_space: true

obstacle_layer:
  observation_sources: laser_scan_sensor
  laser_scan_sensor: {
    sensor_frame: laser_frame,
    data_type: LaserScan,
    topic: /scan,
    marking: true,
    clearing: true,
    inf_is_valid: true,
    observation_keep_time: 0.5
  }
  track_unknown_space: true

inflation_layer:
  inflation_radius: 0.3
  cost_scaling_factor: 10.0

这份配置我用了很多项目，基本能覆盖90%的室内场景。如果你遇到特殊场景（比如超窄通道、高速移动障碍物），再微调inflation_radius和observation_keep_time就行。

代价地图这东西，说复杂也复杂，说简单也简单。核心就一句话：让机器人知道哪里能走、哪里不能走、哪里最好别走。你只要理解了这四层地图的叠加逻辑，再根据实际场景调好参数，导航系统就稳了。
