7 AGV运动学模型与里程计推算：两轮差速运动学模型、麦克纳姆轮运动学模型、里程计推算原理（航迹推算）、里程计标定方法、ROS2里程计发布

各位同学，欢迎来到第七章。这一章我们聊聊AGV的“腿脚”和“感觉”。说白了，就是机器人怎么动起来，以及它怎么知道自己走了多远、转了多少弯。

运动学模型是控制的基础，里程计则是定位的基石。很多新手觉得这俩是分开的，其实不然。你想想看，如果模型建错了，里程计算出来的位置肯定也是错的。我在项目里见过太多人，花大把时间调PID，结果发现是运动学模型参数写错了——嗯，这种坑我踩过，今天带你们绕过去。

核心要点：运动学模型解决“怎么走”，里程计解决“走到哪了”。两者结合，才能让AGV在未知环境中完成最基本的航迹推算。

7.1 两轮差速运动学模型

两轮差速，这是最经典的底盘结构。两个驱动轮独立控制，再加一个或两个万向轮做支撑。我个人习惯把它叫做“坦克式转向”——左右轮速度不同，车体就转弯。

先看正运动学：已知左右轮速度，求车体速度。

# 两轮差速正运动学
v = (v_right + v_left) / 2          # 线速度
w = (v_right - v_left) / wheel_base # 角速度，wheel_base为轮距

逆运动学正好反过来：已知目标线速度和角速度，求左右轮速度。

# 两轮差速逆运动学
v_right = v + w * wheel_base / 2
v_left  = v - w * wheel_base / 2

这里有个关键参数——轮距。我在项目中遇到过，轮距测量差了1厘米，AGV转一圈回来位置就偏了十几厘米。所以建议你们用卡尺多测几次，取平均值。

避坑指南：我曾经在调试时发现AGV走直线总是偏。查了半天，原来是左右轮直径不一样，差了0.5mm。别看这0.5mm，跑10米就能偏出半米多。所以轮径标定一定要做。

7.2 麦克纳姆轮运动学模型

麦克纳姆轮，俗称“全向轮”。它能实现横向移动、原地旋转，灵活性比差速轮高一个档次。但代价是什么？控制复杂，而且对地面要求高。

麦克纳姆轮有四个轮子，每个轮子上的小辊子与轮轴成45度角。四个轮子的布局有两种：X型和O型。我常用的是O型布局，也就是轮子辊子朝向车体中心。

正运动学公式如下（O型布局）：

# 麦克纳姆轮正运动学（O型布局）
# 输入：四个轮子的转速 w1, w2, w3, w4
# 输出：车体速度 vx, vy, w

vx = (w1 + w2 + w3 + w4) * R / 4
vy = (-w1 + w2 + w3 - w4) * R / 4
w  = (-w1 + w2 - w3 + w4) * R / (4 * (L + W))

其中R是轮子半径，L是车体半长，W是车体半宽。逆运动学我就不列了，你们自己推导一下，其实就是解一个4x3的矩阵方程。

注意：麦克纳姆轮对地面平整度非常敏感。我在工厂里遇到过，地面有个小螺丝，AGV压上去后轮子打滑，里程计瞬间就飘了。所以用麦克纳姆轮，地面一定要干净。

7.3 里程计推算原理（航迹推算）

航迹推算，说白了就是“猜”自己在哪里。你从起点出发，知道每一步走了多远、转了多少角度，就能累加出当前位置。这方法简单，但误差会累积。

两轮差速底盘的航迹推算公式：

# 航迹推算（两轮差速）
# 假设dt时间内，左右轮编码器增量为 delta_left, delta_right

delta_s = (delta_right + delta_left) / 2          # 位移增量
delta_theta = (delta_right - delta_left) / wheel_base  # 角度增量

# 更新位姿
x += delta_s * cos(theta + delta_theta / 2)
y += delta_s * sin(theta + delta_theta / 2)
theta += delta_theta

这里我用了“中点法”，也就是取角度变化的中点来计算位移方向。为什么？因为如果直接用起始角度，转弯时误差会很大。这是我踩坑后学到的经验。

麦克纳姆轮的航迹推算稍微复杂一点，需要先算出车体速度，再积分：

# 麦克纳姆轮航迹推算
# 先通过正运动学算出 vx, vy, w
# 然后积分

x += vx * cos(theta) * dt - vy * sin(theta) * dt
y += vx * sin(theta) * dt + vy * cos(theta) * dt
theta += w * dt

关键点：航迹推算的精度取决于三个因素：编码器分辨率、轮径标定精度、轮距标定精度。其中轮径误差是线性累积，轮距误差是角度累积。角度误差更致命，因为它会导致位置误差随时间平方增长。

7.4 里程计标定方法

标定，就是让理论值和实际值对上。我见过太多人直接拿厂家给的轮径参数用，结果跑出来一塌糊涂。记住：每个轮子都有自己的“脾气”，必须现场标定。

常用的标定方法有两种：

标定类型 方法 精度 复杂度
轮径标定 直线往返测试 中等 低
轮距标定 原地旋转测试 中等 低
联合标定 U形轨迹测试 高 中
自动标定 最小二乘法拟合 高 高

我推荐你们用“直线往返+原地旋转”的组合。具体步骤：

  1. 让AGV走一条10米的直线，记录编码器读数
  2. 计算实际轮径 = 理论轮径 * (实际距离 / 编码器推算距离)
  3. 让AGV原地旋转360度，记录角度误差
  4. 调整轮距参数，直到旋转误差小于1度

小技巧：我曾经用激光雷达辅助标定。让AGV对着墙走，用激光测距仪测量实际位移，比用卷尺准多了。精度能到毫米级。

7.5 ROS2里程计发布

在ROS2里，里程计通过nav_msgs/msg/Odometry消息发布。这个消息包含位姿（位置+姿态）和速度（线速度+角速度）。

下面是一个简单的里程计发布节点示例：

# Python示例：ROS2里程计发布
import rclpy
from rclpy.node import Node
from nav_msgs.msg import Odometry
from geometry_msgs.msg import Pose, Twist

class OdometryPublisher(Node):
    def __init__(self):
        super().__init__('odometry_publisher')
        self.pub = self.create_publisher(Odometry, '/odom', 10)
        self.timer = self.create_timer(0.1, self.publish_odom)
        
        # 初始化位姿
        self.x = 0.0
        self.y = 0.0
        self.theta = 0.0
        
    def publish_odom(self):
        # 这里应该从编码器读取数据并做航迹推算
        # 为了演示，我们直接给一个固定值
        
        msg = Odometry()
        msg.header.stamp = self.get_clock().now().to_msg()
        msg.header.frame_id = 'odom'
        msg.child_frame_id = 'base_link'
        
        # 设置位姿
        msg.pose.pose.position.x = self.x
        msg.pose.pose.position.y = self.y
        msg.pose.pose.orientation.z = sin(self.theta / 2)
        msg.pose.pose.orientation.w = cos(self.theta / 2)
        
        # 设置速度
        msg.twist.twist.linear.x = 0.1
        msg.twist.twist.angular.z = 0.0
        
        self.pub.publish(msg)

这里要注意几个细节：

  • frame_id要设为odom，child_frame_id设为base_link
  • 姿态用四元数表示，不要直接用欧拉角
  • 时间戳一定要用当前时间，否则TF树会报错

常见错误：我见过有人把frame_id和child_frame_id搞反了，结果TF树一直报找不到父坐标系。还有人不更新时间戳，导致里程计数据被当作过时数据丢弃。

最后，我建议你们在发布里程计的同时，也发布TF变换。这样其他节点（比如激光雷达）才能正确地将数据转换到机器人坐标系下。

# 同时发布TF
from tf2_ros import TransformBroadcaster

self.tf_broadcaster = TransformBroadcaster(self)

# 在publish_odom函数中添加
t = TransformStamped()
t.header.stamp = msg.header.stamp
t.header.frame_id = 'odom'
t.child_frame_id = 'base_link'
t.transform.translation.x = self.x
t.transform.translation.y = self.y
t.transform.rotation = msg.pose.pose.orientation
self.tf_broadcaster.sendTransform(t)
