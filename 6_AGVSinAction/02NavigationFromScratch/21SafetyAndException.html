21 AGV安全机制与异常处理：急停逻辑、激光雷达安全区域配置、碰撞检测与避障、异常状态恢复（脱轨/定位丢失）、日志记录与报警

做AGV这么多年，我最大的感触就是：导航算法决定车跑不跑得动，安全机制决定车能不能活着回来。说白了，一个没有完善安全机制的AGV，就是个定时炸弹。今天咱们就把这块硬骨头啃下来。

21.1 急停逻辑：最后一道防线

急停按钮，是AGV上最不起眼但最重要的零件。我见过太多项目，急停逻辑写得稀烂，结果真出事了按下去车还在跑。

急停的硬件设计要点：

  • 双通道冗余：急停按钮必须有两路独立的信号通道，一路进安全PLC，一路进主控制器。两路同时失效的概率极低。
  • 常闭触点：急停按钮用常闭（NC）触点，而不是常开（NO）。为什么？因为线路断了、接触器坏了，常闭触点会直接断开，触发急停。这叫「故障安全」。
  • 硬线切断：急停信号必须直接切断驱动器的使能信号，而不是靠软件去发停止指令。软件可能死机，硬线不会。

急停逻辑的软件处理流程：

  1. 检测到急停信号（电平变化或IO中断）
  2. 立即停止所有运动指令，清除速度目标值
  3. 设置电机抱闸，防止溜车
  4. 记录急停事件到日志（时间、位置、原因）
  5. 等待人工复位，禁止自动恢复
// 急停处理伪代码
void EmergencyStopHandler() {
    if (digitalRead(ESTOP_PIN) == LOW) {  // 常闭触点断开
        motorDriver.disableAll();         // 硬线切断
        motionPlanner.clearAllTargets();  // 清除目标
        brake.engage();                   // 抱闸
        logEvent("ESTOP_TRIGGERED", currentPose);
        while(digitalRead(ESTOP_PIN) == LOW) {
            delay(100);  // 等待人工复位
        }
        // 复位后进入待机状态，不自动恢复运动
        setState(ROBOT_STATE_IDLE);
    }
}

注意：急停复位后，AGV绝对不能自动恢复运动。必须由操作人员确认安全后，手动下发恢复指令。我曾经见过一个项目，急停复位后车自己跑了，差点撞到人。

21.2 激光雷达安全区域配置

激光雷达是AGV的「眼睛」，但更重要的是它的「安全区」功能。说白了，就是给雷达画几个圈，不同圈触发不同反应。

安全区域的分级设计：

区域类型 距离范围 触发动作 响应时间
警告区 3-5米 减速至0.3m/s 100ms
减速区 1.5-3米 减速至0.1m/s 50ms
停止区 0-1.5米 紧急停止 20ms

我个人习惯把安全区域配置成动态的。比如AGV直行时，前方安全区拉长；转弯时，侧方安全区加宽。你想想看，如果转弯时还用直行的安全区，车屁股很容易扫到货架。

// 动态安全区域配置示例
void configureSafetyZones(NavigationState state) {
    SafetyZoneConfig config;
    switch(state) {
        case FORWARD:
            config.frontZone = 3.0;   // 前方3米
            config.sideZone = 0.5;    // 侧方0.5米
            break;
        case TURNING:
            config.frontZone = 1.5;   // 前方1.5米
            config.sideZone = 1.2;    // 侧方1.2米（转弯侧）
            break;
        case DOCKING:
            config.frontZone = 0.8;   // 对接时缩小安全区
            config.sideZone = 0.3;
            break;
    }
    lidar.setSafetyZones(config);
}

避坑指南：我曾经在仓库里调试，发现AGV老是莫名其妙急停。查了半天，原来是地面上的反光条被激光雷达当成了障碍物。后来在安全区域配置里加了「地面过滤」参数，把低于10cm的反射点滤掉，问题解决。

21.3 碰撞检测与避障

激光雷达安全区是「主动防御」，碰撞检测是「被动防御」。两者缺一不可。

碰撞检测的三种方式：

  • 机械碰撞开关：AGV前后安装的保险杠，碰到东西就触发。这是最原始但最可靠的方式。
  • 电流/力矩检测：电机驱动器反馈的电流异常增大，说明可能撞到东西了。我习惯设置一个阈值，超过正常值的150%就触发碰撞保护。
  • IMU加速度检测：突然的加速度变化，比如从匀速到急停，可能是撞上了。这个可以用来做辅助判断。

避障策略的优先级：

  1. 急停（最高优先级）—— 碰撞开关触发或安全区被侵入
  2. 绕行 —— 检测到障碍物，重新规划路径
  3. 等待 —— 障碍物是动态的（比如人），等它离开
  4. 减速通过 —— 障碍物在安全距离外，缓慢通过

避障算法的核心逻辑：

说白了就是三步：检测 → 分类 → 决策。先检测到障碍物，然后判断它是静态的还是动态的，最后决定是绕行还是等待。动态障碍物我一般用「速度障碍法」（Velocity Obstacle）来处理，效果不错。

21.4 异常状态恢复：脱轨与定位丢失

这是AGV系统里最头疼的问题。车跑着跑着，突然告诉你「我迷路了」或者「我脱轨了」。怎么办？

脱轨检测与恢复：

  • 检测方式：通过里程计推算的位置与磁条/二维码/激光反射板的位置偏差超过阈值（比如10cm），判定为脱轨。
  • 恢复策略：
    • 先停车，记录当前位置
    • 尝试「回轨」：根据偏差方向，缓慢调整方向，直到重新检测到轨道信号
    • 如果3次回轨失败，上报人工干预

定位丢失的恢复策略：

定位丢失比脱轨更严重。因为脱轨至少知道大概位置，定位丢失是彻底不知道自己在哪。

// 定位丢失恢复流程
void handleLocalizationLoss() {
    // 1. 立即停车
    stopMotion();
    
    // 2. 尝试重定位
    bool relocalized = false;
    for (int i = 0; i < 3; i++) {
        relocalized = attemptRelocalization();
        if (relocalized) break;
        delay(500);  // 等待半秒再试
    }
    
    // 3. 如果重定位失败，进入「迷失模式」
    if (!relocalized) {
        // 缓慢向前移动，同时扫描环境特征
        // 直到找到匹配的地图特征点
        enterLostMode();
    }
    
    // 4. 如果还是不行，上报人工
    if (!relocalized) {
        reportError("LOCALIZATION_LOST");
        waitForHumanIntervention();
    }
}

注意：定位丢失后，AGV绝对不能高速移动。我见过一个案例，定位丢失后AGV以全速往前冲，结果撞上了货架。后来我们规定：定位丢失后最大速度限制在0.2m/s。

21.5 日志记录与报警

日志是AGV的「黑匣子」。出了问题，第一件事就是翻日志。没有日志，你连问题在哪都不知道。

日志分级：

级别 含义 记录内容 存储方式
DEBUG 调试信息 传感器原始数据、算法中间结果 循环覆盖，保留最近7天
INFO 正常运行 任务开始/结束、路径规划、状态切换 按天归档，保留30天
WARN 警告 安全区触发、轻微偏差、通信超时 单独存储，保留90天
ERROR 错误 急停、碰撞、定位丢失、硬件故障 永久保留，上传服务器

报警机制的设计：

  • 声光报警：AGV上的蜂鸣器和三色灯。绿色正常，黄色警告，红色错误。
  • 远程报警：通过MQTT或HTTP上报到调度系统。我习惯用MQTT，实时性好。
  • 报警分级：
    • 一级报警（紧急）：急停、碰撞、定位丢失 → 立即通知运维人员
    • 二级报警（重要）：安全区触发、脱轨、通信中断 → 记录并通知
    • 三级报警（一般）：电池低电量、传感器脏污 → 记录即可

我的经验：日志格式一定要统一。我见过最坑的日志，有的用逗号分隔，有的用空格，有的用中文冒号。后来我强制要求所有日志用JSON格式，时间戳精确到毫秒。这样不管是人工查还是机器分析，都方便。

21.6 安全机制的整体架构

下面这张图，是我做AGV安全系统时画的架构图。说白了，安全机制分三层：硬件层 → 控制层 → 决策层。每一层都有独立的故障检测和响应机制。

这张图我画了很多遍。核心思想就是：每一层独立工作，上层依赖下层，但下层不依赖上层。什么意思？就算主控制器死机了，安全PLC照样能触发急停；就算安全PLC坏了，硬线急停照样能切断驱动器。这才叫真正的安全。

总结一下安全机制的核心原则：

  • 故障安全：任何故障都要让系统进入安全状态，而不是维持原状
  • 冗余设计：关键信号要有备份，单点故障不能导致系统失控
  • 可追溯：所有异常都要记录，方便事后分析
  • 人工确认：紧急情况恢复后，必须由人确认安全

嗯，安全机制这块就聊到这儿。说白了，安全不是功能，是底线。你算法写得再好，安全没做好，一切都是白搭。希望这些经验能帮你少走弯路。
