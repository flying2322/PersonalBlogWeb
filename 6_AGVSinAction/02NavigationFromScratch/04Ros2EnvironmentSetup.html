4 ROS2基础与环境搭建

各位同学，欢迎来到第四章。从这一章开始，我们正式进入ROS2的世界。说实话，ROS2的生态比ROS1成熟太多了，尤其是Humble版本，稳定得让人感动。我在2019年刚接触ROS2时，还踩了不少坑，现在回想起来，都是宝贵的经验。

4.1 ROS2 Humble安装

ROS2 Humble是Ubuntu 22.04的官方推荐版本。我个人习惯用apt安装，干净利落。先设置软件源：

sudo apt update
sudo apt install curl gnupg lsb-release
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
sudo apt update
sudo apt install ros-humble-desktop

安装完成后，记得配置环境变量。我建议直接写到.bashrc里：

echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
source ~/.bashrc
避坑指南： 我曾经遇到过Python版本冲突的问题。ROS2 Humble依赖Python 3.10，如果你系统里装了多个Python版本，记得用update-alternatives设置默认版本。

4.2 工作空间创建

工作空间是ROS2项目的根目录。我习惯用colcon来构建，比catkin快不少。创建步骤很简单：

mkdir -p ~/ros2_ws/src
cd ~/ros2_ws
colcon build

构建完成后，你会看到build、install、log三个目录。每次修改代码后，记得重新colcon build。嗯，这里要注意：如果你只改了某个包，可以用colcon build --packages-select 包名来单独编译，省时间。

4.3 功能包结构

一个标准的ROS2功能包长这样：

my_package/
├── CMakeLists.txt
├── package.xml
├── src/
│   └── my_node.cpp
├── include/
│   └── my_package/
├── launch/
├── msg/
├── srv/
└── config/

package.xml是包的身份证，里面声明了依赖、作者、许可证等信息。CMakeLists.txt是编译规则。我个人习惯把节点代码放在src里，头文件放在include里，这样结构清晰。

核心要点： 功能包的名字必须和package.xml里的<name>一致，否则colcon会报错。我刚开始写的时候，就因为大小写问题折腾了半小时。

4.4 节点与话题通信

节点是ROS2的最小执行单元。话题通信是发布-订阅模式，说白了就是一个节点发消息，其他节点收消息。写一个发布节点：

# publisher.py
import rclpy
from rclpy.node import Node
from std_msgs.msg import String

class MinimalPublisher(Node):
    def __init__(self):
        super().__init__('minimal_publisher')
        self.publisher_ = self.create_publisher(String, 'topic', 10)
        timer_period = 0.5
        self.timer = self.create_timer(timer_period, self.timer_callback)

    def timer_callback(self):
        msg = String()
        msg.data = 'Hello, ROS2!'
        self.publisher_.publish(msg)

订阅节点类似，只是用create_subscription。你想想看，这种模式在AGV里多实用——激光雷达发数据，导航模块收数据，各干各的，互不干扰。

4.5 服务与动作通信

服务通信是请求-响应模式。适合一次性任务，比如「帮我算个路径」。动作通信则适合长时间任务，比如「导航到A点」，过程中还能反馈进度。

服务定义文件（.srv）：

int64 a
int64 b
---
int64 sum

动作定义文件（.action）：

# 目标
geometry_msgs/PoseStamped target_pose
---
# 结果
bool success
---
# 反馈
float32 progress
我的经验： 在AGV项目中，服务常用于「获取当前位姿」，动作常用于「执行导航任务」。动作的反馈机制特别好用，你可以实时看到机器人走到哪了。

4.6 Launch文件编写

Launch文件用来一次性启动多个节点。ROS2的launch文件用Python写，比ROS1的XML灵活多了。看个例子：

# my_launch.py
from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        Node(
            package='my_package',
            executable='my_node',
            name='my_node',
            parameters=[{'param1': 'value1'}]
        ),
        Node(
            package='another_package',
            executable='another_node'
        )
    ])

启动时用ros2 launch my_package my_launch.py。我个人习惯把launch文件放在功能包的launch目录下，方便管理。

4.7 ROS2命令行工具

命令行工具是调试利器。我常用的几个：

命令 用途
ros2 node list 列出所有节点
ros2 topic list 列出所有话题
ros2 topic echo /topic_name 查看话题数据
ros2 service list 列出所有服务
ros2 action list 列出所有动作
ros2 bag record -a 录制所有话题数据

我曾经在调试AGV导航时，用ros2 topic echo /odom发现里程计数据异常，原来是编码器接线松了。你看，命令行工具能帮你快速定位问题。
