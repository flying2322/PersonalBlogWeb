8 激光雷达数据处理与建图基础

各位同学，欢迎来到第八讲。这一讲我们聊聊激光雷达的数据处理，还有建图的基础。说实话，这部分内容在AGV导航里属于「地基」——地基打不牢，后面定位、规划全得翻车。我自己刚入行那会儿，就吃过点云没处理好、建图建出一堆鬼影的亏，今天咱们把这些坑一个个填上。

8.1 激光雷达点云数据格式

先说说点云长什么样。激光雷达扫出来的数据，本质上是一堆三维坐标点，每个点包含(x, y, z)坐标，有的还带强度值(intensity)或时间戳。常见的格式有这么几种：

  • PCD格式：Point Cloud Library的标配，带文件头，可读性好
  • PLY格式：多边形文件格式，支持颜色和法向量
  • ROS的sensor_msgs/LaserScan：2D激光常用，存的是距离和角度
  • ROS的sensor_msgs/PointCloud2：3D激光常用，结构灵活

我个人习惯在ROS里直接用PointCloud2格式，因为它能直接跟PCL库对接，省去格式转换的麻烦。不过要注意，不同激光雷达的坐标系定义可能不一样——有的x轴朝前，有的y轴朝前，这个搞错了，建图直接歪掉。

重要提醒：拿到新雷达，第一件事就是打印一帧点云，肉眼确认坐标系方向。别问我怎么知道的——我曾经在项目里因为这个原因，排查了整整两天。

8.2 点云滤波：直通、体素、统计

原始点云数据量很大，而且包含大量噪声。你想想看，一个16线激光雷达每秒能产生30万个点，全扔给建图算法，CPU直接冒烟。所以滤波是必须的。

8.2.1 直通滤波

直通滤波说白了就是「切一刀」。比如你的AGV只在2米高的空间内运行，那把z > 2.0的点全砍掉。代码很简单：

pcl::PassThrough<pcl::PointXYZ> pass;
pass.setInputCloud(cloud);
pass.setFilterFieldName("z");
pass.setFilterLimits(0.0, 2.0);
pass.filter(*cloud_filtered);

我在项目中遇到过一个问题：直通滤波的边界值设得太死，导致地面反射点被误删，建图时地面那一层全是空洞。后来我习惯留个0.1米的余量。

8.2.2 体素滤波

体素滤波是降采样的利器。它把空间划分成一个个小立方体（体素），每个体素里只保留一个重心点。说白了就是用分辨率换效率。

pcl::VoxelGrid<pcl::PointXYZ> voxel;
voxel.setInputCloud(cloud);
voxel.setLeafSize(0.05f, 0.05f, 0.05f); // 5cm体素
voxel.filter(*cloud_filtered);

体素大小怎么选？我一般这样定：

场景体素大小说明
室内走廊0.03-0.05m细节保留多
仓库货架0.05-0.10m平衡精度与速度
室外大场景0.10-0.20m主要看轮廓

小技巧：体素滤波会丢失边缘信息。如果你要做精确的建图，建议先体素降采样，再单独保留边缘点。

8.2.3 统计滤波

统计滤波用来剔除离群点。它的原理很简单：计算每个点与邻近k个点的平均距离，如果这个距离超过阈值（均值+倍数×标准差），就判定为噪声。

pcl::StatisticalOutlierRemoval<pcl::PointXYZ> sor;
sor.setInputCloud(cloud);
sor.setMeanK(50);          // 邻近点数量
sor.setStddevMulThresh(1.0); // 标准差倍数
sor.filter(*cloud_filtered);

嗯，这里要注意：标准差倍数设得太小，会把正常点也干掉；设得太大，噪声又滤不干净。我一般从1.0开始调，看效果再微调。

8.3 激光雷达畸变校正

激光雷达在运动过程中扫描，会产生畸变。为什么？因为雷达转一圈需要时间（比如100ms），这期间机器人可能已经移动了0.5米。结果就是：同一个物体，在扫描起始和结束时的位置不一样，建图时出现重影。

畸变校正的核心思路：利用里程计或IMU数据，把每个激光点投影到同一个时间戳下。具体步骤：

  1. 获取每个激光点的时间戳（相对扫描起始）
  2. 根据里程计插值，得到每个时刻的机器人位姿
  3. 把每个点从雷达坐标系变换到世界坐标系
  4. 再统一投影到扫描结束时刻的坐标系

代码实现大致长这样：

// 伪代码示意
for (int i = 0; i < scan_points.size(); i++) {
    double t = scan_points[i].time;  // 相对时间
    Pose pose = interpolateOdom(t);  // 里程计插值
    Point p_world = transform(scan_points[i], pose);
    scan_corrected.push_back(p_world);
}

避坑指南：我曾经在畸变校正时直接用线性插值，结果在急转弯场景下建图全糊了。后来改用IMU辅助的匀速模型插值，效果才稳定。记住：里程计频率不够时，IMU是救命稻草。

8.4 Gmapping算法原理与参数调优

Gmapping是2D激光SLAM的经典算法，基于粒子滤波。它的核心思想：用一堆粒子来估计机器人的位姿和地图，每个粒子代表一个可能的轨迹。

8.4.1 算法流程

Gmapping的流程可以概括为四步：

  1. 提议分布：利用激光观测更新粒子的权重，让粒子集中在高概率区域
  2. 权重计算：根据观测模型计算每个粒子的重要性权重
  3. 重采样：剔除权重低的粒子，复制权重高的粒子
  4. 地图更新：用每个粒子的轨迹更新栅格地图

这里有个关键点：Gmapping的提议分布结合了里程计和激光数据，比纯里程计更准。说白了，就是让激光「拽着」粒子往正确方向走。

8.4.2 参数调优

Gmapping的参数很多，但真正需要调的也就这几个：

参数默认值调优建议
particles30场景越大、噪声越大，粒子数越多（50-100）
delta0.05地图分辨率，一般0.05m够用，精细场景用0.025m
linearUpdate1.0机器人移动多少米更新一次地图，建议0.5-1.0
angularUpdate0.5机器人旋转多少弧度更新一次，建议0.3-0.5
srr0.01里程计平移噪声，根据实际里程计精度调
srt0.02里程计旋转噪声，一般比srr大一点

实战经验：我调Gmapping时有个习惯——先调粒子数。粒子太少，建图容易发散；粒子太多，CPU扛不住。一般从30开始，如果建图出现「鬼影」就加到50，还不行就检查畸变校正和里程计。

还有一个容易被忽略的参数：minimumScore。它控制激光匹配的最低分数，低于这个值就丢弃观测。我建议设成50-100，能有效过滤掉遮挡严重时的错误匹配。
