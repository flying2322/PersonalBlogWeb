19 交通管制系统测试与验证

测试与验证，说白了就是给交通管制系统做一次全面体检。我做了这么多年AGV调度，见过太多系统上线后出问题——不是死锁就是碰撞，归根结底都是测试没做到位。这一章，我就把压箱底的测试方法掏出来，跟你聊聊怎么把交通管制系统测透。

19.1 单元测试方法

单元测试，我习惯叫它“零件级测试”。每个模块单独拿出来测，确保它自己不出毛病。

核心测试点：

  • 路径申请模块：输入不同起点、终点，检查返回的路径是否合法
  • 锁分配模块：模拟多个AGV同时申请同一路段，看锁是否互斥
  • 死锁检测模块：构造环形等待图，验证检测算法能否正确识别
  • 优先级仲裁模块：不同优先级的AGV同时请求资源，看高优先级是否优先通过

我个人习惯：单元测试覆盖率至少要达到90%以上。尤其是死锁检测和锁分配这两个模块，我建议用边界值分析法——比如同时申请0个资源、1个资源、N个资源、超过最大资源数，这些边界情况最容易出bug。

举个例子，路径申请模块的单元测试代码（伪代码）：

// 测试用例：路径申请
test("路径申请_正常路径") {
    // 输入：起点A，终点B，当前地图无拥堵
    PathRequest req = new PathRequest("AGV_01", "A", "B");
    PathResult result = trafficSystem.applyPath(req);
    assert(result.isSuccess() == true);
    assert(result.getPath().size() > 0);
}

test("路径申请_目标点被占用") {
    // 输入：起点A，终点B，但B点已被其他AGV锁定
    PathRequest req = new PathRequest("AGV_02", "A", "B");
    PathResult result = trafficSystem.applyPath(req);
    assert(result.isSuccess() == false);
    assert(result.getErrorCode() == ErrorCode.DEST_OCCUPIED);
}

避坑指南：我曾经在单元测试里漏掉了“路径申请超时”这个场景。结果上线后，有个AGV申请路径后一直没得到响应，系统就卡死了。后来我加了个超时机制，单元测试里也补上了这个用例。

19.2 集成测试策略

单元测试过了，接下来就是集成测试。说白了，就是把各个模块拼在一起，看它们能不能好好配合。

我建议的集成测试策略：

  1. 自底向上集成：先测底层模块（如路径规划、锁管理），再测上层模块（如调度决策、异常处理）
  2. 关键路径优先：先测最常用的业务路径，比如“AGV申请路径→获得锁→行驶→释放锁”
  3. 异常场景覆盖：模拟网络中断、AGV故障、地图变更等异常情况

集成测试中，我特别关注模块间的接口契约。比如路径申请模块返回的数据格式，锁分配模块能不能正确解析。你想想看，如果两个模块对“路径ID”的命名规则不一致，那整个系统就乱套了。

注意：集成测试不要只测“快乐路径”。我遇到过最坑的一次，是路径申请模块返回了空路径，但锁分配模块没做空值检查，直接报空指针异常。从那以后，我要求所有模块的接口都必须做输入校验。

集成测试的典型场景：

测试场景 输入 预期结果
单AGV正常行驶 AGV_01从A到B，路径无冲突 成功申请路径，正常行驶
双AGV交叉行驶 AGV_01从A到C，AGV_02从B到D，路径交叉 系统分配优先级，避免碰撞
AGV故障退出 AGV_01行驶中突然离线 系统自动释放锁，重新规划路径

19.3 压力测试与稳定性评估

压力测试，这是我最看重的一环。很多系统在实验室里跑得好好的，一到现场就崩，为什么？说白了就是没扛住压力。

压力测试的核心指标：

  • 并发AGV数量：系统能同时处理多少台AGV的路径申请
  • 请求响应时间：从AGV发出请求到获得响应，平均耗时多少
  • 系统吞吐量：单位时间内能处理多少条路径申请
  • 资源锁竞争率：多个AGV同时申请同一资源时，系统的处理效率

我记得有一次，客户要求系统支持50台AGV同时运行。我们在实验室测了30台没问题，但一上50台，系统响应时间从50ms飙升到500ms，AGV频繁超时。后来发现是锁分配模块的算法复杂度太高，从O(n)优化到O(log n)后才解决。

稳定性评估标准（我常用的）：

  • 7×24小时连续运行，无死锁、无崩溃
  • CPU使用率不超过70%，内存泄漏率低于1%/小时
  • 路径申请成功率不低于99.9%
  • 异常恢复时间不超过5秒

压力测试的常用工具：

  • JMeter：模拟大量AGV并发请求
  • Locust：Python写的压力测试工具，适合自定义场景
  • 自研模拟器：我习惯写一个AGV模拟器，能同时模拟上百台AGV的行为

最后说一句，测试不是一次性的工作。我建议把测试用例写成自动化脚本，每次代码变更后都跑一遍。嗯，这样心里才踏实。
