9 地图建模与环境感知：栅格地图、拓扑地图与动态更新

各位同学，今天我们来聊聊AGV调度系统里一个非常基础但又极其关键的话题——地图建模与环境感知。说实话，我见过不少项目，调度算法写得花里胡哨，结果地图模型没建好，车跑起来各种撞墙、死锁。嗯，地图就是AGV的“世界观”，世界观错了，后面再怎么优化都是白搭。

一、为什么地图建模这么重要？

你想想看，AGV要在一个环境里自主移动，它首先得知道“我在哪”、“我要去哪”、“路上有什么”。这三个问题，全得靠地图来回答。我个人习惯把地图建模比作给AGV画一张“交通图”——不光要有路，还得标清楚哪里是单行道、哪里是红绿灯、哪里在施工。

我在项目中遇到过最典型的案例：一个仓储项目，现场环境其实很简单，就是几排货架加几条主通道。但一开始我们用纯栅格地图，分辨率设得特别高，结果地图文件巨大，路径规划慢得像蜗牛。后来换成拓扑地图加局部栅格，问题就解决了。所以，选对建模方法，比把一种方法做到极致更重要。

二、栅格地图建模方法

栅格地图，说白了就是把环境切成一个个小格子。每个格子要么是“可通行”，要么是“障碍物”。这是最直观、最容易理解的方法。

2.1 栅格地图的核心思想

把连续空间离散化。每个格子的大小（分辨率）决定了地图的精度。分辨率越高，地图越精细，但计算量也越大。

关键参数：
  • 分辨率：通常取AGV车身宽度的1/3到1/2。比如AGV宽1米，格子大小取0.3-0.5米比较合适。
  • 状态值：0表示空闲，1表示障碍物，2表示未知区域。
  • 更新频率：动态环境建议每100-200ms更新一次。

2.2 栅格地图的构建流程

我一般这么干：先用激光雷达或者深度相机扫描环境，得到点云数据。然后做栅格化处理，把点云投影到二维平面上。最后做膨胀处理——把障碍物周围的格子也标记为不可通行，给AGV留出安全距离。

// 伪代码：栅格地图构建
function buildGridMap(pointCloud, resolution):
    grid = new Grid(width, height, resolution)
    for each point in pointCloud:
        x = point.x / resolution
        y = point.y / resolution
        grid.setOccupied(x, y)
    // 膨胀处理
    grid.dilate(robotRadius / resolution)
    return grid
我的经验：膨胀半径别设太大。我曾经设了1.5倍车身宽度，结果AGV在窄通道里直接“认为”自己过不去，绕了一大圈。后来改成1.2倍，刚刚好。

2.3 栅格地图的优缺点

优点 缺点
实现简单，容易理解 大场景下内存占用高
适合局部路径规划 全局规划效率低
容易融合传感器数据 无法表达拓扑关系

三、拓扑地图建模方法

拓扑地图就不一样了。它不关心环境的具体形状，只关心“哪些地方能去”以及“怎么去”。说白了，就是一张“节点-边”图。

3.1 拓扑地图的核心要素

  • 节点：代表关键位置，比如路口、工位、充电站。
  • 边：代表可通行的路径，边上可以附加长度、宽度、限速等信息。
  • 属性：每个节点和边都可以带一堆属性，比如“这个路口只能直行”、“这段路限速0.5m/s”。

3.2 拓扑地图的构建方法

我习惯的做法是：先手动标定关键节点，然后让AGV跑一遍，自动记录路径。这样生成的拓扑地图既准确又高效。当然，也可以从栅格地图自动提取——用图像处理算法找到骨架线，再提取关键点。

// 伪代码：从栅格地图提取拓扑地图
function extractTopology(gridMap):
    skeleton = thinning(gridMap)  // 骨架提取
    nodes = findJunctions(skeleton)  // 找交叉点
    edges = connectNodes(nodes, skeleton)  // 连接节点
    return TopologyMap(nodes, edges)
注意：拓扑地图一旦建好，环境变了就得手动更新。我曾经在一个项目里，客户临时加了一排货架，结果拓扑地图没更新，AGV直接往货架上撞。所以，拓扑地图一定要配合动态更新机制。

四、动态环境感知与更新

环境是活的。货架会移动、人员会走动、叉车会临时占道。如果地图一成不变，AGV迟早要出问题。动态环境感知，就是让AGV“看见”变化，并及时更新地图。

4.1 动态感知的手段

  • 激光雷达：最常用，精度高，但贵。
  • 深度相机：便宜，但受光照影响大。
  • 超声波传感器：近距离检测，适合补盲。
  • 轮式编码器+IMU：辅助定位，但会累积误差。

4.2 地图更新的策略

我个人推荐“分层更新”策略：

  1. 全局层：静态障碍物（墙壁、柱子），几乎不变，低频更新。
  2. 局部层：半静态障碍物（货架、设备），每天或每班次更新一次。
  3. 动态层：临时障碍物（人、叉车），实时更新，每100ms刷新一次。

这样做的好处是：既保证了地图的实时性，又不会因为频繁更新全局地图导致计算量爆炸。

4.3 动态更新的实现

// 伪代码：动态栅格地图更新
function updateGridMap(gridMap, sensorData):
    for each cell in sensorData:
        if cell.isOccupied:
            gridMap.setOccupied(cell.x, cell.y)
        else:
            gridMap.setFree(cell.x, cell.y)
    // 对动态层做衰减处理
    gridMap.decayDynamicLayer(0.9)  // 每次衰减10%
避坑指南：我曾经在动态更新时忘了做“衰减处理”，结果一个临时障碍物被检测到后，地图上永远标记为障碍物。后来加了衰减机制——如果某个格子连续几次都没检测到障碍物，就逐渐恢复为可通行状态。这样临时障碍物消失后，地图能自动恢复。

五、两种地图的融合使用

在实际项目中，我很少只用一种地图。通常的做法是：

  • 全局规划用拓扑地图，速度快，适合长距离路径规划。
  • 局部规划用栅格地图，精度高，适合避障和精细控制。

两种地图之间需要做坐标对齐和状态同步。比如，拓扑地图上的一个节点，对应栅格地图上的一个区域。当栅格地图检测到障碍物时，要能反向更新拓扑地图上对应边的通行状态。
