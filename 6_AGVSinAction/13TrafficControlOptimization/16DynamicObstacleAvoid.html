16 动态障碍物避让：动态障碍物检测方法、避让路径重规划、避让优先级策略

各位做AGV调度的朋友，咱们今天聊一个绕不开的话题——动态障碍物避让。

说实话，静态障碍物好处理。地图画好，禁区标好，路径一规划，基本就稳了。但动态障碍物不一样。你想想看，车间里突然窜出一辆叉车，或者工人临时放了个料架在通道上，AGV要是傻乎乎撞上去，那画面太美我不敢看。

我入行那会儿，就亲眼见过一台AGV直直撞上临时堆放的托盘。原因很简单——系统根本没检测到那个障碍物。从那以后，我对动态避让这块就特别上心。

核心观点：动态障碍物避让不是单一技术，而是「检测 → 决策 → 重规划」的闭环。缺一环，系统就瘸腿。

16.1 动态障碍物检测方法

检测是避让的第一步。检测不准，后面全是白搭。

我个人习惯把检测方法分成三类：

检测方式 典型传感器 优点 缺点
接触式 碰撞条、触边 成本低、可靠 已经撞上了才检测到
近距非接触 超声波、红外 成本适中、反应快 易受环境干扰
远距非接触 激光雷达、深度相机 精度高、可预判 成本高、计算量大

我在项目中遇到过一个问题：某客户车间粉尘大，激光雷达经常误报。后来我们加了一层「时间窗口滤波」——连续3帧都检测到障碍物才触发避让，误报率直接降了80%。

小技巧：别只依赖一种传感器。激光雷达+超声波互补，是我最常用的方案。激光负责远距离预判，超声波负责近距补盲。

16.2 避让路径重规划

检测到障碍物之后，怎么办？

说白了就两条路：绕过去，或者停下来等。

我一般把重规划分成两个层级：

16.2.1 局部路径调整

适用于障碍物不大、旁边有空间的情况。AGV不需要重新算全局路径，只需要在当前路径附近微调。

举个例子：

// 伪代码：局部避让
if (detectObstacle(currentPath, obstacle)) {
    // 计算偏移量
    offset = calculateSafeOffset(obstacle, AGV_WIDTH);
    // 生成临时绕行点
    waypoint = generateDetourPoint(currentPath, offset);
    // 平滑插入路径
    insertWaypoint(waypoint);
}

嗯，这里要注意——局部调整不能太激进。我见过有人把偏移量设得太大，结果AGV直接怼到墙上了。

16.2.2 全局路径重算

如果障碍物把路堵死了，或者局部调整找不到可行路径，那就得重新规划全局路径。

这时候我建议用A*或者Dijkstra重新算一遍。但有个坑——重算不能太频繁。我曾经遇到一个项目，AGV每遇到一个小障碍就重算全局路径，结果CPU跑满了，调度响应慢得像蜗牛。

避坑指南：我曾经吃过一次亏——全局重算时没考虑AGV当前的运动状态。结果路径算出来了，AGV却因为惯性拐不过那个弯。后来我加了一个「运动学可行性检查」，确保新路径AGV能实际走下来。

16.3 避让优先级策略

多台AGV同时遇到障碍物，谁先走？

这个问题其实挺复杂的。我总结了一套优先级规则：

  1. 任务紧急度优先——有急单的AGV优先通过
  2. 障碍物类型优先——固定障碍物让AGV绕，移动障碍物让AGV等
  3. 交通规则优先——主路上的AGV优先于支路上的
  4. 先到先得——谁先到达冲突区域谁先走

你想想看，如果一台空载AGV和一台满载紧急任务的AGV同时要避让，让空载的等一等，是不是更合理？

实际项目中，我一般用「加权评分法」来计算优先级：

// 优先级评分计算
priorityScore = 
    taskUrgency * 0.4 + 
    obstacleType * 0.3 + 
    roadPriority * 0.2 + 
    arrivalOrder * 0.1;

权重怎么调？说实话，没有标准答案。每个工厂的工况不一样，我建议上线后先跑一段时间，根据实际数据调整。

关键提醒：优先级策略不是死的。我见过一个案例——某工厂晚上加班，只有一台AGV在跑，优先级策略反而拖慢了效率。所以，策略要能动态调整，甚至支持手动干预。

16.4 实战经验总结

做了这么多年AGV调度，我觉得动态避让最核心的就三点：

  • 检测要快——延迟超过200ms，避让就变成「撞上」了
  • 路径要稳——别让AGV走S形，车间里看着不专业，还容易出事故
  • 策略要活——死板的优先级规则，早晚会出问题

最后说一句：动态避让没有银弹。每个工厂的布局、AGV型号、物料种类都不一样。我建议先做仿真，再小规模试跑，最后才全面铺开。别一上来就搞大而全的方案，容易翻车。
