4 坐标系与定位：全局坐标系、局部坐标系、AGV定位技术（二维码/激光/IMU）

各位同学，咱们今天聊点实在的——坐标系和定位。说实话，我见过太多刚入行的工程师，一上来就盯着路径规划算法猛啃，结果AGV一跑就偏，连自己在哪里都搞不清楚。嗯，这就像你开车没有导航，再好的驾驶技术也白搭。

坐标系和定位，说白了就是回答三个问题：我在哪？我要去哪？我怎么去？ 今天咱们就把前两个问题彻底讲透。

核心观点：没有精准的定位，再好的路径规划算法都是纸上谈兵。坐标系是定位的“语言”，定位是AGV的“眼睛”。

4.1 全局坐标系：AGV的“世界地图”

全局坐标系，也叫世界坐标系。你可以把它想象成一张仓库的俯视图，整个仓库的每个角落都有一个唯一的坐标。我个人习惯用笛卡尔坐标系，原点通常设在仓库的某个固定角落，比如西南角的地面。

举个例子，我在一个3万平米的电商仓库做项目时，全局坐标系的原点就定在仓库大门的正中心。为什么选这里？因为大门是唯一的固定参照物，不会因为货架移动而改变。你想想看，如果原点选在某个货架腿上，哪天货架被叉车撞歪了，整个坐标系就废了。

全局坐标系通常包含三个维度：

  • X轴：仓库的长度方向（比如从东到西）
  • Y轴：仓库的宽度方向（比如从南到北）
  • θ（朝向角）：AGV车头的朝向，通常以正北为0°，顺时针增加

这里有个坑，我提醒一下：θ角的定义一定要统一。我曾经遇到一个项目，机械团队用弧度制，软件团队用角度制，结果AGV在转弯时直接撞上了货架。嗯，从那以后我规定所有文档里必须用角度制，并且标注清楚“正北为0°”。

4.2 局部坐标系：AGV的“自我认知”

局部坐标系是跟着AGV跑的。它的原点在AGV的几何中心（或者驱动轮中心），X轴指向车头方向，Y轴指向车身左侧。说白了，就是AGV自己眼中的世界。

为什么要搞两套坐标系？我举个例子你就明白了。假设AGV要执行一个“向前移动1米”的指令，在局部坐标系里就是(1, 0, 0)。但在全局坐标系里，这个移动量需要根据AGV当前的朝向做旋转和平移变换。你想想看，如果AGV朝东，向前1米就是全局的(1, 0)；如果朝北，向前1米就是全局的(0, 1)。

坐标变换的公式其实很简单，我直接给代码：

// 局部坐标转全局坐标
// 输入：局部坐标 (x_local, y_local)，AGV当前位姿 (x_agv, y_agv, theta)
// 输出：全局坐标 (x_global, y_global)

x_global = x_agv + x_local * cos(theta) - y_local * sin(theta);
y_global = y_agv + x_local * sin(theta) + y_local * cos(theta);

我的经验：在实际项目中，我建议把坐标变换封装成一个独立的函数，并且加上单元测试。别问我为什么——有一次我在一个紧急项目里手写变换公式，结果把sin和cos写反了，AGV在仓库里画了半小时的“8”字才被发现。

4.3 AGV定位技术：三种主流方案

定位技术是AGV的“眼睛”。目前主流的有三种：二维码、激光、IMU。我一个个说。

4.3.1 二维码定位：便宜但“近视”

二维码定位的原理很简单：在地面贴二维码，每个二维码存储了它在全局坐标系中的精确坐标。AGV底部的摄像头扫到二维码，就知道自己在哪里了。

优点很明显：

  • 成本低，一个二维码几分钱
  • 精度高，可以达到±1mm
  • 实现简单，开源的库一抓一大把

缺点也很致命：

  • 二维码容易被磨损、被灰尘覆盖
  • AGV只能在有二维码的地方知道自己在哪，两个二维码之间是“盲区”
  • 地面改造工作量大，几千平米的仓库贴二维码能贴到怀疑人生

避坑指南：我曾经在一个冷库项目里用二维码定位，结果零下18度的环境下，二维码上的胶水冻脆了，AGV跑着跑着二维码就掉了。后来我们改用环氧树脂粘贴，才解决问题。所以，环境因素一定要提前考虑。

4.3.2 激光定位：精准但“娇气”

激光定位，主要是用激光雷达（LiDAR）扫描周围环境，与预先建好的地图做匹配，从而确定自身位置。目前主流的有两种：

  • 反光板定位：在仓库里固定位置安装反光板，AGV发射激光并接收反射信号，通过三角测量定位
  • SLAM自然导航：利用环境中的自然特征（墙壁、货架腿等）进行定位和建图

我个人更倾向于SLAM自然导航，因为它不需要改造环境。但要注意，SLAM对环境特征有要求——如果仓库里全是光秃秃的白色墙壁，激光扫过去啥特征都没有，定位就会漂移。

激光定位的精度一般在±10mm到±50mm之间，取决于激光雷达的型号和环境复杂度。

4.3.3 IMU定位：不依赖外部但会“漂”

IMU（惯性测量单元）包含加速度计和陀螺仪。它通过积分加速度得到速度，再积分速度得到位移。说白了，就是靠“猜”自己走了多远。

IMU的优点：

  • 完全自主，不需要任何外部设施
  • 更新频率高，可以达到1000Hz以上
  • 短时间内精度不错

IMU的缺点：

  • 累积误差——这是最要命的。你想想看，加速度计有零点漂移，积分一次变成速度误差，再积分一次变成位置误差。时间越长，误差越大。
  • 温度敏感，温度变化会导致IMU参数变化

我的建议：不要单独依赖IMU做定位。在实际项目中，IMU通常作为辅助传感器，用于填补二维码或激光定位之间的“盲区”。比如，AGV在两个二维码之间行驶时，用IMU做短时间的位置推算，等扫到下一个二维码再修正误差。

4.4 多传感器融合：取长补短

说了这么多，你可能会问：到底用哪种定位技术最好？我的答案是：小孩子才做选择，成年人全都要。

在实际工程中，我们通常采用多传感器融合的方式。比如：

  • 激光雷达做主定位，提供全局位置
  • IMU做辅助，提供高频的姿态和速度信息
  • 二维码做“地标”，在关键位置（如货架前、充电站）提供绝对位置修正

融合算法最常用的是扩展卡尔曼滤波（EKF）。我直接给一个简化的融合流程：

// 多传感器融合伪代码
while (AGV运行中) {
    // 预测步骤：基于IMU数据推算当前位置
    pose_predicted = predict(pose_last, imu_data, dt);
    
    // 如果有激光定位数据
    if (laser_data_available) {
        pose_corrected = ekf_update(pose_predicted, laser_data);
    }
    
    // 如果有二维码数据
    if (qr_data_available) {
        pose_corrected = ekf_update(pose_corrected, qr_data);
    }
    
    // 输出最终位姿
    pose_output = pose_corrected;
}

经验之谈：多传感器融合的关键不是算法多复杂，而是时间戳对齐。激光雷达的数据可能是50ms前的，IMU数据是10ms前的，如果不做时间同步，融合出来的位置就是“时空错乱”的。我建议所有传感器都用同一个时钟源，或者用硬件触发同步。
