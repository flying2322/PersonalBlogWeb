13 TEB算法：时间弹性带、轨迹优化、与全局路径的融合

各位好，今天我们来聊聊TEB算法。说实话，我刚接触这个算法时，觉得名字挺唬人的——「时间弹性带」。后来在项目里真正用起来才发现，它本质上就是个带时间约束的轨迹优化器。

你想想看，AGV在仓库里跑，光有全局路径够吗？不够。全局路径只是告诉你「从A到B走哪条路」，但怎么走得稳、走得快、不撞人，这才是TEB要解决的问题。

13.1 什么是时间弹性带？

弹性带（Elastic Band）这个概念，最早是Quinlan和Khatib在1993年提出的。说白了，就是把路径想象成一根橡皮筋。两端固定（起点和终点），中间的点可以受力变形。

我个人的理解是：全局路径是骨架，TEB是肌肉。骨架决定了大致走向，肌肉负责动态调整。

TEB在弹性带的基础上，加入了时间维度。每个路径点不光有位置(x, y)，还有时间戳t。这样一来，我们就能同时优化空间和时间。

核心思想：将路径离散化为一系列位姿点，每个点关联一个时间间隔。通过优化这些点的位置和时间，得到一条平滑、安全、动态可行的轨迹。

13.2 TEB的数学模型

嗯，这里要稍微上点数学了。不过别担心，我会用大白话讲清楚。

TEB的优化目标函数长这样：

min f(s) = w1 * f_path + w2 * f_obstacle + w3 * f_velocity + w4 * f_acceleration + w5 * f_time

其中：

  • f_path：路径平滑性约束——让轨迹别太弯弯绕绕
  • f_obstacle：障碍物避碰约束——离障碍物远一点
  • f_velocity：速度约束——别超速
  • f_acceleration：加速度约束——加减速别太猛
  • f_time：时间最优性约束——尽量快

每个约束都是一个代价函数，乘以权重系数后加起来。权重怎么调？我在项目里踩过坑，后面会讲。

13.3 轨迹优化的核心步骤

TEB的优化过程，我习惯把它分成三步：

  1. 初始化：从全局路径上采样，生成初始的位姿序列
  2. 构建超图：把位姿点、时间间隔、约束条件都塞进一个图优化框架
  3. 迭代求解：用g2o或Ceres等优化库求解，得到最优轨迹

我曾经在一个项目中，全局路径有200多个点。如果全部优化，计算量太大。后来我做了个降采样，每隔3个点取一个，优化完再插值回去。效果不错，实时性从200ms降到了30ms。

小技巧：优化时不要一次性把所有点都丢进去。先优化关键点（拐弯处、障碍物附近），再细化中间点。这叫「分层优化」，效率高很多。

13.4 与全局路径的融合

这是实际落地中最关键的一环。TEB不能脱离全局路径瞎跑，否则容易陷入局部最优。

我常用的融合策略有两种：

策略 做法 适用场景
硬约束 把全局路径点作为TEB的参考路径，偏差太大就惩罚 狭窄通道、货架间
软约束 全局路径只提供初始值，TEB自由优化 开阔区域、临时绕障

我个人更推荐混合使用。在货架区用硬约束，在主干道用软约束。怎么切换？看AGV当前位置的障碍物密度。

注意：全局路径和TEB之间一定要做「时间对齐」。全局路径只有空间信息，TEB需要时间信息。我见过有人直接把全局路径点的时间戳设成0，结果优化出来的轨迹速度忽快忽慢，AGV在仓库里一窜一窜的。

13.5 避坑指南

做TEB这几年，我踩过的坑不少。挑几个典型的说说：

  • 权重调参是个玄学：我曾经花了两周调权重，后来发现用自适应权重更好——根据场景动态调整。比如靠近障碍物时，增大避障权重；直道时，增大速度权重。
  • 时间间隔别设太大：我一开始设了0.5秒，结果轨迹很粗糙。后来改成0.1秒，平滑度明显提升。当然，计算量也上去了，需要平衡。
  • 别忘了运动学约束：差速AGV和全向AGV的TEB参数完全不同。我吃过亏，用差速的参数去调全向车，结果优化出来的轨迹根本执行不了。

13.6 代码示例

下面是一个简化的TEB优化流程，用Python伪代码表示：

class TEBPlanner:
    def __init__(self):
        self.weight_path = 1.0
        self.weight_obstacle = 5.0
        self.weight_velocity = 2.0
        self.weight_time = 0.5
        
    def optimize(self, global_path, obstacles):
        # 1. 初始化位姿序列
        poses = self.sample_from_path(global_path)
        
        # 2. 构建优化问题
        graph = HyperGraph()
        for i in range(len(poses)):
            graph.add_vertex(poses[i])
            graph.add_vertex(self.dt[i])  # 时间间隔
        
        # 3. 添加约束
        graph.add_edge(poses, 'path_smoothness', self.weight_path)
        graph.add_edge(poses, obstacles, 'obstacle_avoidance', self.weight_obstacle)
        graph.add_edge(poses, self.dt, 'velocity_limit', self.weight_velocity)
        
        # 4. 求解
        result = graph.optimize(max_iterations=50)
        
        return result.poses, result.dt

实际项目中，我一般用C++实现，配合ROS的costmap_2d做障碍物检测。Python版本适合快速原型验证。

13.8 实际项目经验

最后分享一个真实案例。去年我在一个电商仓库做AGV调度，货架间距只有1.2米，AGV宽度0.8米。用纯全局路径规划，AGV经常卡在货架间出不来。

后来上了TEB，效果立竿见影。但有个问题——TEB优化后的轨迹有时候会贴着货架走，虽然不撞，但看着吓人。我加了个「安全裕度」参数，把障碍物膨胀半径从0.1米改成0.3米，问题解决。

嗯，这里要注意：安全裕度不是越大越好。设太大，AGV在狭窄区域会认为无路可走，直接报错。我最终设成了动态裕度——根据通道宽度自动调整。

说白了，TEB是个好工具，但用得好不好，全看你对场景的理解。

总结：TEB算法的精髓在于「弹性」二字。它不像全局路径那样死板，也不像纯局部规划那样短视。把全局的骨架和局部的肌肉结合起来，AGV才能在仓库里跑得又快又稳。
