23 仿真环境搭建：ROS/Gazebo仿真、CoppeliaSim、自定义2D仿真器

做AGV路径规划，光有算法不行。你得有个地方跑起来看看效果。

我见过不少团队，算法仿真跑得飞起，一上真车就翻车。为什么？因为仿真环境没搭对。今天我就把三种主流方案掰开揉碎了讲给你听。

为什么需要仿真环境？

说白了，仿真就是你的“安全实验室”。

  • 省钱：一台AGV少说几万块，撞坏了心疼。仿真里随便撞，重启就行。
  • 省时间：真实场景跑一遍要半小时，仿真里可以加速跑。
  • 能复现：有些bug在真实环境里很难复现，仿真里可以精确控制每个参数。

我个人习惯，算法开发阶段，70%的时间在仿真里调参，30%才上真车验证。

核心观点：仿真不是替代真实测试，而是帮你把真实测试的效率提升10倍。

方案一：ROS + Gazebo 仿真

这是目前工业界最主流的方案。ROS负责通信，Gazebo负责物理仿真。

环境搭建步骤

  1. 安装ROS：建议用Noetic（Ubuntu 20.04）或Humble（Ubuntu 22.04）
  2. 安装Gazebo：ROS自带Gazebo，但版本要匹配
  3. 配置AGV模型：用URDF或SDF描述你的车体
  4. 添加传感器：激光雷达、IMU、里程计
  5. 启动仿真：roslaunch命令一键启动
# 安装ROS Noetic（Ubuntu 20.04）
sudo apt install ros-noetic-desktop-full

# 安装Gazebo
sudo apt install ros-noetic-gazebo-ros-pkgs ros-noetic-gazebo-ros-control

# 启动一个简单的AGV仿真
roslaunch turtlebot3_gazebo turtlebot3_world.launch

我在项目中遇到过一个问题：Gazebo默认的物理引擎跑起来很慢。后来发现是碰撞检测精度设得太高了。调低一点，速度能快3倍。

小技巧：Gazebo里可以用Ctrl+R重置仿真，不用每次都重启launch文件。

ROS + Gazebo的优缺点

优点 缺点
社区庞大，资料多 安装配置复杂
与ROS无缝集成 物理仿真速度慢
支持多机器人仿真 对GPU要求高
有现成的AGV模型库 调试起来比较麻烦

方案二：CoppeliaSim（原V-REP）

CoppeliaSim是另一款强大的仿真器。它最大的特点是——脚本驱动。

你想想看，ROS/Gazebo里你要写一堆launch文件、配置文件。CoppeliaSim里，你直接写Lua脚本就能控制一切。

快速上手

  1. 下载安装CoppeliaSim Edu版（免费）
  2. 打开软件，加载一个AGV模型
  3. 用Lua脚本控制运动
  4. 通过ROS接口与外部通信
-- CoppeliaSim Lua脚本示例：控制AGV前进
function sysCall_init()
    motorLeft = sim.getObjectHandle('motor_left')
    motorRight = sim.getObjectHandle('motor_right')
end

function sysCall_actuation()
    sim.setJointTargetVelocity(motorLeft, 2.0)
    sim.setJointTargetVelocity(motorRight, 2.0)
end

我曾经用CoppeliaSim做过一个项目，需要模拟AGV在仓库里的调度。CoppeliaSim的脚本能力让我能快速实现自定义逻辑，比Gazebo快多了。

注意：CoppeliaSim的免费版有水印，商用需要购买授权。不过学习用完全够了。

CoppeliaSim vs Gazebo

对比项 CoppeliaSim Gazebo
上手难度 中等 较高
脚本能力 强（Lua） 弱（需ROS节点）
物理精度 中等 高
渲染效果 好 一般
社区支持 中等 强

方案三：自定义2D仿真器

有时候，你不需要那么复杂的3D物理仿真。你只是想快速验证路径规划算法。

这时候，自己写一个2D仿真器反而更高效。

什么时候用自定义2D仿真器？

  • 只关注路径规划算法，不关心动力学
  • 需要快速迭代，一天跑几百次仿真
  • 想完全控制仿真逻辑

一个简单的Python 2D仿真器

import numpy as np
import matplotlib.pyplot as plt

class Simple2DSimulator:
    def __init__(self, width=10, height=10):
        self.width = width
        self.height = height
        self.obstacles = []
        self.robot_pos = [0, 0]
        
    def add_obstacle(self, x, y, radius):
        self.obstacles.append({'x': x, 'y': y, 'r': radius})
        
    def move_robot(self, dx, dy):
        new_x = self.robot_pos[0] + dx
        new_y = self.robot_pos[1] + dy
        
        # 碰撞检测
        for obs in self.obstacles:
            dist = np.sqrt((new_x - obs['x'])**2 + (new_y - obs['y'])**2)
            if dist < obs['r']:
                return False  # 碰撞了
        
        self.robot_pos = [new_x, new_y]
        return True
    
    def render(self):
        plt.figure(figsize=(8, 8))
        plt.xlim(0, self.width)
        plt.ylim(0, self.height)
        
        # 画障碍物
        for obs in self.obstacles:
            circle = plt.Circle((obs['x'], obs['y']), obs['r'], color='red')
            plt.gca().add_patch(circle)
        
        # 画机器人
        robot = plt.Circle(self.robot_pos, 0.3, color='blue')
        plt.gca().add_patch(robot)
        
        plt.grid(True)
        plt.show()

# 使用示例
sim = Simple2DSimulator()
sim.add_obstacle(3, 3, 0.5)
sim.add_obstacle(7, 5, 0.8)
sim.move_robot(1, 1)
sim.render()

这个仿真器虽然简陋，但跑A*、Dijkstra这些算法完全够用。我早期做AGV调度算法时，就是用这种自定义仿真器，一天能迭代几十个版本。

我的建议：先拿自定义2D仿真器验证算法逻辑，再用Gazebo做物理验证。这样效率最高。

三种方案怎么选？

嗯，这里我直接给结论：

  • 做学术研究、算法验证：自定义2D仿真器就够了
  • 做产品级开发：ROS + Gazebo是标配
  • 做复杂场景模拟：CoppeliaSim更灵活

我个人习惯是：先用Python写个2D仿真器快速验证，然后迁移到Gazebo做精细调参。这样既快又稳。
