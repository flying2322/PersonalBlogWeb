3 地图构建基础：栅格地图、拓扑地图、混合地图的对比与选择

做AGV路径规划这么多年，我经常被问到同一个问题：「地图到底该怎么建？」

说实话，这个问题没有标准答案。不同的仓储场景，对地图的要求天差地别。你想想看，一个几万平米的电商仓库，和一个几百平米的精密零件库，能共用同一种地图吗？显然不能。

今天我就把三种主流地图——栅格地图、拓扑地图、混合地图——掰开揉碎了讲清楚。我会结合自己踩过的坑，告诉你什么场景该选什么地图。

核心观点：没有最好的地图，只有最合适的。选错了地图，你的AGV可能连货架都找不到。

3.1 栅格地图：最直观，但最占内存

栅格地图，说白了就是把真实环境切成一个个小格子。每个格子要么是障碍物（黑色），要么是自由空间（白色）。

我记得刚入行时，第一个项目就是给一个图书仓库做AGV。当时我图省事，直接用了栅格地图。结果呢？地图分辨率设得太高，一个1000平米的仓库，内存直接爆了。

栅格地图的核心参数：

  • 分辨率：每个格子代表的实际尺寸。比如0.1m/格，还是0.5m/格。
  • 存储方式：二维数组，0表示空闲，1表示障碍。
  • 更新频率：静态地图一次建好，动态地图需要实时更新。
// 栅格地图的简单表示（C++伪代码）
const int MAP_WIDTH = 1000;   // 1000列
const int MAP_HEIGHT = 800;   // 800行
int gridMap[MAP_HEIGHT][MAP_WIDTH]; // 0=空闲, 1=障碍

// 检查某个点是否可通行
bool isFree(int x, int y) {
    return gridMap[y][x] == 0;
}

我的经验：栅格地图的分辨率不要低于0.2m/格。太细了内存扛不住，太粗了AGV容易卡在缝隙里。我曾经试过0.5m/格，结果AGV在货架通道里频繁报警——因为格子太大，把通道给「吞掉」了。

栅格地图的优缺点：

优点 缺点
实现简单，容易理解 内存占用大（尤其大面积场景）
路径规划算法成熟（A*、Dijkstra） 无法表达语义信息（比如「这是货架区」）
容易更新和维护 高分辨率下计算量大

3.2 拓扑地图：轻量级，但不够精细

拓扑地图就不一样了。它不关心具体尺寸，只关心「点」和「线」。点代表关键位置（比如货架、充电站），线代表可通行的路径。

为什么会有人用拓扑地图？你想想看，一个大型仓库里，AGV真的需要知道每个角落的精确坐标吗？其实不需要。它只需要知道：从A点到B点，走哪条路最近。

我做过一个汽车零配件仓库的项目，面积很大但路径很简单——就是几条主通道。用栅格地图的话，内存占用太大。后来我换成了拓扑地图，整个地图文件不到10KB，AGV跑得飞快。

// 拓扑地图的简单表示（Python伪代码）

    'D': {'B': 12, 'E': 6},
    'E': {'B': 8, 'D': 6, 'F': 5},
    'F': {'C': 20, 'E': 5}

注意：拓扑地图有一个致命缺陷——它无法处理动态障碍物。如果某个通道临时堆了货物，拓扑地图不会知道。我曾经因为这个吃过亏，AGV按照拓扑路径走，结果撞上了临时堆放的纸箱。

拓扑地图的优缺点：

优点 缺点
内存占用极小 无法表达精细的障碍物信息
路径搜索速度快 构建和维护需要人工干预
适合大规模简单场景 动态环境适应性差

3.3 混合地图：取长补短，但复杂度高

混合地图，顾名思义，就是把栅格地图和拓扑地图结合起来。这也是我个人最推荐的方式。

具体怎么做呢？顶层用拓扑地图做全局规划，底层用栅格地图做局部避障。

举个例子：AGV要从A点到Z点。拓扑地图告诉它：先走到B点，再走到C点，最后到Z点。但走到B点的过程中，如果前面突然出现一个障碍物，栅格地图就派上用场了——它负责局部路径重规划，绕过障碍物。

我在一个3C电子仓库里就是这么干的。仓库有5000平米，货架密集，而且经常有工人走动。纯栅格地图太慢，纯拓扑地图又太危险。混合地图一上，问题全解决了。

// 混合地图的伪代码逻辑
class HybridMap {
    TopoMap topoMap;   // 全局拓扑层
    GridMap gridMap;   // 局部栅格层
    
    Path planPath(Point start, Point end) {
        // 1. 拓扑层规划全局路径
        List<Node> globalPath = topoMap.findPath(start, end);
        
        // 2. 对每个拓扑段，用栅格地图做局部规划
        Path finalPath;
        for each segment in globalPath {
            Path localPath = gridMap.planLocalPath(segment);
            finalPath.append(localPath);
        }
        return finalPath;
    }
}

我的建议：如果你预算充足，直接上混合地图。虽然前期开发成本高一点，但后期维护省心太多。我曾经在一个项目里，纯栅格地图的AGV每天要人工干预3-4次，换成混合地图后，一周都出不了1次问题。

3.4 三种地图的对比与选择

好了，三种地图都讲完了。到底怎么选？我总结了一个简单的判断标准：

  • 场景简单、面积大、路径固定 → 拓扑地图（比如：大型电商仓库的主通道运输）
  • 场景复杂、障碍物多、需要精细避障 → 栅格地图（比如：精密零件仓库）
  • 场景大且复杂、动态障碍物多 → 混合地图（比如：3C电子仓库、生鲜冷链仓库）

嗯，这里要注意：不要为了追求「高级」而盲目选择混合地图。如果你的仓库只有200平米，路径也简单，用栅格地图就足够了。混合地图的开发和维护成本，对于小场景来说完全是浪费。

避坑指南：我曾经在一个小项目里强行上混合地图，结果开发周期从2周拖到了6周。最后发现，用栅格地图+简单A*算法，效果一样好。所以，选地图之前，先搞清楚你的场景到底需要什么。
