6 环境建模：障碍物膨胀、可行区域提取、代价地图生成

各位好，我是老张。今天咱们聊聊环境建模。说白了，就是给AGV画一张它能看懂的地图。

你想想看，AGV在仓库里跑，它看到的原始地图是什么？一堆点云，或者一张栅格图。但直接拿这个图去规划路径，肯定不行。为什么？因为AGV有体积，它不能贴着货架走，得留出安全距离。这就是我们今天要解决的核心问题。

我个人习惯把环境建模分成三步走：障碍物膨胀 → 可行区域提取 → 代价地图生成。这三步做完，AGV才能知道哪里能走、哪里不能走、哪里最好走。

6.1 障碍物膨胀：给AGV留出安全空间

先说说障碍物膨胀。嗯，这里要注意，膨胀不是把障碍物变大，而是把AGV的尺寸考虑进去。

我在项目中遇到过这样一个坑：有次调试，AGV规划出来的路径贴着货架走，距离只有5厘米。理论上能过，但实际跑起来，AGV的传感器一抖动，就撞上了。后来我加了膨胀层，问题就解决了。

膨胀的算法其实不复杂。常用的有两种：

  • 栅格膨胀法：把障碍物周围的栅格标记为不可通行。膨胀半径 = AGV半径 + 安全余量。
  • 多边形膨胀法：对障碍物的轮廓做向外偏移。适合矢量地图。

我一般用栅格法，简单粗暴。代码实现大概是这样：

def inflate_obstacles(grid_map, robot_radius):
    """
    对栅格地图进行障碍物膨胀
    :param grid_map: 二维numpy数组，0表示空闲，1表示障碍物
    :param robot_radius: AGV半径（栅格单位）
    :return: 膨胀后的地图
    """
    import numpy as np
    from scipy.ndimage import binary_dilation
    
    # 定义膨胀结构元素（圆形）
    struct = np.zeros((2*robot_radius+1, 2*robot_radius+1))
    center = robot_radius
    for i in range(2*robot_radius+1):
        for j in range(2*robot_radius+1):
            if (i-center)**2 + (j-center)**2 <= robot_radius**2:
                struct[i,j] = 1
    
    # 执行膨胀操作
    inflated = binary_dilation(grid_map, structure=struct)
    return inflated.astype(int)
⚠️ 避坑指南：膨胀半径不是越大越好。我曾经把半径设成AGV宽度的两倍，结果仓库里一半的路都被堵死了。建议取AGV宽度的1.2倍，再根据实际测试微调。

6.2 可行区域提取：找出AGV能走的路

膨胀完之后，地图上就分成了两块：黑色的是障碍区（含膨胀区），白色的是自由区。但自由区不一定都能走，比如太窄的通道，AGV转不过去。

可行区域提取，说白了就是找出所有满足AGV通行条件的连续区域。我常用的方法是连通域分析。

具体步骤：

  1. 对膨胀后的地图做二值化处理（0=障碍，1=自由）
  2. 用BFS或DFS找出所有连通的自由区域
  3. 过滤掉面积小于AGV转弯半径的区域

你想想看，如果仓库里有个死角，AGV进去了出不来，那这个区域就不能算可行区域。我一般会加一个可达性检查：从AGV的起点出发，能到达的区域才算可行。

💡 个人经验：在提取可行区域时，别忘了考虑AGV的转弯半径。我见过一个案例，AGV规划出来的路径要经过一个90度直角弯，但通道宽度只有1.2米，AGV转弯半径要1.5米，结果卡住了。后来我在可行区域提取时加了一个最小通道宽度检查，就再没出过问题。

6.3 代价地图生成：给每条路打分

可行区域提取完了，AGV知道哪里能走了。但问题来了：能走的路有很多条，走哪条最好？这就需要代价地图了。

代价地图，就是给地图上的每个栅格赋一个代价值。代价越低，AGV越愿意走。代价高的区域，AGV会尽量避开。

我一般把代价分成三层：

代价层 含义 典型值
障碍代价 障碍物附近的栅格，代价高 0~255（255为障碍）
路径代价 距离起点/终点的远近 0~100
偏好代价 人为设定的偏好区域（如充电区、待命区） 0~50

最终代价 = 障碍代价 × 权重1 + 路径代价 × 权重2 + 偏好代价 × 权重3。权重怎么调？我一般先设成1:1:0.5，然后跑仿真看效果。

这里有个小技巧：障碍代价可以用距离变换生成。离障碍物越近，代价越高。这样AGV会自然选择离障碍物远一点的路径，安全性更高。

def generate_cost_map(inflated_map, max_cost=255):
    """
    基于膨胀地图生成代价地图
    :param inflated_map: 膨胀后的二值地图
    :param max_cost: 最大代价值
    :return: 代价地图
    """
    from scipy.ndimage import distance_transform_edt
    
    # 计算距离变换（到最近障碍物的距离）
    dist = distance_transform_edt(inflated_map)
    
    # 将距离映射到代价
    # 距离越近，代价越高
    max_dist = np.max(dist)
    if max_dist == 0:
        return np.zeros_like(dist)
    
    cost_map = max_cost * (1 - dist / max_dist)
    cost_map[inflated_map == 0] = max_cost  # 障碍物区域代价最高
    return cost_map.astype(np.uint8)
🎯 核心要点：代价地图不是一成不变的。仓库里的货架会变动，AGV的电池电量也会变化。我建议每5分钟更新一次代价地图，或者在有事件触发时（如新任务下达）立即更新。

💡 我的习惯：每次做完环境建模，我都会在仿真环境里跑一遍AGV，看看它会不会撞墙、会不会绕远路。如果发现问题，就回头调整膨胀半径或者代价权重。这个迭代过程，往往比算法本身更重要。
