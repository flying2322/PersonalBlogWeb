26 案例1：电商仓库的“货到人”AGV路径规划方案

各位同行，今天咱们聊一个实战案例。

电商仓库的“货到人”模式，说白了就是让AGV把货架搬到你面前。你站着不动，货自己跑过来。听起来很爽对吧？但背后的路径规划，其实挺折腾人的。

我在2019年参与过一个华东地区的电商仓项目，单日订单量峰值超过50万单。那会儿我们用的就是“货到人”方案。今天我把当时的路径规划思路拆开来讲，希望能给你一些启发。

1. 场景特点与挑战

电商仓库跟制造业仓库不一样。制造业的物料流动相对规律，电商呢？订单随机、SKU海量、时效要求极高。

具体来说，有这几个痛点：

  • 订单波次波动大：双十一期间流量是平时的10倍以上，AGV数量需要动态调整
  • 货架布局密集：为了提升存储密度，货架间距通常只有1.2米，AGV转弯空间受限
  • 多机器人协同：几十台甚至上百台AGV同时作业，路径冲突是家常便饭
  • 实时性要求高：从订单下达到AGV出发，延迟不能超过2秒

    • 核心矛盾：如何在有限的空间内，让大量AGV高效、无碰撞地完成“取货架→送工作站→还货架”的闭环？

    2. 路径规划的整体架构

    我们当时采用的是分层规划思路。嗯，这里要注意，不是所有场景都适合分层，但电商仓这种大规模、高动态的场景，分层是必须的。

    整体架构分三层：

    1. 全局路径规划层：基于静态地图，预计算最优路径
    2. 局部路径调整层：处理动态障碍物和临时拥堵
    3. 交通管制层：解决多AGV冲突，防止死锁

    3. 全局路径规划：A*算法的实战改造

    全局路径我们用的是A*算法。但标准的A*直接拿来用，会出问题。

    为什么？因为电商仓库的路径是网格化的，但AGV有尺寸，不能走太窄的通道。我遇到过的情况是：AGV按照A*算出来的路径走，结果卡在货架中间，因为路径宽度不够。

    所以我们对A*做了三点改造：

    • 代价函数增加宽度约束：路径必须满足AGV最小转弯半径和通道宽度
    • 引入时间窗：每条路径记录占用时间段，避免多AGV同时占用同一路段
    • 动态权重调整：高峰时段，优先选择主干道，减少支路拥堵

    小技巧：我个人习惯在A*的启发函数里加入“拥堵系数”。如果某条路最近5秒内被占用了3次以上，就把这条路权重提高20%。效果立竿见影。

    4. 局部路径调整：DWA动态窗口法

    全局路径算好了，但实际跑起来，总有意外。比如前面有台AGV突然故障，或者有个临时障碍物。

    这时候就需要局部路径调整。我们用的是DWA（Dynamic Window Approach）算法。

    DWA的核心思想很简单：在速度空间里采样，找一条能避开障碍物、又尽量靠近全局路径的轨迹。

    具体步骤：

    1. 根据当前速度，生成一组候选速度对（线速度v，角速度ω）
    2. 对每个速度对，模拟未来一段时间的轨迹
    3. 用评价函数打分：距离障碍物越远越好、越靠近全局路径越好、速度越快越好
    4. 选得分最高的速度对，执行

    代码实现大概长这样：

    def dwa_control(robot_pose, goal_pose, obstacles):
    # 速度空间采样
    v_samples = np.linspace(0, max_v, num=10)
    w_samples = np.linspace(-max_w, max_w, num=10)
    
    best_score = -float('inf')
    best_traj = None
    
    for v in v_samples:
        for w in w_samples:
            # 模拟轨迹
            traj = simulate_trajectory(robot_pose, v, w, dt=0.1, steps=20)
            # 评价函数
            score = evaluate_trajectory(traj, goal_pose, obstacles)
            if score > best_score:
                best_score = score
                best_traj = (v, w)
    
    return best_traj

    注意：DWA的采样步长很关键。步长太大，容易漏掉最优解；步长太小，计算量爆炸。我曾经吃过这个亏，后来把采样数从20降到了10，效果反而更好——因为计算快了，控制周期更短。

    5. 交通管制：死锁预防与解除

    多AGV系统最头疼的问题是什么？死锁。

    两台AGV面对面堵着，谁也不让谁。这种情况在电商仓库里太常见了。

    我们的解决方案是“预留区域 + 优先级”：

    策略 说明 适用场景
    预留区域 AGV进入交叉口前，先申请占用区域，离开后释放 十字路口、T型路口
    优先级调度 根据任务紧急程度分配通行权 多AGV同时请求同一路段
    回退机制 死锁发生时，优先级低的AGV倒车让路 死锁已经发生

    我记得有一次，系统里同时跑了80台AGV，突然出现了一个环形死锁——4台AGV互相堵着，形成了一个闭环。当时监控大屏上全是红色报警。

    后来怎么解决的？我们加了一个“死锁检测线程”，每100毫秒扫描一次所有AGV的状态，一旦发现闭环，就强制让其中一台AGV后退3米。问题就解开了。

    6. 实际效果与数据

    这个方案上线后，我们做了对比测试。数据如下：

    指标 优化前 优化后 提升幅度
    单台AGV日均搬运次数 320次 480次 +50%
    路径冲突次数/小时 15次 3次 -80%
    死锁发生频率 每天2-3次 每周不到1次 显著降低
    订单平均处理时间 8.5分钟 5.2分钟 -39%

    说实话，这个结果超出了我们的预期。尤其是死锁频率的降低，让运维人员终于能睡个安稳觉了。

    7. 避坑指南

    最后，分享几个我踩过的坑：

    • 地图精度问题：AGV的定位精度是±5cm，但货架通道宽度只有1.2米。如果地图误差超过3cm，AGV就会刮蹭货架。建议用激光SLAM做高精度建图，别省这个钱。
    • 通信延迟：WiFi环境下，AGV和控制中心的通信延迟可能达到200ms。这在高速运行时很危险。我们后来换成了5G专网，延迟降到了20ms以内。
    • 电池管理：AGV电量低于20%时，路径规划要自动切换到“回充电桩”模式。别等到没电了才处理，那会堵住整条路。

    总结一下：电商仓库的“货到人”AGV路径规划，核心就是三件事——全局路径算得准、局部避障反应快、交通管制不堵车。把这三点做好了，系统基本就稳了。
