9 A*算法优化：双向A*、跳点搜索（JPS）、权重A*

聊到A*算法，很多刚入行的朋友会觉得它已经够用了。嗯，确实，基础A*在简单场景下表现不错。但咱们做仓储自动化的，面对的是动辄几万平方米的仓库，几百台AGV同时跑。这时候基础A*的短板就暴露出来了——慢，而且容易堵。

我个人习惯把A*优化分成三个方向：搜得快、跳得远、走得巧。今天咱们就挨个聊聊。

9.1 双向A*：两头一起搜，效率翻倍

先问个问题：从北京到上海，你是一个人从北京出发快，还是北京和上海同时各派一个人，中间碰头快？

双向A*就是这个思路。它从起点和终点同时开始搜索，两个方向各自维护一个Open List。当两个方向的搜索区域有交集时，路径就找到了。

我在项目中遇到过这样一个场景：一个长条形的货架通道，长度超过200米。基础A*从起点一路搜到终点，Open List里塞了上万个节点。换成双向A*后，搜索空间直接砍了一半多。为什么？因为双向搜索的节点分布是个“哑铃形”，中间交汇，两边扩散少。

核心要点：
  • 双向A*的终止条件：两个方向的当前最优节点互相可达
  • 启发函数可以不对称：起点方向用终点做目标，终点方向用起点做目标
  • 内存占用比单向A*略高，但搜索时间通常减少40%-60%

代码实现上，我建议这样写：

def bidirectional_a_star(start, goal, grid):
    open_start = [start]
    open_goal = [goal]
    closed_start = set()
    closed_goal = set()
    
    while open_start and open_goal:
        # 从起点方向扩展
        current_start = pop_best(open_start)
        if current_start in closed_goal:
            return reconstruct_path(current_start, start, goal)
        # 从终点方向扩展
        current_goal = pop_best(open_goal)
        if current_goal in closed_start:
            return reconstruct_path(current_goal, start, goal)
    return None

注意一个小坑：两个方向的启发函数要一致，否则会出现“擦肩而过”的情况。我曾经调试一个项目，双向A*死活找不到路径，最后发现是起点方向用了曼哈顿距离，终点方向用了欧几里得距离——两个方向对“最优”的理解不一样，自然碰不上。

9.2 跳点搜索（JPS）：让算法学会“跳”

跳点搜索，说白了就是让A*不再一个格子一个格子地走，而是“跳”着走。你想想看，在空旷的仓库通道里，AGV直行100米，中间没有任何障碍物。基础A*会把这100米上的每个格子都加入Open List，然后一个个评估。这不是浪费吗？

JPS的核心思想是：只考虑“跳点”。什么是跳点？就是路径方向发生改变的点，或者障碍物边缘的点。在直线段上，中间那些格子根本不需要评估。

我记得有一次给一个电商仓库做路径规划，货架布局是标准的“回”字形。基础A*跑一次全库路径规划要2.3秒，换成JPS后直接降到0.4秒。效果立竿见影。

JPS的适用条件：
  • 网格地图，且障碍物是静态的
  • 允许8方向移动（上下左右+对角线）
  • 场景中有大量空旷区域（仓库通道、开放区）

不过JPS也有局限。如果仓库里堆满了货架，通道狭窄曲折，那跳点就很少，JPS的优势就发挥不出来。说白了，JPS是为“空旷场景”量身定做的。

避坑指南： 我曾经在一个密集存储仓库里强行用JPS，结果性能还不如基础A*。后来分析发现，因为通道太窄，几乎每个格子都是跳点，JPS的“跳”变成了“一步一步挪”，反而多了跳点判断的开销。所以，场景适配很重要。

9.3 权重A*：给路径加点“偏向”

权重A*，也叫加权A*。它的改动很小，但效果很实用。简单说，就是在启发函数上加一个权重系数w：

f(n) = g(n) + w * h(n)

当w > 1时，算法会更“贪心”，倾向于快速向目标方向搜索。代价是路径可能不是最优的，但搜索速度会快很多。

我在实际项目中，经常把w设在1.2到1.5之间。为什么？因为仓储场景下，AGV的路径不要求绝对最优。差个两三米，多花一两秒，对整体效率影响不大。但搜索时间如果能从1秒降到0.3秒，那对实时调度系统来说就是质的飞跃。

权重A*还有一个变体叫动态权重A*。它的思路是：搜索初期权重高一些，快速逼近目标；接近目标时权重降下来，保证路径质量。我习惯这样设置：

def dynamic_weight(depth, max_depth):
    # 深度越深，权重越接近1
    w = 1.0 + (1.5 - 1.0) * (1 - depth / max_depth)
    return max(1.0, w)

这样既保证了搜索速度，又避免了路径质量太差。嗯，算是一种“既要又要”的折中方案。

9.4 三种优化怎么选？

聊了这么多，你可能会问：到底用哪个？我个人的经验是：

场景 推荐方案 理由
长距离直线通道多 JPS 跳点搜索能跳过大量中间节点
起点和终点距离远 双向A* 搜索空间减半，效果稳定
实时性要求高，路径质量可妥协 权重A* 速度快，实现简单
复杂场景，混合需求 双向A* + 权重A* 两头搜+贪心，综合最优

最后说一句：没有银弹。每种优化都有它的适用边界。我见过太多人拿着JPS当万能药，结果在密集货架区碰了一鼻子灰。做工程嘛，还是要根据实际场景来选。

我个人建议：先跑一遍基础A*做基准测试，然后根据瓶颈选择优化方向。如果Open List太大，试试双向A*；如果扩展节点太多，试试JPS；如果搜索太慢但路径质量要求不高，试试权重A*。一步一步来，别想一口吃成胖子。
