17 电源管理与低功耗：电池电量监测、电源路径管理、低功耗模式切换、充电逻辑

做AGV控制器，电源管理这块儿，说实话，是真正决定产品能不能用的关键。你算法写得再好，电机控制得再顺，电池没电了或者充不进电，一切白搭。我这些年踩过的坑，有一半都跟电源有关。今天咱们就把这块硬骨头啃下来。

17.1 电池电量监测——别让AGV半路“趴窝”

AGV最怕什么？最怕跑到一半没电了，堵在通道上，整个产线都得停。所以电量监测不是简单的“看电压”，而是一门学问。

我个人习惯用TI的BQ系列芯片，比如BQ40Z50、BQ34Z100。这些芯片内置了阻抗跟踪算法，能实时估算电池的剩余电量，精度能做到1%以内。你想想看，如果只靠测电压，锂电池放电平台很平，电压降一点，电量可能已经掉了20%。

核心要点：电量监测不是测电压，而是测“库仑”——也就是流进流出电池的电荷量。BQ芯片内部有高精度ADC，配合电流传感器，实时积分。

我在项目中遇到过一个问题：AGV在低温环境下（比如冷库），电池容量会骤降。BQ芯片的算法会自动补偿温度对容量的影响，但前提是你得把NTC热敏电阻接对位置。嗯，这里要注意，NTC要贴在电池电芯表面，而不是PCB板上，否则测的是环境温度，不是电池温度。

代码层面，我们通过I2C读取BQ芯片的寄存器：

// 读取BQ40Z50的电量百分比
uint8_t read_battery_soc(void) {
    uint8_t soc = 0;
    uint8_t reg_addr = 0x04; // SOC寄存器地址
    i2c_start(BQ_I2C_ADDR);
    i2c_write(reg_addr);
    i2c_restart(BQ_I2C_ADDR | I2C_READ);
    soc = i2c_read_byte(ACK);
    i2c_stop();
    return soc; // 返回0-100
}

注意，BQ芯片的寄存器读取有时需要“解锁”操作，否则读出来的是默认值。我曾经因为这个bug，调试了整整两天，最后发现是忘了发解锁命令。

17.2 电源路径管理——充放电两不误

AGV控制器里，电池和外部电源（比如充电桩）是同时存在的。如果直接并联，会出现电流倒灌、电压冲突等问题。电源路径管理就是解决这个问题的。

说白了，就是让系统优先使用外部电源供电，同时给电池充电；当外部电源断开时，无缝切换到电池供电。这个切换过程不能有掉电，否则控制器会复位。

我常用的方案是BQ25713这颗芯片，它内部集成了双向升降压转换器和路径管理MOSFET。结构图如下：

路径管理的核心逻辑是：

  • 有外部电源时：BQ芯片关闭电池放电通路，打开外部电源通路，同时启动充电回路给电池充电。
  • 无外部电源时：BQ芯片打开电池放电通路，关闭外部电源通路，系统由电池供电。
  • 切换瞬间：BQ芯片内部的理想二极管或MOSFET会保持输出电压稳定，不会出现掉电。

实战技巧：在BQ芯片的VSYS引脚上并联一个大电容（比如220uF），可以进一步吸收切换瞬间的电压跌落。我一般还会加一个TVS管，防止充电桩插拔时的浪涌。

17.3 低功耗模式切换——让AGV“睡个好觉”

AGV不是一直在跑的。它可能停在充电站，或者等待任务。这时候如果控制器全速运行，电池很快就耗光了。低功耗模式就是让控制器在空闲时“打盹”，需要时再“醒来”。

我一般把低功耗分为三级：

模式 功耗 唤醒时间 适用场景
运行模式 5-10W — 正常导航、搬运
待机模式 1-2W <10ms 等待任务、短时停靠
休眠模式 <0.1W <500ms 长时间停靠、充电中

切换逻辑是这样的：

  1. 当AGV到达目标点且无新任务时，进入待机模式。此时关闭电机驱动、激光雷达等大功率外设，但保持通信模块和主控MCU运行。
  2. 如果待机超过设定时间（比如5分钟），自动进入休眠模式。此时MCU进入深度睡眠，只保留RTC和唤醒中断。
  3. 当收到任务指令或充电桩连接信号时，立即唤醒。

代码实现上，我习惯用状态机来管理：

typedef enum {
    POWER_MODE_RUN,
    POWER_MODE_STANDBY,
    POWER_MODE_SLEEP
} power_mode_t;

void power_mode_switch(power_mode_t new_mode) {
    switch(new_mode) {
        case POWER_MODE_STANDBY:
            // 关闭电机、激光雷达
            motor_disable();
            lidar_power_off();
            // 降低MCU主频
            HAL_RCC_ClockConfig(&RCC_ClkInitStruct, FLASH_LATENCY_1);
            // 进入待机模式
            HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);
            break;
        case POWER_MODE_SLEEP:
            // 关闭所有非必要外设
            uart_deinit();
            spi_deinit();
            // 设置RTC唤醒
            HAL_RTC_SetAlarm_IT(&hrtc, &sAlarm, RTC_FORMAT_BIN);
            // 进入深度睡眠
            HAL_PWR_EnterSLEEPMode(PWR_MAINREGULATOR_OFF, PWR_SLEEPENTRY_WFI);
            break;
        default:
            break;
    }
}

注意：进入低功耗模式前，一定要确保所有外设都正确关闭，尤其是电机驱动。我曾经有一次忘了关电机使能，结果AGV在休眠状态下自己溜车了，撞到了货架。嗯，从那以后我每次都会检查外设状态寄存器。

17.4 充电逻辑——安全第一，效率第二

AGV的充电逻辑，说白了就是“怎么充、什么时候停”。锂电池充电有三阶段：预充电、恒流充电、恒压充电。BQ芯片会自动管理这些，但我们需要告诉它充电参数。

我一般通过I2C配置BQ芯片的寄存器：

// 配置充电参数
void charge_config(void) {
    // 设置充电电流：2A
    uint8_t charge_current = 0x14; // 对应2A
    i2c_write_reg(BQ_I2C_ADDR, 0x14, charge_current);
    
    // 设置充电电压：4.2V每节，4节串联=16.8V
    uint8_t charge_voltage = 0x42; // 对应16.8V
    i2c_write_reg(BQ_I2C_ADDR, 0x15, charge_voltage);
    
    // 设置终止电流：0.1C
    uint8_t term_current = 0x05; // 对应0.5A
    i2c_write_reg(BQ_I2C_ADDR, 0x16, term_current);
}

充电逻辑中，有几个关键点：

  • 预充电：当电池电压低于3V时，先用小电流（0.1C）充电，防止损坏电池。
  • 恒流充电：电压达到3V后，用设定电流（比如2A）快速充电。
  • 恒压充电：电压达到4.2V每节后，转为恒压模式，电流逐渐下降。
  • 终止充电：当电流降到终止电流（比如0.1C）时，停止充电。

安全机制：我还会在充电回路中加一个硬件看门狗。如果MCU死机了，看门狗会强制断开充电MOSFET，防止过充。这个设计救过我的AGV一次——有一次充电桩通信异常，MCU一直没发停止命令，硬件看门狗在超时后自动切断了充电，电池才没鼓包。

另外，充电过程中要实时监测电池温度。如果温度超过45°C，应该降低充电电流；超过55°C，立即停止充电。BQ芯片内部有温度保护，但为了保险，我还会在MCU端做一层软件保护。

好了，电源管理这块儿，核心就是这些。你想想看，AGV能不能稳定运行，很大程度上取决于电源系统靠不靠谱。从电量监测到路径管理，再到低功耗和充电逻辑，每一步都得精心设计。我这些年做过的项目，凡是电源出问题的，基本都是细节没做到位——比如NTC位置不对、切换电容太小、充电终止电流设错了。希望你能避开这些坑。
