12 控制算法进阶——LQR、MPC与纯跟踪

各位同学，欢迎来到《AGV控制器开发全流程实战》的第1章。今天咱们聊点硬核的——控制算法进阶。说实话，很多做AGV的朋友，PID调得飞起，但一到复杂场景就抓瞎。我个人觉得，LQR、MPC和纯跟踪这三板斧，是每个AGV工程师必须啃下的硬骨头。

为什么这么说？你想想看，AGV在工厂里跑，既要稳又要准，还要能躲障碍。PID说白了就是个“事后诸葛亮”，出了问题才调整。而LQR和MPC，是“事前诸葛亮”，提前算好最优路径。纯跟踪呢，更像是个“老司机”，盯着前方的路，不断修正方向盘。

好，咱们一个一个来拆解。

1.1 LQR控制器设计——从“拍脑袋”到“算最优”

LQR，全称Linear Quadratic Regulator，线性二次型调节器。名字听着唬人，其实核心思想就一句话：在满足约束的前提下，找一个控制量，让系统状态尽可能接近目标，同时控制量别太大。

我在项目中遇到过这样一个场景：AGV在狭窄通道里高速行驶，PID调了半天，要么超调撞墙，要么响应太慢。后来换成LQR，效果立竿见影。为什么？因为LQR把“状态偏差”和“控制能量”都量化成了代价函数，然后通过求解Riccati方程，找到最优的反馈增益矩阵K。

咱们来看一个典型的离散LQR设计流程：

// 系统模型：x(k+1) = A*x(k) + B*u(k)
// 代价函数：J = sum( x'*Q*x + u'*R*u )

// 1. 定义状态矩阵A和控制矩阵B
// 2. 定义权重矩阵Q（状态权重）和R（控制权重）
// 3. 调用MATLAB的dlqr()或Python的control.lqr()
// 4. 得到反馈增益K，控制律：u = -K*x

// 实际代码片段（Python）：
import control as ct
A = np.array([[1, dt], [0, 1]])  // 位置-速度模型
B = np.array([[0], [dt]])
Q = np.diag([10, 1])  // 位置偏差权重10，速度偏差权重1
R = np.array([[0.1]])  // 控制量权重0.1
K, S, E = ct.dlqr(A, B, Q, R)
print("反馈增益K:", K)
避坑指南：我曾经在调LQR时，Q矩阵设得太大，结果控制量剧烈抖动，电机直接过热保护。记住：Q越大，系统越“激进”；R越大，系统越“保守”。实际调试时，建议先固定R，从小到大调Q的对角线元素。

LQR的优点是计算量小，适合嵌入式实时控制。但缺点也很明显——它假设系统是线性的。AGV的轮胎摩擦、电机饱和，都是非线性。所以LQR更适合做“底层稳定控制”，比如保持AGV直线行驶。

1.2 模型预测控制（MPC）入门——看得更远，算得更准

如果说LQR是“近视眼”，那MPC就是“远视眼”。MPC的核心思想是：在每个控制周期，基于当前状态，预测未来N步的系统行为，然后求解一个带约束的最优化问题，只执行第一步，下个周期再重新算。

说白了，MPC就是“走一步看三步”。我当年第一次在AGV上跑MPC时，最头疼的就是计算量。嵌入式芯片算力有限，一个优化问题要解几十毫秒，控制周期都过了。后来用了快速MPC（Fast MPC）和显式MPC（Explicit MPC），才把计算时间压到5ms以内。

MPC的典型流程：

  1. 预测模型：用状态空间方程预测未来N步的状态
  2. 约束处理：速度上限、加速度上限、转向角限制
  3. 优化求解：最小化预测轨迹与参考轨迹的偏差，同时考虑控制量变化
  4. 滚动时域：只执行第一个控制量，下一周期重新预测
// MPC核心伪代码（简化版）
for each control cycle:
    // 1. 获取当前状态 x0
    // 2. 构建预测矩阵 Phi 和 Gamma
    // 3. 构建QP问题：min 0.5*u'*H*u + f'*u
    //    约束：lb <= u <= ub
    // 4. 调用QP求解器（如OSQP、qpOASES）
    // 5. 取u[0]作为控制输出
    // 6. 等待下一个周期
注意：MPC的预测时域N不能太大。N越大，计算量呈指数增长。我建议N取10~20步，步长0.1秒，预测未来1~2秒就够了。另外，QP求解器一定要选嵌入式友好的，比如OSQP或CVXGEN。

MPC最大的优势是能处理约束。比如AGV前方有障碍物，MPC可以自动规划一条绕行轨迹，同时保证不超速、不侧滑。但代价就是——代码复杂，调试困难。我见过不少团队，MPC调了三个月还没上路，最后换回纯跟踪。

1.3 纯跟踪（Pure Pursuit）路径跟踪——简单粗暴，但有效

纯跟踪，名字很形象——就像你开车时盯着前方一个点，然后打方向盘去追那个点。这个“点”叫前视点（Look-ahead Point），距离车头L米。算法逻辑极其简单：

  1. 在参考路径上，找到距离AGV当前位置最近的点
  2. 从这个点向前延伸L米，得到前视点
  3. 计算AGV当前位置到前视点的圆弧曲率
  4. 根据曲率计算转向角

纯跟踪的公式就一行：

// 转向角 delta = atan2(2 * L * sin(alpha), Ld)
// 其中：
//   Ld - 前视距离
//   alpha - AGV航向与前视点方向的夹角
//   L - AGV轴距

// 实际代码（C语言）：
float pure_pursuit(float ref_x, float ref_y, float lookahead_dist) {
    float dx = ref_x - vehicle_x;
    float dy = ref_y - vehicle_y;
    float alpha = atan2(dy, dx) - vehicle_yaw;
    float delta = atan2(2.0f * wheelbase * sin(alpha), lookahead_dist);
    return delta;
}
核心参数：前视距离Ld
Ld越大，路径越平滑，但转弯会“切内线”；Ld越小，跟踪越精确，但容易震荡。我个人的经验是：Ld取车速的0.5~1.0倍。比如车速1m/s，Ld取0.5~1.0米。低速时Ld小一点，高速时Ld大一点。

纯跟踪的优点：代码量少（不到50行）、计算量极小（微秒级）、不需要系统模型。缺点：无法处理约束，遇到急弯容易“冲出跑道”。所以纯跟踪更适合做“上层路径跟踪”，配合底层PID或LQR使用。

1.4 三种算法的对比与选型

为了让大家一目了然，我整理了一个对比表：

特性 LQR MPC 纯跟踪
计算量 低（微秒级） 高（毫秒级） 极低（微秒级）
是否需要模型 需要线性模型 需要模型（可非线性） 不需要
约束处理 不能 能（核心优势） 不能
适用场景 底层稳定控制 复杂轨迹跟踪+避障 简单路径跟踪
调试难度 中等（调Q/R矩阵） 高（调预测时域、权重） 低（调前视距离）

我个人建议的选型策略：

  • 简单场景（直线、大半径弯道）：纯跟踪 + PID，够用
  • 中等场景（S弯、变速）：LQR做底层，纯跟踪做上层
  • 复杂场景（密集障碍、狭窄通道）：MPC，虽然难调，但效果最好

1.6 实战中的一些碎碎念

最后，分享几个我在项目里踩过的坑：

  • LQR的Q矩阵别乱调：我曾经把位置权重设成100，速度权重设成1，结果AGV一启动就猛加速，差点撞墙。记住：Q矩阵的对角线元素，代表你对各个状态的“重视程度”，要按物理意义来设。
  • MPC的求解器要选对：别在STM32上跑MATLAB生成的MPC代码，算力不够。推荐用OSQP或CVXGEN，专门为嵌入式优化的。
  • 纯跟踪的前视距离要动态调整：固定前视距离在低速时还行，高速时容易震荡。我一般用公式：Ld = k * v + Ld_min，其中k取0.5~1.0，Ld_min取0.3米。
