15 上位机与HMI开发：Qt/C++上位机框架、串口/网络通信、实时数据显示、远程控制指令下发

说到AGV的上位机开发，我个人觉得这是整个系统里最「看得见摸得着」的部分。你想想看，底层控制写得再好，如果上位机界面卡顿、数据延迟、指令发不出去，那客户第一印象就崩了。我这些年带项目，踩过不少坑，今天就把Qt/C++做AGV上位机的核心套路掰开揉碎讲给你听。

15.1 为什么选Qt/C++？

其实市面上能做上位机的框架不少，C#、Python都有。但我个人习惯用Qt/C++，原因有三：

  • 跨平台：Windows调试、Linux部署，一套代码搞定。我在现场遇到过客户突然要换工控机系统，Qt直接重新编译就行，不用重写。
  • 性能硬核：AGV实时数据刷新频率高，C++底层操作内存，延迟可控。用Python做实时曲线，数据量一大就容易卡顿。
  • 生态成熟：Qt的串口类QSerialPort、网络类QTcpSocket都是现成的，省去自己封装协议的时间。

核心观点：上位机不是「能显示数据就行」，而是要稳定、低延迟、易维护。Qt/C++在这三点上平衡得最好。

15.3 串口通信实战

AGV和上位机最常用的物理连接就是串口。别觉得串口老，工业现场它最可靠。Qt里用QSerialPort，代码其实很简洁：

// 串口初始化
QSerialPort *serial = new QSerialPort(this);
serial->setPortName("COM3");
serial->setBaudRate(QSerialPort::Baud115200);
serial->setDataBits(QSerialPort::Data8);
serial->setParity(QSerialPort::NoParity);
serial->setStopBits(QSerialPort::OneStop);

if (serial->open(QIODevice::ReadWrite)) {
    qDebug() << "串口打开成功";
} else {
    qDebug() << "串口打开失败:" << serial->errorString();
}

// 接收数据（信号槽方式）
connect(serial, &QSerialPort::readyRead, this, [=]() {
    QByteArray data = serial->readAll();
    // 这里做协议解析
    parseAGVData(data);
});

避坑指南：我曾经在项目里直接用readAll()，结果数据量大时粘包严重。后来改成按协议帧头帧尾做缓存解析，才稳定下来。建议你定义一个环形缓冲区，逐字节处理。

15.4 网络通信（TCP）

当AGV数量多、距离远时，串口就不够用了。这时候得上TCP。Qt的QTcpSocket用起来跟串口很像，但多了个连接管理：

// TCP客户端
QTcpSocket *tcpSocket = new QTcpSocket(this);
tcpSocket->connectToHost("192.168.1.100", 8080);

if (tcpSocket->waitForConnected(3000)) {
    qDebug() << "TCP连接成功";
} else {
    qDebug() << "连接超时";
}

// 发送指令
QByteArray cmd = buildCommand("MOVE", 100, 200);
tcpSocket->write(cmd);

// 接收数据
connect(tcpSocket, &QTcpSocket::readyRead, this, [=]() {
    QByteArray data = tcpSocket->readAll();
    processNetworkData(data);
});

这里有个细节：TCP是流式协议，没有消息边界。我建议你在应用层自己定义协议头，比如用4字节表示数据长度，这样接收方就能准确切分消息。

15.5 实时数据显示

AGV上位机最核心的界面就是实时数据面板。我一般用QTableWidget配合定时器刷新：

// 定时器刷新（50ms间隔）
QTimer *timer = new QTimer(this);
connect(timer, &QTimer::timeout, this, &MainWindow::updateDisplay);
timer->start(50);

void MainWindow::updateDisplay() {
    // 更新电池电量
    ui->batteryBar->setValue(currentData.battery);
    
    // 更新速度
    ui->speedLabel->setText(
        QString("速度: %1 m/s").arg(currentData.speed, 0, 'f', 2));
    
    // 更新坐标
    ui->posLabel->setText(
        QString("X: %1  Y: %2").arg(currentData.x).arg(currentData.y));
    
    // 更新状态指示灯
    if (currentData.status == ERROR) {
        ui->statusLed->setStyleSheet("background-color: red;");
    }
}

注意：UI刷新别放在数据接收线程里！Qt的UI操作必须在主线程。我见过有人直接在readyRead槽里更新界面，程序跑一会儿就崩溃。正确做法是用信号槽跨线程通信，或者用QMetaObject::invokeMethod。

15.6 远程控制指令下发

控制指令下发，说白了就是上位机给AGV发一串字节。但这里有个设计要点——指令要有确认机制。我常用的协议格式是这样的：

字段 长度 说明
帧头 2字节 0xAA 0x55
指令ID 1字节 0x01=启动, 0x02=停止, 0x03=设置速度
数据长度 2字节 后续数据字节数
数据体 N字节 具体参数
校验 1字节 异或校验
帧尾 2字节 0x0D 0x0A

指令下发代码示例：

void MainWindow::sendCommand(quint8 cmdId, QByteArray params) {
    QByteArray frame;
    frame.append(0xAA);
    frame.append(0x55);
    frame.append(cmdId);
    
    quint16 len = params.size();
    frame.append((len >> 8) & 0xFF);
    frame.append(len & 0xFF);
    frame.append(params);
    
    // 异或校验
    quint8 checksum = 0;
    for (int i = 0; i < frame.size(); i++) {
        checksum ^= frame[i];
    }
    frame.append(checksum);
    frame.append(0x0D);
    frame.append(0x0A);
    
    // 发送
    if (serial->isOpen()) {
        serial->write(frame);
    } else if (tcpSocket->state() == QAbstractSocket::ConnectedState) {
        tcpSocket->write(frame);
    }
}

经验之谈：指令下发后一定要等AGV回复ACK。我遇到过无线网络丢包，指令发了但AGV没收到，结果车还在原地不动。后来加了超时重发机制，3秒没收到ACK就重发，最多重试3次。

15.7 日志与调试

最后说个容易被忽略的点——日志系统。AGV跑起来后，上位机要记录所有收发数据、状态变化、异常事件。我习惯用qInstallMessageHandler重定向日志到文件：

void customMessageHandler(QtMsgType type, const QMessageLogContext &ctx, const QString &msg) {
    QFile file("agv_log.txt");
    if (file.open(QIODevice::Append)) {
        QTextStream stream(&file);
        stream << QDateTime::currentDateTime().toString("yyyy-MM-dd hh:mm:ss.zzz") << " ";
        stream << msg << "\n";
        file.close();
    }
}

// 在main函数中安装
int main(int argc, char *argv[]) {
    qInstallMessageHandler(customMessageHandler);
    QApplication app(argc, argv);
    // ...
}

有了日志，现场出问题才能快速定位。我曾经靠日志里的时间戳，发现某次指令延迟是因为串口缓冲区满了，后来加了流量控制才解决。

好了，上位机开发这块核心内容就这些。Qt/C++做AGV上位机，说白了就是「通信+显示+控制」三个环。把每一层拆开做，别混在一起，后面维护起来你会感谢自己的。
