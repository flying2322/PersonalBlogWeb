25 项目实战：仓储AGV（三）：导航与定位算法部署、地图构建

好，咱们接着往下走。前两章我们把硬件搭起来了，底层驱动也调通了。现在要动真格的了——导航与定位算法部署，还有地图构建。

说实话，这部分是AGV的灵魂。没有好的定位，车就是瞎跑。没有好的地图，定位也无从谈起。我当年第一次做仓储项目时，就吃过这个亏——地图建得马马虎虎，结果车子在货架间来回撞，差点把客户的货给怼翻了。嗯，从那以后，我对地图构建和定位算法就格外较真。

25.1 导航与定位的整体架构

先看整体。导航定位系统，说白了就是三个模块：传感器输入、定位引擎、路径规划输出。

我个人习惯把架构画成下面这样，你一看就明白：

你看，传感器数据进来，定位引擎算出位姿，然后规划层给出控制指令。同时地图模块和定位引擎是双向的——地图帮定位，定位反过来更新地图。这就是SLAM的核心思想。

25.2 地图构建：从激光数据到栅格地图

仓储AGV最常用的地图形式是栅格地图。每个格子代表一小块区域，值表示这个格子被占用的概率。

我一般用0到100表示概率。0代表完全空闲，100代表完全占用，50代表未知。你想想看，这样处理起来多直观。

核心公式：栅格地图的更新基于贝叶斯公式。简单说就是：

新概率 = 旧概率 × 传感器模型

每次激光扫描回来，我们就更新经过的格子。扫到障碍物的格子概率升高，扫到空闲区域的格子概率降低。

代码实现上，我习惯这样写：

// 栅格地图更新函数
void updateGridMap(GridMap* map, LaserScan* scan, Pose robot_pose) {
    // 1. 将激光点从传感器坐标系转换到世界坐标系
    for (int i = 0; i < scan->num_points; i++) {
        float angle = robot_pose.theta + scan->angles[i];
        float range = scan->ranges[i];
        
        // 跳过无效点
        if (range < MIN_RANGE || range > MAX_RANGE) continue;
        
        // 计算激光点在世界坐标系中的位置
        float world_x = robot_pose.x + range * cos(angle);
        float world_y = robot_pose.y + range * sin(angle);
        
        // 2. 更新障碍物格子
        int grid_x, grid_y;
        worldToGrid(map, world_x, world_y, &grid_x, &grid_y);
        if (isValidGrid(map, grid_x, grid_y)) {
            // 增加占用概率
            map->cells[grid_x][grid_y] += OCCUPIED_INC;
            if (map->cells[grid_x][grid_y] > 100) 
                map->cells[grid_x][grid_y] = 100;
        }
        
        // 3. 更新射线经过的空闲格子
        // 从机器人位置到激光点做Bresenham直线
        int robot_gx, robot_gy;
        worldToGrid(map, robot_pose.x, robot_pose.y, &robot_gx, &robot_gy);
        
        // Bresenham算法遍历路径上的格子
        bresenhamLine(map, robot_gx, robot_gy, grid_x, grid_y, 
                      FREE_DEC, &updateFreeCell);
    }
}

实战小技巧：我在项目中遇到过一个问题——激光雷达的噪声会导致地图出现很多"鬼影"。后来我加了一个中值滤波，效果立竿见影。另外，更新概率时不要一步到位，用增量更新更稳健。

25.3 定位算法部署：粒子滤波实战

定位算法我首推粒子滤波，也就是AMCL（自适应蒙特卡洛定位）。为什么？因为它能处理非高斯分布，而且实现起来相对直观。

粒子滤波的核心思想很简单：用一堆粒子来猜测机器人的位置。每个粒子代表一个可能的位姿，粒子越密集的地方，机器人越可能在那里。

算法流程分四步：

  1. 初始化：在已知地图上撒粒子。如果不知道初始位置，就全图均匀撒。
  2. 预测：根据里程计数据，让每个粒子移动。加入噪声模拟不确定性。
  3. 更新：用激光扫描数据计算每个粒子的权重。匹配度高的粒子权重大。
  4. 重采样：根据权重重新抽取粒子。权重高的粒子被复制，权重低的被淘汰。

我当年第一次部署粒子滤波时，遇到一个坑——粒子数量设得太少，定位精度不够；设得太多，CPU扛不住。后来我用了自适应策略：定位稳定时减少粒子，遇到绑架或丢失时增加粒子。

// 粒子滤波核心循环
void particleFilterUpdate(ParticleFilter* pf, Odometry* odom, LaserScan* scan) {
    // 1. 预测阶段：根据里程计移动粒子
    for (int i = 0; i < pf->num_particles; i++) {
        // 加入高斯噪声模拟里程计误差
        float noise_x = gaussianRandom(0, ODOM_NOISE_XY);
        float noise_y = gaussianRandom(0, ODOM_NOISE_XY);
        float noise_theta = gaussianRandom(0, ODOM_NOISE_THETA);
        
        pf->particles[i].pose.x += odom->dx + noise_x;
        pf->particles[i].pose.y += odom->dy + noise_y;
        pf->particles[i].pose.theta += odom->dtheta + noise_theta;
    }
    
    // 2. 更新阶段：计算每个粒子的权重
    float total_weight = 0;
    for (int i = 0; i < pf->num_particles; i++) {
        // 用激光扫描与地图的匹配度计算权重
        pf->particles[i].weight = 
            computeLikelihood(pf->map, scan, pf->particles[i].pose);
        total_weight += pf->particles[i].weight;
    }
    
    // 3. 重采样阶段
    if (total_weight > 0) {
        resampleParticles(pf, total_weight);
    }
    
    // 4. 估计最终位姿（加权平均）
    estimatePose(pf);
}

注意：重采样不能每次都做。我建议设置一个阈值——当有效粒子数低于总粒子数的一半时，才触发重采样。否则粒子会快速退化，全部集中到一个点上，失去多样性。

25.4 部署到嵌入式平台

好了，算法讲完了。但算法再好，跑不到板子上也是白搭。嵌入式部署有几个关键点：

资源 建议配置 我的经验
CPU ARM Cortex-A72 以上 粒子数控制在500-1000，否则帧率掉到10Hz以下
内存 ≥512MB 地图10m×10m，分辨率5cm，约4万个格子，够用
激光雷达 360° 2D LiDAR 我用过RPLIDAR和思岚的，性价比不错
操作系统 Linux + RT补丁 裸机跑也可以，但调试起来太痛苦

部署时我习惯把定位和建图拆成两个线程。定位线程跑高频（20-30Hz），建图线程跑低频（1-2Hz）。这样既保证了实时性，又不会把CPU吃满。

避坑指南：我曾经在STM32上硬跑粒子滤波，结果发现浮点运算慢得离谱。后来改用定点数，速度提升了3倍。如果你用MCU，记得把浮点运算换成定点或者查表法。

25.5 调试与验证

算法部署完，怎么知道它跑对了？我一般用三个方法验证：

  • 回放测试：录一段真实数据，离线跑算法，看定位轨迹是否平滑。
  • 闭环检测：让AGV走一圈回到起点，看定位误差是否累积。
  • 人工推车：推着AGV走，观察地图是否和实际环境一致。

我记得有一次，回放测试时定位轨迹一直在漂。查了两天才发现——编码器标定参数错了，导致里程计误差被放大。所以啊，传感器标定是基础，基础不牢，地动山摇。
