4 基础驱动开发：GPIO与定时器

各位同学，今天咱们聊聊AGV控制器开发中最基础、也最绕不开的一环——GPIO和定时器。说实话，很多新手一上来就急着调运动控制、搞路径规划，结果连个LED都点不亮，编码器脉冲也读不准。我当年带项目时就吃过这个亏，后来老老实实把底层驱动打磨扎实了，上层应用才跑得顺。

这一章，我会带着大家把GPIO初始化、中断配置、定时器PWM生成、编码器脉冲捕获，还有SysTick系统时钟，一个一个啃下来。别急，咱们慢慢来。

1. GPIO初始化与中断

GPIO，说白了就是芯片的“手脚”。你要让AGV的电机驱动板知道“往前走”，或者让传感器告诉芯片“我检测到障碍物了”，都得靠GPIO。

我个人习惯，写GPIO驱动时先画个表格，把每个引脚的功能、方向、默认电平列清楚。不然项目一复杂，引脚复用起来容易乱。

引脚 功能 方向 默认电平
PA0 急停按钮输入 输入 上拉高
PB1 电机使能输出 输出 低
PC2 编码器A相 输入 浮空

初始化代码其实很固定，我一般这样写：

void GPIO_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    // 使能时钟
    __HAL_RCC_GPIOA_CLK_ENABLE();
    __HAL_RCC_GPIOB_CLK_ENABLE();

    // 配置PA0为输入，上拉
    GPIO_InitStruct.Pin = GPIO_PIN_0;
    GPIO_InitStruct.Mode = GPIO_MODE_INPUT;
    GPIO_InitStruct.Pull = GPIO_PULLUP;
    HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);

    // 配置PB1为输出，推挽
    GPIO_InitStruct.Pin = GPIO_PIN_1;
    GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
    GPIO_InitStruct.Pull = GPIO_NOPULL;
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
}
小技巧： 初始化时把不用的引脚也设成模拟输入或上拉输入，能省电，还能抗干扰。我在AGV项目里吃过亏，有个引脚悬空，结果半夜自己触发中断，AGV自己跑起来了……后来加了内部上拉才解决。

GPIO中断配置

中断，就是让芯片“放下手里的活，先来处理紧急事件”。比如急停按钮按下，必须立刻停车。

配置中断分三步：

  1. 设置GPIO为中断模式（上升沿、下降沿或双边沿触发）
  2. 配置NVIC（嵌套向量中断控制器）优先级
  3. 编写中断服务函数
void GPIO_Interrupt_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    __HAL_RCC_GPIOA_CLK_ENABLE();

    GPIO_InitStruct.Pin = GPIO_PIN_0;
    GPIO_InitStruct.Mode = GPIO_MODE_IT_FALLING; // 下降沿触发
    GPIO_InitStruct.Pull = GPIO_PULLUP;
    HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);

    // 配置NVIC
    HAL_NVIC_SetPriority(EXTI0_IRQn, 0, 0);
    HAL_NVIC_EnableIRQ(EXTI0_IRQn);
}

// 中断服务函数
void EXTI0_IRQHandler(void)
{
    if(__HAL_GPIO_EXTI_GET_IT(GPIO_PIN_0) != RESET)
    {
        // 急停！立刻停车
        Motor_Stop();
        __HAL_GPIO_EXTI_CLEAR_IT(GPIO_PIN_0);
    }
}
注意： 中断服务函数里不要做复杂运算，更不要调用HAL_Delay()这类阻塞函数。我曾经见过有人在中端里打印日志，结果系统直接卡死。中断里只做标志位设置，具体处理放到主循环。

2. 定时器PWM生成

AGV的电机调速，靠的就是PWM（脉宽调制）。说白了，就是让电压快速开关，通过占空比控制平均电压，从而控制电机转速。

我一般用通用定时器（比如TIM2、TIM3）来生成PWM。配置要点：

  • 设置预分频器（PSC）和自动重装载值（ARR）决定PWM频率
  • 设置比较值（CCR）决定占空比
  • 选择PWM模式1或模式2
void PWM_Init(void)
{
    TIM_HandleTypeDef htim2;
    TIM_OC_InitTypeDef sConfigOC = {0};

    __HAL_RCC_TIM2_CLK_ENABLE();

    htim2.Instance = TIM2;
    htim2.Init.Prescaler = 84 - 1;      // 84MHz / 84 = 1MHz
    htim2.Init.Period = 1000 - 1;       // 1MHz / 1000 = 1kHz
    htim2.Init.CounterMode = TIM_COUNTERMODE_UP;
    HAL_TIM_PWM_Init(&htim2);

    sConfigOC.OCMode = TIM_OCMODE_PWM1;
    sConfigOC.Pulse = 500;              // 50%占空比
    sConfigOC.OCPolarity = TIM_OCPOLARITY_HIGH;
    HAL_TIM_PWM_ConfigChannel(&htim2, &sConfigOC, TIM_CHANNEL_1);

    HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_1);
}
核心要点： PWM频率不能太低，否则电机会发出嗡嗡声；也不能太高，否则MOS管开关损耗大。AGV电机一般用10kHz~20kHz，我习惯用16kHz，人耳不太敏感。

3. 编码器脉冲捕获

AGV要知道自己走了多远、速度多快，靠的就是编码器。增量式编码器输出两路相位差90°的脉冲（A相和B相），通过捕获这两路脉冲，就能算出位置和方向。

我推荐用定时器的编码器模式，硬件自动处理，省CPU资源。配置如下：

void Encoder_Init(void)
{
    TIM_HandleTypeDef htim3;

    __HAL_RCC_TIM3_CLK_ENABLE();

    htim3.Instance = TIM3;
    htim3.Init.Prescaler = 0;           // 不分频
    htim3.Init.Period = 0xFFFF;         // 最大计数值
    htim3.Init.CounterMode = TIM_COUNTERMODE_UP;
    HAL_TIM_Encoder_Init(&htim3, &sEncoderConfig);

    // 编码器配置
    sEncoderConfig.EncoderMode = TIM_ENCODERMODE_TI12; // 双沿捕获
    sEncoderConfig.IC1Polarity = TIM_ICPOLARITY_RISING;
    sEncoderConfig.IC2Polarity = TIM_ICPOLARITY_RISING;
    HAL_TIM_Encoder_Init(&htim3, &sEncoderConfig);

    HAL_TIM_Encoder_Start(&htim3, TIM_CHANNEL_ALL);
}

// 读取编码器值
int32_t Get_Encoder_Count(void)
{
    return (int16_t)__HAL_TIM_GET_COUNTER(&htim3);
}
避坑指南： 我曾经遇到过编码器计数跳变的问题，查了半天发现是信号线没加滤波电容。编码器脉冲频率高，线长一点就容易受干扰。建议在硬件上加RC滤波，软件里也可以做消抖处理。

4. SysTick系统时钟

SysTick是ARM Cortex-M内核自带的24位递减定时器，专门用来产生系统滴答中断。HAL库里的HAL_Delay()、各种超时判断，都靠它。

配置其实很简单，HAL库在初始化时已经帮我们做好了。但我想强调的是：SysTick的优先级一定要设得合适。设太高，会影响其他实时任务；设太低，HAL_Delay()会不准。

// HAL库默认配置，一般在SystemClock_Config()里调用
HAL_SYSTICK_Config(HAL_RCC_GetHCLKFreq() / 1000); // 1ms中断一次
HAL_SYSTICK_CLKSourceConfig(SYSTICK_CLKSOURCE_HCLK);
HAL_NVIC_SetPriority(SysTick_IRQn, 15, 0); // 最低优先级
注意： 不要在中断里调用HAL_Delay()！因为HAL_Delay()依赖SysTick中断，而SysTick中断优先级可能比当前中断低，导致死锁。我见过有人踩了这个坑，调试了一整天。

知识体系总览

下面这张图，是我自己总结的本章知识结构。你可以把它当成一张地图，学完后再回来看，会更有感觉。

这张图里，GPIO和定时器是基础中的基础。编码器依赖定时器的捕获功能，SysTick则是一个特殊的定时器。把这四个模块吃透了，AGV的底层驱动你就掌握了七成。

总结一下：

  • GPIO：芯片的“手脚”，输入输出加中断
  • 定时器PWM：电机调速的核心，频率和占空比要算准
  • 编码器捕获：AGV的“眼睛”，知道位置和速度
  • SysTick：系统的“心跳”，一切延时和超时的基准
