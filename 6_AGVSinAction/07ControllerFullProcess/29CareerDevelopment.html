29 职业发展：AGV工程师技能树、面试常见问题、开源项目贡献指南

做AGV控制器开发这些年，我带过不少新人，也面试过上百号人。很多人问我：到底怎么才算一个合格的AGV工程师？今天我就把压箱底的经验掏出来，跟你聊聊这个职业的成长路径。

说白了，AGV工程师是个“杂家”。你得懂硬件，也得会写代码，还得能调算法。我见过太多人只盯着一个点死磕，结果项目里一遇到跨领域的问题就抓瞎。嗯，咱们今天就把这事掰扯清楚。

核心观点：AGV工程师不是“码农”，也不是“硬件工”，而是一个系统集成者。你的价值在于让轮子转起来，并且转得稳、转得准。

一、AGV工程师技能树

我把技能树分成三个层次：地基、支柱、塔尖。你想想看，盖楼是不是也得这么来？

1. 地基层：硬核基础

  • 嵌入式C/C++：这是吃饭的家伙。我面试时必问指针和内存管理，能答透的人不多。
  • 实时操作系统（RTOS）：FreeRTOS、RT-Thread至少精通一个。任务调度、信号量、消息队列，这些是基本功。
  • 电机控制原理：直流有刷、无刷、步进，你得知道它们的脾气。PID调参是入门，但能调好的人真不多。
  • 传感器接口：编码器、IMU、激光雷达、超声波。I2C、SPI、UART、CAN，这些总线你得玩得转。

我的经验：刚入行时，我花了大半年死磕FreeRTOS的任务优先级设计。有一次因为优先级反转，AGV在转弯时直接撞墙。从那以后，我对RTOS的调度机制再也不敢马虎。

2. 支柱层：核心算法

  • 运动控制：差速模型、阿克曼模型、全向轮模型。你得能从数学上推导出轮子转速和车身速度的关系。
  • 路径规划：A*、Dijkstra、RRT。别只会调库，要能手撕伪代码。
  • 定位与建图：卡尔曼滤波、粒子滤波、ICP匹配。我建议从一维卡尔曼滤波开始学，别一上来就搞SLAM。
  • 避障策略：DWA（动态窗口法）、VFH（向量场直方图）。这些算法在ROS里都有现成的，但你要理解背后的代价函数设计。

3. 塔尖层：系统思维

  • 软硬件协同设计：选型时，MCU的算力、内存、外设资源要跟算法需求匹配。我曾经因为选了颗低端MCU，导致路径规划跑不动，最后只能降级算法。
  • 调试与排障：逻辑分析仪、示波器、串口打印，这些工具要熟练。我习惯在关键节点加调试灯，一眼就能看出程序卡在哪。
  • 项目管理：Git版本控制、需求文档、测试用例。别觉得这些是“虚的”，项目一复杂，没有规范就是灾难。

二、面试常见问题

我面试过很多人，也被人面试过。总结下来，AGV岗位的面试题其实有套路。我把它分成三类：基础题、算法题、场景题。

1. 基础题（必考）

问题 考察点 我的建议
指针和引用的区别？ C++基础 别只背概念，要能说出底层实现
FreeRTOS任务栈大小怎么估算？ RTOS实战 我习惯先给个保守值，再通过调试工具实测
PID参数怎么调？ 控制理论 先P后I再D，但要注意积分饱和
CAN总线仲裁机制？ 通信协议 按优先级逐位仲裁，ID越小优先级越高

2. 算法题（核心）

  • 手撕A*算法：别只写伪代码，要能写出完整的C实现。包括open list、close list的管理，启发式函数的选择。
  • 卡尔曼滤波推导：从状态预测到观测更新，五个公式要能默写。我面试时会让候选人画信息流图。
  • 差速模型正逆解：给定左右轮速度，求车体线速度和角速度。反过来也要会。

避坑指南：我曾经面试过一个候选人，简历上写着“精通SLAM”。我问了他一个简单问题：激光雷达数据怎么做畸变校正？他支支吾吾答不上来。所以，别在简历上写“精通”，除非你真的能扛住追问。

3. 场景题（拉差距）

  • 场景一：AGV在仓库里突然原地打转，可能是什么原因？——编码器故障、轮子打滑、IMU漂移，你得能列出排查清单。
  • 场景二：两辆AGV在窄通道相遇，怎么避免死锁？——交通管制、优先级调度、预留路径，这些都是考点。
  • 场景三：电池电量低时，AGV应该怎么处理？——降速运行、就近充电、任务重分配，要能说出完整的策略。

三、开源项目贡献指南

说实话，我入行时最大的成长来自读开源代码。ROS Navigation Stack、Cartographer、TEB Local Planner，这些项目我都啃过。你想想看，能跟全球顶尖工程师学写代码，这机会多难得？

1. 怎么选项目？

  • 入门级：Arduino的AGV小车项目、SimpleFOC（无刷电机控制）。代码量小，适合练手。
  • 进阶级：ROS Navigation Stack、move_base。代码量大，但文档齐全。
  • 骨灰级：Autoware（自动驾驶）、PX4（无人机飞控）。这些是工业级项目，能啃下来就是大神。

2. 怎么读代码？

我个人的习惯是“三遍法”：

  1. 第一遍：跑起来。先编译、安装、跑demo，看效果。
  2. 第二遍：画流程。把main函数到核心算法的调用链画出来。
  3. 第三遍：改代码。改一个参数，看效果变化。改一个逻辑，看会不会崩。

我的经验：读ROS Navigation的costmap_2d时，我花了整整两周才搞懂膨胀层的实现。但搞懂之后，我对路径规划的避障逻辑豁然开朗。值！

3. 怎么贡献？

  • 从文档开始：修一个typo、补一个注释，这是最友好的入门方式。
  • 修小bug：在issue里找“good first issue”标签，从简单的开始。
  • 提PR的规范：代码风格要一致、commit message要清晰、测试要覆盖。我见过太多PR因为格式问题被驳回。
// 一个规范的commit message示例

// 详细说明（72字换行）

// 3. 有什么副作用

注意：别一上来就提大PR。我见过有人提交了3000行代码的PR，结果review了两个月还没合并。从小处着手，建立信任，再逐步深入。

好了，关于职业发展这块，我就聊这么多。技能树要慢慢点，面试要提前准备，开源项目要持续贡献。这条路没有捷径，但每一步都算数。记住，AGV工程师的核心竞争力不是你会多少工具，而是你能解决多少实际问题。
