8 任务调度与实时性：FreeRTOS移植与任务创建、消息队列与信号量、任务优先级设计、看门狗与异常处理

AGV控制器，说白了就是一个“实时响应机器”。

车在跑，传感器在报数，电机在转，每一个环节都卡着时间点。你想想看，如果避障信号来了，但任务调度慢了半拍，车就撞上去了。所以，实时操作系统（RTOS）是AGV的灵魂。

我个人习惯用FreeRTOS。轻量、稳定、社区活跃。这一章，我们就把它移植到AGV主控上，然后聊聊任务怎么创建、怎么通信、优先级怎么定，最后再看门狗兜底。

8.1 FreeRTOS移植：从裸机到RTOS

移植FreeRTOS，其实没那么玄乎。核心就三步：

  • 准备一个心跳：FreeRTOS需要一个1ms的定时器中断，作为系统节拍。我一般用SysTick，省事。
  • 配置中断优先级：ARM Cortex-M系列有优先级分组，FreeRTOS要求最低4位用于抢占优先级。这个坑我踩过——优先级设错了，系统直接跑飞。
  • 修改FreeRTOSConfig.h：配置最大任务数、堆栈大小、时钟频率。别贪多，AGV场景下，8-10个任务足够了。

核心配置示例（FreeRTOSConfig.h）

#define configUSE_PREEMPTION          1
#define configCPU_CLOCK_HZ            ( ( unsigned long ) 168000000 )
#define configTICK_RATE_HZ            ( ( TickType_t ) 1000 )
#define configMAX_PRIORITIES          ( 5 )
#define configMINIMAL_STACK_SIZE      ( ( unsigned short ) 128 )
#define configTOTAL_HEAP_SIZE         ( ( size_t ) ( 40 * 1024 ) )

嗯，这里要注意：堆大小别设太大，AGV主控的RAM通常就64KB或128KB，留点余量给传感器数据缓存。

8.2 任务创建：让AGV“动”起来

任务就是一个个独立的小循环。我习惯把AGV拆成这几个任务：

  • 传感器采集任务：读取激光雷达、超声波、IMU数据，优先级最高。
  • 路径规划任务：根据地图和当前位置，计算下一步指令，优先级中等。
  • 电机控制任务：执行速度、转向指令，优先级高。
  • 通信任务：与上位机、调度系统交互，优先级低。
  • 看门狗喂狗任务：定时喂狗，优先级最低。

创建任务的API很简单：

TaskHandle_t xSensorTaskHandle = NULL;

void vSensorTask(void *pvParameters)
{
    for( ;; )
    {
        // 读取激光雷达数据
        ReadLidarData();
        // 发送到消息队列
        xQueueSend(xSensorQueue, &lidarData, portMAX_DELAY);
        // 10ms周期
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

// 在主函数中创建
xTaskCreate(vSensorTask, "Sensor", 256, NULL, 3, &xSensorTaskHandle);

我在项目中遇到过一个问题：任务堆栈给太小，跑着跑着就HardFault了。后来我统一给每个任务分配256字节堆栈，再也没出过事。你想想看，堆栈溢出这种bug，查起来真要命。

8.3 消息队列与信号量：任务间的“传话筒”

任务之间不能直接访问全局变量，否则会打架。FreeRTOS提供了两种机制：

消息队列

用于传递数据。比如传感器任务把数据塞进队列，路径规划任务从队列里取。我习惯用队列长度设为10，防止数据积压。

QueueHandle_t xSensorQueue;

// 创建队列
xSensorQueue = xQueueCreate(10, sizeof(LidarData_t));

// 发送（传感器任务）
xQueueSend(xSensorQueue, &lidarData, 0);

// 接收（路径规划任务）
xQueueReceive(xSensorQueue, &lidarData, portMAX_DELAY);

信号量

用于同步。比如电机控制任务等一个“启动信号”才开始转。二值信号量最常用。

SemaphoreHandle_t xMotorSemaphore;

// 创建
xMotorSemaphore = xSemaphoreCreateBinary();

// 给出信号（比如避障触发）
xSemaphoreGive(xMotorSemaphore);

// 等待信号（电机任务阻塞在这里）
xSemaphoreTake(xMotorSemaphore, portMAX_DELAY);

避坑指南：我曾经在中断服务函数里直接调用xQueueSend，结果系统卡死。后来才想起来，中断里要用xQueueSendFromISR。记住：带FromISR后缀的API才是中断安全的。

8.4 任务优先级设计：别让高优先级“饿死”低优先级

优先级设计是门艺术。我给AGV定了个原则：

  • 实时性要求高的任务：传感器、电机控制，优先级3-4。
  • 计算密集型任务：路径规划，优先级2。
  • 非实时任务：通信、日志、喂狗，优先级0-1。

但有个坑：如果高优先级任务一直不阻塞（比如死循环），低优先级任务永远得不到CPU。我见过一个项目，电机控制任务里用了while(1)轮询，结果通信任务直接“饿死”，上位机收不到数据。

解决办法：高优先级任务里加vTaskDelay，或者用信号量阻塞自己。让出CPU给低优先级任务。

警告：优先级反转是AGV的隐形杀手。比如低优先级任务拿了互斥锁，高优先级任务等锁，中间优先级任务抢了CPU，高优先级任务就被“饿死”了。解决方案：使用互斥量（带优先级继承）代替二值信号量。

8.5 看门狗与异常处理：最后的“安全网”

AGV在工厂里跑，万一程序卡死了怎么办？看门狗就是最后的防线。

我一般用独立看门狗（IWDG），超时时间设为2秒。然后在最低优先级任务里喂狗。为什么用最低优先级？因为如果高优先级任务卡死，低优先级任务也得不到CPU，看门狗就会复位系统。

// 初始化看门狗（STM32 HAL库）
void MX_IWDG_Init(void)
{
    hiwdg.Instance = IWDG;
    hiwdg.Init.Prescaler = IWDG_PRESCALER_64;
    hiwdg.Init.Reload = 1250;  // 约2秒超时
    HAL_IWDG_Init(&hiwdg);
}

// 喂狗任务（优先级0）
void vWatchdogTask(void *pvParameters)
{
    for( ;; )
    {
        HAL_IWDG_Refresh(&hiwdg);
        vTaskDelay(pdMS_TO_TICKS(500));  // 每500ms喂一次
    }
}

异常处理呢？我习惯在HardFault_Handler里记录错误信息到Flash，然后软复位。这样下次上电可以读取错误日志，定位问题。

void HardFault_Handler(void)
{
    // 保存错误现场到Flash
    SaveFaultInfoToFlash();
    // 软复位
    NVIC_SystemReset();
}

我的经验：看门狗不是万能的。如果硬件损坏（比如电机驱动器短路），看门狗复位也没用。所以AGV还得配硬件急停和电流检测。
