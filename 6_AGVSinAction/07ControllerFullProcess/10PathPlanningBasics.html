10 路径规划基础

各位同学，今天我们来聊聊AGV的「大脑」——路径规划。说实话，这是整个控制器开发中最有意思的部分，也是我当年踩坑最多的地方。

路径规划说白了就三件事：全局路径规划、局部路径规划、路径平滑。我习惯把它们比作「看地图」、「看路况」和「走稳当」。你想想看，光有地图不看路况会撞墙，光看路况不看地图会迷路，走起来还一抖一抖的，那用户体验得多差？

核心思路：全局规划找方向，局部规划避障碍，平滑处理保舒适。三者缺一不可。

10.1 全局路径规划：A*算法

A*算法，我愿称之为「路径规划界的瑞士军刀」。它结合了Dijkstra的完备性和贪心算法的效率，说白了就是既保证能找到路，又尽量少走弯路。

核心公式其实很简单：F = G + H。G是起点到当前点的实际代价，H是当前点到终点的估计代价。我当年第一次看这个公式时觉得「就这？」——后来才发现，真正的坑全在H函数的设计上。

我的经验：H函数用欧几里得距离还是曼哈顿距离，直接影响搜索效率。在AGV场景下，我建议用对角线距离，因为它更符合AGV的运动特性。我曾经在一个仓库项目里用曼哈顿距离，结果搜索节点多了30%，后来换成对角线距离，速度直接起飞。

来看一个简化版的A*实现：

// A* 核心逻辑（C语言风格伪代码）
typedef struct {
    int x, y;
    float g, h, f;
    Node* parent;
} Node;

Node* a_star_search(GridMap* map, Node* start, Node* goal) {
    open_list.push(start);
    start->g = 0;
    start->h = heuristic(start, goal);  // 对角线距离
    start->f = start->g + start->h;
    
    while (!open_list.empty()) {
        Node* current = open_list.pop_min_f();  // 取f值最小的节点
        
        if (current == goal) {
            return reconstruct_path(current);  // 回溯路径
        }
        
        closed_list.push(current);
        
        // 遍历8个邻居
        for (int i = 0; i < 8; i++) {
            Node* neighbor = get_neighbor(map, current, i);
            if (!neighbor || closed_list.contains(neighbor)) continue;
            if (!is_walkable(map, neighbor)) continue;
            
            float tentative_g = current->g + distance(current, neighbor);
            
            if (!open_list.contains(neighbor)) {
                neighbor->g = tentative_g;
                neighbor->h = heuristic(neighbor, goal);
                neighbor->f = neighbor->g + neighbor->h;
                neighbor->parent = current;
                open_list.push(neighbor);
            } else if (tentative_g < neighbor->g) {
                // 找到更优路径，更新
                neighbor->g = tentative_g;
                neighbor->f = neighbor->g + neighbor->h;
                neighbor->parent = current;
            }
        }
    }
    return NULL;  // 无路可走
}

避坑指南：我曾经在一个密集货架仓库里，A*跑出来的路径贴着障碍物边缘走，AGV稍微有点定位误差就撞上了。后来我加了障碍物膨胀层——把障碍物边界向外扩展半个车宽。嗯，从此再没出过碰撞事故。

10.2 局部路径规划：DWA算法

全局路径规划完了，是不是就万事大吉了？当然不是。你想想看，地图是静态的，但实际环境里可能有临时障碍物、有人走动、有叉车经过。这时候就需要DWA（动态窗口法）上场了。

DWA的核心思想其实很朴素：在速度空间里采样，找一条能走、走得快、还不撞墙的轨迹。我习惯把它理解成「在方向盘和油门之间找平衡」。

DWA的步骤就三步：

  1. 速度采样：在当前速度附近，生成一组候选速度对 (v, ω)
  2. 轨迹预测：对每个速度对，模拟未来一段时间的运动轨迹
  3. 轨迹评价：用评价函数给每条轨迹打分，选最好的

评价函数通常长这样：

// DWA 评价函数
float evaluate_trajectory(Trajectory* traj, Node* goal, ObstacleList* obstacles) {
    float heading_cost = calc_heading_cost(traj, goal);     // 朝向目标
    float clearance_cost = calc_clearance_cost(traj, obstacles); // 避障
    float velocity_cost = calc_velocity_cost(traj);         // 速度奖励
    
    // 加权求和，权重系数需要调参
    return alpha * heading_cost + beta * clearance_cost + gamma * velocity_cost;
}

调参心得：alpha、beta、gamma这三个权重，我调了整整两周才找到感觉。alpha太大，AGV会直愣愣冲向目标，不管障碍物；beta太大，AGV会绕远路，像个胆小鬼；gamma太大，AGV会飙车，急转弯时差点翻车。最终我用的比例是0.4 : 0.4 : 0.2，你们可以以此为起点微调。

10.3 路径平滑：贝塞尔曲线

A*规划出来的路径是什么样？是一段段直线，拐角处是尖的。你想想看，AGV在尖角处要停下来、原地转向、再启动——效率低不说，对电机和电池都是折磨。

这时候就需要贝塞尔曲线来「润色」了。说白了，就是用一条光滑的曲线把那些尖角「抹圆」了。

三阶贝塞尔曲线的公式：

// 三阶贝塞尔曲线
Point bezier_curve(Point p0, Point p1, Point p2, Point p3, float t) {
    float u = 1 - t;
    float x = u*u*u * p0.x + 3*u*u*t * p1.x + 3*u*t*t * p2.x + t*t*t * p3.x;
    float y = u*u*u * p0.y + 3*u*u*t * p1.y + 3*u*t*t * p2.y + t*t*t * p3.y;
    return (Point){x, y};
}

p0和p3是路径的两个端点，p1和p2是控制点——控制点决定了曲线的弯曲程度。我习惯把控制点放在路径拐角的角平分线上，距离拐角点约1/3路径长度的地方。

实战技巧：不要对整个路径做平滑，只对拐角处做局部平滑。我曾经试过对整个路径做贝塞尔拟合，结果路径变得太「软」，AGV走起来像喝醉了酒。后来改成只对角度变化大于30°的拐点做平滑，效果立竿见影。

10.4 三者的协同工作

这三个算法不是各干各的，而是流水线作业：

步骤 算法 输入 输出 频率
1 A* 静态地图、起点、终点 全局路径（节点序列） 任务开始时执行一次
2 贝塞尔平滑 全局路径节点 平滑路径（密集点序列） 全局路径更新后执行
3 DWA 平滑路径、局部障碍物 实时速度指令 (v, ω) 10-50Hz 实时运行

实际运行时，A*和贝塞尔在后台跑，DWA在前台高频运行。DWA会沿着平滑路径走，同时实时避障。如果遇到无法绕过的障碍物，DWA会报告「我搞不定」，然后触发A*重新规划。

我曾经踩过的坑：DWA的轨迹预测时间窗口设得太短（0.5秒），结果AGV在高速时来不及刹车，撞上了突然出现的障碍物。后来我把预测窗口延长到2秒，同时加入了紧急制动逻辑——当障碍物距离小于安全阈值时，不管评价函数怎么打分，直接刹车。安全第一，效率第二。

好了，路径规划的基础就讲到这里。这三个算法是AGV控制器的核心，也是面试时的高频考点。你们先把代码跑通，下一章我们聊聊更高级的优化技巧。
