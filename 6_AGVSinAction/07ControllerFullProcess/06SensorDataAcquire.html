6 传感器数据采集：AGV的“感官系统”

各位同学，欢迎来到《AGV控制器开发全流程实战》的第一章。

咱们做AGV，说白了就是让一台机器自己走路。那它怎么知道自己在哪？怎么知道周围有没有障碍物？怎么知道自己走了多远？

答案就藏在传感器里。

这一章，我带你搞定AGV最核心的三个传感器：激光雷达（RPLIDAR）、IMU（MPU6050）和编码器。这三样东西，就是AGV的眼睛、耳朵和腿脚神经。

核心观点：传感器数据采集是AGV控制的基础。数据不准，后面一切算法都是空中楼阁。我见过太多项目，算法调得天花乱坠，最后发现是传感器没校准——白费功夫。

1.1 激光雷达（RPLIDAR）驱动与数据解析

先聊激光雷达。RPLIDAR是思岚科技的产品，性价比很高。我最早接触它是在2016年，那时候还只有A1型号，现在都出到A3了。

它的工作原理很简单：激光发射器旋转，测量每个角度上的距离。一圈360°，每0.5°或1°一个采样点，就形成了我们常说的“点云”。

驱动它，核心就三步：

  1. 串口初始化——波特率通常115200或256000
  2. 发送启动指令——0xA5 0x20
  3. 循环读取数据帧——解析距离和角度

数据帧格式是这样的：

字节偏移 长度 含义
0 1 起始标志 (0xFA)
1 1 数据包类型
2-3 2 角度值 (低字节在前)
4-5 2 距离值 (低字节在前)
6 1 信号质量
7 1 校验和

代码实现其实不复杂。我贴一段核心的解析函数：

// RPLIDAR数据解析示例
typedef struct {
    float angle;      // 角度（度）
    float distance;   // 距离（毫米）
    uint8_t quality;  // 信号质量 0-255
} lidar_point_t;

int rplidar_parse_frame(uint8_t *buf, lidar_point_t *point) {
    // 检查起始标志
    if (buf[0] != 0xFA) return -1;
    
    // 解析角度（单位0.01度）
    uint16_t angle_raw = buf[2] | (buf[3] << 8);
    point->angle = angle_raw / 100.0f;
    
    // 解析距离（单位毫米）
    uint16_t dist_raw = buf[4] | (buf[5] << 8);
    point->distance = dist_raw;
    
    // 信号质量
    point->quality = buf[6];
    
    return 0;
}

实战小技巧：我在项目中遇到过一个问题——雷达数据偶尔会跳变，比如明明前面是墙，突然显示距离为0。后来发现是校验和没做。RPLIDAR的校验和算法是累加和取低8位，千万别偷懒不校验。

1.2 IMU（MPU6050）姿态解算

IMU这东西，说白了就是告诉你车头朝哪、车身有没有倾斜。MPU6050集成了三轴加速度计和三轴陀螺仪，通过I2C接口读取数据。

加速度计测的是重力在三个轴上的分量，陀螺仪测的是角速度。但单独用哪个都有问题：

  • 加速度计——静态准，动态时受震动干扰大
  • 陀螺仪——动态响应快，但会漂移

所以需要融合。我常用的方法是互补滤波，简单又有效。

先看初始化代码：

// MPU6050初始化
void mpu6050_init(void) {
    // 唤醒MPU6050
    i2c_write_byte(MPU6050_ADDR, 0x6B, 0x00);
    
    // 设置加速度计量程为±2g
    i2c_write_byte(MPU6050_ADDR, 0x1C, 0x00);
    
    // 设置陀螺仪量程为±250°/s
    i2c_write_byte(MPU6050_ADDR, 0x1B, 0x00);
    
    // 设置数字低通滤波器
    i2c_write_byte(MPU6050_ADDR, 0x1A, 0x06);
}

姿态解算的核心是互补滤波：

// 互补滤波姿态解算
#define Kp 0.98f  // 陀螺仪权重
#define Ki 0.02f  // 加速度计权重

void complementary_filter(float ax, float ay, float az,
                          float gx, float gy, float gz, float dt) {
    // 从加速度计计算俯仰角和横滚角
    float accel_pitch = atan2(-ax, sqrt(ay*ay + az*az)) * 180.0f / M_PI;
    float accel_roll  = atan2(ay, az) * 180.0f / M_PI;
    
    // 陀螺仪积分
    gyro_pitch += gx * dt;
    gyro_roll  += gy * dt;
    
    // 互补融合
    pitch = Kp * (pitch + gx * dt) + Ki * accel_pitch;
    roll  = Kp * (roll  + gy * dt) + Ki * accel_roll;
}

注意：MPU6050的原始数据是16位有符号整数，需要根据量程转换成实际的物理值。比如±2g量程下，每LSB对应16384 LSB/g。我见过有人直接拿原始值去算角度，结果可想而知。

1.3 编码器速度计算

编码器是AGV的“里程计”。它装在电机轴上，每转一圈输出固定数量的脉冲。通过统计单位时间内的脉冲数，就能算出速度。

常用的编码器有增量式和绝对值式两种。AGV上大多用增量式，AB两相输出，相位差90°，可以判断方向。

STM32的定时器有编码器模式，硬件上就能完成脉冲计数和方向判断，省心不少。

// 定时器编码器模式配置
void encoder_timer_init(void) {
    TIM_EncoderInterfaceConfig(TIM2, TIM_ENCODERMODE_TI12,
                               TIM_ICPolarity_Rising, TIM_ICPolarity_Rising);
    TIM_Cmd(TIM2, ENABLE);
}

// 速度计算（单位：mm/s）
float calc_speed(int32_t pulse_cnt, float dt_ms) {
    // 编码器分辨率：每转脉冲数
    const float PULSE_PER_REV = 1024.0f;
    // 车轮直径（mm）
    const float WHEEL_DIAMETER = 100.0f;
    // 减速比
    const float GEAR_RATIO = 30.0f;
    
    // 每脉冲对应的移动距离（mm）
    float dist_per_pulse = (M_PI * WHEEL_DIAMETER) / 
                           (PULSE_PER_REV * GEAR_RATIO);
    
    // 速度 = 脉冲数 * 每脉冲距离 / 时间
    float speed = (pulse_cnt * dist_per_pulse) / (dt_ms / 1000.0f);
    
    return speed;
}

避坑指南：我曾经在一个项目里发现，AGV走直线时左右轮编码器读数差异很大。排查了半天，发现是编码器安装时联轴器没锁紧，有轻微打滑。所以编码器安装后，一定要做空转测试，确认脉冲数稳定。

1.4 三种传感器如何协同工作

你可能会问：这三个传感器各干各的，怎么配合？

我打个比方：

  • 激光雷达负责看路——检测障碍物，构建地图
  • IMU负责感觉——知道车身姿态，辅助定位
  • 编码器负责记步——推算走了多远

在实际的AGV控制器中，这三个传感器的数据会以不同的频率被采集，然后送入融合算法（比如卡尔曼滤波），最终得到更准确的位置和姿态估计。

数据采集的时序安排也很重要。我一般这样分配：

传感器 采样频率 数据用途
激光雷达 5-10 Hz 环境感知、避障
IMU 100-200 Hz 姿态估计、辅助定位
编码器 50-100 Hz 速度控制、里程计算

嗯，这一章的内容就到这里。三种传感器的驱动和解析方法，都是AGV开发的“基本功”。你把这些吃透了，后面讲运动控制、路径规划的时候，才能得心应手。
