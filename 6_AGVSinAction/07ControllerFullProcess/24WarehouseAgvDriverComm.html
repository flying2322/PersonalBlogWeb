24 项目实战：仓储AGV（二）：底层驱动与通信联调、运动学标定

好，咱们接着上一章往下走。上一章我们把硬件平台搭起来了，电机也能转了，编码器也能读数了。但说实话，那只是让轮子动起来，离真正的“车”还差得远。

这一章，我们要干三件硬核的事：底层驱动封装、通信联调、还有运动学标定。这三件事做完，你的AGV才算有了“腿”和“神经”。

核心目标：让电机听话、让数据跑通、让车走直线。

一、底层驱动封装：把硬件藏起来

我个人习惯，写驱动代码时，先想清楚接口。你想想看，如果每次控制电机都要去操作寄存器，那代码就没法维护了。所以第一步，我们把电机、编码器、IO这些硬件抽象成API。

下面是我在项目中常用的驱动层结构：

// motor_driver.h
typedef struct {
    int32_t target_rpm;      // 目标转速
    int32_t current_rpm;     // 当前转速
    uint16_t pwm_duty;       // PWM占空比
    uint8_t direction;       // 方向
    uint8_t brake;           // 刹车状态
} Motor_Handle_t;

// 对外接口
void Motor_Init(Motor_Handle_t *hmotor, uint8_t id);
void Motor_SetSpeed(Motor_Handle_t *hmotor, int32_t rpm);
void Motor_Stop(Motor_Handle_t *hmotor);
int32_t Motor_GetSpeed(Motor_Handle_t *hmotor);

嗯，这里要注意：编码器读数一定要做滤波。我曾经在项目里吃过亏，编码器信号抖动，导致速度环震荡。后来加了个简单的滑动平均滤波，问题就解决了。

避坑指南：编码器线数越高，采样频率也要相应提高。比如用1000线的编码器，建议采样频率至少1kHz，否则低速时会丢步。

二、通信联调：让大脑和四肢对话

AGV的控制器和底层驱动板之间，通常用CAN总线或者RS485通信。我这里以CAN为例，因为它在工业现场抗干扰能力强。

通信协议怎么设计？说白了，就是定义好“谁发、发什么、怎么解析”。

CAN ID 数据内容 方向 说明
0x101 左轮目标速度 控制器→驱动板 int16_t，单位mm/s
0x102 右轮目标速度 控制器→驱动板 int16_t，单位mm/s
0x201 左轮实际速度 驱动板→控制器 int16_t，单位mm/s
0x202 右轮实际速度 驱动板→控制器 int16_t，单位mm/s
0x301 系统状态 驱动板→控制器 故障码、急停状态等

联调的时候，我建议先做“回环测试”。就是控制器发一个速度指令，驱动板收到后原样返回，看看数据对不对。这一步能快速排查硬件接线和CAN配置问题。

警告：CAN总线终端电阻一定要加！120欧姆，两端各一个。不加的话，长距离通信会出现丢包。我见过有人调试一整天，最后发现是没加终端电阻。

三、运动学标定：让车走直线

这是最考验耐心的一步。为什么？因为机械加工有误差，两个轮子的直径不可能完全一样，电机特性也有差异。如果不做标定，你给左右轮发同样的速度指令，车一定会跑偏。

运动学标定的核心，就是找到左右轮的速度修正系数。

具体做法是这样的：

  1. 让AGV在一条直线上跑一段距离，比如5米。
  2. 测量实际偏移量，比如偏右了10厘米。
  3. 根据偏移量计算修正系数。

计算公式其实很简单：

// 假设左轮为基准，修正右轮
修正系数 = (左轮速度 + 偏移量/距离 * 左轮速度) / 左轮速度

// 举例：左轮速度100mm/s，跑5米偏右0.1米
修正系数 = (100 + 0.1/5 * 100) / 100 = 1.02
// 意味着右轮速度要乘以1.02

嗯，这里有个细节：标定距离越长，精度越高。我一般建议至少跑10米。另外，标定要反复做几次，取平均值。

我的经验：标定完成后，在车上画一条直线，让车来回跑几次。如果每次都能回到起点，偏差在1厘米以内，就算合格了。

五、联调实战步骤

好了，理论说完了，咱们来点实际的。下面是我总结的联调步骤，照着做就行：

  1. 上电前检查：电源极性、CAN总线连接、电机线是否牢固。
  2. 单板测试：先让驱动板单独工作，用调试工具发指令，看电机能不能转。
  3. 通信测试：控制器和驱动板建立连接，发一个速度指令，看返回值是否正确。
  4. 开环跑车：不给反馈，直接发固定PWM，看车能不能动。
  5. 闭环跑车：加入编码器反馈，做速度闭环控制。
  6. 标定：按前面说的方法，做运动学标定。
  7. 验证：让车跑一个矩形路径，看能不能回到起点。

小技巧：联调时，把速度设慢一点，比如50mm/s。万一出问题，还有时间反应。我见过有人一上来就全速跑，结果车直接撞墙了。

嗯，这一章的内容就这些。底层驱动封装好了，通信联调通了，运动学标定做完了，你的AGV才算真正有了“腿”。下一章，我们会开始做运动控制算法，让车能走直线、能转弯。
