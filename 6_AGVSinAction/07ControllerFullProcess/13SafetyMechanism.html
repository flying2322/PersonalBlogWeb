13 安全机制设计：急停逻辑、避障策略（VFH+）、电子围栏、故障诊断与恢复

做AGV控制器这么多年，我越来越觉得——安全不是功能，是底线。

你想想看，一辆无人车在工厂里跑，周围全是人、设备、货架。一旦出问题，轻则撞坏东西，重则伤人。所以这一章，咱们重点聊聊AGV的安全机制怎么设计。说白了，就是怎么让车“知道危险”、“避开危险”、“在危险中活下来”。

核心要点： 安全机制不是堆功能，而是分层防御。急停是最后一道墙，避障是日常防御，电子围栏是区域管控，故障诊断是自我修复能力。

13.1 急停逻辑：最后一道防线

急停，听起来简单——按个按钮车就停了。但实际工程里，这里坑很多。

我个人习惯把急停分成两级：

  • 硬件急停：物理按钮，直接切断电机驱动电源。这个优先级最高，不经过任何软件逻辑。
  • 软件急停：通过CAN总线或IO信号触发，控制器收到信号后执行紧急制动流程。

我在项目中遇到过一个问题：客户反馈急停按钮按下去，车还要滑行半米才停。查了半天，发现是软件急停里做了“减速曲线”，想着让车平稳停下。但急停场景下，平稳就是犯罪！

避坑指南： 我曾经在急停逻辑里加了PID缓停，结果被客户骂惨了。急停就是急停，直接抱闸+切断动力，别搞什么平滑过渡。

急停的恢复逻辑也很重要。很多新手会忽略这一点：急停恢复后，车应该处于什么状态？我的建议是：

  • 急停恢复后，车必须处于“手动模式”
  • 必须人工确认安全后，才能重新切换到自动运行
  • 急停触发时的路径信息要保留，方便后续恢复

13.2 避障策略：VFH+算法实战

避障算法有很多，什么DWA、TEB、VFH。我个人最常用的是VFH+，为什么？因为它计算量小、实时性好，适合嵌入式平台。

VFH+的核心思想很简单：把周围环境用极坐标网格表示，然后找出一条“最安全”的方向走。

具体步骤我总结为四步：

  1. 构建局部栅格地图：用激光雷达数据，把障碍物映射到车体周围的栅格中
  2. 生成极坐标直方图：每个角度方向计算一个“障碍物密度值”
  3. 识别可行区域：找密度值低于阈值的连续角度区间
  4. 选择最优方向：结合目标方向、当前方向、历史方向，选一个最合适的

这里我贴一段核心代码，展示VFH+中最关键的一步——极坐标直方图生成：

// VFH+ 极坐标直方图生成（简化版）
#define SECTOR_COUNT 72  // 5度一个扇区
#define MAX_DISTANCE 4.0f // 米

float histogram[SECTOR_COUNT] = {0};

void vfh_build_histogram(LaserScan *scan) {
    memset(histogram, 0, sizeof(histogram));
    
    for (int i = 0; i < scan->point_count; i++) {
        float angle = scan->points[i].angle;
        float dist = scan->points[i].distance;
        
        if (dist > MAX_DISTANCE) continue;  // 太远的忽略
        
        // 计算障碍物密度值
        int sector = (int)(angle / (2*M_PI) * SECTOR_COUNT) % SECTOR_COUNT;
        float density = 1.0f / (dist * dist);  // 距离越近，密度越大
        
        // 考虑障碍物宽度，影响相邻扇区
        int influence = (int)(0.5f / dist * SECTOR_COUNT / (2*M_PI));
        for (int j = -influence; j <= influence; j++) {
            int idx = (sector + j + SECTOR_COUNT) % SECTOR_COUNT;
            histogram[idx] += density * (1.0f - fabs(j) / (float)influence);
        }
    }
}

嗯，这里要注意一个细节：障碍物宽度的影响。很多初学者只考虑障碍物所在的扇区，结果车贴着障碍物边缘走，很容易刮蹭。我习惯把障碍物的影响范围扩散到相邻扇区，距离越近扩散越宽。

实战技巧： VFH+的阈值设置很关键。阈值太高，车会钻到窄缝里出不来；阈值太低，车会绕大圈。我一般设两个阈值：高阈值用于紧急避障，低阈值用于正常导航。动态切换效果更好。

13.3 电子围栏：虚拟的墙

电子围栏，说白了就是在地图上画一些“不能进”的区域。但实际工程里，电子围栏不只是“不能进”，还有“不能出”。

我一般把电子围栏分为三类：

类型 说明 典型场景
禁止进入区 车不能开进去的区域 货架区、人员通道
禁止驶出区 车不能离开的区域 工作区域边界、悬崖边缘
减速区 进入该区域必须减速 转弯处、狭窄通道

电子围栏的实现方式，我推荐用多边形表示。每个围栏是一个多边形顶点列表，判断车的位置是否在多边形内部。这个算法很成熟，用射线法或者角度和法都行。

我在项目中遇到过一个问题：电子围栏的边界判断频率太低，车高速冲过去时，已经越过围栏才检测到。后来我做了“预测性检测”——不光看当前位置，还预测未来0.5秒的位置是否进入围栏。

避坑指南： 我曾经在电子围栏里只做了位置判断，没做方向判断。结果车倒车时，屁股先进入围栏区域，但车头还在外面，系统没报警。后来我改成判断车体轮廓的任意顶点是否进入围栏。

13.4 故障诊断与恢复：让车学会自救

故障诊断，不是等车坏了再修，而是在故障发生前就发现苗头。

我习惯把故障分为三个等级：

  • 一级故障（警告）：不影响运行，但需要记录。比如某个传感器数据偶尔跳变。
  • 二级故障（降级）：部分功能受限，但还能动。比如激光雷达被遮挡，切换到超声波避障。
  • 三级故障（停机）：必须立即停止。比如电机驱动器报错、急停被触发。

故障恢复策略，我总结了一个“三步走”原则：

  1. 诊断：确定故障类型和位置。是传感器坏了？还是通信断了？还是机械卡住了？
  2. 隔离：把故障部分隔离出去，不让它影响其他模块。比如某个电机编码器坏了，就切换到开环控制。
  3. 恢复：尝试自动恢复，或者引导人工介入。比如通信超时，自动重连3次，不行就报人工。

故障恢复这块，我特别想强调一点：不要盲目恢复。有些故障是间歇性的，比如通信偶尔丢包，重试几次就好了。但有些故障是永久性的，比如电机烧了，你重试一万次也没用。

实战技巧： 我习惯给每个故障类型配一个“恢复计数器”。连续恢复失败3次，就不再尝试，直接报人工。这样可以避免车在原地反复重启，浪费电池。

最后，分享一个我踩过的坑：故障日志的记录。刚开始做的时候，我只记录故障代码和时间。后来排查问题时发现根本不够用。现在我要求故障日志必须包含：

  • 故障发生时的车速、方向、位置
  • 前后5秒的传感器数据快照
  • 当前任务ID和路径点
  • 系统状态（电池电量、温度、运行模式）

有了这些信息，排查故障的效率能提升好几倍。嗯，这就是经验的价值吧。
