4 坐标变换基础：TF坐标树、静态/动态变换、TF广播与监听、Eigen库基础操作

各位同学，欢迎来到第四章。这一章，我们聊聊SLAM里最基础、也最容易让人迷糊的东西——坐标变换。

说实话，我刚开始做AGV导航那会儿，最头疼的就是坐标系。明明地图上显示前方没障碍，车就是不走直线。后来排查了半天，发现是激光雷达的安装角度偏了0.5度，坐标变换没处理好。嗯，从那以后，我对TF和Eigen就格外上心。

这一章，我会带你彻底搞懂：TF坐标树、静态/动态变换、TF广播与监听，以及Eigen库的基础操作。这些都是你写SLAM代码的“基本功”。

4.1 为什么需要坐标变换？

你想想看，一辆AGV上，有激光雷达、IMU、轮式里程计、还有车体本身。每个传感器都有自己的“视角”。激光雷达看到的是“前方2米有障碍”，但这个“前方”是雷达自己的前方，不是车体的前方。

所以，我们需要一个统一的坐标系，把所有传感器的数据都转换到同一个参考系下。这个转换过程，就是坐标变换。

核心概念：TF（Transform）是ROS中管理坐标变换的框架。它维护了一棵“坐标树”，记录了所有坐标系之间的相对位置和姿态关系。

4.2 TF坐标树：一切变换的根

TF坐标树，说白了就是一个树状结构。根节点通常是map（地图坐标系）或odom（里程计坐标系）。其他坐标系，比如base_link（车体坐标系）、laser_frame（激光雷达坐标系），都是它的子节点。

我习惯把TF树想象成“家族谱”。每个坐标系就是一个“人”，父子关系就是“谁在谁上面”。比如：

  • map → odom → base_link → laser_frame
  • base_link → imu_link

这样，只要知道laser_frame相对于base_link的变换，以及base_link相对于odom的变换，就能算出laser_frame相对于odom的变换。

我的经验：在调试时，用tf_echo命令查看两个坐标系之间的变换，能快速定位问题。比如：rosrun tf tf_echo /base_link /laser_frame。如果输出是NaN或者无穷大，那肯定是TF树断了。

4.3 静态变换 vs 动态变换

TF变换分两种：静态和动态。

类型 特点 典型场景 发布频率
静态变换 固定不变，发布一次即可 激光雷达相对于车体的安装位置 一次（或低频）
动态变换 随时间变化，需要持续发布 车体相对于里程计的位姿 高频（如10Hz-100Hz）

静态变换，说白了就是“装上去就不动了”。比如激光雷达固定在车头，它的位置和朝向是固定的。我们用static_transform_publisher来发布。

动态变换，则是“一直在变”。比如AGV在移动，车体相对于地图的位姿每时每刻都在更新。这通常由里程计或SLAM算法来发布。

避坑指南：我曾经犯过一个错误——把动态变换当静态变换发布。结果AGV一转弯，激光数据就全乱了。记住：凡是会动的，都用动态变换。

4.4 TF广播与监听：怎么发？怎么收？

在ROS里，TF的发布和接收，是通过“广播”和“监听”实现的。

4.4.1 广播TF

广播TF，就是告诉整个系统：“我这个坐标系现在在哪儿”。代码很简单，但要注意时间戳。

#include <ros/ros.h>
#include <tf/transform_broadcaster.h>

int main(int argc, char** argv) {
    ros::init(argc, argv, "my_tf_broadcaster");
    ros::NodeHandle nh;

    tf::TransformBroadcaster broadcaster;
    tf::Transform transform;

    // 设置激光雷达相对于车体的变换
    transform.setOrigin(tf::Vector3(0.5, 0.0, 0.2)); // x=0.5m, y=0, z=0.2m
    tf::Quaternion q;
    q.setRPY(0, 0, 0); // 无旋转
    transform.setRotation(q);

    ros::Rate rate(10);
    while (nh.ok()) {
        // 广播：父坐标系是base_link，子坐标系是laser_frame
        broadcaster.sendTransform(
            tf::StampedTransform(transform, ros::Time::now(), "base_link", "laser_frame")
        );
        rate.sleep();
    }
    return 0;
}

你看，核心就是sendTransform。参数里，ros::Time::now()是时间戳，base_link是父坐标系，laser_frame是子坐标系。

4.4.2 监听TF

监听TF，就是“我想知道某个坐标系相对于另一个坐标系的位置”。比如，我想知道激光雷达的数据在车体坐标系下是什么样。

#include <ros/ros.h>
#include <tf/transform_listener.h>

int main(int argc, char** argv) {
    ros::init(argc, argv, "my_tf_listener");
    ros::NodeHandle nh;

    tf::TransformListener listener;

    ros::Rate rate(10);
    while (nh.ok()) {
        tf::StampedTransform transform;
        try {
            // 等待变换可用，最多等3秒
            listener.waitForTransform("/base_link", "/laser_frame", ros::Time(0), ros::Duration(3.0));
            // 获取变换
            listener.lookupTransform("/base_link", "/laser_frame", ros::Time(0), transform);
        } catch (tf::TransformException &ex) {
            ROS_ERROR("%s", ex.what());
            continue;
        }

        // 拿到变换后，就可以做数据转换了
        double x = transform.getOrigin().x();
        double y = transform.getOrigin().y();
        ROS_INFO("Laser frame is at (%.2f, %.2f) relative to base_link", x, y);

        rate.sleep();
    }
    return 0;
}

我的习惯：在监听TF时，一定要加waitForTransform。因为TF树可能还没建好，直接查会报错。我曾经在启动脚本里没加等待，结果程序一启动就崩溃，排查了半天才发现是TF还没发布。

4.5 Eigen库基础操作：数学工具

Eigen是C++里一个非常强大的线性代数库。在SLAM中，我们用它来处理矩阵、向量、四元数等。

说实话，我刚开始用Eigen时，觉得它API太复杂。但用久了发现，它真的很顺手。尤其是矩阵运算，比手写循环快多了。

4.5.1 基本类型

#include <Eigen/Core>
#include <Eigen/Geometry>

// 向量
Eigen::Vector3d v(1.0, 2.0, 3.0);  // 三维向量
Eigen::Vector2d v2(1.0, 2.0);      // 二维向量

// 矩阵
Eigen::Matrix3d R;                 // 3x3矩阵
R = Eigen::Matrix3d::Identity();   // 单位矩阵

// 四元数
Eigen::Quaterniond q(1, 0, 0, 0); // w, x, y, z
q = Eigen::Quaterniond::Identity();

4.5.2 常用操作

// 旋转矩阵与四元数互转
Eigen::Matrix3d rot_matrix = q.toRotationMatrix();
Eigen::Quaterniond q2(rot_matrix);

// 向量旋转
Eigen::Vector3d rotated_v = q * v;  // 用四元数旋转向量
Eigen::Vector3d rotated_v2 = rot_matrix * v;  // 用旋转矩阵旋转向量

// 欧拉角转四元数
Eigen::AngleAxisd roll_angle(0.1, Eigen::Vector3d::UnitX());
Eigen::AngleAxisd pitch_angle(0.2, Eigen::Vector3d::UnitY());
Eigen::AngleAxisd yaw_angle(0.3, Eigen::Vector3d::UnitZ());
Eigen::Quaterniond q3 = yaw_angle * pitch_angle * roll_angle;

注意：Eigen的欧拉角顺序是ZYX（偏航-俯仰-横滚），和ROS的默认顺序一致。但不同库可能不一样，使用时一定要确认。

4.5.3 与TF的互转

在实际项目中，我们经常需要在Eigen和TF之间转换数据。我封装了一个小工具：

#include <tf/transform_datatypes.h>

// TF转Eigen
tf::Transform tf_transform;
Eigen::Isometry3d eigen_transform;
tf::transformTFToEigen(tf_transform, eigen_transform);

// Eigen转TF
Eigen::Isometry3d eigen_transform2;
tf::Transform tf_transform2;
tf::transformEigenToTF(eigen_transform2, tf_transform2);

我的经验：在写SLAM后端优化时，我习惯把所有数据都转成Eigen格式。因为Eigen的矩阵运算效率高，而且支持自动求导（用于图优化）。等优化完，再转回TF发布出去。

4.7 小结

这一章，我们聊了：

  • TF坐标树：一切变换的根，理解父子关系是关键。
  • 静态变换 vs 动态变换：固定不变的用静态，会动的用动态。
  • TF广播与监听：sendTransform和lookupTransform是核心API，别忘了加waitForTransform。
  • Eigen库基础操作：向量、矩阵、四元数，以及和TF的互转。
