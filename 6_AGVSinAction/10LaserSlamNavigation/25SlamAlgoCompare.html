25 SLAM算法对比选型：精度/鲁棒性/计算资源对比、场景适配性分析、选型决策树

做AGV导航这么多年，我经常被问到同一个问题：“到底该用哪种SLAM算法？”

说实话，没有银弹。每种算法都有自己的脾气。你想想看，一个在仓库里跑得飞快的AGV，和一台在博物馆里慢慢溜达的巡检机器人，它们对SLAM的要求能一样吗？

这一章，我就把几种主流SLAM算法拉到台面上，从精度、鲁棒性、计算资源三个维度做个硬碰硬的对比。最后，我会给你一张选型决策树，帮你快速找到最适合你项目的那个“它”。

一、三大主流SLAM算法硬核对比

我个人习惯把AGV领域常用的SLAM算法分成三类：Gmapping、Cartographer、Hector SLAM。当然还有Karto、CoreSLAM等，但实战中这三兄弟出场率最高。

对比维度 Gmapping Cartographer Hector SLAM
核心原理 RBPF粒子滤波 图优化+子图匹配 扫描匹配（高斯牛顿）
建图精度 ★★★★☆（依赖里程计） ★★★★★（闭环修正强） ★★★☆☆（无闭环）
鲁棒性 ★★★☆☆（怕打滑） ★★★★★（IMU辅助） ★★☆☆☆（怕快速旋转）
CPU占用 低（单核即可） 中高（多核优化） 极低（轻量级）
内存占用 中等（粒子数决定） 高（子图缓存） 低（仅维护栅格）
是否需要里程计 必须（轮式编码器） 可选（有IMU更好） 不需要（纯激光）
典型场景 室内小场景、低成本AGV 大场景、高精度、多楼层 无人机、快速移动、无轮式
我的实战经验： 记得有一次在汽车工厂做项目，地面全是油污，AGV轮子疯狂打滑。Gmapping直接崩了，地图歪得像抽象画。换成Cartographer后，靠着IMU硬生生把地图拉回来了。嗯，这就是鲁棒性的价值。

二、场景适配性深度分析

说白了，选SLAM算法就像选工具。你不能拿扳手去拧螺丝刀该干的活。下面我按场景拆解一下。

1. 室内结构化环境（仓库、车间）

  • 推荐：Gmapping + 轮式里程计
  • 理由：环境特征丰富（货架、柱子），轮式里程计可靠。粒子数设30-50个，精度足够。
  • 避坑指南：我曾经遇到过地面反光导致激光数据跳变，后来加了反光点滤波才搞定。

2. 大场景/长走廊（物流园区、停车场）

  • 推荐：Cartographer
  • 理由：长走廊容易产生累积误差，Cartographer的闭环检测能有效修正。子图匹配机制对重复结构也有抵抗力。
  • 注意：计算资源要跟上，建议用Jetson Orin或类似级别硬件。

3. 动态/光照变化环境（户外、半户外）

  • 推荐：Hector SLAM 或 3D激光SLAM
  • 理由：Hector不依赖里程计，纯激光扫描匹配，对地面起伏不敏感。但要注意——它没有闭环，长时间运行会漂。
  • 我个人习惯：在户外AGV上，我会用Hector做前端，再叠加一个轻量级的闭环检测模块。

4. 低成本/快速部署场景

  • 推荐：Gmapping + 单线激光
  • 理由：算法成熟，ROS里开箱即用。树莓派4B都能跑得动。
  • 代价：精度一般，遇到长走廊或打滑就露馅。
小技巧： 如果你不确定选哪个，先跑一遍Cartographer。它参数多但容错性强。等验证了场景可行性，再根据资源限制降级到Gmapping或Hector。

三、计算资源消耗实测数据

下面这组数据是我在同一个测试平台上跑出来的。平台：Intel i5-8250U，8GB RAM，2D激光雷达（10Hz）。

算法 CPU占用（%） 内存占用（MB） 建图1000m²耗时 定位频率（Hz）
Gmapping（30粒子） 25-35 120-180 约8分钟 10-15
Cartographer（默认配置） 60-80 350-500 约12分钟 20-30
Hector SLAM 15-25 60-100 约5分钟 30-40
警告： 别被Hector的低资源占用迷惑了。它没有闭环，建完图后如果发现地图歪了，你只能重跑。而Cartographer虽然吃资源，但一次跑通的成功率高得多。

四、选型决策树（实战版）

好了，理论说完了，直接上干货。下面这个决策树，是我在多个项目中总结出来的，你照着走就行。

  1. 第一步：看硬件
    • 有轮式里程计且可靠？ → 走左边（Gmapping/Cartographer）
    • 没有里程计或轮子打滑？ → 走右边（Hector/3D SLAM）
  2. 第二步：看场景大小
    • 小于5000m²且结构简单？ → Gmapping（省资源）
    • 大于5000m²或有多楼层？ → Cartographer（闭环是刚需）
  3. 第三步：看计算资源
    • ARM Cortex-A系列/树莓派？ → Gmapping或Hector
    • x86或Jetson系列？ → Cartographer优先
  4. 第四步：看精度要求
    • ±5cm以内？ → Cartographer + 高精度激光
    • ±10cm可接受？ → Gmapping够用
最终建议： 如果你只能记住一句话——“室内小场景用Gmapping，大场景/高精度用Cartographer，无里程计用Hector”。剩下的，交给实际跑图来验证。

你想想看，SLAM选型其实没那么玄乎。把场景、硬件、精度三个变量列出来，决策树一画，答案就出来了。我见过太多人一上来就调Cartographer的复杂参数，结果连基本地图都建不好。不如先从简单的Gmapping入手，跑通了再升级。

嗯，这一章就到这里。记住，算法是死的，场景是活的。多跑几次，你自然就知道哪个是你的菜了。
