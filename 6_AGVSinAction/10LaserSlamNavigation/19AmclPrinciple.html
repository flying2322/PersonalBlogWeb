19 AMCL定位原理：自适应蒙特卡洛定位、KLD采样、粒子收敛与发散、重定位机制

聊到AGV的定位，很多朋友第一反应就是“用激光雷达匹配一下地图不就行了？”嗯，理论上没错，但实际跑起来你会发现——机器人一旦被推了一下，或者轮子打滑，位置就飞了。这时候，就需要一个能“猜”你在哪儿的算法登场了。

AMCL，全称是自适应蒙特卡洛定位。说白了，就是用一堆粒子来猜机器人的位置。每个粒子就是一个可能的位姿假设。粒子越多，猜得越准，但计算量也越大。怎么平衡？这就是AMCL的精髓所在。

核心思想：用粒子群近似机器人的后验概率分布。粒子密集的地方，就是机器人最可能存在的位置。

19.1 自适应蒙特卡洛定位

传统的蒙特卡洛定位，粒子数量是固定的。你设1000个，它就永远用1000个。但实际场景中，机器人位置很确定时，100个粒子就够用了；位置完全丢失时，可能需要10000个粒子才能找回。

AMCL的自适应体现在哪里？它根据粒子的权重分布，动态调整粒子数量。我习惯用一个指标——有效粒子数（Neff）来判断。

我的经验：Neff 低于粒子总数的一半时，说明粒子退化严重，需要重采样。这时候我会适当增加粒子数，防止粒子枯竭。

具体做法是：

  • 计算所有粒子的归一化权重
  • 计算 Neff = 1 / sum(w_i^2)
  • 如果 Neff 小于阈值（比如 N/2），触发重采样
  • 重采样后，根据收敛程度调整粒子总数

说白了，就是让粒子数跟着不确定性走。机器人跑得稳，粒子就少；遇到拐弯、打滑，粒子自动增多。这样既保证了精度，又节省了算力。

19.2 KLD 采样

KLD 采样，全称是 Kullback-Leibler Divergence 采样。名字听着吓人，其实原理很简单——它用卡方分布来估计当前粒子分布与真实分布之间的差异。

为什么要用KLD？因为AMCL需要知道“我现在用这么多粒子，到底够不够？”KLD采样给出了一个数学上的答案。

核心公式：所需粒子数 M = (k-1) / (2ε) * χ²(1-δ, k-1)

其中 k 是离散化网格数，ε 是误差上限，δ 是置信度。

我在项目中遇到过一个问题：KLD采样在空旷环境下表现很好，但一旦进入长走廊，粒子会沿着走廊方向发散。为什么？因为激光在走廊里的观测信息太少，粒子在纵向上的区分度不够。这时候KLD会误判为“粒子已经收敛”，导致粒子数减少，反而更容易丢失。

我的解决办法是：在KLD计算时，加入一个最小粒子数限制。比如至少保留500个粒子，防止在信息不足时过度缩减。

19.3 粒子收敛与发散

粒子的收敛和发散，是AMCL定位的两个核心过程。它们由两个模型驱动：

模型 作用 效果
运动模型 根据里程计预测粒子新位置 粒子发散（增加不确定性）
观测模型 用激光数据更新粒子权重 粒子收敛（减少不确定性）

你想想看，机器人每走一步，运动模型会让粒子散开一点，模拟里程计的误差累积。然后激光一扫描，观测模型又把权重高的粒子挑出来，让它们繁殖，低权重的粒子淘汰。这一散一聚，就是AMCL定位的节拍。

注意：运动模型的噪声参数非常关键。设得太小，粒子发散不够，遇到打滑就追不上真实位置；设得太大，粒子散得太开，收敛速度变慢。我一般会在仿真里先调好，再拿到真车上微调。

我曾经在一个AGV项目上，因为运动模型噪声设得太小，导致机器人被推了一下后，粒子群完全跟不上真实位置。后来我把里程计协方差矩阵的对角元素放大到原来的1.5倍，问题就解决了。

19.4 重定位机制

重定位，说白了就是“机器人丢了，怎么找回来”。AMCL提供了两种重定位方式：

  • 全局重定位：在地图范围内均匀撒粒子，重新开始定位。适合开机启动或完全丢失的情况。
  • 绑架恢复：当机器人被突然移动（比如被人搬起来），AMCL检测到粒子权重骤降，自动触发重定位。

绑架恢复的检测逻辑是这样的：

if (平均权重 < 阈值) {
    // 可能被绑架了
    增加随机粒子比例（比如10%）
    扩大粒子分布范围
    降低重采样阈值
}

我习惯在绑架恢复时，保留一部分原有粒子。为什么？因为有时候只是短暂打滑，不是真的被搬走。全部撒掉重来，反而浪费了之前积累的信息。

避坑指南：我曾经在仓库项目里，机器人频繁触发绑架恢复。排查后发现是激光雷达被货架遮挡，导致观测模型得分太低。后来我调整了激光的最大有效距离，把30米改成15米，减少了无效观测的影响。

还有一个细节：重定位时，粒子的初始分布范围怎么设？设太小，可能找不到正确位置；设太大，收敛太慢。我一般用地图对角线长度的1/4作为初始分布半径，再根据实际场景微调。

嗯，AMCL的内容就聊到这儿。它不是一个完美的算法，但胜在实用、稳定。只要参数调好了，在大多数室内场景下都能跑得很好。记住一点：没有万能的参数，只有不断调试的工程师。
