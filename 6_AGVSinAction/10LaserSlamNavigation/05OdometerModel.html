5 里程计模型：两轮差速模型、阿克曼模型、轮式编码器数据处理、里程计标定方法

各位同学，今天我们来聊聊里程计。说实话，里程计是SLAM系统里最基础、也最容易被忽视的一环。很多新手一上来就盯着激光雷达和IMU，结果发现建图总是不准，回头一查——原来是轮子编码器数据就没处理好。

我个人习惯把里程计比作「机器人的腿脚感觉」。你闭着眼睛走路，靠的是脚底的感觉和肌肉记忆。机器人也一样，没有GPS，没有视觉，它只能靠轮子转了多少圈来猜自己走了多远。这就是里程计的核心思想。

核心观点：里程计不是万能的，但没有里程计是万万不能的。它提供的是短时间内的局部相对位姿，精度高但会随时间漂移。

5.1 两轮差速模型

两轮差速模型，说白了就是最常见的扫地机器人那种结构。两个驱动轮左右各一个，一个或多个万向轮做支撑。转弯靠的是左右轮速度差。

我在项目中遇到过一个问题：明明左右轮编码器读数都正常，但机器人就是走不直。后来发现是左右轮直径有微小差异，导致直线运动时实际走了个弧线。嗯，这里要注意，理论模型和实际总有差距。

两轮差速模型的核心公式其实很简单：

// 假设左右轮间距为L，左右轮线速度分别为vL和vR
// 机器人线速度 v = (vL + vR) / 2
// 机器人角速度 w = (vR - vL) / L
// 位姿更新（离散时间，dt为采样周期）
x' = x + v * cos(theta) * dt
y' = y + v * sin(theta) * dt
theta' = theta + w * dt

你想想看，这个模型假设轮子与地面是纯滚动、无滑动的。但在实际场景中，瓷砖地面、地毯、斜坡，滑动情况完全不同。我建议你在做标定时，至少采集三种不同地面的数据。

参数 含义 典型值
L 左右轮间距（轮距） 0.3~0.6 m
R 车轮半径 0.05~0.15 m
N 编码器线数（每圈脉冲数） 500~4096

5.2 阿克曼模型

阿克曼模型，就是汽车那种转向方式。前轮转向，后轮驱动。你想想看，汽车转弯时，四个轮子的轨迹是四个不同半径的圆弧，这就是阿克曼几何要解决的问题。

我记得第一次做AGV项目时，客户非要让一个汽车底盘的AGV原地掉头。我解释了半天：阿克曼模型做不到原地旋转，最小转弯半径是由轴距和最大转向角决定的。最后只能加了个麦克纳姆轮方案。

阿克曼模型的核心参数：

  • 轴距 L：前后轮中心距离
  • 轮距 B：左右轮中心距离
  • 转向角 δ：前轮转向角度（注意内外轮转角不同）
// 阿克曼模型简化计算（假设车辆低速，忽略侧偏）
// 转弯半径 R = L / tan(δ)
// 角速度 w = v / R = v * tan(δ) / L
// 位姿更新与两轮差速类似，但v是后轴中心速度

实战技巧：阿克曼模型在低速（< 1 m/s）时精度还不错，但速度一高，轮胎侧偏效应就出来了。我一般会在模型中加一个侧偏刚度补偿项，效果会好很多。

5.3 轮式编码器数据处理

编码器数据处理，说白了就是把脉冲数换算成距离和速度。但这里坑很多，我一个个说。

第一步：脉冲转距离

// 编码器线数 N，车轮半径 R
// 每个脉冲对应的距离 = 2 * π * R / N
// 实际距离 = 脉冲数 * 每个脉冲对应的距离

第二步：速度计算

速度计算有两种方式：M法和T法。M法适合高速，T法适合低速。我建议你直接用M/T混合法，高低速都适用。

// M法：固定时间Δt内计数脉冲数M
// 速度 v = M * (2πR / N) / Δt

// T法：测量两个脉冲之间的时间间隔T
// 速度 v = (2πR / N) / T

// M/T法：同时测量M和T，取两者优势

注意：编码器数据有量化误差。比如每圈500线的编码器，每个脉冲对应约1.26mm（轮径0.2m）。这个分辨率对于高精度SLAM来说是不够的。我曾经在一个项目中用了4096线的编码器，配合细分电路，才勉强达到0.1mm的分辨率。

第三步：滤波处理

原始编码器数据噪声很大，尤其是低速时。我一般会做三步处理：

  1. 中值滤波：去除野点（突然跳变的脉冲）
  2. 滑动平均：平滑速度曲线
  3. 限幅滤波：限制最大加速度，防止突变

5.4 里程计标定方法

标定，说白了就是让理论模型匹配实际机器人。我见过太多人直接拿厂家给的轮径和轮距参数用，结果建图一塌糊涂。

标定什么？

  • 轮径标定：左右轮实际直径与理论值的偏差
  • 轮距标定：左右轮实际间距与设计值的偏差
  • 非正交误差：轮子安装角度偏差

经典标定方法：

我记得最实用的方法是「直线-旋转-直线」法。具体步骤：

  1. 让机器人走一段直线（比如5米），记录实际位移与编码器推算位移的比值，得到轮径修正系数
  2. 让机器人原地旋转360度，记录实际旋转角度与编码器推算角度的比值，得到轮距修正系数
  3. 重复多次，取平均值
// 轮径修正系数计算
// 实际行走距离 D_actual（用激光或卷尺测量）
// 编码器推算距离 D_odom
// 修正系数 k = D_actual / D_odom
// 修正后轮径 R_corrected = k * R_nominal

标定注意事项：

  • 标定场地要平整、足够大（至少10m×10m）
  • 机器人负载要与实际工作时一致
  • 地面材质要与实际工作环境一致
  • 标定速度要覆盖常用速度范围

我曾经在一个项目中，标定做了整整两天。第一天发现标定结果总是不收敛，后来发现是地面有坡度，机器人走直线时其实在爬坡。换了块平地后，半小时就搞定了。所以，标定环境的选择比标定算法本身更重要。

这张图把里程计的知识体系串起来了。从底层模型到数据处理，再到标定方法，每一步都环环相扣。你想想看，如果轮径标定不准，后面的所有计算都是错的。所以我的建议是：先做标定，再做SLAM。

个人经验：标定不是一次性的工作。轮子磨损、负载变化、地面更换，都会影响标定参数。我一般会在AGV的启动脚本里加一个标定参数检查模块，每次启动时自动校验一次。如果偏差超过阈值，就提醒操作员重新标定。
