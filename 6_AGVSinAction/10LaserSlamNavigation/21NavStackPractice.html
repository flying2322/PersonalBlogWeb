21 导航栈综合实战——完整导航流程搭建、多目标点导航、导航性能测试

好，终于到了导航栈的综合实战环节。

前面我们聊了地图、定位、路径规划、控制，这些都是零件。今天，咱们就把这些零件组装起来，让AGV真正跑起来。我个人觉得，这一讲是整个课程里最有成就感的一章。你想想看，看着自己写的代码驱动一台小车，在地图上精准地走完一个又一个点，那种感觉，嗯，确实不错。

一、完整导航流程搭建：从启动到执行

先说说完整的导航流程长什么样。说白了，就是三件事：启动定位、下发目标、执行运动。

我习惯把启动流程写成一个launch文件，一次性把地图服务器、AMCL、move_base、rviz全拉起来。这样调试的时候，一个命令搞定，省心。

<launch>
    <!-- 1. 启动地图服务器 -->
    <node name="map_server" pkg="map_server" type="map_server" args="$(find agv_nav)/maps/warehouse.yaml" />

    <!-- 2. 启动AMCL定位 -->
    <node name="amcl" pkg="amcl" type="amcl">
        <param name="odom_model_type" value="diff"/>
        <param name="initial_pose_x" value="0.0"/>
        <param name="initial_pose_y" value="0.0"/>
        <param name="initial_pose_a" value="0.0"/>
    </node>

    <!-- 3. 启动move_base -->
    <node name="move_base" pkg="move_base" type="move_base">
        <rosparam file="$(find agv_nav)/config/costmap_common_params.yaml" command="load" />
        <rosparam file="$(find agv_nav)/config/local_costmap_params.yaml" command="load" />
        <rosparam file="$(find agv_nav)/config/global_costmap_params.yaml" command="load" />
        <rosparam file="$(find agv_nav)/config/base_local_planner_params.yaml" command="load" />
    </node>

    <!-- 4. 启动rviz可视化 -->
    <node name="rviz" pkg="rviz" type="rviz" args="-d $(find agv_nav)/rviz/nav.rviz" />
</launch>

这里有个小细节：初始位姿。AMCL启动时，如果你不给一个大概的初始位姿，它可能会在全局地图里瞎猜。我曾经在项目现场遇到过，小车一开机，定位直接飘到地图外面去了。后来我养成了习惯，每次启动前，先在rviz里用“2D Pose Estimate”点一下小车的大概位置，或者直接在参数里写死一个初始值。

我的小技巧： 如果你用的是差分底盘，odom_model_type 设成 "diff" 就行。如果是全向轮，记得改成 "omni"。这个参数选错了，定位精度会差一大截。

二、多目标点导航：让AGV学会“跑腿”

单点导航太简单了，实际场景里，AGV需要连续跑多个点。比如从A点取货，送到B点，再去C点充电。

多目标点导航的核心逻辑，就是一个任务队列。我习惯用actionlib来实现，因为可以实时反馈状态。

# 伪代码示例：多目标点导航客户端
import rospy
import actionlib
from move_base_msgs.msg import MoveBaseAction, MoveBaseGoal

def send_goal(x, y, yaw):
    client = actionlib.SimpleActionClient('move_base', MoveBaseAction)
    client.wait_for_server()

    goal = MoveBaseGoal()
    goal.target_pose.header.frame_id = "map"
    goal.target_pose.pose.position.x = x
    goal.target_pose.pose.position.y = y
    goal.target_pose.pose.orientation.z = sin(yaw/2)
    goal.target_pose.pose.orientation.w = cos(yaw/2)

    client.send_goal(goal)
    client.wait_for_result()
    return client.get_state()

# 任务队列
waypoints = [
    (2.0, 3.0, 0.0),
    (5.0, 1.0, 1.57),
    (8.0, 4.0, 3.14)
]

for wp in waypoints:
    state = send_goal(*wp)
    if state == actionlib.GoalStatus.SUCCEEDED:
        rospy.loginfo("到达目标点")
    else:
        rospy.logwarn("导航失败，跳过该点")

你可能会问：如果中间某个点失败了怎么办？嗯，这里要注意。我一般会加一个重试机制。比如失败后，先原地旋转一下，重新规划一次。如果连续失败3次，就跳过这个点，去执行下一个。别让AGV卡死在一个点上，那在实际产线上会出大问题。

避坑指南： 我曾经遇到过，AGV在狭窄通道里连续重试，结果把自己卡在墙角出不来。后来我加了一个“倒车脱困”的逻辑：如果重试2次都失败，就后退0.5米，再重新规划。效果立竿见影。

三、导航性能测试：别光看，要量化

导航跑起来了，但跑得好不好？不能光靠眼睛看。我们需要量化指标。

我个人常用的测试指标有这几个：

指标 说明 我的经验阈值
到达精度 AGV停止时与目标点的距离误差 ±10cm以内算合格，±5cm算优秀
规划时间 从下发目标到开始运动的时间 小于1秒算正常，超过2秒要优化
路径平滑度 角速度和线速度的突变次数 每米不超过2次急转弯
重试次数 一次导航任务中规划失败的次数 0次最好，超过3次说明参数有问题

怎么测？我习惯写一个测试脚本，让AGV反复跑同一条路径，记录每次的到达误差和时间。然后算平均值和方差。方差太大，说明定位或者控制不稳定。

# 测试脚本片段
def run_test(waypoints, repeat=10):
    results = []
    for i in range(repeat):
        for wp in waypoints:
            start = rospy.Time.now()
            state = send_goal(*wp)
            elapsed = (rospy.Time.now() - start).to_sec()
            results.append({
                'wp': wp,
                'state': state,
                'time': elapsed
            })
    # 分析结果
    avg_time = sum(r['time'] for r in results) / len(results)
    print(f"平均规划时间: {avg_time:.2f}s")
核心观点： 导航性能测试不是一次性的。每次修改参数、更新地图、甚至更换传感器位置后，都应该重新跑一遍测试。我见过太多人调完参数后，觉得“看起来不错”就上线了，结果一跑批量任务就出问题。
