10 Cartographer建图实战：配置文件详解、3D/2D模式切换、纯定位模式、性能调优

说实话，Cartographer 这个开源 SLAM 库，我用了好几年了。从最初在实验室里跑 2D 数据，到后来在工厂里调 3D 雷达，它一直是我的主力工具。但很多人觉得它难上手，说白了，就是被那一堆配置文件给吓住了。

今天咱们就把它扒开来看。你跟着我走一遍，保证能搞明白。

10.1 配置文件，到底在配什么？

Cartographer 的配置，核心就两个文件：.lua 和 .launch。前者是算法参数，后者是 ROS 启动参数。

我个人习惯，先把 .lua 文件吃透。它里面定义了传感器、前端匹配、后端优化、回环检测等所有关键参数。

我的经验： 对于 2D 场景，optimize_every_n_nodes 设 90 左右比较稳。如果地图很大，可以调到 150。回环检测的 min_score 设 0.55 是个不错的起点，太低容易误检，太高又容易漏检。

10.2 2D 与 3D 模式切换

这个其实很简单。核心就是改一个布尔值：use_trajectory_builder_2d 或 use_trajectory_builder_3d。

但背后涉及的传感器配置，差别就大了。

配置项 2D 模式 3D 模式
传感器类型 单线激光雷达 多线激光雷达（如 VLP-16）
IMU 需求 可选（建议使用） 必须（用于重力对齐）
子图类型 概率栅格 混合概率栅格（HybridGrid）
前端匹配 CSM + Ceres 实时 CSM（3D）+ Ceres
回环检测 Fast CSM 2D Fast CSM 3D
计算量 低 高（建议 GPU 加速）

切换时，记得把 num_laser_scans 改成 0，num_point_clouds 改成 1。我在项目中遇到过有人忘了改这个，结果 3D 点云数据被当成 2D 扫描处理，地图直接崩了。

注意： 3D 模式下，tracking_frame 必须和 IMU 的坐标系一致。否则重力对齐会出错，地图会飘。

10.3 纯定位模式

纯定位模式，说白了就是地图已经建好了，机器人只负责在里面找自己的位置。不需要再更新地图。

怎么切？在启动时加一个参数：

roslaunch cartographer_ros my_robot_localization.launch load_state_filename:=/path/to/saved_map.pbstream

对应的 .launch 文件里，要设置：

<node name="cartographer_node" pkg="cartographer_ros" type="cartographer_node" args="
  -configuration_directory $(find my_robot)/config
  -configuration_basename my_robot.lua
  -load_state_filename $(arg load_state_filename)
  -keep_running true">

关键参数是 -keep_running true。它告诉 Cartographer：别退出，继续定位。

另外，.lua 文件里要关掉地图更新：

POSE_GRAPH.optimize_every_n_nodes = 0
POSE_GRAPH.constraint_builder.sampling_ratio = 0.0

嗯，这里要注意。纯定位模式下，optimize_every_n_nodes 设成 0 不是不优化，而是不新增节点。后端只做位姿图优化，不插入新的子图。

避坑指南： 我曾经在纯定位模式下忘了关 use_online_correlative_scan_matching，结果前端还在做暴力匹配，CPU 占用率居高不下。纯定位时，建议把实时 CSM 关掉，只用 Ceres 做局部匹配，速度能快不少。

10.4 性能调优，从哪下手？

性能调优，说白了就是找瓶颈。Cartographer 的瓶颈通常在这几个地方：

  1. 前端匹配：实时 CSM 的搜索窗口大小
  2. 后端优化：optimize_every_n_nodes 和 constraint_builder.sampling_ratio
  3. 子图插入：submaps.num_range_data 和栅格分辨率
  4. 回环检测：Fast CSM 的搜索窗口和分支定界深度

我一般按这个顺序调：

步骤 参数 调优方向
1 submaps.grid_options_2d.resolution 0.05 是标准值。如果地图大，可以降到 0.1，但精度会下降
2 submaps.num_range_data 90 是默认值。如果传感器频率高（如 40Hz），可以降到 60
3 real_time_correlative_scan_matcher.linear_search_window 0.1 米是安全的。如果里程计好，可以降到 0.05
4 constraint_builder.sampling_ratio 0.3 是默认。如果 CPU 吃紧，降到 0.1
5 fast_correlative_scan_matcher.branch_and_bound_depth 7 是默认。如果地图大，可以降到 5，但回环检测可能变慢

你想想看，调优就像拧螺丝。拧太紧会滑丝，拧太松会晃动。每个参数都要根据实际场景去试。

我的调优口诀： 先粗后细，先快后准。先用低分辨率、大搜索窗口跑通流程，再逐步收紧参数，提升精度。
