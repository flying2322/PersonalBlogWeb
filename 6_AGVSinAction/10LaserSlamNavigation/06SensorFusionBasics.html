6 传感器融合基础——EKF、粒子滤波与robot_pose_ekf实战

各位同学，欢迎来到第六讲。

前面几讲我们聊了激光雷达、里程计、IMU各自怎么用。但实际AGV跑起来，你会发现一个尴尬的事：单个传感器总有掉链子的时候。激光雷达遇到玻璃墙直接“失明”，里程计在光滑地面疯狂打滑，IMU长时间跑偏得离谱。

怎么办？把它们的优点凑一块儿，缺点互相补。这就是传感器融合。

今天咱们就掰开揉碎，讲讲最经典的两个融合方法——扩展卡尔曼滤波（EKF）和粒子滤波。最后再带大家实操一下ROS里现成的robot_pose_ekf包。

一、为什么需要传感器融合？

先问个问题：你信哪个传感器？

我刚开始做AGV时，天真地以为里程计最准。结果有一次在仓库里，AGV压过一片油污，轮子空转了半米，定位直接偏到隔壁货架去了。激光雷达呢？遇到高反光物体，点云直接飞掉。IMU更别提，积分几分钟就漂出天际。

说白了，每个传感器都有“死穴”。融合的核心思想就是：

  • 互补：用IMU补激光的短时遮挡，用激光修正里程计的长期漂移
  • 冗余：一个坏了，另一个还能顶一阵
  • 加权：谁当前更可信，就多信谁一点

核心结论：融合不是简单平均，而是基于不确定性的最优估计。

二、扩展卡尔曼滤波（EKF）原理

2.1 从卡尔曼滤波说起

卡尔曼滤波（KF）是线性系统的“最优解”。但现实世界哪有那么多线性？AGV的运动模型、观测模型，几乎全是非线性的。

EKF的思路很直接：把非线性函数在估计点附近做一阶泰勒展开，近似成线性，然后套用KF的公式。

嗯，说白了就是“用切线代替曲线”。

2.2 EKF的五个核心公式

我习惯把EKF分成两步：预测和更新。

预测阶段（时间更新）：

1. 状态预测：x_k|k-1 = f(x_k-1|k-1, u_k)
2. 协方差预测：P_k|k-1 = F_k * P_k-1|k-1 * F_k^T + Q_k

更新阶段（测量更新）：

3. 卡尔曼增益：K_k = P_k|k-1 * H_k^T * (H_k * P_k|k-1 * H_k^T + R_k)^(-1)
4. 状态更新：x_k|k = x_k|k-1 + K_k * (z_k - h(x_k|k-1))
5. 协方差更新：P_k|k = (I - K_k * H_k) * P_k|k-1

看着公式多，其实逻辑很简单：

  • 预测：用运动模型猜下一时刻的位置，同时算一下这个猜测有多不靠谱（协方差变大）
  • 更新：拿到传感器数据后，算一个“加权平均”——模型猜的权重和传感器测的权重，由卡尔曼增益K决定

我的经验：调EKF时，Q矩阵（过程噪声）和R矩阵（测量噪声）是关键。Q设太大，滤波会太“信”传感器，噪声大；R设太大，滤波会太“信”模型，响应慢。我一般先让AGV静止，调R让滤波输出平滑；再让AGV急加速，调Q让跟踪不滞后。

2.3 EKF的局限性

EKF虽好，但有两个硬伤：

  • 线性化误差：强非线性下，一阶近似可能直接崩掉。我记得有次做AGV原地旋转，角度变化剧烈，EKF直接发散，定位飞到地图外面去了。
  • 单峰假设：EKF假设状态是高斯分布，只能有一个“最可能的位置”。如果AGV在对称走廊里，左右都有可能，EKF就懵了。

这时候，就该粒子滤波上场了。

三、粒子滤波原理

3.1 核心思想：用一堆粒子“猜”位置

粒子滤波不搞什么高斯分布。它直接撒一大把粒子，每个粒子代表一个可能的位姿。粒子越密集的地方，真实位置的可能性越大。

流程就三步：

  1. 撒粒子：初始化时，在地图里均匀撒N个粒子（比如500个）
  2. 运动更新：每个粒子根据运动模型“动一下”，再加点随机噪声
  3. 观测更新：用激光数据算每个粒子的权重——跟激光匹配得好的粒子权重大，匹配差的权重小
  4. 重采样：扔掉权重小的粒子，复制权重大的粒子。粒子又回到N个，但都集中在高概率区域

一句话总结：粒子滤波就是用一群“带权重的猜测”来近似真实分布。粒子越多，近似越准，但计算越慢。

3.2 粒子滤波 vs EKF

对比项 EKF 粒子滤波
状态分布 高斯分布（单峰） 任意分布（多峰）
非线性处理 一阶线性近似 直接采样，无近似
计算量 低（O(n³)） 高（O(N)）
适用场景 弱非线性、单峰 强非线性、多峰、全局定位
典型应用 robot_pose_ekf AMCL（自适应蒙特卡洛定位）

你想想看，AGV开机时不知道自己在哪里，这就是全局定位问题。用EKF？它需要一个初始猜测。用粒子滤波？直接全地图撒粒子，几分钟就能收敛到正确位置。

注意：粒子滤波不是万能的。粒子数太少会“粒子贫乏”——所有粒子都挤到一个小区域，丢了真实位置。我遇到过粒子数从1000降到200，定位精度直接掉了一个数量级。一般建议500-2000个粒子，根据你的CPU性能来。

四、robot_pose_ekf包使用实战

4.1 包的作用

robot_pose_ekf是ROS官方提供的EKF融合包。它把里程计、IMU、视觉里程计（如果有）的数据融合成一个odom_combined话题，发布在odom坐标系下。

说白了，你给它三个输入，它给你一个更准的输出。

4.2 安装与配置

# 安装
sudo apt install ros-noetic-robot-pose-ekf

# 启动
roslaunch robot_pose_ekf robot_pose_ekf.launch

配置文件robot_pose_ekf.launch长这样：

<launch>
  <node pkg="robot_pose_ekf" type="robot_pose_ekf" name="robot_pose_ekf">
    <param name="output_frame" value="odom"/>
    <param name="base_footprint_frame" value="base_footprint"/>
    
    <!-- 传感器输入 -->
    <param name="odom_used" value="true"/>
    <param name="imu_used" value="true"/>
    <param name="vo_used" value="false"/>
    
    <!-- 调试输出 -->
    <param name="debug" value="false"/>
    <param name="self_diagnose" value="false"/>
  </node>
</launch>

4.3 关键参数调优

我踩过的坑：

  • odom_used：里程计必须开。但如果你用的是差速轮，记得把里程计协方差设大一点（默认可能偏小）
  • imu_used：IMU的yaw角对EKF帮助巨大。但IMU的偏置要提前标定好，否则融合出来的角度会慢慢漂
  • vo_used：视觉里程计，一般AGV上用得少。如果你有RGB-D相机，可以试试

避坑指南：我曾经在AGV上同时开了里程计和IMU，结果EKF输出的位姿反而更差了。查了半天，发现是里程计和IMU的坐标系定义不一致——里程计的yaw是逆时针为正，IMU是顺时针为正。两个正负号打架，EKF直接懵了。所以，一定要确保所有传感器的坐标系约定一致。

4.4 可视化与调试

# 查看融合后的位姿
rostopic echo /robot_pose_ekf/odom_combined

# 在Rviz中查看
rosrun rviz rviz
# 添加Odometry显示，话题选/robot_pose_ekf/odom_combined

在Rviz里，你会看到三条轨迹：原始里程计（红色）、原始IMU（绿色）、融合后的（蓝色）。正常情况下，蓝色应该比红色和绿色都平滑、都准确。

六、总结与建议

今天的内容，说白了就三句话：

  • EKF：简单、高效、适合弱非线性场景。ROS里直接用robot_pose_ekf包，省心
  • 粒子滤波：灵活、鲁棒、适合全局定位和强非线性场景。AMCL就是它的典型应用
  • 实战要点：坐标系一致、噪声矩阵调优、粒子数权衡——这些坑我都替你踩过了

我个人建议，刚开始做AGV定位的同学，先从robot_pose_ekf入手。它配置简单，效果立竿见影。等你把EKF玩熟了，再去看粒子滤波的AMCL，会更容易理解两者的差异。

好了，这一讲就到这里。记住：没有完美的传感器，只有聪明的融合算法。
