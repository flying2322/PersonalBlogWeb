2 ROS环境搭建：ROS Melodic/Noetic安装、工作空间创建、Catkin编译系统、ROS常用命令行工具

好，咱们正式开始动手了。这一章，我带你把ROS环境搭起来。说实话，环境搭建是很多新手的第一道坎，也是我当年踩坑最多的地方。你想想看，一个机器人系统还没跑起来，光装个ROS就折腾半天，确实挺打击人的。不过别担心，我把这些年积累的经验都揉碎了讲给你听。

2.1 ROS版本选择：Melodic还是Noetic？

先聊版本选择。ROS Melodic对应Ubuntu 18.04，ROS Noetic对应Ubuntu 20.04。我个人习惯是：如果你的工控机比较新，直接上Noetic。为什么？因为Noetic是ROS1的最后一个长期支持版本，支持到2025年，而且Python 3的支持更友好。

但有个坑我得提醒你——我曾经在一台老款工控机上装Noetic，结果驱动死活不兼容。后来换成Melodic，一切顺畅。所以，先确认你的硬件和驱动支持情况，再选版本。

版本选择建议：

  • 新工控机（2020年后出厂）→ ROS Noetic + Ubuntu 20.04
  • 老工控机或特殊硬件 → ROS Melodic + Ubuntu 18.04
  • 如果你不确定，先查硬件厂商的驱动支持列表

2.2 ROS Melodic/Noetic安装实战

安装过程其实就几条命令，但顺序很重要。我见过太多人上来就sudo apt install ros-melodic-desktop-full，结果报错一堆。嗯，这里要注意——先配源，再安装。

2.2.1 添加软件源

# 设置sources.list
sudo sh -c 'echo "deb http://packages.ros.org/ros/ubuntu $(lsb_release -sc) main" > /etc/apt/sources.list.d/ros-latest.list'

# 添加密钥
sudo apt-key adv --keyserver 'hkp://keyserver.ubuntu.com:80' --recv-key C1CF6E31E6BADE8868B172B4F42ED6FBAB17C654

这里有个小细节：$(lsb_release -sc)会自动识别你的Ubuntu版本。如果你是Ubuntu 18.04，它会自动填bionic；20.04就是focal。省得你手动改。

2.2.2 安装ROS

# 更新软件包索引
sudo apt update

# 安装完整桌面版（推荐）
sudo apt install ros-noetic-desktop-full

# 或者安装基础版（省空间）
# sudo apt install ros-noetic-ros-base

我个人建议：除非你的硬盘空间真的吃紧，否则直接装desktop-full。为什么？因为后面做SLAM导航，你会用到Rviz、Gazebo、各种工具包。分开装容易漏，到时候缺一个包又得回头补，麻烦。

2.2.3 初始化rosdep

sudo rosdep init
rosdep update

这一步很多人会卡住。如果你遇到网络问题，rosdep init报错，可以试试手动创建配置文件。我曾经在客户现场，网络环境特别差，折腾了半小时才搞定。后来我学乖了——提前把/etc/ros/rosdep/sources.list.d/20-default.list文件准备好，直接拷贝过去。

2.2.4 设置环境变量

echo "source /opt/ros/noetic/setup.bash" >> ~/.bashrc
source ~/.bashrc

这一步千万别漏。不然后面每次开终端都要手动source，烦得很。

2.2.5 验证安装

roscore

如果能看到类似下面的输出，恭喜你，ROS装好了：

... logging to /home/yourname/.ros/log/...
started roslaunch server http://...
ros_comm version 1.15.14

小技巧： 安装完成后，可以用rospack list查看所有已安装的包。如果列表很长，说明安装成功。如果只有寥寥几个，那可能装的是基础版。

2.3 工作空间创建

工作空间，说白了就是你放代码的地方。ROS的工作空间有标准结构，我建议你从一开始就养成好习惯。

2.3.1 创建工作空间

mkdir -p ~/catkin_ws/src
cd ~/catkin_ws/src
catkin_init_workspace

这里catkin_init_workspace会在src目录下生成一个CMakeLists.txt文件。嗯，这个文件是链接到系统CMake的，别删它。

2.3.2 编译工作空间

cd ~/catkin_ws
catkin_make

第一次编译会生成build和devel两个目录。编译成功后，你会看到：

Base path: /home/yourname/catkin_ws
Source space: /home/yourname/catkin_ws/src
Build space: /home/yourname/catkin_ws/build
Devel space: /home/yourname/catkin_ws/devel
Install space: /home/yourname/catkin_ws/install
####
#### Running command: "make cmake_check_build_system" in "...
####

2.3.3 设置工作空间环境变量

echo "source ~/catkin_ws/devel/setup.bash" >> ~/.bashrc
source ~/.bashrc

这里要注意：如果你同时source了ROS系统环境和自己的工作空间，后source的会覆盖前面的。所以我建议把工作空间的source放在.bashrc的最后一行。

避坑指南： 我曾经遇到一个同事，他在.bashrc里source了两次同一个工作空间，结果编译时总是报奇怪的链接错误。排查了半天才发现是环境变量重复了。所以，检查一下你的.bashrc，确保没有重复的source。

2.4 Catkin编译系统

Catkin是ROS的官方编译系统，说白了就是CMake的ROS定制版。你想想看，一个机器人项目可能有几十个包，每个包有自己的依赖关系。Catkin就是帮你管理这些依赖的。

2.4.1 Catkin工作空间结构

目录 作用
src 存放源码包，每个包有自己的CMakeLists.txt和package.xml
build 编译过程中的中间文件，CMake缓存等
devel 编译生成的可执行文件、库文件、头文件等
install 安装目录（使用catkin_make install时生成）

2.4.2 常用编译命令

# 编译整个工作空间
catkin_make

# 只编译某个包
catkin_make --only-pkg-with-deps your_package_name

# 编译并安装
catkin_make install

# 清理编译文件
catkin_make clean

我个人习惯：开发阶段用catkin_make就够了。如果项目大了，可以考虑用catkin_tools，它支持并行编译，速度更快。

2.4.3 package.xml详解

每个ROS包都必须有一个package.xml。它就像包的身份证，告诉Catkin这个包叫什么、依赖谁、谁写的。

<?xml version="1.0"?>
<package format="2">
  <name>agv_navigation</name>
  <version>0.0.1</version>
  <description>AGV激光SLAM导航包</description>
  <maintainer email="yourname@example.com">Your Name</maintainer>
  <license>BSD</license>

  <buildtool_depend>catkin</buildtool_depend>

  <depend>roscpp</depend>
  <depend>std_msgs</depend>
  <depend>sensor_msgs</depend>
  <depend>nav_msgs</depend>
  <depend>tf</depend>
  <depend>move_base</depend>
  <depend>amcl</depend>
</package>

这里要注意<depend>和<build_depend>的区别。<depend>表示编译和运行时都需要，<build_depend>只编译时需要。我一般都用<depend>，省事。

2.5 ROS常用命令行工具

ROS的命令行工具，说白了就是你的瑞士军刀。调试、排查问题全靠它们。我列几个最常用的：

2.5.1 核心工具

命令 作用 常用参数
roscore 启动ROS主节点 无
rosrun 运行单个节点 rosrun [包名] [节点名]
roslaunch 启动多个节点 roslaunch [包名] [launch文件]
rostopic 查看/发布话题 rostopic list, echo, pub
rosservice 调用服务 rosservice list, call
rosparam 操作参数服务器 rosparam list, get, set
rqt_graph 可视化节点关系图 无

2.5.2 调试利器：rostopic

这个命令我几乎天天用。比如你想看看激光雷达有没有数据：

# 列出所有话题
rostopic list

# 查看激光数据
rostopic echo /scan

# 查看话题频率
rostopic hz /scan

# 手动发布一个速度指令
rostopic pub /cmd_vel geometry_msgs/Twist "linear:
  x: 0.5
  y: 0.0
  z: 0.0
angular:
  x: 0.0
  y: 0.0
  z: 0.1"

我曾经在调试AGV时，发现小车不走。用rostopic echo /cmd_vel一看，发现话题根本没数据。排查了半天，原来是导航节点的输出话题名拼错了。这种问题，用命令行工具几分钟就能定位。

2.5.3 可视化工具：rqt_graph

这个工具能画出所有节点和话题的关系图。当你面对一个复杂的机器人系统，节点之间关系乱成一团时，rqt_graph就是你的救星。

rosrun rqt_graph rqt_graph

它会弹出一个窗口，显示节点（椭圆）和话题（矩形）的连接关系。箭头方向表示数据流向。我一般用它来检查：

  • 节点是否都启动了
  • 话题连接是否正确
  • 有没有孤立的节点
