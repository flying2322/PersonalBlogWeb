17 局部路径规划：DWA算法、TEB算法、MPC控制、动态窗口参数调优

局部路径规划，说白了就是让AGV在“当下”怎么走。全局规划给了你一条大方向，但实际跑起来，前面突然冒出个纸箱、地上有个坑，你得自己想办法绕过去。这就是局部规划干的事。

我这些年折腾下来，最常用的就是DWA、TEB和MPC这三板斧。它们各有脾气，也各有绝活。今天咱们就掰开揉碎了聊聊。

17.1 DWA算法：动态窗口法

DWA全称是Dynamic Window Approach。名字挺唬人，核心思想其实很简单：在速度空间里采样，找一条最安全、最快的路。

你想想看，AGV能跑多快、能转多急，是有物理极限的。DWA就在这个“动态窗口”里，生成一堆候选速度对（线速度v，角速度ω），然后挨个打分。

核心三要素：

  • 方位角评价：朝着目标方向走的，得分高
  • 障碍物距离评价：离障碍物越远，得分高
  • 速度评价：跑得越快，得分高

我在项目里遇到过一个问题：AGV在窄通道里来回摇摆，就是过不去。后来发现是障碍物距离评价的权重设得太低了，车总想贴着墙走。调高权重后，车就老实了。

DWA的伪代码长这样：

// DWA核心伪代码
function dwa_control(robot_pose, goal, obstacles):
    // 1. 计算动态窗口
    v_min = max(0, current_v - max_accel * dt)
    v_max = min(max_v, current_v + max_accel * dt)
    w_min = max(-max_w, current_w - max_alpha * dt)
    w_max = min(max_w, current_w + max_alpha * dt)
    
    best_traj = null
    best_score = -inf
    
    // 2. 采样速度对
    for v in [v_min : v_resolution : v_max]:
        for w in [w_min : w_resolution : w_max]:
            // 3. 模拟轨迹
            traj = simulate_trajectory(robot_pose, v, w, dt)
            
            // 4. 碰撞检测
            if collision_detected(traj, obstacles):
                continue
            
            // 5. 评价打分
            heading_score = calc_heading(traj, goal)
            dist_score = calc_clearance(traj, obstacles)
            vel_score = abs(v) / max_v
            
            total_score = alpha * heading_score 
                        + beta * dist_score 
                        + gamma * vel_score
            
            if total_score > best_score:
                best_score = total_score
                best_traj = traj
    
    return best_traj

调参小技巧：

我习惯先调beta（障碍物距离权重），保证安全。再调alpha（方位角权重），让车别跑偏。最后调gamma（速度权重），别让车太怂。

17.2 TEB算法：时间弹性带

TEB，全称Timed Elastic Band。它把路径看成一条“橡皮筋”，可以拉伸、压缩，但必须避开障碍物。

DWA只考虑当前时刻，TEB则考虑未来一段时间的轨迹。它优化的是一系列位姿点，每个点都带时间戳。

为什么会这样？因为TEB把路径规划转化成了一个稀疏图优化问题。节点是位姿，边是约束（速度、加速度、障碍物距离）。

我记得有一次做仓储AGV，货架之间的通道只有80cm宽。DWA死活过不去，换成TEB后，车像泥鳅一样滑过去了。原因就是TEB能“预判”未来几秒的位姿，提前调整方向。

TEB的优化目标函数：

// TEB优化目标
minimize: 
    J = w_path * f_path +        // 路径长度
        w_time * f_time +        // 总时间
        w_obstacle * f_obstacle + // 障碍物距离
        w_vel * f_velocity +     // 速度约束
        w_acc * f_acceleration   // 加速度约束

注意：TEB计算量比DWA大不少。如果AGV的算力有限（比如用STM32），建议把优化迭代次数控制在10次以内。我踩过这个坑，车跑着跑着就卡住了。

17.3 MPC控制：模型预测控制

MPC，Model Predictive Control。它和TEB有点像，但更“硬核”。MPC基于系统的动力学模型，预测未来N步的状态，然后求解一个带约束的最优控制问题。

说白了，MPC是“算一步，看三步”。每一步都重新计算，所以鲁棒性很强。

MPC的典型流程：

  1. 建立模型：AGV的运动学模型（差速、阿克曼等）
  2. 预测未来：给定控制序列，预测未来N步的状态
  3. 求解优化：最小化跟踪误差和控制代价
  4. 执行第一步：只执行第一个控制量
  5. 滚动优化：下一时刻重复1-4

我在做重载AGV（载重5吨）时，必须用MPC。因为惯性大，DWA和TEB都控制不住，车会冲出安全边界。MPC能显式地把加速度、角速度约束写进优化问题里，保证不翻车。

一个简化的MPC代码框架：

// MPC核心步骤
function mpc_control(state_ref, state_current):
    // 1. 初始化优化问题
    Q = diag([q_x, q_y, q_theta])  // 状态权重
    R = diag([r_v, r_w])           // 控制权重
    
    // 2. 构建预测模型（差速模型）
    for k in 0:N-1:
        x_k+1 = x_k + v_k * cos(theta_k) * dt
        y_k+1 = y_k + v_k * sin(theta_k) * dt
        theta_k+1 = theta_k + w_k * dt
    
    // 3. 求解二次规划
    min J = sum(||state_k - state_ref_k||^2_Q) 
          + sum(||control_k||^2_R)
    subject to:
        v_min <= v_k <= v_max
        w_min <= w_k <= w_max
        acc_min <= (v_k+1 - v_k)/dt <= acc_max
    
    // 4. 返回第一个控制量
    return control_0

我的经验：MPC的预测时域N一般取10-20。N太小，效果和DWA差不多；N太大，算不过来。实时性要求高的场景，N取10就够了。

17.4 动态窗口参数调优

不管用DWA、TEB还是MPC，最终都要面对参数调优。我总结了一套“三步走”的方法：

步骤 做什么 怎么调
第一步 调安全参数 增大障碍物距离权重，减小最大速度
第二步 调效率参数 增大速度权重，减小加速度限制
第三步 调平滑参数 增大转角代价，减小角速度变化率

我曾经在一个项目里，光调参数就花了两天。后来发现是动态窗口的采样分辨率设得太粗了。把v_resolution从0.1降到0.05，w_resolution从0.2降到0.1，路径立马顺滑了。

避坑指南：我曾经把最大加速度设得太大，结果AGV启动时直接打滑，里程计都飞了。加速度一定要根据电机和地面摩擦系数来算，别拍脑袋。

17.5 三种算法对比

最后给个对比表，方便你选型：

算法 优点 缺点 适用场景
DWA 计算快、实现简单 只考虑当前时刻，容易陷入局部最优 轻载AGV、低速场景
TEB 轨迹平滑、能过窄通道 计算量中等，参数多 仓储AGV、窄通道场景
MPC 鲁棒性强、能处理约束 计算量大、建模复杂 重载AGV、高速场景

嗯，局部路径规划就聊到这儿。记住一句话：没有最好的算法，只有最合适的参数。多动手调，多跑仿真，你也能成为调参大师。

核心要点回顾：

  • DWA：速度空间采样，适合快速响应
  • TEB：时间弹性带优化，适合复杂环境
  • MPC：模型预测控制，适合高动态场景
  • 参数调优：安全→效率→平滑，三步走
