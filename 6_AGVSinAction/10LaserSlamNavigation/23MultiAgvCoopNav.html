23 多AGV协同导航：通信机制、交通管制、路径冲突解决、编队控制基础

各位做AGV的朋友，你们有没有遇到过这种情况？

一台车跑得好好的，两台车一碰面，直接堵死。或者更惨，三台车在十字路口互相让路，结果谁都不走。

这就是多AGV协同导航要解决的问题。说白了，就是让一群机器人像人类司机一样，有秩序地共享道路资源。

23.1 通信机制：AGV之间怎么“说话”

多车协同的第一步，是让车与车之间能通信。我见过不少项目，一开始图省事，让每台车独立跑，结果就是各种撞车。

目前主流的通信方式有两种：

  • 点对点通信：每台AGV直接跟调度中心通信，车与车之间不直接对话。这种方式简单，但调度中心一旦挂了，整个系统就瘫痪。
  • 分布式通信：AGV之间通过无线网络（比如Wi-Fi、UWB）直接交换状态信息。每台车都知道周围车的位置、速度、意图。

我个人习惯用混合模式。调度中心负责全局规划，AGV之间做局部协调。这样既保证了全局最优，又提高了实时性。

核心通信内容：每台AGV至少要广播以下信息——

  • 当前位姿（x, y, theta）
  • 当前速度（v, w）
  • 当前任务状态（空闲、行驶中、装卸货）
  • 下一段路径（未来3-5秒的轨迹点）

我曾经在一个项目里吃过亏。通信频率设得太低（只有2Hz），结果两台车都以为对方会让自己，直接怼上了。后来我改成10Hz广播，加上时间戳校验，再没出过问题。

23.2 交通管制：谁先走，谁让行

交通管制，说白了就是给AGV定规矩。没有规矩，再好的算法也白搭。

常见的管制策略有：

  • 区域锁：把地图分成若干区域，每台车进入前先申请锁。锁被占用就排队等待。
  • 优先级调度：根据任务紧急程度、车辆类型、剩余电量等，动态分配路权。
  • 时间窗分配：给每台车分配通过某个路口的时间段，避免同时到达。

我的经验：区域锁虽然简单，但容易造成死锁。比如A车占了区域1要去区域2，B车占了区域2要去区域1，两车就互相等死。这时候需要加一个死锁检测机制，一旦发现就强制让一台车倒车让路。

嗯，这里要注意。交通管制不是越复杂越好。我见过有人用图论做全局死锁检测，算法跑得比车还慢。对于大多数场景，简单的优先级+超时重试就够用了。

23.3 路径冲突解决：别让两车“亲上”

路径冲突分两种：

  1. 正面冲突：两车在同一条直线上相向而行。
  2. 交叉冲突：两车在路口交叉相遇。

解决思路其实不复杂：

  • 速度调整：让其中一台车减速或停车等待。
  • 路径重规划：让其中一台车绕路走。
  • 动态避障：把对方当成动态障碍物，实时规划局部路径。

你想想看，如果两车在狭窄通道里相遇，谁倒车？我的做法是：先到先得。后到的车自动倒车到最近的避让点。如果两车同时到达，就按ID大小决定谁退让。

避坑指南：我曾经遇到过一个问题——两车在弯道相遇，激光雷达互相看不到对方，结果撞上了。后来我强制要求所有AGV在弯道前广播自己的位置，并且把弯道设为“减速观察区”。

代码实现上，我一般用代价地图来做冲突检测。每台车把自己的未来轨迹投影到代价地图上，如果发现重叠区域，就触发冲突解决逻辑。

// 伪代码：冲突检测与解决
bool checkConflict(AGV a, AGV b) {
    for (auto& pa : a.futureTrajectory) {
        for (auto& pb : b.futureTrajectory) {
            if (distance(pa, pb) < SAFE_DISTANCE) {
                return true;  // 发现冲突
            }
        }
    }
    return false;
}

void resolveConflict(AGV& a, AGV& b) {
    if (a.priority > b.priority) {
        b.slowDown(0.3);  // 低优先级减速
    } else {
        a.slowDown(0.3);
    }
    // 如果减速后仍然冲突，触发重规划
}

23.4 编队控制基础：让AGV排好队

编队控制，就是让多台AGV保持特定队形移动。比如三台车排成一字型，或者V字型。

常用的编队方法有三种：

  • 领航-跟随法：一台车当领队，其他车跟着它走。简单可靠，但领队挂了整个编队就散了。
  • 虚拟结构法：定义一个虚拟的队形框架，每台车占据框架上的一个点。队形移动时，每台车跟踪自己的目标点。
  • 行为法：给每台车定义几个基本行为（如：保持距离、对齐方向、避障），通过加权组合得到最终控制指令。

我个人偏爱领航-跟随法，因为实现起来最直接。但要注意，跟随车不能简单地把领航车的位置当目标点，否则会出现“过冲”现象。

编队控制的关键参数：

参数 说明 典型值
纵向间距 前后车的距离 1.5 - 2.0 米
横向偏移 左右车的距离 0.8 - 1.2 米
角度偏差 跟随车与领航车的航向角差 < 5 度
响应延迟 跟随车对领航车动作的响应时间 < 200 ms

我做过一个编队项目，要求四台AGV排成菱形队形通过一个窄门。一开始总是卡住，后来发现是跟随车的PID参数没调好。领航车一转弯，跟随车就冲过头。我把跟随车的比例系数调低，微分系数调高，问题就解决了。

编队控制还有一个坑——通信延迟。如果跟随车收到的领航车位置是200ms前的，那编队就会像喝醉了一样左右摇摆。我的解决办法是：在跟随车端做一个运动预测，用领航车的历史轨迹外推当前时刻的位置。

// 运动预测示例
Pose predictLeaderPose(Pose history[], int len, double dt) {
    // 用最近两帧计算速度
    double vx = (history[len-1].x - history[len-2].x) / dt;
    double vy = (history[len-1].y - history[len-2].y) / dt;
    // 外推当前时刻位置
    Pose predicted;
    predicted.x = history[len-1].x + vx * COMMUNICATION_DELAY;
    predicted.y = history[len-1].y + vy * COMMUNICATION_DELAY;
    return predicted;
}

小技巧：编队转弯时，内圈的车要减速，外圈的车要加速。这个逻辑如果不做，队形就会扭曲。我一般会根据转弯半径给每台车分配不同的速度系数。

好了，多AGV协同导航的核心内容就这些。通信是基础，交通管制是规则，路径冲突解决是应急，编队控制是进阶。把这四点吃透了，多车系统基本就能跑起来。

最后说一句，别想着一次把所有功能都做全。先让两台车能安全地共享道路，再慢慢加编队、加调度。步子迈大了，容易扯着蛋。
