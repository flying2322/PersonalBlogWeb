16 全局路径规划：Dijkstra算法、A*算法、Hybrid A*算法、路径平滑处理

全局路径规划，说白了就是给AGV找一条从起点到终点的路。你想想看，AGV在工厂里跑，总不能瞎撞吧？得有个“导航地图”，然后算法告诉它怎么走最省时间、最安全。

这一章，我带你过一遍最经典的几个算法：Dijkstra、A*、Hybrid A*，还有路径平滑处理。这些算法我几乎每个项目都碰过，踩过不少坑，今天一并分享给你。

16.1 Dijkstra算法：最朴素的“地毯式搜索”

Dijkstra算法，说白了就是“广度优先搜索”的加权版。它从起点开始，一层一层往外扩，直到找到终点。我刚开始学SLAM时，觉得这算法太笨了——明明终点就在右边，它非得把左边也搜一遍。

但后来我发现，Dijkstra有个好处：一定能找到最短路径。只要地图是静态的，它不会漏掉任何一条可能的路线。

核心思想：维护一个“距离表”，记录从起点到每个节点的最短距离。每次从未访问的节点中选一个距离最小的，然后更新它的邻居。

伪代码长这样：

function Dijkstra(Graph, source):
    dist[source] = 0
    for each vertex v in Graph:
        if v != source:
            dist[v] = INFINITY
        prev[v] = UNDEFINED
        add v to Q  // 优先队列

    while Q is not empty:
        u = vertex in Q with min dist[u]
        remove u from Q

        for each neighbor v of u:
            alt = dist[u] + length(u, v)
            if alt < dist[v]:
                dist[v] = alt
                prev[v] = u
    return dist[], prev[]

嗯，这里要注意：Dijkstra不能处理负权边。我在一个项目中遇到过，地图里有个“下坡路段”被设成了负权值，结果算法直接崩了。后来我改成A*才解决。

我的经验：Dijkstra适合小地图（比如100x100网格以内），或者需要精确最短路径的场景。如果地图很大，它的效率就太低了。

16.2 A*算法：带“方向感”的搜索

A*算法是Dijkstra的升级版。它加了一个“启发式函数”，说白了就是给搜索一个方向感。你想想看，如果终点在右边，A*会优先往右边搜，而不是像Dijkstra那样四面八方乱扩。

A*的核心公式很简单：

f(n) = g(n) + h(n)
  • g(n)：从起点到当前节点n的实际代价
  • h(n)：从节点n到终点的估计代价（启发式函数）
  • f(n)：总代价，算法优先选f(n)最小的节点

启发式函数h(n)怎么选？我常用的有两种：

启发式函数 适用场景 特点
曼哈顿距离 四方向移动（上下左右） 计算快，但可能不是最优
欧几里得距离 八方向移动（可斜走） 更精确，但计算稍慢

我曾经在一个仓库项目里，用曼哈顿距离做A*，结果AGV老是走“之”字形路径，看着特别别扭。后来换成欧几里得距离，路径就顺多了。

注意：如果h(n)估计值比实际值大，A*就退化成Dijkstra了。如果h(n)估计值比实际值小太多，A*可能找不到最短路径。所以h(n)要选得“可采纳”——即不大于实际代价。

16.3 Hybrid A*算法：让路径更“可驾驶”

A*算法虽然快，但它生成的路径是一段段直线，AGV没法直接跟着走——你想想看，AGV有转弯半径，不能像像素点一样瞬间转向。这就是Hybrid A*要解决的问题。

Hybrid A*是A*的变种，它把连续状态空间考虑进去了。说白了，它不光规划位置，还规划朝向和曲率。我最早接触Hybrid A*是在做无人驾驶项目时，当时觉得这算法太巧妙了。

它的核心区别在于：

  • A*：在离散网格上搜索，每个格子只有一个状态
  • Hybrid A*：在连续空间里搜索，每个格子可以有多个状态（不同朝向、速度）

Hybrid A*的搜索过程大致如下：

  1. 从起点开始，用车辆运动模型生成一系列可能的轨迹（比如左转、直行、右转）
  2. 对每条轨迹，计算终点状态（位置+朝向）
  3. 用A*的启发式函数评估这些状态，选最优的继续扩展
  4. 重复直到到达终点附近

伪代码示例：

function HybridAStar(start, goal):
    open_set = PriorityQueue()
    open_set.add(start)
    closed_set = {}

    while not open_set.empty():
        current = open_set.pop()
        if distance(current, goal) < threshold:
            return reconstruct_path(current)

        for each control_input in [steer_left, steer_straight, steer_right]:
            next_state = motion_model(current, control_input)
            if is_collision(next_state):
                continue
            if next_state not in closed_set:
                closed_set.add(next_state)
                next_state.g = current.g + cost(current, next_state)
                next_state.h = heuristic(next_state, goal)
                open_set.add(next_state)
    return failure

我的经验：Hybrid A*的计算量比A*大很多，所以一般会配合“Reeds-Shepp曲线”做终点附近的精确连接。我习惯在距离终点5米以内时，直接用Reeds-Shepp曲线生成路径，而不是继续搜索。

16.4 路径平滑处理：让AGV走得“优雅”

不管是A*还是Hybrid A*，生成的路径都可能存在“折角”或“抖动”。AGV如果直接跟着走，要么急转弯，要么来回晃。所以我们需要做路径平滑处理。

常用的平滑方法有几种：

方法 原理 优点 缺点
B样条曲线 用控制点生成平滑曲线 局部可控，计算快 可能偏离原始路径
贝塞尔曲线 用控制点生成多项式曲线 简单直观 全局影响，调整麻烦
梯度下降平滑 优化路径点，最小化曲率 可保留路径形状 迭代计算，可能慢

我个人最常用的是梯度下降平滑。它的思路很简单：把路径上的每个点看作一个“粒子”，然后施加两种力——

  • 平滑力：让相邻点尽量共线（减小曲率）
  • 吸引力：让点尽量靠近原始路径（不偏离太远）

代码实现大概长这样：

def smooth_path(path, alpha=0.5, beta=0.1, iterations=100):
    """
    alpha: 平滑权重（越大越平滑）
    beta: 吸引权重（越大越贴近原始路径）
    """
    new_path = path.copy()
    for _ in range(iterations):
        for i in range(1, len(path) - 1):
            # 平滑项：让点靠近相邻点的中点
            smooth_term = (new_path[i-1] + new_path[i+1]) / 2 - new_path[i]
            # 吸引项：让点靠近原始路径
            attract_term = path[i] - new_path[i]
            # 更新
            new_path[i] += alpha * smooth_term + beta * attract_term
    return new_path

注意：平滑后的路径一定要做碰撞检测！我曾经有一次平滑做得太猛，路径直接穿墙了。后来我加了一步“碰撞检查+局部调整”，才解决这个问题。
