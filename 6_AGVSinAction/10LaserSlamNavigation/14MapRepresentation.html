14 地图表示方法：占据栅格地图、TSDF地图、ESDF地图、OctoMap八叉树地图

做SLAM这么多年，我越来越觉得一个道理：地图就是机器人的世界观。你给它什么样的地图，它就怎么理解这个世界。

打个比方，你让一个AGV去仓库送货。如果地图是稀疏的，它可能只知道「这里有墙，那里有空」。但如果地图是稠密的，它还能知道「这个货架离我0.5米，那个柱子离我1.2米」。不同的任务，需要不同的地图。

今天咱们就把四种主流地图掰开揉碎讲清楚。嗯，这四种地图我都在实际项目里用过，踩过的坑也不少。

核心观点：没有最好的地图，只有最合适的地图。导航、避障、规划、建图，每个环节对地图的要求都不一样。

14.1 占据栅格地图（Occupancy Grid Map）

这是最经典、最基础的地图表示方法。说白了，就是把空间划分成一个个小格子，每个格子存一个概率值，表示这个格子被占用的可能性。

我最早接触SLAM时用的就是这种地图。那时候做扫地机器人，2D激光雷达扫一圈，每个格子要么是0（空闲），要么是1（占用），要么是0.5（未知）。简单粗暴，但够用。

核心公式：

// 对数几率更新
l(m_i | z_{1:t}) = l(m_i | z_{1:t-1}) + l(m_i | z_t) - l(m_i)

// 其中 l(m_i) = log( p(m_i) / (1 - p(m_i)) )

我的经验：实际项目中，我习惯把初始概率设为0.5（完全未知）。每次激光打到某个格子，就更新它的概率。如果连续多次观测到同一个格子是空闲，概率会趋近0；反之趋近1。这样做的好处是抗干扰能力强——偶尔一次误检测不会导致地图崩掉。

优缺点：

  • 优点：实现简单、计算快、内存占用固定（提前分配好数组就行）
  • 缺点：分辨率固定，无法自适应。你想想看，如果格子设成1cm，100m×100m的地图就要1亿个格子，内存直接爆炸

14.2 TSDF地图（Truncated Signed Distance Function）

TSDF，全称是截断符号距离函数。这个名字听着吓人，其实核心思想很简单：每个体素存一个距离值，表示这个体素到最近物体表面的距离。正数表示在物体外面，负数表示在物体里面，0就是表面。

为什么要「截断」？因为离表面太远的地方，距离值就没意义了。我们只关心表面附近的一小段范围，比如±10cm。超出这个范围，直接截断掉。

我在做RGB-D SLAM时用过TSDF。那时候用Kinect扫一个房间，TSDF地图重建出来的墙面非常平滑，比占据栅格地图细腻多了。

// TSDF更新伪代码
for each voxel v:
    // 计算体素到传感器光心的距离
    d_voxel = distance(v, sensor_origin)
    // 计算体素在深度图上的投影点
    d_proj = depth_image(project(v))
    // 计算符号距离
    sdf = d_proj - d_voxel
    // 截断
    if sdf > truncation_threshold:
        tsdf = 1
    elif sdf < -truncation_threshold:
        tsdf = -1
    else:
        tsdf = sdf / truncation_threshold
    // 加权融合
    tsdf_avg = (tsdf_avg * weight + tsdf) / (weight + 1)
    weight += 1

注意：TSDF地图对传感器精度要求比较高。我曾经用低成本的深度相机做TSDF建图，结果表面全是噪点，根本没法用。后来换了高精度激光雷达，效果才起来。所以，传感器不行的话，别硬上TSDF。

14.3 ESDF地图（Euclidean Signed Distance Field）

ESDF和TSDF有点像，但目的完全不同。TSDF是为了建图，ESDF是为了规划。

ESDF地图里，每个格子存的是到最近障碍物的欧几里得距离。你想想看，这对路径规划有多重要？机器人想知道「我离墙还有多远」，直接查一下ESDF就知道，不用实时计算碰撞检测。

我做过一个AGV项目，在仓库里用ESDF做全局路径规划。效果出奇的好——机器人能贴着货架走，但永远不会撞上。因为ESDF给了它一个「安全距离」的直觉。

ESDF的计算方法：

  1. 先从占据栅格地图或TSDF地图出发
  2. 用快速行进法（Fast Marching Method）或波前传播算法
  3. 从障碍物边界开始，向外一层层扩散距离值
// 波前传播算法（简化版）
queue = all obstacle boundary cells
while queue is not empty:
    cell = queue.pop()
    for each neighbor of cell:
        new_dist = cell.distance + 1  // 假设格子大小为1
        if new_dist < neighbor.distance:
            neighbor.distance = new_dist
            queue.push(neighbor)

关键区别：TSDF存的是到表面的距离（有正负），ESDF存的是到最近障碍物的距离（只有正数）。TSDF用于重建，ESDF用于规划。

14.4 OctoMap八叉树地图

终于说到OctoMap了。这是我最喜欢的地图表示方法之一，因为它解决了占据栅格地图的致命问题——内存爆炸。

OctoMap的思路很聪明：用八叉树来存储空间。如果一个区域全是空闲或者全是占用，就不往下细分了。只有那些包含边界的区域，才递归细分到最高分辨率。

举个例子，一个100m×100m×10m的仓库，如果用1cm分辨率的占据栅格地图，需要10亿个体素，内存至少4GB。但用OctoMap，可能只需要几十MB，因为大部分空间都是空的。

OctoMap的核心操作：

  • 插入观测：从根节点开始，沿着树往下走，更新每个节点的占据概率
  • 剪枝：如果一个节点的所有子节点状态相同，就把子节点删掉，合并到父节点
  • 查询：给定一个3D点，从根节点往下找，直到叶子节点，返回占据概率
// OctoMap插入观测伪代码
function insert_observation(node, point, sensor_origin):
    if node.is_leaf():
        node.update_probability(point, sensor_origin)
        return
    child_index = get_child_index(point, node.center)
    insert_observation(node.children[child_index], point, sensor_origin)
    // 剪枝检查
    if all children have same state:
        node.merge_children()

我的建议：如果你做的是大场景3D建图，比如室外园区或者大型仓库，OctoMap几乎是唯一的选择。ROS里也有现成的octomap库，直接拿来用就行。不过要注意，OctoMap的更新速度比占据栅格地图慢一些，因为涉及树的遍历和剪枝。

14.5 四种地图的对比总结

特性 占据栅格地图 TSDF地图 ESDF地图 OctoMap
数据结构 2D/3D数组 3D体素网格 3D体素网格 八叉树
存储内容 占据概率 截断符号距离 欧几里得距离 占据概率
内存效率 低（固定分辨率） 中 中 高（自适应）
主要用途 2D导航、避障 3D重建、SLAM 运动规划 大场景3D建图
更新速度 快 中 慢（需全局计算） 中
ROS支持 map_server, costmap_2d voxblox, chisel voxblox, fiesta octomap_server

嗯，看到这里你应该明白了。没有哪种地图是万能的。做2D导航，占据栅格地图就够了。做3D重建，TSDF是首选。做路径规划，ESDF最顺手。做大场景，OctoMap最省内存。

我个人习惯是：先根据任务选地图，再根据地图选算法。别一上来就想着用最炫酷的，适合的才是最好的。

避坑指南：我曾经在一个项目里，用TSDF地图去做路径规划，结果发现每次查距离都要遍历整个体素网格，慢得要死。后来换成ESDF，速度提升了10倍。所以，建图用TSDF，规划用ESDF，这个原则别搞混了。

好了，这四种地图就讲到这里。每种地图都有它的脾气，摸透了就好用。下次你遇到地图选型的问题，不妨回头看看这张对比表，应该能帮你少走不少弯路。
