1 死锁现象初探：什么是AGV死锁？

大家好，我是老张。在AGV调度这行摸爬滚打了十几年，今天咱们来聊聊一个让所有项目经理都头疼的问题——死锁。

死锁这东西，说白了就是一群AGV在某个区域互相堵住，谁也动不了。你想想看，一个车间里几十台AGV跑来跑去，突然全都卡住了，产线停摆，老板急得跳脚。嗯，我当年第一次遇到这情况时，还以为是程序bug，查了三天三夜才发现是死锁。

1.1 死锁的直观理解

先别急着看公式和定义。咱们用个生活化的例子来理解。

假设你开车到了一个十字路口。你从东往西走，我从南往北走。你到了路口中间，我也到了路口中间。你挡着我，我挡着你。谁都想先走，但谁都不让。结果就是——大家都动不了。

这就是死锁。AGV死锁本质上是一样的：
多台AGV在共享资源（比如路径交叉点、工位、充电站）上互相等待，形成循环依赖，导致系统整体瘫痪。

死锁的四个必要条件（Coffman条件）：

  1. 互斥：资源一次只能被一台AGV占用
  2. 持有并等待：AGV占着资源不放，同时等待其他资源
  3. 不可剥夺：资源不能被强制拿走
  4. 循环等待：形成闭环等待链

这四个条件缺一不可。只要打破任意一个，死锁就能解除。

1.2 一个简单的十字路口死锁案例

咱们来看一个最经典的场景。我画了个示意图，你一看就明白。

你看这张图。四台AGV（A、B、C、D）同时到达十字路口。每台车都想穿过路口，但每台车都被另一台车挡住了去路。

  • AGV A（蓝色）从东往西走，被C挡住了
  • AGV B（橙色）从南往北走，被A挡住了
  • AGV C（绿色）从西往东走，被D挡住了
  • AGV D（紫色）从北往南走，被B挡住了

这就形成了一个完美的循环等待链：A→C→D→B→A。谁也别想走。

💡 个人经验：我在项目里见过最离谱的死锁，是12台AGV在一个环形走廊里堵成一圈。当时监控画面看起来就像个「AGV贪吃蛇」。后来我们花了整整两天才手动解开。从那以后，我设计系统时第一件事就是考虑死锁预防。

1.3 死锁的代价

死锁不是小事。我给大家算笔账：

影响维度 具体表现 典型损失
生产效率 产线停摆，物料无法配送 每小时损失数万到数十万
设备寿命 AGV电机长时间堵转，电池过放 缩短设备寿命30%以上
系统可靠性 调度系统崩溃，需要人工干预 恢复时间从几分钟到几小时
安全风险 人工介入时可能发生碰撞 设备损坏或人员受伤

⚠️ 避坑指南：我曾经在一个项目中，客户为了省钱，只部署了10台AGV，觉得死锁概率低。结果投产第三天就发生了死锁，整个仓库瘫痪了4小时。后来我们紧急加装了死锁检测模块，才算稳住。所以我的建议是：不管AGV数量多少，死锁检测必须从一开始就设计进去。别等出了事再补，那代价太大了。

1.4 死锁检测的基本思路

那么，怎么知道系统里有没有死锁呢？

说白了就两步：

  1. 建图：把AGV和资源的关系画成一张图。AGV是节点，等待关系是边。
  2. 找环：在这张图里找循环。有环，就有死锁。

我习惯用资源分配图（RAG）来做这件事。每个资源（路口、工位、路段）和每个AGV都作为一个节点。如果AGV占用了资源，画一条从AGV到资源的边；如果AGV在等待资源，画一条从资源到AGV的边。

然后，用深度优先搜索（DFS）或者拓扑排序来找环。找到环，就找到了死锁。

// 伪代码：死锁检测核心逻辑
function detectDeadlock(agvList, resourceList):
    // 1. 构建资源分配图
    graph = buildRAG(agvList, resourceList)
    
    // 2. 对每个节点做DFS找环
    for each node in graph.nodes:
        if node not visited:
            if dfsFindCycle(node, graph):
                return true  // 发现死锁
    
    return false  // 无死锁

function dfsFindCycle(node, graph):
    mark node as visiting
    for each neighbor in graph.getNeighbors(node):
        if neighbor is visiting:
            return true  // 找到环
        if neighbor not visited:
            if dfsFindCycle(neighbor, graph):
                return true
    mark node as visited
    return false

这段代码看着简单，但实际项目中要考虑的东西多得多。比如：

  • AGV的路径是动态变化的，图要实时更新
  • 多个路口可能形成嵌套死锁
  • 检测频率太高会影响性能，太低又可能漏检

核心要点：

  • 死锁的本质是循环等待
  • 十字路口是最简单的死锁场景
  • 死锁检测的核心是找环
  • 预防胜于治疗，设计阶段就要考虑
