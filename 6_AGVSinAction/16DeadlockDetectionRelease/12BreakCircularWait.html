12 死锁预防：破坏循环等待（资源有序分配法）

死锁预防这事儿，说白了就是「别让死锁发生」。

我们上一章聊了死锁的四个必要条件。今天要讲的，就是直接对其中一个条件下手——破坏循环等待。

我个人习惯把这种方法叫做「资源有序分配法」。名字听着挺学术，其实道理很简单：给所有资源排个队，AGV只能按顺序申请。

为什么循环等待会发生？

你想想看，AGV调度系统里，死锁最常见的样子是什么？

AGV_A 占了路口1，想去路口2。
AGV_B 占了路口2，想去路口3。
AGV_C 占了路口3，想去路口1。

这不就闭环了嘛。谁也别想动。

我在项目里遇到过好几次这种场景。有一次在仓库里，三台AGV在十字路口堵成一团，调度系统直接卡死。后来一查日志，就是典型的循环等待。

资源有序分配法的核心思想

给每个资源（比如路口、充电站、装卸点）分配一个唯一的编号。
AGV 申请资源时，必须按照编号从小到大的顺序来。

举个例子：

  • 路口1 编号 1
  • 路口2 编号 2
  • 路口3 编号 3

AGV 想从路口1 到路口3，必须先申请 1，再申请 2，最后申请 3。
不能跳着申请，更不能倒着来。

核心原则：所有AGV必须按照资源编号递增的顺序申请资源。

为什么这样能预防死锁？

因为循环等待的条件被破坏了。

假设所有AGV都按编号从小到大申请资源，那么：

  • 持有大编号资源的AGV，不可能去申请小编号资源
  • 持有小编号资源的AGV，只能申请更大的编号

这样一来，资源申请的方向永远是单向的。闭环？不存在的。

我的经验：我曾经在一个大型物流中心部署这套方案。刚开始觉得编号规则很简单，结果发现资源数量一多，编号管理就乱了。后来我建议用「区域+层级」的方式编号，比如 1-1、1-2、2-1，这样扩展性更好。

资源编号怎么定？

嗯，这里要注意。编号不是随便给的。

我一般遵循这几个原则：

  1. 全局唯一：每个资源只有一个编号，不能重复
  2. 物理位置相关：靠近入口的编号小，靠近出口的编号大
  3. 层级清晰：主路径资源编号小，分支路径编号大

举个例子，一个仓库的路径资源编号可以这样设计：

资源类型 编号范围 说明
主通道路口 1 - 50 优先级最高，先申请
货架区路口 51 - 200 次优先级
充电站 201 - 250 最后申请

代码示例：资源有序分配检查

下面是我在项目中用过的检查逻辑，判断AGV申请资源是否合法：

def check_resource_order(agv_id, current_resources, new_resource):
    """
    检查AGV申请新资源是否满足有序分配原则
    :param agv_id: AGV编号
    :param current_resources: 当前已占用的资源编号列表
    :param new_resource: 新申请的资源编号
    :return: True 合法，False 非法
    """
    if not current_resources:
        # 没有占用任何资源，可以申请任意编号
        return True
    
    # 获取当前占用的最大资源编号
    max_held = max(current_resources)
    
    # 新资源编号必须大于当前最大编号
    if new_resource <= max_held:
        print(f"AGV {agv_id} 申请资源 {new_resource} 失败，"
              f"当前最大资源编号为 {max_held}")
        return False
    
    return True

# 使用示例
agv_1_resources = [1, 2]  # 已占用路口1和2
new_resource = 3          # 想申请路口3
if check_resource_order("AGV_001", agv_1_resources, new_resource):
    print("申请合法，允许通行")
else:
    print("申请非法，拒绝通行")

避坑指南：我曾经犯过一个错误——只检查了申请顺序，没考虑释放顺序。AGV释放资源时，如果先释放小编号资源，后释放大编号资源，可能会造成其他AGV「插队」。后来我加了一条规则：释放资源必须按编号从大到小释放。

资源有序分配法的优缺点

优点 缺点
实现简单，逻辑清晰 资源编号需要全局规划，灵活性差
死锁预防效果可靠 AGV可能绕路，降低效率
不需要额外的死锁检测机制 资源编号变更时，需要重新规划

实际项目中的调整

说实话，纯理论的有序分配法在实际中很少直接套用。为什么？因为AGV的路径不是线性的。

我在一个项目中做过调整：

  • 把「资源」从「路口」改成「路径段」
  • 每个路径段按起点到终点的方向编号
  • AGV只能沿着编号递增的方向移动

这样既保留了有序分配的思想，又更贴合实际路径规划。

一句话总结：资源有序分配法，就是给资源排个队，让AGV按顺序申请。简单、有效，但需要结合实际场景做调整。

嗯，死锁预防这块，破坏循环等待是最容易落地的方法之一。我建议你在设计调度系统时，优先考虑这个方案。毕竟，能预防的问题，何必等到检测和解除呢？
