18 死锁检测与解除实战：单行线场景下的死锁处理

18.1 单行线场景：一个经典死锁模型

各位做AGV调度，肯定遇到过这种场景：

一条窄巷子，只能走一辆车。两边各来一辆，面对面堵住了。谁也别想动。

这就是单行线死锁。说白了，就是双向交通管制没做好。

我在项目里遇到过最夸张的一次，三条单行线交叉，堵了8台车。现场工程师打电话说“车全停了，像僵尸一样”。嗯，那次之后我专门写了个死锁检测模块。

18.2 死锁检测：怎么判断“堵死了”？

检测死锁，核心就一句话：找环路。

每台车占一个位置，申请下一个位置。如果A等B的位置，B等C的位置，C又等A的位置，那就是死锁。

我习惯用资源分配图来建模。节点是车，边是“我在等你”。

死锁检测算法（简化版）：

  • 遍历所有等待中的车
  • 从每台车出发，沿着“等待链”走
  • 如果走回起点，说明有环 → 死锁

代码实现其实不复杂。我贴一段核心逻辑：

def detect_deadlock(vehicles):
    """
    vehicles: dict, key=车ID, value=当前占用的路段ID
    返回死锁环路上的车辆列表
    """
    waiting_graph = {}
    for v in vehicles:
        next_segment = get_next_segment(v)
        if next_segment and is_occupied(next_segment):
            owner = get_owner(next_segment)
            waiting_graph[v] = owner
    
    # DFS找环
    visited = set()
    for start in waiting_graph:
        if start in visited:
            continue
        path = []
        current = start
        while current and current not in visited:
            visited.add(current)
            path.append(current)
            current = waiting_graph.get(current)
        if current and current in path:
            # 找到环
            cycle_start = path.index(current)
            return path[cycle_start:]
    return None

避坑指南：我曾经在检测时只检查了“直接等待”，忽略了“间接等待”。结果死锁已经形成，但检测模块说“一切正常”。后来加了递归搜索，才把问题解决。

18.3 死锁解除：怎么“解扣”？

检测到死锁，下一步就是解除。单行线场景下，我常用的方法有三种：

方法 原理 适用场景
预留点让车 让一台车倒车到避让区 有避让点的单行线
路径重规划 给其中一台车找新路 有替代路径的网络
强制调度 人工介入，手动挪车 紧急情况，无其他方案

我个人最推荐预留点让车。为什么呢？因为单行线场景下，重规划往往不现实——旁边根本没路。

具体做法：

  • 在单行线两端或中间，设置避让区
  • 死锁时，让环路上优先级最低的车倒车进避让区
  • 其他车先通过，再让避让车出来

注意：倒车操作有风险。一定要确保倒车路径上没有其他车，而且避让区足够长。我见过一次倒车撞到后方车辆的事故，就是因为避让区长度算错了。

18.4 实战案例：一个完整的死锁处理流程

拿我去年做的一个项目举例。仓库里有条30米长的单行线，两端各有一个工作站。那天来了4台车，两两相对，堵在中间。

检测模块很快发现了环路：

死锁环: [AGV_03, AGV_07, AGV_05, AGV_01]
等待关系:
  AGV_03 → AGV_07
  AGV_07 → AGV_05
  AGV_05 → AGV_01
  AGV_01 → AGV_03

解除步骤：

  1. 选出优先级最低的车：AGV_05（任务最不紧急）
  2. 命令AGV_05倒车到最近的避让区（距离8米）
  3. 其他三台车依次通过
  4. AGV_05从避让区驶出，继续执行任务

整个过程耗时约45秒。如果没做死锁检测，这几台车可能堵到天荒地老。

18.5 单行线场景下的设计建议

最后，给各位几个实用建议：

  • 设计阶段就考虑死锁：单行线尽量设计成环线，或者加避让区
  • 检测频率别太高：我一般每2秒检测一次，太频繁浪费算力
  • 解除操作要记录日志：方便事后分析，优化调度策略
  • 留好人工干预接口：自动解除失败时，能快速切到手动模式

一句话总结：单行线死锁，检测靠找环，解除靠让车。提前设计好避让区，比事后想办法强十倍。
