4 路径规划基础：环境建模、拓扑地图、栅格地图、A*算法原理

各位同学，欢迎来到第四章。

前面我们聊了AGV的硬件、通信和调度架构。但有个核心问题一直没解决——车到底该怎么走？

你想想看，一辆AGV在车间里跑，它要知道自己从A点到B点，中间有没有障碍物，哪条路最近，哪条路不堵车。这就是路径规划要干的事。

我个人习惯把路径规划拆成两步：第一步，把现实世界变成计算机能理解的数据结构（环境建模）；第二步，在这个数据结构上找出一条最优路径（搜索算法）。

好，我们一步步来。

4.1 环境建模：把物理世界“翻译”给机器

AGV不像人，它没有“直觉”。它需要我们把车间、仓库、走廊这些物理空间，用一种它看得懂的方式描述出来。

说白了，环境建模就是“翻译”。

常见的建模方式有三种：

  • 拓扑地图：只保留节点和连接关系，像地铁线路图。
  • 栅格地图：把空间切成一个个小格子，每个格子标记“可通行”或“障碍物”。
  • 几何地图：用精确的坐标和几何形状描述环境，比如激光SLAM建出来的图。

在AGV调度系统里，拓扑地图和栅格地图用得最多。几何地图通常用于单车的定位和避障，不太适合多车协同的全局规划。

核心观点：环境建模没有“最好”，只有“最合适”。拓扑地图轻量、快，适合大范围路径规划；栅格地图精细、灵活，适合局部避障和动态环境。

4.2 拓扑地图：用“点”和“线”说话

拓扑地图，说白了就是一张“节点-边”图。

节点代表关键位置，比如工位、充电站、交叉口、货架入口。边代表可通行的路径，比如一段直道、一个转弯。

我在项目中遇到过这样一个场景：一个汽车零部件仓库，面积很大，但AGV只走固定路线。如果用栅格地图，整个仓库几千平米全要建图，数据量太大。后来我改用拓扑地图，只标注了30多个节点和50多条边，调度系统跑起来飞快。

拓扑地图的构建要点：

  • 节点要“有意义”：不是随便一个点都能当节点。必须是AGV需要停、需要拐弯、需要决策的地方。
  • 边要“可通行”：每条边都要确认AGV能安全通过，包括宽度、转弯半径、地面承重等。
  • 权重要“真实”：边的权重不只是距离，还要考虑时间、能耗、拥堵概率。我曾经吃过亏，只按距离算权重，结果AGV全挤到一条近路上，堵成一锅粥。

我的经验：拓扑地图适合结构化环境，比如工厂车间、仓库通道。如果环境经常变化（比如临时堆货），拓扑地图维护起来会很痛苦。这时候栅格地图更合适。

4.3 栅格地图：把世界切成“像素”

栅格地图的思路很直观：把环境划分成一个个大小相同的格子（比如10cm×10cm），每个格子标记为“空闲”、“占用”或“未知”。

你想想看，这就像一张黑白像素图。白色格子可以走，黑色格子不能走。

栅格地图的优缺点：

优点 缺点
实现简单，容易理解 网格大小影响精度和性能
容易融合传感器数据（激光、超声波） 大范围环境内存占用高
适合动态障碍物更新 路径可能不够平滑（锯齿状）

我记得有一次做AGV项目，客户要求AGV在仓库里能绕开临时堆放的货物。拓扑地图改起来太麻烦，我直接上了栅格地图。AGV每扫描到新障碍物，就把对应格子标记为“占用”，路径规划自动避开。效果立竿见影。

注意：栅格地图的网格大小很关键。网格太大，路径精度不够，AGV可能撞到障碍物；网格太小，计算量爆炸，实时性跟不上。我个人建议：网格大小取AGV宽度的一半到三分之一。比如AGV宽80cm，网格设30cm左右比较合适。

4.4 A*算法原理：启发式搜索的“扛把子”

地图建好了，接下来就是找路。在AGV领域，A*算法是绝对的主流。

为什么是A*？因为它比Dijkstra快，比BFS聪明。

A*的核心公式：

F(n) = G(n) + H(n)
  • G(n)：从起点到当前节点n的实际代价（已经花掉的路程）。
  • H(n)：从当前节点n到终点的估计代价（还要花多少，通常用曼哈顿距离或欧几里得距离）。
  • F(n)：总代价，A*每次选F值最小的节点去探索。

说白了，A*就是“既要看过去，也要看未来”。Dijkstra只看过去（G值），所以它像个无头苍蝇一样四面八方乱搜。A*有了H值的引导，会朝着终点方向优先搜索，效率高得多。

A*算法的基本步骤：

  1. 把起点加入Open List（待探索列表）。
  2. 从Open List中取出F值最小的节点，记为当前节点。
  3. 如果当前节点是终点，搜索结束，回溯路径。
  4. 否则，遍历当前节点的所有邻居节点：
    • 如果邻居不可通行（障碍物），跳过。
    • 计算邻居的G、H、F值。
    • 如果邻居不在Open List中，加入；如果在，且新G值更小，更新。
  5. 把当前节点移入Close List（已探索列表）。
  6. 重复步骤2-5，直到找到终点或Open List为空。

避坑指南：我曾经在项目里直接用A*跑栅格地图，结果AGV走出来的路径全是锯齿状的折线。后来加了路径平滑处理（比如用B样条曲线拟合），AGV走起来才顺滑。记住：A*找到的路径是“可行路径”，不一定是“可执行路径”。

4.6 实战中的选择建议

说了这么多，到底怎么选？我根据自己的项目经验，给你几个参考：

  • 场景一：固定路线、环境稳定 → 拓扑地图 + A*。轻量、高效、维护成本低。
  • 场景二：环境动态变化、需要避障 → 栅格地图 + A*。灵活、实时性好。
  • 场景三：大范围 + 局部动态 → 拓扑地图全局规划 + 栅格地图局部规划。这是工业AGV最常用的方案。
  • 场景四：高精度定位、狭窄通道 → 几何地图 + A*（或更高级的Hybrid A*）。适合AGV在狭小空间里精确移动。

一个小技巧：如果你用栅格地图，可以给不同格子设置不同的“通行代价”。比如靠近障碍物的格子代价高一点，AGV就会自动远离障碍物走。这比单纯标记“可通行/不可通行”要智能得多。

好了，这一章的内容就到这里。环境建模和A*算法是AGV路径规划的基石，理解了它们，后面讲多车协同避障、交通管制就好办了。

记住：地图是基础，算法是灵魂。地图建得不好，算法再牛也白搭。
