11 高级调度算法：遗传算法、粒子群算法、强化学习入门

各位同学，欢迎来到高级调度算法的章节。

说实话，前面我们聊的调度策略，比如先到先得、最短路径优先，都属于“规则型”算法。它们简单、稳定，但遇到复杂场景就有点力不从心了。比如几十台AGV在密集仓库里穿梭，还要考虑充电、避让、任务优先级……这时候，我们就得请出“智能优化算法”了。

我个人习惯把这类算法叫做“仿生派”。因为它们很多灵感都来自大自然。今天咱们就聊三个最常用的：遗传算法、粒子群算法，还有最近特别火的强化学习。

11.1 遗传算法：让AGV学会“优胜劣汰”

遗传算法（GA），说白了就是模拟生物进化。你想想看，生物进化靠什么？靠“选择”、“交叉”和“变异”。遗传算法也一样。

在AGV调度里，我们把一个调度方案（比如AGV1去A点，AGV2去B点……）看作一个“个体”。一堆个体组成“种群”。然后我们让它们一代代进化，最终找到最优解。

核心流程：

  1. 编码：把调度方案变成一串数字或二进制码。比如“AGV1→任务3→任务1”编码成 [1,3,1]。
  2. 适应度函数：评价这个方案好不好。比如总路径最短、等待时间最少。
  3. 选择：适应度高的个体，有更大机会“繁殖”下一代。
  4. 交叉：两个父代交换部分基因，产生新个体。
  5. 变异：随机改变某个基因，防止陷入局部最优。

我在项目中遇到过一个问题：AGV数量一多，编码长度就爆炸，算法跑得特别慢。后来我用了“分段编码”，把每台AGV的任务序列分开，效果好了很多。

避坑指南：

我曾经把交叉率设得太高（0.9以上），结果算法像抽风一样，好不容易找到的好方案全被破坏了。后来我控制在0.6~0.8之间，变异率0.01~0.1，稳定多了。

// 伪代码示例：遗传算法核心循环
for (int gen = 0; gen < MAX_GEN; gen++) {
    // 计算每个个体的适应度
    for (Individual ind : population) {
        ind.fitness = evaluate(ind); // 比如计算总路径长度
    }
    // 选择：轮盘赌法
    List<Individual> selected = selectByRoulette(population);
    // 交叉：单点交叉
    List<Individual> offspring = crossover(selected, CROSS_RATE);
    // 变异：随机翻转基因
    mutate(offspring, MUTATE_RATE);
    // 生成新种群
    population = offspring;
}

11.2 粒子群算法：让AGV像鸟群一样协作

粒子群算法（PSO）是另一种思路。它模拟鸟群觅食：每只鸟（粒子）知道自己当前的位置，也知道群体里谁离食物最近。然后它调整自己的速度和方向，向最优位置靠拢。

在AGV调度里，每个粒子就是一个“潜在解”。粒子有位置（调度方案）和速度（调整方向）。每次迭代，粒子会参考两个信息：

  • 个体最优（pBest）：这个粒子自己找到过的最好方案。
  • 全局最优（gBest）：整个群体找到过的最好方案。

然后粒子更新自己的速度和位置。公式很简单：

v_new = w * v_old + c1 * r1 * (pBest - x) + c2 * r2 * (gBest - x)
x_new = x + v_new

其中w是惯性权重，c1、c2是学习因子，r1、r2是随机数。

注意：

粒子群算法容易“早熟收敛”——就是所有粒子都挤到局部最优附近，跳不出来。我建议w从0.9线性递减到0.4，前期探索，后期开发。c1和c2都设成2.0左右，效果比较均衡。

我记得有一次做多AGV路径规划，遗传算法跑了200代还没收敛，粒子群算法50代就找到了差不多的解。但粒子群对离散问题（比如任务分配）处理起来有点别扭，需要做离散化处理。

11.3 强化学习：让AGV自己“试错”成长

强化学习（RL）跟前两个算法完全不同。它不靠模拟进化，也不靠群体协作，而是让智能体（AGV）在环境中“试错”，通过奖励和惩罚来学习最优策略。

你想想看，这就像训练一只小狗：做对了给零食，做错了轻轻拍一下。慢慢地，小狗就知道该怎么做。

在AGV调度里，强化学习的核心要素是：

  • 状态（State）：当前AGV的位置、任务队列、地图拥堵情况等。
  • 动作（Action）：AGV下一步的选择，比如去哪个站点、走哪条路。
  • 奖励（Reward）：完成任务给正奖励，碰撞或绕路给负奖励。
  • 策略（Policy）：AGV根据状态选择动作的规则。

常用算法：

  • Q-Learning：最基础的表格型方法，适合状态空间小的情况。
  • Deep Q-Network (DQN)：用神经网络代替Q表，处理大规模状态空间。
  • Policy Gradient：直接优化策略，适合连续动作空间。

我个人觉得，强化学习在AGV调度里最有潜力的应用是“动态调度”。比如突然来了一个紧急任务，或者某条路堵了，传统算法要重新计算，而强化学习模型可以实时调整。

避坑指南：

我曾经在仿真环境里训练了一个DQN模型，效果特别好。结果一上真实AGV，直接翻车。为什么？因为仿真和现实的“状态分布”不一样。后来我加了“域随机化”，在仿真里随机改变地图、任务分布，模型才泛化过来。

# 伪代码示例：Q-Learning更新
def update_q_table(state, action, reward, next_state):
    # 当前Q值
    current_q = q_table[state][action]
    # 下一状态的最大Q值
    max_next_q = max(q_table[next_state])
    # Q值更新公式
    new_q = current_q + alpha * (reward + gamma * max_next_q - current_q)
    q_table[state][action] = new_q

11.4 三种算法的对比与选择

说了这么多，到底该用哪个？我整理了一个表格，方便你对比：

算法 适用场景 优点 缺点
遗传算法 离线调度、任务分配 全局搜索能力强，适合离散问题 收敛慢，参数敏感
粒子群算法 路径规划、参数优化 收敛快，实现简单 容易早熟，不适合离散问题
强化学习 动态调度、实时决策 能适应环境变化，可在线学习 训练时间长，需要大量数据

嗯，这里要注意：没有银弹。我见过有人非要用强化学习解决一个简单的静态调度问题，结果训练了三天三夜，还不如遗传算法跑10分钟。反过来，也有人用遗传算法做实时调度，结果AGV都到站了，算法还没算完。

我的建议是：

  • 如果任务固定、环境不变，用遗传算法或粒子群算法。
  • 如果环境动态变化、需要实时响应，考虑强化学习。
  • 如果条件允许，可以混合使用：遗传算法做离线预调度，强化学习做在线微调。
