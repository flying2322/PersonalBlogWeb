22 定位与地图构建：卡尔曼滤波、粒子滤波、地图更新

各位同学，今天我们来聊聊AGV调度系统里最核心、也最让人头疼的问题——定位与地图构建。

说白了，就是让AGV知道自己“在哪”，以及周围“长什么样”。

我刚开始做AGV项目时，以为定位就是GPS加个惯性导航。结果一进车间，全是金属货架、叉车穿梭，GPS信号直接被屏蔽。嗯，那时候我才意识到，室内定位这件事，真没那么简单。

22.1 定位问题的本质

AGV的定位，本质上是一个状态估计问题。

你想想看，AGV在运动，轮子转了多少圈、激光雷达扫到了什么、里程计累积了多少误差……这些信息都是带噪声的。我们要做的，就是从这些不完美的数据里，估算出AGV最可能的位置和姿态。

我个人习惯把定位问题拆成两步：

  • 预测：根据上一时刻的位置和运动模型，猜一下现在在哪
  • 更新：用传感器观测到的环境特征，修正这个猜测

听起来是不是有点像“猜谜语”？没错，定位就是一场有依据的猜谜。

22.2 卡尔曼滤波：线性系统的老朋友

卡尔曼滤波，我估计很多同学都听过。它是处理线性高斯系统状态估计的经典方法。

我在项目中遇到过这样一个场景：AGV在平整地面上直线行驶，轮式里程计加上激光雷达测距，用卡尔曼滤波效果非常好。计算量小，实时性高，CPU占用率不到5%。

它的核心思想就两个公式：

// 预测阶段
x_pred = A * x_prev + B * u
P_pred = A * P_prev * A^T + Q

// 更新阶段
K = P_pred * H^T * (H * P_pred * H^T + R)^(-1)
x_updated = x_pred + K * (z - H * x_pred)
P_updated = (I - K * H) * P_pred

这里我解释一下关键变量：

  • x：状态向量，比如位置(x,y)和朝向θ
  • P：状态协方差矩阵，代表我们对估计的置信度
  • Q：过程噪声，比如轮子打滑带来的不确定性
  • R：观测噪声，比如激光雷达的测量误差
  • K：卡尔曼增益，说白了就是“我更相信预测还是观测”的权重
我的经验：调参时，Q和R的比值决定了滤波器的“性格”。Q设大了，滤波器反应快但容易抖动；R设大了，滤波器平滑但响应迟钝。我一般先根据传感器手册标定R，再通过实验调整Q。

22.3 粒子滤波：非线性世界的救星

但是，现实世界哪有那么多线性系统？

AGV在仓库里转弯、遇到斜坡、经过金属货架导致激光数据异常……这些场景下，卡尔曼滤波就不太够用了。为什么呢？因为系统的运动模型和观测模型可能高度非线性，噪声也不一定是高斯分布。

这时候，粒子滤波就派上用场了。

粒子滤波的思想很直观：用一堆随机粒子来近似概率分布。每个粒子代表一个可能的位置，粒子越密集的地方，AGV越可能在那里。

我给大家画个流程图，看看粒子滤波是怎么工作的：

流程其实就四步：

  1. 初始化：在可能的位置撒一堆粒子
  2. 预测：根据运动模型，让每个粒子移动
  3. 更新权重：用激光雷达等观测数据，给每个粒子打分——跟观测越吻合，权重越高
  4. 重采样：淘汰权重低的粒子，复制权重高的粒子

循环往复，粒子就会逐渐收敛到AGV的真实位置附近。

注意：粒子滤波的计算量跟粒子数成正比。我曾经在一个项目里用了5000个粒子，结果CPU跑满了，AGV反应延迟了200ms。后来优化到1000个粒子，配合自适应重采样策略，效果就平衡了。粒子数不是越多越好，够用就行。

22.4 地图更新：让AGV学会“记住”环境

定位搞定了，地图怎么办？

很多同学以为地图是一次建好、永久使用的。其实不然。仓库里的货架会移动、地面会有新的障碍物、光照变化会影响视觉特征……地图必须能动态更新。

我参与过一个项目，客户仓库每周都会调整货架布局。如果地图不更新，AGV第二天就“迷路”了。后来我们实现了增量式地图更新，每次AGV经过时，都会用最新的激光数据修正地图。

地图更新的核心策略：

  • 占用栅格地图：每个格子存储“被占用”的概率。新观测到障碍物，概率增加；观测到空闲，概率降低
  • 贝叶斯更新：用贝叶斯公式融合新旧数据，避免单次误检测导致地图突变
  • 局部更新：只更新AGV当前位置附近的栅格，减少计算量

这里给个简单的更新公式：

// 栅格占用概率更新（对数形式）
// odds(p) = p / (1 - p)
// log_odds(p) = log(p / (1 - p))

// 更新公式
log_odds_updated = log_odds_prior + log_odds_measurement

// 转回概率
p_updated = 1 / (1 + exp(-log_odds_updated))

用对数形式的好处是，加法运算比乘法快得多，而且数值稳定性更好。

关键点：地图更新不是“覆盖”，而是“融合”。每次观测都只是修正，不是重写。这样即使偶尔有误检测，也不会把地图搞坏。

22.5 定位与建图的耦合：鸡生蛋还是蛋生鸡？

到这里，你可能发现了：定位需要地图，建图又需要定位。这不就是鸡生蛋蛋生鸡吗？

没错，这就是SLAM（同步定位与地图构建）的核心矛盾。

在实际工程中，我们通常分两步走：

  1. 先建图：人工遥控AGV走一遍环境，用SLAM算法建好初始地图
  2. 再定位：日常运行时，基于已有地图做定位，同时小范围更新地图

我建议初学者先从已知地图的定位入手，把卡尔曼滤波或粒子滤波跑通了，再去做完整的SLAM。一口吃不成胖子，AGV调度系统更是如此。

方法 适用场景 计算量 我的评价
卡尔曼滤波 线性系统、环境稳定 低 入门首选，调参友好
粒子滤波 非线性、全局定位 中 灵活但注意粒子数
地图更新 动态环境 中低 增量更新是关键
避坑指南：我曾经在一个项目里，粒子滤波的粒子数设得太少（200个），结果AGV在长走廊里定位漂移了。后来增加到800个粒子，并加入了里程计的运动模型约束，问题就解决了。记住：粒子数要跟环境复杂度匹配。

好了，关于定位与地图构建的核心内容就这些。卡尔曼滤波适合线性场景，粒子滤波处理非线性问题，地图更新让系统适应变化。三者配合，才能让AGV在复杂环境中稳定运行。

嗯，这些方法我都亲手调过、踩过坑，希望能帮你少走弯路。
