24 多传感器融合：激光雷达、IMU、里程计、视觉传感器

说到多传感器融合，我脑子里第一个蹦出来的画面，就是几年前在仓库里调试AGV的场景。当时一台车在走廊里突然“抽风”，明明激光雷达扫到前面是墙，它却硬要往前冲。后来查了半天，发现是IMU数据飘了，里程计也累积了误差，三个传感器各说各话，系统直接懵了。

从那以后我就明白了一个道理：单一传感器都有短板，融合才是王道。今天咱们就来聊聊，怎么把激光雷达、IMU、里程计、视觉传感器这几路数据，揉成一个靠谱的定位结果。

为什么非要搞融合？

你想想看，每种传感器都有自己的“脾气”：

  • 激光雷达：精度高，但怕灰尘、怕遮挡，而且价格不便宜
  • IMU：短时间很准，但长时间会漂移，说白了就是“越走越偏”
  • 里程计：简单可靠，但轮子打滑就完蛋
  • 视觉传感器：信息丰富，但受光照影响大，晚上可能就瞎了

单独用哪一个，都像瘸腿走路。融合起来，才能互相补位。

核心思想：用IMU和里程计做高频短时预测，用激光雷达和视觉做低频长时修正。各取所长。

嗯，这里要注意，时间同步是个大坑。不同传感器的采样频率不一样，激光雷达一般是10Hz，IMU能到100Hz甚至更高。如果不做时间对齐，融合出来的结果就是乱的。

我的小技巧：在ROS里用message_filters做时间同步，或者自己维护一个时间戳缓冲区。千万别偷懒用“最近一次数据”直接凑合。

融合算法怎么选？

常用的就两种：扩展卡尔曼滤波（EKF）和粒子滤波（PF）。我个人更偏爱EKF，计算量小，实时性好。

EKF的核心就两步：预测和更新。预测靠IMU和里程计，更新靠激光雷达和视觉。

// 伪代码示例：EKF融合流程
void ekfUpdate() {
    // 1. 预测步骤（IMU + 里程计）
    x_pred = f(x_prev, u_imu, u_odom);
    P_pred = F * P_prev * F^T + Q;
    
    // 2. 如果有激光雷达观测
    if (lidar_available) {
        z_lidar = getLidarObs();
        y_lidar = z_lidar - h_lidar(x_pred);
        S_lidar = H_lidar * P_pred * H_lidar^T + R_lidar;
        K_lidar = P_pred * H_lidar^T * inv(S_lidar);
        x_pred = x_pred + K_lidar * y_lidar;
        P_pred = (I - K_lidar * H_lidar) * P_pred;
    }
    
    // 3. 如果有视觉观测
    if (visual_available) {
        z_vis = getVisualObs();
        y_vis = z_vis - h_vis(x_pred);
        S_vis = H_vis * P_pred * H_vis^T + R_vis;
        K_vis = P_pred * H_vis^T * inv(S_vis);
        x_pred = x_pred + K_vis * y_vis;
        P_pred = (I - K_vis * H_vis) * P_pred;
    }
    
    x_est = x_pred;
    P_est = P_pred;
}

避坑指南

我曾经在一个项目里，激光雷达和视觉的坐标系没对齐，结果融合出来的位置偏差了20厘米。查了两天才发现，原来是激光雷达装在车头，相机装在车尾，两个坐标系之间的变换矩阵写错了。

所以，坐标系标定是融合的前提。你得先知道每个传感器相对于车体中心的位置和朝向，不然数据对不上。

传感器 常见坐标系 标定参数
激光雷达 极坐标系 → 笛卡尔坐标系 安装位置(x,y,z) + 朝向(roll,pitch,yaw)
IMU 机体坐标系 与车体中心的旋转矩阵
里程计 车轮坐标系 轮距、编码器分辨率
视觉 像素坐标系 → 相机坐标系 内参矩阵 + 外参矩阵
特别注意：IMU的零偏会随时间变化，最好在每次启动时做一次静态校准。不然你会发现，车停着不动，融合出来的位置却在慢慢漂移。

实际项目中的经验

我记得有一次在工厂里调试，AGV经过一段金属货架区域，激光雷达的反射信号变得乱七八糟。这时候IMU和里程计就顶上来了，虽然精度差一点，但至少没让车撞墙。

反过来，在开阔区域，激光雷达和视觉的观测质量很好，就能把IMU累积的误差拉回来。说白了，这就是优势互补。

还有一个细节：异常检测。传感器偶尔会出故障，比如激光雷达被遮挡、视觉图像模糊。我习惯在融合前加一个数据质量检查，如果某个传感器的观测值明显偏离预测值太多，就暂时把它踢出去。

// 异常检测示例
bool isOutlier(double innovation, double covariance) {
    double mahalanobis = innovation * innovation / covariance;
    // 卡方检验，置信度95%
    if (mahalanobis > 5.991) {
        return true;  // 异常，丢弃该观测
    }
    return false;
}

嗯，这套方法我用了好几年，效果一直不错。多传感器融合不是什么玄学，说白了就是用数学把各路信息拧成一股绳。你只要把每个传感器的特性摸清楚，把时间同步和坐标系标定做扎实，剩下的交给卡尔曼滤波就好。

总结一句话：激光雷达给精度，IMU给速度，里程计给连续性，视觉给语义信息。四者合一，AGV才能跑得稳、跑得准。
