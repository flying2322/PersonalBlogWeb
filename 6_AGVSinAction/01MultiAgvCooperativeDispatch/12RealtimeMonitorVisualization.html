12 实时监控与可视化

各位同学，今天我们来聊聊调度系统的「眼睛」——实时监控与可视化。说实话，我见过太多调度系统，算法再牛，界面一团糟，现场工程师根本不敢用。你想想看，AGV在车间里跑，你连它在哪都不知道，这调度谁敢信？

12.1 为什么需要实时监控？

AGV调度系统不是写完代码就完事了。它是个24小时运转的活系统。我参与过一个项目，上线第一天，调度算法跑得挺好，但操作员盯着黑乎乎的终端，完全不知道AGV在干嘛。结果呢？一个AGV卡在角落里，系统还在给它派任务，白白浪费了半小时产能。

实时监控要解决三个核心问题：

  • 位置可见：AGV当前在哪，往哪走，速度多少
  • 状态可知：是空闲、执行任务、充电还是故障
  • 异常可预警：电量低、路径堵塞、通信中断，得第一时间弹出来

核心观点：监控不是「看个热闹」，而是让操作员在3秒内判断「系统是否健康」。

12.2 WebSocket：让数据「推」起来

传统的HTTP轮询，说白了就是前端每隔几秒问一次「有更新吗？」。这在AGV场景下根本行不通。AGV位置每秒都在变，轮询间隔短了服务器扛不住，长了数据滞后严重。

WebSocket就解决了这个问题。它建立一条长连接，服务端有数据就主动推过来。我习惯用Spring Boot + Netty做WebSocket服务端，前端用原生WebSocket API或者Socket.IO。

下面是一个简单的服务端推送示例：

// 服务端（Java + Spring Boot）
@ServerEndpoint("/ws/agv/{agvId}")
public class AgvWebSocket {
    
    @OnOpen
    public void onOpen(Session session, @PathParam("agvId") String agvId) {
        // 记录连接，用于后续推送
        SessionManager.add(agvId, session);
        System.out.println("AGV " + agvId + " 监控连接建立");
    }
    
    // 推送AGV位置
    public void pushPosition(String agvId, double x, double y, double speed) {
        JSONObject msg = new JSONObject();
        msg.put("type", "position");
        msg.put("agvId", agvId);
        msg.put("x", x);
        msg.put("y", y);
        msg.put("speed", speed);
        msg.put("timestamp", System.currentTimeMillis());
        
        Session session = SessionManager.get(agvId);
        if (session != null && session.isOpen()) {
            session.getBasicRemote().sendText(msg.toString());
        }
    }
}

前端接收也很简单：

// 前端（JavaScript）
const ws = new WebSocket('ws://localhost:8080/ws/agv/AGV001');

ws.onmessage = function(event) {
    const data = JSON.parse(event.data);
    if (data.type === 'position') {
        // 更新地图上的AGV位置
        updateAgvPosition(data.agvId, data.x, data.y, data.speed);
    }
};

避坑指南：我曾经遇到过WebSocket连接频繁断开的问题。后来发现是心跳机制没做好。建议每30秒发一次心跳包，服务端60秒没收到就主动断开，避免僵尸连接占用资源。

12.3 前端图表库：让数据「活」起来

光有原始数据不够，得可视化。我个人比较喜欢用ECharts，它图表类型丰富，社区活跃，中文文档也全。当然，如果你追求轻量，Chart.js也不错。

AGV调度系统里，我常用这几类图表：

图表类型 用途 更新频率
折线图 AGV速度、电量随时间变化 1秒/次
柱状图 各AGV任务完成数对比 10秒/次
饼图 AGV状态分布（空闲/忙碌/充电/故障） 5秒/次
仪表盘 系统整体吞吐量、拥堵指数 实时

举个例子，AGV电量监控的折线图，代码大概这样：

// ECharts 折线图示例
const chart = echarts.init(document.getElementById('batteryChart'));

function updateBatteryChart(agvId, batteryLevel) {
    // 维护一个长度为60的滑动窗口（最近60秒数据）
    if (!chartData[agvId]) {
        chartData[agvId] = { time: [], value: [] };
    }
    
    const now = new Date().toLocaleTimeString();
    chartData[agvId].time.push(now);
    chartData[agvId].value.push(batteryLevel);
    
    // 只保留最近60个点
    if (chartData[agvId].time.length > 60) {
        chartData[agvId].time.shift();
        chartData[agvId].value.shift();
    }
    
    chart.setOption({
        xAxis: { data: chartData[agvId].time },
        series: [{
            name: agvId,
            type: 'line',
            data: chartData[agvId].value,
            smooth: true
        }]
    });
}

// 通过WebSocket接收数据后调用
ws.onmessage = function(event) {
    const data = JSON.parse(event.data);
    if (data.type === 'battery') {
        updateBatteryChart(data.agvId, data.level);
    }
};

注意：图表数据不能无限堆积。我见过一个系统跑了三天，前端浏览器直接卡死——因为图表里存了上万个数据点。一定要做数据裁剪，比如只保留最近5分钟的数据，或者做降采样。

12.4 地图渲染：AGV的「实时位置」

这是监控系统最直观的部分。说白了，就是在地图上画AGV，然后让它动起来。

地图渲染我推荐用Canvas或者Leaflet。如果车间地图是平面图，Canvas就够用了。如果需要叠加卫星图或建筑图，Leaflet更合适。

下面是一个简单的Canvas地图渲染逻辑：

// Canvas 地图渲染
class AgvMap {
    constructor(canvasId, mapImageUrl) {
        this.canvas = document.getElementById(canvasId);
        this.ctx = this.canvas.getContext('2d');
        this.agvs = {};  // 存储所有AGV的位置和状态
        
        // 加载地图背景
        this.bgImage = new Image();
        this.bgImage.src = mapImageUrl;
        this.bgImage.onload = () => this.render();
    }
    
    // 更新AGV位置（由WebSocket触发）
    updateAgv(agvId, x, y, angle, status) {
        this.agvs[agvId] = { x, y, angle, status };
        this.render();
    }
    
    render() {
        // 清空画布
        this.ctx.clearRect(0, 0, this.canvas.width, this.canvas.height);
        
        // 绘制地图背景
        this.ctx.drawImage(this.bgImage, 0, 0);
        
        // 绘制所有AGV
        for (let id in this.agvs) {
            const agv = this.agvs[id];
            
            // 根据状态设置颜色
            let color = '#4CAF50';  // 正常
            if (agv.status === 'charging') color = '#FFC107';
            if (agv.status === 'fault') color = '#F44336';
            
            // 绘制AGV（简化为一个带方向的圆点）
            this.ctx.beginPath();
            this.ctx.arc(agv.x, agv.y, 8, 0, Math.PI * 2);
            this.ctx.fillStyle = color;
            this.ctx.fill();
            
            // 绘制方向指示
            this.ctx.beginPath();
            this.ctx.moveTo(agv.x, agv.y);
            this.ctx.lineTo(
                agv.x + 12 * Math.cos(agv.angle),
                agv.y + 12 * Math.sin(agv.angle)
            );
            this.ctx.strokeStyle = '#333';
            this.ctx.lineWidth = 2;
            this.ctx.stroke();
            
            // 显示AGV编号
            this.ctx.fillStyle = '#000';
            this.ctx.font = '10px Arial';
            this.ctx.fillText(id, agv.x + 12, agv.y - 12);
        }
    }
}

// 使用示例
const map = new AgvMap('mapCanvas', '/images/workshop.png');

// WebSocket收到位置更新
ws.onmessage = function(event) {
    const data = JSON.parse(event.data);
    if (data.type === 'position') {
        map.updateAgv(data.agvId, data.x, data.y, data.angle, data.status);
    }
};

个人经验：地图上的AGV图标不要用真实照片，太卡了。用简单的几何图形加颜色区分状态就行。我一般用圆形表示正常，三角形表示故障，闪电符号表示充电。操作员一眼就能看出问题。

12.6 性能优化：别让监控拖垮系统

最后聊点实战经验。监控系统本身不能成为性能瓶颈。我遇到过最夸张的情况：监控页面打开后，CPU直接飙到90%，因为每秒钟渲染了50个AGV的动画。

几个优化建议：

  • 数据降频：AGV位置每秒变化10次，但前端每秒更新2次就够了。人眼根本看不出区别。
  • 离屏渲染：地图背景图提前渲染到离屏Canvas上，每次只更新AGV图标，别重绘整个地图。
  • 虚拟列表：如果AGV数量超过50台，列表展示时用虚拟滚动，只渲染可见区域。
  • Web Worker：数据解析这种计算密集型的任务，丢到Worker线程里，别阻塞UI。

总结一下：实时监控不是「把数据扔到页面上」就完事了。WebSocket保证数据及时性，图表库让数据可读，地图渲染让位置直观。三者配合好，操作员才能对系统「一眼看透」。

好了，这一章就到这里。记住，监控系统是调度系统的「面子」，也是「里子」。面子不好看，没人敢用；里子不扎实，数据不准，再好看也没用。
