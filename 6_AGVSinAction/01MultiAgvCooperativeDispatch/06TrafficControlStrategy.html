6 交通管制策略：单向通行、区域锁、时间窗、预留路径

各位好，我是老张。今天聊的这块，是AGV调度系统里最容易出幺蛾子的地方——交通管制。

你想想看，几十台AGV在仓库里跑来跑去，路口就那么几个，不打架才怪。我见过最夸张的一次，客户现场12台车堵成一个死结，最后只能人工去搬车。嗯，从那以后，我对交通管制这块就特别上心。

说白了，交通管制就是解决一个核心问题：谁先走，谁让谁，怎么走不撞。今天我把四种主流策略掰开揉碎了讲，都是实战中验证过的。

6.1 单向通行：最简单也最有效

单向通行，顾名思义，就是给道路定方向。就像城市里的单行道，只能朝一个方向走。

我在项目中遇到过这样一个场景：一个窄巷道，宽度只够一辆AGV通过。如果双向都走，那必须做复杂的会车逻辑。我的做法很简单——直接改成单向。虽然绕了点路，但系统稳定性提升了一大截。

核心原则： 单向通行的路段，所有AGV必须按同一方向行驶，禁止逆行。

实现起来也不复杂。你只需要在路网模型里给每条边加一个方向属性：

// 路网边定义示例
{
  "edgeId": "E-001",
  "fromNode": "N-01",
  "toNode": "N-02",
  "direction": "forward",  // forward 或 backward
  "oneWay": true
}

单向通行有个好处——死锁概率几乎为零。但代价是路径可能变长。我一般建议在以下场景使用：

  • 窄巷道（宽度小于1.5倍车宽）
  • 高密度作业区（同时有5台以上AGV活动）
  • 交叉口密集的区域
我的习惯： 单向通行的路段，我会在物理地面上也贴上箭头标识。这样运维人员一眼就能看出问题，不用翻代码。

6.2 区域锁：给关键区域上把锁

区域锁，说白了就是给某个物理区域加一把「互斥锁」。同一时间，只允许一台AGV进入。

为什么会需要这个？举个例子：充电站、上下料点、电梯口。这些地方空间有限，两台车挤进去就是事故。

区域锁的实现逻辑其实很简单：

class ZoneLock {
  constructor(zoneId) {
    this.zoneId = zoneId;
    this.lockedBy = null;  // 当前占用车辆的ID
  }

  requestLock(agvId) {
    if (this.lockedBy === null) {
      this.lockedBy = agvId;
      return true;  // 获取锁成功
    }
    return false;  // 被占用，等待
  }

  releaseLock(agvId) {
    if (this.lockedBy === agvId) {
      this.lockedBy = null;
    }
  }
}

我曾经踩过一个坑：区域锁释放的时机没把握好。AGV已经离开区域了，但锁没释放，后面的车一直等着。排查了半天，发现是传感器信号延迟导致的。后来我加了个超时机制——如果AGV离开区域超过2秒还没释放锁，系统强制解锁。

注意： 区域锁不能滥用。锁的区域越大，系统并发度越低。我建议每个区域锁覆盖的范围不超过20平方米。

6.3 时间窗：精确到秒的通行调度

时间窗策略，是我个人觉得最优雅的一种方案。它给每个路段分配一个时间窗口，AGV只能在指定的时间段内通过。

你想想看，这就像火车调度——每趟车都有固定的时刻表。AGV也一样，提前规划好什么时间到达哪个路口，什么时间通过哪个路段。

时间窗的计算公式大致是这样的：

// 时间窗计算示例
function calculateTimeWindow(agv, edge) {
  const travelTime = edge.length / agv.speed;  // 行驶时间
  const bufferTime = 2;  // 缓冲时间，单位秒
  
  return {
    startTime: currentTime + agv.remainingTimeToEdge,
    endTime: currentTime + agv.remainingTimeToEdge + travelTime + bufferTime
  };
}

时间窗的好处是确定性高。只要时间窗算得准，就不会有冲突。但问题也在这里——AGV的行驶速度不是恒定的，电池电量、负载重量都会影响速度。

我记得有一次，一台满载的AGV爬坡时速度慢了3秒，结果和另一台车的时间窗重叠了。还好系统有动态调整机制，自动重新计算了后续的时间窗。

避坑指南： 时间窗一定要留缓冲时间。我一般留2-3秒，高密度区域留5秒。别心疼这点时间，安全第一。

6.4 预留路径：提前占道，避免冲突

预留路径，就是AGV在出发前，就把整条路径上的所有路段都「预订」了。其他AGV看到这些路段被占，就会自动绕行。

这有点像你在网上订酒店——提前把房间锁定了，别人就订不了了。AGV也是一样，路径预留了，其他车就不能再走这条路。

实现上，需要一个全局的路径资源管理器：

class PathReservationManager {
  constructor() {
    this.reservations = new Map();  // key: edgeId, value: { agvId, timeRange }
  }

  reservePath(agvId, path) {
    for (let edge of path) {
      if (this.isEdgeAvailable(edge.edgeId, agvId)) {
        this.reservations.set(edge.edgeId, {
          agvId: agvId,
          timeRange: edge.timeWindow
        });
      } else {
        // 路径被占用，重新规划
        return false;
      }
    }
    return true;
  }
}

预留路径的优点是冲突概率极低。但缺点也很明显——资源利用率不高。如果一台AGV预留了路径但迟迟不走，后面的车就得等着。

我一般把预留路径和动态超时结合使用。如果AGV在预留路径后30秒内没有进入该路段，系统自动释放预留资源。

6.5 四种策略怎么选？

说了这么多，你可能会问：到底用哪种？我的建议是组合使用。

策略 适用场景 优点 缺点
单向通行 窄巷道、高密度区 实现简单，死锁概率低 路径可能变长
区域锁 充电站、上下料点 安全性高，逻辑清晰 并发度受限
时间窗 交叉口、汇流区 确定性高，调度精确 对速度波动敏感
预留路径 长距离运输、关键路径 冲突概率极低 资源利用率低

我个人习惯的做法是：主干道用单向通行，关键节点用区域锁，交叉口用时间窗，长距离运输用预留路径。这样组合下来，既保证了安全性，又兼顾了效率。
