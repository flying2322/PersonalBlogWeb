3 最短路径与地图拓扑：地图抽象方法、Dijkstra与A*算法

各位同学，今天我们来聊聊AGV调度里最核心的底层问题——地图怎么建，路怎么走。

说实话，我见过不少团队，一上来就搞复杂的调度算法，结果发现地图模型没搭好，路径算出来全是死胡同。嗯，这就像盖楼不打地基，迟早要塌。

所以这一章，我们老老实实把地图抽象、最短路径算法讲透。你把这些吃透了，后面那些高级策略才能玩得转。

3.1 地图抽象方法：从物理世界到节点-边模型

AGV跑在车间里，但算法不能直接处理“从A点走到B点”这种自然语言。我们需要把物理地图抽象成数学结构。

我个人习惯用节点-边模型。说白了，就是把地图拆成一个个关键点（节点），点与点之间用线（边）连接，边上附带权重（距离、时间、能耗等）。

节点（Node）：AGV可以停留或转向的位置，比如工位、充电站、交叉口。

边（Edge）：连接两个节点的路径段，通常是有向的（单向/双向）。

权重（Weight）：边的代价，可以是物理距离、行驶时间、或者综合成本。

我在项目中遇到过一个问题：有家工厂的通道很窄，两辆AGV无法交汇。如果只按物理距离建模，算法会算出两条路径在窄道里“擦肩而过”，实际根本跑不通。后来我加了一个边属性——是否允许双向通行，这才解决了。

你想想看，地图抽象这一步做不好，后面所有算法都是空中楼阁。所以我的建议是：先画拓扑图，再写代码。

3.2 Dijkstra算法原理：稳扎稳打的“贪心”

地图建好了，接下来就是找最短路径。Dijkstra算法是经典中的经典，我当年学数据结构时第一个接触的图算法就是它。

它的核心思想很简单：从起点出发，每次选一个当前距离最短的未处理节点，然后更新它的邻居。说白了，就是“贪心”策略——每次都走眼前最近的路。

我的经验：Dijkstra算法在静态地图、边权非负的场景下非常好用。我在一个仓库项目里用它做基础路径规划，配合交通管制，效果很稳。

但Dijkstra有个缺点：它像个“无头苍蝇”一样向四周扩散，直到找到终点。如果地图很大，效率会很低。

伪代码长这样：

function Dijkstra(Graph, start):
    dist[start] = 0
    for each node v != start:
        dist[v] = INFINITY
    Q = 所有节点  // 优先队列
    
    while Q 不为空:
        u = Q中dist最小的节点
        if u == 目标节点: break
        for each 邻居 v of u:
            alt = dist[u] + weight(u, v)
            if alt < dist[v]:
                dist[v] = alt
                prev[v] = u
    return dist, prev

你想想看，如果地图有1000个节点，Dijkstra可能要遍历大部分节点才能找到终点。这时候，A*算法就登场了。

3.3 A*算法原理：带“方向感”的搜索

A*算法和Dijkstra最大的区别是什么？它知道终点在哪。

Dijkstra是“盲目”地向外扩散，而A*会利用一个启发式函数来估算当前节点到终点的距离，从而优先探索“看起来更有可能”的方向。

核心公式就一个：

f(n) = g(n) + h(n)

g(n)：从起点到当前节点n的实际代价

h(n)：从节点n到终点的估计代价（启发式函数）

f(n)：综合优先级，值越小越优先探索

我曾经在一个项目里对比过Dijkstra和A*：同样一张200个节点的地图，Dijkstra算了120ms，A*只用了35ms。差距就在这里。

3.4 启发式函数设计：A*的灵魂

启发式函数h(n)的设计，直接决定了A*算法的效率和正确性。我见过不少新手随便写个曼哈顿距离就往上套，结果路径算出来绕远路。

常用的启发式函数有几种：

类型 公式 适用场景 我的评价
曼哈顿距离 |x1-x2| + |y1-y2| 只能上下左右移动的网格 简单，但AGV很少用
欧几里得距离 √((x1-x2)²+(y1-y2)²) 任意方向移动 直观，但计算稍慢
对角线距离 max(|dx|,|dy|) 允许对角线移动 折中方案，我常用
自定义加权 根据实际路况加权 复杂地形 精度高，但需要调参

避坑指南：我曾经在一个项目里用了曼哈顿距离，结果AGV在通道里来回折返，因为启发式函数低估了实际距离。记住：h(n)必须小于等于实际代价，否则A*会退化成非最优解。

我个人习惯在AGV调度中用对角线距离，因为它既考虑了方向，又不会过度低估。如果地图有障碍物，我会在h(n)上加一个障碍物惩罚系数，让算法主动避开拥堵区域。

嗯，这里要注意：启发式函数不是越复杂越好。我见过有人把交通拥堵预测也塞进h(n)里，结果计算量爆炸，实时性完全跟不上。我的建议是：h(n)保持轻量，g(n)承担更多细节。

最后总结一下：

  • 地图抽象：节点-边模型是基础，别忘了加边属性
  • Dijkstra：稳，但慢，适合小地图或静态场景
  • A*算法：快，但有方向感，适合动态调度
  • 启发式函数：选对h(n)，事半功倍

这些内容我反复讲过很多次，但每次都有新同学在启发式函数上栽跟头。你回去可以自己写个demo，对比一下不同h(n)的效果，感受会更深。
