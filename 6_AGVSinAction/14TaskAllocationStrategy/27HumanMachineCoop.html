27 人机协同调度：人机交互界面设计、人工干预机制、半自动模式切换

说实话，做了这么多年AGV调度系统，我最深的体会就是：再聪明的算法，也扛不住现场一个突发状况。

你想想看，产线上突然掉下来一个零件，或者某个工位临时要加急订单，这时候全自动调度反而成了绊脚石。所以，人机协同不是锦上添花，而是刚需。这一章，我就把我在几个大项目里踩过的坑、攒下的经验，掰开了跟你聊聊。

27.1 人机交互界面设计：别让操作员对着黑盒发懵

我见过太多调度系统，界面做得跟飞机驾驶舱似的，密密麻麻全是按钮。操作员一紧张，点错一个键，整个产线就乱了。我个人习惯，界面设计要遵循「三秒原则」——操作员扫一眼，三秒内能看懂当前状态。

27.1.1 核心信息分层展示

别把所有信息堆在一个页面。我一般分三层：

  • 第一层：全局概览——地图上显示所有AGV位置、任务队列长度、拥堵区域。用颜色标识：绿色正常、黄色预警、红色异常。
  • 第二层：车辆详情——点击任意AGV，弹出面板显示当前任务、电量、路径、状态（自动/半自动/手动）。
  • 第三层：任务看板——列表展示所有待执行、执行中、已完成的任务。支持按优先级、时间、车辆筛选。
我的小技巧： 在全局地图上，我习惯用「热力图」展示AGV密度。哪块区域车多，颜色就深。操作员一眼就能看出哪里可能堵车，提前干预。

27.1.2 操作反馈必须即时

操作员点了一个「暂停任务」按钮，系统要立刻给出反馈。我曾经遇到一个项目，点击按钮后要等3秒才有反应，操作员以为没点上，又点了一次，结果任务被暂停了两次……

所以，我要求：任何操作，100ms内必须给出视觉反馈（按钮变色、加载动画、或状态文字变化）。后台处理可以慢，但前台反馈不能等。

27.2 人工干预机制：给操作员一把「安全剪刀」

全自动调度就像自动驾驶，大部分时候很稳，但遇到突发情况，必须允许人「剪断」自动流程。我在项目中总结了几种最常用的人工干预场景：

27.2.1 任务插队与优先级调整

产线上突然来了一个加急订单，需要立刻送料。这时候操作员要能手动提升某个任务的优先级，甚至直接插到队列最前面。

// 伪代码：任务插队接口
function insertUrgentTask(taskId, targetVehicleId) {
    // 1. 检查目标车辆当前状态
    if (vehicle.status === 'IDLE') {
        // 直接分配
        assignTask(vehicle, taskId);
    } else {
        // 2. 将当前任务挂起，插入紧急任务
        suspendCurrentTask(vehicle);
        assignTask(vehicle, taskId);
        // 3. 紧急任务完成后，自动恢复原任务
        onTaskComplete(taskId, function() {
            resumeSuspendedTask(vehicle);
        });
    }
    // 4. 记录干预日志
    logIntervention('TASK_INSERT', taskId, vehicle.id);
}
注意： 插队操作必须记录日志！我曾经遇到一个项目，操作员频繁插队，导致原任务被无限期挂起，产线停了两小时。后来我强制要求：每个任务被挂起超过30分钟，系统自动报警提醒。

27.2.2 车辆锁定与解锁

有时候AGV出了小故障，或者需要临时充电，操作员要能手动锁定某辆车，不让系统分配新任务给它。但要注意：锁定不能导致死锁。

举个例子：如果A车正驮着B车需要的物料，你把A车锁了，B车就永远等不到物料。所以，我设计的锁定逻辑会先检查依赖关系，如果有依赖，会提示操作员「该车正在执行关键任务，是否强制锁定？」。

27.2.3 路径重规划与手动导航

当AGV前方有障碍物，或者某条路被封了，操作员可以手动拖拽AGV的路径点，重新规划路线。我习惯在界面上提供「路径编辑模式」：

  • 点击AGV，显示当前路径
  • 操作员可以拖拽路径点，或者点击地图上的新位置作为目标
  • 系统自动计算新路径，并显示预计时间变化
  • 操作员确认后，AGV按新路径行驶
核心原则： 人工干预不是「推翻系统」，而是「临时修正」。所有干预操作都应该可追溯、可回退、可审计。

27.3 半自动模式切换：在「全自动」和「全手动」之间找个平衡

全自动模式效率高，但遇到异常就抓瞎。全手动模式灵活，但操作员累死。所以，我一直在推「半自动模式」——说白了，就是让系统做80%的常规工作，人只处理那20%的异常。

27.3.1 三种模式的定义

模式 任务分配 路径规划 异常处理 适用场景
全自动 系统自动 系统自动 系统自动 稳定产线、常规任务
半自动 系统建议 + 人工确认 系统自动（可人工修改） 人工处理 多品种小批量、频繁插单
全手动 人工指定 人工指定 人工处理 调试、维修、应急

27.3.2 模式切换的平滑过渡

我最怕的就是模式切换时「哐当」一下，所有AGV都停了。所以，我要求切换必须平滑：

  • 从全自动切到半自动： 正在执行的任务不中断，但新任务会弹出确认窗口。操作员可以设置「自动确认超时时间」——比如5秒内没操作，系统自动按建议执行。
  • 从半自动切回全自动： 需要操作员手动确认「是否恢复全自动」。我习惯加一个倒计时，防止误操作。
  • 紧急切换（全自动→全手动）： 允许一键切换，但必须输入密码或二次确认。切换后，所有AGV立即减速停车，等待人工指令。
避坑指南： 我曾经在一个项目里，操作员误触了「全手动」按钮，结果20台AGV全部停在巷道里，堵死了。后来我加了一个「切换保护」——从全自动切到全手动，必须同时按住两个按钮3秒以上。虽然麻烦点，但安全第一。

27.3.3 状态同步与冲突检测

半自动模式下，最怕的就是「人以为车在自动跑，车以为人在手动管」。所以，状态同步必须实时：

  • 操作员界面上，每台AGV的模式状态要显眼显示（比如用不同颜色的光环）
  • 如果操作员手动修改了某台车的路径，系统要自动将该车切换为「半自动」模式
  • 当操作员长时间（比如5分钟）没有操作，系统可以提示「是否恢复全自动？」

另外，冲突检测不能因为有人工干预就关闭。即使操作员手动指定了路径，系统也要检查是否会与其他AGV碰撞。如果会，系统要弹出警告，并给出替代路径建议。

27.4 实战经验：一个让我印象深刻的教训

最后，分享一个真实案例。有个项目，客户要求「全自动运行，但操作员可以随时接管」。我们设计了一个「接管按钮」，按下去后，操作员可以用手柄控制AGV。

结果呢？有一次操作员接管了一台AGV，开到了非作业区，然后忘了切回自动模式。系统以为这台车还在自动运行，继续给它分配任务。等操作员想起来的时候，任务已经超时了，后面的车全堵上了。

从那以后，我定了一个规矩：任何人工接管，系统必须在30秒后自动弹窗提醒「是否恢复自动模式？」。如果操作员没回应，系统自动将车导航到安全区域并停车。这个机制后来救了好几次场。

总结一下我的核心观点：

  • 人机交互界面要「三秒看懂」，别让操作员猜
  • 人工干预要「可逆、可追溯、安全兜底」
  • 半自动模式是「系统做80%，人做20%」，切换要平滑
  • 永远不要相信操作员会记得切回自动模式——系统要主动提醒

嗯，这一章就聊到这儿。人机协同调度，说白了就是「让机器干机器的活，让人干人的活」。设计得好，效率翻倍；设计得不好，就是互相添乱。希望我这些踩过的坑，能帮你少走点弯路。
