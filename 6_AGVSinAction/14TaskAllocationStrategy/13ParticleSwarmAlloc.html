13 基于粒子群算法的分配优化：粒子编码、速度与位置更新、全局最优搜索

粒子群算法，简称PSO。说实话，我第一次接触它是在一个多AGV协同搬运的项目里。当时任务量一上来，贪心算法就开始"摆烂"——分配结果越来越离谱。我翻了不少论文，最后发现PSO这玩意儿，思路简单，效果却出奇的好。

你想想看，一群鸟找食物，每只鸟都不知道食物在哪，但它们会互相交流信息。有的鸟飞得高，视野广；有的鸟飞得低，但嗅觉灵。最终整个鸟群总能找到食物。PSO就是模拟这个过程。

在AGV调度里，我们的"食物"就是最优的任务分配方案。每个粒子代表一种分配方案，粒子群就是一群候选方案。它们通过迭代，不断向最优解靠拢。

13.1 粒子编码——怎么把分配方案变成粒子

编码是PSO的第一步。说白了，就是怎么用一串数字表示"哪个AGV去干哪个任务"。

我个人习惯用整数编码。假设有M个AGV，N个任务。每个粒子的位置就是一个N维向量，每一维的值表示该任务分配给哪个AGV。

举个例子：

3台AGV（编号0,1,2），5个任务。

粒子位置：[2, 0, 1, 2, 1]

含义：任务0→AGV2，任务1→AGV0，任务2→AGV1，任务3→AGV2，任务4→AGV1

这里有个坑。我在项目里遇到过：如果直接用连续值编码，比如位置是2.7，那它到底对应AGV2还是AGV3？所以我的做法是——取整。位置值在[0, M-1]范围内，计算适应度时四舍五入取整。

# 粒子编码示例
def decode_particle(position, num_agvs):
    """
    将粒子位置解码为任务分配方案
    position: [0, num_agvs-1] 之间的浮点数数组
    """
    assignment = [int(round(p)) for p in position]
    # 边界处理：防止越界
    assignment = [min(max(a, 0), num_agvs-1) for a in assignment]
    return assignment

我的经验：编码时最好预留一个"空闲"标记。比如用-1表示该任务暂不分配，等后续再动态调整。这在任务数多于AGV容量时特别有用。

13.2 速度与位置更新——粒子怎么"飞"

PSO的核心就两个公式：速度更新和位置更新。别被公式吓到，其实逻辑很简单。

速度更新公式：

v_new = w * v_old 
       + c1 * r1 * (pbest - x) 
       + c2 * r2 * (gbest - x)

拆开来看：

  • w * v_old：惯性部分。粒子保持原来的运动趋势。w越大，全局搜索能力越强；w越小，局部搜索越精细。
  • c1 * r1 * (pbest - x)：个体认知。粒子向自己历史最优位置靠拢。c1控制"自信"程度。
  • c2 * r2 * (gbest - x)：社会认知。粒子向群体最优位置靠拢。c2控制"从众"程度。

r1和r2是[0,1]之间的随机数，给搜索引入随机性。我刚开始调参时，总想把随机数去掉，觉得它不靠谱。后来发现，没有随机性，粒子群很容易陷入局部最优——就像一群人开会，大家都听一个人的，最后方案肯定有盲区。

位置更新公式：

x_new = x_old + v_new

简单吧？就是老位置加上速度向量，得到新位置。

注意：速度需要做限幅处理。我曾经在一个项目中没做限幅，结果粒子位置直接飞到了AGV编号100多（实际只有5台AGV）。后来我加了速度上限，一般设为位置范围的10%-20%。

def update_velocity(velocity, position, pbest, gbest, w, c1, c2, v_max):
    import random
    r1 = random.random()
    r2 = random.random()
    
    # 速度更新
    new_velocity = (w * velocity 
                    + c1 * r1 * (pbest - position) 
                    + c2 * r2 * (gbest - position))
    
    # 速度限幅
    new_velocity = [max(min(v, v_max), -v_max) for v in new_velocity]
    return new_velocity

def update_position(position, velocity, pos_min, pos_max):
    new_position = position + velocity
    # 位置限幅
    new_position = [max(min(p, pos_max), pos_min) for p in new_position]
    return new_position

13.3 全局最优搜索——怎么找到最好的方案

全局最优搜索，说白了就是"比一比，留最好的"。每个粒子有两个"记忆"：

  • 个体最优（pbest）：这个粒子自己历史上找到的最好位置
  • 全局最优（gbest）：整个粒子群中所有粒子找到的最好位置

每次迭代，我们都要做两件事：

  1. 计算每个粒子当前位置的适应度（比如总行驶距离、任务完成时间等）
  2. 更新pbest和gbest

适应度函数设计：

在AGV调度中，我通常把适应度设计为最小化总完成时间。但光这样不够，还要加惩罚项：

  • 任务超时惩罚
  • AGV冲突惩罚（两车同时去同一个站点）
  • 电量不足惩罚

适应度值越小，方案越好。

def evaluate_fitness(assignment, tasks, agvs):
    """
    计算分配方案的适应度
    assignment: [任务0的AGV, 任务1的AGV, ...]
    返回：总完成时间 + 惩罚项
    """
    total_time = 0
    penalty = 0
    
    # 计算每个AGV的任务序列和总时间
    agv_tasks = {i: [] for i in range(len(agvs))}
    for task_id, agv_id in enumerate(assignment):
        agv_tasks[agv_id].append(task_id)
    
    for agv_id, task_list in agv_tasks.items():
        time = calculate_agv_time(agv_id, task_list, tasks, agvs)
        total_time += time
        
        # 检查是否超时
        if time > agvs[agv_id]['max_work_time']:
            penalty += 1000  # 超时惩罚
    
    return total_time + penalty

13.4 完整算法流程

嗯，到这里，我们把PSO的三个核心部分都讲完了。把它们串起来，就是完整的算法流程：

  1. 初始化：随机生成N个粒子，每个粒子随机分配任务给AGV
  2. 评估：计算每个粒子的适应度
  3. 更新pbest：如果当前位置比历史最优好，就更新
  4. 更新gbest：从所有pbest中挑最好的
  5. 更新速度和位置：用公式计算新速度和位置
  6. 检查终止条件：达到最大迭代次数或适应度不再改善，就停止
  7. 输出：gbest对应的分配方案

调参建议：

  • w（惯性权重）：我一般从0.9线性递减到0.4。前期大范围搜索，后期精细调整
  • c1、c2：通常取2.0。如果问题复杂，可以c1大一点（鼓励探索），c2小一点
  • 粒子数量：20-50个。任务少就少点，任务多就多点

我曾经在一个仓储项目里用PSO做任务分配。仓库有15台AGV，高峰期每小时要处理200多个任务。用贪心算法，任务完成率只有78%。换成PSO后，完成率提升到了93%。虽然每次计算要多花2-3秒，但效果立竿见影。

当然，PSO也不是万能的。如果任务数量特别大（比如上千个），粒子群的收敛速度会变慢。这时候我通常会结合启发式初始化——先用贪心算法生成一个不错的初始解，把它作为一个粒子的初始位置，其他粒子随机生成。这样既能保证收敛速度，又能避免陷入局部最优。

最后说一句，PSO的参数调优没有银弹。我在不同项目里用过完全不同的参数组合。关键是要理解每个参数的作用，然后根据实际问题去试。多跑几次实验，你就能找到感觉。
