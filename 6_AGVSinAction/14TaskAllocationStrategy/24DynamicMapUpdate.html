24 地图动态更新：障碍物检测与避让、动态路权分配、局部路径重规划

各位同行，今天我们来聊聊AGV调度系统里一个绕不开的硬骨头——地图动态更新。

说实话，静态地图谁都会做。但真正让系统“活”起来的，是它能不能应对突发状况。我见过太多项目，地图画得漂漂亮亮，一遇到叉车临时挡路、托盘放歪了，整个车队就卡死。嗯，今天我们就来拆解这个问题。

一、为什么地图必须“动态”？

你想想看，工厂里的环境是实时变化的。昨天这里还没东西，今天可能就堆了一箱货。AGV如果只认死地图，那跟瞎子开车没区别。

我个人习惯把地图更新分成三个层次：

  • 静态层：墙壁、固定货架、永久通道。这些基本不变。
  • 半静态层：充电桩位置、工作站、缓存区。偶尔调整。
  • 动态层：临时障碍物、其他AGV、人员、叉车。这才是重点。

说白了，动态更新主要处理的就是第三层。我在项目中遇到过最头疼的情况，就是两台AGV在窄通道里互相“顶牛”，谁都不让谁。后来我才意识到，光有路径规划不够，还得有动态路权分配。

二、障碍物检测与避让

障碍物检测，听起来简单，做起来坑很多。

AGV通常靠激光雷达、超声波、或者视觉传感器来感知周围。但传感器有盲区，也有误报。我记得有一次，一台AGV对着墙上的消防栓猛报警，以为是障碍物。后来发现是激光雷达的安装角度偏了。

核心原则：障碍物检测不是“看到就停”，而是“判断后决策”。

我一般把障碍物分为三类：

类型 特征 处理方式
静态障碍物 位置固定，如临时堆放的货物 更新地图，标记为不可通行
动态障碍物 移动中，如行人、叉车 减速、等待、或绕行
半静态障碍物 偶尔移动，如可移动货架 触发重新扫描，更新路网

避让策略上，我个人习惯用“分级响应”：

  • 远距离（>5米）：提前减速，规划绕行路径。
  • 中距离（2-5米）：停车等待，或发出请求让障碍物移动。
  • 近距离（<2米）：紧急制动，同时上报调度系统。

避坑指南：我曾经在项目里只做了“检测到障碍物就停车”，结果AGV在仓库门口停了一整天，因为门口总有工人经过。后来改成“短暂等待+超时绕行”，问题才解决。

三、动态路权分配

路权分配，说白了就是“谁先走，谁让谁”。

多台AGV同时运行时，如果没有路权管理，那就是一场灾难。我见过最夸张的场景，四台AGV在十字路口堵成一团，每台都在等对方让路。

动态路权分配的核心逻辑：

  1. 路段占用锁：每个路段同一时间只允许一台AGV进入。
  2. 优先级机制：任务紧急的AGV优先通过。
  3. 死锁检测：如果发现循环等待，强制让其中一台倒车。

这里我分享一个常用的路权分配伪代码：

// 动态路权分配示例
function requestRightOfWay(agvId, segmentId):
    if segment[segmentId].isOccupied:
        // 路段被占用，加入等待队列
        waitQueue[segmentId].add(agvId)
        // 检查是否死锁
        if detectDeadlock(agvId, segmentId):
            resolveDeadlock()
        return WAITING
    else:
        // 分配路权
        segment[segmentId].occupier = agvId
        return GRANTED

function releaseRightOfWay(agvId, segmentId):
    segment[segmentId].occupier = null
    // 通知下一个等待的AGV
    if waitQueue[segmentId].notEmpty():
        nextAgv = waitQueue[segmentId].pop()
        notify(nextAgv, segmentId)

注意：路权分配一定要考虑“超时释放”。我曾经遇到过AGV在路段中间故障，结果锁死了整条通道。后来加了心跳检测，如果AGV超过10秒没有移动，自动释放路权。

四、局部路径重规划

当障碍物出现，或者路权被占用时，AGV不能傻等，得重新规划路径。

但全局重规划太耗时，尤其是地图大的时候。所以，我一般用“局部重规划”。

局部重规划的思路：

  • 范围限定：只在障碍物周围一定半径内重新搜索路径。
  • 增量更新：保留原有路径的大部分，只修改受影响的部分。
  • 实时性：重规划必须在100ms内完成，否则AGV会停下来。

我常用的算法是D* Lite，它特别适合动态环境。每次只更新一小块区域的代价，不用全图重算。

// 局部路径重规划伪代码
function localReplan(agvId, obstaclePosition):
    // 1. 获取当前路径
    currentPath = getCurrentPath(agvId)
    // 2. 找到障碍物影响的路段
    affectedSegments = findAffectedSegments(currentPath, obstaclePosition)
    // 3. 在受影响区域内重新规划
    newLocalPath = DStarLite(agvId, affectedSegments)
    // 4. 拼接路径
    finalPath = splicePath(currentPath, newLocalPath)
    return finalPath

我的经验：局部重规划时，别忘了给AGV留一个“安全缓冲区”。我习惯在障碍物周围额外扩大0.5米的不可通行区域，防止AGV贴着障碍物走，那样太危险。

下面这张图，是我对本章知识点的总结。你可以看到，地图动态更新是一个闭环：检测到变化 → 更新地图 → 重新分配路权 → 重规划路径 → 执行 → 继续检测。

六、实战中的坑与对策

最后，我总结几个实战中容易踩的坑：

  • 地图更新太频繁：AGV每走一步都更新地图，系统直接卡死。我建议设置更新阈值，比如障碍物位置变化超过20cm才触发更新。
  • 路权分配不考虑任务优先级：紧急任务被普通任务堵住，导致产线停线。我习惯在路权请求里带上任务等级。
  • 重规划路径太“绕”：有时候算法为了避开障碍物，规划出一条极其诡异的路径。我一般会加一个“路径平滑”步骤，把多余的拐弯去掉。

一句话总结：地图动态更新不是技术问题，而是工程问题。检测要准，分配要快，重规划要稳。三者缺一不可。
