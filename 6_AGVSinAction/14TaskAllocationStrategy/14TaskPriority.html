14 任务优先级策略：静态优先级（FIFO、EDF）、动态优先级（基于截止时间、基于价值密度）

各位同行，今天我们来聊聊任务优先级策略。说实话，这是AGV调度系统里最让我头疼，也最有意思的一块。

你想想看，仓库里几十台AGV同时跑，任务一个接一个地来。谁先走？谁后走？搞不好就是死锁、拥堵、订单超时。我见过太多项目，算法写得花里胡哨，结果现场一跑就崩。说白了，优先级策略没选对。

我个人习惯把优先级策略分成两大类：静态优先级和动态优先级。咱们一个一个说。

14.1 静态优先级：简单粗暴，但够用

静态优先级，就是任务一进来，优先级就定死了。后面不管发生什么，都不改。好处是啥？实现简单，CPU开销小。坏处呢？不够灵活。

14.1.1 FIFO（先进先出）

FIFO，说白了就是排队。谁先来，谁先干。这招在任务量不大、紧急程度差不多的时候特别好使。

我记得有一次给一个电商仓库做调度。白天订单少，FIFO跑得稳稳的。但一到双十一大促，订单像潮水一样涌进来。FIFO就扛不住了——一个普通订单排在前头，后面加急订单只能干等着。

适用场景：任务类型单一、无紧急程度差异、系统负载较低。

14.1.2 EDF（最早截止时间优先）

EDF就聪明一点了。它不看谁先来，看谁最急。每个任务都有一个截止时间，谁的时间最近，谁先执行。

我做过一个产线配送项目，每个工位都有严格的物料到达时间窗口。EDF就特别合适。举个例子：

// 伪代码示例：EDF调度核心逻辑
Task taskA = { id: "A", deadline: 10:30:00 };
Task taskB = { id: "B", deadline: 10:25:00 };
Task taskC = { id: "C", deadline: 10:35:00 };

// 按截止时间排序
priorityQueue.sortByDeadline();
// 结果：B -> A -> C

嗯，这里要注意。EDF有个坑——如果任务太多，CPU可能一直在做排序。我建议任务队列长度控制在200以内，否则性能会下降。

我曾经踩过的坑：EDF在任务量突增时，会出现“多米诺效应”——一个任务超时，导致后续所有任务都跟着超时。解决方案是引入“松弛时间”概念，给每个任务留点余量。

14.2 动态优先级：灵活，但复杂

动态优先级就不一样了。任务的优先级不是一成不变的，它会随着时间、系统状态、任务价值等因素动态调整。说白了，就是“见风使舵”。

14.2.1 基于截止时间的动态优先级

这个和EDF有点像，但更灵活。任务的优先级会随着时间推移而升高。比如一个任务还有10分钟截止，优先级是5；还剩5分钟，优先级升到8；还剩1分钟，优先级直接拉满到10。

我管这叫“紧迫度递增策略”。在医疗物流AGV项目里，这招特别好使。运送紧急药品的AGV，越接近截止时间，优先级越高，其他AGV都得给它让路。

// 动态优先级计算示例
function calculatePriority(task) {
    let remainingTime = task.deadline - currentTime;
    let basePriority = task.basePriority;
    
    // 紧迫度因子：剩余时间越少，因子越大
    let urgencyFactor = 1 + (1 / (remainingTime + 1));
    
    return basePriority * urgencyFactor;
}
我的经验：动态优先级更新不要太频繁。我一般设置每5秒或每完成一个任务后更新一次。太频繁了，调度器自己先累趴了。

14.2.2 基于价值密度的动态优先级

这个策略，我个人觉得是最“聪明”的。它不光看任务急不急，还看任务“值不值”。

价值密度 = 任务价值 / 任务耗时。

举个例子：

任务 价值（元） 耗时（分钟） 价值密度
运送VIP订单 500 10 50
运送普通补货 100 5 20
运送退货 50 8 6.25

你看，虽然VIP订单价值高，但耗时也长。普通补货虽然价值低，但耗时短，价值密度反而更高。在系统繁忙时，优先处理价值密度高的任务，整体收益最大。

我在一个跨境电商仓库用过这个策略。当时有个场景：一台AGV正在执行退货任务，突然来了一个高价值订单。系统自动把退货任务挂起，先跑高价值订单。结果呢？当天整体吞吐量提升了15%。

注意：价值密度策略有个前提——你得能准确评估每个任务的价值和耗时。如果评估不准，那就是瞎指挥。我建议用历史数据做机器学习模型，动态预测任务耗时。

14.4 实战建议

说了这么多理论，最后给点实在的。

  • 不要迷信任何一种策略。我见过有人非要用EDF，结果现场全是普通任务，EDF和FIFO效果一样，还多花了CPU。选策略要看场景。
  • 混合策略往往更香。我现在的做法是：先用静态优先级做粗筛，再用动态优先级做细调。比如FIFO排队，但紧急任务可以插队。
  • 一定要有兜底机制。不管用什么策略，都要设置最大等待时间。一个任务等太久，直接提升到最高优先级。这叫“饥饿保护”。
一个小技巧：在系统上线初期，先用FIFO跑一段时间，收集数据。然后根据数据调整策略参数。别一上来就上复杂的动态策略，容易翻车。

好了，关于任务优先级策略，今天就聊到这儿。记住一句话：没有最好的策略，只有最合适的策略。多试、多调、多总结，你也能成为调度高手。
