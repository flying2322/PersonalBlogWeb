19 货架到人模式的核心逻辑

各位同学，今天咱们聊聊仓储场景里最火的一种模式——货架到人。

说白了，就是让AGV把货架搬到人面前，而不是让人满仓库跑去找货。这个模式在电商、3C、医药行业特别常见。我最早接触这个项目是在2018年，一个大型电商仓，每天要处理10万+订单。当时我就想，如果靠人拉着拣货车满场跑，效率肯定上不去。

1.1 货架到人 vs 人到货架

先看个对比，你就明白为什么货架到人更香了。

对比项 人到货架 货架到人
行走距离 拣货员每天走10-15公里 拣货员几乎不动
拣货效率 80-120件/小时 300-500件/小时
人员培训 需要熟悉库位 几乎零培训
系统复杂度 低 高（调度+路径规划）

你看，效率提升3-5倍，但代价是系统复杂度上去了。嗯，这就是咱们这节课要啃的硬骨头。

1.2 拣选任务分配的核心要素

任务分配不是随便扔给一台AGV就完事。我总结了三要素：

  • 任务优先级：紧急订单、超时订单要优先处理
  • AGV状态：电量、当前位置、当前负载
  • 货架位置：哪个货架离AGV最近、哪个货架被锁定了

举个例子。有一次我在现场调试，发现一台AGV明明空载，却一直不接任务。查了半天，原来是它的电量低于30%，系统自动把它切成了充电模式。你看，状态判断有多重要。

1.3 路径规划与任务分配的集成

任务分配和路径规划，其实是两件事，但必须一起考虑。

任务分配决定「谁去干」，路径规划决定「怎么去」。如果分开做，很容易出现：AGV被分配了任务，但路径被堵死，或者绕远路。

我个人习惯的做法是：

  1. 先做粗粒度分配：根据AGV位置和货架位置，算一个曼哈顿距离
  2. 再做细粒度校验：用A*算法算实际路径，看是否可行
  3. 最后做冲突检测：多台AGV会不会抢路

核心原则：任务分配时就要考虑路径可行性，别等AGV出发了才发现走不通。

1.5 避坑指南

我曾经踩过的坑：

  • 任务分配时没考虑AGV电量，结果AGV半路没电，货架卡在半道上
  • 路径规划只算最短路径，没考虑多AGV冲突，结果三台车在路口堵死
  • 货架锁定机制没做好，两台AGV同时去搬同一个货架

这些坑，你想想看，任何一个都够你调试一整天。所以我的建议是：

实战建议：

  • 任务分配时，预留10%的AGV作为机动队，处理突发订单
  • 路径规划要预留安全距离，至少1.5倍车长
  • 货架锁定用Redis的分布式锁，别用数据库行锁，性能差太多

1.6 代码示例：任务分配核心逻辑

下面是一个简化版的任务分配代码，我用Python写的。实际项目里会用C++或者Java，但逻辑是一样的。

class TaskAllocator:
    def __init__(self, agv_list, shelf_list):
        self.agvs = agv_list  # AGV列表
        self.shelves = shelf_list  # 货架列表
    
    def assign_task(self, order):
        # 1. 筛选可用AGV（电量>30%，空闲状态）
        available_agvs = [agv for agv in self.agvs 
                         if agv.battery > 30 and agv.status == 'idle']
        
        if not available_agvs:
            return None  # 没有可用AGV
        
        # 2. 找到最近的AGV
        target_shelf = self.shelves[order.shelf_id]
        best_agv = min(available_agvs, 
                      key=lambda agv: self.manhattan_distance(
                          agv.position, target_shelf.position))
        
        # 3. 锁定货架和AGV
        target_shelf.lock()
        best_agv.assign(order)
        
        return best_agv
    
    def manhattan_distance(self, pos1, pos2):
        return abs(pos1.x - pos2.x) + abs(pos1.y - pos2.y)

这段代码看着简单，但实际项目里要考虑的东西多得多。比如：

  • 多订单同时到达时的排队策略
  • AGV任务完成后的回库策略
  • 货架热度的动态调整（热门货架优先靠近拣选站）
