4 单任务分配策略：就近分配、最早空闲、贪心算法

各位同学，今天我们来聊聊单任务分配策略。说白了，就是当系统里只有一个新任务冒出来时，我们该派哪辆车去干这活。

这个问题看似简单，但我在实际项目中踩过不少坑。有一次在3C电子厂的仓库里，就因为分配策略选错了，导致AGV空跑率飙升到40%。嗯，咱们今天就把这三种经典策略掰开揉碎了讲清楚。

4.1 就近分配原则

这个策略最直观——谁离任务点最近，谁就去。你想想看，这就像你叫外卖，肯定选离你最近的餐厅，送得快嘛。

核心逻辑：计算所有空闲AGV到任务起点的曼哈顿距离，选最小的那辆。

def nearest_vehicle(task, vehicles):
    min_dist = float('inf')
    selected = None
    for v in vehicles:
        if v.status == 'idle':
            dist = abs(v.x - task.start_x) + abs(v.y - task.start_y)
            if dist < min_dist:
                min_dist = dist
                selected = v
    return selected

我个人习惯在小型仓库（50台车以内）用这个策略。它响应快，计算量小，CPU几乎没负担。

我的经验：在电子元器件仓库，任务密集且距离短，就近分配能把空跑时间压缩到最低。我曾经在一个3000平米的仓库里，用这个策略把平均响应时间从12秒降到了4秒。

避坑指南：我曾经犯过一个错误——没考虑AGV的当前电量。结果最近的那辆车电量只剩15%，跑到一半没电了，堵在通道上。后来我加了个电量阈值过滤，低于20%电量的车不参与就近分配。

4.2 最早空闲车辆优先

这个策略关注的是时间维度——谁最早完成当前任务，谁就去接新活。说白了就是「先闲先得」。

为什么会这样？因为有些AGV虽然离得远，但它马上要空闲了；而近的那辆可能还有3个任务在排队。你想想看，这时候派近的车反而不划算。

def earliest_idle_vehicle(task, vehicles):
    earliest = None
    earliest_time = float('inf')
    for v in vehicles:
        if v.status == 'idle':
            # 空闲车辆，预计空闲时间就是当前时间
            idle_time = 0
        else:
            # 忙碌车辆，预计空闲时间 = 当前任务剩余时间
            idle_time = v.remaining_time()
        if idle_time < earliest_time:
            earliest_time = idle_time
            earliest = v
    return earliest
策略 适用场景 缺点
就近分配 任务密集、距离短 忽略车辆忙闲状态
最早空闲 任务稀疏、长距离运输 计算稍复杂，需预测剩余时间

我建议：在电商大促期间，订单洪峰到来时，最早空闲策略能有效平衡负载。我记得双十一那天，我们用这个策略让AGV利用率从65%提升到了82%。

4.3 基于距离的贪心算法

这个策略是前两者的结合体。它不只看距离，也不只看空闲时间，而是算一个综合得分——谁的总成本最低，谁就去。

贪心算法的核心思想：每一步都选当前最优解。在单任务分配里，就是选那个「完成任务总时间最短」的AGV。

def greedy_assignment(task, vehicles):
    best_vehicle = None
    best_cost = float('inf')
    for v in vehicles:
        if v.status != 'idle':
            continue
        # 成本 = 空跑时间 + 任务执行时间
        travel_time = distance(v, task.start) / v.speed
        execute_time = distance(task.start, task.end) / v.speed
        total_cost = travel_time + execute_time
        if total_cost < best_cost:
            best_cost = total_cost
            best_vehicle = v
    return best_vehicle

实际项目中的变体：我在汽车零部件工厂做过一个优化——在成本函数里加入了「路径拥堵系数」。如果某条路线上已经有3辆车了，就自动加一个惩罚因子。这样能避免所有车挤到同一条通道上。

三种策略的对比

我整理了一张对比表，方便你快速决策：

策略 计算复杂度 响应速度 负载均衡 推荐场景
就近分配 O(n) 快 差 小仓库、任务密集
最早空闲 O(n) 中 好 长距离、任务稀疏
贪心算法 O(n) 中 较好 通用场景

注意：贪心算法虽然叫「贪心」，但它只保证局部最优。我曾经在一个环形布局的仓库里吃过亏——贪心算法选的车虽然单次成本最低，但连续分配几次后，所有车都堆到了同一区域。后来我加了「区域分散因子」才解决。
