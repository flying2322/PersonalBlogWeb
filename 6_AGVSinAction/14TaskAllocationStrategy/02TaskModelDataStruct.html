2 任务建模与数据结构

大家好，我是老张。在AGV调度系统里摸爬滚打了十几年，今天咱们聊聊任务建模这件事。

很多人觉得任务建模不就是定义几个字段吗？起点、终点、优先级，完事。其实没那么简单。我见过太多项目，前期任务模型没设计好，后期改得想哭。今天我把这些年踩过的坑、总结的经验，一次性讲清楚。

1.1 任务属性定义

一个任务，说白了就是告诉AGV「去干什么」。但怎么描述这个「干什么」，学问大了。

1.1.1 核心属性

我个人习惯把任务属性分成三类：定位属性、约束属性、状态属性。

属性类别 属性名称 说明 示例
定位属性 起点 任务起始位置 W01-入库口
定位属性 终点 任务目标位置 R05-货架位
约束属性 优先级 任务紧急程度 1（最高）~ 5（最低）
约束属性 时间窗 允许执行的时间范围 09:00 - 09:30
状态属性 任务状态 当前所处阶段 待分配、执行中、已完成

这里我要特别强调一下时间窗。很多新手会忽略这个字段，觉得「任务来了就干呗」。但实际场景中，时间窗太重要了。

核心观点：时间窗是任务调度的「硬约束」。AGV必须在规定时间内到达指定位置，否则整个生产节拍都会被打乱。

我曾经在一个汽车零部件工厂做项目，客户说「任务没有时间要求」。结果上线后，AGV把物料送到工位时，工人已经下班了。后来我们加了时间窗属性，问题才解决。

1.1.2 扩展属性

除了上面这些，实际项目中我还会加几个扩展属性：

  • 任务类型：搬运、充电、待命、维修等
  • 负载信息：空载、满载、负载重量
  • 关联任务ID：用于任务链、任务依赖
  • 超时策略：超时后重试、取消、降级

你想想看，如果没有「关联任务ID」，你怎么实现「先取A再送B」这种复合任务？

1.2 任务状态机

任务不是一成不变的。它会经历各种状态转换。我习惯用状态机来管理。

小技巧：状态机设计得好，代码逻辑会非常清晰。我见过有人用if-else写状态流转，那叫一个乱。

1.2.1 标准状态定义

这是我常用的状态定义：

// 任务状态枚举
enum TaskState {
    PENDING,      // 待分配
    ASSIGNED,     // 已分配
    ACCEPTED,     // 已接受
    EXECUTING,    // 执行中
    COMPLETED,    // 已完成
    FAILED,       // 失败
    CANCELLED     // 已取消
}

1.2.2 状态转换规则

状态转换不是随便跳的。我总结了几条铁律：

  • PENDING → ASSIGNED：调度器分配了AGV
  • ASSIGNED → ACCEPTED：AGV确认接收任务
  • ACCEPTED → EXECUTING：AGV开始移动
  • EXECUTING → COMPLETED：任务正常结束
  • 任何状态 → FAILED：出现异常（AGV故障、路径阻塞等）
  • PENDING/ASSIGNED → CANCELLED：人工取消或超时取消

注意：千万不要让状态随意跳转。比如从「已完成」跳回「执行中」，这会导致数据混乱。我见过有人这么干，结果报表全错了。

嗯，这里要注意一点：状态机要支持回滚。比如AGV走到一半发现路堵了，任务状态要从「执行中」回退到「待分配」。这个逻辑很多新手会漏掉。

1.3 任务队列设计

任务队列是调度系统的「心脏」。所有任务都在这里排队，等待被分配。

1.3.1 队列结构

我一般用优先级队列 + 时间窗队列的组合：

// 任务队列数据结构
class TaskQueue {
    // 按优先级排序的队列
    PriorityQueue<Task> priorityQueue;
    
    // 按时间窗排序的队列
    PriorityQueue<Task> timeWindowQueue;
    
    // 所有任务的索引
    HashMap<String, Task> taskIndex;
}

为什么要两个队列？因为调度策略不同。紧急任务看优先级，定时任务看时间窗。

1.3.2 队列调度策略

我常用的策略有三种：

  1. 优先级优先：高优先级任务先分配。适合紧急插单场景。
  2. 时间窗优先：时间窗最早的任务先分配。适合准时制生产。
  3. 混合策略：先按优先级分组，组内按时间窗排序。这是我最常用的。

实战经验：混合策略有个坑——优先级高的任务可能会一直插队，导致低优先级任务永远得不到执行。我一般会加一个「最大等待时间」，超过这个时间的任务自动提升优先级。

1.3.3 队列监控

队列不能只进不出。我习惯加几个监控指标：

  • 队列深度：当前排队任务数
  • 平均等待时间：任务从入队到出队的平均时间
  • 超时任务数：超过时间窗仍未分配的任务数
  • 任务完成率：已完成任务 / 总任务数

这些指标能帮你快速发现系统瓶颈。比如队列深度突然增大，说明AGV不够用了。
