12 基于遗传算法的分配优化：染色体编码、适应度函数、交叉与变异操作

说到任务分配，很多朋友第一反应就是贪心算法或者匈牙利算法。嗯，这些方法在小规模场景下确实好用。但当你面对几十台AGV、几百个任务点时，传统方法往往就卡住了——要么解不出来，要么解出来的结果让人哭笑不得。

这时候，遗传算法就派上用场了。说白了，它就是模拟大自然的进化过程：优胜劣汰，适者生存。我最早接触这个是在一个汽车总装车间的项目里，200多台AGV同时跑，任务队列乱成一锅粥。后来我用遗传算法重构了分配模块，效果出奇的好。

今天我们就来拆解一下，遗传算法在AGV任务分配中到底怎么落地。核心就四个字：编、适、交、变。

12.1 染色体编码——怎么把任务“塞”进基因里

遗传算法第一步，就是把你的解决方案表示成一条“染色体”。在AGV任务分配里，染色体其实就是一组任务到AGV的映射关系。

我个人习惯用整数编码。举个例子：

染色体：[2, 1, 3, 1, 2, 3]
含义：
- 任务0 → AGV 2
- 任务1 → AGV 1
- 任务2 → AGV 3
- 任务3 → AGV 1
- 任务4 → AGV 2
- 任务5 → AGV 3

你看，每个基因位代表一个任务，基因值就是分配给哪台AGV。这种编码方式直观、好理解，而且交叉变异操作起来也方便。

我的经验： 编码方式决定了算法的搜索空间。整数编码适合任务数不多（几百以内）的场景。如果任务量上万，建议改用基于优先级的编码，否则染色体太长，收敛速度会慢得让你怀疑人生。

还有一种编码方式叫排列编码，就是把所有任务排成一个序列，然后按顺序分配给AGV。比如：

染色体：[3, 1, 4, 2, 5, 0]
含义：按这个顺序依次分配给AGV 1、2、3循环

这种方式的好处是天然保证每个AGV的任务量均衡。但我在实际项目中踩过坑——如果AGV的负载能力不一样，这种编码反而会出问题。所以，编码方式一定要跟你的业务约束匹配。

12.2 适应度函数——怎么才算“好”的分配

有了染色体，接下来就要评判它好不好。适应度函数就是干这个的。

在AGV调度里，我们通常关心这几个指标：

  • 总行驶距离：所有AGV完成任务的总路径长度
  • 任务完成时间：最后一个任务完成的时间（makespan）
  • AGV负载均衡：各AGV的工作量差异
  • 能耗：电池消耗情况

我一般会把它们加权组合成一个适应度值。比如：

适应度 = w1 * (1/总距离) + w2 * (1/完成时间) + w3 * (1/负载方差)

其中 w1 + w2 + w3 = 1

为什么要取倒数？因为遗传算法里适应度越大越好，而距离、时间这些指标是越小越好。取个倒数，方向就对了。

注意： 权重的设置很关键。我曾经在一个项目里把负载均衡的权重设得太高，结果算法拼命让所有AGV跑一样多的任务，完全不管路径长短，最后总时间反而变差了。后来我把权重调成了 0.5:0.3:0.2，效果才正常。

还有一种做法是多目标优化，用帕累托前沿来筛选。但说实话，在工业现场，老板通常只关心一个综合指标。所以加权法更实用。

12.3 交叉操作——让好基因“联姻”

交叉，就是让两条染色体交换部分基因，产生新的后代。目的是把好的基因片段组合起来。

常用的交叉方式有：

  • 单点交叉：随机选一个点，交换后面的部分
  • 两点交叉：选两个点，交换中间的部分
  • 均匀交叉：每个基因位以50%概率交换

我个人最常用的是两点交叉。为什么？因为单点交叉容易破坏好的基因块，均匀交叉又太随机。两点交叉刚好平衡。

父代1: [2, 1, 3, 1, 2, 3]
父代2: [1, 3, 2, 2, 1, 3]

选交叉点：位置2和位置4

子代1: [2, 1, | 2, 2, | 2, 3]  → 中间部分来自父代2
子代2: [1, 3, | 3, 1, | 1, 3]  → 中间部分来自父代1

你看，子代既保留了父代的“头部”和“尾部”特征，又引入了新的中间组合。这样搜索空间就能不断扩展。

避坑指南： 交叉概率一般设在0.7~0.9之间。我曾经设成0.5，结果算法收敛极慢，跑了500代还没找到好解。后来改成0.8，100代就出结果了。

12.4 变异操作——防止“近亲繁殖”

交叉虽然能组合基因，但如果种群里所有个体都差不多，就容易陷入局部最优。这时候就需要变异——随机改变某个基因的值，引入新的可能性。

在AGV任务分配里，变异操作很简单：

原始染色体: [2, 1, 3, 1, 2, 3]
随机选中位置3，把值从1改成2
变异后:     [2, 1, 3, 2, 2, 3]

相当于把任务3从AGV 1改派给了AGV 2。就这么一个小改动，有时候能带来意想不到的优化效果。

变异概率通常设得很低，0.01~0.1之间。太高了算法就变成随机搜索了，太低又起不到作用。我一般取0.05，也就是每100个基因里有5个会发生变异。

核心要点：
  • 编码：整数编码最常用，注意匹配业务约束
  • 适应度：加权组合多个指标，权重需要调参
  • 交叉：两点交叉效果好，概率0.7~0.9
  • 变异：概率0.01~0.1，防止早熟收敛

下面这张图展示了遗传算法在AGV任务分配中的完整流程。你可以看到，从初始化种群开始，经过适应度评估、选择、交叉、变异，一代代进化，直到找到满意的分配方案。

嗯，到这里你应该对遗传算法的核心操作有了清晰的认识。编码、适应度、交叉、变异，这四个环节环环相扣。我在实际项目中调试最多的就是适应度函数的权重和交叉概率，这两个参数直接决定了算法能不能找到好解。

记住一句话：没有万能的参数，只有不断调试出来的经验。多跑几组实验，对比不同参数下的收敛曲线，你很快就能找到适合自己场景的那组参数。
