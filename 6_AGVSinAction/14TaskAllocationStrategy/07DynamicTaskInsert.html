7 动态任务插入策略

各位做AGV调度的朋友，咱们今天聊点实际的。

静态调度谁都会做，任务排好队一个个跑就行。但现实世界哪有那么理想？

我做了这么多年AGV系统，最头疼的就是——任务突然来了怎么办？

你想想看，产线上正跑得好好的，突然来个急单，或者某个工位物料告急。这时候系统要是傻等着当前任务跑完，那产线就得停。停线的代价，动辄每分钟几万块。

所以，动态任务插入策略，说白了就是让AGV系统具备「应急处理能力」。

7.1 在线任务到达处理

先说说最简单的场景：新任务来了，系统怎么接？

我个人习惯把任务到达分成三种情况：

  • 空闲态插入：AGV闲着，任务来了直接派
  • 运行态插入：AGV正在执行任务，新任务排队等待
  • 紧急态插入：新任务优先级高，需要打断当前任务

前两种都好处理，真正考验系统的是第三种。

核心原则：在线任务到达时，系统必须在50ms内完成「任务评估-路径计算-资源分配」三步。超过这个时间，产线就可能出现等待。

我在项目中遇到过一个问题：某次客户现场，新任务到达后系统花了200ms才响应。结果就是AGV在路口犹豫了一下，跟另一台车差点撞上。从那以后，我强制要求所有任务插入必须在30ms内完成决策。

7.2 任务抢占与重分配

任务抢占，这是个敏感话题。

为什么敏感？因为抢占意味着「有人要被牺牲」。你想想看，一个AGV正拉着半成品去下一站，突然被叫停去干别的。那半成品怎么办？产线节奏怎么调？

我总结了一套抢占规则，供你参考：

抢占类型 触发条件 处理方式
完全抢占 紧急任务优先级 > 当前任务3级以上 立即停止当前任务，AGV原地待命或空载返回
部分抢占 紧急任务优先级 > 当前任务1-2级 完成当前任务的关键步骤后再切换
非抢占 优先级相同或略高 当前任务执行完再处理新任务

这里有个坑，我曾经踩过：

避坑指南：我曾经在某个项目中允许完全抢占任意任务，结果导致一台AGV在10分钟内被抢占了5次，最后哪个任务都没完成。后来我加了个「最小执行时间」保护——每个任务至少执行30秒后才允许被抢占。

重分配的逻辑其实更复杂。当任务被抢占后，被搁置的任务怎么办？

我的做法是：

  • 被抢占的任务进入「挂起队列」
  • 系统每5秒检查一次挂起队列
  • 一旦有合适的AGV空闲，立即重新分配
  • 如果挂起超过2分钟，触发告警

7.3 动态优先级调整

优先级不是一成不变的。这是我这些年最大的体会。

很多系统设计者喜欢给任务定死优先级，比如1到10级。但实际运行中，你会发现：

  • 一个原本低优先级的任务，如果等了太久，它其实已经变成了紧急任务
  • 一个高优先级任务，如果一直抢不到资源，它的实际价值也在下降

所以，我建议采用「动态优先级算法」：

// 动态优先级计算示例
function calculatePriority(basePriority, waitTime, deadline) {
    let urgencyFactor = 0;
    
    // 等待时间越长，优先级越高
    if (waitTime > 60) {
        urgencyFactor = 2;
    } else if (waitTime > 30) {
        urgencyFactor = 1;
    }
    
    // 距离截止时间越近，优先级越高
    let deadlineFactor = 0;
    let remainingTime = deadline - currentTime;
    if (remainingTime < 300) {  // 5分钟内
        deadlineFactor = 3;
    } else if (remainingTime < 600) {  // 10分钟内
        deadlineFactor = 2;
    }
    
    return basePriority + urgencyFactor + deadlineFactor;
}

说白了，就是让优先级「活起来」。一个任务在队列里等得越久，它的优先级就应该自动上涨。这样能避免「饿死」现象——低优先级任务永远得不到执行。

个人经验：我习惯在系统中设置一个「优先级天花板」。比如最高优先级是10，但动态调整后不能超过8。为什么？因为要给真正的紧急任务留出空间。如果所有任务都变成10级，那优先级就失去了意义。

但实际落地时，每个判断点背后都有大量细节。比如「优先级高于当前任务」这个判断，不是简单比大小，还要考虑任务类型、AGV当前位置、路径拥堵情况等等。

总结一下：动态任务插入策略，本质上是在「效率」和「公平」之间找平衡。完全偏向效率，低优先级任务永远得不到执行；完全偏向公平，紧急任务又会被耽误。我个人的经验是：让系统有「弹性」，既能快速响应紧急任务，又能保证所有任务最终都能完成。
