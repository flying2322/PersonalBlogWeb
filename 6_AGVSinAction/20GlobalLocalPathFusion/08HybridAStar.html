8 Hybrid A*：考虑车辆运动学的搜索、Reeds-Shepp曲线、在泊车场景中的应用

各位同学，今天我们来聊一个非常实战的话题——Hybrid A*。说实话，我在做AGV泊车项目之前，一直觉得A*算法已经够用了。直到有一次，我让一个差速底盘去执行一个窄车位泊入任务，结果A*规划出来的路径全是折线，车辆根本没法沿着走。嗯，那一次我意识到，不考虑运动学的路径规划，在真实场景里就是纸上谈兵。

Hybrid A* 的出现，说白了就是为了解决这个问题。它把车辆的运动学约束直接塞进了搜索过程里。你想想看，传统的A*是在栅格地图上跳来跳去，而Hybrid A*是在连续的状态空间里“开”过去的。这两者的区别，就像你在地图上画线，和真正握着方向盘开车一样。

8.1 为什么需要Hybrid A*？

我们先看一个简单的对比。传统A*搜索出来的路径，是由一系列离散的网格点组成的。每个点之间用直线连接，车辆在转弯时根本没法平滑过渡。我见过不少新手工程师，拿着A*的路径就直接下发到控制器，结果车辆在原地打转，或者撞到路沿。

Hybrid A* 的核心改进在于：

  • 状态空间是连续的：每个节点不仅包含位置 (x, y)，还包含朝向角 θ。这就意味着，搜索出来的路径天然就是平滑的。
  • 扩展方式基于运动学模型：每次扩展节点时，不是跳到相邻网格，而是根据车辆的最小转弯半径、最大加速度等参数，生成一段真实的行驶轨迹。
  • 代价函数更合理：除了距离代价，还会考虑转向代价、倒车代价、靠近障碍物的惩罚等。

核心要点：Hybrid A* 不是对A*的简单改进，而是把搜索问题从“离散图搜索”变成了“连续空间中的运动学可行搜索”。

8.2 Reeds-Shepp曲线：最短的可行路径

说到Hybrid A*，就绕不开Reeds-Shepp曲线。我个人习惯把它叫做“RS曲线”。这个曲线解决了一个很经典的问题：给定起点和终点的位姿（位置+朝向），如何用最短的距离把车开过去？

RS曲线的厉害之处在于，它考虑了车辆的前进和后退，以及最小转弯半径。它把所有的可行路径归纳为48种类型（实际上对称后是9种基本类型）。比如：

  • CCC：三个圆弧（Curve-Curve-Curve）
  • CSC：圆弧-直线-圆弧
  • CCSC：圆弧-圆弧-直线-圆弧

我在项目中遇到过一个问题：用RS曲线直接连接起点和终点时，如果中间有障碍物，路径就会穿过障碍物。所以RS曲线通常只作为Hybrid A*搜索的“启发式”或者“最终连接段”来使用。

实战技巧：在Hybrid A*搜索过程中，当当前节点距离目标点很近时（比如小于5米），可以直接尝试用RS曲线连接。如果RS曲线没有碰撞，就可以提前终止搜索，大幅提升效率。

8.3 Hybrid A*的搜索流程

我们来拆解一下Hybrid A*的搜索步骤。你想想看，它其实就是在做三件事：

  1. 离散化控制空间：把方向盘转角、油门/刹车等控制量离散成几个档位。比如前进时左转30度、直行、右转30度，后退时同理。
  2. 模拟运动：从当前节点出发，用车辆运动学模型（比如自行车模型）向前模拟一小段距离，生成一系列候选轨迹。
  3. 剪枝与碰撞检测：对每个候选轨迹，检查是否与障碍物碰撞，同时检查是否已经访问过类似的状态（通过栅格哈希来去重）。

下面是我常用的一个伪代码框架，你可以参考一下：

function HybridAStar(start, goal, grid):
    open_set = PriorityQueue()
    open_set.push(start, 0)
    visited = {}
    
    while not open_set.empty():
        current = open_set.pop()
        
        // 尝试用RS曲线直接连接
        if distance(current, goal) < THRESHOLD:
            rs_path = ReedsShepp(current, goal)
            if not collision(rs_path, grid):
                return reconstruct_path(current, rs_path)
        
        // 扩展控制空间
        for control in [forward_left, forward_straight, forward_right,
                        backward_left, backward_straight, backward_right]:
            new_state = simulate_motion(current, control, dt)
            if collision(new_state, grid):
                continue
            
            // 栅格去重
            cell = discretize(new_state.x, new_state.y)
            if cell in visited and visited[cell] <= new_state.g:
                continue
            
            visited[cell] = new_state.g
            new_state.h = heuristic(new_state, goal)  // 可以用RS曲线长度作为启发式
            open_set.push(new_state, new_state.g + new_state.h)
    
    return failure

注意：这里的启发式函数非常关键。如果用欧几里得距离，搜索会非常慢。我建议用RS曲线长度作为启发式，因为它考虑了运动学约束，更接近真实代价。

8.4 在泊车场景中的应用

泊车是Hybrid A*最经典的应用场景之一。为什么？因为泊车需要频繁的前进后退，而且空间非常狭窄。传统A*根本搞不定这种“揉库”操作。

我记得有一次做垂直泊车项目，车位宽度只比车宽多30厘米。用Hybrid A*规划出来的路径是这样的：

  1. 车辆先向前行驶到车位前方
  2. 然后向右打满方向盘，倒车进入车位
  3. 如果一次倒不进去，会自动生成“前进-后退-前进”的多段路径

这里有一个关键点：Hybrid A*的搜索空间是6维的（x, y, θ, 前进/后退, 方向盘转角, 速度）。但在实际工程中，我们通常会把速度固定为低速，只搜索前4维。这样能大幅降低计算量。

下面是我在泊车场景中常用的参数配置：

参数 推荐值 说明
最小转弯半径 2.5 m 根据车辆轴距和最大转向角计算
搜索步长 0.5 m 每一步模拟行驶的距离
控制离散数 6个 前进3个方向 + 后退3个方向
RS曲线阈值 3.0 m 距离目标小于此值时尝试RS连接
栅格分辨率 0.2 m 用于去重的栅格大小

避坑指南：我曾经把栅格分辨率设得太小（0.05m），结果搜索时大量节点被判定为“未访问”，导致计算量爆炸。后来我改成0.2m，效果好了很多。记住，去重栅格的分辨率不需要和地图分辨率一致，它只是用来判断“这个区域是否已经探索过”。

8.6 一些实战建议

最后，我分享几个在项目中踩过的坑：

  • 启发式函数别用欧几里得距离：我之前试过，搜索时间直接翻倍。用RS曲线长度作为启发式，效率高很多。
  • 注意车辆的最小转弯半径：如果地图上的通道宽度小于2倍最小转弯半径，Hybrid A*可能找不到路径。这时候需要降低速度，或者考虑用“原地旋转”的差速底盘。
  • RS曲线的碰撞检测要仔细：RS曲线是一段连续的弧线，不能只检测端点。我建议把曲线离散成多个点，然后逐点检测。
  • 搜索步长别太大也别太小：步长0.5米是个不错的起点。步长太大，路径不够精细；步长太小，搜索节点爆炸。

总结一下：Hybrid A* 是解决泊车、窄通道通行等复杂场景的利器。它把运动学约束融入搜索，配合RS曲线作为启发式和最终连接，能生成真正可执行的路径。你在实际项目中，一定要根据车辆参数和场景特点，调整好搜索步长、控制离散数和去重栅格大小。
