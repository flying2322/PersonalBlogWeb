20 动态环境处理：动态障碍物预测、速度障碍法（VO）、交互博弈、时空联合规划

各位做AGV的朋友，咱们今天聊点硬核的——动态环境处理。

说实话，静态环境下的路径规划，现在开源方案一抓一大把。但真正让AGV从实验室走向工厂、走向医院、走向商超的，恰恰是动态环境的处理能力。我见过太多AGV在静态测试中跑得飞起，一到真实场景就原地打转，或者跟人“跳探戈”。

为什么会这样？因为真实世界是活的。人、其他机器人、叉车、手推车……这些东西不会按你规划的路径走。所以，这一章我们重点解决一个问题：当周围的一切都在动，你的AGV该怎么决策？

核心观点：动态环境处理不是单一算法能搞定的，它需要“预测-决策-规划”三层联动。预测是眼睛，决策是大脑，规划是手脚。

20.1 动态障碍物预测：先看三步，再走一步

我个人习惯把动态障碍物预测比作“下棋”。高手下棋，不是看当前这一步，而是看后面三步。AGV也一样，它需要知道周围的人和机器接下来几秒会往哪走。

预测方法有很多，我挑三个最实用的讲：

20.1.1 基于运动模型的预测

这是最基础的方法。假设障碍物保持当前运动状态不变，用卡尔曼滤波或粒子滤波去跟踪。

// 伪代码：卡尔曼滤波预测障碍物位置
// 状态向量: [x, y, vx, vy]
// 预测步长: dt = 0.1s

void predictObstacle(State& s, float dt) {
    // 状态转移矩阵 F
    s.x += s.vx * dt;
    s.y += s.vy * dt;
    // 协方差更新（略）
}

嗯，这里要注意：这种方法的假设太强了。人突然转身怎么办？叉车突然加速怎么办？我在项目里吃过这个亏——AGV以为行人会直走，结果人家突然拐弯，差点撞上。

我的经验：基于运动模型的预测只适合短期预测（1秒以内）。超过2秒，误差会急剧放大。所以别指望它能预测5秒后的位置。

20.1.2 基于社会力模型的预测

社会力模型（Social Force Model）是Helbing提出来的，原本用于模拟人群疏散。它假设每个行人受到三种力：

  • 驱动力：想去目标点的力
  • 排斥力：避开障碍物和其他人的力
  • 吸引力：被某些目标吸引的力（比如出口、货架）

说白了，就是给每个行人算一个合力，然后预测它的运动趋势。这个方法比纯运动模型准一些，因为它考虑了“意图”。

但有个坑——社会力模型需要知道行人的目标点。在工厂里，你很难知道每个工人要去哪。所以实际应用中，我一般用社会力模型做定性判断，比如“这个人大概率会往左走”，而不是精确预测轨迹。

20.1.3 基于学习的预测

最近几年，基于LSTM、Transformer的轨迹预测火得不行。比如Social-LSTM，它能把周围所有人的轨迹编码成一个“社会张量”，然后预测每个人的未来轨迹。

说实话，效果确实好，但部署成本高。我在一个仓储项目里试过，模型跑在Jetson Xavier上，推理时间要15ms，勉强能接受。但如果你用的是低端MCU，就别想了。

避坑指南：我曾经在AGV上部署过一个深度学习预测模型，结果发现模型在仿真里跑得飞起，一到真实场景就崩。为什么？因为训练数据里没有“人突然蹲下捡东西”这种场景。所以，数据覆盖度比模型复杂度更重要。

20.2 速度障碍法（VO）：让AGV学会“让一让”

预测完了，接下来就是决策。速度障碍法（Velocity Obstacle，简称VO）是我个人非常喜欢的一个方法。它不规划路径，而是直接告诉你：哪些速度是安全的，哪些会撞。

核心思想很简单：

  1. 把AGV和障碍物都抽象成圆（或凸多边形）
  2. 在速度空间里，找出所有会导致碰撞的速度向量
  3. 从剩余的安全速度里选一个最优的

你想想看，这就像开车时，你看到前面有辆车，你脑子里会快速判断：“我如果保持这个速度会撞，我得减速或者变道。”VO做的就是这件事。

// 速度障碍法核心逻辑（简化版）
// AGV位置: pa, 速度: va
// 障碍物位置: pb, 速度: vb
// 安全半径: ra + rb

bool isVelocitySafe(Vector2 va, Vector2 vb, Vector2 pa, Vector2 pb) {
    Vector2 relVel = va - vb;          // 相对速度
    Vector2 relPos = pb - pa;          // 相对位置
    float dist = relPos.length();
    
    // 计算碰撞锥的半角
    float halfAngle = asin((ra + rb) / dist);
    
    // 判断相对速度是否在碰撞锥内
    float angle = angleBetween(relVel, relPos);
    return abs(angle) > halfAngle;
}

但VO有个问题——它假设障碍物会保持当前速度。如果对方突然变向，VO就失效了。所以后来有了RVO（Reciprocal VO）和ORCA（Optimal Reciprocal Collision Avoidance），加入了“互相避让”的机制。

我的建议：在工厂AGV场景中，用ORCA比用原始VO更靠谱。因为ORCA考虑了双方都在避让的情况，不会出现“两个人互相让，结果让到一起去”的尴尬局面。

20.3 交互博弈：当AGV学会“读心术”

VO虽然好用，但它有个隐含假设：障碍物不会主动配合你。但在真实场景中，人和机器是会互动的。比如你推着购物车走向一个人，对方会下意识地让开。这种“你让我，我让你”的交互，就是博弈论要解决的问题。

交互博弈的核心是纳什均衡——每个智能体都选择对自己最有利的策略，同时考虑对方的策略。在AGV场景中，可以建模成：

  • 策略空间：左转、右转、减速、加速、停止
  • 收益函数：到达目标的时间 + 碰撞惩罚 + 舒适度惩罚
  • 求解目标：找到一组策略，使得任何一方单方面改变策略都不会获益

听起来很完美对吧？但实际做起来，计算量巨大。两个智能体还好，如果场景里有5个、10个，求解纳什均衡的复杂度是指数级的。

所以我在实际项目中，用的是简化版博弈：只考虑AGV和最近的一个障碍物之间的博弈，其他障碍物用VO处理。这样既保留了博弈的“交互感”，又不会把算力吃光。

一个小技巧：在博弈模型中，给“让行”行为加一个小的正收益。这样AGV会倾向于主动让行，而不是等对方让。这在人机交互中特别重要——人会觉得这AGV“有礼貌”。

20.4 时空联合规划：把时间维度拉进来

前面讲的预测、VO、博弈，本质上都是在做“瞬时决策”。但AGV的路径是一条连续的轨迹，不能只看当前这一帧。所以我们需要时空联合规划——把时间作为一个维度，和空间一起规划。

最经典的方法是ST图（Space-Time Graph）：

  • 横轴是时间 t
  • 纵轴是路径里程 s（沿着参考路径的距离）
  • 每个点 (s, t) 表示“在t时刻，AGV在路径上的s位置”
  • 动态障碍物的轨迹在ST图上表现为“障碍物区域”

然后，问题就变成了：在ST图上找一条从起点到终点的、不穿过障碍物区域的路径。这可以用A*或者动态规划来解。

// 时空A*搜索（简化版）
struct STNode {
    float s;      // 路径里程
    float t;      // 时间
    float cost;   // 累计代价
};

// 启发式函数：假设匀速行驶到终点
float heuristic(STNode node, float s_goal) {
    float remaining = s_goal - node.s;
    return remaining / MAX_SPEED;
}

// 扩展节点：考虑加速、减速、匀速三种动作
vector<STNode> expand(STNode node) {
    vector<STNode> children;
    float dt = 0.1;  // 时间步长
    for (float acc : {-MAX_ACC, 0, MAX_ACC}) {
        float v_new = node.v + acc * dt;
        v_new = clamp(v_new, MIN_SPEED, MAX_SPEED);
        float s_new = node.s + v_new * dt;
        float t_new = node.t + dt;
        // 检查是否与障碍物碰撞
        if (!isColliding(s_new, t_new)) {
            children.push_back({s_new, t_new, node.cost + cost(acc)});
        }
    }
    return children;
}

ST图的好处是直观，但缺点也很明显——它假设AGV沿着固定路径走。如果AGV需要横向避让（比如变道），ST图就搞不定了。这时候需要时空联合轨迹优化，把横向偏移也作为优化变量。

我曾经踩过的坑：在ST图上做规划时，时间步长设得太小（0.01s），结果搜索空间爆炸，AGV在原地算了3秒才动。后来我把步长调到0.2s，虽然轨迹粗糙了点，但实时性好了很多。记住：实时性优先，精度次之。

20.5 实战中的融合策略

讲了这么多，你可能会问：这些方法到底怎么组合在一起用？

我分享一个我在项目中验证过的融合框架：

层级 方法 更新频率 输出
预测层 卡尔曼滤波 + 社会力模型 10Hz 障碍物未来3秒的预测轨迹
决策层 ORCA + 简化博弈 20Hz 当前时刻的最优速度向量
规划层 时空A* + 轨迹优化 2Hz 未来5秒的平滑轨迹

这个框架的核心思路是：高频做决策，低频做规划。决策层（ORCA）每50ms更新一次，保证AGV能快速响应突发情况；规划层（时空A*）每500ms更新一次，保证轨迹的全局最优性。

嗯，这里有个细节要注意：决策层的输出和规划层的输出不能冲突。我一般让规划层生成一条“参考轨迹”，决策层在参考轨迹附近做微调。如果决策层发现必须大幅偏离参考轨迹（比如有人突然冲出来），就触发规划层重新规划。

总结一句话：动态环境处理没有银弹。预测、VO、博弈、时空规划，每个方法都有自己的适用场景。我的做法是——用预测看未来，用VO保安全，用博弈懂人心，用时空规划定全局。四者结合，才能让AGV在真实世界中跑得稳、跑得顺。
