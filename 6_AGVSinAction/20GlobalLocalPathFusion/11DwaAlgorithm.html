11 DWA算法详解：速度空间采样、轨迹预测、评价函数设计、动态窗口的工程调参

DWA，全称Dynamic Window Approach，中文叫动态窗口法。

说实话，这名字起得挺贴切的。它核心就干一件事：在每一帧控制周期里，从所有可能的速度组合中，找出那个最安全、最接近目标、跑得还最快的速度。

我当年刚接触AGV时，觉得这算法挺玄乎。后来亲手调过几台车，踩过坑，才真正理解它的精髓。今天咱们就把DWA掰开揉碎，从采样到评价，再到工程调参，一次性讲透。

核心思想一句话：DWA不是规划一条长路径，而是每时每刻都在问自己——「我现在踩油门、打方向，接下来几秒钟会不会撞墙？能不能往前走？」

11.1 速度空间采样：到底哪些速度是「合法」的？

DWA的第一步，就是找出所有「可能的速度」。但注意，不是随便什么速度都行。

我习惯把速度空间分成三层过滤：

  1. 第一层：机器人自身极限
    说白了，电机能转多快？最大线速度v_max，最小v_min，最大角速度ω_max。超出这个范围，物理上就做不到。
  2. 第二层：电机加减速能力
    就算你当前能跑到1m/s，但电机加速度有限。下一时刻你最多能加速到v_max_acc，或者减速到v_min_acc。这个窗口就是「动态窗口」的由来。
  3. 第三层：安全约束
    即使速度在物理范围内，但如果按这个速度跑下去，会在刹车距离内撞到障碍物，那也得排除。

嗯，这里要注意：第三层其实已经属于轨迹预测的范畴了。很多初学者把采样和预测混在一起，我建议你分开理解——先采样出候选速度，再逐个预测轨迹，最后评价。

我的经验：采样分辨率别设太密。v方向0.1m/s步长，ω方向0.1rad/s步长，对于大多数室内AGV已经够用。太密了计算量爆炸，实时性扛不住。

11.2 轨迹预测：给定速度，未来几秒会怎样？

采样出一堆(v, ω)组合后，接下来要预测：如果我用这个速度跑Δt时间，轨迹长什么样？

这里用的是最简单的运动学模型——差速模型。公式不复杂：

// 假设当前位姿 (x, y, θ)
// 给定线速度 v，角速度 ω，预测时间 dt
x_next = x + v * cos(θ) * dt
y_next = y + v * sin(θ) * dt
θ_next = θ + ω * dt

就这么简单？对，就这么简单。DWA不关心复杂的动力学，它只关心「接下来一小段时间内，车会走到哪里」。

我见过有人把预测时间设得特别长，比如5秒。结果呢？轨迹预测得乱七八糟，因为误差会累积。我个人习惯：预测时间1.5~2秒，步长0.1秒。这样既能看到前方障碍，又不会因为累积误差导致误判。

避坑指南：我曾经遇到一个案例，AGV在转弯时总是急刹。查了半天，发现是预测时间太短（0.5秒），导致算法看不到弯道内侧的障碍物。等看到了，已经来不及减速。把预测时间调到1.8秒后，问题解决。

11.3 评价函数设计：三个维度的博弈

采样了，预测了，现在有N条候选轨迹。选哪条？

DWA用三个评价指标来打分：

评价项 含义 权重符号
方位角评价 轨迹终点朝向与目标方向的偏差 α (heading)
障碍物距离评价 轨迹与最近障碍物的距离 β (dist)
速度评价 线速度大小，鼓励跑得快 γ (velocity)

最终得分 = α * heading + β * dist + γ * velocity

你想想看，这三个指标其实是互相矛盾的：

  • 想跑得快？可能离障碍物近。
  • 想对准目标？可能得减速转弯。
  • 想离障碍物远？可能绕大圈。

DWA的厉害之处就在于，它用加权求和的方式，在每一帧都找到那个「最优妥协点」。

调参口诀：

  • α（朝向权重）大 → 车更激进，直奔目标，容易撞墙
  • β（避障权重）大 → 车更保守，绕路远，但安全
  • γ（速度权重）大 → 车更莽，能跑多快跑多快

我刚开始调参时，α设得特别大，结果AGV直愣愣地往墙上怼。后来把β调高，车又变得畏畏缩缩，半天到不了目标。最后找到一个平衡点：α:β:γ = 0.3:0.5:0.2，对于大多数室内场景都适用。

11.4 动态窗口的工程调参：从理论到实战

理论说完了，咱们聊聊工程调参。这部分我踩过的坑最多。

11.4.1 动态窗口大小怎么设？

动态窗口的大小，取决于电机的加减速能力。公式很简单：

v_min_dw = v_current - a_max * dt
v_max_dw = v_current + a_max * dt
ω_min_dw = ω_current - α_max * dt
ω_max_dw = ω_current + α_max * dt

其中a_max是最大线加速度，α_max是最大角加速度。这两个参数怎么来？

我建议你直接查电机手册，或者做一次「急加速急减速」实验。把AGV放在空地上，给一个最大速度指令，记录从0到最大速度的时间。反过来也一样。

我的习惯：a_max设得比实际值小20%。为什么？因为电机老化、负载变化都会影响实际性能。留点余量，避免算法计算出「理论上可行但实际做不到」的速度。

11.4.2 评价函数归一化

这是新手最容易忽略的点。三个评价项的量纲不一样：

  • heading：角度偏差，范围0~π
  • dist：距离，范围0~几米
  • velocity：速度，范围0~v_max

如果不归一化，dist的数值天然就大，权重β再大一点，heading和velocity就完全被淹没了。

我常用的归一化方法：

// 对每条轨迹
heading_norm = heading / max_heading
dist_norm = dist / max_dist
velocity_norm = velocity / max_velocity

// 然后加权求和
score = α * heading_norm + β * dist_norm + γ * velocity_norm

说白了，就是把所有指标都压到0~1之间，这样权重才有意义。

11.4.3 避障距离的「死区」处理

你想想看，如果障碍物距离评价函数是线性的，会出现什么问题？

离障碍物1米和离障碍物0.1米，得分差距很大。但0.1米其实已经非常危险了！

我建议设置一个「安全死区」：

if (dist < safe_threshold) {
    dist_score = 0;  // 直接判死刑
} else {
    dist_score = dist / max_dist;  // 正常归一化
}

safe_threshold我一般设为机器人半径的1.5倍。小于这个距离，不管其他指标多好，这条轨迹直接淘汰。

我曾经犯过的错：有一次在仓库里调试，AGV总是贴着货架走，距离只有5厘米。理论上没撞，但稍微有点打滑就蹭上了。后来加了死区处理，强制要求距离货架至少20厘米，再也没出过问题。

11.5 DWA的局限性（实话实说）

DWA不是万能的。我用了这么多年，总结出几个硬伤：

  • 局部最优陷阱：DWA只看未来几秒，容易陷入U形障碍物出不来。
  • 对参数敏感：换个场景，权重可能就得重新调。
  • 不适合高速场景：预测时间短，高速下反应不过来。

但话说回来，对于室内AGV、服务机器人这些中低速场景，DWA依然是性价比最高的选择。简单、稳定、好调试。

总结一下DWA的工程调参流程：

  1. 先确定机器人物理极限（v_max, ω_max, a_max, α_max）
  2. 设定采样分辨率（v步长0.1，ω步长0.1）
  3. 设定预测时间（1.5~2秒）
  4. 初始化权重（α=0.3, β=0.5, γ=0.2）
  5. 加入安全死区（1.5倍半径）
  6. 跑仿真，观察轨迹，微调权重
  7. 实车测试，重点观察转弯和靠近障碍物时的行为

嗯，DWA的内容就这些。算法本身不复杂，难的是调参和工程适配。希望今天的分享能帮你少走弯路。
