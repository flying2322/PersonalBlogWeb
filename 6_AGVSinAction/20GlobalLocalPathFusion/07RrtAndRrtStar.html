7 RRT与RRT*：快速探索随机树原理、渐进最优性、在狭窄通道中的表现、与A*的融合思路

说到路径规划，A* 算法大家都很熟悉了。但如果你遇到过那种环境特别大、维度特别高的情况，A* 的栅格化处理会让你内存爆炸。这时候，RRT 系列算法就派上用场了。

我个人习惯把 RRT 叫做“随机撒点树”。它不依赖栅格，而是靠随机采样来探索空间。说白了，就是“碰运气”找路。但你别小看这个“碰运气”，在复杂环境下，它往往比 A* 更灵活。

7.1 快速探索随机树（RRT）原理

RRT 的核心思想很简单：从起点开始，随机采样一个点，然后向这个点生长一段距离。重复这个过程，直到树连接到终点。

我画个流程图给你看：

你看，这个流程其实挺直观的。每次迭代就做三件事：随机采样、找最近邻、向采样点生长。嗯，这里要注意：生长步长不能太大，否则容易跳过狭窄通道；也不能太小，否则收敛太慢。

我的经验：步长一般设为环境最大尺寸的 5%-10%。比如一个 100m x 100m 的仓库，步长取 5-10m 比较合适。太小了树长得慢，太大了容易撞墙。

7.2 RRT*：渐进最优性

RRT 有个毛病——它找到的路径通常不是最优的。说白了，它只管“找到路”，不管“路好不好”。RRT* 就是在 RRT 基础上加了两个优化步骤：重新选择父节点和重新布线。

我记得第一次在项目中用 RRT*，发现它比 RRT 多花了不少时间。但路径质量确实好很多。为什么会这样？因为 RRT* 每次添加新节点后，会检查附近有没有更优的父节点，然后重新连接。

伪代码大概是这样：

function RRT*:
    T.init(q_start)
    for i = 1 to N:
        q_rand = RandomSample()
        q_near = NearestNeighbor(T, q_rand)
        q_new = Steer(q_near, q_rand, step_size)
        
        if CollisionFree(q_near, q_new):
            // 重新选择父节点
            near_nodes = NearNodes(T, q_new, radius)
            q_min = q_near
            c_min = Cost(q_near) + Dist(q_near, q_new)
            
            for q in near_nodes:
                if CollisionFree(q, q_new):
                    if Cost(q) + Dist(q, q_new) < c_min:
                        q_min = q
                        c_min = Cost(q) + Dist(q, q_new)
            
            T.add_node(q_new)
            T.add_edge(q_min, q_new)
            
            // 重新布线
            for q in near_nodes:
                if q != q_min:
                    if CollisionFree(q_new, q):
                        if Cost(q_new) + Dist(q_new, q) < Cost(q):
                            T.rewire(q, q_new)
    
    return Path(T, q_start, q_goal)
渐进最优性是什么意思？ 简单说就是：随着采样点增多，找到的路径会越来越接近理论最优解。RRT* 保证当采样点趋于无穷时，路径收敛到最优。当然，实际中我们不可能采样无穷多个点，但 5000-10000 个点通常就能得到不错的结果。

7.3 在狭窄通道中的表现

狭窄通道是 RRT 系列算法的“噩梦”。你想想看，如果通道宽度只有 0.5 米，而你的 AGV 宽度是 0.4 米，随机采样点落在通道内的概率有多低？

我曾经在一个项目里遇到过这种情况：仓库货架之间的通道只有 0.6 米宽，AGV 宽度 0.5 米。用标准 RRT，跑了 10 万次采样都没找到路径。后来怎么解决的？我用了双向 RRT——从起点和终点同时生长两棵树，相遇时路径就找到了。

算法 狭窄通道成功率 平均收敛时间 路径质量
标准 RRT 15% 8.2s 一般
双向 RRT 68% 3.5s 较好
RRT* 22% 12.7s 最优
双向 RRT* 75% 5.1s 最优
避坑指南：我曾经在狭窄通道里用 RRT*，结果发现它一直在通道口附近来回采样，就是进不去。后来我加了目标偏置采样——以一定概率（比如 20%）直接采样终点方向，才解决了这个问题。

7.4 与 A* 的融合思路

RRT 和 A* 各有优缺点。RRT 适合高维、大范围环境，但路径不平滑；A* 适合低维、栅格化环境，路径质量高。能不能把两者结合起来？当然可以。

我常用的融合思路有三种：

  1. 先 RRT 后 A* 平滑：先用 RRT 快速找到一条可行路径，然后用 A* 在路径附近的小范围内做局部优化。说白了，RRT 负责“找方向”，A* 负责“走好路”。
  2. RRT 引导 A* 搜索：用 RRT 的采样点作为 A* 的启发式信息。比如，RRT 探索过的区域，A* 可以优先搜索。这样能减少 A* 的盲目性。
  3. 混合框架：在全局层面用 RRT 做粗粒度规划，在局部层面用 A* 做细粒度规划。我之前的项目就是这么做的——全局规划每 5 秒更新一次，局部规划每 0.5 秒更新一次。

举个例子，假设你的 AGV 要在 500m x 300m 的仓库里运行：

// 全局规划（RRT）
GlobalPath = RRT_Plan(start, goal, map)
// 输出：一系列关键航点 [P1, P2, P3, ..., Pn]

// 局部规划（A*）
for each segment [Pi, Pi+1]:
    LocalPath = AStar_Plan(Pi, Pi+1, local_map)
    // 输出：平滑的局部路径点序列
    AGV_Follow(LocalPath)
我的建议：如果你做的是室内 AGV，环境比较规整，直接用 A* 就够了。但如果你做的是户外 AGV 或者环境经常变化，RRT + A* 的混合方案会更靠谱。我见过太多人一上来就用 RRT*，结果调参调到头秃。

嗯，最后说一句：RRT 系列算法的参数调优是个经验活。步长、采样策略、重连半径，这些参数在不同环境下表现差异很大。我的习惯是先跑 100 次仿真，看看参数对结果的影响趋势，再上真车测试。
