28 真实项目案例2：园区物流AGV的融合方案（Hybrid A* + MPC）

各位，欢迎来到第28章。

前面我们聊了很多理论，从A*到DWA，从TEB到Lattice Planner。但说实话，真正让这些算法在园区里跑起来，又是另一回事。今天这个案例，是我去年主导的一个园区物流项目。园区面积大概有5个足球场那么大，AGV车队要穿梭于各个仓库、装卸区、充电站之间。

这个项目的核心难点在于：既要全局路径最优，又要局部避障灵活。单纯用A*，遇到临时堆放的货物就傻眼了；只用DWA，又容易绕远路，效率低下。最终我们采用的方案是：Hybrid A* 做全局规划 + MPC 做局部控制。嗯，今天就把这个融合方案的细节掰开揉碎了讲给你听。

28.1 为什么是Hybrid A* + MPC？

先说说选型思路。我个人习惯，做方案选型时，先看场景约束。

园区物流AGV有几个特点：

  • 非完整约束：AGV是差速驱动或阿克曼转向，不能原地掉头，也不能横向移动。
  • 动态障碍物多：行人、叉车、临时堆放的托盘，随时可能出现。
  • 路径质量要求高：不能急转弯，不能频繁启停，否则货物会晃动甚至倾倒。

传统A*规划出的路径是折线，AGV根本走不了。而Hybrid A*天生就是为这类非完整约束机器人设计的。它不光考虑位置，还考虑航向角，规划出的路径是连续的、可执行的曲线。

那为什么还要加MPC？

Hybrid A*规划的是全局路径，但它是基于静态地图的。一旦遇到动态障碍物，它需要重新规划，计算量太大。MPC（模型预测控制）正好弥补这个短板。它可以在线滚动优化，把全局路径作为参考，实时调整局部轨迹，同时考虑运动学约束和障碍物避碰。

核心思路：Hybrid A*负责“去哪”，MPC负责“怎么去”。一个管战略，一个管战术。

28.2 系统架构与数据流

先看整体架构。我画了一张图，帮你理清数据流。

数据流是这样的：

  1. 感知模块提供静态地图给Hybrid A*，同时提供动态障碍物信息给MPC。
  2. Hybrid A*基于静态地图规划出一条从起点到终点的平滑路径，作为MPC的参考轨迹。
  3. MPC以参考轨迹为目标，结合当前位姿和动态障碍物信息，滚动优化出控制指令。
  4. 执行模块接收控制指令，驱动AGV运动，同时将状态反馈给感知模块。

我的经验：这里有个坑。Hybrid A*规划出的路径是离散点序列，但MPC需要连续可微的参考轨迹。我通常用三次样条插值对路径点做平滑处理，效果很好。

28.3 Hybrid A* 全局规划实现

Hybrid A*的核心思想，是在A*的搜索框架下，引入连续状态空间。传统A*在栅格地图上搜索，每个格子代表一个离散状态。Hybrid A*则把每个格子细分为多个航向角区间，搜索时同时考虑位置和航向。

具体实现时，我用了Reeds-Shepp曲线作为节点之间的连接方式。为什么？因为Reeds-Shepp曲线能给出两个位姿之间的最短可行路径，而且满足车辆的运动学约束。

伪代码大致如下：

function HybridAStar(start, goal, map):
    open_set = PriorityQueue()
    open_set.push(start, 0)
    closed_set = {}
    
    while not open_set.empty():
        current = open_set.pop()
        if distance(current, goal) < threshold:
            return reconstruct_path(current)
        
        closed_set.add(current)
        
        for each steering angle in discretized_angles:
            for each velocity in [forward, backward]:
                path_segment = ReedsShepp(current, steering, velocity, step_size)
                if collision_free(path_segment, map):
                    new_node = Node(path_segment.end)
                    new_node.g = current.g + path_segment.length
                    new_node.h = heuristic(new_node, goal)
                    new_node.parent = current
                    
                    if new_node not in closed_set:
                        open_set.push(new_node, new_node.g + new_node.h)
    
    return None

这里有几个关键点：

  • 航向角离散化：我一般取8个方向（0°, 45°, 90°, ...），精度够用，计算量可控。
  • 启发式函数：不能用欧氏距离，因为AGV不能直线移动。我用的是Reeds-Shepp距离，也就是不考虑障碍物时的最短路径长度。
  • 碰撞检测：把AGV近似为矩形，用分离轴定理检测是否与障碍物相交。

避坑指南：我曾经在启发式函数上吃过亏。如果用欧氏距离，搜索会优先往直线方向扩展，但实际路径可能绕很远，导致搜索效率极低。改用Reeds-Shepp距离后，搜索方向更合理，速度提升了3倍。

28.4 MPC 局部控制实现

MPC的核心思想，是“滚动优化，反馈校正”。每一时刻，MPC根据当前状态和参考轨迹，预测未来N步的系统行为，然后求解一个带约束的优化问题，得到最优控制序列，只执行第一步，然后重复这个过程。

我们的MPC模型是这样的：

状态量：[x, y, theta, v]（位置、航向角、速度）

控制量：[a, delta]（加速度、前轮转角）

运动学模型（差速驱动）：

x(k+1) = x(k) + v(k)*cos(theta(k))*dt
y(k+1) = y(k) + v(k)*sin(theta(k))*dt
theta(k+1) = theta(k) + v(k)*tan(delta(k))/L*dt
v(k+1) = v(k) + a(k)*dt

其中L是轴距。

优化目标：

min sum_{i=1}^{N} ( ||state_i - ref_i||_Q + ||control_i||_R )

Q是状态权重矩阵，R是控制权重矩阵。Q越大，跟踪越紧；R越大，控制越平滑。

约束条件：

  • 速度限制：v_min <= v <= v_max
  • 加速度限制：a_min <= a <= a_max
  • 转向角限制：delta_min <= delta <= delta_max
  • 障碍物避碰：distance(AGV, obstacle) >= safety_margin

求解这个优化问题，我用了OSQP求解器。它是专门为二次规划设计的，速度快，适合嵌入式平台。

关键参数调优：预测时域N的选择很讲究。N太小，MPC看不到远处的障碍物，容易撞；N太大，计算量爆炸，实时性跟不上。我一般取N=10~20，步长dt=0.1s，这样预测未来1~2秒，够用了。

28.5 融合策略与避坑

Hybrid A*和MPC怎么融合？说白了，就是MPC把Hybrid A*的路径当作参考轨迹，但允许一定程度的偏离。

具体做法：

  1. Hybrid A*规划出全局路径后，每隔一定距离取一个参考点，形成参考轨迹。
  2. MPC运行时，从参考轨迹中选取距离当前位姿最近的N个点作为跟踪目标。
  3. 如果遇到动态障碍物，MPC会主动偏离参考轨迹，绕过后再回到参考轨迹上。

这里有个问题：如果偏离太远，MPC可能回不到参考轨迹上。怎么办？

我的做法是：设置一个偏离阈值。当AGV与参考轨迹的横向偏差超过阈值时，触发Hybrid A*重新规划。这样既保证了局部灵活性，又防止了全局路径丢失。

我的经验：阈值设多少合适？我一般取1.5倍车宽。太小了频繁重规划，计算量大；太大了AGV可能绕到死胡同里。

28.6 实际效果与数据

这个方案在园区跑了3个月，效果怎么样？我列一组数据：

指标 纯A* + DWA Hybrid A* + MPC 提升
平均路径长度 125m 108m 13.6%
平均运输时间 8分20秒 6分45秒 19.0%
急转弯次数 12次/趟 3次/趟 75.0%
碰撞预警次数 5次/天 1次/天 80.0%

你看，效果还是很明显的。尤其是急转弯次数大幅下降，货物倾倒的投诉基本没有了。

28.7 总结与思考

这个案例告诉我们一个道理：没有万能的算法，只有合适的组合。

Hybrid A*擅长全局规划，但实时性差；MPC擅长局部控制，但需要参考轨迹。两者结合，取长补短，才能应对园区物流这种复杂场景。

如果你也在做类似的项目，我建议你从这几个点入手：

  • 先搞清楚你的AGV是什么运动模型，再选全局规划算法。
  • MPC的权重矩阵Q和R一定要现场调，仿真调出来的参数往往偏保守。
  • 别忘了加一个重规划触发机制，防止MPC跑偏。
