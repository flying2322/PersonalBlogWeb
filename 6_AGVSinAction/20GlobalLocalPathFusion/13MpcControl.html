13 MPC模型预测控制：预测模型、滚动优化、约束处理、在AGV高速场景中的应用

各位同学，今天我们来聊聊MPC——模型预测控制。说实话，这玩意儿在AGV圈子里，以前大家觉得是“杀鸡用牛刀”。但这两年，随着AGV跑得越来越快，场景越来越复杂，MPC突然就成了香饽饽。

为什么？因为传统的PID或者纯跟踪控制，在低速、简单路径下够用。但一旦AGV飙到2m/s以上，还要过窄通道、急转弯，你就会发现——控制滞后、超调、甚至撞墙。嗯，我当年在做一个高速分拣项目时就吃过这个亏。

MPC的核心思想，说白了就是：走一步，看三步，随时调整。它不是等错了再纠正，而是提前算好未来几步怎么走最稳。

13.1 预测模型——你得知道车接下来会怎么走

MPC的第一步，就是建一个模型，用来“猜”未来。对于AGV来说，最常用的是运动学模型。差速轮AGV的模型很简单：

// 差速轮AGV运动学模型（离散化）
x(k+1) = x(k) + v(k) * cos(θ(k)) * dt
y(k+1) = y(k) + v(k) * sin(θ(k)) * dt
θ(k+1) = θ(k) + ω(k) * dt

这里v是线速度，ω是角速度，dt是控制周期。我个人习惯把dt设成50ms，也就是20Hz的控制频率。太快了计算扛不住，太慢了控制精度不够。

但注意，这只是理想模型。实际AGV有轮胎打滑、惯性延迟。我在一个仓储项目里，AGV满载时刹车距离比空载多了30%。所以，模型一定要留余量，或者加一个自适应修正项。

我的经验： 如果AGV跑高速（>1.5m/s），建议用二轮动力学模型，把加速度和转向率也作为状态量。虽然计算量翻倍，但控制平滑度好很多。

13.2 滚动优化——不是算一次就完事

MPC和传统控制最大的区别，就是“滚动”这两个字。每次控制周期，MPC都会做三件事：

  1. 预测未来N步：基于当前状态，用模型算出未来N个时刻的状态
  2. 求解最优控制序列：在满足约束的前提下，找一组控制量（v, ω），让预测轨迹最接近参考路径
  3. 只执行第一步：把算出来的第一个控制量发给底层，然后下一周期重新算

你想想看，这就像开车时，你永远只看前方50米的路况，而不是闭着眼按导航走。每次打完方向盘，再根据实际位置重新调整。

优化目标函数长这样：

min J = Σ (误差项) + Σ (控制量变化惩罚)

其中：
误差项 = (预测位置 - 参考位置)^2 + (预测航向 - 参考航向)^2
控制量变化惩罚 = (v(k+1) - v(k))^2 + (ω(k+1) - ω(k))^2

为什么要加控制量变化惩罚？因为如果不加，MPC算出来的控制量会剧烈抖动，AGV走起来像喝醉了酒。我曾经吃过这个亏——第一次调MPC时没加平滑项，结果AGV在直道上左右摇摆，把货都晃倒了。

13.3 约束处理——这才是MPC的真本事

AGV不是赛车，它有物理极限。MPC牛逼的地方，就是能把所有约束直接写进优化问题里：

约束类型 数学表达 实际意义
速度上限 0 ≤ v ≤ v_max 电机最高转速限制
加速度限制 |v(k+1) - v(k)| ≤ a_max * dt 防止急加速/急刹车导致货物倾倒
转向角速度 |ω| ≤ ω_max 转向电机物理限制
安全边界 距离障碍物 ≥ d_safe 防止碰撞
避坑指南： 我曾经在一个项目中，只加了速度约束没加加速度约束。结果AGV在急转弯时，速度从2m/s瞬间降到0.2m/s，货物直接飞出去了。后来我加上了加速度约束，问题才解决。记住：约束不是越多越好，但关键约束一个都不能少。

13.4 高速场景中的应用——MPC的用武之地

AGV跑高速（1.5m/s以上）时，会遇到几个棘手问题：

  • 惯性大：刹车距离变长，提前减速距离不好算
  • 转弯侧倾：高速转弯时，AGV有侧翻风险
  • 路径跟踪误差大：纯跟踪控制容易超调

MPC怎么解决？举个例子，AGV要过一个90度弯道：

  1. MPC提前5步（约250ms）就开始减速，而不是到了弯道口才刹车
  2. 在弯道中，MPC会动态调整ω，让AGV走一条“外-内-外”的平滑弧线，而不是生硬地转直角
  3. 出弯时，MPC会平滑加速，不会出现“一冲一停”的感觉

我在一个电商仓库项目中，AGV原来用PID控制，过弯速度只能降到0.5m/s。换成MPC后，过弯速度提升到1.2m/s，而且路径偏差从15cm降到了3cm。效果立竿见影。

核心要点： MPC在高速场景下的优势，本质上是“用计算量换控制精度”。如果你算力够（比如用NVIDIA Jetson或高性能工控机），MPC绝对是高速AGV的首选。

13.5 代码实现要点

这里给一个简化的MPC伪代码框架，方便你理解实现流程：

// MPC主循环（伪代码）
while(AGV运行中) {
    // 1. 获取当前状态
    state = getCurrentState(x, y, θ, v, ω);
    
    // 2. 获取参考轨迹（未来N步）
    ref_traj = getReferenceTrajectory(current_time, N);
    
    // 3. 构建优化问题
    //    - 目标函数：预测轨迹与参考轨迹的误差
    //    - 约束：速度、加速度、转向角、安全距离
    problem = buildOptimization(state, ref_traj, constraints);
    
    // 4. 求解（常用OSQP或ACADO求解器）
    solution = solveQP(problem);
    
    // 5. 只取第一个控制量
    v_cmd = solution.control[0].v;
    ω_cmd = solution.control[0].ω;
    
    // 6. 发送给底层电机
    sendControl(v_cmd, ω_cmd);
    
    // 7. 等待下一个控制周期
    sleep(dt);
}

注意，实际工程中，求解器选型很关键。我个人推荐OSQP，它轻量、快，适合嵌入式环境。如果算力紧张，可以缩短预测时域N（比如从10步减到5步），但控制效果会打折扣。

调试技巧： 第一次跑MPC时，先把约束设得松一点（比如速度上限设成实际值的80%），等系统稳定了再慢慢收紧。这样即使模型有误差，也不至于一出错就撞墙。

好了，关于MPC模型预测控制，今天就聊到这儿。记住：预测模型是基础，滚动优化是灵魂，约束处理是保障。下次你调试AGV高速过弯时，不妨试试MPC——你会发现，原来AGV也可以开得这么稳。
