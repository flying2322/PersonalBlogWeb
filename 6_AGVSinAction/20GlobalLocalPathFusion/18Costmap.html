18 代价地图（Costmap）：静态层、障碍物层、膨胀层、代价更新策略、多图层融合

各位同学，今天我们来聊聊代价地图。说实话，这是AGV路径规划里最“接地气”的一个模块。你想想看，全局规划算出一条路径，但机器人能不能真的沿着走？靠的就是代价地图。

我刚开始做AGV那会儿，以为路径规划就是A*算法跑一跑。结果第一次上路，机器人直接怼上了墙。为什么？因为地图里没有“代价”这个概念。后来我才明白——代价地图，就是给机器人一张“哪里能走、哪里危险”的评分表。

18.1 什么是代价地图？

代价地图本质上是一张栅格图，每个格子（cell）存一个0~255的数值。0代表完全自由，255代表绝对障碍。中间值呢？比如50、100，代表“最好别走，但实在没办法也能凑合”。

我个人习惯把代价地图比作“热力图”。红色区域是障碍，绿色区域是安全区。机器人规划路径时，会尽量绕开高代价区域，实在绕不开，就挑代价最低的路线走。

核心概念： 代价地图 = 静态地图 + 动态障碍 + 安全膨胀 + 实时更新

18.2 静态层（Static Layer）

静态层是最基础的一层。它来自我们事先建好的地图，比如激光SLAM生成的栅格地图。这层数据基本不变——墙就是墙，柱子就是柱子。

我在项目中遇到过一个问题：静态地图的分辨率太高，导致代价地图更新特别慢。后来我学乖了，静态层用较低分辨率（比如0.05m/像素），动态层用高分辨率。这样既保证精度，又兼顾实时性。

# 静态层配置示例
static_layer:
  enabled: true
  map_topic: "/map"           # 订阅静态地图话题
  subscribe_to_updates: true  # 是否接收地图更新
  map_type: "occupancy"       # 占用网格地图
  track_unknown_space: true   # 是否跟踪未知区域
小技巧： 静态层里的“未知区域”（unknown）代价默认设为255。但如果你想让机器人探索未知区域，可以手动改成0。我做过一个仓储AGV项目，就是这么干的。

18.3 障碍物层（Obstacle Layer）

障碍物层负责处理动态障碍。比如突然跑过来的人、临时堆放的货物、另一台AGV。这层数据更新频率很高，通常10Hz以上。

障碍物层的数据来源很多：激光雷达、深度相机、超声波、甚至碰撞传感器。我个人建议优先用激光雷达，因为它精度高、视野广。但要注意——激光雷达有盲区，比如机器人正前方半米内可能扫不到。

# 障碍物层配置示例
obstacle_layer:
  enabled: true
  observation_sources: ["laser_scan", "point_cloud"]
  laser_scan:
    topic: "/scan"
    sensor_frame: "laser_frame"
    data_type: "LaserScan"
    clearing: true    # 是否清除障碍物（当障碍物消失时）
    marking: true     # 是否标记障碍物
    obstacle_range: 2.5   # 障碍物检测范围（米）
    raytrace_range: 3.0   # 光线追踪范围（米）
注意： obstacle_range和raytrace_range要设置合理。我见过有人把obstacle_range设成10米，结果远处一个纸箱让机器人绕了半栋楼。一般室内AGV设2~3米就够了。

18.4 膨胀层（Inflation Layer）

膨胀层，说白了就是给障碍物“加一圈安全距离”。为什么需要？因为机器人有尺寸，不能贴着墙走。膨胀层会把障碍物周围的格子也标上代价，越靠近障碍物代价越高。

膨胀层的核心参数有两个：

  • 膨胀半径（inflation_radius）：障碍物向外膨胀的距离。一般设为机器人半径+安全余量。
  • 代价缩放因子（cost_scaling_factor）：控制代价随距离衰减的速度。值越大，衰减越快。

我记得有一次调试AGV，机器人总是卡在走廊拐角。后来发现是膨胀半径设太大了，机器人觉得两边都是“危险区”，不敢走。调小一点，问题就解决了。

# 膨胀层配置示例
inflation_layer:
  enabled: true
  inflation_radius: 0.55     # 膨胀半径（米）
  cost_scaling_factor: 10.0  # 代价缩放因子
经验值： 对于1米宽、0.6米长的AGV，我一般设inflation_radius=0.5~0.6米，cost_scaling_factor=8~12。具体要实测调整。

18.5 代价更新策略

代价地图不是一成不变的。机器人每走一步，障碍物层都要更新。更新策略主要有两种：

  1. 标记（Marking）：传感器检测到障碍物，就把对应格子代价设为255。
  2. 清除（Clearing）：传感器没检测到障碍物（比如障碍物移走了），就把格子代价恢复为0。

这里有个坑：清除策略依赖光线追踪（raytrace）。激光雷达发射一束光，如果光路上没有障碍，就把沿途格子都清掉。但如果传感器有噪声，可能会误清。我遇到过一台AGV，因为激光雷达抖动，把墙都“清”掉了，结果机器人直接穿墙而过……

# 代价更新策略伪代码
def update_costmap(scan_data):
    for point in scan_data:
        if point.distance < obstacle_range:
            mark_obstacle(point.x, point.y)  # 标记障碍
        if point.distance < raytrace_range:
            clear_raytrace(point.x, point.y) # 清除光路
避坑指南： 我曾经在工厂里调试，发现AGV总是莫名其妙急停。查了半天，原来是地面上的反光条被激光雷达当成障碍物了。解决方案：在障碍物层里加一个“高度过滤”，只标记一定高度以上的障碍。

18.6 多图层融合

现在我们把静态层、障碍物层、膨胀层都准备好了。怎么把它们合在一起？多图层融合就是干这个的。

融合策略很简单：取各层对应格子的最大值。比如静态层格子代价是0，障碍物层是255，膨胀层是100，那最终代价就是255（取最大）。

但这里有个细节：不同层的优先级可以调整。比如你希望障碍物层永远覆盖静态层，那就在融合时给障碍物层加权。我一般用默认的“最大值策略”，简单可靠。

# 多图层融合伪代码
def fuse_layers(layers):
    # layers = [static_layer, obstacle_layer, inflation_layer]
    costmap = np.zeros_like(layers[0])
    for layer in layers:
        costmap = np.maximum(costmap, layer)  # 取最大值
    return costmap
核心原则： 安全第一。任何一层标记为障碍（255），最终代价地图就是障碍。宁可让机器人绕路，也不能让它撞墙。

18.7 实战中的常见问题

最后分享几个我踩过的坑：

  • 地图漂移：静态地图和实际位置对不上。解决方案：定期用AMCL重定位，或者用二维码/反光板做辅助定位。
  • 障碍物残留：人走过去了，但代价地图上还留着障碍。检查clearing参数是否开启，以及raytrace_range是否够大。
  • 膨胀层过大：导致窄通道无法通行。我建议在狭窄区域（比如门、走廊）临时降低膨胀半径。
  • 多图层冲突：静态层说这里是墙，障碍物层说这里是空地。检查传感器数据是否正常，或者调整图层优先级。
调试小工具： 我习惯用rviz实时查看代价地图。把各个图层分别显示出来，一眼就能看出问题出在哪一层。比如机器人明明看到障碍，但代价地图没更新，那八成是障碍物层配置有问题。

18.8 本章小结

代价地图是AGV路径规划的“眼睛”。静态层提供基础地图，障碍物层处理动态变化，膨胀层保证安全距离。三层融合后，机器人才能做出合理的路径决策。

嗯，这里要注意：代价地图不是越精细越好。分辨率太高，计算量爆炸；分辨率太低，路径不精确。我一般用0.05米/像素，对于大多数室内AGV足够了。

最后送大家一句话：代价地图调好了，路径规划就成功了一半。别急着调A*参数，先把代价地图搞明白。
