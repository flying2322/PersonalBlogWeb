12 TEB算法：基于时间弹性带的优化

说到局部路径规划，TEB算法是我个人非常偏爱的一个方法。为什么？因为它把「时间」这个维度直接拉进了优化框架里。你想想看，传统的路径规划只关心空间位置，但机器人运动本质上是个时空问题。TEB的厉害之处，就是它把路径看成一条「有弹性的带子」，既能在空间上弯曲，又能在时间上伸缩。

12.1 什么是时间弹性带？

TEB的全称是Timed Elastic Band，翻译过来就是「时间弹性带」。它的核心思想很简单：把机器人的轨迹表示成一系列位姿点，每个点都带有一个时间戳。这些点之间通过「弹性约束」连接起来，就像一条橡皮筋。

我在项目中遇到过这样一个场景：AGV在仓库里行驶，前方突然出现一个障碍物。传统的DWA算法会重新规划速度，但路径往往很生硬。而TEB呢？它会把整条路径「弹」开，同时调整每个点的时间分配——该快的地方快，该慢的地方慢。

核心思想：TEB将路径规划转化为一个多目标优化问题，在满足运动学约束的前提下，同时优化路径长度、行驶时间、平滑度和障碍物距离。

12.2 图优化框架

TEB的底层实现依赖图优化。说白了，就是把所有约束条件构建成一个图，然后用优化器去求解。我习惯用g2o或者Ceres Solver来做这件事。

图优化框架包含三个要素：

  • 节点（Nodes）：每个位姿点是一个节点，包含(x, y, theta, delta_t)
  • 边（Edges）：连接相邻节点的约束，包括运动学约束、速度约束、加速度约束
  • 超图（Hypergraph）：多个节点和边构成的优化问题

来看一个简化的代码示例，展示如何构建TEB的图优化问题：

// 伪代码：TEB图优化构建
class TEBOptimizer {
    // 定义节点：每个位姿点
    struct PoseVertex {
        double x, y, theta;  // 位置和朝向
        double delta_t;      // 到达该点的时间间隔
    };
    
    // 定义边：相邻节点之间的约束
    struct VelocityEdge {
        double v_max;        // 最大速度约束
        double omega_max;    // 最大角速度约束
    };
    
    void buildGraph() {
        // 1. 添加所有位姿节点
        for (int i = 0; i < num_poses; i++) {
            graph.addVertex(poses[i]);
        }
        
        // 2. 添加运动学约束边
        for (int i = 0; i < num_poses - 1; i++) {
            graph.addEdge(poses[i], poses[i+1], 
                         new KinematicsEdge());
        }
        
        // 3. 添加障碍物约束边
        for (auto& obs : obstacles) {
            graph.addEdge(poses, obs, 
                         new ObstacleEdge());
        }
        
        // 4. 执行优化
        optimizer.optimize(max_iterations);
    }
};
我的经验：图优化的迭代次数不要设太大，20-30次就够。设多了反而容易过拟合，导致路径抖动。我曾经吃过这个亏，后来发现限制迭代次数后效果反而更好。

12.3 约束处理

TEB的约束处理是它的精髓所在。我把它归纳为四大类：

约束类型 具体内容 数学表达
运动学约束 非完整约束、曲率限制 |κ| ≤ κ_max
动力学约束 最大速度、最大加速度 v_min ≤ v ≤ v_max
障碍物约束 与障碍物的最小距离 d_obs ≥ d_min
时间约束 总时间最小化 min Σ Δt_i

这些约束在优化框架中都是以「代价函数」的形式存在的。每个约束对应一个代价项，优化器会尝试最小化所有代价的加权和。

避坑指南：我曾经在调参时把障碍物约束的权重设得太大，结果机器人为了绕开一个很小的障碍物，走了个巨大的弯路。记住：权重不是越大越好，要平衡。

12.4 动态环境中的表现

TEB在动态环境中的表现，说实话，比我想象的要好。它有几个关键特性：

  1. 实时重规划：每帧都重新优化，能快速响应环境变化
  2. 时间弹性：遇到动态障碍物时，可以「等一等」或者「加速通过」
  3. 轨迹预测：可以结合障碍物的运动预测，提前调整路径

我记得有一次在工厂里调试，一个叉车突然从侧面插进来。TEB的反应是这样的：先减速，然后路径向右偏移，等叉车过去后再回到原路径。整个过程非常平滑，没有急停急转。

但TEB也不是万能的。它有个明显的短板：计算量偏大。如果你用的是低算力的嵌入式平台，每帧优化可能会卡顿。我建议的做法是：

  • 降低优化频率（比如10Hz就够了）
  • 减少路径点数量（20-30个点足够）
  • 使用稀疏优化（只优化关键点）

12.6 实战建议

最后，我想分享几个实战中的小技巧：

参数调优口诀：权重先调障碍物，速度限制看车型，时间权重别太大，迭代次数二十足。

嗯，TEB算法就讲到这里。它不是一个完美的算法，但在动态环境中的表现确实让人印象深刻。如果你在实际部署中遇到问题，不妨从约束权重和优化频率入手，这两个参数往往能解决大部分问题。
