27 真实项目案例1：仓储AGV的全局与局部融合方案（A* + DWA）

各位同学，今天咱们聊点实在的。

前面讲了那么多理论，A*怎么搜、DWA怎么避障，但说实话，真正把这两套东西揉在一起跑起来，才是考验人的地方。我当年第一次做仓储AGV项目时，就踩了不少坑。今天这个案例，是我个人觉得最有代表性的一个——一个中型电商仓库，面积大概5000平米，货架密集，通道窄，AGV需要同时跑20台以上。

嗯，咱们就从这个项目说起。

项目背景与需求

这个仓库主要做B2C的拣选业务。AGV的任务很简单：从充电区出发，到指定货架取货，然后送到工作站，再返回。听起来不复杂，对吧？但实际跑起来，问题就来了。

  • 全局路径：需要提前规划出一条从起点到终点的最优路径，避开静态障碍物（货架、柱子、墙）。
  • 局部路径：运行过程中，会遇到其他AGV、临时堆放的货物、甚至人。这时候需要实时调整轨迹，不能死板地跟着全局路径走。

说白了，全局规划负责“大方向”，局部规划负责“微操”。

为什么选A* + DWA？

我个人习惯，选方案先看场景。仓储环境的特点是：

  • 地图是已知的，静态障碍物固定
  • 动态障碍物多，且不可预测
  • 对实时性要求高（AGV不能停下来思考太久）

A*在静态地图上找路径，效率高，结果稳定。DWA呢，擅长处理动态障碍，反应快。这两者搭配，说白了就是“长板互补”。

我曾经试过用纯A*跑，结果遇到对面来车，直接卡死。也试过只用DWA，结果全局方向经常跑偏，绕远路。所以，融合才是王道。

整体架构设计

先看一张图，这是我当时画的系统流程图，现在看依然经典。

你看，整个流程其实很清晰：

  1. 全局规划模块加载静态地图，用A*算出一条全局路径。
  2. 局部规划模块拿到这条路径，结合传感器实时数据，用DWA生成速度指令。
  3. 执行模块（电机）按指令跑。
  4. 传感器反馈回来，DWA再调整，形成闭环。

A*全局路径规划实现

这里我直接贴一段核心代码，是我当时项目里用的简化版。注意，实际项目中地图是二维数组，0表示可通行，1表示障碍物。

def a_star_search(grid, start, goal):
    """
    A* 路径搜索
    grid: 二维栅格地图，0=可通行，1=障碍物
    start: 起点坐标 (x, y)
    goal: 终点坐标 (x, y)
    """
    open_list = []
    closed_list = set()
    
    # 起点
    start_node = Node(start, None, 0, heuristic(start, goal))
    open_list.append(start_node)
    
    while open_list:
        # 取f值最小的节点
        current_node = min(open_list, key=lambda n: n.f)
        
        if current_node.pos == goal:
            # 找到路径，回溯
            path = []
            while current_node:
                path.append(current_node.pos)
                current_node = current_node.parent
            return path[::-1]
        
        open_list.remove(current_node)
        closed_list.add(current_node.pos)
        
        # 扩展邻居
        for neighbor_pos in get_neighbors(current_node.pos, grid):
            if neighbor_pos in closed_list:
                continue
            if grid[neighbor_pos[0]][neighbor_pos[1]] == 1:
                continue  # 障碍物
            
            g = current_node.g + 1  # 假设每步代价为1
            h = heuristic(neighbor_pos, goal)
            neighbor = Node(neighbor_pos, current_node, g, h)
            
            # 如果邻居已在open_list中，且g值更小，则更新
            existing = [n for n in open_list if n.pos == neighbor_pos]
            if existing:
                if g < existing[0].g:
                    existing[0].g = g
                    existing[0].parent = current_node
                    existing[0].f = g + h
            else:
                open_list.append(neighbor)
    
    return None  # 无路径
小技巧： 我建议在启发函数里用曼哈顿距离，因为仓储环境大多是网格状通道，曼哈顿距离比欧氏距离更准。当然，如果你有斜向通道，那就用欧氏距离。

DWA局部规划实现

DWA的核心思想，说白了就是“采样速度、模拟轨迹、选最优”。我当年调试DWA时，最头疼的就是参数调优。这里给个核心片段：

def dwa_control(x, y, yaw, v, w, global_path, obstacles):
    """
    DWA 动态窗口法
    x, y, yaw: 当前位姿
    v, w: 当前线速度和角速度
    global_path: 全局路径点列表
    obstacles: 障碍物点云（来自激光雷达）
    """
    # 1. 速度采样空间
    dw = calc_dynamic_window(v, w, config)
    
    # 2. 对每个速度组合，模拟轨迹
    best_u = [0.0, 0.0]
    best_cost = float('inf')
    
    for v_sample in np.arange(dw[0], dw[1], config.v_reso):
        for w_sample in np.arange(dw[2], dw[3], config.w_reso):
            # 模拟轨迹
            traj = predict_trajectory(x, y, yaw, v_sample, w_sample, config.dt, config.predict_time)
            
            # 3. 计算代价
            cost = calc_cost(traj, global_path, obstacles, config)
            
            if cost < best_cost:
                best_cost = cost
                best_u = [v_sample, w_sample]
    
    return best_u  # 返回最优速度指令
注意： 我曾经因为预测时间设得太长（3秒），导致AGV在窄通道里频繁急刹。后来改成1.5秒，效果好了很多。这个参数要根据AGV的最大速度和制动距离来调，别照搬别人的值。

融合策略：全局路径如何喂给DWA

这里有个关键点：DWA需要知道“往哪走”。全局路径是一串点，但DWA不能直接跟踪所有点，否则会变成“点对点”的僵硬运动。

我的做法是：

  1. 从全局路径中，找到离AGV当前位置最近的点，记为near_idx。
  2. 取near_idx + 5（也就是往前数5个点）作为局部目标点。
  3. 把这个局部目标点传给DWA的代价函数，作为“朝向目标”的引导。

为什么要取第5个点？你想想看，如果取最近的点，AGV会一直试图“精确”经过每个路径点，导致频繁转向。取前几个点，相当于给了一个“前瞻距离”，让运动更平滑。

核心经验： 前瞻距离不是固定的。我建议根据AGV当前速度动态调整——速度快时，前瞻远一点；速度慢时，近一点。这样在直道上能提前加速，在弯道前能提前减速。

避坑指南：我踩过的三个坑

  • 坑一：全局路径穿过窄通道。A*算出来的路径，有时会贴着障碍物边缘走。DWA在避障时，稍微一偏就可能撞上。解决方案：对全局路径做“膨胀处理”，把障碍物周围多膨胀一格，让路径尽量走通道中间。
  • 坑二：多AGV死锁。两台AGV在通道里面对面，DWA各自避让，结果让来让去都卡住。我后来加了一个“交通规则”：在窄通道里，规定行驶方向，AGV只能单向通行。如果对面来车，先到的先走，后到的原地等待。
  • 坑三：传感器噪声导致DWA误判。激光雷达偶尔会扫到地面反光点，当成障碍物。DWA一检测到，立刻急刹。解决方案：对障碍物点做“时间滤波”，连续3帧都检测到的点才认为是真障碍物。

性能对比：融合方案 vs 单独方案

我在项目里做了个对比测试，结果如下：

方案 平均运行时间（秒） 碰撞次数（每100次任务） 路径长度（米）
纯A*（无局部避障） 45 12 38
纯DWA（无全局引导） 62 3 51
A* + DWA 融合 38 0 39

你看，融合方案在运行时间和路径长度上接近纯A*，但碰撞次数降为0。说白了，就是既保持了全局最优性，又保证了局部安全性。

总结

这个案例让我深刻体会到一件事：算法融合不是简单的“1+1”，而是要让两个模块互相理解对方的意图。A*给DWA一个“方向感”，DWA给A*一个“灵活性”。

嗯，如果你也在做类似的项目，我建议先从简单的场景开始调试，比如单台AGV在空旷区域跑，然后逐步增加障碍物和AGV数量。别一上来就上20台，否则你连问题出在哪都找不到。
