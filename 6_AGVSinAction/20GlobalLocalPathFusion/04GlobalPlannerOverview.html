4 全局规划算法概览：Dijkstra、A*、RRT、RRT*、Hybrid A* 的适用场景与优缺点

聊到全局路径规划，很多刚入行的朋友容易陷入一个误区：总想找一个「万能算法」。

我当年也干过这事。拿着A*到处套，结果在非结构化环境里跑得一塌糊涂。后来才明白，选算法就像选工具——拧螺丝用扳手，切木头用锯子。没有最好的算法，只有最合适的场景。

今天咱们就把主流的五个全局规划算法掰开揉碎聊一聊。我会结合自己踩过的坑，帮你理清它们各自该用在哪儿、不该用在哪儿。

核心观点：全局规划算法的本质是在「搜索效率」和「路径质量」之间做权衡。Dijkstra 保证最优但慢，RRT 快但不优，Hybrid A* 则是在连续空间里找可行解。

4.1 Dijkstra：教科书里的「老实人」

Dijkstra 算法，说白了就是地毯式搜索。它从起点开始，一层一层往外扩，直到找到终点。

优点很明确：

  • 保证找到最短路径（如果存在的话）
  • 实现简单，逻辑清晰
  • 适用于带权图，能处理不同代价的边

缺点也很致命：

  • 搜索范围太大，效率低
  • 没有启发信息，盲目扩张
  • 在大地图上基本没法用

我的经验：Dijkstra 最适合做「基准测试」。我在评估一个新地图的拓扑结构时，会先用 Dijkstra 跑一遍，拿它的结果当「标准答案」，再去对比其他算法的优化效果。

适用场景：小规模静态地图、网络路由、需要绝对最优解且地图不大的情况。

4.2 A*：工业界的「扛把子」

A* 在 Dijkstra 的基础上加了一个启发函数。说白了就是给搜索过程装了个「指南针」，让它朝着目标方向走，而不是四处乱撞。

核心公式就一句话：f(n) = g(n) + h(n)。g(n) 是起点到当前点的实际代价，h(n) 是当前点到终点的估计代价。

// 伪代码示例：A* 核心逻辑
openList.add(startNode);
while (!openList.isEmpty()) {
    current = openList.getLowestF();
    if (current == goal) return reconstructPath();
    
    openList.remove(current);
    closedList.add(current);
    
    for (neighbor : current.neighbors) {
        if (closedList.contains(neighbor)) continue;
        
        tentativeG = current.g + distance(current, neighbor);
        if (!openList.contains(neighbor) || tentativeG < neighbor.g) {
            neighbor.g = tentativeG;
            neighbor.h = heuristic(neighbor, goal);
            neighbor.f = neighbor.g + neighbor.h;
            neighbor.parent = current;
            if (!openList.contains(neighbor)) openList.add(neighbor);
        }
    }
}

优点：

  • 比 Dijkstra 快得多，尤其在大地图上
  • 启发函数设计得好时，能保证最优解
  • 栅格地图上的首选算法

缺点：

  • 启发函数设计有讲究——太大会丢失最优性，太小退化成 Dijkstra
  • 在动态环境中需要反复重规划
  • 对内存要求较高（要维护 open 表和 closed 表）

避坑指南：我曾经在一个仓库项目里直接用欧几里得距离做启发函数，结果路径拐来拐去特别奇怪。后来换成曼哈顿距离，配合地图的网格特性，路径就顺多了。记住：启发函数要贴合你的地图结构。

适用场景：栅格地图、游戏寻路、机器人室内导航。只要地图能离散化成网格，A* 基本是首选。

4.3 RRT：高维空间的「探险家」

RRT（快速随机扩展树）的思路很有意思——在地图里随机撒点，然后从起点开始「长」出一棵树，直到这棵树碰到终点。

你想想看，如果地图特别大，或者维度特别高（比如机械臂的关节空间），A* 那种穷举式的搜索根本跑不动。这时候 RRT 就派上用场了。

优点：

  • 在高维空间里效率极高
  • 不需要显式构建地图，只要有碰撞检测就行
  • 实现简单，代码量少

缺点：

  • 路径不是最优的，甚至可能很绕
  • 路径不平滑，拐角多
  • 具有随机性，同样的地图每次跑出来的路径不一样

我的习惯：RRT 适合做「快速可行性验证」。比如一个新项目，我先用 RRT 看看能不能找到一条可行路径，如果能，再换 A* 或 RRT* 去优化。别一上来就上复杂算法，容易白费功夫。

适用场景：高维空间（如机械臂规划）、非结构化环境、对路径质量要求不高的场景。

4.4 RRT*：RRT 的「升级版」

RRT* 解决了 RRT 的一个大问题——路径质量。它在 RRT 的基础上加了两个关键操作：重新选择父节点和重新布线。

说白了就是：树长出来之后，RRT* 会不断「修剪」这棵树，让路径越来越短。随着采样点增多，路径会渐近收敛到最优解。

优点：

  • 渐近最优性——采样越多，路径越好
  • 保留了 RRT 在高维空间的优势
  • 路径比 RRT 平滑得多

缺点：

  • 计算量比 RRT 大
  • 收敛速度慢，需要大量采样才能接近最优
  • 实现比 RRT 复杂

关键点：RRT* 的「渐近最优」意味着你可以在时间和质量之间做 trade-off。时间紧就少采样，时间充裕就多采样。这种灵活性在实际项目中非常实用。

适用场景：需要较高质量路径的高维空间规划、无人机航迹规划、有时间做离线计算的场景。

4.5 Hybrid A*：让路径「开得动」

前面四个算法有个共同问题：它们规划出来的路径，车不一定能走。

举个例子，A* 规划出一条折线路径，每个拐点都是直角。但你的 AGV 是差速驱动或者阿克曼转向，根本没法原地转弯。这时候 Hybrid A* 就来了。

Hybrid A* 在 A* 的基础上，考虑了车辆的运动学约束。它不是在栅格节点之间跳转，而是在连续空间里搜索符合车辆运动模型的轨迹。

优点：

  • 规划出来的路径车辆可以直接执行
  • 特别适合阿克曼转向模型（汽车、卡车）
  • 能处理狭窄空间的泊车、掉头等复杂操作

缺点：

  • 计算量大，实时性差
  • 实现复杂，需要懂车辆运动学
  • 不一定保证最优解

避坑指南：我曾经在一个项目中直接用 Hybrid A* 做全局规划，结果发现它在开阔地带跑得特别慢。后来我改成「全局用 A* + 局部用 Hybrid A*」的混合方案，效率提升了好几倍。记住：Hybrid A* 适合做精细规划，不适合做大范围搜索。

适用场景：自动驾驶车辆、阿克曼转向的 AGV、需要精确控制车辆姿态的场景（如仓储 AGV 的货架对接）。

4.6 算法对比一览

算法 最优性 效率 运动学约束 适用维度 实现难度
Dijkstra ✅ 保证最优 ⭐ 低 ❌ 不支持 低维 ⭐ 简单
A* ✅ 保证最优（启发函数合适时） ⭐⭐⭐ 高 ❌ 不支持 低维 ⭐⭐ 中等
RRT ❌ 非最优 ⭐⭐⭐⭐ 很高 ❌ 不支持 高维 ⭐ 简单
RRT* ✅ 渐近最优 ⭐⭐ 中等 ❌ 不支持 高维 ⭐⭐⭐ 较复杂
Hybrid A* ❌ 非最优 ⭐⭐ 中等 ✅ 支持 低维（状态空间） ⭐⭐⭐⭐ 复杂

4.7 选型建议：我一般怎么选？

在实际项目中，我通常会按下面这个思路来选：

  1. 先看地图类型：如果是栅格地图，直接上 A*。如果是连续空间或高维空间，考虑 RRT 系列。
  2. 再看车辆模型：如果是差速驱动（能原地转弯），A* 或 RRT 都行。如果是阿克曼转向，必须上 Hybrid A* 或者至少做路径平滑。
  3. 最后看实时性要求：如果要求毫秒级响应，RRT 或 A* 的轻量版本。如果离线计算，RRT* 或 Hybrid A* 慢慢优化。

一个小技巧：别把鸡蛋放在一个篮子里。我现在的项目基本都是「全局 A* + 局部 TEB/MPC」的混合架构。全局负责大方向，局部负责避障和运动学约束。这样既保证了效率，又兼顾了可行性。
