24 传感器融合与定位：激光雷达、IMU、里程计、EKF/UKF融合、对规划的影响

各位同学，今天我们来聊聊定位。说实话，在AGV这个行当里摸爬滚打这么多年，我最大的感触就是：定位不准，规划白做。你想想看，全局路径规划得再漂亮，局部避障算法再牛，如果车连自己在哪都不知道，那一切都是空中楼阁。

这一章，我们就来拆解一下传感器融合与定位这个核心模块。我会结合我踩过的坑，把激光雷达、IMU、里程计这些传感器怎么配合，EKF和UKF怎么用，以及定位精度到底怎么影响路径规划，一次性讲透。

24.1 为什么需要传感器融合？

单一传感器都有短板。激光雷达精度高，但遇到玻璃、镜面或者空旷走廊就抓瞎。IMU不怕环境，但漂移严重，跑个几十米就偏到姥姥家。里程计在平坦地面还行，一打滑就完蛋。

所以，融合不是锦上添花，而是刚需。我个人习惯把传感器融合比作「三个臭皮匠顶个诸葛亮」——每个传感器都有弱点，但组合起来就能互相弥补。

核心原则：用IMU补激光雷达的短时中断，用激光雷达修正IMU的长期漂移，用里程计提供轮速约束。三者缺一不可。

24.2 各传感器特性分析

先看看每个传感器的脾气秉性，这样融合时才能对症下药。

传感器 优点 缺点 典型频率 适用场景
激光雷达 精度高（±2cm），不受光照影响 怕玻璃/镜面，计算量大 10-20 Hz 室内结构化环境
IMU 高频（100-400Hz），不受环境干扰 漂移严重，需要频繁修正 100-400 Hz 短时高动态运动
里程计 低成本，短时精度好 打滑/空转时完全失效 50-100 Hz 平坦硬质地面

我的经验：在AGV项目中，我一般把激光雷达作为「主传感器」，IMU作为「惯性参考」，里程计作为「速度约束」。三者权重不是固定的——比如在光滑瓷砖地面上，我会降低里程计的置信度，提高IMU的权重。

24.3 EKF与UKF：两种融合方案怎么选？

说到融合算法，EKF（扩展卡尔曼滤波）和UKF（无迹卡尔曼滤波）是两大主流。很多新手问我：「到底用哪个？」我的回答是：看你的系统非线性程度。

24.3.1 EKF：经典但需要小心

EKF的原理很简单：把非线性系统在估计点附近做一阶泰勒展开，然后套用标准卡尔曼滤波框架。说白了就是「用切线近似曲线」。

优点：计算量小，实现简单。
缺点：如果系统非线性强，一阶近似误差会很大，甚至导致滤波发散。

我曾经在一个项目中，AGV在急转弯时EKF直接炸了——因为转弯时的运动模型非线性太强，一阶近似根本hold不住。后来换成UKF才稳住。

// EKF 预测步骤（简化伪代码）
// 状态向量: [x, y, θ, v, ω]
// 控制输入: [a, α] 加速度和角加速度

void predictEKF(VectorXf& x, MatrixXf& P, float dt) {
    // 运动模型（非线性）
    float theta = x(2);
    float v = x(3);
    float omega = x(4);
    
    // 状态预测
    x(0) += v * cos(theta) * dt;
    x(1) += v * sin(theta) * dt;
    x(2) += omega * dt;
    // 速度保持不变（假设匀速）
    
    // 计算雅可比矩阵 F
    MatrixXf F = MatrixXf::Identity(5,5);
    F(0,2) = -v * sin(theta) * dt;
    F(0,3) = cos(theta) * dt;
    F(1,2) = v * cos(theta) * dt;
    F(1,3) = sin(theta) * dt;
    F(2,4) = dt;
    
    // 协方差预测
    P = F * P * F.transpose() + Q;
}

24.3.2 UKF：更鲁棒但稍慢

UKF的思路不一样——它不近似函数，而是近似概率分布。通过选取一组Sigma点，让这些点经过非线性变换后，再重新计算均值和协方差。

优点：对非线性系统更精确，不需要计算雅可比矩阵。
缺点：计算量大约是EKF的1.5-2倍。

我的建议：如果你的AGV主要在仓库、工厂等结构化环境运行，运动相对平稳，EKF完全够用。但如果AGV经常在复杂地形、急转弯、或者有颠簸的路面运行，我强烈建议上UKF。多花那点算力，换来的是定位的稳定性，绝对值。

24.4 融合架构实战：激光雷达+IMU+里程计

下面是我在项目中常用的融合架构，经过多个项目验证，比较稳定。

24.4.1 整体流程

  1. IMU预积分：在两次激光雷达扫描之间，用IMU做高频状态预测（100Hz），输出位姿增量。
  2. 激光雷达扫描匹配：当前帧点云与地图匹配（如ICP或NDT），得到绝对位姿观测。
  3. 里程计约束：轮式编码器提供速度观测，约束运动模型。
  4. EKF/UKF融合：将IMU预测作为先验，激光雷达和里程计作为观测，进行状态更新。

24.4.2 关键参数调优

这里有几个参数我每次调都要反复试：

参数 含义 典型值 调优经验
Q矩阵 过程噪声协方差 位置: 0.01, 角度: 0.001 Q越大，滤波器越相信观测
R_lidar 激光雷达观测噪声 位置: 0.05, 角度: 0.01 在玻璃多的环境要放大
R_odom 里程计观测噪声 速度: 0.1 打滑时动态调大
IMU bias IMU零偏 在线估计 启动后前5秒做静态初始化

避坑指南：我曾经在一个项目中，IMU的bias没有做静态初始化，结果滤波器前30秒一直在收敛，导致AGV启动时定位偏差超过20cm，直接撞了货架。从那以后，我每次都会在启动时让AGV静止5秒，做IMU bias初始化。

24.5 定位精度对路径规划的影响

这部分是重点。很多同学觉得定位和规划是两回事，其实它们深度耦合。

24.5.1 全局规划层面

全局路径规划（如A*、Dijkstra）依赖地图和起点。如果定位误差大，起点位置偏了，规划出来的路径可能直接穿墙。更严重的是，如果定位漂移导致AGV认为自己在地图上的A点，实际在B点，那全局路径就是一张废纸。

24.5.2 局部规划层面

局部规划（如DWA、TEB）更敏感。它需要实时知道AGV的位置和速度，才能计算避障轨迹。定位延迟或抖动会导致：

  • 避障轨迹滞后，撞上动态障碍物
  • 速度控制震荡，AGV走S形
  • 在狭窄通道中来回碰撞

一个真实案例：我调试过一个AGV，在2米宽的走廊里总是左右摇摆。查了两天，最后发现是IMU的yaw角漂移导致定位每秒钟抖动0.5度。局部规划器以为车在转圈，就不断修正方向。换成UKF后，yaw角稳定在0.1度以内，问题立刻解决。

24.5.3 定位精度要求量化

根据我的项目经验，不同场景对定位精度的要求大致如下：

应用场景 定位精度要求 融合方案推荐
仓库搬运（通道宽>2m） ±10cm EKF + 激光雷达 + 里程计
产线对接（精度要求高） ±2cm UKF + 激光雷达 + IMU + 二维码辅助
室外园区（GPS拒止） ±15cm UKF + 激光雷达 + IMU + 轮速

24.6 实战中的几个关键点

最后，分享几个我在项目中反复踩坑后总结的经验：

  1. 时间同步是基础：激光雷达、IMU、里程计的时间戳必须对齐。我见过太多项目因为时间戳没对齐，融合结果一塌糊涂。建议用ROS的tf树或者硬件同步信号。
  2. 异常检测不能少：激光雷达被遮挡、里程计打滑、IMU饱和——这些异常情况要能检测并处理。我的做法是维护一个「传感器健康状态」标志，异常时降低对应传感器的权重。
  3. 初始化要稳：启动时先做静态初始化，让滤波器收敛。不要一启动就猛跑，否则定位发散的概率很高。
  4. 回环检测是最后一道防线：即使EKF/UKF做得再好，长期运行也会有累积误差。配合回环检测（如Scan-to-Map匹配），可以定期修正全局位姿。

一个小技巧：在调试阶段，我会把每个传感器的原始数据和融合后的位姿一起录下来，用可视化工具回放。这样能快速定位是哪个传感器出了问题，还是融合参数不对。省时省力。

好了，关于传感器融合与定位，今天就聊到这里。记住一句话：定位是规划的基石，融合是定位的灵魂。下一章我们会深入局部规划，到时候你会发现，定位精度直接决定了局部规划器的参数怎么调。
