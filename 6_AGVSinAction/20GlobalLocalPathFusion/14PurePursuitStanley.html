14 Pure Pursuit与Stanley——几何跟踪方法、前视距离的影响、曲率自适应、工程调参经验

各位同学，今天我们来聊聊AGV路径跟踪里最经典的两个几何方法：Pure Pursuit和Stanley。说实话，这两个方法我用了快十年，从最早的差速底盘到后来的阿克曼转向，几乎每个项目都离不开它们。

你可能会问，现在深度学习那么火，为什么还要学这些“老古董”？嗯，我当年也有这个疑问。直到有一次在工厂现场，激光雷达突然丢帧，深度学习模型直接“懵圈”，而Pure Pursuit靠着简单的几何计算，硬是把车稳稳地拉回了路径上。从那以后，我明白了——简单的东西往往最可靠。

14.1 Pure Pursuit：最简单的几何跟踪

Pure Pursuit的思路特别直观——想象你开车时，眼睛盯着前方某个点，然后打方向盘让车头对准那个点。说白了，就是“看远一点，追上去”。

它的核心公式很简单：

// 计算曲率
κ = 2 * sin(α) / Ld

// 其中：
// α 是车辆航向与目标点方向的夹角
// Ld 是前视距离（lookahead distance）
// κ 是曲率，用于计算前轮转角

我个人习惯把Ld设成车速的0.5~1.5倍。比如车速1m/s，Ld就取0.5~1.5米。为什么是这个范围？因为太近了车会震荡，太远了又切弯太狠。

核心要点：Pure Pursuit本质上是一个比例控制器，前视距离Ld就是它的比例系数。Ld越小，响应越快但越震荡；Ld越大，响应越平滑但跟踪误差越大。

14.2 前视距离的影响——我踩过的坑

前视距离这个参数，我当年调了整整一周。为什么？因为不同场景下最优值完全不一样。

举个例子：

场景 推荐Ld范围 原因
直道行驶 1.5~2.5倍车速 大前视距离让路径更平滑
急转弯 0.3~0.6倍车速 小前视距离才能及时转向
狭窄通道 0.5~1.0倍车速 需要兼顾精度和稳定性

我曾经踩过的坑：有一次在仓库里测试，我把Ld设成了固定值2米。结果在直角弯处，车直接冲向了货架——因为前视距离太大，车看到的目标点还在弯道外面，等它反应过来已经晚了。从那以后，我坚持用动态前视距离。

14.3 Stanley方法：前轮偏差的艺术

Stanley和Pure Pursuit最大的区别是什么？Stanley不仅看前视点，还看当前的前轮偏差。说白了，它更关注“我现在偏了多少”，而不是“我要去哪里”。

Stanley的控制律是这样的：

// Stanley 控制律
δ = θe + arctan(k * ye / v)

// 其中：
// δ 是前轮转角
// θe 是航向偏差（车辆航向与路径切线方向的夹角）
// ye 是横向偏差（车辆到路径的最短距离）
// k 是增益系数
// v 是车速

你想想看，这个公式里有两个部分：航向偏差负责把车头对准路径方向，横向偏差负责把车拉回路径上。两者配合，效果比Pure Pursuit更平滑。

我的调参习惯：k值一般从0.5开始试。如果车在路径两侧来回摆动，说明k太大了；如果车偏离路径后回正太慢，说明k太小了。记住一个口诀：“大k快响应，小k稳如狗”。

14.4 曲率自适应——让算法自己“思考”

前面说了，固定参数在复杂场景下根本不够用。那怎么办？让算法根据路径曲率自动调整参数。

我常用的方法：

  1. 计算路径曲率：对路径点做三次样条插值，然后求二阶导数得到曲率。
  2. 动态调整前视距离：曲率越大，Ld越小；曲率越小，Ld越大。
  3. 限制变化率：Ld不能突变，否则车会“抽搐”。我一般加一个低通滤波器。
// 曲率自适应伪代码
function adaptiveLookahead(curvature, baseLd):
    // curvature 是当前路径曲率
    // baseLd 是基础前视距离
    
    // 曲率越大，前视距离越小
    adaptiveLd = baseLd / (1 + abs(curvature) * 2.0)
    
    // 限制范围
    adaptiveLd = clamp(adaptiveLd, 0.3, 3.0)
    
    // 低通滤波，防止突变
    filteredLd = 0.8 * lastLd + 0.2 * adaptiveLd
    
    return filteredLd

实际效果：用了曲率自适应之后，车在直道上跑得又直又稳，到了弯道又能自动“收窄视野”顺利过弯。我曾在一条S形路径上测试，跟踪误差从原来的15cm降到了3cm以内。

14.5 工程调参经验——那些年我踩过的坑

调参这件事，说难不难，说简单也不简单。我总结了几条血泪教训：

  • 先调稳态，再调动态：先让车在直道上跑稳了，再去调弯道参数。不要一上来就挑战S弯。
  • 记录每一次参数：我习惯用CSV文件记录每次调参的参数和效果。有时候调了一整天，最后发现还是早上那组参数最好——有记录才能复盘。
  • 注意执行器延迟：AGV的转向电机通常有50~200ms的延迟。如果发现车总是“过冲”，可以适当增大前视距离或减小增益。
  • 速度与参数联动：车速变化时，Ld和k都要跟着变。我一般用线性插值：低速用小Ld，高速用大Ld。

我曾经犯过的错：有一次在调试Stanley时，我把k值设得很大，想着“响应快一点”。结果车在直道上就开始左右摇摆，像喝醉了酒一样。后来才发现，k太大导致横向偏差被过度放大，系统进入了自激振荡。嗯，从那以后我记住了：增益不是越大越好。

14.6 Pure Pursuit vs Stanley：怎么选？

很多同学问我这个问题。我的建议是：

对比项 Pure Pursuit Stanley
实现难度 极简单，几行代码搞定 稍复杂，需要计算横向偏差
跟踪精度 中等，受前视距离影响大 较高，尤其在中低速场景
平滑性 前视距离大时平滑，小时震荡 天生平滑，因为考虑了航向偏差
适用底盘 差速、阿克曼都行 更适合阿克曼转向
我的推荐 快速原型验证 正式产品部署

说白了，如果你只是想快速跑起来，Pure Pursuit就够了。但如果你要做产品，追求稳定性和精度，我建议上Stanley。当然，两个都学会是最好的——毕竟，多一个工具，多一条路。

最后分享一个小技巧：在实际项目中，我经常把Pure Pursuit和Stanley结合起来用——直道上用Stanley保证精度，弯道上用Pure Pursuit保证过弯能力。切换时加一个平滑过渡，效果出奇的好。

好了，关于几何跟踪方法就聊到这里。记住，算法是死的，场景是活的。多动手调参，多记录数据，你也能成为路径跟踪的高手。
