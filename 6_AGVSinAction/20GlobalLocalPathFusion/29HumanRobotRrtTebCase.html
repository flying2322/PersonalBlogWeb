29 真实项目案例3：人机协作场景下的融合方案（RRT* + TEB + 社会力模型）

各位同学，欢迎来到第29讲。

前面我们聊了不少理论，从全局规划到局部避障，再到各种优化。但说实话，理论再漂亮，落地才是硬道理。今天这个案例，是我个人觉得最有意思的一个——人机协作场景下的路径融合。

什么叫人机协作？说白了，就是AGV和人在同一个物理空间里干活。AGV不能把工人当障碍物一样绕过去就完事，你得考虑人的意图、人的舒适度，甚至人的“面子”。你想想看，一台叉车AGV从工人背后突然贴脸冲过去，工人吓一跳，这项目肯定黄。

所以，今天这个方案，我把它叫做“三层融合”：RRT* 负责全局骨架，TEB 负责局部平滑与动态避障，社会力模型负责“人味儿”。

核心思路：全局规划定方向，局部优化保安全，社会力模型管“人情世故”。

29.1 场景痛点分析

先说说我遇到过的真实场景。某汽车零部件工厂，产线旁边有工人走动、有叉车AGV送货。原来的方案是纯TEB，结果呢？AGV经常在工人面前“犹豫不决”，或者走出一条让工人觉得“这机器人是不是有病”的路径。

具体痛点有三个：

  • 全局路径不合理：纯TEB容易陷入局部最优，比如被一个站着不动的工人堵死，绕一大圈。
  • 局部避障太“硬”：TEB的优化目标主要是路径长度和平滑度，它不会考虑“人会不会觉得被冒犯”。
  • 人机交互缺失：AGV不知道工人下一步要往哪走，只能被动反应。

嗯，这里要注意，被动反应在低速场景还行，一旦速度上来，很容易出安全事故。

29.2 融合方案架构

我设计的方案，简单来说就是“RRT* 搭骨架，TEB 做肌肉，社会力模型当神经”。下面这张图能帮你快速理解整体流程：

你看，RRT* 先跑一遍，给出一个从起点到终点的无碰撞路径。这个路径可能很粗糙，有很多折角，但它保证了可达性。然后TEB接手，把这个粗糙路径作为初始解，进行局部优化，生成平滑、满足运动学约束的轨迹。

关键点来了：社会力模型不是独立运行的，它作为TEB优化中的一个额外代价项。什么意思？就是TEB在优化时，不仅要考虑路径长度、平滑度、障碍物距离，还要考虑“这个轨迹会不会让旁边的人感到不舒服”。

我的经验：社会力模型的参数调起来很玄学。我曾经在一个仓库里，把“人际距离”参数设得太小，结果AGV贴着工人走，工人直接投诉说“这机器人想撞我”。后来我把参数调大，AGV开始绕远路，工人又说“这机器人太怂了”。最后折中方案是：根据工人当前的活动状态动态调整参数——工人站着不动时，保持1.5米距离；工人在走动时，保持2米以上。

29.3 关键技术实现

29.3.1 RRT* 的改进：引入“人机友好”采样

标准的RRT* 采样是均匀的，但在人机协作场景下，我建议做一点小改动：在行人密集区域，提高采样密度。这样生成的骨架路径会更精细，给后续TEB留出更多调整空间。

代码实现上，其实就是改一下采样概率分布：

// 伪代码：人机友好采样
if (区域内有行人) {
    // 在行人周围进行高斯采样
    sample_point = 行人位置 + 高斯噪声(mean=0, std=1.5m);
} else {
    // 标准均匀采样
    sample_point = 随机采样(地图边界);
}

这样做的好处是，RRT* 生成的路径天然会“避开”行人密集区，而不是等到TEB阶段才急刹车。

29.3.2 TEB 的改造：加入社会力代价项

TEB 的核心是一个优化问题，目标函数通常是这样的：

min J = w_path * 路径长度代价 
       + w_smooth * 平滑度代价 
       + w_obstacle * 障碍物距离代价 
       + w_social * 社会力代价   // 新增！

这个社会力代价怎么算？我参考了Helbing的社会力模型，但做了简化：

  • 排斥力：AGV与行人距离越近，代价越大。公式：cost = 1 / (距离^2)，距离小于阈值时急剧增大。
  • 方向力：如果AGV的运动方向与行人预期运动方向相反，代价增加。说白了，就是不要“迎面怼”行人。
  • 速度力：AGV在行人附近时，速度越快，代价越大。这符合直觉——离人近就慢点。

避坑指南：我曾经把社会力代价的权重设得过高，结果AGV在空旷区域也“畏手畏脚”，走出一条蛇形路径。后来我加了一个自适应权重：行人密度高时，w_social 增大；行人密度低时，w_social 减小。这样AGV在没人的地方该快就快，有人的地方该怂就怂。

29.3.3 社会力模型的实时预测

社会力模型不仅要考虑当前时刻的行人位置，还要预测未来几秒的行人位置。我用的方法很简单：

  1. 通过激光雷达或视觉传感器获取行人位置和速度。
  2. 假设行人保持当前速度方向匀速运动，预测未来2秒内的轨迹。
  3. 将预测轨迹上的每个点都作为“动态障碍物”输入到TEB中。

你可能会问：“预测不准怎么办？” 嗯，确实不准。所以我在TEB中设置了一个滚动时域，每0.5秒重新优化一次。这样即使预测有偏差，也能快速修正。

29.4 实际效果与参数调优

我在现场跑过这个方案，给大家看一组对比数据：

指标 纯TEB方案 RRT* + TEB + 社会力模型
平均路径长度 12.3 m 13.1 m（略长，但可接受）
行人“惊吓”次数（主观评价） 8次/小时 1次/小时
AGV急停次数 15次/小时 3次/小时
工人满意度评分（满分10） 4.2 8.7

你看，路径长度虽然增加了不到1米，但人机交互体验提升了一大截。说白了，在和人打交道的场景里，效率不是唯一指标，舒适度和安全感更重要。

29.5 部署时的几个坑

最后，分享几个我踩过的坑，希望能帮你少走弯路：

  • 传感器延迟：社会力模型依赖行人位置数据，如果传感器延迟超过100ms，预测就会严重不准。我建议用EKF（扩展卡尔曼滤波）对行人轨迹做平滑和预测。
  • 多人场景的计算量：如果场景里有10个以上行人，社会力代价的计算会变得很重。我的做法是：只考虑AGV周围5米内的行人，远处的忽略。
  • 社会力模型的“过度礼貌”：有时候AGV会为了避让行人，把自己逼到墙角出不去。这时候需要给TEB加一个“逃生路径”约束，确保AGV始终有一条通往目标的可行路径。

总结一下：RRT* 负责“能不能到”，TEB 负责“怎么到得好”，社会力模型负责“怎么到得让人舒服”。三者缺一不可。这个方案我在三个不同工厂部署过，效果都还不错。如果你也在做人机协作项目，不妨试试这个思路。
