16 全局与局部融合架构：分层规划框架、Map更新机制、重规划触发条件、状态机设计

各位同学，今天我们来聊聊AGV路径规划里最核心的一个话题——全局与局部融合架构。

说实话，我见过不少团队，全局规划做得漂漂亮亮，局部规划也写得头头是道。但一上路跑，车就撞墙。为什么？因为两者没融合好。全局规划告诉你「走这条路」，局部规划却因为传感器噪声突然拐了个弯，结果全局路径白算了。

所以，融合架构不是简单的「全局+局部」，而是一套完整的协同机制。今天我就把这套机制拆开揉碎了讲给你听。

16.1 分层规划框架：为什么需要分层？

先问一个问题：你开车从北京到上海，你会怎么做？

你肯定先看地图，规划一条高速路线。这是全局规划。但上了高速，前面有辆车开得慢，你会变道超车。这是局部规划。你不会因为要超车，就重新规划整个北京到上海的路线吧？

AGV也是这个道理。全局规划负责「宏观路线」，局部规划负责「微观避障」。两者各司其职，才能高效运行。

我习惯把分层规划框架画成三层：

分层规划框架（三层结构）
1. 全局规划层：基于静态地图，生成从起点到终点的最优路径。频率低（秒级），计算量大。
2. 局部规划层：基于传感器数据，在全局路径附近做局部调整。频率高（毫秒级），实时性强。
3. 执行层：将局部路径转化为电机控制指令。频率最高（微秒级）。

这里有个关键点：全局路径不是一成不变的。它更像一个「参考线」。局部规划器沿着这条参考线走，但允许有小幅度的偏移。

我在项目中遇到过一个问题：全局路径穿过了两个货架之间的狭窄通道，但局部规划器因为传感器噪声，把车往左边偏了5厘米，结果撞上了货架。后来怎么解决的？我们在局部规划里加了一个「走廊约束」——局部路径不能偏离全局路径超过一定阈值。嗯，这个阈值要根据车宽和通道宽度来调，不能一刀切。

16.2 Map更新机制：地图不是死的

你想想看，工厂里的环境是动态的。今天这里放了个托盘，明天那里多了个工人。如果地图不更新，全局规划就是「盲人摸象」。

Map更新机制，说白了就是让地图「活起来」。我把它分为两种：

更新类型 触发条件 更新内容 频率
静态更新 人工导入/手动编辑 货架位置、充电站、工作站 天级
动态更新 传感器检测到变化 临时障碍物、移动物体 秒级/毫秒级

动态更新这块，我踩过不少坑。曾经有一次，AGV检测到前方有个纸箱，于是把地图上那个位置标记为「障碍物」。但纸箱很快被工人搬走了，地图上却还留着障碍物标记。结果后面的AGV都绕道走，效率大打折扣。

避坑指南：动态障碍物要有「超时清除」机制。比如一个障碍物被检测到后，如果连续3秒没有再次被检测到，就自动从地图上移除。这个超时时间要根据场景来调，仓库里可以长一点，车间里要短一点。

另外，我建议把地图分成「全局地图」和「局部地图」两层。全局地图存的是固定结构（墙壁、货架），局部地图存的是动态信息（临时障碍物、行人）。这样更新局部地图不会影响全局地图的稳定性。

16.3 重规划触发条件：什么时候该重新算路？

全局路径不是算一次就完事的。什么时候需要重新规划？我总结了几个典型场景：

  1. 路径被完全阻塞：局部规划尝试了N次都无法通过，说明这条路走不通了。
  2. 目标点发生变化：比如任务中途被取消，或者要先去另一个工作站。
  3. 地图发生重大变化：比如某个区域被封锁，或者新增了障碍物。
  4. 路径代价过高：比如原路径上出现了拥堵，绕行反而更快。

这里有个细节：重规划不是越频繁越好。每次重规划都要消耗计算资源，而且如果规划器不稳定，会导致路径来回跳变。

我曾经遇到过一个案例：AGV在走廊里，前方有个工人站着不动。局部规划尝试绕行，但走廊太窄绕不过去。于是触发了重规划，全局规划算了一条新路径——从走廊另一头绕过去。但工人很快走开了，AGV又触发了一次重规划，回到了原路径。结果AGV就在那里来回折腾，像个无头苍蝇。

我的经验：重规划触发后，加一个「冷却时间」。比如触发重规划后，至少等5秒才能再次触发。这样可以避免频繁重规划导致的震荡。另外，重规划前先让局部规划多尝试几次，有时候只是临时障碍物，等一等就过去了。

16.4 状态机设计：让AGV知道自己该干嘛

状态机，说白了就是AGV的「大脑状态」。它知道自己现在在干嘛，下一步该干嘛。

我设计的状态机一般包含以下几个状态：

  • IDLE（空闲）：等待任务，停在原地。
  • PLANNING（规划中）：正在计算全局路径。
  • FOLLOWING（跟随中）：沿着全局路径行驶，局部规划器在实时调整。
  • REPLANNING（重规划中）：遇到障碍，正在重新计算路径。
  • BLOCKED（阻塞）：多次重规划失败，需要人工干预。
  • COMPLETED（完成）：到达目标点，任务结束。

状态之间的转换逻辑是这样的：

IDLE → 收到任务 → PLANNING → 路径计算完成 → FOLLOWING → 遇到障碍 → REPLANNING → 新路径算好 → FOLLOWING → 到达目标 → COMPLETED → IDLE

如果REPLANNING连续失败3次，就进入BLOCKED状态，等待人工处理。

核心要点总结：
1. 分层规划：全局管宏观，局部管微观，两者通过「走廊约束」协同。
2. Map更新：静态地图和动态地图分开管理，动态障碍物要有超时清除机制。
3. 重规划触发：不是越频繁越好，加冷却时间，避免路径震荡。
4. 状态机：明确每个状态的责任，转换条件要清晰，失败处理要兜底。

好了，关于全局与局部融合架构，我就讲这么多。这套架构我在多个项目中验证过，效果还不错。你如果自己实现，建议先从状态机入手，把各个状态的行为定义清楚，然后再逐步加入Map更新和重规划逻辑。一步步来，别想一口吃成胖子。

一个小技巧：调试阶段，把状态机的状态实时显示在AGV的屏幕上。这样你一眼就能看出AGV当前在干嘛，是卡在PLANNING还是BLOCKED。我当年调试时，就靠这个快速定位问题。
