6 Dijkstra算法：原理、与A*的对比、在无权图与有权图中的应用、实际项目中的变体

6.1 算法原理：从起点开始“水波扩散”

Dijkstra算法，说白了就是一张地图上，从你家出发，怎么找到去公司最近的路。它不关心路上有几个红绿灯，只关心每条路的长度。

它的核心思想很简单：每次从“未确定最短路径”的节点中，挑一个离起点最近的，然后更新它邻居的距离。就像在水面上扔一块石头，波纹一圈一圈往外推，最先碰到哪个点，那个点就是最近的。

我刚开始做AGV调度时，觉得这算法太基础了。后来发现，很多复杂场景下，它反而是最稳的。为什么？因为它保证能找到最短路径，前提是所有边的权重非负。

具体步骤是这样的：

  1. 初始化：起点距离为0，其他节点距离为无穷大。
  2. 维护一个优先队列（最小堆），把起点放进去。
  3. 每次从队列里取出距离最小的节点u。
  4. 遍历u的所有邻居v，如果 dist[u] + weight(u,v) < dist[v]，就更新dist[v]，并把v加入队列。
  5. 重复直到队列为空。

嗯，这里要注意：Dijkstra不能处理负权边。我在项目里踩过这个坑，后面会讲。

核心要点：Dijkstra是广度优先搜索（BFS）的加权版本。BFS用队列，Dijkstra用优先队列。

6.2 与A*的对比：一个“盲目”，一个“有方向”

很多人问我：Dijkstra和A*到底选哪个？我的回答是：看场景。

Dijkstra是“盲目”的。它不知道目标在哪，只能一圈一圈往外扩。如果地图很大，它会浪费大量时间在错误的方向上。

A*是“有方向”的。它加了一个启发式函数（比如欧几里得距离），告诉算法“目标大概在那个方向”。所以A*通常更快。

但A*有个致命弱点：启发式函数必须设计得好。如果启发式函数高估了距离，A*可能找不到最短路径。我在一个仓储AGV项目里，就因为启发式函数没调好，导致机器人绕了远路。

对比项 Dijkstra A*
搜索方式 均匀扩散 有方向扩散
保证最优解 是（非负权） 是（启发式可采纳）
时间复杂度 O(E log V) 通常更快，但最坏情况相同
适用场景 地图小、需要绝对最优 地图大、需要快速响应
启发式函数 不需要 需要

我个人习惯：如果地图节点数少于1000，直接用Dijkstra。超过1000，考虑A*。但如果你不确定启发式函数怎么设计，Dijkstra永远是最安全的选择。

6.3 在无权图与有权图中的应用

无权图，说白了就是所有边的权重都是1。这时候Dijkstra退化成BFS。你想想看，既然每条路都一样长，那先找到的肯定就是最短的。

有权图才是Dijkstra的主场。比如AGV在工厂里跑，有的路段是直线（权重小），有的路段要转弯（权重大），有的路段是斜坡（权重更大）。Dijkstra能精确算出综合代价最小的路径。

我在一个项目里遇到过这种情况：工厂地面有不同材质，瓷砖地面摩擦小，水泥地面摩擦大。我们把不同地面的权重设成不同值，Dijkstra算出来的路径会主动避开水泥地，哪怕绕一点路。

实战技巧：在AGV项目中，权重不一定是距离。可以是时间、能耗、安全性等。我习惯把权重设计成“综合代价”，比如 weight = distance * (1 + congestion_factor)。

6.4 实际项目中的变体

Dijkstra在教科书里很完美，但在实际项目中，我们经常需要改一改。下面是我用过的几个变体：

6.4.1 双向Dijkstra

从起点和终点同时开始搜索，直到两个搜索区域相遇。速度能快一倍左右。我在一个2000节点的地图上测试过，单向Dijkstra要50ms，双向只要28ms。

6.4.2 带约束的Dijkstra

AGV不能走某些路段（比如维修区），或者不能经过某些节点（比如其他AGV正在作业的区域）。我们可以在算法里加一个“禁止列表”，遇到这些节点直接跳过。

我曾经踩过一个坑：只禁止了节点，没禁止边。结果AGV从节点A到节点B的路径被禁止了，但算法还是找到了A->C->B的路径，绕了一大圈。后来我把禁止列表改成了“禁止边+禁止节点”双检查。

6.4.3 时间依赖Dijkstra

工厂里有些路段在特定时间段会拥堵。比如午餐时间，工人会经过某些通道。这时候边的权重是随时间变化的。Dijkstra需要改成“时间依赖最短路径”，每次计算时根据当前时间查权重表。

注意：时间依赖Dijkstra不能直接用优先队列，因为权重会变。我建议用“动态规划+时间窗口”的方式实现，或者干脆用A*加时间惩罚。

6.5 代码示例：一个简单的Dijkstra实现

下面是我在项目中常用的Dijkstra实现，用Python写的。注意，我用了heapq来实现优先队列。

import heapq

def dijkstra(graph, start):
    # graph: 邻接表，{node: [(neighbor, weight), ...]}
    # start: 起点
    dist = {node: float('inf') for node in graph}
    dist[start] = 0
    pq = [(0, start)]  # (距离, 节点)
    
    while pq:
        current_dist, u = heapq.heappop(pq)
        
        # 如果当前距离大于已知最短距离，跳过
        if current_dist > dist[u]:
            continue
        
        for v, w in graph[u]:
            new_dist = dist[u] + w
            if new_dist < dist[v]:
                dist[v] = new_dist
                heapq.heappush(pq, (new_dist, v))
    
    return dist

这段代码看起来简单，但有几个细节要注意：

  • 第8行的 if current_dist > dist[u] 是优化，避免重复处理过时的队列条目。
  • 第12行的 new_dist < dist[v] 是核心更新逻辑。
  • 如果你要记录路径，需要加一个 prev 字典来保存前驱节点。

6.7 避坑指南

最后，分享几个我踩过的坑：

  • 负权边：Dijkstra不能处理负权边。如果你有负权，用Bellman-Ford。我曾经在一个项目里不小心把权重设成了负数，结果算法一直跑不出结果。
  • 大图性能：如果地图节点超过10万，Dijkstra会慢得让人崩溃。这时候考虑用A*或者分层Dijkstra。
  • 动态变化：AGV运行过程中，地图会变化（比如新障碍物）。Dijkstra需要重新计算，但你可以用“增量式Dijkstra”来优化，只更新受影响的部分。

嗯，Dijkstra算法就讲到这里。它虽然基础，但用好它，你的AGV就能在复杂环境中找到最优路径。记住：没有最好的算法，只有最合适的算法。
