22 仿真环境搭建——Gazebo/CoppeliaSim、ROS Navigation Stack、自定义仿真场景

说实话，做AGV路径规划最头疼的是什么？不是算法本身，而是你写了一大堆代码，却不敢直接往真车上跑。万一撞了，那可不是闹着玩的。所以，仿真环境就是我们算法工程师的「安全气囊」。

这一章，我带你搭建一套完整的仿真测试环境。我们会用到Gazebo和CoppeliaSim两种主流仿真器，配合ROS Navigation Stack，再搞一个自定义的测试场景。嗯，这套组合拳打下来，你的算法就有了可靠的试验田。

22.1 为什么需要仿真环境？

我个人习惯，任何新算法必须先过仿真这一关。为什么？三个原因：

  • 安全第一：真车测试撞一次，维修费够你买几台工作站了
  • 可重复性：仿真里你可以让机器人跑1000次同样的路径，真车做不到
  • 调试效率：仿真里可以暂停、回放、单步执行，真车调试你只能追着跑

核心观点：仿真不是替代真车测试，而是把80%的bug消灭在虚拟环境里。剩下的20%，才是真车验证的活。

22.2 Gazebo vs CoppeliaSim：怎么选？

这两个仿真器我都用过，各有千秋。我整理了一张对比表，你一看就明白：

特性 Gazebo CoppeliaSim（原V-REP）
与ROS集成 原生支持，无缝对接 通过插件支持，稍复杂
物理引擎 ODE、Bullet、DART等 Bullet、ODE、Vortex等
场景编辑 SDF/URDF文件，命令行式 GUI拖拽，所见即所得
传感器仿真 激光雷达、IMU、相机等 同样丰富，且支持自定义
学习曲线 中等，需要熟悉ROS 较陡，但功能更强大
社区活跃度 极高，ROS生态 中等，工业用户多

我的建议是：如果你主要用ROS，优先选Gazebo。如果你需要复杂的机械臂或多机器人协同，CoppeliaSim更合适。我在项目中遇到过用Gazebo模拟多机器人时性能下降的问题，后来切到CoppeliaSim才搞定。

22.3 搭建Gazebo仿真环境

好，我们开始动手。先搞定Gazebo + ROS Navigation Stack这套组合。

22.3.1 安装与配置

首先，确保你装了ROS Noetic或Melodic。然后：

sudo apt-get install ros-noetic-gazebo-ros-pkgs ros-noetic-gazebo-ros-control
sudo apt-get install ros-noetic-navigation
sudo apt-get install ros-noetic-slam-gmapping

嗯，这里要注意：版本一定要匹配。我见过有人装了ROS Melodic却装了Noetic的导航包，结果编译报错一整天。

22.3.2 创建AGV机器人模型

我们需要一个URDF文件来描述AGV。下面是一个简化版的双轮差速AGV模型：

<robot name="simple_agv">
  <link name="base_link">
    <visual>
      <geometry>
        <box size="0.5 0.4 0.2"/>
      </geometry>
    </visual>
    <collision>
      <geometry>
        <box size="0.5 0.4 0.2"/>
      </geometry>
    </collision>
  </link>

  <joint name="left_wheel_joint" type="continuous">
    <parent link="base_link"/>
    <child link="left_wheel"/>
    <origin xyz="-0.15 0.25 -0.1" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
  </joint>

  <link name="left_wheel">
    <visual>
      <geometry>
        <cylinder radius="0.1" length="0.05"/>
      </geometry>
    </visual>
  </link>

  <!-- 右轮类似，省略 -->

  <gazebo>
    <plugin name="gazebo_ros_control" filename="libgazebo_ros_control.so">
      <robotNamespace>/agv</robotNamespace>
    </plugin>
  </gazebo>
</robot>

小技巧：URDF里别忘了加<gazebo>插件，否则你的机器人动不了。我曾经因为这个卡了整整一个下午。

22.3.3 配置ROS Navigation Stack

Navigation Stack需要几个配置文件：

  • costmap_common_params.yaml：代价地图通用参数
  • global_costmap_params.yaml：全局代价地图
  • local_costmap_params.yaml：局部代价地图
  • base_local_planner_params.yaml：局部规划器参数
  • move_base.launch：启动文件

核心参数示例：

# costmap_common_params.yaml
obstacle_range: 2.5
raytrace_range: 3.0
footprint: [[0.25, 0.2], [-0.25, 0.2], [-0.25, -0.2], [0.25, -0.2]]
inflation_radius: 0.3
observation_sources: laser_scan_sensor
laser_scan_sensor: {
  sensor_frame: laser_frame,
  data_type: LaserScan,
  topic: /scan,
  marking: true,
  clearing: true
}

你想想看，这些参数直接影响路径规划的质量。inflation_radius设太小，机器人容易擦墙；设太大，又过不去窄通道。我一般从0.3开始调，根据实际场景微调。

22.3.4 启动仿真

写一个launch文件，把一切串起来：

<launch>
  <!-- 启动Gazebo世界 -->
  <include file="$(find gazebo_ros)/launch/empty_world.launch">
    <arg name="world_name" value="$(find agv_sim)/worlds/test_world.world"/>
  </include>

  <!-- 加载机器人模型 -->
  <param name="robot_description" command="$(find xacro)/xacro $(find agv_sim)/urdf/agv.xacro"/>
  <node name="spawn_urdf" pkg="gazebo_ros" type="spawn_model" args="-param robot_description -urdf -model agv"/>

  <!-- 启动move_base -->
  <node pkg="move_base" type="move_base" name="move_base" output="screen">
    <rosparam file="$(find agv_sim)/config/costmap_common_params.yaml" command="load" ns="global_costmap"/>
    <rosparam file="$(find agv_sim)/config/costmap_common_params.yaml" command="load" ns="local_costmap"/>
    <rosparam file="$(find agv_sim)/config/local_costmap_params.yaml" command="load"/>
    <rosparam file="$(find agv_sim)/config/global_costmap_params.yaml" command="load"/>
    <rosparam file="$(find agv_sim)/config/base_local_planner_params.yaml" command="load"/>
  </node>
</launch>

运行：

roslaunch agv_sim gazebo_navigation.launch

如果一切顺利，你会看到Gazebo里出现一辆AGV，Rviz里显示代价地图和路径。用2D Nav Goal点一下，机器人就会自己规划路径走过去。

22.4 CoppeliaSim仿真环境搭建

Gazebo搞定了，我们再看看CoppeliaSim。说实话，CoppeliaSim的GUI编辑确实比Gazebo方便。

22.4.1 安装与ROS接口

从官网下载CoppeliaSim，解压即可。然后安装ROS接口：

cd ~/CoppeliaSim_Edu_V4_1_0_Ubuntu20_04
./sim.sh  # 启动仿真器

# 安装ROS插件
cp libsimExtROSInterface.so ~/catkin_ws/devel/lib/

22.4.2 创建AGV场景

在CoppeliaSim里：

  1. 添加一个Cuboid作为车体
  2. 添加两个Cylinder作为轮子
  3. 添加一个Vision Sensor作为激光雷达
  4. 用Revolute Joint连接轮子和车体
  5. 添加一个Path对象作为参考路径

嗯，这里有个坑：CoppeliaSim的坐标系和ROS不一样。ROS是右手系，CoppeliaSim是左手系。你需要用simROS.handleROSInterface来转换。

22.4.3 编写控制脚本

用Lua写一个简单的差速控制：

function sysCall_init()
    leftMotor = sim.getObjectHandle('leftMotor')
    rightMotor = sim.getObjectHandle('rightMotor')
    simROS = require('simROS')
    sub = simROS.subscribe('/cmd_vel', 'geometry_msgs/Twist', 'velocityCallback')
end

function velocityCallback(msg)
    local vx = msg.linear.x
    local wz = msg.angular.z
    local wheelBase = 0.4
    local leftSpeed = vx - wz * wheelBase / 2
    local rightSpeed = vx + wz * wheelBase / 2
    sim.setJointTargetVelocity(leftMotor, leftSpeed)
    sim.setJointTargetVelocity(rightMotor, rightSpeed)
end

注意：CoppeliaSim的仿真步长默认是50ms，如果你用ROS的Navigation Stack，需要调整控制频率。我一般设成20ms，这样路径跟踪更平滑。

22.5 自定义仿真场景

光有仿真器还不够，你得有测试场景。我教你建一个典型的仓库场景。

22.5.1 场景设计思路

一个好的测试场景应该包含：

  • 直道：测试直线路径跟踪
  • 弯道：测试转弯性能
  • 窄通道：测试避障和通过性
  • 动态障碍物：测试实时避障
  • 货架区域：模拟真实仓库环境

22.5.2 用Gazebo建场景

创建一个SDF世界文件：

<?xml version="1.0" ?>

    <!-- 地面 -->

      <link name="link">
        <collision name="collision">

              <normal>0 0 1</normal>

          </geometry>
        </collision>

22.6 仿真测试流程

场景搭好了，怎么跑测试？我一般按这个流程来：

  1. 启动仿真器：加载自定义场景
  2. 启动SLAM：用gmapping或cartographer建图
  3. 保存地图：map_server保存为pgm+yaml
  4. 启动导航：加载地图，启动move_base
  5. 发送目标点：用rviz或命令行发送导航目标
  6. 记录数据：rosbag记录所有话题
  7. 分析结果：回放数据，评估路径质量

经验之谈：我习惯用rosbag record -a记录所有话题，然后离线分析。这样你可以反复回放，找到问题所在。有一次我发现路径抖动，回放数据才发现是激光雷达的帧率太低导致的。

22.7 常见问题与避坑

最后，分享几个我踩过的坑：

  • 仿真时间不同步：Gazebo的仿真时间和真实时间可能不一致，导致导航卡顿。解决办法是设置<real_time_update_rate>1000</real_time_update_rate>
  • 激光雷达盲区：默认的激光雷达模型有盲区，AGV靠近障碍物时可能检测不到。我一般把range设成0.1m起步
  • 轮子打滑：Gazebo的摩擦系数默认值偏小，AGV转弯时容易打滑。把<mu>1.0</mu>调大一些
  • 代价地图膨胀：inflation_radius设太大，AGV在窄通道里会认为无路可走。我一般根据AGV宽度动态调整

嗯，仿真环境搭建就讲到这里。这套环境你搭好了，后面学全局路径规划、局部路径规划、动态避障，都有地方练手了。记住，仿真不是终点，是起点。你的算法在仿真里跑得稳，真车上才敢放心用。
