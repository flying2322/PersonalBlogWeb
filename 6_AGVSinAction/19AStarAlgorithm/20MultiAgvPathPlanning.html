20 多AGV路径规划：冲突检测、优先级规划、交通管制

各位同学，欢迎来到第20章。

前面我们聊了很多单台AGV怎么找路，A*算法怎么优化。但说实话，那都是「理想状态」。真实工厂里，十几台甚至几十台AGV同时跑，那场面，跟早高峰的十字路口差不多。你想想看，如果每台车都只想着自己走最短路径，那结果就是——堵死。

所以这一章，我们来解决多AGV协同的核心问题：冲突检测、优先级规划、交通管制。这三个词，说白了就是「发现堵点、谁先走、怎么管」。我在项目里吃过不少亏，今天把这些坑都给你摆出来。

核心观点：多AGV调度不是路径规划的简单叠加，而是一个分布式约束满足问题。单台车的最优解，往往是全局的灾难。

20.1 冲突检测：先要知道「撞没撞」

冲突检测听起来简单，但实际做起来，细节很多。我刚开始做多车调度时，以为只要检查两车坐标是否重合就行。结果呢？有一次在仓库里，两台AGV在十字路口「擦肩而过」，坐标没重合，但车身刮到了。嗯，这就是典型的「检测盲区」。

常见的冲突类型有三种：

  • 节点冲突：两台车同时要占用同一个网格点。比如十字路口中心。
  • 边冲突：两台车相向而行，要经过同一条路径段。这是最常见的。
  • 跟随冲突：前车慢，后车快，后车被堵住。虽然没撞上，但效率没了。

我个人习惯用时空占用表来做冲突检测。简单说，就是给每台AGV规划路径时，把每个时间点它占用的网格坐标记录下来。然后查表，看有没有重叠。

# 伪代码：时空占用表冲突检测
def detect_conflict(path_a, path_b):
    # path_a: [(x1,y1,t1), (x2,y2,t2), ...]
    # path_b: [(x1,y1,t1), (x2,y2,t2), ...]
    for step_a, step_b in zip(path_a, path_b):
        if step_a[0] == step_b[0] and step_a[1] == step_b[1]:
            return True  # 节点冲突
        # 边冲突检测：检查相邻时间步的交换
        if step_a[0] == step_b[0] and step_a[1] == step_b[1]:
            # 这里简化了，实际要检查前后两步
            pass
    return False

避坑指南：我曾经犯过一个错——只检测了节点冲突，没检测边冲突。结果两台车在一条直道上面对面开，各自规划路径时都没占用同一个节点，但到了中间段就卡住了。所以，边冲突一定要检测相邻时间步的路径段交换。

20.2 优先级规划：谁先走，谁让路

检测到冲突之后，怎么办？总得有个规则来决定谁先走。这就是优先级规划。

优先级怎么定？我见过几种做法：

  1. 任务紧急度：比如产线急停的物料，优先级最高。
  2. 距离终点远近：快到的车优先，避免它绕路。
  3. 固定优先级：给每台AGV编号，编号小的先走。简单粗暴，但公平性差。
  4. 动态优先级：根据当前负载、电量、任务状态实时调整。这是最灵活的。

我个人比较推荐混合优先级。举个例子：先按任务紧急度分大等级（紧急、普通、空闲），同等级内再按距离终点远近排序。这样既保证了关键任务不耽误，又避免了低优先级车永远等不到的情况。

关键点：优先级不是一成不变的。我见过一个项目，一台AGV因为优先级低，在路口等了3分钟。后来我们加了「等待超时提升优先级」的机制，问题就解决了。

20.3 交通管制：像红绿灯一样管理

冲突检测和优先级规划是「事后处理」——发现冲突了再解决。但交通管制是「事前预防」。说白了，就是在关键路口设置管制区，一次只让一台车通过。

交通管制通常分两种：

  • 路口管制：在十字路口、丁字路口设置管制区。AGV进入前要申请，获得许可后才能进入。
  • 路段管制：在狭窄通道、单行道设置管制。一次只允许一个方向的车通过。

实现方式上，我习惯用资源锁的概念。每个管制区就是一个资源，AGV要占用时先加锁，离开时释放。如果锁被占用，AGV就在入口处等待。

# 伪代码：交通管制资源锁
class TrafficControl:
    def __init__(self):
        self.zones = {}  # zone_id -> owner_agv_id
    
    def request_entry(self, agv_id, zone_id):
        if zone_id not in self.zones:
            self.zones[zone_id] = agv_id
            return True  # 获得许可
        else:
            return False  # 等待
    
    def release_zone(self, agv_id, zone_id):
        if self.zones.get(zone_id) == agv_id:
            del self.zones[zone_id]

注意：交通管制要小心死锁。比如两台AGV在十字路口互相等待对方让路，结果谁都不动。我遇到过这种情况，后来加了超时强制释放机制——如果一台车在管制区入口等待超过5秒，就强制降低它的优先级，让另一台车先走。

20.5 实战经验：三个常见坑

最后，分享三个我在项目中踩过的坑，希望能帮你少走弯路。

坑 现象 解决方案
死锁 两台AGV在路口互相等待，谁都不动 加超时机制，等待超过阈值就强制让一台车后退或绕路
优先级饥饿 低优先级AGV永远等不到通行机会 动态提升等待时间过长的AGV优先级
检测盲区 只检测节点冲突，没检测边冲突，导致刮擦 时空占用表必须包含路径段信息，不能只看节点

我的建议：刚开始做多AGV调度时，别想着一步到位。先实现基础的冲突检测+优先级规划，跑通后再加交通管制。我见过有人一上来就搞复杂的分布式算法，结果调试了两个月还没跑起来。嗯，稳扎稳打才是正道。

好了，这一章的内容就到这里。冲突检测、优先级规划、交通管制，这三个东西是绑在一起的。你想想看，没有检测，就不知道谁撞了谁；没有优先级，就不知道谁该让谁；没有管制，就算知道了也执行不下去。三者缺一不可。
