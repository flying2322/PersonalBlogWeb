17 A星算法在AGV中的应用：全局路径规划、局部路径规划

各位好，我是老张。今天咱们聊聊A星算法在实际AGV项目里到底怎么用。说实话，很多教材把A星讲得神乎其神，但真正落地时你会发现——嗯，理论和工程之间，隔着一道不小的鸿沟。

我个人习惯把AGV的路径规划拆成两层：全局规划和局部规划。全局规划负责“大方向”，局部规划负责“避坑”。这两层配合好了，AGV才能跑得又稳又聪明。

17.1 全局路径规划：先定大方向

全局规划，说白了就是在地图上找一条从起点到终点的可行路径。A星算法在这里是绝对的主力。

我在项目中遇到过一个问题：工厂地图动不动就几百米乘几百米，栅格化后网格数量惊人。如果直接用标准A星，搜索空间太大，计算时间能让你等到怀疑人生。

那怎么办？ 我一般会做两件事：

  • 地图分层：先在高一层的地图上跑A星，找到关键路径点，再在低一层的地图上细化。这就像你先看城市地图选主干道，再看街区地图找具体路线。
  • 启发函数调优：标准A星用曼哈顿距离或欧几里得距离。但在AGV场景里，我建议用对角距离，因为它更符合AGV的运动特性——AGV可以斜着走，但代价比直行高一点。

核心要点：全局规划的目标不是“最优”，而是“可行且高效”。在工业现场，90%的路径只要“足够好”就行，不必追求数学上的绝对最优。

下面是我常用的全局A星伪代码，注意看启发函数那块：

function globalAStar(start, goal, grid):
    openSet = PriorityQueue()
    openSet.add(start, 0)
    cameFrom = {}
    gScore = map(default=infinity)
    gScore[start] = 0
    fScore = map(default=infinity)
    fScore[start] = heuristic(start, goal)
    
    while not openSet.isEmpty():
        current = openSet.pop()
        if current == goal:
            return reconstructPath(cameFrom, current)
        
        for neighbor in getNeighbors(current, grid):
            // 这里考虑AGV的转弯代价
            turnCost = getTurnCost(current, neighbor)
            tentativeG = gScore[current] + dist(current, neighbor) + turnCost
            
            if tentativeG < gScore[neighbor]:
                cameFrom[neighbor] = current
                gScore[neighbor] = tentativeG
                fScore[neighbor] = gScore[neighbor] + heuristic(neighbor, goal)
                if neighbor not in openSet:
                    openSet.add(neighbor, fScore[neighbor])
    
    return failure

我的经验：启发函数heuristic()不要用曼哈顿距离。AGV在工厂里经常需要绕开障碍物，曼哈顿距离会严重高估实际代价，导致搜索效率下降。我用的是带权重的对角距离，权重系数一般取1.2~1.5。

17.2 局部路径规划：实时避坑

全局路径规划好了，但AGV跑起来后，你会发现——地图上突然多了个箱子、有个人走过来了、另一台AGV堵在路上了。这时候就需要局部路径规划上场了。

局部规划，说白了就是“短视”的规划。它只看AGV周围几米的范围，实时调整路径。A星在这里也能用，但需要做一些改造。

为什么不能直接用全局A星？ 你想想看，全局A星每次规划都要遍历整个地图，计算量太大。局部规划要求毫秒级响应，必须轻量化。

我常用的做法是：

  • 局部窗口法：只取AGV周围5米×5米的区域作为搜索空间。这个窗口随着AGV移动而移动。
  • 动态障碍物处理：把传感器检测到的动态障碍物实时更新到局部地图中。注意，这些障碍物只在局部地图中标记，不影响全局地图。
  • 路径平滑：局部规划出来的路径往往有锯齿，需要做平滑处理。我用的是B样条曲线，效果不错。

避坑指南：我曾经在局部规划里直接用全局A星的启发函数，结果AGV在狭窄通道里来回震荡。后来发现，局部规划里启发函数应该用欧几里得距离，因为它更符合局部空间的几何特性。

17.3 全局与局部的协同

全局规划和局部规划不是孤立的，它们需要协同工作。我画了一张图来说明这个关系：

从这张图可以看出：全局规划先生成一条参考路径，然后局部规划沿着这条路径往前走，同时根据传感器数据实时调整。如果局部规划发现前方有障碍物无法通过，它会反馈给全局规划，请求重新规划。

这里有个关键点：反馈的时机。我建议不要一遇到障碍就重新全局规划，那样计算量太大。可以设置一个阈值，比如局部规划尝试3次都失败，再触发全局重规划。

17.4 实际项目中的坑与对策

做了这么多年AGV，我踩过的坑不少。挑几个典型的说说：

问题 现象 对策
路径锯齿 AGV走“之”字形，不流畅 在A星代价函数中加入转弯惩罚项
局部震荡 AGV在障碍物前反复横跳 增加局部规划的时间一致性约束
全局重规划频繁 AGV频繁停车等待 提高重规划触发阈值，增加局部绕行能力
地图更新延迟 AGV撞上已移除的障碍物 使用实时传感器数据更新局部地图

我的小技巧：在局部规划中，我会给路径加一个“时间戳”。如果某条路径在0.5秒内没有被更新，就认为它已经失效，强制重新规划。这样可以避免AGV使用过时的路径信息。

好了，关于A星在AGV中的应用，全局和局部规划就聊这么多。记住一句话：全局规划看方向，局部规划看细节。两者配合好了，你的AGV就能在复杂工厂里游刃有余。
