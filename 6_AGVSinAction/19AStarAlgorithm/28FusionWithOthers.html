28 A星算法与其他路径规划算法融合：混合A星、TEB、DWA

各位同学，今天我们来聊一个实战中绕不开的话题——A星算法怎么跟其他算法“组队”。

说实话，纯A星在AGV项目里很少单打独斗。为什么？因为A星本质上是全局规划，它假设环境是静态的、已知的。但真实工厂里，叉车在跑、人在走、货架在移动，你规划好的路径可能下一秒就被堵死了。所以，我们需要把A星和其他算法融合起来，取长补短。

我个人习惯把这种融合分成两类：一类是“改良派”，比如混合A星，它把A星从离散网格扩展到了连续空间；另一类是“组合派”，比如A星+TEB、A星+DWA，让全局规划负责方向，局部规划负责避障。今天我们就逐个拆解。

28.1 混合A星：从离散到连续的跨越

先说说混合A星（Hybrid A Star）。这个名字你可能听过，但很多人以为它只是A星加了个平滑处理。其实不是。

传统A星在网格上搜索，每个节点代表一个格子，运动方向只有上下左右（或者加上对角线）。但AGV是差速驱动或阿克曼转向的，它不能原地掉头，也不能走直角弯。你想想看，A星规划出一条“锯齿状”路径，AGV根本没法执行。

混合A星的核心改进在于：节点不再是一个格子，而是一个状态（x, y, θ）。θ是航向角。搜索时，它用车辆的运动学模型（比如Reeds-Shepp曲线或Dubins曲线）来生成候选路径段，而不是简单的网格邻接。

关键区别：

  • 传统A星：节点 = 网格坐标，运动 = 离散方向
  • 混合A星：节点 = (x, y, θ)，运动 = 连续曲线

我在项目中遇到过一个问题：混合A星的搜索空间比传统A星大得多。因为θ是连续的，你不可能枚举所有角度。通常的做法是离散化θ，比如每10度一个采样。但离散太粗会丢失可行路径，太细又导致搜索爆炸。嗯，这里要注意，θ的离散粒度直接影响路径质量和计算时间，需要根据车辆的最小转弯半径来调。

下面是一个简化的混合A星伪代码，帮你理解核心逻辑：

def hybrid_a_star(start, goal, grid, vehicle_model):
    open_set = PriorityQueue()
    open_set.put(start, 0)
    came_from = {}
    g_score = {start: 0}
    
    while not open_set.empty():
        current = open_set.get()
        
        if distance(current, goal) < threshold:
            return reconstruct_path(came_from, current)
        
        # 关键：用运动学模型生成候选动作
        for steering_angle in [-max_steer, 0, max_steer]:
            for velocity in [forward_speed, reverse_speed]:
                # 模拟一小段运动，得到新状态
                new_state = vehicle_model.simulate(current, steering_angle, velocity, dt)
                
                # 碰撞检测
                if grid.is_collision(new_state):
                    continue
                
                # 计算代价（包含转向代价、倒车惩罚等）
                cost = g_score[current] + motion_cost(current, new_state)
                
                if new_state not in g_score or cost < g_score[new_state]:
                    g_score[new_state] = cost
                    # 启发式使用Reeds-Shepp距离
                    f_score = cost + reeds_shepp_distance(new_state, goal)
                    open_set.put(new_state, f_score)
                    came_from[new_state] = current
    
    return None

注意最后一行：启发式函数用的是Reeds-Shepp距离，而不是欧氏距离。这是混合A星能保证路径可执行的关键。我曾经踩过坑，直接用欧氏距离做启发式，结果搜索出来的路径虽然短，但车辆根本转不过去——因为忽略了最小转弯半径。

避坑指南：混合A星的启发式必须考虑运动学约束。如果你用欧氏距离，搜索会倾向于走直线，但实际车辆需要转弯，导致扩展节点过多。建议用Reeds-Shepp距离或Dubins距离，虽然计算稍慢，但能大幅减少无效搜索。

28.2 A星 + TEB：全局引导下的局部优化

接下来聊TEB（Timed Elastic Band）。这个名字听起来玄乎，说白了就是“带时间戳的橡皮筋”。

TEB的核心思想是：把路径看作一根有弹性的带子，通过优化带子的形状来满足避障、速度、加速度等约束。它本身是一个局部规划器，但如果没有全局指引，它容易陷入局部最优。

所以，常见的做法是：A星提供全局路径作为“参考线”，TEB在这条参考线附近做局部优化。

具体流程是这样的：

  1. A星规划出一条从起点到终点的全局路径（离散点序列）
  2. TEB以全局路径为初始解，构建一个带时间戳的路径（每个点关联一个到达时间）
  3. TEB通过图优化（比如g2o或Ceres）调整路径点和时间，最小化代价函数

代价函数通常包含这几项：

  • 路径跟随代价：偏离全局路径的惩罚
  • 避障代价：与障碍物的距离惩罚
  • 动力学代价：速度、加速度、转弯速率限制
  • 时间代价：希望尽快到达终点

我记得有一次做仓储AGV项目，现场有大量窄通道。纯A星规划的路径在通道正中间，但TEB优化时发现通道两侧有货架突出，于是自动把路径往中间偏了10厘米，同时降低了通过速度。这就是融合的价值——A星保证“能到”，TEB保证“能安全到”。

注意：TEB的优化是实时的，但计算量不小。如果全局路径太长（比如超过100个点），建议先对全局路径做稀疏化处理，只保留关键转折点。否则TEB的优化矩阵会变得很大，影响实时性。

28.3 A星 + DWA：动态窗口里的快速决策

最后说说DWA（Dynamic Window Approach）。这个算法在机器人领域很经典，它的思路是：在速度空间里采样，找到一条无碰撞且能最快到达目标的速度指令。

DWA的优点是反应快，适合动态环境。但缺点也很明显——它只看眼前几步，容易“迷路”。比如遇到一个U形障碍物，DWA可能直接冲进去然后困在里面。

这时候就需要A星来“指路”。具体做法是：

  1. A星规划全局路径
  2. DWA的代价函数里加入“朝向全局路径”的项
  3. DWA在局部避障的同时，尽量沿着全局路径走

DWA的代价函数通常长这样：

cost = w1 * heading_cost + w2 * clearance_cost + w3 * velocity_cost

其中：

  • heading_cost：当前朝向与目标方向的偏差（目标方向来自全局路径的下一个关键点）
  • clearance_cost：与最近障碍物的距离（越远越好）
  • velocity_cost：希望保持较高速度

当加入A星后，heading_cost不再指向最终目标，而是指向全局路径上的“前瞻点”。这个前瞻点距离当前位姿多远？我一般取3-5米，或者根据车速动态调整。车速快时前瞻远一点，车速慢时近一点。

我曾经在项目里试过只用DWA，结果AGV在货架区里来回打转，因为DWA每次只看到眼前1米，找不到出口。后来加上A星全局路径作为引导，问题就解决了。说白了，A星是“战略层”，DWA是“战术层”，两者缺一不可。

28.4 三种融合方案的对比

为了让你更直观地理解，我整理了一个对比表格：

融合方案 适用场景 优点 缺点 我推荐的使用条件
混合A星 狭窄通道、停车场、需要精确轨迹 路径可执行、考虑运动学 计算量大、不适合动态环境 低速、高精度场景（如仓储AGV）
A星 + TEB 半动态环境、有障碍物移动 实时优化、平滑轨迹 依赖全局路径质量、参数多 中等速度、需要避障的场景
A星 + DWA 动态环境、快速响应 反应快、计算轻量 局部最优、前瞻距离难调 高速、障碍物频繁出现的场景

最后说一句：没有最好的算法，只有最合适的组合。我见过有人把混合A星和DWA串起来用——先用混合A星规划一条运动学可行的路径，再用DWA做局部避障。效果不错，但计算开销也大。具体怎么选，还是要看你的AGV跑在什么场景、对实时性要求多高。
