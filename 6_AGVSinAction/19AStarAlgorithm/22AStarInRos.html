22 A星算法在ROS中的实现：nav_core接口、global_planner插件

好，咱们今天聊点实在的。

前面讲了那么多A星的理论、优化、工程技巧，但很多朋友会问：这些东西在ROS里到底怎么落地？说白了，你怎么让机器人真正跑起来？

我个人习惯，先搞清楚ROS的导航框架是怎么组织的。你想想看，ROS Navigation Stack是一个庞大的体系，它把路径规划分成了几个层次。而A星算法，就藏在global_planner这个插件里。

nav_core接口：插件的“身份证”

在ROS里，所有全局路径规划器都必须实现nav_core::BaseGlobalPlanner这个接口。这不是可选项，是强制要求。

为什么？因为ROS的move_base节点只认这个接口。你写的算法再牛，不实现这个接口，move_base就不搭理你。

核心接口定义：

namespace nav_core {
  class BaseGlobalPlanner {
    public:
      virtual bool makePlan(
        const geometry_msgs::PoseStamped& start,
        const geometry_msgs::PoseStamped& goal,
        std::vector<geometry_msgs::PoseStamped>& plan
      ) = 0;
      
      virtual void initialize(
        std::string name, 
        costmap_2d::Costmap2DROS* costmap_ros
      ) = 0;
  };
}

嗯，这里要注意。接口只有两个纯虚函数：initialize和makePlan。前者是初始化，传入代价地图；后者是核心，输入起点和终点，输出一条路径。

我在项目中遇到过，有人自己写了个规划器，但忘了实现initialize，结果运行时直接崩溃。这种坑，踩一次就记住了。

global_planner插件：A星的“新家”

ROS官方其实已经提供了一个global_planner包，里面默认实现了A星和Dijkstra。但说实话，那个实现比较基础，很多优化都没做。

我个人建议，如果你做产品级AGV，最好基于这个框架自己写一个插件。为什么？因为你可以控制每一个细节。

插件注册示例：

#include <pluginlib/class_list_macros.h>
#include <global_planner/planner_core.h>

PLUGINLIB_EXPORT_CLASS(global_planner::GlobalPlanner, nav_core::BaseGlobalPlanner)

这行宏是必须的，它告诉ROS：我这个类是一个插件，可以动态加载。

核心流程：从代价地图到路径

咱们拆解一下makePlan里到底发生了什么。我习惯把它分成三步：

  1. 获取代价地图数据：从costmap_ros拿到二维栅格地图，每个格子有代价值（0-255）。
  2. 运行A星搜索：在代价地图上执行A星算法，找到从起点到终点的最优路径。
  3. 路径平滑与输出：对原始路径做插值、平滑，转换成PoseStamped格式输出。

你可能会问：代价地图里的代价值怎么用？

嗯，这里有个关键点。ROS的代价地图把障碍物标记为254（致命障碍），未知区域标记为255，自由空间是0。但A星算法不能直接用这些值，因为254和255会让启发式函数失效。

避坑指南：

我曾经在项目里直接用了原始代价值，结果A星在障碍物边缘疯狂绕圈。后来发现，需要把致命障碍的代价值设成一个很大的数（比如1e6），而不是254。这样启发式函数才能正常工作。

代码实战：一个精简的A星插件

下面是我写的一个简化版，只保留了核心逻辑。你可以在global_planner包的基础上修改。

bool GlobalPlanner::makePlan(
  const geometry_msgs::PoseStamped& start,
  const geometry_msgs::PoseStamped& goal,
  std::vector<geometry_msgs::PoseStamped>& plan
) {
  // 1. 获取代价地图
  unsigned int start_x, start_y, goal_x, goal_y;
  costmap_->worldToMap(start.pose.position.x, start.pose.position.y, start_x, start_y);
  costmap_->worldToMap(goal.pose.position.x, goal.pose.position.y, goal_x, goal_y);
  
  // 2. 初始化A星搜索
  std::priority_queue<Node, std::vector<Node>, CompareNode> open_list;
  std::vector<std::vector<bool>> closed_list(height_, std::vector<bool>(width_, false));
  
  // 3. 主循环
  while (!open_list.empty()) {
    Node current = open_list.top();
    open_list.pop();
    
    if (current.x == goal_x && current.y == goal_y) {
      // 找到路径，回溯
      return extractPath(current, plan);
    }
    
    // 扩展邻居节点
    for (int dx = -1; dx <= 1; dx++) {
      for (int dy = -1; dy <= 1; dy++) {
        if (dx == 0 && dy == 0) continue;
        // 检查障碍物、边界、closed_list
        // 计算g值和h值
        // 加入open_list
      }
    }
  }
  
  return false; // 没找到路径
}

这段代码我故意省略了一些细节，比如代价计算、启发式函数。因为每个项目对代价的敏感度不一样。有的场景要避开障碍物，有的场景要尽量走直线，你得自己调。

配置与调参：让A星真正跑起来

插件写好了，怎么让它被ROS加载？你需要一个plugin.xml文件和一个launch文件。

<!-- plugin.xml -->
<library path="lib/libmy_global_planner">
  <class type="my_planner::MyGlobalPlanner" 
         base_class_type="nav_core::BaseGlobalPlanner">
    <description>My custom A* planner</description>
  </class>
</library>

然后在launch文件里指定：

<param name="base_global_planner" value="my_planner/MyGlobalPlanner"/>

嗯，这里有个小技巧。我习惯在initialize函数里读取一些动态参数，比如启发式函数的权重、是否使用八方向搜索。这样不用重新编译，改个yaml文件就行。

关键参数建议：

参数名 默认值 说明
use_dijkstra false 是否使用Dijkstra（A星的特例）
use_quadratic true 是否使用二次代价函数
heuristic_factor 1.0 启发式权重，越大越贪心
allow_unknown true 是否允许通过未知区域

我曾经在一个仓库AGV项目里，把heuristic_factor设成了1.2，结果路径总是贴着墙走。后来发现，权重太大导致A星忽略了实际代价，路径虽然短但很危险。调回1.0就好了。

总结一下

ROS里的A星实现，说白了就是三件事：实现接口、注册插件、配置参数。但真正让算法跑得稳、跑得快，还得靠你对代价地图的理解和参数调优的经验。
