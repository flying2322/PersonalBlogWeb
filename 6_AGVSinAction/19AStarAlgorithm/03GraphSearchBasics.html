3 图搜索基础——DFS、BFS与Dijkstra算法原理

各位同学，今天我们来聊聊图搜索。说实话，很多做AGV路径规划的朋友，一上来就盯着A*算法看，结果调参调到怀疑人生。我当年也是这么过来的——后来才发现，真正理解DFS、BFS和Dijkstra，才是打好地基的关键。

你想想看，A*算法本质上就是Dijkstra加了个启发式函数。如果连Dijkstra都没吃透，那A*的G值和H值怎么权衡，你心里肯定没底。所以这一章，咱们把这三个基础算法彻底讲明白。

3.1 图的基本概念

先简单回顾一下图是什么。图由节点（Node）和边（Edge）组成。在AGV场景里，节点就是地图上的位置点，边就是可通行的路径。

图分两种：

  • 有向图：边有方向，比如AGV只能单向行驶的通道
  • 无向图：边没有方向，双向通行

还有一种叫加权图，每条边带一个权重。在AGV里，权重可以是距离、时间、能耗，甚至风险系数。我个人习惯把权重统一设为时间，因为AGV调度最关心的就是时效。

核心概念：搜索算法要解决的核心问题，就是「从起点到终点，找一条路径」。至于找得快不快、路径好不好，就看算法怎么遍历图了。

3.2 深度优先搜索（DFS）

DFS的思路很简单：一条路走到黑，撞了南墙再回头。

具体做法是：从起点出发，沿着一条边一直往下走，直到走不动了（没有未访问的邻居），然后回溯到上一个节点，换一条路继续走。

3.2.1 DFS的伪代码

function DFS(start, goal):
    stack = [start]
    visited = set()
    
    while stack is not empty:
        current = stack.pop()
        if current == goal:
            return path
        
        for neighbor in current.neighbors:
            if neighbor not in visited:
                visited.add(neighbor)
                stack.push(neighbor)
    return None

注意这里用的是栈（Stack），后进先出。这就是DFS能「一条路走到黑」的原因。

3.2.2 DFS的特点

特性 说明
完备性 有限图里能找到解，但可能不是最优解
时间复杂度 O(V+E)，V是节点数，E是边数
空间复杂度 O(V)，最坏情况要存所有节点
适用场景 拓扑排序、连通性检测、迷宫求解

避坑指南：我曾经在AGV调度系统里用DFS做路径搜索，结果地图稍微大一点，算法就跑了几分钟还没出结果。为什么？因为DFS会盲目地往深处钻，如果目标节点在浅层，它反而要绕一大圈。所以DFS不适合做AGV的实时路径规划。

3.3 广度优先搜索（BFS）

BFS和DFS正好相反。它是层层推进，像水波一样扩散。

从起点开始，先访问所有距离为1的节点，再访问距离为2的节点，以此类推。直到找到目标节点。

3.3.1 BFS的伪代码

function BFS(start, goal):
    queue = [start]
    visited = set()
    parent = {}
    
    while queue is not empty:
        current = queue.pop(0)
        if current == goal:
            return reconstruct_path(parent, start, goal)
        
        for neighbor in current.neighbors:
            if neighbor not in visited:
                visited.add(neighbor)
                parent[neighbor] = current
                queue.append(neighbor)
    return None

这里用的是队列（Queue），先进先出。所以BFS会先处理离起点近的节点。

3.3.2 BFS的特点

特性 说明
完备性 能找到解，且是步数最少的解（无权图）
时间复杂度 O(V+E)
空间复杂度 O(V)，需要存储所有已访问节点
适用场景 无权图的最短路径、社交网络分析

我的经验：BFS在AGV里有个很实用的场景——当所有路径的代价都相同时（比如网格地图），BFS能找到最短路径。但一旦引入权重（比如不同路面的摩擦系数不同），BFS就失效了。这时候就得请出Dijkstra。

3.4 Dijkstra算法

Dijkstra算法是BFS的升级版。它解决了加权图的最短路径问题。

核心思想：维护一个「当前最短距离」表，每次从未处理的节点中选一个距离最小的，然后更新它的邻居。

3.4.1 Dijkstra的伪代码

function Dijkstra(start, goal):
    dist = {node: INF for node in graph}
    dist[start] = 0
    pq = [(0, start)]  // 优先队列
    parent = {}
    
    while pq is not empty:
        current_dist, current = pq.pop()
        if current == goal:
            return reconstruct_path(parent, start, goal)
        
        if current_dist > dist[current]:
            continue
        
        for neighbor, weight in current.neighbors:
            new_dist = dist[current] + weight
            if new_dist < dist[neighbor]:
                dist[neighbor] = new_dist
                parent[neighbor] = current
                pq.push((new_dist, neighbor))
    return None

注意这里用了优先队列（Priority Queue），每次取出距离最小的节点。这就是Dijkstra比BFS聪明的地方——它知道先处理「最有希望」的节点。

3.4.2 Dijkstra的特点

特性 说明
完备性 能找到解，且是加权图的最短路径
时间复杂度 O((V+E)logV)，使用二叉堆优化
空间复杂度 O(V)
适用场景 加权图的最短路径、网络路由、AGV路径规划

重要提醒：Dijkstra要求所有边的权重必须是非负的。如果有负权边，算法会陷入死循环。我在实际项目中遇到过这个问题——有一次地图里设置了「下坡路」的负权重，结果Dijkstra跑出来的路径完全不对。后来改用Bellman-Ford才解决。

3.6 实际应用中的选择建议

说了这么多理论，咱们来点实际的。在AGV路径规划里，到底该用哪个？

  • 地图很小（几十个节点）：用DFS就够了，简单粗暴
  • 地图中等（几百个节点），所有路径代价相同：BFS是最佳选择，能找到最短路径
  • 地图大（几千个节点），路径有不同权重：必须用Dijkstra，或者它的升级版A*

我的建议：如果你刚开始做AGV项目，先用Dijkstra打底。等跑通了，再考虑优化成A*。我见过太多人一上来就搞A*，结果启发式函数设计不好，反而比Dijkstra还慢。基础打牢了，后面才能飞得起来。

3.7 本章小结

这一章我们讲了三个基础搜索算法：

  • DFS：深度优先，用栈，适合探索
  • BFS：广度优先，用队列，适合无权图最短路径
  • Dijkstra：最小代价优先，用优先队列，适合加权图最短路径

这三个算法是图搜索的基石。下一章我们会看到，A*算法就是在Dijkstra的基础上加了一个启发式函数，让搜索更有方向感。但如果你连Dijkstra都没搞明白，那A*的调参绝对会让你头疼。
