16 动态环境下的A星：动态障碍物处理、重规划策略

各位同学，咱们今天聊点实战的。

前面几章讲的A星算法，说白了都是在静态地图上跑。但现实中的AGV哪有那么舒服？仓库里有人走动、有叉车临时停靠、有货物突然掉落——这些动态障碍物才是真正的拦路虎。

我记得刚入行那会儿，给一个电商仓库做AGV调度。第一次测试时，AGV按照静态路径跑得稳稳当当，结果一个理货员推着推车横穿通道，AGV直接傻在原地，疯狂报错。嗯，从那以后我就明白——动态环境下的路径规划，才是真正考验算法工程师功底的地方。

动态障碍物的本质

先搞清楚一个问题：动态障碍物到底分几种？

我个人习惯把它们分成三类：

  • 可预测的动态障碍物：比如AGV车队里的其他车辆，它们的运动轨迹是已知的，或者可以通过通信获取。说白了，就是“自己人”。
  • 半可预测的动态障碍物：比如传送带上的货物、旋转的机械臂。运动规律固定，但AGV没法直接跟它们通信。
  • 不可预测的动态障碍物：人、叉车、掉落的箱子。这些家伙想怎么走就怎么走，AGV只能靠传感器实时感知。

你想想看，这三种障碍物，处理方式能一样吗？肯定不能。

核心原则：能预测的提前避让，不能预测的实时响应。

动态A星的核心思路

传统的A星算法，假设地图是静态的。一旦障碍物动了，它规划的路径可能瞬间变成死路。怎么办？

我给大家画个图，看看动态A星的整体流程：

这个流程其实不复杂。AGV先跑一遍静态A星，然后边走边用传感器（激光雷达、视觉、超声波）更新环境信息。一旦发现路径上有新障碍物，就触发重规划。

动态障碍物处理的三种策略

我在项目中试过好几种方法，最后沉淀下来三种比较实用的策略：

策略一：局部重规划（Local Replanning）

这是最直接的方法。当AGV发现前方有障碍物时，只重新规划当前位置到目标点的一小段路径。

具体怎么做？

  • 把AGV当前位置作为起点
  • 把原路径上障碍物后方的第一个节点作为临时目标点
  • 在这个局部区域内跑A星

我曾经在一个项目里踩过坑——局部重规划的范围设得太小，结果AGV绕了半天绕不出去。后来我总结了一个经验：局部范围至少是AGV车身长度的3倍，这样才有足够的转弯空间。

小技巧：局部重规划时，可以把障碍物周围的栅格代价临时调高，而不是直接设为不可通行。这样AGV会尽量远离障碍物，而不是贴着边绕过去。

策略二：D* Lite算法

D* Lite是动态A星的经典变种。它的核心思想是：只更新受障碍物影响的那部分路径，而不是从头跑一遍A星。

我给大家看一段伪代码，理解一下它的精髓：

// D* Lite 核心逻辑
function DStarLite(start, goal, map):
    // 初始化
    g = infinity for all nodes
    rhs = infinity for all nodes
    rhs[goal] = 0
    
    // 从目标点反向搜索
    queue.insert(goal, calculateKey(goal))
    
    while queue is not empty:
        current = queue.pop()
        if current == start:
            break
        
        // 更新当前节点的邻居
        for each neighbor of current:
            new_cost = g[current] + cost(current, neighbor)
            if new_cost < g[neighbor]:
                g[neighbor] = new_cost
                queue.update(neighbor, calculateKey(neighbor))
    
    // 当检测到障碍物变化时
    function onObstacleDetected(changed_cells):
        for each cell in changed_cells:
            updateCost(cell)  // 更新代价
            // 只更新受影响的节点
            for each neighbor of cell:
                queue.update(neighbor, calculateKey(neighbor))

你看，D* Lite聪明的地方在于——它从目标点反向搜索，这样当障碍物出现时，只需要更新受影响的那一小块区域。效率比重新跑A星高得多。

注意：D* Lite虽然高效，但实现起来比A星复杂。如果你的AGV计算资源有限，或者动态障碍物出现频率不高，用局部重规划反而更简单可靠。

策略三：时间窗法（Time Window）

这个方法特别适合多AGV协同的场景。说白了，就是给每个AGV规划一条带时间戳的路径。

举个例子：

时间 AGV-1位置 AGV-2位置 冲突检测
t=0 (1,1) (3,3) 无冲突
t=1 (2,2) (2,2) 冲突！
t=2 (3,3) (1,1) 无冲突

当检测到t=1时刻两个AGV会撞上时，有两种处理方式：

  • 让AGV-1在(1,1)等待1个时间单位
  • 或者给AGV-2重新规划一条绕行的路径

我个人比较喜欢用等待策略——简单、可靠、计算量小。但要注意，等待时间不能太长，否则会影响整体效率。

重规划策略的选择指南

说了这么多，到底该用哪种策略？我给大家一个参考：

场景 推荐策略 原因
单AGV，偶尔遇到人 局部重规划 实现简单，够用
多AGV协同 时间窗法 避免死锁
障碍物频繁变化 D* Lite 效率高，不用每次都重跑
计算资源紧张 局部重规划 计算量最小

避坑指南

最后，分享几个我踩过的坑：

  • 不要频繁重规划：我曾经犯过一个错误——传感器每更新一次就触发重规划。结果AGV像喝醉了酒一样左右摇摆。后来我加了死区，只有当障碍物距离小于某个阈值时才触发重规划。
  • 注意路径平滑：重规划出来的路径往往有尖角，直接让AGV走会急停急转。我习惯在重规划后加一个平滑处理，用B样条曲线把路径捋顺了。
  • 保留历史路径：如果重规划失败（比如障碍物把路堵死了），可以回退到上一个安全位置，重新规划。这个机制救过我很多次。

嗯，动态环境下的A星就讲到这里。说白了，核心就两件事——快速感知变化，高效重新规划。具体怎么选，看你的场景和资源。

一句话总结：静态A星是基础，动态A星才是实战。别怕踩坑，每个坑都是经验。
