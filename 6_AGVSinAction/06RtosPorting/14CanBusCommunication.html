14 CAN总线通信：CAN控制器初始化、CAN报文收发、CANopen协议栈移植

各位同学，咱们今天聊CAN总线。

做AGV控制器，CAN总线是绕不开的坎。电机驱动器、激光雷达、IO模块，十有八九都挂在CAN总线上。我最早接触CAN是在一个仓储AGV项目上，当时被CANopen协议栈折腾得够呛，后来摸透了，发现其实就那么回事。

14.1 CAN控制器初始化——别小看这步

CAN控制器初始化，说白了就是让硬件准备好干活。我习惯把初始化拆成三步：

  1. 引脚配置——把GPIO复用到CAN功能
  2. 波特率设置——这个最容易翻车
  3. 工作模式选择——正常模式还是环回模式

先看一段我常用的初始化代码，基于STM32的bxCAN：

void CAN_Init(void)
{
    CAN_HandleTypeDef hcan;
    
    // 1. 使能时钟
    __HAL_RCC_CAN1_CLK_ENABLE();
    __HAL_RCC_GPIOB_CLK_ENABLE();
    
    // 2. 引脚配置：PB8-CAN_RX, PB9-CAN_TX
    GPIO_InitTypeDef gpio = {0};
    gpio.Pin = GPIO_PIN_8 | GPIO_PIN_9;
    gpio.Mode = GPIO_MODE_AF_PP;
    gpio.Pull = GPIO_PULLUP;
    gpio.Speed = GPIO_SPEED_FREQ_HIGH;
    gpio.Alternate = GPIO_AF9_CAN1;
    HAL_GPIO_Init(GPIOB, &gpio);
    
    // 3. CAN参数配置
    hcan.Instance = CAN1;
    hcan.Init.Prescaler = 6;          // 分频系数
    hcan.Init.Mode = CAN_MODE_NORMAL; // 正常模式
    hcan.Init.SyncJumpWidth = CAN_SJW_1TQ;
    hcan.Init.TimeSeg1 = CAN_BS1_13TQ;
    hcan.Init.TimeSeg2 = CAN_BS2_2TQ;
    hcan.Init.TimeTriggeredMode = DISABLE;
    hcan.Init.AutoBusOff = ENABLE;
    hcan.Init.AutoWakeUp = DISABLE;
    hcan.Init.AutoRetransmission = ENABLE;
    hcan.Init.ReceiveFifoLocked = DISABLE;
    hcan.Init.TransmitFifoPriority = DISABLE;
    
    HAL_CAN_Init(&hcan);
}
⚠️ 注意：波特率计算别想当然。我见过有人直接把Prescaler设成1，结果总线死活不通。记住公式：
波特率 = 时钟频率 / (Prescaler × (BS1 + BS2 + 1))
比如72MHz时钟，Prescaler=6，BS1=13，BS2=2，算出来就是：
72M / (6 × (13+2+1)) = 72M / 96 = 750kbps

14.2 CAN报文收发——核心中的核心

CAN报文收发，其实就两个动作：发出去，收进来。但细节都在过滤器里。

14.2.1 发送报文

发送一个标准帧，我习惯这么写：

uint8_t CAN_SendMessage(uint32_t id, uint8_t *data, uint8_t len)
{
    CAN_TxHeaderTypeDef txHeader;
    uint32_t txMailbox;
    
    txHeader.StdId = id;          // 标准ID，11位
    txHeader.ExtId = 0;           // 扩展ID不用
    txHeader.IDE = CAN_ID_STD;    // 标准帧
    txHeader.RTR = CAN_RTR_DATA;  // 数据帧
    txHeader.DLC = len;           // 数据长度
    txHeader.TransmitGlobalTime = DISABLE;
    
    // 发送，等待邮箱空闲
    if (HAL_CAN_AddTxMessage(&hcan, &txHeader, data, &txMailbox) != HAL_OK)
    {
        return 1; // 发送失败
    }
    
    // 等待发送完成
    while (HAL_CAN_GetTxMailboxesFreeLevel(&hcan) < 3);
    
    return 0;
}

这里有个坑——发送优先级。CAN控制器有三个发送邮箱，优先级由ID决定，ID越小优先级越高。我曾在项目里遇到电机控制指令被低优先级的诊断报文堵住，后来把电机指令ID设成0x001，问题就解决了。

14.2.2 接收报文与过滤器

接收报文，过滤器是关键。CAN总线上的报文很多，你只关心其中一部分。过滤器就是帮你筛选的。

我常用的过滤器配置：

void CAN_FilterConfig(void)
{
    CAN_FilterTypeDef filter;
    
    filter.FilterBank = 0;           // 使用过滤器组0
    filter.FilterMode = CAN_FILTERMODE_IDMASK;  // 掩码模式
    filter.FilterScale = CAN_FILTERSCALE_32BIT; // 32位
    filter.FilterIdHigh = 0x0000;    // 标准ID高16位
    filter.FilterIdLow = 0x0000;     // 标准ID低16位
    filter.FilterMaskIdHigh = 0x0000; // 掩码高16位
    filter.FilterMaskIdLow = 0x0000; // 掩码低16位
    filter.FilterFIFOAssignment = CAN_FILTER_FIFO0; // 关联到FIFO0
    filter.FilterActivation = ENABLE;
    filter.SlaveStartFilterBank = 14;
    
    HAL_CAN_ConfigFilter(&hcan, &filter);
}
💡 我的经验：调试阶段，把掩码全设成0，这样所有报文都能收到。等调通了再收紧过滤器。我曾经一上来就设了严格的过滤器，结果报文收不到，排查了半天才发现是过滤器把想要的报文也滤掉了。

14.3 CANopen协议栈移植——从零到跑通

CANopen，说白了就是CAN总线上的应用层协议。它定义了设备如何描述自己、如何通信。AGV控制器里，电机驱动器、IO模块几乎都支持CANopen。

我移植过几个协议栈，最顺手的是CANopenNode。开源、轻量、文档全。移植步骤我总结为四步：

  1. 硬件抽象层对接——把协议栈的发送/接收函数挂到你的CAN驱动上
  2. 对象字典配置——定义你的设备有哪些参数、命令
  3. PDO/SDO配置——决定数据怎么传
  4. NMT状态机管理——设备启动、停止、预操作

14.3.1 硬件抽象层对接

CANopenNode要求你实现几个底层函数。我一般这么写：

// CAN发送回调
void canSend(CAN_MSG *msg)
{
    CAN_SendMessage(msg->id, msg->data, msg->len);
}

// CAN接收回调（在中断中调用）
void canReceive(uint32_t id, uint8_t *data, uint8_t len)
{
    CAN_MSG msg;
    msg.id = id;
    msg.len = len;
    memcpy(msg.data, data, len);
    
    // 喂给协议栈
    CO_CANinterrupt(&canopenObj, &msg);
}

14.3.2 对象字典配置

对象字典是CANopen的灵魂。每个设备都有一个对象字典，描述了所有参数。比如电机驱动器的目标速度在0x6040，实际速度在0x6041。

我习惯用Excel管理对象字典，然后生成C代码。一个典型的条目：

// 对象字典条目：0x2000 - 自定义参数
{
    .Index = 0x2000,
    .SubIndex = 0x00,
    .ObjectType = OD_VAR,
    .DataType = OD_UNSIGNED32,
    .AccessType = O_RW,
    .pData = &customParam,
    .attribute = ODA_SDO_RW
}

🔑 关键点：对象字典的索引范围有规定：

  • 0x1000-0x1FFF：通信对象（如设备类型、错误寄存器）
  • 0x2000-0x5FFF：制造商特定对象（你自定义的参数放这里）
  • 0x6000-0x9FFF：标准设备行规（如DS402电机驱动）

14.3.3 PDO配置——实时通信的关键

PDO（过程数据对象）用于实时数据交换。比如电机驱动器每10ms发送一次实际速度，这就是一个TPDO（发送PDO）。

我常用的PDO映射：

// TPDO1：电机状态反馈
// 映射：0x6041（状态字）+ 0x6064（实际位置）+ 0x606C（实际速度）
{
    .Index = 0x1800,    // TPDO1通信参数
    .SubIndex = 0x02,   // 传输类型
    .Value = 0xFE       // 事件触发（数据变化就发）
},
{
    .Index = 0x1A00,    // TPDO1映射参数
    .SubIndex = 0x00,   // 映射数量
    .Value = 3          // 映射了3个对象
},
{
    .Index = 0x1A00,
    .SubIndex = 0x01,
    .Value = 0x60410010 // 0x6041，子索引0，16位
},
{
    .Index = 0x1A00,
    .SubIndex = 0x02,
    .Value = 0x60640020 // 0x6064，子索引0，32位
},
{
    .Index = 0x1A00,
    .SubIndex = 0x03,
    .Value = 0x606C0010 // 0x606C，子索引0，16位
}
⚠️ 注意：PDO映射的总长度不能超过8字节。上面这个例子：16位+32位+16位=64位=8字节，刚好塞满一帧。我曾经贪心多映射了一个对象，结果数据被截断，排查了好久才发现是PDO长度超了。

14.5 避坑指南

最后，分享几个我踩过的坑：

  • 终端电阻——CAN总线两端必须各加一个120Ω电阻。我见过有人只加了一个，结果总线反射严重，通信时好时坏。
  • 波特率一致性——总线上所有设备的波特率必须一致。差一点都连不上。我习惯用示波器量一下CAN_H和CAN_L的位时间，确认无误再上协议栈。
  • CANopen节点ID——每个设备必须有唯一的节点ID。我曾在调试时忘了改ID，两个电机驱动器ID都是1，结果总线冲突，一个都动不了。
  • 心跳报文——CANopen设备默认会发心跳报文。如果收不到心跳，主站会认为设备离线。我建议把心跳周期设成100ms，既不会太频繁占用总线，又能及时检测掉线。

嗯，CAN总线通信这块，说白了就是硬件配好、初始化做对、报文收发调通、协议栈移植跑起来。每一步都有坑，但摸透了就顺了。你们在实际项目中遇到什么问题，随时可以来问我。
