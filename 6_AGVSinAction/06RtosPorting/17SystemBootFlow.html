17 系统启动流程：从复位到main函数、硬件初始化顺序、RTOS启动与多任务创建

说实话，很多做嵌入式开发的朋友，写了几年代码，对系统启动流程还是一知半解。我刚开始做AGV控制器那会儿，也踩过不少坑。有一次，板子死活跑不起来，查了三天，最后发现是启动文件里中断向量表配置错了。嗯，从那以后，我养成了一个习惯——每次移植RTOS，第一件事就是把启动流程从头到尾捋一遍。

今天这一章，咱们就聊聊AGV控制器从复位到多任务运行的完整过程。说白了，就是芯片上电后，到底干了哪些事，才让我们的应用代码跑起来的。

17.1 复位后的第一行代码

芯片上电复位后，CPU会去固定地址取第一条指令。对于Cortex-M系列内核，这个地址是0x00000000，存放的是栈顶指针；0x00000004存放的是复位中断向量，指向复位处理函数。

我见过不少新手，以为main函数是程序的起点。其实不是。在main之前，系统已经干了一大堆活。你想想看，如果连堆栈都没初始化好，C语言代码怎么运行？

核心要点：复位后，CPU首先执行的是启动文件（startup_xxx.s）中的复位处理函数，而不是main函数。

启动文件里主要干了这几件事：

  • 设置堆栈指针（SP）
  • 初始化中断向量表
  • 调用SystemInit函数进行时钟配置
  • 初始化BSS段（清零）和DATA段（从Flash拷贝到RAM）
  • 调用C库的初始化函数
  • 最后跳转到main函数

我个人习惯，在SystemInit里把系统时钟、PLL、外设总线时钟都配好。这样进入main后，所有外设都能直接用了。

17.2 硬件初始化顺序

硬件初始化顺序，这个很有讲究。顺序搞反了，轻则功能异常，重则直接死机。我在AGV项目里总结了一套顺序，分享给你：

初始化阶段 具体内容 说明
第1步 时钟系统 配置系统时钟、PLL、外设时钟使能
第2步 GPIO基础 关键引脚初始化（如调试串口）
第3步 中断控制器 NVIC配置，中断优先级分组
第4步 定时器 系统滴答定时器（SysTick）
第5步 通信外设 UART、CAN、SPI、I2C等
第6步 存储外设 Flash、SRAM、外部存储器
第7步 电机驱动相关 PWM、编码器接口、电机控制逻辑
第8步 传感器 激光雷达、IMU、超声波等

注意：千万不要在时钟还没稳定之前就去操作外设寄存器。我曾经遇到过，在PLL锁定前就去配置UART，结果波特率完全不对，调试信息全是乱码。

17.3 RTOS启动流程

硬件初始化完成后，就该RTOS登场了。以FreeRTOS为例，启动流程大概是这样的：

int main(void)
{
    /* 1. 硬件初始化 */
    SystemInit();           // 时钟配置
    BoardInit();            // 板级初始化
    PeriphInit();           // 外设初始化
    
    /* 2. RTOS内核初始化 */
    prvInitializeTaskLists();   // 初始化任务链表
    prvInitializeTCB();         // 初始化任务控制块
    
    /* 3. 创建启动任务 */
    xTaskCreate(AppTaskStart, "Start", 512, NULL, 1, NULL);
    
    /* 4. 启动调度器 */
    vTaskStartScheduler();
    
    /* 正常情况下不会执行到这里 */
    while(1);
}

这里有个关键点：vTaskStartScheduler一旦调用，就不会返回了。它会做以下几件事：

  • 创建空闲任务（Idle Task）
  • 初始化系统滴答定时器
  • 设置PendSV和SVC中断
  • 启动第一个任务

嗯，这里要注意。启动调度器之前，一定要确保SysTick已经配置好了。否则RTOS没法进行时间片轮转，任务调度就乱套了。

17.4 多任务创建的艺术

多任务创建，说白了就是怎么把AGV控制器的各个功能模块，合理地分配到不同的任务里。我一般遵循几个原则：

  1. 实时性要求高的放高优先级——比如电机控制、急停处理
  2. 周期性的任务用定时器触发——比如传感器数据采集
  3. 非关键任务放低优先级——比如日志记录、状态显示

下面是一个典型的AGV控制器任务划分：

/* 任务优先级定义 */
#define PRIO_MOTOR_CTRL     5   // 电机控制（最高）
#define PRIO_SAFETY         4   // 安全监控
#define PRIO_SENSOR         3   // 传感器采集
#define PRIO_NAVIGATION     2   // 导航算法
#define PRIO_COMM           1   // 通信任务
#define PRIO_LOGGING        0   // 日志（最低）

/* 创建任务 */
xTaskCreate(MotorControlTask, "Motor", 256, NULL, PRIO_MOTOR_CTRL, NULL);
xTaskCreate(SafetyMonitorTask, "Safety", 128, NULL, PRIO_SAFETY, NULL);
xTaskCreate(SensorTask, "Sensor", 256, NULL, PRIO_SENSOR, NULL);
xTaskCreate(NavigationTask, "Nav", 512, NULL, PRIO_NAVIGATION, NULL);
xTaskCreate(CommTask, "Comm", 256, NULL, PRIO_COMM, NULL);
xTaskCreate(LoggingTask, "Log", 128, NULL, PRIO_LOGGING, NULL);

经验之谈：任务栈大小别抠得太死。我刚开始做AGV时，为了省内存，把每个任务的栈都压到最小。结果跑着跑着就栈溢出，系统随机死机。后来我学乖了，每个任务至少留30%的余量。

17.6 避坑指南

最后，分享几个我踩过的坑，希望能帮你少走弯路：

坑1：中断优先级分组不一致

我曾经在启动文件里设了一组优先级分组，在RTOS配置里又设了另一组。结果中断响应完全乱套，高优先级中断被低优先级中断抢占。后来统一在SystemInit里设置，再也没出过问题。

坑2：SysTick被其他定时器干扰

有一次，我为了省一个定时器，把SysTick用作PWM输出。结果RTOS的时间片轮转直接失效，所有任务都卡住了。记住，SysTick是RTOS的心跳，别乱动。

坑3：任务栈溢出检测没开

FreeRTOS提供了栈溢出检测功能，但默认是关闭的。我建议你在调试阶段一定要打开。方法很简单，在FreeRTOSConfig.h里设置：

#define configCHECK_FOR_STACK_OVERFLOW 2

这样一旦栈溢出，系统会调用vApplicationStackOverflowHook，你就能第一时间发现问题。
