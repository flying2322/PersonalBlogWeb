27 参数调优：任务优先级优化、栈空间大小调整、系统时钟节拍频率选择

各位同学，欢迎来到参数调优这一节。

说实话，RTOS移植完了能跑起来，只是第一步。真正让系统稳定、高效地运行，靠的是参数调优。这就像你组装了一台赛车，发动机能点火了，但能不能在赛道上跑出好成绩，还得看悬挂怎么调、轮胎气压多少、换挡时机怎么把握。

今天我们就来聊聊三个最关键的调优参数：任务优先级、栈空间大小、系统时钟节拍频率。这三个参数调好了，你的AGV控制器才能算得上是一个合格的实时系统。

27.1 任务优先级优化：别让高优先级饿死低优先级

任务优先级，说白了就是给每个任务排个队。谁重要谁先跑。

但这里有个坑——优先级反转。我在项目中遇到过，一个低优先级的任务拿着互斥锁不放，中优先级的任务一直抢CPU，结果高优先级的任务反而被卡住了。AGV在转弯时突然停下来，就是因为这个原因。

核心原则：

  • 实时性要求高的任务（如电机控制、急停处理）给最高优先级
  • 周期性任务（如传感器采集）给中等优先级
  • 后台任务（如日志记录、状态显示）给最低优先级

我个人习惯的做法是：先按功能分类，再按时间要求排序。比如AGV控制器里，我一般这样分配：

任务名称 优先级 说明
急停处理 最高（5） 必须立即响应，毫秒级延迟都不行
电机控制 高（4） 控制周期1ms，不能抖动
传感器采集 中（3） 10ms周期，允许少量抖动
路径规划 中低（2） 计算量大，但可以分步执行
日志记录 低（1） 有空就写，没空就丢

小技巧：不要把所有任务都挤在相邻的优先级上。留出一些空档，方便以后扩展。我曾经因为没留空档，加一个新功能时不得不重构整个优先级表，那叫一个痛苦。

27.2 栈空间大小调整：给多了浪费，给少了崩溃

栈空间，是每个任务私有的内存区域。函数调用、局部变量、中断嵌套，全都要用栈。

你想想看，如果栈空间给小了，任务一运行就栈溢出，系统直接崩溃。给大了呢？内存浪费。AGV控制器上内存本来就金贵，不能这么挥霍。

怎么确定栈大小？我一般用三步法：

  1. 估算：根据任务中最大的函数调用链深度，加上局部变量大小，再留30%余量
  2. 实测：在调试模式下运行，观察栈使用峰值
  3. 调整：根据实测数据，精确设置栈大小

举个例子，我之前调一个传感器采集任务，估算需要512字节。结果实测发现，峰值只用了不到300字节。嗯，这里要注意，不同运行场景下栈使用量可能不同。比如正常运行时和异常处理时，栈深度可能差很多。

避坑指南：我曾经因为栈空间给得太紧，AGV在连续急转弯时频繁死机。查了两天才发现，是路径规划任务在计算复杂路径时，递归调用深度超过了预期。从那以后，我每个任务都至少留50%的余量。

在FreeRTOS里，可以用uxTaskGetStackHighWaterMark()来查看栈剩余空间。我建议在调试阶段，每个任务都打印一下这个值：

// 在任务循环中定期检查栈使用情况
UBaseType_t uxHighWaterMark;
uxHighWaterMark = uxTaskGetStackHighWaterMark(NULL);
if(uxHighWaterMark < 100) {
    // 栈空间不足，需要调整
    printf("Warning: Task stack low, only %d bytes left\n", uxHighWaterMark);
}

27.3 系统时钟节拍频率选择：快有快的好，慢有慢的妙

系统时钟节拍，就是RTOS的心跳。每个心跳，调度器都会检查一次，看看要不要切换任务。

频率高了，任务切换更及时，实时性更好。但代价呢？CPU花在调度上的时间就多了。频率低了，CPU利用率高，但任务响应会变慢。

怎么选？我建议从两个角度考虑：

  • 任务的最小时间需求：如果你的电机控制需要1ms周期，那节拍频率至少得1000Hz
  • CPU的负载能力：节拍频率越高，调度开销越大。一般建议不超过CPU主频的1%

举个例子，AGV控制器用STM32F4，主频168MHz。我一般选1000Hz的节拍频率。为什么？因为电机控制周期是1ms，传感器采集是10ms，1000Hz刚好能满足需求，调度开销也只有0.6%左右，完全可以接受。

经验之谈：如果你用的是低端MCU，比如Cortex-M0，主频只有48MHz，那建议把节拍频率降到500Hz甚至100Hz。别为了追求实时性把CPU都耗在调度上了。

在FreeRTOS里，节拍频率通过configTICK_RATE_HZ配置：

// FreeRTOSConfig.h
#define configTICK_RATE_HZ    ((TickType_t)1000)  // 1000Hz，1ms一个节拍

这里有个细节要注意：节拍频率越高，vTaskDelay()的精度也越高。但如果你只是做简单的延时，没必要追求太高的精度。我见过有人把节拍频率设到10000Hz，结果CPU一半时间都在跑调度器，得不偿失。

27.4 三者之间的平衡

这三个参数不是孤立的。优先级影响任务的响应时间，栈空间影响任务的稳定性，节拍频率影响系统的整体实时性。

我一般这样调优：

  1. 先确定节拍频率，满足最紧急任务的时间需求
  2. 再分配优先级，确保关键任务能及时得到CPU
  3. 最后调整栈空间，保证每个任务都能稳定运行

调优是个迭代的过程。别指望一次就能调好。我每次做新项目，都要反复调个三五轮，才能找到最合适的参数组合。

最后说一句：参数调优没有标准答案。同样的参数，在不同的硬件平台、不同的应用场景下，效果可能天差地别。多测试、多观察、多总结，才是王道。

好了，参数调优就讲到这里。记住，调优不是一蹴而就的事，多动手、多测试，你的AGV控制器会越来越稳。
