23 路径规划任务：A*算法实现、全局路径规划、局部避障策略

路径规划，说白了就是让AGV知道「怎么走」。

我做了这么多年AGV控制器，见过太多车在车间里「原地打转」或者「撞墙」的案例。其实问题往往不在电机控制，而在路径规划没做好。今天我们就来聊聊这个核心话题。

23.1 全局路径规划：A*算法的RTOS实现

全局路径规划，就是给AGV画一张「大地图」，告诉它从A点到B点怎么走最省时间。我个人习惯用A*算法，因为它兼顾了效率和最优性。

在RTOS环境下实现A*，有几个坑要特别注意。

23.1.1 地图建模

首先，你得把物理空间转成计算机能理解的数据结构。我常用的是栅格地图。

/* 栅格地图结构体 */
typedef struct {
    uint8_t grid[MAP_HEIGHT][MAP_WIDTH];  /* 0:空闲, 1:障碍, 2:未知 */
    uint16_t width;
    uint16_t height;
    float resolution;  /* 每个栅格代表的实际尺寸（米） */
} GridMap_t;

嗯，这里要注意：分辨率不能太高，否则内存吃不消。我在一个项目中试过0.01米的分辨率，结果一个100平米的车间，光地图就占了1MB多——这在MCU上根本跑不动。后来我改成0.05米，内存占用降了25倍，精度也够用。

23.1.2 A*核心算法

A*的核心公式很简单：F = G + H。但实现起来，细节决定成败。

/* A*节点 */
typedef struct {
    uint16_t x, y;
    float g;  /* 起点到当前点的实际代价 */
    float h;  /* 当前点到终点的估计代价 */
    float f;  /* g + h */
    struct AStarNode *parent;
    uint8_t state;  /* 0:未处理, 1:在open列表, 2:在close列表 */
} AStarNode_t;

我建议用最小堆来管理open列表，而不是简单的数组。为什么？因为每次取最小F值的节点时，数组需要O(n)的遍历时间，而最小堆只需要O(log n)。

关键优化点：

  • 使用预分配的节点池，避免动态内存分配
  • 启发函数H用曼哈顿距离（允许四方向移动）或欧几里得距离（允许八方向）
  • 设置最大迭代次数，防止死循环

23.1.3 RTOS任务设计

路径规划不能阻塞主控制循环。我通常把它设计成一个独立任务。

void PathPlanningTask(void *param) {
    GridMap_t *map = (GridMap_t *)param;
    PathResult_t result;
    
    while(1) {
        /* 等待路径请求信号量 */
        xSemaphoreTake(pathRequestSem, portMAX_DELAY);
        
        /* 执行A*算法 */
        result = AStarSearch(map, startPoint, endPoint);
        
        /* 发送结果到控制任务 */
        xQueueSend(pathResultQueue, &result, 0);
        
        /* 任务休眠，让出CPU */
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

我曾经在一个项目里把路径规划任务的优先级设得太高，结果导致电机控制任务响应不及时，车在转弯时「抖」得厉害。后来我把优先级降到中等，问题就解决了。

23.2 局部避障策略：动态窗口法

全局路径规划假设地图是静态的。但现实世界哪有那么完美？

你想想看，车间里突然出现一个人，或者一个叉车临时停在了路上——这时候就需要局部避障了。

23.2.1 动态窗口法（DWA）原理

DWA的核心思想是：在速度空间里采样，找到一条既能避开障碍物、又能靠近目标点的轨迹。

/* DWA参数结构体 */
typedef struct {
    float v_min, v_max;      /* 线速度范围 */
    float w_min, w_max;      /* 角速度范围 */
    float v_resolution;      /* 线速度采样分辨率 */
    float w_resolution;      /* 角速度采样分辨率 */
    float predict_time;      /* 轨迹预测时间 */
} DWAConfig_t;

说白了，就是三步：

  1. 在速度空间里生成一组候选速度对 (v, w)
  2. 对每个速度对，模拟未来一段时间的轨迹
  3. 用评价函数选出最优轨迹

23.2.2 评价函数设计

评价函数一般包含三个子项：

子项含义权重
方位角偏差轨迹终点方向与目标方向的夹角0.5
障碍物距离轨迹上离最近障碍物的距离0.3
速度大小鼓励快速移动0.2

我的经验：权重不是固定的。在狭窄通道里，我会把障碍物距离的权重提到0.5以上；在开阔区域，我会提高速度权重。你可以设计一个动态权重调整机制。

23.2.3 与全局路径的融合

局部避障不能「放飞自我」。它必须受到全局路径的约束。

我常用的方法是：

  • 全局路径提供一系列子目标点
  • 局部规划器只负责从当前子目标到下一个子目标
  • 如果局部规划发现当前子目标被障碍物完全挡住，就向上层报告「路径不可达」，触发全局重规划

注意：不要频繁触发全局重规划！我曾经犯过这个错——AGV每次遇到小障碍就重新跑A*，结果CPU占用率飙升到90%，其他任务全被饿死了。正确的做法是：设置一个「重规划冷却时间」，比如5秒内最多重规划一次。

23.4 实际项目中的避坑指南

最后，分享几个我踩过的坑。

我曾经在一个项目中，A*算法跑出来的路径「贴墙走」。后来发现是启发函数H的权重设得太低了，导致算法过度探索。解决办法：把H的权重乘以一个系数1.2，路径就「居中」了。

我曾经在DWA的轨迹预测中，预测时间设了3秒。结果AGV在高速时预测轨迹太长，把远处的障碍物也算进来了，导致频繁减速。后来我把预测时间改成max(1.0, v * 0.5)，速度越快预测越远，问题解决。

嗯，路径规划这块内容确实不少。但只要你把全局规划和局部避障的接口设计好，剩下的就是调参和优化了。记住：没有万能的参数，只有不断调试的工程师。
