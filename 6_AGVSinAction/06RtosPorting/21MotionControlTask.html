21 AGV运动控制任务：差速驱动模型、PID控制算法实现、速度与位置闭环

各位好，我是老李。今天咱们聊点硬核的——AGV的运动控制。说实话，我当年第一次调AGV的时候，车在地上画龙，我在屏幕前画圈。后来才明白，差速模型和PID算法，这两样东西必须吃透。

AGV运动控制，说白了就是让车按照你想要的轨迹走。差速驱动是它的腿，PID算法是它的大脑。腿要稳，脑子要灵，车才能跑得顺。

差速驱动模型：AGV的“两条腿”

差速驱动，就是左右两个轮子独立驱动。通过控制两个轮子的转速差，实现前进、后退、转弯。我习惯把它想象成坦克的履带——左轮快右轮慢，车就往右转。

先看运动学模型。假设两个驱动轮间距为L，轮子半径为R。左轮转速ωL，右轮转速ωR。那么：

  • 前进速度v = (ωL + ωR) * R / 2
  • 旋转角速度ω = (ωR - ωL) * R / L
  • 转弯半径r = v / ω

嗯，这里要注意：当ωL = ωR时，车直线前进。当ωL = -ωR时，车原地旋转。我在项目中遇到过，有些新手把左右轮方向搞反了，结果车原地打转，还以为是电机坏了。

核心公式：

v = (ωL + ωR) * R / 2

ω = (ωR - ωL) * R / L

实际编码时，我们通常把目标速度v和角速度ω作为输入，反算出左右轮的目标转速：

// 差速模型逆解算
float L = 0.5;  // 轮距，单位米
float R = 0.1;  // 轮半径，单位米

void diff_drive_inverse(float v, float omega, float *wl, float *wr) {
    *wl = (v - omega * L / 2.0) / R;
    *wr = (v + omega * L / 2.0) / R;
}

你想想看，这个逆解算在RTOS里怎么跑？我一般把它放在运动控制任务里，每10ms执行一次。输入来自上层路径规划，输出给PID控制器。

PID控制算法：AGV的“小脑”

PID控制，比例、积分、微分。说白了就是：看现在差多少（P），看过去差了多少（I），预测未来会差多少（D）。

我刚开始做PID时，总觉得参数调起来很玄学。后来发现，其实有套路可循。先调P，让系统能响应；再加I，消除静差；最后加D，抑制超调。

看一个位置式PID的实现：

typedef struct {
    float Kp, Ki, Kd;
    float integral;
    float prev_error;
    float limit;
} PID_Controller;

float pid_update(PID_Controller *pid, float setpoint, float measurement) {
    float error = setpoint - measurement;
    
    // 比例项
    float p_out = pid->Kp * error;
    
    // 积分项，带限幅
    pid->integral += error;
    if (pid->integral > pid->limit) pid->integral = pid->limit;
    if (pid->integral < -pid->limit) pid->integral = -pid->limit;
    float i_out = pid->Ki * pid->integral;
    
    // 微分项
    float d_out = pid->Kd * (error - pid->prev_error);
    pid->prev_error = error;
    
    return p_out + i_out + d_out;
}

避坑指南：我曾经在积分项上吃过亏。积分限幅一定要做，否则积分饱和会让系统响应变得极其迟钝。还有，微分项对噪声敏感，建议先对测量值做低通滤波。

速度闭环与位置闭环

AGV控制通常分两层：内环是速度环，外环是位置环。速度环跑得快，位置环跑得稳。

速度闭环的目标是让电机实际转速跟上目标转速。我一般用编码器反馈，PID输出给电机驱动器。位置闭环则是在速度环的基础上，再加一层位置误差的PID。

看一个双环控制的伪代码：

// 10ms任务：位置环
void position_control_task(void) {
    float pos_error = target_position - current_position;
    float target_speed = position_pid_update(pos_error);
    // 限幅
    if (target_speed > MAX_SPEED) target_speed = MAX_SPEED;
    // 传给速度环
    set_speed_target(target_speed);
}

// 2ms任务：速度环
void speed_control_task(void) {
    float speed_error = target_speed - current_speed;
    float motor_output = speed_pid_update(speed_error);
    set_motor_pwm(motor_output);
}

为什么速度环要跑得更快？因为电机响应快，位置变化慢。速度环2ms更新一次，位置环10ms更新一次，这样系统既稳定又灵敏。我在项目中试过把速度环也放到10ms，结果车一加速就抖，跟得了帕金森似的。

实战中的坑与经验

讲几个我踩过的坑：

  1. 编码器方向搞反：左右轮编码器相位接反，导致速度反馈为负，PID疯狂输出，车直接冲出去。建议上电后先手动转轮子，确认编码器方向。
  2. 积分饱和：AGV被堵住时，积分项会一直累加。等障碍物移开，车会猛地冲出去。解决办法：积分限幅 + 条件积分（误差大时不积分）。
  3. 微分震荡：编码器信号有噪声时，微分项会放大噪声。我习惯在微分前加一个一阶低通滤波，截止频率设20Hz左右。

警告：PID参数不要在生产环境直接调。先在仿真环境里跑通，再上真车。我见过有人直接在AGV上调参数，结果车撞墙了，损失好几万。
