22 传感器融合任务：卡尔曼滤波实现、里程计与IMU数据融合、定位估计

各位同学，欢迎来到传感器融合这一章。

说实话，做AGV定位，单靠里程计或者单靠IMU，都挺不靠谱的。里程计有累计误差，跑久了就飘；IMU有零偏和噪声，积分出来的位置更是没法看。那怎么办？把两者融合起来。这就是我们今天要聊的——卡尔曼滤波。

22.1 为什么需要传感器融合？

我刚开始做AGV那会儿，就吃过这个亏。只用编码器做里程计，在平整地面上跑个十米还行，一上坡、一打滑，位置直接飞掉。后来加了IMU，想着互补一下，结果发现IMU的加速度积分，两秒钟就漂出天际。

说白了，每个传感器都有自己的短板。里程计短期准、长期飘；IMU高频响应好、但噪声大。融合的目的，就是取长补短。

核心思想：用IMU的高频数据填补里程计的更新间隙，用里程计的绝对位置约束IMU的漂移。

22.2 卡尔曼滤波——你只需要理解这几步

卡尔曼滤波听起来高大上，其实核心就五个公式。我习惯把它分成两个阶段：预测和更新。

22.2.1 预测阶段

这一步，我们用系统模型去猜下一时刻的状态。比如，已知上一时刻的位置和速度，我们就能估算出当前的位置。

// 状态预测
x_pred = A * x_est + B * u;
// 协方差预测
P_pred = A * P_est * A^T + Q;

这里的A是状态转移矩阵，Q是过程噪声协方差。Q设多大？我个人的经验是：如果你对模型很自信，Q设小一点；如果模型不准，Q设大一点。我在项目中遇到过，Q设太小，滤波器反应迟钝，跟不上实际运动。

22.2.2 更新阶段

有了预测值，再用观测值去修正。观测值就是传感器读到的数据。

// 卡尔曼增益
K = P_pred * H^T * (H * P_pred * H^T + R)^-1;
// 状态更新
x_est = x_pred + K * (z - H * x_pred);
// 协方差更新
P_est = (I - K * H) * P_pred;

卡尔曼增益K，说白了就是一个权重。如果观测噪声R小，K就大，我们更相信传感器；如果R大，K就小，我们更相信模型预测。

避坑指南：我曾经把R设得太小，结果传感器一有毛刺，滤波器就跟着乱跳。后来我学乖了，先跑一段静态数据，算一下传感器的方差，再用这个值去初始化R。

22.3 里程计与IMU数据融合实战

好，理论讲完了，我们来看看怎么在AGV上落地。

22.3.1 状态向量定义

我习惯用7维状态向量：

状态量 符号 说明
x位置 x 全局坐标系下的x坐标
y位置 y 全局坐标系下的y坐标
航向角 θ 机器人朝向
x方向速度 vx 全局坐标系下
y方向速度 vy 全局坐标系下
角速度 ω 航向角速度
IMU零偏 b_ω 角速度零偏

22.3.2 预测模型（IMU驱动）

IMU提供角速度和加速度。我们用IMU数据做预测更新，频率可以到100Hz甚至更高。

// 预测步骤（简化版）
void predict_imu(float dt, float gyro_z, float accel_x, float accel_y) {
    // 去除零偏
    float omega = gyro_z - state.b_omega;
    
    // 更新航向
    state.theta += omega * dt;
    
    // 从IMU加速度计算速度变化
    float ax_body = accel_x;
    float ay_body = accel_y;
    
    // 转换到全局坐标系
    float ax_global = ax_body * cos(state.theta) - ay_body * sin(state.theta);
    float ay_global = ax_body * sin(state.theta) + ay_body * cos(state.theta);
    
    // 更新速度和位置
    state.vx += ax_global * dt;
    state.vy += ay_global * dt;
    state.x += state.vx * dt;
    state.y += state.vy * dt;
    
    // 更新协方差（省略矩阵运算细节）
    update_covariance_prediction(dt);
}

注意：IMU的加速度包含重力分量。如果你用的IMU没有做重力补偿，记得在融合前减去重力。我曾经忘了这步，结果滤波器估计的位置一直在往下掉，排查了半天才发现。

22.4 定位估计——融合后的效果

融合之后，定位效果会有质的提升。我给大家画个图，看看融合前后的对比。

你看，纯里程计（红色）跑着跑着就偏了，尤其在转弯处。融合后（蓝色）基本贴着真实轨迹走。这就是卡尔曼滤波的功劳。

22.5 工程实现中的几个关键点

  1. 时间同步：IMU和里程计的时间戳必须对齐。我习惯在RTOS中用一个高精度定时器给所有传感器打时间戳。
  2. 坐标系统一：IMU的坐标系和里程计的坐标系可能不一样。记得做旋转矩阵转换。
  3. 异常值处理：传感器偶尔会出坏值。我一般在更新前加一个卡方检验，如果残差太大，就跳过这次更新。
  4. 初始化：启动时让AGV静止几秒钟，用这段时间估算IMU的零偏和噪声方差。

我的习惯：在调试阶段，我会把每个中间变量都打印出来。状态预测值、观测值、卡尔曼增益、残差……这样一旦出问题，一眼就能看出是预测不准还是观测有问题。

22.6 代码结构建议

在RTOS中，我通常把传感器融合做成一个独立任务。伪代码如下：

void sensor_fusion_task(void *arg) {
    kalman_filter_t kf;
    kalman_init(&kf);
    
    while(1) {
        // 等待IMU数据（100Hz）
        imu_data_t imu = imu_queue_receive(portMAX_DELAY);
        
        // 预测步骤
        kalman_predict(&kf, &imu, dt);
        
        // 检查是否有里程计数据
        odom_data_t odom;
        if (odom_queue_receive(&odom, 0) == pdTRUE) {
            // 更新步骤
            kalman_update(&kf, &odom);
        }
        
        // 输出融合后的位姿
        pose_t pose = kalman_get_pose(&kf);
        pose_queue_send(&pose, 0);
    }
}

嗯，这里要注意：IMU和里程计的数据频率不同，所以预测和更新的频率也不同。预测跑得快，更新跑得慢，这是正常的。

好了，这一章的内容就到这里。传感器融合是个实践性很强的活，光看理论没用，一定要动手调参数。你想想看，同样的代码，在不同AGV上跑，Q和R的取值可能完全不一样。这就是工程。

一句话总结：卡尔曼滤波不是魔法，它只是用统计的方法，把两个不完美的传感器，融合成一个更靠谱的定位结果。
