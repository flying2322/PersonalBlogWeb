13 AGV专用外设驱动：电机编码器接口、IMU数据读取、激光雷达数据解析

各位同学，今天咱们聊点硬核的。AGV（自动导引车）说白了就是个长了轮子的机器人，它得知道自己跑多快、往哪拐、周围有没有障碍物。这些信息从哪来？就靠三大件：电机编码器、IMU（惯性测量单元）、激光雷达（LiDAR）。

我在好几个AGV项目里都栽过跟头，尤其是编码器数据跳变和IMU零漂的问题。今天我把这些坑都给你们摆出来，咱们一个一个过。

13.1 电机编码器接口：速度与位置的“眼睛”

编码器装在电机屁股上，电机转一圈，它输出N个脉冲。我们通过脉冲数算位置，通过脉冲频率算速度。嗯，原理很简单，但实际写驱动时，细节多到让人头大。

13.1.1 编码器类型与接口

AGV上常用的编码器有两种：

  • 增量式编码器：输出A、B两相脉冲，相位差90度。正转A领先B，反转B领先A。我习惯用STM32的定时器编码器模式，硬件自动判向，省心。
  • 绝对值编码器：输出SSI或BiSS协议，一上电就知道绝对位置。适合需要掉电记忆位置的场景，但成本高。

接口方面，我建议用差分信号（RS-422），抗干扰能力强。车间里电机一启动，电磁干扰能把单端信号打成筛子。我曾经吃过这个亏，后来全部换成差分线，世界清净了。

13.1.2 驱动代码实现（以增量式编码器为例）

下面是我在FreeRTOS下写的一个编码器驱动框架。核心思路是：用定时器硬件捕获脉冲，然后通过一个任务周期性地读取计数值并换算成速度。

/* 编码器初始化 */
void encoder_init(void)
{
    /* 使能定时器时钟 */
    __HAL_RCC_TIM3_CLK_ENABLE();

    /* 配置TIM3为编码器模式 */
    TIM_Encoder_InitTypeDef sConfig = {0};
    sConfig.EncoderMode = TIM_ENCODERMODE_TI12;
    sConfig.IC1Polarity = TIM_ICPOLARITY_RISING;
    sConfig.IC2Polarity = TIM_ICPOLARITY_RISING;
    HAL_TIM_Encoder_Init(&htim3, &sConfig);

    /* 启动编码器 */
    HAL_TIM_Encoder_Start(&htim3, TIM_CHANNEL_ALL);
}

/* 速度计算任务 */
void vEncoderTask(void *pvParameters)
{
    int32_t last_count = 0;
    int32_t current_count = 0;
    float speed = 0.0f;

    for (;;)
    {
        current_count = __HAL_TIM_GET_COUNTER(&htim3);
        /* 计算速度：脉冲差 / 时间间隔 * 系数 */
        speed = (float)(current_count - last_count) / ENCODER_PULSE_PER_REV * 60.0f;
        last_count = current_count;

        /* 将速度值发送给控制任务 */
        xQueueSend(xSpeedQueue, &speed, 0);

        vTaskDelay(pdMS_TO_TICKS(100)); /* 100ms采样一次 */
    }
}
注意：编码器计数值会溢出！32位定时器转一圈就溢出了。我建议在任务里做溢出补偿，或者直接用32位变量累加。我曾经因为没处理溢出，AGV跑着跑着突然反向，差点撞墙。

13.2 IMU数据读取：姿态感知的“内耳”

IMU包含加速度计和陀螺仪。加速度计测重力方向，陀螺仪测角速度。两者融合，就能得到AGV的俯仰、横滚、航向角。

我常用的IMU是MPU6050或ICM-20948。接口用I2C，速率400kHz就够了。但要注意，IMU数据有噪声，尤其是陀螺仪的零漂。你想想看，AGV停着不动，陀螺仪输出却在缓慢变化，这怎么行？

13.2.1 数据读取与滤波

读取IMU数据，我一般用DMA + I2C，不占用CPU。然后做两步处理：

  1. 校准：上电后静止2秒，采集100个样本取平均，作为零偏值。
  2. 滤波：用互补滤波或卡尔曼滤波融合加速度计和陀螺仪数据。

下面是一个简单的互补滤波实现：

/* 互补滤波，alpha为权重系数，通常取0.98 */
float complementary_filter(float acc_angle, float gyro_rate, float dt, float *angle)
{
    *angle = 0.98f * (*angle + gyro_rate * dt) + 0.02f * acc_angle;
    return *angle;
}
我的经验：互补滤波的alpha值不是固定的。AGV震动大时，我调低alpha（更信任陀螺仪）；静止时调高alpha（更信任加速度计）。说白了，就是动态调整权重。

13.2.2 避坑指南：IMU安装位置

我曾经把IMU装在AGV底盘正中央，结果电机一启动，振动全传上来了。后来我改到靠近重心、用减震垫固定，数据干净多了。记住：IMU离电机越远越好，离振动源越远越好。

13.3 激光雷达数据解析：AGV的“眼睛”

LiDAR（激光雷达）通过发射激光束并测量反射时间，得到周围物体的距离和角度。AGV用它来做SLAM（同步定位与建图）和避障。

市面上常见的LiDAR有思岚A1/A2、镭神N10等。它们通常通过串口或以太网输出数据。我习惯用串口，简单可靠。

13.3.1 数据协议解析

以思岚A2为例，它的输出协议是：

  • 起始字节：0xFA
  • 数据长度：2字节
  • 数据包：包含角度、距离、置信度等信息
  • 校验和：1字节

解析时，我一般用状态机。为什么？因为串口数据可能断帧、粘包。状态机能优雅地处理这些问题。

/* LiDAR数据解析状态机 */
typedef enum {
    LIDAR_STATE_WAIT_HEADER,
    LIDAR_STATE_WAIT_LENGTH,
    LIDAR_STATE_WAIT_DATA,
    LIDAR_STATE_WAIT_CHECKSUM
} lidar_state_t;

lidar_state_t state = LIDAR_STATE_WAIT_HEADER;

void lidar_parse_byte(uint8_t byte)
{
    switch (state)
    {
        case LIDAR_STATE_WAIT_HEADER:
            if (byte == 0xFA)
                state = LIDAR_STATE_WAIT_LENGTH;
            break;

        case LIDAR_STATE_WAIT_LENGTH:
            /* 保存长度，进入数据接收 */
            data_len = byte;
            data_index = 0;
            state = LIDAR_STATE_WAIT_DATA;
            break;

        case LIDAR_STATE_WAIT_DATA:
            rx_buffer[data_index++] = byte;
            if (data_index >= data_len)
                state = LIDAR_STATE_WAIT_CHECKSUM;
            break;

        case LIDAR_STATE_WAIT_CHECKSUM:
            if (verify_checksum(rx_buffer, data_len, byte))
            {
                /* 数据有效，处理点云 */
                process_lidar_data(rx_buffer, data_len);
            }
            state = LIDAR_STATE_WAIT_HEADER;
            break;
    }
}
核心要点：LiDAR数据量大（一帧可能几百个点），解析任务要放在高优先级线程里。我一般给它分配一个独立任务，栈空间给足2KB，防止溢出。

13.3.2 点云数据的使用

解析出来的数据是极坐标（角度、距离）。要用于避障，得转成笛卡尔坐标：

/* 极坐标转笛卡尔坐标 */
void polar_to_cartesian(float angle_deg, float distance_mm, float *x, float *y)
{
    float rad = angle_deg * M_PI / 180.0f;
    *x = distance_mm * cosf(rad);
    *y = distance_mm * sinf(rad);
}

然后，把这些点放到一个二维数组里，做栅格地图。AGV看到前方1米内有障碍物，就减速或转向。嗯，逻辑不复杂，但实时性要求高。

13.4 本章知识体系总览

下面这张图，是我自己画的三大外设驱动的关系图。你看一眼，心里就有数了。

你看，编码器提供速度和位置，IMU提供姿态，LiDAR提供环境信息。三者融合，AGV才能知道自己在哪里、要去哪里、怎么去。

13.5 总结与个人心得

写这三个驱动，我最大的体会是：硬件接口是基础，数据处理是灵魂。编码器接口调通了，但速度算不准，AGV就抖得像筛糠；IMU数据读出来了，但滤波没做好，航向角就漂到天边；LiDAR数据解析对了，但实时性不够，避障就形同虚设。

我个人习惯，每写完一个驱动，先做单元测试。编码器用手转，看计数对不对；IMU放桌上静止，看角度稳不稳；LiDAR对着墙，看距离准不准。这一步省不了，省了后面调试更痛苦。

好了，这一章的内容就到这里。记住：外设驱动是RTOS移植的“最后一公里”，也是AGV能跑起来的基石。多动手，多踩坑，经验就是这么攒出来的。
