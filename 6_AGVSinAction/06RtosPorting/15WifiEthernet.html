15 Wi-Fi/以太网通信：LWIP协议栈移植、TCP/IP Socket编程、MQTT客户端实现

说到AGV控制器的网络通信，我脑子里第一个蹦出来的就是LWIP。这玩意儿在嵌入式圈子里，说白了就是轻量级TCP/IP协议栈的扛把子。你想想看，AGV要跟调度系统通信，要上报位置，要接收任务，没有网络怎么行？

我个人习惯把网络通信分成三层来看：底层是物理层，Wi-Fi或者以太网；中间是协议栈，LWIP负责把数据包拆了装、装了拆；上层就是应用层，Socket编程和MQTT协议。今天咱们就把这三层挨个捋一遍。

15.1 LWIP协议栈移植——从零开始跑通网络

LWIP移植，我做过不下十次了。每次换芯片平台，第一件事就是把LWIP跑起来。为什么？因为网络通了，调试效率能翻好几倍。

移植LWIP，核心就三个文件：lwipopts.h、cc.h、sys_arch.c。说白了，一个管配置，一个管数据类型，一个管操作系统适配。

核心要点：LWIP移植的关键在于底层接口的对接，特别是网卡驱动和操作系统抽象层。

15.1.1 网卡驱动对接

LWIP跟硬件打交道，靠的是netif结构体。你得实现四个函数：

  • low_level_init() —— 初始化MAC、PHY，设置MAC地址
  • low_level_output() —— 把LWIP封装好的数据包发出去
  • low_level_input() —— 从网卡收数据，交给LWIP
  • 中断处理函数 —— 收到数据包后通知LWIP来取

我在项目中遇到过一个问题：AGV在仓库里移动时，Wi-Fi信号会波动。一开始没做重传机制，结果丢包率高达30%。后来在驱动层加了重传和链路检测，才稳定下来。

我的经验：网卡驱动里，中断处理一定要快。收到数据包后，用netif->input()交给LWIP，不要在中断里做太多处理。否则实时性会崩。

15.1.2 操作系统适配层

LWIP支持多线程，但需要你提供几个基础接口：

接口 作用 我常用的实现方式
sys_mbox_new/free 消息邮箱，用于线程间通信 基于RTOS的消息队列
sys_sem_new/signal/wait 信号量，用于同步 基于RTOS的二进制信号量
sys_thread_new 创建LWIP内部线程 直接调用RTOS的线程创建函数
sys_arch_protect/unprotect 临界区保护 关中断或使用互斥锁

嗯，这里要注意：LWIP的sys_arch.c实现，直接决定了协议栈的稳定性。我曾经偷懒，信号量实现用了轮询方式，结果CPU占用率飙升到80%。后来改成阻塞等待，CPU占用率直接降到5%。

15.2 TCP/IP Socket编程——AGV的通信骨架

LWIP移植好了，接下来就是写应用代码。我个人偏爱用Socket API，因为它跟Linux下的网络编程几乎一模一样。你如果写过PC端的网络程序，上手LWIP的Socket API基本零成本。

15.2.1 TCP客户端——AGV上报位置

AGV通常作为TCP客户端，主动连接调度服务器。下面是我常用的代码模板：

int agv_tcp_client_init(void)
{
    int sock = -1;
    struct sockaddr_in server_addr;

    // 1. 创建Socket
    sock = socket(AF_INET, SOCK_STREAM, 0);
    if (sock < 0) {
        printf("Socket创建失败\n");
        return -1;
    }

    // 2. 设置服务器地址
    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons(8080);  // 调度服务器端口
    server_addr.sin_addr.s_addr = inet_addr("192.168.1.100");

    // 3. 连接服务器
    if (connect(sock, (struct sockaddr *)&server_addr, sizeof(server_addr)) < 0) {
        printf("连接失败\n");
        closesocket(sock);
        return -1;
    }

    // 4. 设置超时（防止网络卡死）
    struct timeval timeout = {5, 0};  // 5秒超时
    setsockopt(sock, SOL_SOCKET, SO_RCVTIMEO, &timeout, sizeof(timeout));

    return sock;
}

避坑指南：我曾经在AGV上没设置Socket超时，结果网络断开后，connect()和recv()直接卡死，AGV彻底失联。后来所有Socket都加了超时处理，再也没出过这个问题。

15.2.2 心跳机制——保持连接不断

AGV在车间里跑，Wi-Fi信号时好时坏。TCP连接看着还在，实际上可能早就断了。怎么办？加心跳包。

我一般这么设计：

  • AGV每3秒发一个心跳包，内容就一个字节：0xAA
  • 服务器收到后回复0xBB
  • 如果连续5次没收到回复，判定连接断开，主动重连

你想想看，这个机制简单吧？但效果特别好。AGV在仓库里跑一天，连接断个十几次都能自动恢复，调度系统完全无感。

15.3 MQTT客户端实现——轻量级通信的王者

TCP Socket虽然灵活，但你要自己处理协议格式、重连逻辑、消息路由。MQTT把这些都封装好了，说白了就是物联网界的HTTP协议。

为什么AGV要用MQTT？三个理由：

  1. 发布/订阅模型 —— 多台AGV可以同时订阅同一个主题，调度系统发一条消息，所有AGV都能收到
  2. QoS质量等级 —— 关键指令用QoS 1或2，保证不丢消息
  3. 遗嘱消息 —— AGV突然掉电，服务器能立刻知道，触发报警

15.3.1 MQTT客户端移植

嵌入式MQTT客户端，我常用的是Eclipse Paho MQTT C/C++客户端库。它跟LWIP配合得天衣无缝。

移植步骤很简单：

  • 把MQTTClient-C的源码加到工程里
  • 实现网络接口：MQTTClient_setCallbacks()里注册收发函数
  • 配置MQTT参数：Broker地址、客户端ID、用户名密码
// MQTT客户端初始化示例
void agv_mqtt_init(void)
{
    MQTTClient client;
    MQTTClient_connectOptions conn_opts = MQTTClient_connectOptions_initializer;
    int rc;

    // 1. 创建客户端
    MQTTClient_create(&client, "tcp://192.168.1.100:1883", 
                      "AGV_001", MQTTCLIENT_PERSISTENCE_NONE, NULL);

    // 2. 设置回调
    MQTTClient_setCallbacks(client, NULL, connlost_cb, msgarrvd_cb, delivered_cb);

    // 3. 配置连接参数
    conn_opts.keepAliveInterval = 20;    // 心跳间隔20秒
    conn_opts.cleansession = 1;          // 清除会话
    conn_opts.username = "agv_user";
    conn_opts.password = "agv_pass";

    // 4. 连接Broker
    rc = MQTTClient_connect(client, &conn_opts);
    if (rc != MQTTCLIENT_SUCCESS) {
        printf("MQTT连接失败，错误码：%d\n", rc);
        return;
    }

    // 5. 订阅主题
    MQTTClient_subscribe(client, "agv/001/cmd", 1);  // QoS 1
}

关键点：MQTT的keepAliveInterval一定要设置。我见过有人设成0，结果Broker以为客户端死了，把连接给踢了。AGV正在执行任务，突然断连，那叫一个尴尬。

15.3.2 主题设计——AGV通信的命名规范

MQTT的主题设计，直接决定了系统的可扩展性。我总结了一套AGV常用的主题命名规则：

主题 方向 说明
agv/{id}/status AGV → 服务器 上报位置、电量、状态
agv/{id}/cmd 服务器 → AGV 下发任务指令
agv/{id}/alarm AGV → 服务器 报警信息
agv/all/broadcast 服务器 → 所有AGV 全局广播，比如紧急停止

我个人习惯用{id}做通配符，这样新增AGV时，服务器端不用改任何代码。你想想看，车间里几十台AGV，每台都有自己的主题，管理起来多清爽。

15.4 实战经验总结——网络通信的坑与解

做了这么多年AGV控制器，网络通信这块踩过的坑，能写一本书。挑几个典型的说说：

关于Wi-Fi漫游：AGV在仓库里移动，会从一个AP切换到另一个AP。LWIP的TCP连接在切换时会断，怎么办？我的方案是：在应用层做自动重连，MQTT的自动重连机制正好用上。AGV检测到连接断开，自动重新连接并恢复订阅。

关于内存管理：LWIP默认的PBUF池大小是256字节，如果你要发大包（比如上传地图数据），会频繁分配大块内存，导致碎片。我建议根据实际数据量调整PBUF_POOL_SIZE和PBUF_POOL_BUFSIZE。AGV上报位置数据一般就几十字节，256够用；但上传日志文件时，我临时把池大小翻倍。

嗯，最后说一句：网络通信是AGV控制器的命脉。LWIP移植好了，Socket写对了，MQTT配通了，你的AGV才算真正活过来。调试时多用Wireshark抓包看看，很多问题一眼就能看出来。
