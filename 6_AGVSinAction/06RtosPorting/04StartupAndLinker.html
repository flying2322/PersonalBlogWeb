4 启动文件与链接脚本：芯片启动流程分析、链接脚本（.ld）编写、堆栈与中断向量表配置

各位同学，咱们今天聊点硬核的。启动文件和链接脚本，说白了就是芯片上电后第一口“奶”怎么喂，以及你的程序代码在内存里怎么摆。我当年刚接触RTOS移植时，觉得这玩意儿就是个模板，改改完事。结果有一次，芯片死活跑不起来，查了三天，最后发现是链接脚本里一个段地址没对齐。嗯，从那以后，我再也不敢小看这两兄弟了。

4.1 芯片启动流程：从复位到main()的“惊险一跃”

芯片上电后，CPU到底干了啥？你想想看，它连C语言环境都没有，怎么执行你的代码？

流程其实很清晰，我画了个图，你一看就懂：

你看，从复位到main()，其实就五步。但每一步都可能翻车。我个人习惯在Reset_Handler里加个LED闪烁，确认芯片确实跑起来了。这招在调试初期特别管用。

4.2 链接脚本（.ld）编写：给代码“安家落户”

链接脚本，说白了就是告诉链接器：你的代码放哪，数据放哪，堆栈放哪。没有它，编译器生成的.o文件就是一盘散沙。

我见过很多新手直接拿官方例程的.ld文件改都不改就用。结果RAM不够了，或者代码跑飞了，都不知道问题出在哪。我曾经在一个项目里，因为.ld文件里RAM的起始地址写错了，导致程序在中断里莫名其妙地死机。查了两天，最后发现是地址偏移了一个字节。

来，看一个典型的.ld文件结构：

/* 内存区域定义 */
MEMORY
{
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
    RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 128K
}

/* 段定义 */
SECTIONS
{
    /* 中断向量表：必须放在起始地址 */
    .isr_vector :
    {
        . = ALIGN(4);
        KEEP(*(.isr_vector))
        . = ALIGN(4);
    } > FLASH

    /* 代码段 */
    .text :
    {
        . = ALIGN(4);
        *(.text)
        *(.text*)
        *(.glue_7)
        *(.glue_7t)
        *(.rodata)
        *(.rodata*)
        . = ALIGN(4);
        _etext = .;
    } > FLASH

    /* 数据段：初始值在Flash，运行时在RAM */
    _sidata = .;
    .data : AT(_sidata)
    {
        . = ALIGN(4);
        _sdata = .;
        *(.data)
        *(.data*)
        . = ALIGN(4);
        _edata = .;
    } > RAM

    /* BSS段：未初始化数据 */
    .bss :
    {
        . = ALIGN(4);
        _sbss = .;
        *(.bss)
        *(.bss*)
        *(COMMON)
        . = ALIGN(4);
        _ebss = .;
    } > RAM

    /* 堆栈区域 */
    ._user_heap_stack :
    {
        . = ALIGN(8);
        PROVIDE ( end = . );
        PROVIDE ( _end = . );
        . = . + _Min_Heap_Size;
        . = . + _Min_Stack_Size;
        . = ALIGN(8);
    } > RAM
}

这里有几个关键点，我得跟你说道说道：

段名称 存放内容 存放位置 注意事项
.isr_vector 中断向量表 Flash起始地址 必须4字节对齐，用KEEP防止被优化掉
.text 代码+只读数据 Flash 包含.text和.rodata
.data 已初始化全局变量 运行时在RAM，初始值在Flash 需要从Flash拷贝到RAM
.bss 未初始化全局变量 RAM 启动时需清零
._user_heap_stack 堆和栈 RAM末尾 大小由_Min_Heap_Size和_Min_Stack_Size决定
我的小技巧： 在.ld文件里加个注释，记录每次修改的日期和原因。比如“2024-03-15: 堆栈从2K改为4K，因为任务栈溢出”。这习惯救过我很多次。

4.3 堆栈与中断向量表配置：别让细节毁了你的系统

堆栈和中断向量表，是启动文件里的两个“灵魂”。搞不好，系统连跑都跑不起来。

4.3.1 堆栈配置：多大才够？

这个问题，我几乎每次培训都会被问到。我的回答是：没有标准答案，但有个经验法则。

在RTOS环境下，每个任务都有自己的栈。但启动时的栈（我们叫它“主栈”或“中断栈”）是给中断服务程序和启动代码用的。我个人习惯这样算：

  • 最小栈：至少256字节，保证能处理嵌套中断
  • 推荐栈：1KB - 4KB，取决于中断嵌套深度和局部变量大小
  • 土豪栈：8KB以上，如果你有大量浮点运算或递归调用

我曾经在一个项目里，把栈设成了512字节，结果系统运行几个小时后就死机。查到最后，发现是一个中断服务函数里定义了一个512字节的局部数组，直接把栈给撑爆了。嗯，从那以后，我都在启动文件里加个栈溢出检测。

4.3.2 中断向量表配置：地址对齐是命根子

中断向量表，就是一张“函数指针表”。每个中断来了，CPU就去这张表里找对应的处理函数地址。

配置时，有几点你一定要注意：

  1. 地址必须对齐：对于Cortex-M系列，向量表必须按512字节对齐。不对齐？CPU直接跑飞。
  2. 第一项是栈顶指针：不是函数！很多新手在这里犯错，把第一项写成了函数地址。
  3. 第二项是复位向量：也就是Reset_Handler的地址。
  4. 其他中断按顺序排列：缺一个都不行，CPU会找不到入口。

看一个标准的向量表定义：

__Vectors:
    .word __initial_sp           /* 栈顶指针 */
    .word Reset_Handler          /* 复位向量 */
    .word NMI_Handler            /* NMI中断 */
    .word HardFault_Handler      /* 硬错误中断 */
    .word MemManage_Handler      /* 内存管理中断 */
    .word BusFault_Handler       /* 总线错误中断 */
    .word UsageFault_Handler     /* 用法错误中断 */
    .word 0                      /* 保留 */
    .word 0                      /* 保留 */
    .word 0                      /* 保留 */
    .word 0                      /* 保留 */
    .word SVC_Handler            /* SVC中断 */
    .word DebugMon_Handler       /* 调试监视中断 */
    .word 0                      /* 保留 */
    .word PendSV_Handler         /* PendSV中断 */
    .word SysTick_Handler        /* SysTick中断 */
    /* 外部中断从这里开始 */
    .word WWDG_IRQHandler        /* 窗口看门狗 */
    .word PVD_IRQHandler         /* PVD中断 */
    /* ... 后面还有几十个 */
警告： 如果你在RTOS环境下，记得把PendSV和SysTick的中断优先级设为最低。否则，你的任务调度可能会被高优先级中断“饿死”。我曾经见过一个项目，因为SysTick优先级设得太高，导致低优先级任务永远得不到执行。

4.4 实战：从零编写启动文件

光说不练假把式。咱们来手写一个最小启动文件，看看里面到底有啥：

.syntax unified
.cpu cortex-m4
.fpu softvfp
.thumb

/* 全局符号声明 */
.global __initial_sp
.global Reset_Handler
.global Default_Handler

/* 中断向量表 */
.section .isr_vector, "a", %progbits
.type __Vectors, %object
__Vectors:
    .word __initial_sp
    .word Reset_Handler
    .word Default_Handler     /* NMI */
    .word Default_Handler     /* HardFault */
    .word Default_Handler     /* MemManage */
    .word Default_Handler     /* BusFault */
    .word Default_Handler     /* UsageFault */
    .word 0                   /* 保留 */
    .word 0                   /* 保留 */
    .word 0                   /* 保留 */
    .word 0                   /* 保留 */
    .word Default_Handler     /* SVC */
    .word Default_Handler     /* DebugMon */
    .word 0                   /* 保留 */
    .word Default_Handler     /* PendSV */
    .word Default_Handler     /* SysTick */
__Vectors_End:

/* 复位处理函数 */
.section .text.Reset_Handler
.weak Reset_Handler
.type Reset_Handler, %function
Reset_Handler:
    /* 设置栈指针 */
    ldr sp, =__initial_sp

    /* 拷贝.data段 */
    ldr r0, =_sdata
    ldr r1, =_edata
    ldr r2, =_sidata
    movs r3, #0
    b LoopCopyDataInit

CopyDataInit:
    ldr r4, [r2, r3]
    str r4, [r0, r3]
    adds r3, r3, #4

LoopCopyDataInit:
    adds r4, r0, r3
    cmp r4, r1
    bcc CopyDataInit

    /* 清零.bss段 */
    ldr r0, =_sbss
    ldr r1, =_ebss
    movs r2, #0
    b LoopFillZerobss

FillZerobss:
    str r2, [r0]
    adds r0, r0, #4

LoopFillZerobss:
    cmp r0, r1
    bcc FillZerobss

    /* 跳转到main */
    bl main
    bx lr

/* 默认中断处理函数 */
.section .text.Default_Handler
.weak Default_Handler
.type Default_Handler, %function
Default_Handler:
    b Default_Handler

这段代码，我建议你一个字一个字地看。每个指令都有它的意义。比如那个b Default_Handler，就是个死循环。为什么？因为如果某个中断没实现，CPU就会卡在这里，方便你调试时发现。

核心要点总结：
  • 启动文件负责建立C运行环境，包括堆栈、数据段、BSS段
  • 链接脚本决定代码和数据的物理布局，必须与启动文件配合
  • 中断向量表必须4字节对齐，第一项是栈顶，第二项是复位向量
  • 堆栈大小要留余量，建议至少1KB起步
  • 所有未使用的中断都要有默认处理函数，防止意外触发

好了，关于启动文件和链接脚本，咱们就聊到这。这些东西看起来枯燥，但它们是整个系统的基石。你想想看，如果地基没打好，上面盖的房子再漂亮也没用。下次你移植RTOS时，记得先检查这两兄弟，能省下不少调试时间。
