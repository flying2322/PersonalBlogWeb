13 地图构建实战——使用ROS与Cartographer构建室内环境地图

好，到了真正动手的时候了。

前面我们聊了那么多理论，什么概率栅格、粒子滤波、图优化……说实话，光看公式确实有点枯燥。但今天不一样，今天我们要让机器人真正跑起来，把一张室内地图给“画”出来。

我个人习惯用Cartographer来做这件事。为什么？因为它稳定，而且对传感器要求没那么苛刻。你想想看，一个实验室里，不是每个人都有64线激光雷达的。Cartographer用2D激光雷达就能干出不错的活，这点很实在。

本章核心目标：用一台搭载2D激光雷达的移动机器人，在室内环境下，通过ROS + Cartographer实时构建出可用的栅格地图。

13.1 环境准备：别让工具坑了你

我记得第一次搭Cartographer的时候，光编译就折腾了大半天。嗯，这里要注意，版本问题最容易踩坑。

你需要准备的东西：

  • ROS版本：Melodic 或 Noetic（我建议用Noetic，支持周期更长）
  • Cartographer：官方ROS集成版（cartographer_ros）
  • 传感器：2D激光雷达（比如RPLIDAR A1/A2，或者Hokuyo系列）
  • 机器人平台：差速底盘，能发布/odom和/tf就行

安装Cartographer其实不复杂，但有几个坑我曾经踩过：

避坑指南：我曾经因为用了系统自带的protobuf版本，导致Cartographer编译报错。后来发现必须用wstool拉取指定版本的依赖。记住，别偷懒用apt-get install装protobuf，老老实实按官方教程走。

安装命令（简版）：

# 创建工作空间
mkdir -p ~/cartographer_ws/src
cd ~/cartographer_ws
wstool init src
wstool merge -t src https://raw.githubusercontent.com/cartographer-project/cartographer_ros/master/cartographer_ros.rosinstall
wstool update -t src

# 安装依赖
rosdep install --from-paths src --ignore-src --rosdistro=${ROS_DISTRO} -y

# 编译
catkin_make_isolated --install --use-ninja
source install_isolated/setup.bash

13.2 核心流程：一张图看懂Cartographer在干什么

说白了，Cartographer干的事就两件：局部匹配和全局优化。

局部匹配负责“当前这一帧激光跟上一帧怎么对齐”，全局优化负责“走了一圈回来发现门没对齐，赶紧修正”。

13.3 配置文件：调参才是真功夫

很多人以为装好Cartographer就能跑，其实不然。配置文件才是灵魂。我见过太多人拿着默认参数去跑，结果地图歪歪扭扭。

这里给出一份我常用的2D激光雷达配置（my_robot.lua）：

include "map_builder.lua"
include "trajectory_builder.lua"

options = {
  map_builder = MAP_BUILDER,
  trajectory_builder = TRAJECTORY_BUILDER,
  map_frame = "map",
  tracking_frame = "base_link",
  published_frame = "base_link",
  odom_frame = "odom",
  provide_odom_frame = true,
  publish_frame_projected_to_2d = false,
  use_odometry = true,
  use_nav_sat = false,
  use_landmarks = false,
  num_laser_scans = 1,
  num_multi_echo_laser_scans = 0,
  num_subdivisions_per_laser_scan = 1,
  num_point_clouds = 0,
  lookup_transform_timeout_sec = 0.2,
  submap_publish_period_sec = 0.3,
  pose_publish_period_sec = 5e-3,
  trajectory_publish_period_sec = 30e-3,
  rangefinder_sampling_ratio = 1.,
  odometry_sampling_ratio = 1.,
  fixed_frame_pose_sampling_ratio = 1.,
  imu_sampling_ratio = 1.,
  landmarks_sampling_ratio = 1.,
}

MAP_BUILDER.use_trajectory_builder_2d = true

TRAJECTORY_BUILDER_2D.submaps.num_range_data = 35
TRAJECTORY_BUILDER_2D.min_range = 0.3
TRAJECTORY_BUILDER_2D.max_range = 12.
TRAJECTORY_BUILDER_2D.missing_data_ray_length = 5.
TRAJECTORY_BUILDER_2D.use_imu_data = false
TRAJECTORY_BUILDER_2D.use_online_correlative_scan_matching = true
TRAJECTORY_BUILDER_2D.real_time_correlative_scan_matcher.linear_search_window = 0.1
TRAJECTORY_BUILDER_2D.real_time_correlative_scan_matcher.translation_delta_cost_weight = 1e-1
TRAJECTORY_BUILDER_2D.real_time_correlative_scan_matcher.rotation_delta_cost_weight = 1e-1

POSE_GRAPH.optimize_every_n_nodes = 90
POSE_GRAPH.constraint_builder.sampling_ratio = 0.3
POSE_GRAPH.constraint_builder.min_score = 0.55
POSE_GRAPH.constraint_builder.global_localization_min_score = 0.6

return options

调参小技巧：如果你发现地图出现重影，试着把submaps.num_range_data调小到25左右。如果发现闭环后地图突然跳变，把optimize_every_n_nodes调大到120，让优化更稀疏一些。

13.4 启动建图：让机器人动起来

配置写好了，接下来就是启动。我个人习惯把启动文件分成三层：

  1. 底层驱动层：启动激光雷达和底盘
  2. SLAM层：启动Cartographer
  3. 可视化层：启动RViz

启动命令大概长这样：

# 终端1：启动机器人底层
roslaunch my_robot_bringup robot.launch

# 终端2：启动Cartographer
roslaunch cartographer_ros my_robot.launch

# 终端3：启动RViz
roslaunch cartographer_ros demo_backpack_2d.launch
# 或者自己配置一个rviz文件加载

嗯，这里要注意，RViz的显示配置很重要。你至少要把Map、LaserScan、PoseArray这几个显示项加上去，不然你什么都看不到。

13.5 建图过程中的实战技巧

我记得第一次带学生做实验，有个同学推着机器人走太快，结果地图直接崩了。Cartographer虽然稳定，但也不是万能的。

建图时的几个要点：

  • 速度控制：别超过0.3m/s，转弯时更慢。你想想看，激光雷达一帧数据就那么多，走太快匹配就丢了。
  • 闭环策略：尽量走“8”字形路线，让机器人多次经过同一个区域。闭环越多，地图越准。
  • 光照影响：虽然激光雷达不怕暗，但如果你用了视觉辅助，注意光照均匀。
  • 地面材质：光滑地砖容易导致里程计打滑，这时候use_odometry = true反而会引入误差。我建议如果地面太滑，把里程计权重调低。

曾经踩过的坑：有一次在走廊建图，走到尽头掉头时，Cartographer突然把地图扭曲了。后来发现是走廊太窄（只有1.2米），激光点云特征太少，匹配失败。解决办法是加了一个短距离的超声波传感器做辅助，或者干脆走慢一点，让每一帧的重叠率更高。

13.6 保存地图：别白忙活一场

建完图之后，最重要的一步就是保存。我见过有人建了半小时的图，结果忘了保存，直接关终端……

保存命令很简单：

# 保存当前地图
rosservice call /write_state "{filename: '${HOME}/maps/my_office.pbstream'}"

# 如果需要导出为PGM/YAML格式（用于导航）
rosrun cartographer_ros cartographer_pbstream_to_ros_map \
  -pbstream_filename=${HOME}/maps/my_office.pbstream \
  -map_filestem=${HOME}/maps/my_office

这样你会得到三个文件：.pbstream（Cartographer原生格式）、.pgm（栅格图片）、.yaml（地图元信息）。

重要提醒：.pbstream文件包含了完整的位姿图信息，如果你以后想做地图编辑或者重优化，一定要保留这个文件。.pgm只是导出给导航用的“快照”。

13.7 常见问题与排查

最后，我把这些年遇到的高频问题整理成了一张表，你遇到问题可以先来这里翻翻：

现象 可能原因 解决办法
地图出现重影/双影 闭环检测没触发，或者子图数量太多 调小num_range_data，增加闭环检测频率
地图突然跳变 闭环优化时位姿图调整过大 调大optimize_every_n_nodes，让优化更平滑
建图过程中TF报错 odom到base_link的变换没发布 检查底盘驱动是否正常发布/tf
地图边缘模糊 激光雷达最大距离设置太小 调大max_range，但注意不要超过雷达实际量程
CPU占用过高 全局优化线程太频繁 调大optimize_every_n_nodes到150以上

好了，地图构建实战就讲到这里。Cartographer这套工具，说白了就是“配置调得好，地图建得早”。你多跑几次，多调几次参数，慢慢就有感觉了。

记住，建图不是一次就能成功的。我当年第一次建图，跑了五遍才拿到一张能用的地图。别怕失败，多试几次就好。
