24 ROS导航栈：move_base框架、costmap配置、导航行为树

说到ROS导航栈，我最早接触是在一个仓储AGV项目上。当时小车总在货架拐角处卡住，折腾了好几天才发现是costmap参数没调对。嗯，今天咱们就把move_base这套东西彻底捋清楚。

24.1 move_base框架：导航的大脑

move_base说白了就是ROS导航栈的调度中心。它接收目标点，然后协调全局路径规划和局部路径规划，最终输出速度指令给底盘。

我个人习惯把move_base拆成三个核心模块来看：

  • 全局规划器：负责从起点到终点的宏观路径，通常用A*或Dijkstra算法
  • 局部规划器：负责实时避障和轨迹跟踪，常用DWA或TEB算法
  • 恢复行为：当规划失败时，尝试旋转、后退等动作脱离困境

我在项目中遇到过一个问题：全局路径明明规划出来了，但小车就是不走。后来发现是base_global_planner和base_local_planner的参数没配对。你想想看，全局规划器输出的是路径点，局部规划器要的是速度指令，中间缺个转换层肯定不行。

核心要点：move_base的启动文件里，一定要确认planner的类型和参数文件路径。我见过太多人直接复制别人的launch文件，结果地图坐标系对不上，小车原地转圈。

24.2 costmap配置：地图的代价层

costmap是导航的"风险地图"。它把环境分成三种区域：自由空间、障碍物空间、膨胀空间。说白了，就是告诉机器人哪里能走，哪里不能走，哪里最好别走。

配置costmap时，我建议重点关注这几个参数：

参数名 作用 我的经验值
inflation_radius 障碍物膨胀半径 0.3~0.5米，视AGV宽度而定
cost_scaling_factor 代价衰减系数 10.0左右，太大容易卡死
observation_sources 传感器数据源 激光雷达+深度相机组合最稳
update_frequency 地图更新频率 5.0Hz够用，太高CPU扛不住

我曾经在一个仓库项目里，把inflation_radius设成了0.8米。结果AGV在货架通道里直接"自闭"了——因为膨胀后的障碍物把整个通道都堵死了。后来改成0.4米，配合cost_scaling_factor=8.0，小车才顺利通过。

避坑指南：我曾经把static_map和obstacle_layer的坐标系搞混了。静态地图用的是map坐标系，障碍物层用的是odom或base_link。如果两个坐标系对不上，costmap会显示一片空白。

24.3 导航行为树：决策的骨架

行为树是move_base的决策逻辑。它不像传统状态机那样写死，而是用树状结构组织各种行为。我刚开始觉得这东西花里胡哨，直到有一次需要修改导航逻辑——改状态机要动整个框架，改行为树只需要拖拽节点。

典型的导航行为树包含这些节点：

  • Sequence（顺序节点）：按顺序执行子节点，全部成功才算成功
  • Fallback（回退节点）：尝试第一个子节点，失败就尝试下一个
  • Action（动作节点）：执行具体行为，比如"规划路径"、"执行路径"
  • Condition（条件节点）：检查状态，比如"是否到达目标"、"是否被卡住"

举个例子，当AGV被障碍物挡住时，行为树会这样决策：

Fallback:
  Sequence:
    - 检查是否可重规划
    - 执行重规划
  Sequence:
    - 检查是否可旋转
    - 执行旋转避障
  Sequence:
    - 检查是否可后退
    - 执行后退
  - 报告导航失败

嗯，这里要注意：行为树的执行频率不能太高。我见过有人把tick_rate设成100Hz，结果CPU直接跑满。实际项目中10~20Hz就足够了。

注意事项：行为树的调试比较麻烦。我建议先在仿真环境里跑通，再上真车。否则一旦行为树卡死，AGV可能会一直原地旋转，直到电池耗尽。

24.4 实战配置示例

下面是我在一个AGV项目里用过的costmap配置，你可以参考：

global_costmap:
  global_frame: map
  robot_base_frame: base_link
  update_frequency: 5.0
  publish_frequency: 2.0
  static_map: true
  rolling_window: false
  resolution: 0.05
  plugins:
    - {name: static_layer, type: "costmap_2d::StaticLayer"}
    - {name: obstacle_layer, type: "costmap_2d::ObstacleLayer"}
    - {name: inflation_layer, type: "costmap_2d::InflationLayer"}

local_costmap:
  global_frame: odom
  robot_base_frame: base_link
  update_frequency: 10.0
  publish_frequency: 5.0
  static_map: false
  rolling_window: true
  width: 4.0
  height: 4.0
  resolution: 0.05
  plugins:
    - {name: obstacle_layer, type: "costmap_2d::ObstacleLayer"}
    - {name: inflation_layer, type: "costmap_2d::InflationLayer"}

这个配置里，全局地图用静态地图+障碍物层，局部地图用滚动窗口。我建议局部地图的宽度设为AGV长度的2~3倍，太小了来不及避障，太大了计算量爆炸。

个人经验：如果你用的是差速底盘，局部规划器推荐DWA。如果是全向轮，TEB更灵活。我踩过最大的坑就是底盘类型和规划器不匹配——差速底盘用TEB，结果原地打转出不来。
