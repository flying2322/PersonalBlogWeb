3 地图构建基础——地图类型与坐标变换

各位同学，今天我们来聊聊地图构建的底子。说实话，地图是AGV导航的灵魂。没有地图，AGV就是个瞎子。我在项目里见过太多人一上来就调路径规划，结果地图没建好，车跑得再快也是乱撞。

这一章，我们重点讲三件事：地图有哪些类型、坐标系怎么玩、坐标变换怎么算。嗯，都是基本功，但也是后面所有高级功能的地基。

3.1 地图类型：三种主流方案

AGV用的地图，说白了就三种：栅格地图、拓扑地图、特征地图。每种都有它的脾气，我一个个说。

3.1.1 栅格地图（Occupancy Grid Map）

这是最直观的一种。把环境切成一个个小格子，每个格子标记为“有障碍”或“无障碍”。就像像素画一样。

核心思想：用概率表示每个格子被占用的可能性。0表示空闲，1表示占用，0.5表示未知。

我个人习惯用栅格地图做室内导航。为什么？因为它简单、直观，激光雷达扫一圈，直接往格子里填概率就行。

优点：

  • 容易构建和维护
  • 适合路径规划（A*、Dijkstra直接跑）
  • 能表达任意形状的环境

缺点：

  • 存储量大（100m×100m，0.05m分辨率，就是400万个格子）
  • 对动态环境敏感
  • 精度受分辨率限制

我的经验：分辨率别设太高。0.05m够用了，再细就是浪费内存。我曾经有个项目，把分辨率设成0.01m，结果地图文件300MB，AGV加载都要半分钟。后来改成0.05m，效果差不多，文件只有30MB。

3.1.2 拓扑地图（Topological Map）

拓扑地图不关心具体尺寸，只关心“节点”和“边”。节点代表关键位置（比如路口、工位），边代表连通关系。

你想想看，地铁线路图就是典型的拓扑地图。它不告诉你站台有多宽、轨道有多长，只告诉你哪站能换乘。

优点：

  • 存储量极小
  • 适合大规模环境
  • 路径规划速度快

缺点：

  • 无法精确定位
  • 构建需要人工标注或额外算法
  • 对动态环境适应性差

注意：拓扑地图不能单独用于精确导航。我见过有人只用拓扑地图做AGV导航，结果车在走廊里走歪了也不知道。拓扑地图必须配合其他定位手段（比如二维码、UWB）才能用。

3.1.3 特征地图（Feature Map）

特征地图提取环境中的几何特征，比如墙、柱子、角点。它不存所有点，只存“有意义”的点。

举个例子：一个房间有四面墙、四个角、一根柱子。特征地图就存这9个特征，而不是几万个激光点。

优点：

  • 存储量适中
  • 适合做SLAM（特征匹配方便）
  • 对动态环境有一定鲁棒性

缺点：

  • 特征提取算法复杂
  • 在空旷环境（比如大仓库）特征太少
  • 对传感器质量要求高

选型建议：

  • 室内小场景（<1000m²）：栅格地图
  • 大场景（>10000m²）：拓扑地图+局部栅格地图
  • 需要SLAM：特征地图+栅格地图混合

3.2 坐标系：AGV的“世界观”

坐标系这东西，说白了就是给AGV一个“我在哪”的参考系。AGV导航里，我们至少需要三个坐标系。

3.2.1 世界坐标系（World Frame）

也叫全局坐标系。它是固定的，通常以地图原点为基准。所有物体的绝对位置都用世界坐标表示。

比如：仓库的东北角是(0,0)，货架A在(10, 5)，充电站在(20, 0)。

3.2.2 机器人坐标系（Robot Frame）

以AGV自身为原点。通常定义：车头方向为X轴正方向，左侧为Y轴正方向。

这个坐标系是动的。AGV往前走，坐标系也跟着走。

3.2.3 传感器坐标系（Sensor Frame）

激光雷达、摄像头、IMU都有自己的坐标系。它们相对于机器人坐标系有一个固定的偏移和旋转。

举个例子：激光雷达装在车头前方0.3米处，那它的坐标就是(0.3, 0, 0)（相对于机器人坐标系）。

避坑指南：我曾经犯过一个低级错误——把激光雷达的安装位置量错了5厘米。结果建出来的地图全是歪的，AGV定位偏差10厘米以上。后来花了整整两天排查，才发现是传感器外参标定出了问题。所以，安装参数一定要反复核对。

3.3 坐标变换：从传感器到世界

坐标变换，就是把一个坐标系下的点，换算到另一个坐标系下。AGV导航里，我们经常要做三件事：

  1. 把激光雷达的点云从传感器坐标系转到机器人坐标系
  2. 把机器人坐标系下的障碍物转到世界坐标系
  3. 把目标点从世界坐标系转到机器人坐标系

3.3.1 二维坐标变换公式

二维空间里，坐标变换就是旋转+平移。公式很简单：

// 点P在坐标系A下的坐标是(x_a, y_a)
// 坐标系A到坐标系B的变换：旋转θ，平移(tx, ty)
// 点P在坐标系B下的坐标：

x_b = x_a * cos(θ) - y_a * sin(θ) + tx
y_b = x_a * sin(θ) + y_a * cos(θ) + ty

嗯，其实就是旋转矩阵加上平移向量。我建议你把这个公式背下来，后面写代码天天用。

3.3.2 齐次坐标与变换矩阵

为了计算方便，我们通常用齐次坐标。把二维点(x, y)写成(x, y, 1)，变换就变成了矩阵乘法：

// 变换矩阵 T
// [cosθ  -sinθ  tx]
// [sinθ   cosθ  ty]
// [  0      0    1 ]

// 点P的齐次坐标
// [x]
// [y]
// [1]

// 变换后的坐标 = T * P

为什么用齐次坐标？因为可以把旋转和平移写在一个矩阵里，方便链式变换。比如：

// 传感器坐标 -> 机器人坐标 -> 世界坐标
T_world_sensor = T_world_robot * T_robot_sensor

核心要点：坐标变换的链式法则——从A到C的变换，等于从A到B的变换乘以从B到C的变换。顺序不能搞反，矩阵乘法不满足交换律。

3.3.3 实际应用：激光点云投影

我举个实际例子。激光雷达扫到一个点，距离2米，角度30度。怎么把它画到地图上？

// 1. 传感器坐标系下的坐标
float range = 2.0;  // 距离
float angle = 30.0 * M_PI / 180.0;  // 转弧度
float x_sensor = range * cos(angle);  // 1.732m
float y_sensor = range * sin(angle);  // 1.0m

// 2. 转到机器人坐标系（假设激光雷达装在车头前方0.3m）
float x_robot = x_sensor + 0.3;  // 2.032m
float y_robot = y_sensor;        // 1.0m

// 3. 转到世界坐标系（假设机器人当前位置(5, 3)，朝向45度）
float theta = 45.0 * M_PI / 180.0;
float x_world = x_robot * cos(theta) - y_robot * sin(theta) + 5.0;
float y_world = x_robot * sin(theta) + y_robot * cos(theta) + 3.0;

// 结果：这个激光点在世界坐标系下的位置
printf("世界坐标: (%.3f, %.3f)\n", x_world, y_world);

你看，三步变换，清清楚楚。我在写代码时，习惯把每一步的变换都封装成函数，这样不容易出错。

常见错误：

  • 角度单位搞混（度 vs 弧度）——我吃过这个亏，一次调试花了3小时
  • 变换顺序搞反——先旋转后平移，不是先平移后旋转
  • 忘记更新机器人位姿——AGV在动，坐标系也在动，每帧都要重新计算

这张图把本章的三个核心内容串起来了。地图类型决定了你用什么方式存环境信息，坐标系定义了参考基准，坐标变换则负责在不同参考系之间转换数据。这三者就像三脚架，缺一个，AGV导航就站不稳。

我的建议：学完这一章，你最好自己动手写一个小程序：

  1. 定义一个2D栅格地图（100×100，分辨率0.1m）
  2. 模拟一个激光雷达，在几个位置扫描
  3. 把扫描结果通过坐标变换投影到地图上
  4. 可视化显示结果

这个练习做完，你对地图构建的理解会上一个台阶。我当年就是这么学的。
