27 仿真环境搭建——Gazebo仿真、Stage仿真、仿真传感器配置

各位同学，今天我们来聊聊仿真环境搭建。说实话，我在做AGV导航系统初期，最头疼的就是调试环境。真车跑起来，撞一次墙就得修半天，传感器坏了更是心疼。后来我学乖了——先在仿真里跑通，再上真车。这个习惯，帮我省了至少一半的调试时间。

仿真环境说白了，就是给算法一个“安全沙盒”。你可以在里面随便折腾，撞了、翻了、传感器失灵了，重启一下就好。今天我们就来拆解两个最常用的仿真工具：Gazebo和Stage。

核心观点：仿真不是“玩具”，而是AGV开发中不可或缺的环节。一个好的仿真环境，能帮你发现80%以上的潜在问题。

一、Gazebo仿真：高保真的物理世界

Gazebo，我个人觉得它是目前ROS生态里最成熟的3D仿真器。它支持物理引擎、传感器模拟、甚至多机器人协同。我在做仓储AGV项目时，就是用Gazebo模拟了整排货架和巷道。

1.1 安装与启动

安装其实很简单，一条命令搞定：

sudo apt install ros-noetic-gazebo-ros-pkgs ros-noetic-gazebo-ros-control

启动时，我习惯先跑一个空世界看看环境：

roslaunch gazebo_ros empty_world.launch

嗯，这里要注意——如果你用的是虚拟机，记得给Gazebo分配至少2GB显存，否则画面会卡成PPT。我曾经在笔记本上跑Gazebo，结果风扇狂转，最后发现是显卡驱动没装好。

1.2 构建AGV模型

Gazebo里的机器人模型，用的是URDF（统一机器人描述格式）。说白了，就是一堆连杆和关节的XML描述。我给大家看一个简化版的AGV底盘模型：

<robot name="simple_agv">
  <link name="base_link">
    <visual>
      <geometry>
        <box size="0.5 0.3 0.1"/>
      </geometry>
    </visual>
    <collision>
      <geometry>
        <box size="0.5 0.3 0.1"/>
      </geometry>
    </collision>
  </link>
  <!-- 轮子部分省略 -->
</robot>

你想想看，这个模型虽然简单，但已经包含了碰撞检测和物理属性。Gazebo会基于这个模型计算摩擦力、惯性、甚至打滑效果。

1.3 仿真传感器配置

传感器是AGV的“眼睛”。Gazebo里最常用的传感器有激光雷达、IMU、摄像头。配置方式大同小异，我以激光雷达为例：

<sensor name="laser" type="ray">
  <ray>
    <scan>
      <horizontal>
        <samples>360</samples>
        <resolution>1</resolution>
        <min_angle>-3.14159</min_angle>
        <max_angle>3.14159</max_angle>
      </horizontal>
    </scan>
    <range>
      <min>0.1</min>
      <max>30.0</max>
    </range>
  </ray>
  <plugin name="gazebo_ros_laser" filename="libgazebo_ros_laser.so"/>
</sensor>

这里有个坑——samples参数决定了激光线的数量。360线看起来很美，但计算量很大。我建议调试时先用180线，跑通了再改回360。否则Gazebo会卡得让你怀疑人生。

小技巧：在Gazebo里调试传感器时，可以打开rosrun rqt_graph rqt_graph查看话题流。如果发现传感器数据没发布，八成是插件没加载成功。

二、Stage仿真：轻量级的2D替代方案

Stage跟Gazebo不一样，它是2D仿真器。说白了，就是俯视图，没有物理引擎，没有3D渲染。但它的优势也很明显——快！启动只要几秒钟，跑起来几乎不占CPU。

我个人习惯是：做路径规划、导航算法验证时用Stage；做传感器融合、物理交互测试时用Gazebo。各取所长。

2.1 Stage的安装与配置

安装同样简单：

sudo apt install ros-noetic-stage-ros

Stage的配置文件是.world格式。我给大家看一个典型的AGV测试场景：

define floorplan model
(
  size [20 20 1]
  boundary 1
  gui_nose 0
  gui_grid 0
  gui_move 0
  gui_outline 0
  gripper_return 0
  fiducial_return 0
  laser_return 1
)

define robot position
(
  size [0.5 0.3 0.2]
  drive "diff"
  laser_return 1
)

你想想看，这个配置里定义了地图大小、机器人尺寸、驱动方式。Stage会基于这些信息模拟激光雷达的扫描结果。

2.2 仿真传感器在Stage中的配置

Stage的传感器配置比Gazebo简单得多。它内置了激光雷达模型，你只需要在机器人定义里加上laser_return 1就行。但要注意，Stage的激光雷达是理想化的——没有噪声，没有多路径效应。所以你在Stage里跑通的算法，上真车后可能还需要微调。

我曾经犯过一个错误：在Stage里把导航参数调得完美无缺，结果一上真车，激光雷达数据全是噪点，定位直接崩了。从那以后，我学乖了——Stage只用来验证逻辑，不用来调参。

警告：Stage仿真中的传感器数据是“干净”的。如果你在Stage里调好了滤波器参数，上真车后一定要重新标定。否则，真实世界的噪声会让你措手不及。

四、实战建议与避坑指南

最后，我给大家总结几条实战经验：

  • 先Stage后Gazebo：我建议先用Stage跑通逻辑，再转到Gazebo做精细调试。这样效率最高。
  • 传感器参数要留余量：仿真里的传感器参数，上真车后通常要调低20%-30%。比如仿真里激光雷达能测30米，真车可能只能测20米。
  • 别忘了仿真时间：Gazebo默认是实时仿真，但如果你跑复杂场景，可以调慢仿真速度。用rosrun gazebo_ros gazebo --pause可以暂停仿真，方便调试。

避坑指南：我曾经在Gazebo里跑多机器人仿真，结果发现机器人之间互相“穿模”。后来才发现是碰撞检测没开。记得在URDF里加上<collision>标签，否则物理引擎不会生效。

好了，关于仿真环境搭建，今天就聊到这里。记住一句话：仿真不是万能的，但没有仿真，AGV开发就是盲人摸象。希望你们能善用这些工具，少走弯路。
