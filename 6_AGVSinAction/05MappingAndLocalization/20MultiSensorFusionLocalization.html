20 多传感器融合定位——GPS+IMU+LiDAR融合方案

各位好，今天我们来聊聊多传感器融合定位。说实话，这是AGV导航里最让我头疼也最让我兴奋的话题。为什么？因为单一传感器总有它的短板。GPS在室内失效，IMU会漂移，LiDAR在空旷场景容易迷失。但把它们组合起来，效果就完全不一样了。

我最早接触融合定位是在一个港口AGV项目上。那会儿GPS信号被集装箱遮挡得厉害，纯靠LiDAR又怕遇到长直走廊。折腾了两个月，最后用了一套松耦合的方案才搞定。今天就把这些经验分享给大家。

为什么需要融合？

先看个简单的对比：

传感器 优势 劣势
GPS 绝对位置，无累积误差 室内失效，更新率低（10Hz）
IMU 高频（100-1000Hz），短时精度高 长期漂移，无绝对参考
LiDAR 环境特征丰富，相对定位准 退化场景（长走廊）易失败

说白了，GPS给个"大方向"，IMU负责"短跑冲刺"，LiDAR则像"眼睛"盯着周围环境。三者互补，才能让AGV在各种场景下都稳得住。

融合架构：松耦合 vs 紧耦合

我个人习惯把融合方案分成两类。先看这张图：

松耦合：每个传感器先自己算位姿，然后扔给一个滤波器（比如EKF）做加权平均。优点是实现简单，各模块解耦。缺点嘛，信息有损失——你想想看，LiDAR的原始点云信息其实比它算出来的位姿丰富得多。

紧耦合：直接在原始数据层面融合。比如把GPS的伪距观测、IMU的加速度、LiDAR的点云特征一起丢进优化器。精度更高，但计算量也大。我在一个仓储AGV项目里试过紧耦合，效果确实好，但嵌入式平台跑起来有点吃力。

我的建议：如果算力够（比如有Jetson Orin），优先选紧耦合。如果用的是STM32这类MCU，老老实实松耦合吧。

核心算法：误差状态卡尔曼滤波（ES-EKF）

嗯，这里要重点讲一下。为什么用误差状态而不是全状态？

你想想看，IMU的原始数据是加速度和角速度，积分一次得到速度，再积分得到位置。这个过程误差会累积。但如果我们只估计误差——比如位置误差、速度误差、姿态误差——这些量通常很小，线性化效果更好。

看个简化版的代码：

// 预测步骤（IMU驱动）
void predict(State &x, const ImuData &imu, double dt) {
    // 状态预测：位置、速度、姿态
    x.position += x.velocity * dt + 0.5 * imu.accel * dt * dt;
    x.velocity += imu.accel * dt;
    x.quaternion = quat_update(x.quaternion, imu.gyro, dt);
    
    // 误差状态协方差预测
    Matrix F = compute_jacobian(x, imu, dt);
    Matrix Q = imu_noise_model(imu);
    x.covariance = F * x.covariance * F.transpose() + Q;
}

// 更新步骤（GPS或LiDAR观测）
void update(State &x, const Observation &z) {
    // 计算残差
    Vector y = z.measurement - h(x);
    
    // 卡尔曼增益
    Matrix H = compute_measurement_jacobian(x, z);
    Matrix S = H * x.covariance * H.transpose() + R;
    Matrix K = x.covariance * H.transpose() * S.inverse();
    
    // 更新误差状态
    Vector dx = K * y;
    x.position += dx.segment(0, 3);
    x.velocity += dx.segment(3, 3);
    x.quaternion = quat_update(x.quaternion, dx.segment(6, 3));
    
    // 更新协方差
    x.covariance = (I - K * H) * x.covariance;
}

小技巧：IMU的噪声模型别用固定的。我习惯根据运动状态动态调整——静止时Q矩阵小一点，急转弯时大一点。这样能减少漂移。

LiDAR退化场景的处理

做融合定位最怕什么？怕LiDAR在长走廊或空旷广场"跑飞"。这时候IMU和GPS就得顶上。

我分享一个实际策略：

  1. 实时评估LiDAR定位质量：用点云匹配的残差和特征点数量来判断。如果残差突然变大，或者特征点少于50个，说明退化了。
  2. 降低LiDAR权重：在EKF里，把LiDAR观测的噪声协方差R矩阵调大。比如从0.1调到10.0，相当于告诉滤波器"我不太信这个观测"。
  3. IMU+GPS主导：这时候主要靠IMU积分，GPS做绝对校正。LiDAR只用来检测障碍物，不参与定位。

注意：千万别在退化时完全丢弃LiDAR数据。我吃过这个亏——有一次在仓库里，LiDAR突然退化，我直接把它的权重设为零。结果AGV拐弯时撞到了货架。后来改成"软切换"，保留一点权重，至少能检测到障碍物。

时间同步问题

说实话，这是融合定位里最容易被忽视的坑。GPS是10Hz，IMU是100Hz，LiDAR是10Hz。它们的时间戳如果不对齐，融合出来的位姿就是错的。

我的做法：

  • 硬件上：所有传感器用同一个PPS信号同步。GPS的PPS脉冲精度在微秒级，够用了。
  • 软件上：IMU数据用插值法对齐到LiDAR和GPS的时间戳。别用最近邻，误差太大。

我曾经在一个项目里发现定位误差有30cm，查了两天才找到原因——IMU和GPS的时间戳差了50ms。50ms对于1m/s的AGV来说，就是5cm的误差。嗯，细节决定成败。

实战经验总结

最后，给大家列几个我踩过的坑：

  • 初始化：别一开机就融合。先让GPS收敛（至少10秒），IMU做零偏标定。否则初始位姿就是歪的。
  • 异常检测：加一个卡方检验。如果某个传感器的残差太大，直接丢弃这次观测。我见过GPS突然跳变几十米的情况。
  • 回环检测：如果LiDAR有回环检测能力，一定要用。回环可以修正IMU的长期漂移，效果比GPS还好。

好了，关于GPS+IMU+LiDAR融合定位，今天就聊这么多。这套方案我用了三年，从港口到仓库再到园区，基本能覆盖90%的AGV场景。剩下的10%？嗯，那是另一个故事了。
