6 环境感知与特征提取

各位好，欢迎来到第六讲。前面几讲我们聊了地图的表示方式、定位的基本原理。今天要讲的，是AGV导航系统里最"接地气"的一环——环境感知与特征提取。

说白了，就是AGV怎么"看懂"周围的世界。激光雷达扫出来的点云，密密麻麻几万个点，你不能直接拿它去匹配地图吧？得先提炼出有用的信息。我个人习惯把这一步叫做"从数据到知识"的转化。

6.1 点云预处理：别让噪声毁了你的定位

先说说点云处理。你想想看，激光雷达扫出来的原始数据，其实挺"脏"的。我在项目中遇到过，一台AGV在仓库里跑，旁边有台叉车经过，扬起的灰尘直接让点云里多了一堆"幽灵点"。

所以第一步，滤波。常用的方法有这么几种：

  • 体素滤波（Voxel Filter）：把空间切成小立方体，每个立方体里只保留一个代表点。说白了就是降采样，减少计算量。
  • 统计滤波（Statistical Outlier Removal）：计算每个点周围邻居的平均距离，离群太远的直接干掉。我习惯把阈值设成1.5倍标准差，效果不错。
  • 半径滤波（Radius Outlier Removal）：如果一个点周围指定半径内邻居太少，就认为是噪声。

我的经验：体素滤波的格子大小很关键。设太大，特征细节全丢了；设太小，降采样效果不明显。室内场景我一般用0.05m，室外开阔场景可以放宽到0.1m。

嗯，这里要注意一点：滤波的顺序也有讲究。我建议先做体素降采样，再做统计滤波。为什么？因为降采样后点数少了，统计滤波的计算量会小很多。

6.2 特征提取：从点到线、面、角

滤波完的点云，还是几万个离散的点。怎么变成AGV能用的特征？

我个人把特征分成三类：角点、直线、平面。这三类特征基本能覆盖室内环境90%以上的结构信息。

6.2.1 直线提取

走廊、墙壁、货架边缘，这些都是直线特征。最经典的方法是RANSAC（随机采样一致性）。

思路很简单：随机选两个点拟合一条直线，然后数一数有多少点"支持"这条线（距离小于阈值）。重复多次，选支持点最多的那条。

// 伪代码示例
for i = 1 to maxIterations:
    随机选两个点 p1, p2
    计算直线参数 (a, b, c)
    inliers = 0
    for each point in cloud:
        if distance(point, line) < threshold:
            inliers++
    if inliers > bestInliers:
        更新最佳直线参数

避坑指南：我曾经把RANSAC的迭代次数设得太少，结果在长走廊里提取出来的直线歪歪扭扭。后来我总结了一个经验公式：迭代次数至少是 (1 - 内点比例)^(-3) 的量级。保守起见，室内场景设500次以上比较稳妥。

6.2.2 角点检测

角点就是两条直线相交的地方。在AGV导航里，角点特别有用——它提供了明确的几何约束，定位精度比直线高得多。

我常用的方法是基于曲率的角点检测。计算每个点邻域的曲率变化，曲率突变的地方就是潜在的角点。

还有一种做法：先提取直线，再求直线交点。这个方法更鲁棒，但计算量稍大。我个人偏好后者，因为直线提取本身已经做了滤波，角点质量更高。

6.2.3 平面提取

地面、天花板、墙面，这些都是平面。平面特征对AGV的位姿估计特别重要——尤其是地面，它能直接约束Z轴和俯仰角、翻滚角。

平面提取的主流方法还是RANSAC，只不过模型从直线换成了平面方程 ax + by + cz + d = 0。

特征类型 提取方法 典型应用 我的建议
直线 RANSAC / Hough变换 走廊导航、墙壁对齐 RANSAC更鲁棒，Hough适合密集点云
角点 曲率分析 / 直线求交 定位锚点、回环检测 直线求交更稳定
平面 RANSAC / 区域生长 地面检测、障碍物分割 区域生长适合连续平面

6.3 障碍物检测：AGV的"刹车系统"

特征提取完了，接下来是更实际的问题——障碍物检测。这直接关系到AGV会不会撞上东西。

我把它分成两个层次：

  1. 静态障碍物：墙壁、货架、柱子。这些通常已经在地图里了，但实际环境中可能有变化（比如货架被移动了）。
  2. 动态障碍物：人、叉车、其他AGV。这些是实时检测的重点。

对于静态障碍物，我习惯用栅格地图法。把点云投影到二维栅格上，每个格子统计点的高度分布。如果某个格子的点云高度突然变化，说明可能有新障碍物出现。

对于动态障碍物，方法就不一样了。我推荐基于聚类的检测：

  • 用欧几里得聚类把点云分成一堆一堆的簇
  • 每个簇计算包围盒、速度（通过帧间匹配）
  • 如果某个簇的速度不为零，且尺寸符合人/车的特征，就标记为动态障碍物

核心要点：障碍物检测的难点不在算法，而在阈值设置。聚类距离阈值设太大，会把人和货架粘在一起；设太小，一个人会被切成好几块。我一般从0.3m开始调，根据实际场景微调。

6.5 实战中的几个坑

最后，分享几个我在实际项目中踩过的坑：

  • 地面点干扰：提取直线时，地面上的点（比如地砖缝）经常被误识别为墙壁。我习惯先做地面分割，把地面点去掉再提取特征。
  • 动态物体污染：有人走过时，点云里会多出一坨"移动的墙"。如果不做动态物体滤除，特征提取结果会乱套。我一般用帧差法或者速度滤波来处理。
  • 参数泛化性：同一个算法，换一个场景就要重新调参。我的做法是写一个自动调参脚本，在不同场景下跑一遍，选最优参数组合。

小技巧：如果你用的是ROS，可以试试 pcl_ros 包里的现成节点。它封装了大部分滤波和特征提取算法，省去不少重复造轮子的时间。
