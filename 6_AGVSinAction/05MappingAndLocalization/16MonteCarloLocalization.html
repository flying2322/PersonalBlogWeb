16 蒙特卡洛定位（MCL）

说到定位，咱们之前聊过卡尔曼滤波、扩展卡尔曼滤波。这些方法有个共同点——它们假设噪声是高斯分布的。但实际项目中，这个假设经常不成立。

我记得有一次在仓库调试AGV，地面有些金属反光条，激光雷达的数据突然出现一堆离群点。EKF直接崩了，定位误差飙到半米多。后来换成蒙特卡洛定位，问题就解决了。

为什么？因为MCL不假设噪声分布。它用一堆粒子来模拟所有可能的位置。说白了，就是用暴力计算换鲁棒性。

16.1 蒙特卡洛定位的核心思想

蒙特卡洛定位，也叫粒子滤波定位。它的核心就一句话：用一群随机粒子来近似机器人的位姿概率分布。

你想想看，一个粒子就是一个猜测。1000个粒子就是1000个「我觉得机器人在哪」的假设。粒子越密集的地方，机器人越可能在那里。

核心流程：

  1. 初始化：在可能的位置撒一堆粒子
  2. 预测：根据运动模型移动粒子
  3. 更新：根据观测数据给粒子打分
  4. 重采样：淘汰低分粒子，复制高分粒子
  5. 重复2-4步

我习惯把这个过程叫做「猜-动-看-筛」四步曲。每次循环，粒子群都会更集中、更准确。

16.2 粒子滤波的实现细节

光说理论不够，咱们直接看代码。我写一个简化版的MCL实现，你感受一下。

import numpy as np

class ParticleFilter:
    def __init__(self, num_particles=1000):
        self.num_particles = num_particles
        # 每个粒子: [x, y, theta, weight]
        self.particles = np.zeros((num_particles, 4))
        
    def initialize_uniform(self, x_range, y_range, theta_range):
        """均匀初始化：不知道机器人在哪"""
        self.particles[:, 0] = np.random.uniform(*x_range, self.num_particles)
        self.particles[:, 1] = np.random.uniform(*y_range, self.num_particles)
        self.particles[:, 2] = np.random.uniform(*theta_range, self.num_particles)
        self.particles[:, 3] = 1.0 / self.num_particles  # 等权重
        
    def predict(self, control, noise_std=[0.1, 0.1, 0.05]):
        """运动预测：加噪声模拟不确定性"""
        dx, dy, dtheta = control
        self.particles[:, 0] += dx + np.random.normal(0, noise_std[0], self.num_particles)
        self.particles[:, 1] += dy + np.random.normal(0, noise_std[1], self.num_particles)
        self.particles[:, 2] += dtheta + np.random.normal(0, noise_std[2], self.num_particles)
        
    def update(self, measurement, map_data, sensor_model):
        """观测更新：计算每个粒子的权重"""
        for i in range(self.num_particles):
            # 预测该粒子位置应该看到什么
            expected = sensor_model.predict_measurement(
                self.particles[i, :3], map_data)
            # 计算与实际观测的匹配度
            likelihood = sensor_model.likelihood(measurement, expected)
            self.particles[i, 3] *= likelihood
            
        # 归一化权重
        weight_sum = np.sum(self.particles[:, 3])
        if weight_sum > 0:
            self.particles[:, 3] /= weight_sum
            
    def resample(self):
        """重采样：低分粒子淘汰，高分粒子复制"""
        weights = self.particles[:, 3]
        # 系统重采样（比轮盘赌更稳定）
        cumsum = np.cumsum(weights)
        step = 1.0 / self.num_particles
        positions = np.random.uniform(0, step) + np.arange(self.num_particles) * step
        
        indices = np.searchsorted(cumsum, positions)
        self.particles = self.particles[indices]
        self.particles[:, 3] = 1.0 / self.num_particles  # 重置权重
        
    def estimate(self):
        """估计位姿：加权平均"""
        mean_x = np.average(self.particles[:, 0], weights=self.particles[:, 3])
        mean_y = np.average(self.particles[:, 1], weights=self.particles[:, 3])
        mean_theta = np.average(self.particles[:, 2], weights=self.particles[:, 3])
        return [mean_x, mean_y, mean_theta]

我的经验：粒子数量不是越多越好。1000个粒子在大多数场景够用，5000个以上边际效益递减。我一般从500开始调，看定位抖动情况再增减。

16.3 重采样策略的选择

重采样是MCL的关键。选不好，粒子会「退化」——要么全部挤在一起，要么分散得找不到北。

常见的重采样方法有几种：

方法 原理 优点 缺点
轮盘赌 按权重概率抽取 实现简单 方差大，容易丢失多样性
系统重采样 等间隔抽取 方差小，更稳定 实现稍复杂
残差重采样 先保留整数部分 计算快 低权重粒子可能被完全丢弃
分层重采样 分层后再抽样 多样性好 实现最复杂

我个人习惯用系统重采样。它在稳定性和多样性之间平衡得最好。轮盘赌我踩过坑——有一次粒子全部坍缩到一个错误位置，就是因为轮盘赌的随机性太大。

16.4 自适应MCL

标准MCL有个问题：粒子数量固定。机器人被「绑架」（突然搬动）时，需要大量粒子重新搜索。平时稳定跟踪时，又不需要那么多。

自适应MCL（KLD采样）就是解决这个问题的。它动态调整粒子数量。

核心思想：根据粒子分布的熵来决定粒子数。

  • 粒子分布很分散（不确定大）→ 增加粒子数
  • 粒子分布很集中（确定性强）→ 减少粒子数

具体实现用Kullback-Leibler距离（KL散度）来衡量分布差异。当粒子分布和真实分布之间的KL距离小于阈值时，就停止增加粒子。

def adaptive_resample(particles, weights, min_particles=100, max_particles=5000):
    """KLD自适应重采样"""
    # 计算有效粒子数
    w_sq_sum = np.sum(weights ** 2)
    n_eff = 1.0 / w_sq_sum if w_sq_sum > 0 else 0
    
    # 根据有效粒子数调整目标粒子数
    target = min(max(int(n_eff * 1.5), min_particles), max_particles)
    
    # 执行重采样
    cumsum = np.cumsum(weights)
    step = 1.0 / target
    positions = np.random.uniform(0, step) + np.arange(target) * step
    indices = np.searchsorted(cumsum, positions)
    
    return particles[indices], np.ones(target) / target

注意：自适应MCL不是万能的。如果机器人被「绑架」到很远的地方，粒子可能永远搜不到正确位置。我建议配合全局定位模块一起用——当检测到定位误差过大时，重新撒全局粒子。

16.5 实际项目中的避坑指南

做MCL落地，有几个坑我替你们踩过了：

  • 粒子贫化：重采样太频繁，粒子多样性丢失。解决方案：保留一部分随机粒子（比如5%的粒子随机撒）。
  • 计算延迟：粒子数太多，一帧处理不完。解决方案：用C++实现核心循环，或者用GPU加速。
  • 对称环境混淆：走廊、仓库货架区，多个位置看起来一样。解决方案：结合里程计短期约束，或者用语义特征辅助。

我曾经在一个大型仓库项目里，遇到AGV在货架通道里反复「漂移」。排查了两天，发现是激光雷达的更新频率和粒子滤波的更新频率不匹配。后来加了时间戳对齐，问题就解决了。

嗯，做定位就是这样。理论看起来简单，落地全是细节。

本章小结：

  • MCL用粒子群近似位姿概率分布，不依赖高斯假设
  • 核心四步：初始化→预测→更新→重采样
  • 重采样方法影响定位稳定性和多样性
  • 自适应MCL动态调整粒子数，平衡精度和计算量
  • 实际落地要注意粒子贫化、计算延迟、环境对称等问题
