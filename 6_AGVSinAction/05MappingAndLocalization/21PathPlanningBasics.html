21 路径规划基础——全局路径规划与局部路径规划

各位同学，今天我们来聊聊AGV导航里最核心的一个环节——路径规划。说白了，就是让小车知道“怎么走”的问题。

我个人习惯把路径规划分成两个层次：全局路径规划和局部路径规划。全局规划负责“大方向”，局部规划负责“躲障碍”。两者缺一不可。

一、全局路径规划：从A到B的宏观路线

全局路径规划，就是在地图上找一条从起点到终点的可行路径。我刚开始做AGV项目时，总觉得这步很简单——不就是找条路吗？后来发现，地图大了、障碍多了，计算量能把你CPU跑冒烟。

1. Dijkstra算法：最朴素的“地毯式搜索”

Dijkstra算法，说白了就是“从起点开始，一层一层往外扩”。它保证能找到最短路径，但效率嘛……你想想看，如果地图有10000个节点，它可能要遍历8000个才能找到目标。

核心思想：

  • 维护一个距离表，记录每个节点到起点的最短距离
  • 每次从未访问的节点中选距离最小的，更新它的邻居
  • 直到所有节点都被访问，或者到达目标点

适用场景：地图不大、对路径长度要求绝对最优的场景。比如仓库里固定路线的AGV。

// Dijkstra伪代码
function Dijkstra(graph, start, end):
    dist[start] = 0
    visited = {}
    while visited 未包含所有节点:
        u = 未访问节点中dist最小的
        visited.add(u)
        if u == end: break
        for v in u的邻居:
            if dist[u] + weight(u,v) < dist[v]:
                dist[v] = dist[u] + weight(u,v)
                prev[v] = u
    return 回溯prev得到路径

我的经验：我在一个工厂项目里用过Dijkstra，地图节点大概5000个，每次规划要跑200ms。后来发现其实不需要每次都重新规划——把路径缓存起来，除非障碍物变了，否则直接用缓存。嗯，这里要注意，缓存失效策略要设计好。

2. A*算法：带“方向感”的搜索

A*算法是Dijkstra的升级版。它加了一个“启发式函数”，告诉搜索方向“往目标那边走”。

为什么A*比Dijkstra快？

Dijkstra是“无头苍蝇”，四面八方都搜。A*是“有目标的苍蝇”，知道目标在东南方向，就优先往东南搜。你想想看，效率能差多少？

核心公式：

f(n) = g(n) + h(n)
- g(n): 从起点到当前节点n的实际代价
- h(n): 从节点n到终点的估计代价（启发式函数）
- f(n): 节点n的总估计代价

启发式函数h(n)的选择很关键。我建议用欧几里得距离或曼哈顿距离。如果h(n)低估了实际距离，A*保证能找到最优解；如果高估了，可能找不到最优解，但速度更快。

避坑指南：我曾经在一个项目中用了曼哈顿距离做启发式，结果地图上有斜角障碍物，A*绕了一大圈。后来换成欧几里得距离，路径就合理了。所以，启发式函数的选择要结合地图特点。

// A*伪代码
function AStar(graph, start, end):
    openSet = {start}
    g[start] = 0
    f[start] = h(start, end)
    while openSet 不为空:
        current = openSet中f值最小的节点
        if current == end: return 回溯路径
        openSet.remove(current)
        for neighbor in current的邻居:
            tentative_g = g[current] + cost(current, neighbor)
            if tentative_g < g[neighbor]:
                g[neighbor] = tentative_g
                f[neighbor] = g[neighbor] + h(neighbor, end)
                prev[neighbor] = current
                if neighbor not in openSet:
                    openSet.add(neighbor)
    return 无路径

二、局部路径规划：动态避障的“微观操作”

全局路径规划给出了宏观路线，但实际运行时，路上可能有临时障碍物——比如突然出现的人、叉车、掉落的箱子。这时候就需要局部路径规划来“见招拆招”。

1. DWA算法：速度空间的“暴力枚举”

DWA（Dynamic Window Approach），中文叫动态窗口法。它的思路很简单：在当前速度附近采样，选一个最好的速度执行。

核心步骤：

  1. 速度空间采样：在当前线速度v和角速度ω附近，采样一组(v, ω)组合
  2. 轨迹预测：对每个(v, ω)组合，模拟未来一小段时间的运动轨迹
  3. 轨迹评价：用评价函数给每条轨迹打分
  4. 选择最优：选得分最高的(v, ω)执行

评价函数通常包含三个部分：

  • 朝向代价：轨迹终点与目标方向的偏差
  • 障碍物代价：轨迹与最近障碍物的距离
  • 速度代价：鼓励高速行驶，提高效率

我的经验：DWA的参数调优是个体力活。我记得在一个项目里，障碍物代价权重调大了，AGV在空旷区域也龟速前进；调小了，又容易撞到东西。后来我用了自适应权重——障碍物近时加大障碍物代价，远时加大速度代价。效果还不错。

2. TEB算法：带时间约束的“弹性带”

TEB（Timed Elastic Band），中文叫时间弹性带。它把路径看作一条“橡皮筋”，通过优化来调整路径的形状和时间分配。

核心思想：

  • 路径由一系列位姿点组成，每个点带时间戳
  • 通过优化目标函数，让路径更平滑、更安全、更高效
  • 目标函数包括：路径长度、障碍物距离、速度限制、加速度限制等

DWA vs TEB：怎么选？

对比项 DWA TEB
计算复杂度 低，适合嵌入式 高，需要较强算力
路径平滑度 一般 好，可生成平滑轨迹
动态避障 反应快 可预测障碍物运动
适用场景 简单环境、低速AGV 复杂环境、高速AGV

我的建议：如果你用的是STM32这类MCU，老老实实用DWA。如果用的是Jetson或工控机，可以考虑TEB。我在一个仓储项目里试过TEB，路径确实平滑，但CPU占用率飙到60%——后来还是换回了DWA。

三、全局+局部：双剑合璧

实际项目中，全局规划和局部规划是配合使用的：

  1. 全局规划（A*）先生成一条宏观路径
  2. 局部规划（DWA或TEB）沿着这条路径前进，同时实时避障
  3. 如果局部规划发现路径被完全堵死，就触发全局重规划

嗯，这里要注意：全局重规划不能太频繁。我曾经遇到过一个bug，AGV每次遇到小障碍就重规划，结果路径一直在变，小车在原地打转。后来加了“重规划冷却时间”——5秒内不重复规划，问题就解决了。

四、本章小结

路径规划是AGV导航的“大脑”。全局规划负责“想好怎么走”，局部规划负责“走好每一步”。

  • Dijkstra：保证最优，但慢。适合小地图。
  • A*：带方向感的搜索，效率高。最常用。
  • DWA：速度空间采样，反应快。适合嵌入式。
  • TEB：弹性带优化，路径平滑。适合高性能平台。

我个人习惯：A* + DWA 是黄金组合，90%的场景都能搞定。剩下的10%，要么地图太大需要分层规划，要么环境太复杂需要TEB。

最后提醒：路径规划不是“调好参数就完事”的。实际部署时，一定要做边界测试——比如障碍物紧贴路径、多AGV交汇、传感器噪声等场景。我吃过这个亏，不说了，都是泪。
