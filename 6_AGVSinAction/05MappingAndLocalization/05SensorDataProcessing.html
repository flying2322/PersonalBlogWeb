5 传感器数据处理：数据滤波、标定与时间同步

传感器数据处理，说白了就是让AGV的“眼睛”和“耳朵”变得靠谱。我做了这么多年导航系统，见过太多因为传感器数据没处理好，导致AGV在车间里“画龙”的案例。今天咱们就聊聊这块硬骨头。

核心观点：传感器数据处理的三个支柱——滤波、标定、时间同步。缺一个，你的AGV就可能撞墙。

5.1 数据滤波：卡尔曼滤波

卡尔曼滤波，我习惯叫它“最优估计器”。它不直接消除噪声，而是根据模型预测和实际观测，算出最可能的状态。说白了，就是“猜得准”。

我在项目中遇到过一个问题：AGV在仓库里跑，激光雷达测距偶尔跳变。卡尔曼滤波一上，立马稳了。为什么？因为它知道AGV不可能瞬间位移，所以把跳变点给“平滑”掉了。

卡尔曼滤波的核心公式其实就五个，我给大家拆解一下：

// 预测阶段
x_pred = A * x_prev + B * u      // 状态预测
P_pred = A * P_prev * A^T + Q    // 协方差预测

// 更新阶段
K = P_pred * H^T * (H * P_pred * H^T + R)^-1  // 卡尔曼增益
x_est = x_pred + K * (z - H * x_pred)         // 状态更新
P_est = (I - K * H) * P_pred                  // 协方差更新

嗯，这里要注意：Q和R矩阵的调参是个手艺活。Q太大，滤波响应快但噪声大；R太大，滤波平滑但滞后严重。我一般先让AGV静止，调R让输出稳定；再让AGV跑直线，调Q让跟踪不滞后。

我的小技巧：调参时，先固定R，只调Q。Q的对角线元素代表各状态的不确定性。比如位置不确定性大，就把对应Q值设大一点。

5.2 数据滤波：粒子滤波

卡尔曼滤波有个前提——系统是线性的、噪声是高斯的。但现实世界哪有那么完美？AGV在非结构化环境里，或者遇到多峰分布的情况，卡尔曼就抓瞎了。这时候，粒子滤波上场。

粒子滤波的思想很朴素：用一堆随机粒子来近似概率分布。每个粒子代表一个可能的状态，权重代表这个状态的可信度。粒子越多，估计越准，但计算量也越大。

我记得有一次做AGV在走廊里的定位，走廊两边都是相似的货架。卡尔曼滤波直接“左右不分”，定位结果在两个货架间来回跳。换成粒子滤波后，粒子分布在两个可能的走廊位置，虽然不确定，但至少没跳变。后来AGV拐了个弯，粒子迅速收敛到正确位置。

粒子滤波的流程，我总结为三步：

  1. 采样：根据上一时刻的粒子分布，加上运动模型，生成新粒子
  2. 权重计算：根据当前观测，计算每个粒子的权重
  3. 重采样：根据权重重新采样，权重高的粒子多复制，权重低的粒子淘汰

避坑指南：我曾经在粒子滤波的重采样步骤上栽过跟头。如果重采样太频繁，粒子会迅速“退化”到少数几个点，失去多样性。我现在的做法是：计算有效粒子数Neff，当Neff小于阈值（比如N/2）时才重采样。

5.3 传感器标定

传感器标定，说白了就是给传感器“校准”。你想想看，一个激光雷达装在AGV上，它的安装角度偏了0.5度，10米外的测距误差就是8.7厘米。这误差足以让AGV撞上货架。

标定分两种：

  • 内参标定：传感器自身的参数。比如激光雷达的测距偏移、IMU的零偏和尺度因子
  • 外参标定：传感器之间的相对位姿。比如激光雷达相对于AGV车体的安装位置和角度

我个人的习惯是，每次更换传感器或维修后，必须重新标定。别偷懒，偷懒的代价是AGV跑偏。

外参标定常用的方法是“手眼标定”。原理很简单：让AGV走一段已知轨迹，同时记录传感器观测到的特征点。然后解一个方程组，算出传感器相对于车体的位姿。

// 手眼标定的核心方程
A * X = X * B

其中：
A: 车体在两个时刻之间的位姿变换
B: 传感器在两个时刻之间的位姿变换
X: 传感器相对于车体的位姿（待求）

这个方程看着简单，但解起来挺麻烦。我一般用开源工具包，比如Kalibr或者lidar_align。但要注意，标定数据要覆盖各个自由度——前后、左右、旋转都要有，不然解出来的参数会“病态”。

我的经验：标定IMU时，一定要让IMU静止足够长时间（至少1分钟），这样才能准确估计零偏。我曾经只静止了10秒，结果零偏估计不准，导致后续的航位推算误差累积得飞快。

5.4 时间同步

时间同步，是传感器融合里最容易被忽视、但后果最严重的问题。你想想看，激光雷达的数据是10Hz，IMU的数据是100Hz，相机是30Hz。如果这些数据的时间戳对不上，融合出来的结果就是“驴唇不对马嘴”。

我在项目中遇到过：AGV在高速转弯时，定位突然跳变。查了半天，发现是激光雷达和IMU的时间戳差了50毫秒。50毫秒对于高速转弯的AGV来说，位置误差已经超过10厘米了。

时间同步的常用方法：

  • 硬件同步：用同一个时钟源给所有传感器提供时间戳。精度最高，但需要硬件支持
  • 软件同步：用ROS的tf树或者自定义的时间戳对齐算法。精度稍差，但实现简单

我一般推荐硬件同步。如果条件不允许，软件同步也可以，但要注意：

  1. 所有传感器的时间戳必须统一到同一个时钟（比如系统时钟）
  2. 对于不同频率的传感器，采用“最近邻插值”或“线性插值”对齐
  3. 定期检查时间戳偏差，如果偏差超过阈值（比如10毫秒），发出警告

避坑指南：我曾经在ROS里直接用传感器自带的时间戳，结果发现激光雷达的时间戳是UTC时间，IMU的时间戳是系统启动后的相对时间。两个时间戳根本对不上。后来我统一用系统时钟给所有传感器打时间戳，问题才解决。

好了，传感器数据处理这块就聊到这儿。内容不少，但都是实战中摸爬滚打出来的经验。大家在实际项目中遇到问题，可以多想想这三个方面——滤波参数调了吗？标定做了吗？时间戳对齐了吗？很多时候，问题就出在这些“不起眼”的地方。

一句话总结：传感器数据处理没有捷径，只有把滤波、标定、时间同步都做到位，AGV才能真正“看得清、走得稳”。
