23 控制与跟踪——纯追踪算法、Stanley算法、MPC控制

各位好，今天我们聊点硬核的。地图建好了，定位也准了，接下来干什么？当然是让车动起来，并且沿着我们规划的路径走。

说白了，控制与跟踪就是解决一个问题：“车该怎么打方向盘，才能稳稳地跟上目标路径？”

我这些年调试AGV，最头疼的往往不是建图，而是控制。明明路径规划得好好的，车一跑起来就歪了，要么震荡，要么干脆冲出去。嗯，这里面的门道，我们今天一次讲透。

这节课我们重点讲三种经典方法：纯追踪（Pure Pursuit）、Stanley算法、以及MPC（模型预测控制）。它们各有脾气，适用场景也不同。

一、纯追踪算法——最直观的几何法

纯追踪算法，名字听着玄乎，其实原理特别简单。你想象一下：在目标路径上选一个前方的点，然后控制车头一直对准那个点开过去。就像你走路时盯着前方某个目标，自然就走过去了。

它的核心公式是这样的：

// 纯追踪算法核心——计算前轮转角
double computeSteerAngle(double L, double ld, double alpha) {
    // L: 轴距
    // ld: 前视距离（look-ahead distance）
    // alpha: 车头方向与目标点的夹角
    double delta = atan2(2.0 * L * sin(alpha), ld);
    return delta;
}

这里有个关键参数——前视距离 ld。我刚开始调这个参数时，踩过不少坑。ld 设得太小，车会左右震荡，像喝醉了酒；ld 设得太大，车又切弯太狠，走内线。

我的经验：前视距离一般取车速的 0.5~2 倍。低速时（0.5m/s），ld 取 0.5~1m；高速时（2m/s），ld 取 2~4m。你可以根据路径曲率动态调整——弯道小一点，直道大一点。

纯追踪的优点很明显：实现简单，计算量小，适合低速AGV。缺点呢？它对路径曲率变化敏感，而且前视距离的整定比较依赖经验。

二、Stanley算法——基于前轮偏差的反馈控制

Stanley 算法是斯坦福大学参加 DARPA 挑战赛时用的方法。我个人觉得，它比纯追踪更「聪明」一点。

Stanley 的核心思想是：同时考虑横向偏差和航向偏差。说白了，就是车不仅要看前方，还要看自己当前偏离了路径多少。

// Stanley 算法核心
double stanleyControl(double crossTrackError, double headingError, double k, double v) {
    // crossTrackError: 横向偏差（车到路径的垂直距离）
    // headingError: 航向偏差（车头方向与路径切线方向的夹角）
    // k: 增益系数
    // v: 当前车速
    double delta = headingError + atan2(k * crossTrackError, v);
    // 限幅处理
    return clamp(delta, -MAX_STEER_ANGLE, MAX_STEER_ANGLE);
}

这里有个细节：atan2(k * crossTrackError, v) 这一项，车速 v 在分母上。这意味着车速越快，横向偏差的修正作用越小——这其实符合直觉：高速时猛打方向容易翻车。

关键区别：纯追踪是「看前方一点追过去」，Stanley 是「看当前偏差和前方方向一起修正」。Stanley 的收敛性更好，尤其在路径曲率连续变化时。

我曾经在一个仓库项目里，用 Stanley 算法跑 1.5m/s 的 AGV，路径跟踪误差能控制在 ±5cm 以内。纯追踪在同条件下，误差大概在 ±10cm。差距还是挺明显的。

注意：Stanley 算法假设车辆是前轮转向模型（阿克曼转向）。如果你的 AGV 是差速驱动（两轮独立驱动），需要先做运动学转换。我见过有人直接把差速车的线速度差当成前轮转角往里套，结果车原地打转——千万别这么干。

三、MPC控制——带约束的「预言家」

MPC（模型预测控制）是这三者里最复杂、也最强大的。它的思路是：每走一步，都往前预测几步，然后选一条最优的轨迹走。

打个比方：纯追踪是「看着前方10米的目标点走」，Stanley 是「看着脚下和前方10米走」，而 MPC 是「看着前方50米的整段路，还要考虑油门、刹车、转向极限，然后决定怎么走」。

MPC 的核心步骤：

  1. 建立车辆模型——通常是运动学或动力学模型
  2. 设定预测时域 N——比如往前预测 20 步
  3. 构建代价函数——包括跟踪误差、控制量大小、控制量变化率
  4. 施加约束——最大转向角、最大加速度、障碍物距离等
  5. 在线求解优化问题——得到最优控制序列，只执行第一步
// MPC 代价函数示例（简化）
// J = sum_{k=0}^{N-1} ( w_e * error(k)^2 + w_u * u(k)^2 + w_du * du(k)^2 )
// 约束: |delta| <= 30°, |a| <= 1.0 m/s^2

MPC 最大的优势是能处理约束。比如你的 AGV 在狭窄通道里，既要跟踪路径，又不能撞墙，MPC 可以同时考虑这些约束，给出一个安全可行的控制量。

但代价也很明显——计算量大。我早期在嵌入式板子上跑 MPC，一个控制周期 100ms，优化求解就要花 80ms，差点把 CPU 跑满。后来换了更高效的求解器，才降到 20ms 以内。

实用建议：如果你的 AGV 速度低于 1m/s，路径简单，用纯追踪就够了。速度 1~2m/s，路径有弯道，用 Stanley。速度 2m/s 以上，或者有严格的安全约束（比如人车混行），上 MPC。

三种算法对比

特性 纯追踪 Stanley MPC
原理类型 几何法 反馈控制 优化控制
计算复杂度 低 低 高
约束处理 不支持 不支持 原生支持
跟踪精度 中等 良好 优秀
参数整定难度 中等（前视距离） 简单（增益k） 复杂（权重+时域）
适用车速 低速（<1m/s） 中低速（<2m/s） 全速域

最后说一句实在的：没有最好的算法，只有最合适的算法。我见过有人用纯追踪在工厂里跑得好好的，也见过有人用 MPC 调了三个月还没上路。关键是根据你的 AGV 车型、运行速度、环境约束来选。

嗯，控制与跟踪这块，今天就先聊到这儿。下次你们调试 AGV 时，如果发现车在画龙，不妨试试调整前视距离或者增益系数——有时候问题没那么复杂。
