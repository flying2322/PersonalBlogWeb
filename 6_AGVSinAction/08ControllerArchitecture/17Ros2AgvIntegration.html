17 ROS2基础与AGV集成：ROS2节点与话题、ROS2服务与动作、ROS2参数服务器、ROS2 Launch文件

各位同学，今天我们来聊聊ROS2。说实话，ROS2在AGV领域已经成了标配。我最早接触ROS还是ROS1的Indigo版本，那时候做AGV导航，动不动就掉节点，调试起来真是头疼。后来ROS2出来，我才算真正松了口气。

这一章，我会把ROS2的核心通信机制讲透。你想想看，AGV本质上就是一个分布式系统——传感器采集数据、规划算法计算路径、电机执行控制指令，这些模块之间怎么高效通信？答案就在ROS2的节点、话题、服务、动作和参数服务器里。

核心观点：ROS2不是简单的升级版，而是从架构上重新设计了通信机制。它抛弃了ROS1的Master中心节点，改用DDS（数据分发服务）作为底层通信中间件。这意味着什么？意味着去中心化、实时性更好、可靠性更高。

17.1 ROS2节点与话题——AGV的"神经元"与"神经信号"

节点，说白了就是一个可执行程序。每个节点负责一个具体的功能。比如在AGV上，激光雷达驱动是一个节点，里程计计算是一个节点，路径规划又是一个节点。它们各自独立运行，互不干扰。

话题呢？就是节点之间传递数据的通道。一个节点发布话题，另一个节点订阅话题，数据就流通起来了。我习惯把话题想象成"广播电台"——发布者只管往外发，订阅者只管收，双方不需要知道对方是谁。

来看一个实际例子。这是AGV上激光雷达数据发布的代码片段：

# 激光雷达驱动节点
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import LaserScan

class LidarDriver(Node):
    def __init__(self):
        super().__init__('lidar_driver')
        self.publisher_ = self.create_publisher(LaserScan, '/scan', 10)
        self.timer = self.create_timer(0.1, self.publish_scan)  # 10Hz
        
    def publish_scan(self):
        msg = LaserScan()
        # 填充激光雷达数据...
        self.publisher_.publish(msg)

嗯，这里要注意。话题名称的命名规范很重要。我在项目中遇到过，两个团队各自开发模块，一个用/lidar/scan，另一个用/scan，结果集成时发现数据对不上。后来我们统一了命名规则：/[设备类型]/[数据名称]。比如激光雷达就是/lidar/scan，里程计就是/odom/data。

话题命名示例 说明
/lidar/scan 激光雷达原始扫描数据
/odom/data 里程计位置数据
/cmd_vel 速度控制指令
/imu/data IMU姿态数据

17.2 ROS2服务与动作——请求-响应与长期任务

话题是单向的、持续的。但有些场景需要"一问一答"。比如AGV要获取当前电池电量，或者要重置里程计。这时候就该服务上场了。

服务是同步的。客户端发请求，服务端处理完返回响应。我举个例子：

# 电池状态服务
from std_srvs.srv import Trigger

class BatteryService(Node):
    def __init__(self):
        super().__init__('battery_service')
        self.srv = self.create_service(Trigger, 'get_battery_status', self.get_battery_callback)
    
    def get_battery_callback(self, request, response):
        response.success = True
        response.message = f"当前电量: {self.read_battery()}%"
        return response

但服务有个问题——它是阻塞的。如果AGV正在执行一个导航任务，你发一个服务请求，它得等任务完成才能响应。这显然不合理。所以就有了动作（Action）。

动作是异步的。它允许你发送一个目标，然后可以随时查询进度，也可以取消任务。AGV的导航任务就是典型的动作应用：

# 导航动作客户端
from nav2_msgs.action import NavigateToPose

class NavClient(Node):
    def __init__(self):
        super().__init__('nav_client')
        self.action_client = ActionClient(self, NavigateToPose, 'navigate_to_pose')
    
    def send_goal(self, x, y, theta):
        goal_msg = NavigateToPose.Goal()
        # 设置目标位置...
        self.action_client.send_goal_async(goal_msg)

我的经验：动作的反馈机制特别适合AGV。你可以实时看到"已走完30%路径"、"遇到障碍物正在绕行"这样的状态。我曾经用这个机制做了一个可视化界面，操作员能清楚知道AGV在干什么。

17.3 ROS2参数服务器——AGV的"配置文件"

参数服务器，说白了就是一个全局的键值对存储。AGV的很多参数——比如最大速度、加速度、激光雷达的扫描范围——都不应该硬编码在代码里。用参数服务器，你可以随时修改，甚至运行时动态调整。

我个人习惯把参数分成三类：

  • 静态参数：启动时加载，运行中不变。比如轮子直径、编码器分辨率。
  • 动态参数：运行中可以修改。比如最大速度、安全距离阈值。
  • 调试参数：只在调试阶段使用。比如日志级别、模拟模式开关。

来看参数声明和使用的代码：

class AGVConfig(Node):
    def __init__(self):
        super().__init__('agv_config')
        self.declare_parameter('max_speed', 1.0)  # 默认1.0 m/s
        self.declare_parameter('acceleration', 0.5)
        self.declare_parameter('safety_distance', 0.3)
        
    def get_params(self):
        max_speed = self.get_parameter('max_speed').value
        acc = self.get_parameter('acceleration').value
        return max_speed, acc

注意：参数服务器不是数据库。别把大量数据往里塞。我曾经见过有人把整个地图数据存成参数，结果启动时卡了半分钟。参数适合存标量值或短字符串，复杂数据请用话题或文件。

17.4 ROS2 Launch文件——一键启动AGV系统

AGV系统少说也有十几个节点。激光雷达、IMU、里程计、导航、控制、监控……一个个手动启动？不现实。Launch文件就是用来解决这个问题的。

Launch文件可以：

  • 同时启动多个节点
  • 设置节点参数
  • 配置节点之间的依赖关系
  • 支持条件判断和变量替换

一个典型的AGV启动文件长这样：

# agv_bringup.launch.py
from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        Node(
            package='agv_drivers',
            executable='lidar_driver',
            name='lidar_driver',
            parameters=[{'frame_id': 'laser_frame'}]
        ),
        Node(
            package='agv_drivers',
            executable='motor_controller',
            name='motor_controller',
            parameters=[{'max_speed': 1.5}]
        ),
        Node(
            package='agv_navigation',
            executable='nav_node',
            name='navigation'
        ),
    ])

启动时只需要一行命令：ros2 launch agv_bringup agv_bringup.launch.py。所有节点自动启动，参数自动加载。省心。

避坑指南：我曾经在Launch文件里忘了加remappings参数，结果两个节点的话题名称对不上。一个发/scan，另一个收/lidar/scan，数据就是传不过去。后来我养成了习惯——在Launch文件里显式声明话题重映射：remappings=[('/scan', '/lidar/scan')]。
