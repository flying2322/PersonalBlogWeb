16 仿真环境搭建

各位同学，今天我们来聊聊仿真环境搭建。说实话，我在AGV领域摸爬滚打这么多年，最深的体会就是：仿真做得好，实车调试少。很多新手一上来就怼实车，结果撞坏几个传感器、烧了几块驱动板之后，才老老实实回来搭仿真环境。

我个人习惯是：先仿真跑通，再实车验证。这样既省钱又省时间。今天我们就从Gazebo仿真环境开始，一步步把AGV的仿真环境搭起来。

16.1 Gazebo仿真环境概览

Gazebo是什么？说白了就是一个3D机器人仿真器。它和ROS是天生一对，配合起来非常默契。你可以在里面建地图、加传感器、跑算法，效果和实车差不多。

我建议你安装Gazebo 9或11版本。为什么？因为这两个版本和ROS Melodic、Noetic兼容性最好。我在项目中遇到过用Gazebo 7死活跑不起来的情况，后来换成9就一切正常了。

核心要点：Gazebo + ROS = 仿真黄金搭档

  • Gazebo负责物理引擎和3D渲染
  • ROS负责通信和算法调度
  • 两者通过gazebo_ros_pkgs桥接

安装命令很简单：

sudo apt-get install ros-melodic-gazebo-ros-pkgs ros-melodic-gazebo-ros-control

嗯，这里要注意：版本一定要匹配。Melodic对应Gazebo 9，Noetic对应Gazebo 11。别搞混了。

16.2 AGV模型URDF配置

URDF是啥？Unified Robot Description Format，统一机器人描述格式。说白了就是用一个XML文件描述你的AGV长什么样、有多重、轮子在哪。

我刚开始写URDF时，总觉得这东西很玄乎。后来发现，其实就是把AGV拆成几个部分：

  • 底盘：车体主体，一般是个长方体
  • 轮子：驱动轮、万向轮
  • 传感器支架：激光雷达、摄像头的位置

来看一个简单的AGV URDF示例：

<robot name="my_agv">
  <!-- 底盘 -->
  <link name="base_link">
    <visual>
      <geometry>
        <box size="0.5 0.4 0.15"/>
      </geometry>
    </visual>
    <collision>
      <geometry>
        <box size="0.5 0.4 0.15"/>
      </geometry>
    </collision>
  </link>

  <!-- 左驱动轮 -->
  <joint name="left_wheel_joint" type="continuous">
    <parent link="base_link"/>
    <child link="left_wheel"/>
    <origin xyz="0.2 0.25 0" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
  </joint>
</robot>

我的经验：URDF里<collision>和<visual>最好保持一致。我曾经偷懒只写了visual，结果Gazebo里碰撞检测一塌糊涂，AGV直接穿模了。

16.3 仿真传感器配置

AGV上常用的传感器就那几种：激光雷达、深度相机、IMU。在Gazebo里配置传感器，其实就是加几个插件。

拿激光雷达举例：

<gazebo reference="laser_link">
  <sensor type="ray" name="head_laser">
    <pose>0 0 0 0 0 0</pose>
    <visualize>true</visualize>
    <update_rate>10</update_rate>
    <ray>
      <scan>
        <horizontal>
          <samples>360</samples>
          <resolution>1</resolution>
          <min_angle>-3.14159</min_angle>
          <max_angle>3.14159</max_angle>
        </horizontal>
      </scan>
      <range>
        <min>0.1</min>
        <max>10.0</max>
      </range>
    </ray>
  </sensor>
</gazebo>

你想想看，这个配置和真实激光雷达的参数是不是很像？samples对应线数，min_angle和max_angle对应扫描范围。说白了就是把真实传感器的参数填进去。

避坑指南：我曾经把update_rate设成100Hz，结果Gazebo直接卡死。仿真环境不是越快越好，10-20Hz就够用了。真实激光雷达也就10-15Hz。

16.4 仿真与实车切换

这是很多同学关心的问题：怎么在仿真和实车之间无缝切换？

我的做法是：用命名空间和参数服务器。说白了就是写一个launch文件，通过参数控制启动仿真还是实车。

<launch>
  <arg name="use_sim" default="true"/>

  <!-- 仿真模式 -->
  <group if="$(arg use_sim)">
    <include file="$(find my_agv)/launch/gazebo.launch"/>
    <node name="fake_odom" pkg="fake_localization" type="fake_localization"/>
  </group>

  <!-- 实车模式 -->
  <group unless="$(arg use_sim)">
    <include file="$(find my_agv)/launch/real_robot.launch"/>
    <node name="odom" pkg="robot_localization" type="ekf_localization"/>
  </group>

  <!-- 公共部分 -->
  <node name="move_base" pkg="move_base" type="move_base"/>
</launch>

启动时只需要加一个参数：

# 仿真模式
roslaunch my_agv start.launch use_sim:=true

# 实车模式
roslaunch my_agv start.launch use_sim:=false

核心思想：仿真和实车共用一套算法代码，只切换底层驱动和传感器数据源。这样你写的导航、避障算法，在仿真里调好了，直接拿到实车上就能跑。

我的建议：刚开始做仿真时，别追求完美。先让AGV在Gazebo里动起来，哪怕只是原地转圈。然后再慢慢加传感器、调参数。一口吃不成胖子，仿真也是迭代出来的。

好了，这一章的内容就到这里。记住一句话：仿真不是目的，是手段。我们的最终目标是在实车上跑出好效果，仿真只是帮我们更快、更安全地达到这个目标。
