6 运动控制模块设计：两轮差速模型、PID速度控制、加速度与减速度规划、轨迹跟踪

各位同学，今天我们来聊聊AGV运动控制里最核心的一块——两轮差速模型。说实话，我在这个领域摸爬滚打十几年，见过太多项目栽在运动控制上。硬件选得再好，算法写得再花哨，运动控制这块要是拉胯了，车跑起来就跟喝醉了酒似的，左右摇摆，定位精度一塌糊涂。

所以，咱们今天把这四个核心知识点掰开揉碎了讲清楚。

6.1 两轮差速运动模型

先说说两轮差速模型。说白了，就是靠左右两个驱动轮的转速差来实现转向。你想想看，左轮转得快、右轮转得慢，车就往右拐；反过来就往左拐。两个轮子转速一样，那就直着走。

这个模型在数学上其实挺简单的。我给大家一个最常用的公式：

// 两轮差速模型核心公式
v = (v_right + v_left) / 2          // 车体线速度
ω = (v_right - v_left) / L          // 车体角速度，L为轮距

// 逆运动学：从目标速度到轮速
v_left  = v - (ω * L) / 2
v_right = v + (ω * L) / 2

嗯，这里要注意一个坑。我在项目里遇到过，很多人直接把轮子转速当成线速度来算。实际上，轮子转速是角速度，要乘以轮子半径才能得到线速度。这个转换千万别忘了。

避坑指南：我曾经在一个项目中，同事直接用电机编码器的脉冲数代入公式，结果车跑起来轨迹完全不对。后来排查了半天，发现是忘了做单位换算。轮子半径、编码器线数、减速比，这三个参数必须校准到位。

6.2 PID速度控制

有了运动模型，接下来就是怎么让轮子精确地跑到目标转速。PID控制，这是最经典的方法，也是我个人的首选。

PID的公式大家应该都熟悉：

// 位置式PID
error = target_speed - current_speed
integral += error * dt
derivative = (error - last_error) / dt
output = Kp * error + Ki * integral + Kd * derivative
last_error = error

但实际工程中，我建议你用增量式PID。为什么？因为位置式PID的积分项容易饱和，一旦积分饱和，系统响应会变得很迟钝。增量式PID只计算输出变化量，天然抗饱和。

// 增量式PID
error = target_speed - current_speed
delta_output = Kp * (error - last_error) + Ki * error + Kd * (error - 2*last_error + last_last_error)
output += delta_output

// 更新历史误差
last_last_error = last_error
last_error = error
调参心得：我个人习惯先调Kp，让系统能快速响应但不振荡。然后加一点Kd抑制超调。最后才加Ki消除静差。记住，Ki不要太大，否则系统会低频振荡。我见过有人把Ki调得很大，结果轮子一直在目标转速附近来回晃，就是稳不住。

6.3 加速度与减速度规划

速度控制搞定了，但还有个问题——你直接给轮子一个阶跃速度指令，电机瞬间加速，车体就会猛地一冲。这在AGV上绝对不行，货物会倒，定位会偏。

所以我们需要做加速度规划。说白了，就是让速度平滑地变化，而不是跳变。

最常用的方法是梯形速度规划：

// 梯形速度规划
// 输入：目标速度v_target，当前速度v_current，最大加速度a_max，控制周期dt

if (v_target > v_current) {
    // 加速阶段
    v_cmd = v_current + a_max * dt;
    if (v_cmd > v_target) v_cmd = v_target;
} else if (v_target < v_current) {
    // 减速阶段
    v_cmd = v_current - a_max * dt;
    if (v_cmd < v_target) v_cmd = v_target;
} else {
    v_cmd = v_target;
}

但梯形规划有个问题——加速度突变。从零加速到最大加速度那一瞬间，其实还是有冲击。更平滑的做法是用S形曲线规划，也就是加速度本身也是连续变化的。

我的经验：对于一般的AGV，梯形规划已经够用了。但如果你做的是重载AGV或者运载精密仪器的AGV，我建议上S形曲线。我曾经帮一个客户调试半导体晶圆搬运AGV，用梯形规划时晶圆总是轻微移位，换成S形曲线后问题就解决了。

6.4 轨迹跟踪

最后一块，轨迹跟踪。前面我们讲了怎么控制轮子转速，怎么平滑加减速，但这些都是底层的。上层要给运动控制模块发什么指令？是发目标点坐标，还是发路径点序列？

常用的轨迹跟踪方法有两种：

  • Pure Pursuit（纯追踪法）：在路径上找一个前瞻点，然后控制车体朝这个点运动。简单直观，适合低速场景。
  • Stanley方法：基于前轮偏角的控制方法，收敛性更好，适合高速场景。

我个人更常用Pure Pursuit，因为它实现简单，而且对路径的平滑度要求不高。核心逻辑如下：

// Pure Pursuit 核心算法
// 输入：当前位姿(x, y, yaw)，路径点序列path[]，前瞻距离lookahead

// 1. 找到距离当前位置为lookahead的路径点
target_point = findLookaheadPoint(path, x, y, lookahead);

// 2. 计算目标点相对于车体的角度
alpha = atan2(target_point.y - y, target_point.x - x) - yaw;

// 3. 计算曲率半径
curvature = 2 * sin(alpha) / lookahead;

// 4. 根据曲率计算左右轮速
v_left  = v_target * (1 - curvature * L / 2);
v_right = v_target * (1 + curvature * L / 2);
注意：前瞻距离的选择很关键。太短了，车会振荡；太长了，车会切弯。我一般把前瞻距离设为车体长度的2-3倍，然后根据车速动态调整。车速快的时候前瞻远一点，车速慢的时候近一点。

好了，这四个知识点串起来，就是一个完整的运动控制模块。从运动模型到速度控制，再到加减速规划，最后到轨迹跟踪，每一层都有它的作用。少了任何一个环节，AGV都跑不好。

从这张图可以看得很清楚，运动控制模块是分层设计的。每一层只负责自己的事情，层与层之间通过标准接口通信。这样做的好处是，哪一层出了问题，我们可以单独调试，不影响其他层。

举个例子，如果你发现AGV在转弯时轨迹偏差大，可能是轨迹跟踪层的前瞻距离没调好，也可能是速度控制层的PID参数不对，还可能是运动模型层的轮距参数没校准。分层设计让你能快速定位问题。

调试建议：我一般从底层往上调。先确保电机能精确响应速度指令（PID调好），再验证运动模型是否正确（让车走直线和圆弧），然后测试加减速规划是否平滑，最后才调轨迹跟踪。一层一层来，问题就清晰了。

好了，以上就是运动控制模块设计的核心内容。两轮差速模型是基础，PID速度控制是保障，加减速规划是品质，轨迹跟踪是目标。这四个环节环环相扣，缺一不可。
