15 轨迹跟踪控制：基于模型的预测控制（MPC）、纯追踪算法、Stanley算法

各位同学，今天我们来聊聊AGV调度系统里最“接地气”也最“烧脑”的一个环节——轨迹跟踪控制。

说白了，就是规划层给你画好了一条路，你作为底层控制器，得让车老老实实沿着这条路走。别小看这一步，我见过太多项目，规划做得漂漂亮亮，一上路就歪七扭八，最后撞货架。嗯，这里面的门道，我今天一次性讲透。

核心观点：轨迹跟踪不是“跟着走”，而是“预测着走”。你想想看，AGV有惯性、有延迟，等发现偏了再纠偏，早就晚了。所以，好的控制器必须能“预判”未来。

15.1 三种算法的核心差异

我个人习惯把轨迹跟踪算法分成三类：几何法、运动学法、模型法。今天要讲的三个算法，正好各占一类。

算法 类型 核心思想 适用场景
纯追踪（Pure Pursuit） 几何法 找前视点，圆弧拟合 低速、路径平滑
Stanley 运动学法 横向偏差+航向偏差 中高速、连续路径
MPC 模型法 滚动优化+约束处理 高速、强约束、复杂场景

先别急着背表格，我们一个个拆开看。

15.2 纯追踪算法：最直观的“追点”策略

纯追踪算法，名字就很直白——就是让车去追一个前方的点。

怎么追？ 在参考轨迹上，找一个距离车当前位置为 \( L_d \)（前视距离）的点，然后计算一个圆弧半径，让车沿着这个圆弧开过去。

公式很简单：

δ = arctan( 2 * L * sin(α) / L_d )

其中：

  • δ：前轮转角
  • L：轴距
  • α：车头方向与目标点的夹角
  • L_d：前视距离

我在项目中遇到过一个问题：前视距离怎么调？ 调小了，车像喝醉酒一样左右摇摆；调大了，车又“抄近道”，切弯严重。

我的经验：前视距离最好跟车速挂钩。车速越快，看得越远。我一般用 \( L_d = k * v \)，k取1.5~2.5之间。低速场景（<0.5m/s）可以固定值。

纯追踪的优点很明显：实现简单，计算量小。但缺点也致命——它不考虑车的动力学，遇到急弯或者高速，容易失控。

15.3 Stanley算法：来自斯坦福的“纠偏大师”

Stanley算法是我个人比较偏爱的一个。它来自斯坦福大学的Stanley赛车，在2005年DARPA大挑战赛中拿了冠军。

它的核心思想是：同时考虑横向偏差和航向偏差。

δ = θ_e + arctan( k * e / v )

其中：

  • θ_e：航向偏差（车头方向与路径切线方向的夹角）
  • e：横向偏差（车中心到路径的最短距离）
  • k：增益系数
  • v：车速

你想想看，纯追踪只盯着一个点，而Stanley是“看全局”——既看方向对不对，也看位置偏没偏。

我曾经踩过一个坑： 在仓库里用Stanley，发现车在直道上跑得挺好，一到转弯就“甩尾”。后来排查发现，是增益系数k设得太大了。k越大，纠偏越猛，但容易过冲。我建议k值从0.5开始调，慢慢往上加。

注意：Stanley算法对路径的连续性要求很高。如果路径上有尖锐的折角，车会剧烈抖动。所以，规划层最好给一条平滑的路径（比如用B样条插值）。

15.4 MPC：工业级的“最优解”

MPC（模型预测控制）是这三个算法里最复杂的，也是效果最好的。说白了，它每走一步，都要“算一卦”——预测未来N步的状态，然后找一个最优的控制序列。

MPC的核心流程：

  1. 建立模型： 用运动学或动力学方程描述AGV
  2. 滚动优化： 在每个控制周期，求解一个带约束的优化问题
  3. 反馈校正： 只执行第一个控制量，然后重新预测

代码框架大概长这样：

// 伪代码：MPC核心循环
while (running) {
    // 1. 获取当前状态
    state = getCurrentState();
    
    // 2. 预测未来N步的参考轨迹
    ref_traj = getReferenceTrajectory(state, N);
    
    // 3. 求解优化问题
    //    目标：最小化跟踪误差 + 控制量变化
    //    约束：速度限制、加速度限制、转向角限制
    control_seq = solveQP(state, ref_traj, constraints);
    
    // 4. 只执行第一个控制量
    applyControl(control_seq[0]);
    
    // 5. 等待下一个控制周期
    sleep(control_period);
}

我建议初学者先别急着调MPC的参数，而是先理解它的“代价函数”。代价函数里，权重矩阵Q和R决定了你是更看重跟踪精度，还是更看重控制平顺性。

实战经验： 我在一个港口AGV项目里，用MPC替代了原来的PID。原来PID在重载时抖得厉害，换了MPC后，跟踪误差从±5cm降到了±1cm。代价是计算量大了10倍——所以，硬件算力得跟上。

15.5 三种算法的对比与选型

讲到这里，你可能会问：那我到底该用哪个？

我的建议是：

  • 纯追踪： 适合教学演示、简单场景、低成本MCU。如果你做的是玩具车或者低速巡检车，用它就够了。
  • Stanley： 适合中高速、路径平滑的场景。比如仓储AGV、园区物流车。我个人的主力算法就是它。
  • MPC： 适合高速、强约束、高精度场景。比如港口、矿山、无人驾驶。但需要较强的硬件和算法团队。

15.6 避坑指南与调参心得

最后，我把自己这些年踩过的坑，总结成几条经验：

  • 我曾经因为前视距离没跟车速联动，导致车在高速时冲出路径。 后来加了个简单的线性映射，问题就解决了。
  • 我曾经在Stanley算法里把增益k设得太大，车在直道上左右摇摆。 记住：k值越小越稳，但响应慢；k值越大越灵敏，但容易振荡。
  • MPC的预测时域N不是越大越好。 N太大，计算量爆炸，而且远处的预测本身就不准。我一般取N=10~20步。
  • 别忘了控制周期。 纯追踪和Stanley可以跑50ms周期，MPC建议至少100ms周期，否则算不过来。

一个小技巧： 调试时，先把车放在直道上，调好直道跟踪，再上弯道。弯道调试时，先低速（0.3m/s），再慢慢提速。这样能快速定位问题是出在直道还是弯道。

好了，轨迹跟踪控制的核心内容就这些。三种算法各有千秋，选型时一定要结合你的实际场景——车速、路径形状、硬件算力、精度要求。没有最好的算法，只有最合适的算法。
