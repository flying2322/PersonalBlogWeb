12 AGV定位与导航——从磁条到SLAM，从PID到纯追踪

各位同学好，我是老张。今天咱们聊聊AGV的定位与导航。

说实话，这章内容我纠结了很久。为什么？因为定位和导航这两个词，在AGV领域里经常被混着用。但在我个人看来，它们其实是两码事——定位是回答“我在哪”，导航是回答“怎么去”。你想想看，如果连自己在哪都不知道，那规划路径、控制运动就全是空谈。

好，咱们先看定位技术。

12.1 定位技术：三种主流方案

AGV的定位方式，说白了就三大类：磁条、二维码、激光SLAM。我按从“老古董”到“新贵”的顺序讲。

12.1.1 磁条导航

这是最传统的方式。地面贴磁条，AGV沿着磁条走。优点是便宜、稳定、抗干扰强。缺点？太死板了——改路径就得重新贴磁条，工厂里满地胶带，看着就头疼。

核心原理：磁传感器检测磁条磁场强度，通过左右偏差信号控制转向。

我在项目里遇到过一个问题：磁条用久了会磨损，磁场强度下降，导致AGV跑偏。后来我们加了个自动增益校准，每次启动时自动调整传感器灵敏度，才算解决。

⚠️ 避坑指南
我曾经在某个项目里，磁条贴在了金属地板上。结果金属产生涡流，干扰了磁场信号。AGV像喝醉了酒一样左右摇摆。后来我们垫了一层绝缘胶带才搞定。所以，磁条下方不能有金属，切记。

12.1.2 二维码导航

二维码导航是目前工业AGV的主流。地面贴二维码标签，AGV通过摄像头识别，获取精确位置。

定位精度：±5mm以内，比磁条高一个数量级。

工作原理：

  • 二维码里编码了坐标信息（x, y, 角度）
  • 摄像头拍摄后，通过图像处理解码
  • 结合IMU（惯性测量单元）做航位推算，填补二维码之间的盲区

我个人习惯，二维码的间距不要超过1米。太远了，IMU的累积误差会大到离谱。我见过一个项目，二维码间距设了2米，结果AGV在中间段偏了10厘米，直接撞货架。

💡 小技巧
二维码导航的“死穴”是地面反光。如果地面是亮面瓷砖，反光会导致摄像头过曝。我建议用哑光材质的二维码贴纸，或者加偏振片。

12.1.3 激光SLAM导航

这是目前最“高级”的方案。不需要任何地面标记，AGV通过激光雷达扫描环境，实时构建地图并定位。

SLAM = Simultaneous Localization and Mapping（同步定位与地图构建）

说白了，就是AGV一边走，一边画地图，同时在地图上找自己。这有点像你蒙着眼走进一个陌生房间，一边摸墙一边在脑子里画平面图。

主流算法：

  • Gmapping：基于粒子滤波，适合小场景，计算量小
  • Cartographer：Google出品，基于图优化，适合大场景，精度高
  • Hector SLAM：不需要里程计，纯激光匹配，但容易漂移

我在实际项目中，90%的情况用Cartographer。为什么？因为它能处理回环检测——就是AGV绕一圈回到原点时，能自动修正累积误差。Gmapping在回环时经常“炸掉”，地图对不齐。

🔑 核心对比
方案精度成本灵活性适用场景
磁条±10mm低极低固定路线、简单环境
二维码±5mm中中仓库、产线、半结构化环境
激光SLAM±20mm高高动态环境、无标记场景

12.2 导航控制算法：让AGV动起来

定位搞定了，接下来就是怎么控制AGV沿着路径走。这里有两个经典算法：PID和纯追踪。

12.2.1 PID控制

PID是控制界的“万金油”。比例（P）、积分（I）、微分（D），三个参数调好了，AGV就能稳稳地走直线、转弯。

在AGV导航中的应用：

  • 位置环：控制AGV与目标点的距离偏差
  • 速度环：控制AGV的线速度和角速度
  • 航向环：控制AGV的朝向角偏差

我调PID有个习惯：先调P，让系统能响应；再加D，抑制震荡；最后加I，消除静差。千万别一上来三个参数一起调，那会把自己搞疯。

// 一个简单的PID控制器示例
float pid_control(float setpoint, float current, float dt) {
    float error = setpoint - current;
    
    // 比例项
    float P = kp * error;
    
    // 积分项（带限幅）
    integral += error * dt;
    if (integral > integral_max) integral = integral_max;
    if (integral < -integral_max) integral = -integral_max;
    float I = ki * integral;
    
    // 微分项
    float derivative = (error - last_error) / dt;
    float D = kd * derivative;
    
    last_error = error;
    
    return P + I + D;
}
⚠️ 注意
PID的积分项是个双刃剑。积分太强，AGV转弯时会“过冲”；积分太弱，直道上会有稳态误差。我曾经在一个项目里，积分项设得太大，AGV在弯道直接甩尾，差点把货甩下来。后来我把积分限幅砍了一半，才稳住。

12.2.2 纯追踪算法

纯追踪（Pure Pursuit）是一种几何路径跟踪算法。它不关心AGV的动力学模型，只关心“我该往哪转才能追上目标点”。

核心思想：

  • 在路径上选一个“预瞄点”（look-ahead point）
  • 计算AGV当前位置到预瞄点的圆弧半径
  • 根据圆弧半径计算转向角

说白了，就是AGV像狗追飞盘一样——眼睛盯着飞盘（预瞄点），身体自动调整方向去追。

关键参数：预瞄距离（look-ahead distance）

  • 预瞄距离太短：AGV会频繁转向，路径抖动
  • 预瞄距离太长：AGV会“切弯”，走捷径，偏离路径

我一般把预瞄距离设为AGV车长的2-3倍。比如车长1米，预瞄距离设2-3米。这样转弯时既不会太急，也不会太飘。

// 纯追踪算法核心计算
float pure_pursuit(float current_x, float current_y, float current_theta,
                   float target_x, float target_y) {
    // 计算预瞄点相对于AGV的坐标
    float dx = target_x - current_x;
    float dy = target_y - current_y;
    
    // 转换到AGV坐标系
    float local_x = dx * cos(current_theta) + dy * sin(current_theta);
    float local_y = -dx * sin(current_theta) + dy * cos(current_theta);
    
    // 计算曲率（转弯半径的倒数）
    float curvature = 2.0 * local_y / (local_x * local_x + local_y * local_y);
    
    // 计算转向角
    float steering_angle = atan(curvature * wheel_base);
    
    return steering_angle;
}
💡 经验之谈
纯追踪算法对速度很敏感。速度快时，预瞄距离要相应增大。我习惯把预瞄距离设为速度的线性函数：look_ahead = k * velocity + base_distance。这样AGV在高速时看得远，低速时看得近，转弯更自然。
