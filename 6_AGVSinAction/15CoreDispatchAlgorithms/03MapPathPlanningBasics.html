3 地图与路径规划基础：地图表示与搜索算法

各位同学好，我是老张。今天咱们聊聊AGV调度系统里最基础、也最核心的一块——地图表示和路径搜索。说实话，我见过不少团队，算法调得天花乱坠，结果地图建模没做好，车跑起来各种撞墙。嗯，这章咱们就把地基打牢。

地图表示方法

AGV要跑，首先得知道“世界长什么样”。地图怎么存，直接决定了后续所有算法的效率和可行性。我个人习惯把地图表示分成两大类：栅格图和拓扑图。

栅格图（Grid Map）

栅格图，说白了就是把真实环境切成一个个小格子。每个格子要么是空地（可通行），要么是障碍物（不可通行）。就像你玩扫雷游戏那个棋盘。

核心特点：

  • 精度取决于栅格大小。1米一格？还是0.1米一格？
  • 存储简单，就是一个二维数组
  • 搜索时直接操作格子坐标

我在项目中遇到过一个问题：工厂车间有200米长、100米宽，如果用0.1米的栅格，那就是2000×1000=200万个格子。每次路径搜索都要遍历这么多格子，性能扛不住。所以实际项目中，我建议栅格大小取0.5米到1米之间，够用就行。

// 栅格图的数据结构示例
struct GridMap {
    int width;          // 宽度（格子数）
    int height;         // 高度（格子数）
    double resolution;  // 分辨率（米/格）
    int** cells;        // 0=空地, 1=障碍物
};

避坑指南：我曾经把栅格分辨率设成0.05米，结果地图文件直接爆了内存。后来才意识到，AGV本身有0.5米的转弯半径，你搞那么精细的栅格，纯属浪费。

拓扑图（Topological Map）

拓扑图就聪明多了。它只关心“关键点”和“关键点之间的连接关系”。你想想看，AGV在工厂里跑，其实不需要知道每个角落长什么样，它只需要知道：从A点到B点，走哪条路最近。

拓扑图由两部分组成：

  • 节点（Node）：代表关键位置，比如工位、充电站、路口
  • 边（Edge）：代表可通行的路径，边上可以带权重（距离、时间、能耗）

我个人更偏爱拓扑图，原因很简单：搜索速度快。一个工厂可能只需要几百个节点，比几百万个栅格快太多了。

// 拓扑图的数据结构示例
struct TopoNode {
    int id;
    double x, y;        // 实际坐标
    vector<int> neighbors;  // 邻居节点ID列表
};

struct TopoEdge {
    int from, to;
    double weight;      // 距离或时间成本
};

我的经验：实际项目中，我通常把栅格图和拓扑图结合使用。栅格图用于全局规划，拓扑图用于局部调度。两者互补，效果最好。

路径搜索算法

地图建好了，接下来就是找路。AGV从A点到B点，怎么走最短？怎么走最快？这里我重点讲两个算法：Dijkstra和A*。

Dijkstra算法

Dijkstra是个经典算法，它的核心思想就一句话：从起点开始，一层层往外扩散，直到找到终点。它保证找到的是最短路径，但代价是——慢。

为什么慢？因为它像个无头苍蝇，四面八方都搜。你想想看，如果起点和终点在一条直线上，Dijkstra还是会去搜反方向的路。

// Dijkstra算法伪代码
function Dijkstra(graph, start, end):
    dist[start] = 0
    queue = priority_queue()
    queue.push((0, start))
    
    while queue not empty:
        (d, u) = queue.pop()
        if u == end: break
        for v in graph.neighbors(u):
            if dist[u] + weight(u,v) < dist[v]:
                dist[v] = dist[u] + weight(u,v)
                queue.push((dist[v], v))
    return dist[end]

适用场景：地图小、节点少、对最优性要求极高的情况。比如AGV在充电站和工位之间来回跑，路径固定，用Dijkstra一次算好，后面直接复用。

A*算法

A*算法是Dijkstra的升级版。它加了一个“启发式函数”，说白了就是给算法一个方向感。它知道终点在哪个方向，就不会往反方向瞎搜了。

A*的核心公式：

f(n) = g(n) + h(n)
  • g(n)：从起点到当前节点n的实际代价
  • h(n)：从当前节点n到终点的估计代价（启发式函数）
  • f(n)：总代价估计值

启发式函数h(n)怎么选？我常用的有两种：

  • 曼哈顿距离：适合只能上下左右移动的场景（比如仓库货架间）
  • 欧几里得距离：适合可以任意方向移动的场景（比如开阔车间）
// A*算法伪代码
function AStar(graph, start, end):
    openSet = priority_queue()
    openSet.push((f(start), start))
    g[start] = 0
    
    while openSet not empty:
        current = openSet.pop()
        if current == end: break
        for neighbor in graph.neighbors(current):
            tentative_g = g[current] + weight(current, neighbor)
            if tentative_g < g[neighbor]:
                g[neighbor] = tentative_g
                f[neighbor] = g[neighbor] + heuristic(neighbor, end)
                openSet.push((f[neighbor], neighbor))

我的建议：实际项目中，90%的情况用A*就够了。Dijkstra虽然保证最优，但A*在大多数情况下也能找到最优路径，而且快得多。我曾经在一个200节点的拓扑图上测试，A*比Dijkstra快了将近10倍。

两种算法的对比

特性 Dijkstra A*
搜索方向 全方位扩散 有方向性
最优性 保证最优 取决于启发式函数
速度 慢（节点数多时明显） 快（有方向引导）
适用场景 小地图、静态路径 大地图、动态调度

重要提醒：别以为学了算法就万事大吉。我曾经在一个项目里，A*算法跑得飞快，结果AGV走到一半发现路被堵了。为什么？因为地图是静态的，但环境是动态的。所以实际调度系统里，路径搜索只是第一步，后面还要做冲突检测和动态重规划。
