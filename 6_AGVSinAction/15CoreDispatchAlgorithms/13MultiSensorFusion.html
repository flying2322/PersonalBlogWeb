13 多传感器融合——让AGV真正“看清”世界

各位同学，今天我们来聊一个非常核心的话题——多传感器融合。说实话，我做了这么多年AGV调度系统，见过太多“单传感器翻车”的案例了。你想想看，如果只靠激光雷达，遇到玻璃墙怎么办？只靠编码器，轮子打滑了怎么办？所以，多传感器融合不是“锦上添花”，而是“雪中送炭”。

13.1 传感器类型：各有各的脾气

先说说我们常用的三种传感器。我个人习惯把它们比作“三兄弟”——各有长处，也各有短板。

13.1.1 激光雷达（LiDAR）

激光雷达是AGV的“眼睛”。它通过发射激光束并测量反射时间，来获取周围环境的点云数据。精度高、范围广，但遇到透明物体（比如玻璃）或者强光环境，就容易“瞎掉”。

我在项目中遇到过：有一次在仓库里，AGV对着玻璃门直接撞了上去。后来一查，激光雷达把玻璃当成了“不存在”。从那以后，我坚持必须加IMU做辅助。

关键参数：
  • 测量范围：通常10-50米
  • 角度分辨率：0.1°-1°
  • 更新频率：10-20Hz

13.1.2 IMU（惯性测量单元）

IMU是AGV的“内耳”。它测量加速度和角速度，用来推算姿态和位置。优点是更新频率高（100-400Hz），不受外界环境影响。但缺点也很明显——误差会随时间累积，也就是“漂移”。

我曾经做过一个测试：只用IMU跑30秒，位置误差就超过了1米。所以IMU必须和其他传感器配合使用。

13.1.3 编码器

编码器装在电机或轮子上，测量旋转角度和速度。它是最“老实”的传感器，成本低、可靠性高。但问题在于——轮子打滑、地面不平都会导致误差。

你想想看，如果AGV在湿滑地面上行驶，编码器告诉你“走了1米”，实际上可能只走了0.8米。这就是所谓的“滑移误差”。

传感器 优点 缺点 典型频率
激光雷达 精度高、范围广 受环境光影响、无法检测透明物体 10-20Hz
IMU 高频、不受外界干扰 漂移严重 100-400Hz
编码器 成本低、可靠 滑移误差、累积误差 50-200Hz

13.2 卡尔曼滤波原理：从“猜”到“信”

好了，传感器数据都有了，怎么融合呢？这里就要请出我们的主角——卡尔曼滤波。

说白了，卡尔曼滤波就是“用数学方法做最优估计”。它不依赖历史数据，只根据当前观测和上一时刻的估计，就能算出当前最可能的状态。

13.2.1 核心思想：预测+更新

卡尔曼滤波就两步：

  1. 预测：根据上一时刻的状态和控制输入，猜一下当前状态。
  2. 更新：用当前传感器的观测值，修正这个猜测。

嗯，这里要注意：预测和更新之间有个“权重”问题。如果传感器很准，就多信观测；如果模型很准，就多信预测。这个权重就是卡尔曼增益。

我的经验：卡尔曼增益的调参是门手艺活。我一般先让系统跑几圈，记录下误差特性，再反推噪声协方差矩阵。千万别拍脑袋设参数，否则会“发散”。

13.2.2 数学公式（简化版）

我知道有些同学看到公式就头疼。没关系，我们只讲核心：

预测阶段：
  x_pred = A * x_prev + B * u
  P_pred = A * P_prev * A^T + Q

更新阶段：
  K = P_pred * H^T * (H * P_pred * H^T + R)^(-1)
  x_est = x_pred + K * (z - H * x_pred)
  P_est = (I - K * H) * P_pred

其中：

  • x：状态向量（位置、速度等）
  • P：误差协方差矩阵
  • Q：过程噪声（模型不准的程度）
  • R：观测噪声（传感器不准的程度）
  • K：卡尔曼增益

为什么会这样？因为卡尔曼滤波本质上是在最小化估计误差的方差。你想想看，如果传感器噪声R很大，K就会变小，系统更相信预测；反之亦然。

13.3.2 代码实现（Python伪代码）

下面是我常用的一个简化版融合定位类。注意，这里只展示核心逻辑：

class MultiSensorFusion:
    def __init__(self):
        # 状态向量: [x, y, theta, vx, vy, omega]
        self.x = np.zeros(6)
        # 误差协方差
        self.P = np.eye(6) * 0.1
        # 过程噪声
        self.Q = np.diag([0.05, 0.05, 0.01, 0.1, 0.1, 0.02])
        # 观测噪声（不同传感器不同）
        self.R_lidar = np.diag([0.1, 0.1, 0.02])
        self.R_imu = np.diag([0.5, 0.5, 0.1])
        self.R_encoder = np.diag([0.2, 0.2, 0.05])
        
    def predict(self, dt, u):
        """预测阶段：根据控制输入u和dt更新状态"""
        # 运动模型（简化版）
        self.x[0] += self.x[3] * dt  # x位置
        self.x[1] += self.x[4] * dt  # y位置
        self.x[2] += self.x[5] * dt  # 朝向角
        # 更新协方差
        F = np.eye(6)  # 雅可比矩阵（简化）
        self.P = F @ self.P @ F.T + self.Q
        
    def update(self, z, sensor_type):
        """更新阶段：根据传感器观测值z修正状态"""
        if sensor_type == 'lidar':
            R = self.R_lidar
            H = self._get_H_lidar()  # 观测矩阵
        elif sensor_type == 'imu':
            R = self.R_imu
            H = self._get_H_imu()
        else:  # encoder
            R = self.R_encoder
            H = self._get_H_encoder()
            
        # 卡尔曼增益
        K = self.P @ H.T @ np.linalg.inv(H @ self.P @ H.T + R)
        # 状态更新
        self.x = self.x + K @ (z - H @ self.x)
        # 协方差更新
        self.P = (np.eye(6) - K @ H) @ self.P
        
    def get_pose(self):
        """获取融合后的位姿"""
        return self.x[0:3]  # 返回 (x, y, theta)
注意：实际项目中，运动模型和观测模型都是非线性的，需要用扩展卡尔曼滤波（EKF）或无迹卡尔曼滤波（UKF）。上面的代码只是教学演示，千万别直接用在产品里！

13.3.3 时间同步问题

嗯，这里有个坑——不同传感器的采样频率不一样。激光雷达10Hz，IMU 200Hz，编码器100Hz。如果不做时间同步，融合出来的结果会“串味”。

我的做法是：

  • 以IMU为基准，因为它频率最高
  • 每次收到激光雷达数据时，先做一次预测，再用激光数据更新
  • 编码器数据则作为“控制输入”的一部分，参与预测阶段

说白了，就是“高频预测，低频更新”。这样既保证了实时性，又保证了精度。

13.4 避坑指南

最后，分享几个我踩过的坑：

我曾经在一个项目中，把激光雷达的观测噪声设得太小，结果卡尔曼滤波完全跟着激光走，IMU和编码器等于没用。后来发现，激光雷达在仓库角落有严重的多路径效应，导致定位跳变。解决办法是：根据激光点的置信度动态调整R矩阵。
另一个坑：IMU的零偏校准。如果IMU没有做零偏补偿，积分出来的位置会漂移得很快。我建议每次AGV启动时，先静止5秒，采集IMU的零偏值。
