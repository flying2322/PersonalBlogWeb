23 地图构建与路径规划模块实现

好，咱们今天来聊聊AGV调度系统里最核心的两个模块——地图构建和路径规划。说实话，这两个东西是调度系统的地基。地基不稳，上面再花哨的算法都是空中楼阁。

我在做第一个AGV项目时，就吃过地图建模的亏。当时图省事，直接用二维网格，结果车跑起来各种撞墙。后来才明白，地图构建不是简单的画格子，你得考虑AGV的物理尺寸、转弯半径、还有各种障碍物的实际形状。

地图构建：从物理世界到数字模型

地图构建，说白了就是把仓库、车间这些真实环境，变成计算机能理解的数据结构。我个人习惯用拓扑地图+栅格地图的混合方案。

拓扑地图：用节点和边表示路径网络。节点是AGV可以停靠或转向的点，边是AGV可以行驶的路径。这种地图计算快，适合全局路径规划。

栅格地图：把环境划分成小格子，每个格子标记为可通行或不可通行。这种地图精度高，适合局部避障。

我一般这样设计地图数据结构：

// 拓扑地图节点
struct MapNode {
    int id;           // 节点ID
    double x, y;      // 物理坐标
    double theta;     // 朝向角（可选）
    int type;         // 0:普通点, 1:充电站, 2:装卸站
};

// 拓扑地图边
struct MapEdge {
    int fromNode;     // 起点ID
    int toNode;       // 终点ID
    double length;    // 实际距离
    double maxSpeed;  // 限速
    bool isBidirectional; // 是否双向
};

// 栅格地图
class GridMap {
    int width, height;       // 栅格数量
    double resolution;       // 每个格子代表的物理尺寸（米）
    vector<vector<int>> grid; // 0:空闲, 1:障碍物, 2:未知
};

嗯，这里要注意一点：栅格地图的分辨率不能太高也不能太低。太高了计算量爆炸，太低了AGV过不去窄通道。我一般取0.1米到0.2米，刚好能匹配AGV的尺寸。

路径规划：A*算法的工程化改造

路径规划算法很多，但工程上用得最多的还是A*。为什么？因为它稳定、可控、好调参。

不过，教科书上的A*直接拿来用，十有八九会出问题。我在项目中遇到过几个坑：

  • 路径不平滑：A*出来的路径全是直角拐弯，AGV根本走不了
  • 计算太慢：地图一大，搜索空间爆炸
  • 动态障碍物：其他AGV或人突然出现，路径就废了

针对这些问题，我做了几个改造：

1. 启发函数优化

标准A*用曼哈顿距离或欧氏距离。但实际AGV有运动约束，不能斜着走。我改用考虑转向代价的启发函数：

double heuristic(int fromX, int fromY, int toX, int toY, int currentDir) {
    double dx = abs(fromX - toX);
    double dy = abs(fromY - toY);
    
    // 基础距离
    double baseDist = dx + dy;
    
    // 转向代价：如果当前方向与目标方向不一致，增加代价
    int targetDir = getDirection(fromX, fromY, toX, toY);
    double turnCost = (currentDir == targetDir) ? 0 : TURN_PENALTY;
    
    return baseDist + turnCost;
}

你想想看，如果不加转向代价，AGV会频繁变向，实际跑起来比乌龟还慢。

2. 分层规划策略

地图一大，A*就慢。我的做法是分层：

  1. 全局层：在拓扑地图上用A*，找到节点序列
  2. 局部层：在两个节点之间，用栅格地图做精细路径

这样全局规划毫秒级完成，局部规划也能实时响应。

3. 动态重规划

AGV跑着跑着，前面突然出现障碍物怎么办？不能停下来等死。我设计了一个局部重规划触发器：

  • 当AGV前方3米内出现新障碍物
  • 当AGV偏离原路径超过0.5米
  • 当路径被其他AGV占用超过5秒

触发后，只重新规划当前节点到目标节点的局部路径，不重新跑全局。

核心要点：路径规划不是一次性的，而是持续迭代的过程。AGV每走一步，都要检查路径是否还可用。

代码实战：A*路径规划模块

下面是我实际项目里用的A*核心代码，去掉了业务细节，保留了骨架：

class AStarPlanner {
private:
    GridMap* map;
    vector<Node> openList;
    vector<Node> closedList;
    
    struct Node {
        int x, y;
        double g, h, f;
        Node* parent;
        int direction; // 0:上, 1:右, 2:下, 3:左
    };
    
public:
    vector<Point> plan(int startX, int startY, int endX, int endY) {
        // 1. 初始化起点
        Node* start = new Node{startX, startY, 0, 0, 0, nullptr, 0};
        start->h = heuristic(startX, startY, endX, endY, 0);
        start->f = start->g + start->h;
        openList.push_back(*start);
        
        // 2. 主循环
        while (!openList.empty()) {
            // 取f值最小的节点
            Node current = getLowestF();
            
            // 到达终点？
            if (current.x == endX && current.y == endY) {
                return reconstructPath(&current);
            }
            
            // 移到closed列表
            openList.erase(remove(openList.begin(), openList.end(), current));
            closedList.push_back(current);
            
            // 3. 扩展邻居
            vector<Point> neighbors = getNeighbors(current.x, current.y);
            for (auto& n : neighbors) {
                if (isInClosedList(n.x, n.y)) continue;
                if (!map->isPassable(n.x, n.y)) continue;
                
                double newG = current.g + distance(current.x, current.y, n.x, n.y);
                double newH = heuristic(n.x, n.y, endX, endY, current.direction);
                double newF = newG + newH;
                
                // 更新或添加节点
                updateOrAddNode(n.x, n.y, newG, newH, newF, &current);
            }
        }
        
        return {}; // 无路径
    }
};

避坑指南：我曾经在openList用vector存储，每次取最小f值时遍历整个列表。地图一大，性能直接崩了。后来改成优先队列（priority_queue），速度提升了10倍。记住：数据结构选型很重要。

地图与路径的联动

地图构建和路径规划不是孤立的。它们之间有个接口层，负责：

  • 把拓扑路径转换成栅格路径
  • 把栅格路径平滑成AGV可执行的轨迹
  • 实时更新地图中的动态障碍物

我一般用三次样条插值做路径平滑。A*出来的折线路径，经过样条插值后，变成AGV能顺畅跟随的曲线。

注意事项：地图数据一定要做版本管理。我见过一个项目，地图被误改了，AGV直接往墙上撞。后来我们给地图加了时间戳和变更日志，每次加载都校验完整性。

性能优化：让AGV跑得更快

路径规划的性能直接影响AGV的响应速度。我总结了几条优化经验：

优化手段 效果 适用场景
JPS（跳点搜索） 减少搜索节点数，速度提升5-10倍 栅格地图，障碍物稀疏
分层规划 全局+局部，响应时间<10ms 大规模地图（1000x1000以上）
路径缓存 相同起终点直接复用，节省80%计算 固定路线场景（如仓库）
增量式A* 只更新变化部分，避免全量重算 动态障碍物频繁出现

我个人最推荐JPS。它本质上是对A*的加速，在栅格地图上效果特别明显。说白了，就是跳过那些「一眼就能看出没希望」的格子，直接跳到关键节点。
