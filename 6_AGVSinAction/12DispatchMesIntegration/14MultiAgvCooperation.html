14 多AGV协同：任务分配算法、避碰策略、交通管制规则、充电站管理

多AGV协同，说白了就是让一群机器人干活不打架。我见过不少工厂，AGV一多就乱套——路口堵死、任务抢单、电量耗尽趴窝。这些问题，本质上就是协同没做好。

这一章，我把核心拆成四个模块：任务怎么分、路怎么走、堵了怎么办、没电了怎么管。每个模块都有实战经验，你拿去就能用。

14.1 任务分配算法：谁有空谁干

任务分配不是简单的“先到先得”。我早期踩过一个坑：让AGV按距离最近原则接单，结果一台车忙死，其他车闲死。后来才明白，要综合考虑距离、电量、当前任务状态。

14.1.1 常用分配策略

策略 原理 适用场景
最短路径优先 选距离任务点最近的AGV 任务紧急、单点配送
负载均衡 统计每台车任务队列长度 长时间连续作业
电量感知 电量低于阈值时不分配新任务 防止半路没电
优先级抢占 高优先级任务打断低优先级 产线急单、异常处理

我个人习惯用“加权评分法”。给每个因素打分，比如距离权重0.4、电量权重0.3、任务队列长度权重0.3。总分最高的车接单。这样既公平又灵活。

核心逻辑：任务分配不是选最优，而是选最合适。一台车再近，如果电量只剩20%，接了也是麻烦。

14.1.2 代码示例：加权评分分配

def assign_task(agvs, task):
    best_agv = None
    best_score = -1
    
    for agv in agvs:
        # 跳过电量不足的
        if agv.battery < 20:
            continue
            
        # 计算距离分（越小越好，取倒数）
        dist = calc_distance(agv.position, task.start)
        dist_score = 1.0 / (dist + 1)
        
        # 电量分
        battery_score = agv.battery / 100.0
        
        # 负载分（任务队列越短越好）
        load_score = 1.0 / (len(agv.task_queue) + 1)
        
        # 加权总分
        total = 0.4 * dist_score + 0.3 * battery_score + 0.3 * load_score
        
        if total > best_score:
            best_score = total
            best_agv = agv
    
    return best_agv

实战技巧：权重值不是拍脑袋定的。我建议用历史数据跑一遍模拟，看哪种权重组合下系统吞吐量最高。我曾经调了三天参数，最后发现0.35/0.35/0.3最稳。

14.2 避碰策略：别让车撞车

AGV避碰分两级：全局规划和局部反应。全局规划在任务下发时就定好路线，局部反应是遇到突发障碍时临时调整。

14.2.1 全局避碰：路径预留

我常用的方法是“时间窗预留”。每台AGV申请路径时，把占用路段的时间段登记到一张表里。新AGV申请路径时，避开冲突的时间段。

class PathReservation:
    def __init__(self):
        self.reservations = {}  # {路段ID: [(开始时间, 结束时间, AGV_ID)]}
    
    def request_path(self, agv_id, path, speed):
        # 计算每段路的占用时间
        time_windows = []
        current_time = get_current_time()
        for segment in path:
            travel_time = segment.length / speed
            time_windows.append((current_time, current_time + travel_time))
            current_time += travel_time
        
        # 检查冲突
        for i, segment in enumerate(path):
            for res in self.reservations.get(segment.id, []):
                if is_overlap(time_windows[i], res):
                    return False  # 有冲突，拒绝
        
        # 无冲突，预留
        for i, segment in enumerate(path):
            self.reservations.setdefault(segment.id, [])
            self.reservations[segment.id].append(
                (time_windows[i][0], time_windows[i][1], agv_id)
            )
        return True

注意：时间窗预留要求所有AGV时钟同步。我遇到过因为时钟偏差导致两车在路口相撞的事故。后来强制要求每台车每5秒和服务器对时一次。

14.2.2 局部避碰：动态调整

全局规划搞定了大部分情况，但总有意外。比如有人突然走到路中间，或者另一台AGV偏离了预定路线。

这时候需要局部避碰。我一般用“减速-等待-绕行”三级策略：

  1. 减速：检测到前方障碍，先减速到0.3m/s
  2. 等待：如果障碍在3秒内消失，恢复原速
  3. 绕行：等待超时，重新规划局部路径

你想想看，如果一遇到障碍就绕行，系统会频繁重规划，反而更乱。先减速观察，很多时候障碍只是临时经过。

14.3 交通管制规则：路口怎么过

路口是AGV系统最容易出问题的地方。多台车同时到达，谁先走？

我见过最粗暴的做法是“先到先走”。但这样会导致一个方向的车永远过不去——如果另一个方向的车连续到达。

14.3.1 四阶段管制法

我推荐用“四阶段管制法”，类似十字路口的红绿灯：

阶段 允许方向 禁止方向
阶段1 东西直行 南北直行、所有转弯
阶段2 东西左转 其他所有方向
阶段3 南北直行 东西直行、所有转弯
阶段4 南北左转 其他所有方向

每个阶段持续5-10秒，根据车流量动态调整。右转车辆不受限制，但必须减速到0.5m/s以下。

关键点：管制不是死板的。如果某个方向长时间没车，可以跳过该阶段，直接进入下一阶段。我管这叫“自适应相位跳跃”。

14.3.2 死锁检测与恢复

多AGV系统最怕死锁——四台车各占一个路口，互相等对方让路。这种情况一旦发生，人工介入非常麻烦。

我写过一个死锁检测算法，每5秒检查一次：

def detect_deadlock(agvs):
    # 构建等待图
    wait_graph = {}
    for agv in agvs:
        if agv.status == 'WAITING':
            # 该AGV在等谁让路
            waiting_for = agv.waiting_for
            wait_graph[agv.id] = waiting_for
    
    # 检测环
    visited = set()
    for agv_id in wait_graph:
        if agv_id not in visited:
            if has_cycle(wait_graph, agv_id, visited, set()):
                return True  # 发现死锁
    return False

def resolve_deadlock(agvs):
    # 最简单的恢复：让其中一台车倒车退出路口
    deadlocked = find_deadlocked_agvs(agvs)
    # 选任务优先级最低的那台
    victim = min(deadlocked, key=lambda a: a.task_priority)
    victim.reverse_out(5)  # 倒车5米

避坑指南：我曾经遇到过死锁检测太频繁导致系统卡顿。后来改成“当有AGV等待超过10秒时才触发检测”，效率高了很多。

14.4 充电站管理：别让车饿死在路上

AGV没电了，比堵车更麻烦。堵车还能等，没电了直接趴窝，还得派人去推。

14.4.1 充电策略

我见过三种充电策略：

  • 低电量强制充电：电量低于20%时，强制返回充电站。优点是安全，缺点是可能中断重要任务。
  • 任务间隙充电：完成当前任务后，如果电量低于50%，就去充一会儿。适合连续作业场景。
  • 预测性充电：根据任务路径计算耗电量，提前安排充电。这是最智能的，但需要精确的能耗模型。

我个人推荐“混合策略”：电量低于20%强制充，20%-50%之间任务间隙充，高于50%正常干活。

14.4.2 充电站调度

充电站数量有限，多台车同时要充电怎么办？

我设计过一个简单的排队机制：

class ChargingStation:
    def __init__(self, station_id):
        self.id = station_id
        self.queue = []  # 等待充电的AGV列表
        self.charging = None  # 正在充电的AGV
    
    def request_charge(self, agv):
        if self.charging is None:
            # 直接开始充电
            self.charging = agv
            agv.start_charging()
        else:
            # 加入队列，按电量从低到高排序
            self.queue.append(agv)
            self.queue.sort(key=lambda a: a.battery)
    
    def charge_complete(self):
        # 当前AGV充完电
        self.charging = None
        if self.queue:
            next_agv = self.queue.pop(0)
            self.charging = next_agv
            next_agv.start_charging()

注意：不要让所有AGV同时去充电。我遇到过下班前所有车一起回充电站，结果路口堵死。建议设置充电时间窗口，比如每台车错开15分钟。

14.5 知识体系总览

下面这张图把多AGV协同的四个模块串起来了。你一看就明白它们之间的关系。

这四个模块不是孤立的。任务分配时要考虑电量，路径规划要避开拥堵路口，充电调度要避开高峰期。说白了，它们是一个整体。

总结一句话：多AGV协同的核心不是让每台车跑得快，而是让整个系统跑得稳。任务分配、避碰、管制、充电，缺一个都不行。
