22 行业案例2：电商仓储AGV与MES/WMS集成实战（拣选、补货、退货、盘点）

电商仓储，说白了就是“快”。订单来了，你得在几分钟内把货找出来、打包好、发出去。我这些年做过的电商仓项目，少说也有十几个了。今天拿一个典型的案例，跟大家聊聊AGV调度系统怎么跟MES、WMS深度集成。

这个项目是个中型电商仓，日均单量5万左右。仓库里跑着80台潜伏式AGV，货架是标准的1.2m×1m可移动货架。他们原来的WMS是自研的，MES是后来上的，AGV调度系统是我这边搭的。嗯，集成过程确实踩了不少坑。

一、业务场景与系统边界

电商仓储的核心业务，无非就是四个字：进、存、拣、发。但具体到AGV的调度，我们得把每个环节拆开来看。

业务场景 主导系统 AGV角色 交互频率
拣选（波次） WMS下发任务 搬运货架到工作站 高（秒级）
补货 MES触发 搬运补货托盘到货架区 中（分钟级）
退货上架 WMS/MES协同 搬运退货箱到指定货架 低（小时级）
盘点 MES发起 搬运货架到盘点台 低（按需）

你看，不同场景下，AGV的调度逻辑完全不同。拣选要求的是“快”，补货要求的是“准”，退货要求的是“稳”，盘点要求的是“全”。

二、拣选流程：AGV与WMS的“心跳”对接

拣选是电商仓的命脉。我习惯把拣选流程分成三步：任务下发、货架搬运、任务闭环。

WMS会按波次生成拣选任务。每个任务包含：订单号、SKU列表、数量、工作站编号。AGV调度系统收到任务后，会做两件事：

  1. 锁定货架：找到包含该SKU的货架，标记为“不可移动”，防止其他任务冲突。
  2. 路径规划：计算货架到工作站的最优路径，避开拥堵区域。

这里有个坑，我必须要说。有一次，WMS下发了100个拣选任务，AGV调度系统一股脑全接了。结果呢？工作站排起了长队，AGV堵成一锅粥。后来我加了个任务队列管理，每次只下发5个任务到AGV，等一个任务完成，再释放下一个。说白了，就是给AGV“限流”。

核心接口示例（AGV调度系统接收WMS任务）：

{
  "task_id": "PICK_20240321_001",
  "type": "PICKING",
  "priority": 1,
  "sku_list": [
    {"sku": "SKU_A001", "qty": 2, "location": "A-01-01"},
    {"sku": "SKU_B002", "qty": 1, "location": "B-02-03"}
  ],
  "station_id": "ST_01",
  "deadline": "2024-03-21 10:30:00"
}

AGV到达工作站后，操作员扫码确认拣选完成。这时候，AGV调度系统会通知WMS：任务已完成，货架可以释放。WMS更新库存后，再通知AGV把货架送回原位。

三、补货流程：MES的“主动触发”

补货这件事，很多项目都做得不好。为什么？因为补货的触发时机很难把握。我个人习惯让MES来做这个“裁判”。

MES会实时监控每个SKU的库存水位。当某个SKU的库存低于安全库存时，MES会生成一个补货任务。这个任务包含：补货SKU、数量、目标货架位置。

AGV调度系统收到补货任务后，会做两件事：

  • 搬运空托盘：从空托盘区搬运一个托盘到补货工作站。
  • 搬运补货箱：从收货区搬运补货箱到工作站。

操作员把补货箱里的商品放到托盘上，然后AGV把托盘搬运到目标货架位置。嗯，这里要注意，补货的优先级通常比拣选低。我一般会给补货任务设置一个较低的优先级，避免影响拣选效率。

避坑指南：我曾经在一个项目里，把补货和拣选混在一起调度。结果补货AGV和拣选AGV在通道里“打架”，效率直接掉了30%。后来我强制把补货AGV和拣选AGV的路径分开，问题才解决。

四、退货流程：WMS与MES的“协同作战”

退货是电商仓最头疼的环节。退货商品需要质检、重新包装、再上架。这个流程，WMS和MES必须协同工作。

流程大概是这样的：

  1. WMS接收退货单：生成退货任务，包含退货单号、SKU、数量。
  2. MES触发质检：AGV把退货箱搬运到质检工作站。
  3. 质检完成：MES更新质检结果（合格/不合格）。
  4. AGV搬运：合格品搬运到上架区，不合格品搬运到退货区。

这里有个细节，我特别想强调。退货箱的尺寸、重量都不固定，AGV的货叉需要自适应调整。我在项目中遇到过，退货箱太重，AGV直接报警停机的。后来我们加了个重量传感器，AGV在搬运前先称重，超重就报警，让操作员处理。

五、盘点流程：MES的“定时任务”

盘点这件事，很多仓库都是人工做。但用AGV来做盘点，效率能提升好几倍。

MES会定时生成盘点任务。比如每天晚上12点，盘点A区的所有货架。AGV调度系统收到任务后，会按顺序把货架搬运到盘点台。操作员扫描货架上的所有SKU，确认库存数量。

盘点完成后，MES会对比系统库存和实际库存。如果有差异，生成差异报告，通知WMS调整库存。

注意事项：盘点期间，AGV不能执行其他任务。我建议把盘点安排在业务低峰期，比如凌晨2点到5点。另外，盘点货架的路径要避开主通道，避免影响白天的作业。

七、总结与经验

电商仓储的AGV集成，说白了就是三个字：快、准、稳。

  • 快：拣选任务要秒级响应，AGV路径要实时优化。
  • 准：库存数据要实时同步，任务状态要闭环反馈。
  • 稳：系统要能扛住高峰流量，AGV要能处理异常情况。

我个人觉得，做集成最怕的就是“想当然”。你以为WMS下发了任务，AGV就能自动跑起来？没那么简单。你得考虑网络延迟、任务冲突、AGV电量、货架锁定……这些细节，一个没处理好，整个系统就崩了。

嗯，今天就聊到这儿。电商仓储的AGV集成，其实还有很多细节可以深挖。比如AGV的充电策略、工作站的任务分配、异常订单的处理……这些我们后面再聊。
