27 模拟器开发：AGV模拟器、MES模拟器、场景模拟器、压力测试模拟器

说实话，做AGV调度系统与MES对接，最怕什么？

怕现场跑起来才发现问题。AGV撞了、任务丢了、MES那边没收到反馈……这些坑，我年轻时都踩过。后来我学乖了——先模拟，再上线。

这一章，我们就聊聊怎么开发一套完整的模拟器体系。包括AGV模拟器、MES模拟器、场景模拟器，还有压力测试模拟器。说白了，就是让你在不上真车、不连真MES的情况下，把整个系统跑一遍。

27.1 为什么需要模拟器？

我在一个汽车零部件工厂做过项目。当时AGV调度系统开发完了，但MES那边还在改接口。现场AGV也没到位。怎么办？干等？

不行。我花了三天时间，写了个简单的AGV模拟器和MES模拟器。调度系统跑起来，模拟器假装是AGV，假装是MES。结果提前发现了三个接口字段不匹配的问题。要是等到现场再发现，那可就尴尬了。

模拟器的核心价值就三点：

  • 解耦依赖——AGV没到货，MES没上线，你照样能开发测试
  • 复现异常——模拟网络延迟、AGV故障、任务超时，这些在真实环境很难触发
  • 压力测试——看看系统到底能扛多少台AGV、多少并发任务

我的经验：模拟器不是玩具，是工程利器。我见过太多项目，现场调试花了两周，其实一半问题在模拟阶段就能解决。

27.2 AGV模拟器

AGV模拟器，说白了就是假装自己是AGV。它要能接收调度系统的指令，然后假装移动、假装取货、假装报状态。

我习惯把AGV模拟器拆成三个模块：

27.2.1 通信模块

模拟器要能跟调度系统建立连接。通常用TCP、HTTP或者MQTT。我推荐MQTT，因为它在模拟多台AGV时更灵活。

// 伪代码：AGV模拟器通信模块
class AgvSimulator:
    def __init__(self, agv_id, broker_url):
        self.agv_id = agv_id
        self.client = mqtt.Client(agv_id)
        self.client.on_message = self.on_command
        
    def connect(self):
        self.client.connect(broker_url)
        # 订阅调度系统下发的指令主题
        self.client.subscribe(f"agv/{self.agv_id}/command")
        
    def on_command(self, client, userdata, msg):
        # 解析指令，比如：去A点、取货、放货
        command = json.loads(msg.payload)
        self.execute_command(command)
        
    def report_status(self, status):
        # 上报位置、状态、电量等
        topic = f"agv/{self.agv_id}/status"
        self.client.publish(topic, json.dumps(status))

27.2.2 运动模拟模块

AGV收到移动指令后，不能瞬间到达。要模拟移动时间。我一般用线性插值，加上一点随机抖动。

def move_to(self, target_x, target_y):
    # 计算距离
    distance = math.sqrt((target_x - self.x)**2 + (target_y - self.y)**2)
    # 假设速度1m/s，加上随机延迟模拟路况
    travel_time = distance / 1.0 + random.uniform(0, 2)
    time.sleep(travel_time)
    self.x, self.y = target_x, target_y
    self.report_status({"x": self.x, "y": self.y, "state": "idle"})

避坑指南：我曾经把运动模拟写得太完美，每次移动时间都精确到毫秒。结果上线后发现，真实AGV因为避障、转弯，时间波动很大。后来我在模拟器里加了随机延迟，才更贴近真实。

27.2.3 状态机模块

AGV有状态：空闲、行驶中、取货中、充电中、故障。模拟器要能正确切换状态。

当前状态收到指令下一状态
空闲移动指令行驶中
行驶中到达空闲
空闲取货指令取货中
取货中完成空闲
任意故障指令故障

27.3 MES模拟器

MES模拟器，就是假装自己是MES系统。它要能接收调度系统上报的任务状态，也能下发生产任务。

我一般把MES模拟器做得简单点，重点模拟几个核心接口：

  • 任务下发接口——MES告诉调度系统：现在有个物料要从A运到B
  • 状态查询接口——MES问调度系统：那个任务怎么样了？
  • 异常上报接口——调度系统告诉MES：AGV故障了，任务完不成
class MesSimulator:
    def __init__(self):
        self.tasks = []
        self.task_id_counter = 0
        
    def create_task(self, from_location, to_location, priority=1):
        # MES创建任务
        task = {
            "task_id": f"TASK_{self.task_id_counter}",
            "from": from_location,
            "to": to_location,
            "priority": priority,
            "status": "pending"
        }
        self.tasks.append(task)
        self.task_id_counter += 1
        # 通过API发送给调度系统
        requests.post("http://scheduler/api/task", json=task)
        return task
        
    def query_task_status(self, task_id):
        # 查询任务状态
        response = requests.get(f"http://scheduler/api/task/{task_id}")
        return response.json()

我的习惯：MES模拟器里我会加一个"自动任务生成器"。每隔几秒自动下发一个任务，模拟真实产线的节拍。这样调度系统就能持续跑起来，不用手动点来点去。

27.4 场景模拟器

场景模拟器，是最高级的玩法。它不只是模拟单个AGV或MES，而是模拟整个工厂环境。

我做过一个场景模拟器，里面包含：

  • 地图数据（路径、站点、充电桩位置）
  • 多台AGV同时运行
  • MES持续下发任务
  • 随机事件（AGV故障、道路堵塞、任务取消）

场景模拟器的核心是时间驱动。不是真实时间，而是模拟时间。你可以让模拟器跑得比真实时间快10倍，这样一小时就能模拟出10小时的运行情况。

class ScenarioSimulator:
    def __init__(self, map_data, agv_count=10):
        self.map = Map(map_data)
        self.agvs = [AgvSimulator(f"AGV_{i}") for i in range(agv_count)]
        self.mes = MesSimulator()
        self.clock = 0  # 模拟时钟
        
    def run(self, simulation_hours=8, speed_factor=10):
        # speed_factor=10 表示模拟时间比真实时间快10倍
        end_time = simulation_hours * 3600  # 转为秒
        while self.clock < end_time:
            # 每模拟秒处理一次
            self.tick()
            self.clock += 1
            # 真实时间等待
            time.sleep(1 / speed_factor)
            
    def tick(self):
        # 检查是否有新任务
        if self.clock % 30 == 0:  # 每30模拟秒下发一个任务
            self.mes.create_task(random_location(), random_location())
        # 更新所有AGV状态
        for agv in self.agvs:
            agv.tick()

经验之谈：场景模拟器里一定要加随机事件。我曾经不加随机事件，模拟结果完美得不像话。结果上线第一天，一台AGV卡在路口，整个系统就乱了。后来我在模拟器里加了"随机故障率"，才把调度系统的容错机制逼出来。

27.5 压力测试模拟器

压力测试模拟器，就是往死里压你的系统。看看它到底能扛多少。

我一般关注几个指标：

  • 最大AGV数量——调度系统能同时管理多少台AGV？
  • 最大任务并发——一秒内下发100个任务，系统会不会崩溃？
  • 响应时间——从任务下达到AGV开始执行，需要多久？
  • 资源消耗——CPU、内存、网络带宽

压力测试模拟器的写法，其实就是把AGV模拟器和MES模拟器放大100倍。

class StressTestSimulator:
    def __init__(self, agv_count=100, task_rate=10):
        # agv_count: 模拟100台AGV
        # task_rate: 每秒下发10个任务
        self.agvs = [AgvSimulator(f"AGV_{i}") for i in range(agv_count)]
        self.task_rate = task_rate
        
    def run_stress_test(self, duration_minutes=10):
        start_time = time.time()
        task_count = 0
        while time.time() - start_time < duration_minutes * 60:
            # 按任务率下发任务
            for _ in range(self.task_rate):
                self.create_task()
                task_count += 1
            time.sleep(1)
        print(f"共下发 {task_count} 个任务")
        print(f"平均响应时间: {self.calc_avg_response_time()} ms")

注意：压力测试时，你的开发机可能先扛不住。我试过在一台8G内存的笔记本上模拟200台AGV，结果调度系统没崩，笔记本先蓝屏了。建议压力测试在服务器上跑，或者用分布式模拟器。

你看，四个模拟器围绕调度系统，各自扮演不同角色。AGV模拟器假装是车，MES模拟器假装是工厂系统，场景模拟器把两者整合起来，压力测试模拟器则负责往死里压。

27.7 我的建议

做模拟器，别想着一次做完美。我一般分三步走：

  1. 先做AGV模拟器——能跑通基本指令就行
  2. 再加MES模拟器——能自动下发任务
  3. 最后整合成场景模拟器——加上随机事件和压力测试

嗯，模拟器这东西，投入产出比极高。花三天写模拟器，可能省下三周的现场调试时间。这笔账，你算算看。

一句话总结：模拟器不是替代真实环境，而是让你在真实环境出问题之前，先把问题找出来。
